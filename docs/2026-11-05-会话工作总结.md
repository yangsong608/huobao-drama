## 4. 方法与经验

1. **先证据后修复**：先取真实 provider payload、`sys_task.prompt`、桥接 `state.json` 与 ComfyUI 队列，不接受「UI 里没写」作为结论。
2. **TDD**：新增迁移、清洗、媒体路径、音色分配等能力均先写失败测试，再实现；桌面迁移测试先因模块缺失 RED，再转 GREEN。
3. **纵深防御**：生成规则（模板）→ 提交清洗（运行时）→ 存量迁移（桌面工作区），三层覆盖新老数据。
4. **单一事实源**：音色只保留一套 store/卡片；集视频配置由选择写回；模型列表不擅自替换用户选择。
5. **四语言同步**：模板、技能、Agent 规则、前端文案一起改；英文遗漏由本次复盘补上，后续以键审计与结构测试守卫。
6. **包/源一致性**：每次源码变更后重新 generate/dist，校验 asar、随包模板、安装后资源与 `TEMPLATE_VERSION`，避免「源码修了、桌面还是旧的」。
7. **文档即验收账本**：执行日志记录命令、计数、产物大小、安装路径与边界；`v3-state.json` 只维护当前指标与门禁，不虚报通过。
8. **安全边界**：不输出密钥/密码/私钥/公网 IP；不打印 DSH 密码；不动 5679/3013；不擅自启动或重启桌面应用；提交仅在明确授权后执行。
