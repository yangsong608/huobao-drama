## 0. 一页结论

**建议做，但定位必须是「AI 短剧成片工作台」，不是通用剪映克隆。**

本方案以「音频和视频分开」为前置约束，形成两个独立工作台：

| 工作台 | 负责 | 不负责 |
| --- | --- | --- |
| **剪辑工作台（视频）** | 画面排序、裁剪、分割、转场、字幕时间、成片导出 | 完整混音台、总线、ducking、音频分离 |
| **混音工作台（音频）** | 对白/原声/环境/音效/BGM、总线、音量、声像、ducking、混音导出 | 视频片段编辑、字幕编辑、最终成片导出 |

两页共享同一份工程数据、同一份素材库、同一套版本与导出任务；页面之间通过带上下文的跳转协作，而不是把两套工具塞进一个页面。

**核心结论：**

1. **不嵌入开源编辑器。** OpenCut 尚未定型，主流项目是 React/Qt，且 Concat、Shotcut、Kdenlive、OpenShot、etro 等为 AGPL/GPL；直接嵌入或 fork 的许可证与 UI 重写成本都不可接受。
2. **不新增第二个播放器。** 每个工作台内部只保留一个播放器、一个时钟；跨页跳转携带 `episodeId + playheadMs + selection`，接收页自行 seek，不共享播放器实例。
3. **导出管线已经覆盖约 70%。** 现有 FFmpeg 合片、转场、混音、字幕、响度、校验、任务状态机可复用；真正缺的是可编辑视频时间线和实时预览。
4. **最大技术风险是预览与音画同步，不是导出。** 建议先做 1–2 周 Phase 0 Spike，用真实剧集验证多片段预览、转场、seek、音画同步，再决定是否进入 MVP。
5. **先解决成片指针冲突。** `episodes.video_url` 目前有合片、导出、配音、版本回滚、动效后处理多个写入方；不收敛指针，剪辑结果会被重新合片覆盖。

**建议默认决策：**

| 决策 | 建议 |
| --- | --- |
| 页面结构 | 剪辑、混音两个独立路由，不做单页合并 |
| 素材范围 | 生成镜头 + 有限本地导入（mp4/mov） |
| 视频轨 | MVP 单视频轨 |
| 最终成片导出 | 放在剪辑工作台；混音工作台只导出混音 |
| 平台 | Electron 桌面优先 |
| AI 深度 | P0 手工剪辑 + 台词生成字幕；自动字幕与 AI 粗剪放 P2 评估 |

## 1. 背景与问题

### 1.1 现有链路

当前项目已经具备完整的「小说 → 剧本 → 资产 → 生图 → 分镜 → 生视频 → 配音 → 合片/混音/字幕 → 导出」流水线，但成片阶段有三个入口，职责重叠：

| 入口 | 位置 | 现状 | 问题 |
| --- | --- | --- | --- |
| 制作页「拼接导出」 | `frontend/app/views/drama/episode.vue` 约 1000 行起 | 选择镜头、AI 过渡、`video_merges`、FFmpeg concat/xfade | 是表单/对话框，不是时间线；无法精细调整单片段 |
| 配音工作台第 4 步「预览与混音」 | `MixStage.vue` + `MixTimeline.vue` + `useMixStage.ts` | 多轨音频时间线、波形、总线、ducking、版本 | 视频轨只读、只能 seek；不能剪画面 |
| 配音工作台第 5 步「合成导出」 | `ExportStage.vue` + `useExportSession.ts` + `episode_exports` | 预设、字幕模式、响度、校验、任务状态 | 与制作页合片、混音页职责交叉；最终成片指针不唯一 |

现有音频工作台是很好的基础：`MixPlan` 是唯一数据源，轨道/片段/总线都由它派生，保存后以服务端结果为准；`MixTimeline` 已有画布时间线、缩放、吸附、拖拽、裁剪、波形；`MixStage` 已有播放头、试听、撤销/重做。但它不是视频编辑器：

- 视频轨是只读的，点击只 seek，不能命中视频片段（`MixTimeline.vue` 的 `clipAt` 只命中音频轨）。
- 预览是「单个 `<video>` + 实时 WebAudio 多轨监听/渲染终检」；视频仍只有一个，无法看多片段拼接；渲染终检仍限 30 秒。
- 字幕没有独立可编辑轨，主要从台词/时间线派生。
- 视频片段没有源入出点、转场、变换等数据结构。

### 1.2 为什么必须分开

用户明确要求音频和视频分开，不应把两个工作台合并成一个页面。产品上这也成立：

1. **两种心智模型。** 剪辑是「画面节奏、镜头顺序、叙事」，混音是「声音平衡、空间、响度」；同一屏同时呈现会互相干扰。
2. **两种专业工具。** Premiere + Audition、DaVinci Resolve 的 Cut/Edit 页与 Fairlight 页都是分工的；CapCut 把两者放在一页，是因为它面向广谱轻量用户，代价是界面密度极高。
3. **避免「四不像」。** 之前混音工作台被反馈为「四不像」，核心原因之一就是播放器/时钟/轨道职责混杂。分页是降低认知负荷，而不是增加步骤。
4. **各自演进。** 视频编辑器需要预览、合成、转场、字幕；混音器需要总线、ducking、响度、stem。两者的技术栈和性能瓶颈不同，分页后可以独立迭代。

**但分开不等于割裂。** 两页必须共享：

- 同一集、同一份素材库；
- 同一份时间基准与片段引用（`lineId / shotId / videoTakeAssetId`；配音侧用 `voiceTakeId`）；
- 当前剪辑版本和当前混音版本；
- 当前成片指针与导出任务；
- 跳转上下文（剧集、播放头、选区、区间）。

### 1.3 分开后的核心风险

| 风险 | 表现 | 对策 |
| --- | --- | --- |
| 用户不知道去哪个页面 | 「我要改这句话的声音，去剪辑还是混音？」 | 入口文案明确：画面去剪辑，声音去混音；两页顶部互相跳转 |
| 剪辑后混音过期 | 改了镜头顺序，旧混音对不上 | `MixPlan` 绑定 `editRevisionId`；剪辑变更后标记 stale，提示重新对齐 |
| 两个页面各有一个播放器 | 用户来回切换，播放头丢失 | 跨页携带 `playheadMs + range + selection`；每页仍只有一个播放器 |
| 最终成片指针冲突 | 重新合片覆盖用户剪辑 | 收敛 `episodes.video_url` 写入方；合片/配音产物降级为素材 |
| 重复建设 | 两页各自做时间线、波形、缩放 | 抽共享底层原语，不做共享业务组件 |

### 2.2 竞品给我们的启示

1. **剪映的广度不可跟。** 多轨、关键帧、蒙版、抠像、跟踪、调色、特效、素材库是多年积累；火宝如果追广度，会陷入长期维护战。
2. **Descript 的文本驱动最适合短剧。** 短剧的对白、字幕、配音都是结构化数据，按台词剪、删静音、自动字幕比波形剪辑更高效。
3. **专业工具普遍把音视频分工。** Premiere + Audition、Resolve 的 Edit/Fairlight 分页说明：音视频分开不是产品缺陷，而是专业分工。
4. **Web 端要克制。** Clipchamp 的简洁证明浏览器端不需要完整 NLE；火宝桌面端也应把复杂度放在服务端渲染，前端保持轻量。
5. **AI 要嵌入流程，不要做聊天框。** 竞品的 AI 都落在具体动作上：自动字幕、静音删除、智能踩点、粗剪、配音；火宝应把 AI 放在「从剧本/分镜生成初剪」和「按台词修改」上。

### 2.3 短剧场景能力优先级

> 优先级与产品设计一致：**P0 = MVP，P1 = 完整核心（发布门槛），P2 = 专业扩展**。

| 优先级 | 能力 | 归属 | 说明 |
| --- | --- | --- | --- |
| **P0** | 多片段排列、裁剪、分割、波纹删除、显式留空 | 剪辑 | 工作台地基 |
| **P0** | 帧级播放头、逐帧前进/后退 | 剪辑 | 口型/动作对齐 |
| **P0** | 硬切 + 叠化；片段边缘淡入/淡出黑 | 剪辑 | 短剧最常用；淡入淡出不是独立转场类型 |
| **P0** | 变速（0.25x–4x）、简单适配（填充/适配） | 剪辑 | 节奏调整 |
| **P0** | 台词生成字幕：文本/时间微调、样式、偏移 | 剪辑 | 现有字幕能力可复用 |
| **P0** | 音频波形参考、剪辑页音频监听 | 剪辑（监听）+ 混音（波形编辑） | 剪辑页只读波形并监听当前混音/原声 |
| **P0** | 导出预设、进度、取消、失败重试、校验 | 剪辑 | 复用 `episode_exports` |
| **P0** | 撤销/重做、自动保存、刷新恢复 | 两页 | 编辑信任基础 |
| **P0** | 对白/原声/环境/音效/BGM/总线/ducking | 混音 | 现有 MixPlan 主责；MVP 必须保留 |
| **P0** | 混音页实时监听 | 混音 | 已具备 `useMixPlayback`；保留 30 秒渲染终检 |
| **P1** | 画中画/叠加轨（一条）、滤镜、标题 | 剪辑 | 完整核心；不是第二条主视频轨 |
| **P1** | Take 切换（同台词多版本） | 剪辑（展示）+ 混音（听感） | 火宝独有数据优势 |
| **P1** | 精确预览、版本对比、批量导出、SRT 导入 | 剪辑 | 发布门槛 |
| **P2** | AI 自动字幕、AI 粗剪（含静音/口癖清理） | 剪辑 | 需单独技术选型；本设计不承诺 |
| **P2** | 第二视频轨、关键帧、蒙版、抠像、跟踪、多机位、专业调色、变速曲线、倒放/定格 | 剪辑 | 不在完整核心 |

### 3.2 Build vs Buy

| 路线 | 可行性 | 原因 |
| --- | --- | --- |
| 直接嵌入开源编辑器 | **不可行** | OpenCut 未定型；主流项目是 React/Qt；AGPL/GPL 许可证不适合闭源商业产品 |
| Fork 一个项目改 Vue | **不划算** | UI 重写成本接近自研；还要承担上游维护、许可证和架构绑定 |
| 复用其渲染内核 | **有限可行** | filmcraft 的 Rust 内核、OpenCut 的 Editor API 可研究；但现有 FFmpeg 后端已经够用 |
| 借鉴交互与架构 | **推荐** | 借鉴 OpenCut 的轨道/片段模型、openreel/freecut 的 WebCodecs 预览、Descript 的文本驱动、openfilm 的 AI 粗剪 |
| 自研 Vue 时间线 + 现有 FFmpeg | **推荐** | 与现有工程、许可证、交互脊柱最一致，长期维护可控 |

**结论：不嵌入、不 fork；只借鉴架构与交互。**

### 3.3 可借鉴清单

| 来源 | 可借鉴 | 不照搬 |
| --- | --- | --- |
| OpenCut | 轨道/片段/时间线数据模型；插件化 Editor API 思路 | 其重写中的 UI 与 Rust 内核 |
| openreel / freecut | WebCodecs 预览、代理、帧级 seek、浏览器端渲染降级 | React 组件与状态管理 |
| Concat / Drift / Shotcut | 本地优先、FFmpeg 滤镜图、代理/缓存 | GPL/AGPL 代码 |
| Descript | 文本驱动剪辑、静音/口癖删除、转录定位 | 其云端转录依赖 |
| Filmora | 专业与易用的平衡、AI 功能落点 | 素材库/模板商城 |
| openfilm / diffusionstudio | AI 粗剪、Agent 化编辑的任务拆解 | 其具体 Agent 实现 |

## 4. 产品定位与用户

### 4.1 定位

**「给 AI 短剧创作者的成片工作台：画面在剪辑工作台完成，声音在混音工作台完成，两个页面共享同一份工程。」**

不是通用剪辑器，不追求剪映的功能广度；追求「从生成镜头到可交付成片」的最短路径。

### 4.2 目标用户与 JTBD

| 角色 | 主要场景 | JTBD |
| --- | --- | --- |
| 短剧剪辑/运营 | 镜头生成后拼第一版、调节奏、加转场、出竖屏 | 「镜头都好了，我要在 10 分钟内拼出可审片的第一版」 |
| 配音/音频编辑 | 对白、环境、BGM、响度、ducking | 「我要把声音混到平台可接受的响度，且不盖住台词」 |
| 导演/制片 | 审片、指定替换某镜头/某句 | 「某句台词/某个镜头要换，原位替换，不破坏其他剪辑」 |
| 单人创作者 | 一人完成剪辑 + 混音 + 导出 | 「不要让我在三个页面之间来回找按钮」 |

### 4.3 差异化

1. **剧本/分镜/台词联动。** 每个片段携带 `lineId / shotId / videoTakeAssetId`（视频 Take，`assets.id`）；配音侧用 `voiceTakeId`（`line_takes.id`）；检查器直接显示台词、分镜和角色；重新生成某个 take，时间线片段原位替换，而不是重新合片。
2. **对话驱动剪辑。** 基于现有台词、配音、字幕数据，做「按台词剪」「删静音/口癖」「自动字幕」「配音同步」；这是 Descript 的强项，也是火宝数据天然占优的地方。
3. **Take 管理。** 同一句台词多个配音/镜头版本，时间线 A/B 切换，保留选择记录；通用剪辑器没有这个短剧能力。
4. **一致交付。** 预览、混音、字幕、导出共用工程数据；内置响度、分辨率、音频流、字幕流校验；竖屏/横屏、软/硬字幕、批量预设。
5. **本地/私有与成本可控。** 本地 FFmpeg、现有 H3 网关、本地素材；不依赖云剪辑服务，适合批量短剧生产。

### 4.4 非目标

- 通用任意素材的专业剪辑器；
- 专业调色/Fusion 级 VFX/Fairlight 级音频后期；
- 本次设计与 P0/P1 不做：多机位、运动跟踪、抠像、蒙版（P2 远期候选）；8K 为非目标；
- 实时多人协作、插件市场、移动端；
- 社交模板/素材商城；
- 浏览器内 FFmpeg 渲染；
- 在剪辑页内提供完整混音台，或在混音页内编辑视频。

### 4.5 产品指标

| 指标 | 定义 | 目标（MVP 后观察） |
| --- | --- | --- |
| 首次初剪时间 | 从进入剪辑页到第一次保存/导出 | 中位数 < 10 分钟（10 镜以内） |
| 成片交付时间 | 从镜头齐备到最终导出成功 | 比现有「合片 + 配音导出」流程缩短 30% |
| 页面往返次数 | 每集成片过程中剪辑/混音切换次数 | 2–4 次，且每次上下文不丢 |
| 导出一遍通过率 | `validateExport` 通过 / 总导出 | > 95% |
| 音画不同步问题 | 用户反馈/测试发现的 A/V 偏差 | MVP 阶段 0 个 P0 |
| 混音 stale 处理时长 | 视频变更后到混音重新对齐 | < 2 分钟 |
| 编辑丢失率 | 刷新/崩溃后丢失的编辑 | 0（自动保存 + 恢复） |
| 渲染缓存命中率 | 复用已有导出的比例 | > 30% |

## 5. 产品结构：两个独立工作台

### 5.1 总体结构

```text
剧集工作台
├─ 剪辑工作台（视频）  /drama/:id/episode/:episodeNumber/edit
│   ├─ 素材库：镜头 / Take / 导入素材 / 字幕
│   ├─ 预览：单视频合成预览 + 音频监听
│   ├─ 时间线：视频轨、字幕轨、只读音频参考轨
│   ├─ 检查器：片段、字幕、转场
│   └─ 成片导出
│
├─ 混音工作台（音频）  /drama/:id/episode/:episodeNumber/mix
│   ├─ 视频参考：只读、静音或监听最终混音
│   ├─ 时间线：对白 / 原声 / 环境 / 音效 / BGM
│   ├─ 混音台：M/S、音量、声像、ducking、总线
│   ├─ 检查器：轨道 / 片段 / 总线
│   └─ 混音导出（WAV/M4A/stems）
│
└─ 共享：素材库、EditPlan/MixPlan、当前版本指针、导出任务、跳转上下文
```

**入口收敛：**

- 制作页「拼接导出」改为「打开剪辑工作台」；旧的合片对话框保留为「生成初剪」的快捷动作，但不再承担最终成片导出。
- 配音工作台第 4 步「预览与混音」改为「打开混音工作台」；第 5 步「合成导出」迁移到剪辑工作台的「成片导出」。
- 迁移期保留旧入口，达到 parity 后收敛；不新增第三个成片页面。

### 5.2 剪辑工作台（视频）

| 区域 | 内容 | 关键约束 |
| --- | --- | --- |
| 顶部 | 剧集信息、当前剪辑版本、混音状态、打开混音、导出 | 显示「混音是否与当前剪辑匹配」 |
| 左侧 | 素材库：分镜镜头、Take、导入视频、字幕 | 点击插入到播放头/选中轨 |
| 中部 | 预览 + 运输条（播放/暂停/逐帧/时间码） | 只有一个可见预览窗口（内部 2–3 个 `<video>` 池）；音频监听来自当前混音或原声 |
| 下部 | 时间线：视频轨、字幕轨、只读音频参考 | 视频轨可编辑；音频参考轨只显示波形，不可编辑 |
| 右侧 | 检查器：源入出点、时长、转场、简单变换、字幕文本/时间 | 音频属性显示「由混音工作台管理」并给出跳转 |
| 底部/弹窗 | 成片导出：预设、字幕模式、进度、取消、重试 | 导出前检查混音是否 stale |

**剪辑页不做的：**

- 完整混音台、总线、ducking、声音分离；
- 多视频轨；画中画/叠加轨在 P1 只支持一条，第二条视频轨为 P2；
- 关键帧、蒙版、抠像、跟踪、专业调色（P2）。

### 5.3 混音工作台（音频）

| 区域 | 内容 | 关键约束 |
| --- | --- | --- |
| 顶部 | 剧集信息、当前混音版本、打开剪辑、混音导出 | 显示「画面版本是否已更新」 |
| 中部 | 只读视频参考 + 音频运输条 | 视频只 seek，不可编辑；沿用现有**视频主时钟**（漂移阈值 320ms），音频多轨跟随视频 |
| 下部 | 多轨音频时间线、波形、片段拖拽/裁剪 | 沿用 `MixTimeline` 能力 |
| 右侧 | 混音台/检查器：M/S、音量、声像、ducking、总线 | 沿用 `MixPlan` 总线模型 |
| 底部 | 混音导出：WAV/M4A/stems | 不提供最终视频导出 |

**混音页不做的：**

- 视频片段排序/裁剪/转场；
- 字幕文本/时间编辑；
- 最终成片导出。

### 5.4 职责边界表

| 能力 | 剪辑工作台 | 混音工作台 |
| --- | --- | --- |
| 视频片段排列、裁剪、分割、转场 | **主责** | 只读参考（静音画面） |
| 字幕文本、时间、样式 | **主责** | 只读参考 |
| 对白/原声/环境/音效/BGM | 只读波形 + 跳转 | **主责** |
| 总线、音量、声像、ducking | 只读状态 | **主责** |
| 混音试听 | 监听当前混音 | **主责** |
| 混音导出（WAV/M4A/stems） | 不提供 | **主责** |
| 成片导出（视频+混音+字幕） | **主责** | 不提供 |
| 版本 | `edit_revisions` | `mix_revisions` |
| 播放器 | 视频预览 + 音频监听 | 音频监听 + 静音视频参考 |

### 5.5 页面跳转与上下文

**跳转参数：**

```ts
interface WorkbenchHandoff {
  episodeId: number
  playheadMs: number
  rangeStartMs?: number
  rangeEndMs?: number
  selection?: { kind: 'clip' | 'line' | 'cue'; id: number | string }
  from?: 'edit' | 'mix'
}
```

**规则：**

1. 剪辑页「调整这段的声音」→ 打开混音页，定位到该片段/台词，播放头一致。
2. 混音页「查看画面」→ 打开剪辑页，定位到同一播放头，选中对应片段。
3. 返回时保留来源页的滚动/缩放/选区；不共享播放器实例。
4. 两页都只有一个播放器；跳转时旧页暂停并释放解码资源。
5. 页面顶部显示对方状态：混音版本、剪辑版本、是否 stale。

### 5.6 跨工作台一致性

这是分页方案能否成立的关键。

```text
EditPlan（时间脊梁）
  ├─ clips[]: 有序视频片段（sourceId、sourceInMs/sourceOutMs、speed、gapBeforeMs、transform、filter）
  │    └─ 时间线位置由布局算法派生，不持久化 start/end
  ├─ subtitles[]: 字幕 cue（跟随片段或绝对时间）
  ├─ overlays[] / markers[]
  └─ refs: lineId / videoTakeAssetId
        ↓ buildEditTimeline 派生 linePlacements
MixPlan（声音层）
  ├─ dialogue / original / sfx / bgm / master
  └─ editRevisionId + editPlanHash + editSyncHash + dialogueSyncHash
        ↓
最终导出 = 当前 EditPlan + 当前 MixPlan + 字幕
```

**规则：**

- `EditPlan` 是时间基准；`MixPlan` 必须记录它基于哪个 `editRevisionId`。
- 剪辑变更（顺序、时长、转场）→ 混音标记 `stale`；混音页顶部提示「画面已更新，需要重新对齐」。
- 重新对齐时，按 `lineId / clipId` 保留人工混音调整；无法匹配的片段进入「待确认」列表，不静默丢弃。
- 最终导出前检查 `mixRevision.editSyncHash` 与 `dialogueSyncHash` 是否匹配当前剪辑；版本 ID 仅用于回溯，哈希一致即视为对齐；不匹配时阻止导出或提示先重新对齐。
- 混音变更 → 剪辑页显示「混音已更新」，预览使用最新混音；不影响画面编辑。
- `episodes.video_url` 只由「设为当前成片」更新（删除当前成片时的回退除外）；合片、配音、动效产物只作为素材/中间产物。

| P0（MVP，必须做） | P1（完整核心，发布门槛） | P2（专业扩展，暂不做） |

### 6.3 共同能力

- 自动保存（剪辑页 300ms 防抖；混音页沿用现有）；
- 撤销/重做（剪辑页独立历史，混音页独立历史）；
- 版本列表与恢复；
- 导出任务中心（复用 `episode_exports` 状态机）；
- 媒体代理/缩略图/波形缓存；
- 错误提示与重试；
- 键盘快捷键（空格播放/暂停、←/→ 逐帧、Shift+←/→ 逐秒、I/O 入出点、Cmd/Ctrl+B 分割、Delete 波纹删除、Shift+Delete 仅删除留空、Cmd/Ctrl+Z 撤销、Cmd/Ctrl+Shift+Z 重做）。`J/K/L` 不在 P0 范围，避免与“倒放”混淆。

### 6.4 关键交互

**剪辑：**

- 拖动片段边缘 = 波纹裁剪源入出点（默认后续片段跟随）；按住 `Alt/Option` 拖动 = 非波纹裁剪，写入显式空隙；拖动片段本体 = 移动。
- 播放头分割；删除默认波纹删除，`Shift+Delete` 仅删除留空。
- 转场拖到片段交界；默认硬切，叠化时长可调；淡入/淡出黑在片段检查器中设置，属于片段边缘效果，不占转场槽位。
- 字幕轨支持拖动整段、改文本、微调入出点；与台词行双向定位。
- 选中片段时，右侧检查器显示「台词/镜头/Take」和「声音由混音工作台管理」。

**混音：**

- 保持现有 `MixTimeline` 的拖拽/裁剪/波形/吸附。
- 顶部显示当前画面版本和 stale 状态。
- 「打开剪辑」携带播放头与选中台词。

| 缺口 | 现状 | 影响 |
| --- | --- | --- |
| `EditPlan` 数据模型 | 只有 MixPlan（音频）和 `video_merges`（拼接） | 缺视频轨/片段/源入出点/转场/字幕轨统一计划 |
| 可编辑视频时间线 | `MixTimeline` 视频轨只读，`clipAt` 只命中音频轨 | 不能拖视频、裁剪、分割、排序 |
| 多片段预览 | `SubtitlePreview` 单 `<video>`；`MixStage` 已有实时音频但无多片段视频 | 无法实时看拼接、转场、音画同步 |
| 实时音频监听 | 混音页已具备 `useMixPlayback`；剪辑页尚未接入 | 剪辑页需要与视频时钟同步 |
| 渲染编译器 | 合片和混音两套流程 | 需要 EditPlan → FFmpeg filter graph |
| 当前成片唯一指针 | `episodes.video_url` 多写入方 | 编辑结果可能被重新合片覆盖 |
| 代理/中间格式 | 生成视频编码/分辨率可能不一致 | 预览卡顿、seek 慢、A/V 不同步 |
| 编辑版本/恢复 | MixPlan 有 300ms 防抖 + 50 步撤销 | 视频编辑需要同样能力并持久化 |

### 7.3 推荐架构

```text
前端
├─ /edit  剪辑工作台
│   ├─ EditTimeline（视频轨 + 字幕轨 + 只读音频参考）
│   ├─ useEditPlan（编辑状态、撤销、自动保存）
│   ├─ useEditPlayback（视频池 + WebAudio + 字幕叠加）
│   └─ EditInspector / ExportPanel
├─ /mix   混音工作台
│   ├─ MixStage / MixTimeline（现有）
│   ├─ useMixStage（现有）
│   └─ MixInspector / MixExportPanel
└─ shared
    ├─ transport 原语（播放/暂停/seek/逐帧；由各页 composable 实例化）
    ├─ useEditHistory（50 步）
    ├─ media cache（视频池、缩略图、波形）
    └─ handoff（跨页上下文）

后端
├─ edit-plan.ts（校验、布局、hash、初始化/迁移）
├─ edit-media.ts（源解析/探测/指纹/代理/导入/重链）
├─ edit-service.ts（草稿/版本/锁/聚合状态）
├─ edit-timeline.ts（EditPlan → 混音时间桥）
├─ edit-render.ts（静音剪辑轨/原声参考/预览区间）
├─ edit-preview.ts + edit-jobs.ts（精确预览与渲染队列）
├─ mix-plan.ts（现有，增加 EditPlan 时间桥与重新对齐）
├─ export-service.ts（现有，新增成片封装分支）
└─ episode_exports（统一任务/版本/复用）
```

**原则：**

- 共享底层原语，不共享业务组件；剪辑和混音各自维护交互状态。
- 每页一个 transport 实例（`useEditPlayback` / `useMixPlayback`）；页面切换时暂停并释放。
- 渲染编译器只消费持久化的 EditPlan，不依赖前端临时状态。
- 预览和导出使用同一份 EditPlan；预览允许简化转场，但必须明确标注「最终以导出为准」，且提供精确预览。

### 7.4 预览引擎

| 方案 | 优点 | 缺点 | 适用 |
| --- | --- | --- | --- |
| HTMLVideoElement 池 | 实现简单、浏览器解码、成本低 | 转场/合成不帧级；多视频同步难；同时解码数量有限 | MVP 硬切预览 |
| WebCodecs + Canvas/WebGL | 帧级、可合成、可做转场/滤镜 | 复杂度高、需要解封装、浏览器支持差异 | P2 评估 |
| 服务端代理/预渲染 | 与最终成片一致、实现简单 | 有延迟、占 CPU、不适合连续拖动 | 转场预览、精确校验 |
| ffmpeg.wasm | 浏览器内 FFmpeg | 内存/性能差、长视频不现实 | 不采用 |

**推荐混合：**

- 剪辑页：视频池播放当前片段，预加载下一片段；硬切即时；转场用简化着色器/CSS 叠化预览；精确帧用「生成预览」服务端渲染当前区间（0.5–30 秒）。
- 音频：复用 `useMixPlayback` 的 WebAudio 实时多轨监听，加载当前混音/原声；**剪辑页以音频为主时钟**，视频刷到音频位置，漂移阈值 120ms。
- 混音页：已使用 `useMixPlayback` 实时监听；**沿用视频主时钟**，音频跟随视频，漂移阈值 320ms；保留 30 秒渲染终检作为最终校验。
- 最终导出始终服务端 FFmpeg，不在浏览器渲染。

### 7.5 渲染管线

```text
EditPlan
  ↓ compileVideoGraph
视频轨：trim/setpts/scale/fps/format/xfade/concat
  ↓
cut.mp4（静音画面轨）+ audio-ref.m4a（源原声参考，含入出点/变速/间隙）
  ↓
MixPlan（绑定 editRevisionId + editSyncHash）
  ↓ compileMixGraph
音频：对白/原声/SFX/BGM/ducking/loudnorm/limiter
  ↓
mix.wav
  ↓
成片导出（render_mode='final'）：cut.mp4 + mix.wav + 字幕（软/硬）+ 校验
  ↓
episode_exports（kind='video' + render_mode，isCurrent）
```

**说明：**

- `cut.mp4` 不再携带原声；原声参考单独生成，避免合片原声与混音重复叠加。
- 混音页的“原声”轨读取 `audio-ref.m4a`，与 EditPlan 时间轴一一对应。
- 精确预览复用同一渲染链；交互预览允许简化转场，但必须标注。

**复用：**

- `ffmpeg-merge.ts` 的 concat/xfade/画布归一化；
- `export-render.ts` 的 loudness 与封装；
- `export-validation.ts` 的时长/分辨率/音频/字幕流校验；
- `episode_exports` 的复用键：`kind + preset + renderMode + editPlanHash + editSyncHash + dialogueSyncHash + mixRevisionId + subtitleMode + paramsJson`。

**任务模型：**

- 复用 `episode_exports.kind`：`video` / `mix` / `stems`。
- 成片导出用 `kind='video'` + `render_mode='final'|'temp'|'edit-only'`；不再新增 `edit-render`/`final-export` 任务类型（`edit-render.ts` 只是服务模块名）。
- 混音导出用现有 `kind='mix'`（`audio-wav`/`audio-m4a`）与 `kind='stems'`。
- 中间产物不进 `episode_exports`：`cut.mp4`/`audio-ref.m4a`/精确预览记录在 `edit_renders`。
- 状态机复用：`pending → running → completed | failed | cancelled`。
- 并发保护、重启恢复、复用键沿用现有实现，并纳入 `editRevisionId/mixRevisionId` 与哈希。

### 7.8 性能与容量

| 指标 | 目标 | 手段 |
| --- | --- | --- |
| 时间线规模（MVP 性能目标） | 10 分钟 / 100 片段 | 画布虚拟化、只渲染可视区 |
| 硬上限 | 200 片段 / 60 分钟 / 计划 JSON 8MB | 校验拦截；100–200 片段允许降级，不承诺原画帧率 |
| 预览帧率 | 1080p ≥ 24fps | 代理预览、视频池、限制同时解码 |
| Seek 响应 | < 200ms（代理） | 代理 + Range/206 + 关键帧间隔 |
| 自动保存 | < 300ms（本地） | 300ms 防抖 + 草稿表 |
| 导出 | 可取消、可重试、可复用 | 任务队列 + 并发保护 + 缓存 |
| 磁盘 | 可控 | 代理/缓存清理、导出保留策略 |

**代理策略：**

- 生成 720p H.264 代理，统一帧率/像素格式；
- 缩略图每 2s 一张，波形峰值缓存；
- 最终导出使用原素材，不使用代理；
- 代理生成异步，不阻塞进入工作台。

### 7.9 风险

| 风险 | 等级 | 缓解 |
| --- | --- | --- |
| 预览与成片不一致 | 高 | 同一 EditPlan 编译；黄金样片对比；转场用服务端代理预览 |
| 音画不同步/漂移 | 高 | 单时钟、WebAudio 调度、定期校正；长时长测试 |
| 混音 stale 未处理 | 高 | `editSyncHash`/`dialogueSyncHash` 绑定；导出前强校验；一键重对齐 |
| 编辑结果被覆盖 | 高 | `episodes.video_url` 单写入方；版本 + 自动保存 |
| 编码/分辨率不一致 | 中 | 代理/中间格式；最终用原素材 |
| 长时间线性能 | 中 | 虚拟化、代理、限制解码数 |
| 两页造成用户困惑 | 中 | 明确入口文案、顶部互跳、完成后引导回剪辑导出 |
| 范围失控 | 高 | 非目标 + 阶段门禁 |
| 许可证 | 低（自研） | 不引入 AGPL/GPL；只借鉴思路 |
| 磁盘/CPU | 中 | 队列、并发保护、缓存清理、时长限制 |

## 9. 验收标准

### 9.1 剪辑工作台黄金路径

1. 打开剧集 → 进入剪辑工作台，时间线加载镜头、字幕、只读音频参考。
2. 裁剪、分割、排序片段；加叠化；调整字幕文本/时间。
3. 拖动播放头、播放预览，音画同步；逐帧前进/后退可用。
4. 点击「调整这段声音」→ 混音工作台定位到同一播放头/台词；调整后返回。
5. 成片导出竖屏硬字幕/软字幕；进度可取消、失败可重试、可复用。
6. 成片可播放，时长/分辨率/音频流/字幕流校验通过。
7. 刷新后编辑仍在；撤销/重做正确；版本可恢复。

> 完整黄金路径 A–E（首次初剪、横屏与导入、跨页一致性、精修、并发/恢复）以《V3-剪辑工作台产品设计》12.1 与《V3-剪辑工作台技术架构设计》13.6 为准。

### 9.2 混音工作台黄金路径

1. 打开混音工作台，视频参考只读，音频时间线/波形/总线可用。
2. 调整对白/原声/BGM 音量、ducking，试听。
3. 导出混音 WAV/M4A/stems。
4. 顶部「打开剪辑」定位到同一播放头。
5. 画面变更后显示 stale 提示；一键重新对齐，人工调整保留。

### 9.3 跨工作台一致性

- 剪辑变更后，混音必须标记 stale；未重新对齐时，**最终成片导出必须硬阻断**；用户只能改走「临时导出（原声，不含混音）」或先去重新对齐。
- 混音变更后，剪辑页显示最新混音版本；预览使用最新混音。
- `episodes.video_url` 只由「设为当前成片」更新（删除回退除外）；重新合片不会覆盖用户剪辑。
- 两页跳转后播放头一致；不出现两个播放器同时播放。

### 9.4 性能指标

- MVP 性能目标：10 分钟 / 100 片段时间线，1080p 预览 ≥24fps；
- 硬上限：200 片段 / 60 分钟 / 8MB；100–200 片段允许降级；
- seek <200ms（代理）；
- 自动保存 <300ms（本地）；
- 导出可取消，取消后资源释放；
- 连续编辑 30 分钟无内存持续增长。

## 10. 决策与下一步

### 10.1 已确认决策

| 决策 | 选项 | 结论 |
| --- | --- | --- |
| 页面结构 | 两个独立路由 / 单页合并 | **两个独立路由**（已按用户要求） |
| 最终成片导出 | 剪辑页 / 混音页 / 独立导出中心 | **剪辑页**；混音页只导出混音 |
| 素材范围 | 仅生成镜头 / 生成镜头 + 有限导入 / 任意导入 | **生成镜头 + 有限导入** |
| 视频轨 | 单轨 / 多轨 | **MVP 单轨** |
| 平台 | Electron 桌面优先 / 浏览器优先 | **Electron 桌面优先** |
| AI 深度 | 手工 + 自动字幕 / AI 粗剪进 MVP | **手工 + 台词生成字幕（P0）**；自动字幕与 AI 粗剪均在 P2 评估，需单独技术选型 |
| 混音监听 | 沿用现有实时监听 / 仅渲染试听 | **沿用现有实时监听 + 渲染终检** |
| 迁移策略 | 新旧并存 / 达到 parity 后收敛 | **达到 parity 后收敛** |
