# 02 · 智能体 / 剪辑 / 三维技术分析

> 分析对象：`reference/reveric/`，`unstable @ 8ba248d`，v0.8.0。本文把三条主技术线拆开：智能体运行时、六轨剪辑、三维导演台；最后给出配置方式与对本项目的启示。

# A. Agent 运行时

## A1. 角色模型

Reveric 的 Agent 体系不是“一个聊天框 + 一组函数”，而是分层的：

| 概念 | 定义 | 代码位置 |
| --- | --- | --- |
| **Chat Orchestrator** | 聊天入口背后唯一的主控 Agent，用户不可选择；负责直接回答、调用工具、把任务委派给子 Agent | `lib/shared/services/ai/chat_turn_runner.dart`、`lib/shared/agent/` |
| **Chat Subagent** | 可被主控委派的专门 Agent，分用户可管理和内部两类 | `lib/shared/models/subagent.dart`、`lib/shared/services/ai/spawn_agent_handler.dart` |
| **Internal Subagent** | 只对主控可见、不出现在管理 UI 的子 Agent；`chronicler` 是典型 | `lib/shared/services/ai/builtin_agent_tools.dart:8-20` |
| **Spawn Session** | 一次委派创建的子会话，挂在源会话下，保存子 Agent 自己的历史 | `lib/shared/services/ai/spawn_agent_handler.dart`、`spawn_agent_run.dart` |
| **Session Handoff** | 在新会话中以“来源会话引用 + 当前指令”继续工作，不复制完整历史 | `lib/shared/services/ai/handoff_service.dart` |
| **Workflow** | 用户定义的可复用 AI 工作图，节点含 Agent/Loop/Split，按作品安装后运行 | `CONTEXT.md:130-165`、`lib/shared/services/production/` |
| **Codemode** | 让模型写一段受限脚本，批量串行调用数据工具与 `Run` 命令 | `lib/shared/services/ai/codemode/` |
| **Agent Skill** | 以 `name + prompt + references` 定义的技能包，加载后作为工具使用 | `lib/shared/models/agent_skill.dart:36-70` |

内置主 Agent 只有三种特殊模式：`monologue_narrator`、`roleplay_master`、`theater_actor`；普通聊天统一由运行时 `orchestrator` 承担，不再有 planner/writer/artist 之类的主 Agent 选择（`builtin_agent_tools.dart:12-17`）。内置 Chat Subagent 有 11 个：`explorer、writer、chronicler、review、style_polish、plot_architect、character_analyst、world_builder、pacing_expert、conflict_designer、theme_guardian`（`:20-32`）。

## A2. 单次 Agent 循环

`lib/shared/agent/agent.dart` 是运行时核心，文件头写明职责：**persona + 工具循环 + steer/followUp/fork/cancel + 上下文压缩**（`agent.dart:1-8`）。

一次 `process` 的主要阶段：

```
用户消息
  ↓
构建上下文（历史 + 规则 + 技能 + 工作区引用 + 当前活动资源）
  ↓
调用模型客户端（流式；OpenAI / Anthropic / Gemini / Codex / Responses）
  ↓
接收文本增量 / thinking 增量 / tool call
  ↓
工具分发（Host Tool / Run / Codemode / MCP）
  ↓
工具结果回填 → 继续下一轮（while true）
  ↓
收敛：正常结束 / 达到失控上限 / 用户取消 / 结构化失败
```

几个关键工程点：

- **流式重试**：最多 4 次额外重试；首事件或事件间静默超过 2 分钟即判定流卡死（`agent.dart:38-55`）。
- **失控收敛**：连续 5 轮“只思考不产出”或“正文截断续写”即终止（`:57-69`）。
- **截断续写**：正文撞到输出上限时，自动追加隐藏的 `<system-remind type='incomplete_continue'>` 要求从断点继续；thinking-only 也走同样机制（`:71-103`）。
- **半截工具调用**：参数未传完整的调用会被丢弃，并提示模型重新发起，避免模型误以为工具已执行（`:105-113`）。
- **上下文压缩**：`AgentContextManager` 在模型窗口使用到 80% 时触发压缩；未知模型用 200k 保守窗口；压缩切点优先落在 turn 边界（`lib/shared/agent/agent_context_manager.dart:18-45`）。
- **Hook 机制**：`beforeDone` 可注入验证、待办续跑、日志、trace；`VerificationHook` 会在完成前要求 Agent 自检产出和用户规则（`lib/shared/agent/hooks/verification_hook.dart:10-45`）。
- **工具白名单**：`HostToolPolicyDispatcher` 在“声明工具列表”和“实际执行”两个边界同时过滤，禁用的工具既不可见也不可执行（`lib/shared/services/ai/host_tool_policy.dart:11-40`）。

## A3. 多 Agent 编排

`lib/shared/agent/agent_orchestrator.dart` 是 Council / Theater / Monologue 共用的通用多 Agent 多轮编排器：

- 同一个 participant 在多轮中**复用同一个 `Agent` 实例**，因此历史与工具结果自然累积，业务层不用手工拼“之前的发言”（`agent_orchestrator.dart:36-45`）。
- 支持固定顺序或 `pickNext` 动态选择下一位发言者；支持流式 `onTextDelta` / `onToolCallStart` / `onToolCallResult`。
- 支持取消：`cancel()` 会取消所有活跃 Agent（`:47-53`）。
- 失败策略可选 `stopOnAgentError`；单 Agent 的结构化错误用 `AgentOrchestratorFailure` 表达（`:25-32`）。

这让“多角色讨论/剧场/独白”不是另一套运行时，而是同一个 Agent 内核的组合方式。

## A4. 子 Agent 与后台委派

`SpawnAgentHandler` 负责创建或续跑独立子运行（`spawn_agent_handler.dart:1-10`）：

- **身份在启动时冻结**：`runId`、`subSessionId`、`parentSessionId`、`sourceTurnId`、`callId` 等在构造时固定；运行状态有 `initializing / running / stopping / completed / failed / cancelled`（`spawn_agent_run.dart:30-80`）。
- **资源一次性移交**：`SpawnAgentResources` 持有模型客户端与工具分发器，`release()` 幂等释放；初始化失败时由工厂释放部分资源（`spawn_agent_run.dart:22-48`）。
- **子会话回填**：持久化完成后通过 `onSessionStarted` 把 `session_id` 回填到父级 tool call（`spawn_agent_handler.dart:70-73`）。
- **事件透传**：子会话消息跑完才落库，运行中通过 `onSubAgentEvent` 把动态事件透传给父级 UI（`:75-77`）。
- **上下文用量**：结束时报告子会话上下文使用情况，供主控决定是否继续复用或新开。
- **工具限制**：`builtinDefaultSubAgentDisabledToolNames` 默认禁用 `SpawnAgent/ForkAgent/AskUser/SuggestNextAction/SendAgentMessage/StopAgent`，`explorer` 还额外禁用 `Create/Write/Edit/Replace/Remove/Run/TodoWrite`（`builtin_agent_tools.dart:35-48`）。这防止子 Agent 递归委派或越权写入。

主控委派时使用 `SpawnAgent` 工具；子 Agent 完成后，结果会以工具结果或后台通知的形式回到主控。`Stop Reply` 只停止主控当前工作，后台子任务继续；`Stop All` 才会同时停止子任务（`CONTEXT.md:88-100`）。

## A5. 会话交接（Handoff）

`handoff_service.dart` 明确区分“交接”与“复制历史”：

- 只加载真实存在、且有已保存消息的来源会话；不会凭空创建数据（`handoff_service.dart:18-35`）。
- 生成一条 `<user-remind type="session" path="ai-session:...">` 引用，告诉新会话“这是从哪个会话继续的；需要早期细节时用 `Run sessions` 按需读取”，不自动复制消息、不生成摘要（`:50-73`）。
- 这样新会话上下文干净，来源历史仍可被工具按需检索，避免把长历史整段塞进新窗口。

## A6. 工具面

Agent 可见的工具大致分五类：

1. **Host 工具**：`Create`、`Write`、`Edit`、`Replace`、`Remove`、`Read`、`Glob`、`Grep`、`Run`、`TodoWrite`、`SpawnAgent`、`ForkAgent`、`AskUser`、`SuggestNextAction`、`SendAgentMessage`、`StopAgent`、`Codemode`、`AgentSkill` 等（`lib/shared/services/ai/tools.dart` 及其拆分文件）。
2. **`Run` 命令命名空间**：`assets、stagings、styles、settings、providers、operations、files、ffmpeg、production、editing、character、item、agent-skills、themes、subagents、novel、agent-rules、sessions、map、notify`（`lib/shared/services/ai/tools_run.dart:163-454`）。每个子命令都绑定权限声明和 Codemode 访问级别。
3. **Codemode**：模型写 FJS 脚本，串行调用允许的数据工具和 `Run` 命令；有独立的运行时限制与调度器（`lib/shared/services/ai/codemode/orchestrator.dart`、`runtime.dart`、`scheduler.dart`）。
4. **Agent Skills**：技能以全局唯一 `name` 作为工具名；加载后返回 instructions + references 清单（`lib/shared/models/agent_skill.dart:13-35`）。
5. **MCP 工具**：MCP server 暴露的工具直接以原名或 `mcp__` 前缀出现在工具列表；调用走 `McpToolDispatcher`（详见 04 的绕过问题）。

## A7. 权限与审批

Reveric 的权限模型是“**动作 × 作用域 × 决策**”：

- **动作**只有 5 个：`generation.image`、`generation.video`、`generation.audio`、`files.read`、`files.remove`（`lib/shared/models/tool_permission.dart:14-20`）。
- **作用域**从窄到宽：`session → episode → work → global`；解析时按此顺序取第一条匹配规则（`tool_permission.dart:65-80`、`lib/shared/services/tool_permissions.dart:47-65`）。
- **决策**：`allow / ask / deny`；没有规则时默认 `ask`（`tool_permissions.dart:61-64`）。
- **审批门禁流程**（`lib/shared/services/tool_permission_gate.dart:24-125`）：
  1. 解析最新规则；`deny` 直接抛错。
  2. `ask` 且尚未批准 → 生成审批卡（冻结参数、目标路径、动作、作用域）。
  3. 等待用户决定；支持取消，取消会撤下审批卡。
  4. 批准后执行 `verifyTarget()`，再重新解析最新规则（防止审批期间规则被改）。
  5. 如果最新规则变成 `deny`，仍然拒绝；如果变成 `ask` 且没批准过，继续等待。
  6. 全程检查取消令牌。
- **拒绝提示**很明确：`_deniedHint` 要求 Agent “不要重试、不要换工具绕过，告诉用户未执行并询问下一步”（`tool_permission_gate.dart:127-133`）。
- **参数冻结**：`freezeToolArguments` 深拷贝为不可变 Map/List，防止审批后 UI 或模型篡改请求（`tool_permission.dart:108-131`）。

这套设计在“内置工具”范围内是扎实的：参数不可变、目标二次验证、规则实时重解析、取消可传播、拒绝有明确语义。

但它只覆盖 5 个动作；`editing`、`stagings`、`agent-skills`、`ffmpeg.execute` 等大量操作要么 `RunPermission.none()`，要么只要求 `files.read`。这会在 04 展开。

## A8. Agent 配置面

一个 Agent 的可配置项包括：

- provider、model、reasoning effort；
- system prompt / 用户自定义 prompt；
- 可用工具白名单与禁用集合；
- 可委派的 Subagent 列表；
- 可加载的 Agent Skill 列表；
- Agent Rules（长期遵守的写作规则）；
- 上下文引用（AI Context Reference）与当前活动工作区目标；
- 是否启用验证 Hook、待办续跑 Hook、trace Hook。

供应商侧通过 `AiProviderType` + `AiModelKind` + `ImageProtocol/VideoProtocol/AudioProtocol` 描述能力，模型目录由 `models_catalog.dart` 提供（`lib/shared/models/ai_provider.dart`、`models_catalog.dart`）。这意味着新增一家供应商主要是“加一个类型配置 + 协议适配”，而不是改 Agent 内核。

## A9. Agent 设计评价

**强项**

- 长任务收敛机制完整：流式超时、重试、thinking-only、截断续写、半截工具调用、循环检测、上下文压缩。
- 工具执行与 UI 状态分离：`ToolOperationRecord` 有 `waiting_approval / queued / running / cancelling / completed / failed / cancelled / interrupted` 等状态，支持后台任务与一次性完成通知（`lib/shared/services/ai/tool_operations.dart:18-60`）。
- 子 Agent 有真正的会话隔离与资源生命周期，不是“在主会话里换个 prompt”。
- 权限门禁的“冻结参数 + 重验证 + 最新规则”是值得直接借鉴的实现。

**弱项**

- 权限目录太小，无法表达“删除一个剪辑工程”“写入一个分镜”“安装一个技能”这类高风险动作。
- MCP 工具绕过统一门禁；插件 HTTP 没有网络权限；详见 04。
- 多 Agent 模式的配置面很宽，普通用户理解成本高；默认值是否安全依赖实现细节。

# B. 六轨剪辑

## B1. 数据模型：帧是唯一时间单位

`lib/shared/models/editing/document.dart` 定义了剪辑工程：

- 固定 **24fps**、**48kHz** 采样率、每帧 2,000 采样（`document.dart:6-10`）。
- 时间统一用 **帧** 表示；需要微秒时用 `editingMicroseconds(frames)` 转换。
- 轨道角色：`main`（唯一磁吸主视频轨）、`overlay`、`subtitle`、`dialogue`、`sfx`、`music`、`audio`（`document.dart:17-28`）。README 说的“6 轨”是业务口径：视频、叠加、对白、音效、音乐、字幕；`audio` 是通用音频角色。
- 素材按 `kind` 限定可放入的角色：视频只能进 `main/overlay`，音频只能进 `dialogue/sfx/music/audio`，文本只能进 `subtitle`（`:27-31`）。
- `EditingSource` 固定素材身份、类型、时长与是否有原声；视频原声直接从源文件混音（`:33-56`）。
- `EditingClip` 保存轨道、起止帧、源入点、变换、音量/淡入淡出、字幕样式、制作来源等；`EditingDocument` 负责整体校验与序列化（`:300-530`）。

关键设计：**素材路径不写进剪辑文档**，只保存 `assetId`，渲染时从素材库解析。这样工程可迁移、可校验素材缺失，也避免把绝对路径泄漏进作品文件。

## B2. 命令面

`lib/shared/services/editing/commands.dart` 是纯函数式命令层，所有变更都返回新文档：

| 命令 | 作用 |
| --- | --- |
| `setRatio` | 设置画幅比例 |
| `updateTrack` / `addAudioTrack` / `reorderTrack` / `removeTrack` | 轨道增删改排序 |
| `move` / `reorder` / `insertMain` | 片段移动、排序、插入主轨 |
| `trim` / `split` / `remove` / `update` / `place` | 修剪、分割、删除、更新、放置 |
| `addText` / `replace` | 添加字幕、替换素材 |
| `extractAudio` | 从视频分离音频 |
| `snap` | 吸附计算 |

命令层不碰数据库、不碰 UI，便于测试与 Agent 调用。

## B3. 会话与撤销

`EditingSession`（`lib/shared/services/editing/session.dart`）负责：

- 持有当前文档、已保存快照、标题、选中片段；
- **撤销/重做**：`_past` / `_future`，最多保留 100 步（`:83-99`）；
- **脏状态**：通过文档身份与标题比较，而不是逐字段 diff；
- **修订冲突**：保存时带 `expectedRevision`，底层 `EditingDao.save` 在修订不匹配时抛 `EditingConflict`（`service.dart:34-52`）；
- **串行保存**：`_pending` 串行化自动保存，失败时保留内存修改；
- **租约/驱逐**：`retain()` 计数 + `evictable` 判断，避免正在编辑的会话被缓存回收（`:20-35`）；
- **素材校验**：加载后异步 `verify`，缺失素材以 `EditingSourceProblem` 暴露给 UI（`:64-76`）。

## B4. 渲染管线

`lib/shared/services/editing/render_service.dart` 是完整的 ffmpeg 渲染编排：

- **分块渲染**：每 120 帧一块（`render_service.dart:52`），逐块生成后拼接；预览与成片共用同一套分块规则，避免“预览能过、成片失败”。
- **2GB 预览缓存**：缓存目录在作品库下，跨启动复用；按 `video.mp4` 修改时间做 LRU 淘汰；启动时清理超过 1 小时的半成品块（`:53-85`）。
- **串行队列**：`_tail` 保证同一时间只有一个渲染任务；新的预览会取消旧的预览（`:95-125`）。
- **字幕三种模式**：`burn`（烧录）、`srt`（另存 SRT，标题仍烧录）、`none`（`EditingSubtitles`，`:31-35`、`:200-205`）。
- **进度**：`EditingProgress(stage, progress)`，阶段含 `verify / render ...`，UI 可直接展示。
- **磁盘空间**：渲染前检查空间，不足抛 `EditingInsufficientSpace`。
- **取消**：`MediaCancellation` 贯穿渲染与 ffmpeg 子进程；取消会终止任务。
- **输出**：通过 `FfmpegRunner` 执行；输出目标经过 `FfmpegOutputs.resolveTarget` 校验（`lib/shared/services/ai/ffmpeg/command.dart:249-263`）。

## B5. Agent 剪辑

Agent 不直接改 `EditingDocument`，而是走 `Run editing` 命令：

- `EditingAgentCommands.parse` 严格限制：命令必须是 1–100 个对象，总 JSON ≤ 256 KiB，未知字段直接拒绝（`lib/shared/services/editing/agent_commands.dart:23-45`）。
- 每个命令复用 `EditingCommands` 的逐步校验，返回实际影响范围（`before/after` 的片段区间），便于主控向用户解释“改了什么”（`:47-100`）。
- Agent 可执行 `list / read / create / apply / undo / redo / preview / frames / cleanup`，但这些子命令的权限全部是 `RunPermission.none()`（`tools_run.dart:334-359`）。
- `frames` 在 Codemode 中被明确拒绝，必须通过直接 `Run` 调用查看帧图，避免脚本批量读取图像内容（`:341-345`）。

**评价**：命令面设计得很好——可审计、可回放、有影响范围；但“权限为 none”意味着 Agent 可以在没有用户审批的情况下创建、修改、撤销、清理剪辑工程。对本地单人创作工具可以接受，对多人/半自动生产则是风险。

## B6. 剪辑 UI 结构

`lib/desktop/features/editing/` 下按区域拆分：

- `region.dart`：整体布局与状态组合；
- `timeline.dart`：时间线、标尺、轨道、播放头；
- `clip.dart`：片段渲染、拖拽、修剪手柄；
- `assets.dart`：素材库与拖入；
- `shell.dart`：页面壳与工具栏；
- 预览播放器复用 `production/playback_service.dart` 与 `EditingRenderService`。

时间线交互：主轨磁吸、片段吸附（`snap`）、分割/修剪、轨道锁定/隐藏/静音、缩放与横向滚动。预览采用“分块渲染 + 缓存”，不是实时逐帧合成；这对本地 ffmpeg 方案是合理取舍。

# C. 3D 导演台

## C1. 工程文档

`lib/shared/models/director/document.dart` 是一个严格的版本化 JSON 文档：

- 必需字段：`format version id revision title units up_axis fps duration_frames output objects cameras lighting tracks motion_paths camera_moves camera_cuts default_camera_id`（`document.dart:27-31`）。
- 上限：5 MiB；128 条属性轨、128 条运动路径、256 个运镜、2,048 个 unit；最多 6 个演员、20 个道具、8 台相机；24–720 帧，固定 24fps（`:33-36`）。
- 解析时先做大小检查，再用 `StrictJson` 解析、校验并归一化旋转；保存、插值、渲染共用规范化后的值（`:46-72`）。
- 对象、相机、切镜以 JSON 暴露；属性轨、运镜、路径在采样时读预解析类型，编辑统一改 JSON（`:100-125`）。
- `revision` 每次编辑递增；`businessContent` 用于判断“业务内容是否变化”，避免保存时把纯 UI 状态算成修改。

## C2. 场景构建

`lib/shared/services/director/scene_builder.dart` 把文档变成 `flutter_scene` 场景：

- 设置环境光强度、方向光方向/强度、MSAA 抗锯齿；
- 可选地面（20×20 的薄盒）；
- 遍历 `objects`：`actor` 用 `ActorModels.instantiate(geometry_key, material)` 实例化 GLB 角色；`prop` 从预加载的 `PropModels` 克隆；
- 为每个对象建立 `roots` 与 `owners` 映射，供拾取/控制；
- PBR 材质：`metallic=0`、`roughness=0.85`，颜色来自文档（`scene_builder.dart:31-100`）。

角色是**骨架 + 姿态**：`lib/shared/models/director/rig.dart`、`pose.dart`、`rig_data.dart` 定义骨骼与姿态；`ActorModels` 负责 GLB 资源加载与实例化。

## C3. 采样与数学

`lib/shared/models/director/sampling.dart` + `animation_math.dart` 负责时间轴采样：

- 平滑插值：`smooth(u) = u²(3-2u)`（smoothstep）。
- 四元数：`slerp` 带最短路径处理与线性退化；`eulerQuaternion` / `quaternionEuler` 做 YXZ 欧拉角与四元数互转；俯仰到 ±90° 时 roll 归零，避免万向锁异常（`animation_math.dart:13-55`）。
- 相机：`camera.dart` 处理朝向、焦距、光圈、焦点距离、目标点；支持 `camera_target` 与自由朝向。
- 路径/运镜：`path.dart`、`properties.dart` 定义关键帧与通道；`bake.dart` 把路径/运镜转换为**误差受控的稀疏属性键**，并对整条时间轴验证（`bake.dart:12-60`）。
- 采样 API 每次最多 12 帧，返回对象、相机、有效相机、灯光与诊断（`query.dart:26-55`）。

## C4. 离屏抽帧

`lib/shared/services/director/renderer.dart`：

- 复用 `SceneBuilder`，按 `document.encode()` 判断是否需要重建；重建时先释放旧 builder。
- 用 `ui.PictureRecorder` 绘制到指定尺寸，`Scene.render(camera, canvas, viewport, pixelRatio: 1)`。
- `picture.toImage(width, height)` → PNG 字节；每帧独立持有 Picture/Image，并在 `finally` 中释放。
- 捕获返回 `Uint8List`，供 Agent 查看构图或导出参考图。

这是“用渲染器出图”而不是“截 UI 屏”：抽帧尺寸由文档 `output` 决定，不受窗口大小影响，适合作为视频生成的首帧/参考帧。

## C5. 导出与检查

- `export_task.dart` / `file_output.dart`：导出任务与文件输出。
- `contact_sheet.dart`：多帧拼图，便于快速检查一段运镜。
- `frame_validation.dart`：帧范围、相机、对象可见性等校验。
- `bake.dart`：把连续控制曲线烘焙为关键帧，保证渲染器只处理有限采样点。

## C6. Agent 与 3D

`Run stagings` 是导演工程的 Agent 命令面（`tools_run.dart:175-207`），支持：

```
schema / presets / sample / frames / list / create / read / apply / write / restore / remove / preview
```

- Agent 可以读取 schema、列出工程、创建工程、读写/应用/恢复工程、采样、抽帧、预览。
- `sample` 最多 12 帧，适合“检查构图/机位”而不是批量导出。
- `frames` 生成检查图；`preview` 生成预览。
- 这些子命令同样是 `RunPermission.none()`（`tools_run.dart:194-205`）。

**评价**：3D 导演台不是实时游戏引擎，而是“**可编排的镜头预演器**”：有限角色/道具/相机、固定帧率、离屏抽帧、可烘焙运镜。它服务于“给视频生成提供构图参考”，而不是做最终 3D 动画。这个边界划得很清楚，工程复杂度可控。

## C7. 导演台 UI

`lib/shared/widgets/director/` 与 `lib/shared/theme/reveric_spacing.dart` 定义了固定布局：

- 左侧分类栏 56px、分类 tab 46px；
- 侧面板 256px、侧栏 312px、检查器 288px；
- 视口预览 280px、底部 dock 46px；
- 时间线标签 300px（紧凑 136px）、标尺 28px、行高 26px、最大高度 236px；
- 历史面板 300px、最大高度 320px（`reveric_spacing.dart:43-70`）。

组件包括 `stage.dart`（视口）、`gizmo.dart`（变换手柄）、`timeline.dart` / `timeline_bar.dart`（时间线）、`inspector/`（属性）、`panels/`（相机、运镜、路径）、`paths/`（路径编辑）、`sidebar.dart`、`header.dart`、`history_panel.dart`。交互模型是“选择对象 → 视口 gizmo 变换 / 检查器数值编辑 → 时间线打关键帧”。

# D. 配置面

## D1. 模型与供应商

- 供应商类型 20+，各自声明支持的 `AiModelKind` 与协议（图像/视频/音频）；不支持的能力不会出现在 UI。
- 模型目录 `models_catalog.dart` 提供上下文窗口、能力、默认推理强度等；未知模型用保守默认值。
- 代理：支持 HTTP/SOCKS5 代理，供应商配置里有 `proxyPassword` 等字段。
- 对象存储：S3 兼容配置（AK/SK）用于素材外置。

## D2. Agent 配置

- 每个 Subagent 可单独指定 provider/model/reasoning effort（`subagent.dart:40-60`）。
- Agent Rules 是长期行为约束；Agent Skills 是可加载的能力包；两者都进入系统提示或工具列表。
- MCP server 可配置 stdio（command/args/cwd/env）或 Streamable HTTP（URL/headers/OAuth）。
- Workflow 定义是全局的，按作品安装；V1 支持手动与每日/每周/每月定时触发（`CONTEXT.md:146-165`）。

## D3. 剪辑/导演工程配置

- 剪辑：画幅比例、轨道顺序/锁定/隐藏/静音、字幕样式、渲染分辨率与字幕模式。
- 导演：画幅模式（固定比例或自适应）、输出尺寸、帧率固定 24、背景色、灯光、相机、运镜、路径、切镜。
- 两者都保存为版本化 JSON，可被 Agent 读写；剪辑的 revision 冲突检测更严格。

# E. 对本项目的启示

1. **把“工程文档”作为跨模块的第一公民**：剪辑 `EditingDocument`、导演 `DirectorDocument` 都是可序列化、可校验、可版本化、可被 Agent 命令驱动的文档。混音、配音、分镜也应采用同样的“文档 + 命令 + 渲染”结构，而不是散落的 UI 状态。
2. **时间单位要唯一**：Reveric 剪辑用帧、音频用采样、导演用帧，三者边界清晰。混音工作台如果同时用秒、毫秒、采样，容易出现漂移；应确定主时钟与换算规则。
3. **Agent 操作命令面，不操作数据库**：`Run editing` / `Run stagings` 的严格解析、命令数量上限、影响范围返回，值得直接借鉴到本项目的 ComfyUI 工作流、配音、混音操作。
4. **长任务需要收敛机制**：流式超时、重试上限、thinking-only 上限、截断续写、半截工具调用处理、上下文压缩，这些不是“优化项”，而是 Agent 能否稳定跑完一集的关键。
5. **3D 预演的边界要明确**：如果本项目要做“3D 分镜/机位预演”，Reveric 的“有限角色 + 固定帧率 + 离屏抽帧 + 烘焙运镜”是可控路径；不要一上来做实时引擎。
6. **权限目录要覆盖真实高风险动作**：Reveric 的 5 个动作不够；本项目至少应覆盖生成、文件读写删、工程删除、工作流修改、模型配置修改、插件/MCP 安装与调用。
