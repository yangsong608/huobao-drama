# 01 · 项目总览与架构

> 分析对象：`reference/reveric/`，`unstable @ 8ba248d`，v0.8.0。证据行号均指该提交。

## 1. 产品定位

Reveric（幻界）把自己定义为 **“AI Native 桌面创作工作台，读懂整部作品，和你一起从小说写到成片”**：

- 本地优先：作品保存在设备上的 SQLite，模型由用户自带（BYOK），直连 OpenAI、Anthropic、Gemini、DeepSeek、Seedance、H3 或自建网关。
- 全流程：长篇小说 → 剧本改编 → 无限画布/分镜与素材生产 → 3D 导演台 → 六轨剪辑成片。
- Agent 是工作区的一部分：不是独立聊天窗口，而是能直接读写小说、剧本、画布、导演台和剪辑工程的操作者。

证据：`reference/reveric/README.md:52-61`；`reference/reveric/PRODUCT.md:5-25`。

目标用户是 **长篇虚构写作者**：需要长时间连续工作，在提纲、人物、世界观、章节草稿、修订与 AI 润色之间来回切换；他们要的是“有纪律的创作协作者”，而不是通用聊天助手。品牌人格是 **calm, literary, deliberate**（平静、文学性、克制）。

## 2. 功能矩阵与实现位置

| 模块 | 用户能力 | 主要代码位置 | 成熟度判断 |
| --- | --- | --- | --- |
| 小说创作 | 章节/大纲、自动保存、历史对比、人物/势力/伏笔/地图设定、实体关系图谱 | `lib/desktop/pages/novel_editor.dart`、`lib/shared/services/novel_*`、`lib/shared/entity_graph/` | 核心成熟，页面体量极大（`novel_editor.dart` 超过 4,800 行） |
| 剧本改编 | 场次、角色、对白、动作、转场；剧本排版与 AI 改编 | `lib/desktop/features/screenplay/`、`lib/shared/services/screenplay*`、`docs/adr/0019-0022` | 成熟，且有专门的剧本写入约束 ADR |
| 无限画布 | 节点式分镜、角色定妆、音视频资产、生图流 | `lib/desktop/features/canvas/`、`lib/shared/services/canvas_service.dart`、`production/` | 成熟，画布 v1 明确“Agent 写、用户读” |
| 制片/素材生产 | 图像、视频、音频生成；风格、主体引用、批量网格、全景、取帧 | `lib/shared/services/production/`（40+ orchestrator/service） | 成熟，是 Agent 生成素材的主通道 |

| 多轨剪辑 | 6 轨时间线、分割/修剪/吸附、预览、导出 | `lib/shared/services/editing/`、`lib/desktop/features/editing/` | 成熟，具备撤销、修订冲突、分块预览缓存 |
| Agent 对话 | 主控编排、子 Agent、后台委派、会话交接、工具审批、技能、MCP、Codemode | `lib/shared/agent/`、`lib/shared/services/ai/` | 核心成熟，是产品差异点 |
| 多 Agent 模式 | Council、Theater、Monologue、Roleplay、Narration | `lib/shared/services/ai/agent_council_orchestrator.dart`、`monologue_*`、`roleplay_*`、`lib/desktop/features/{council,theater,monologue,narration}/` | 可用，属于“专用编排 + 现有 Agent 运行时”的组合 |
| 阅读/故事地图/封面 | 阅读进度、地图生成、封面工作室 | `reading/`、`map/`、`cover_studio/` | 辅助能力，完整度低于主链路 |
| 插件系统 | 本地插件、TSX 页面、任务、SQLite 存储、密钥、HTTP | `lib/shared/services/plugins/`、`plugins/` | 能力完整，但安全边界偏弱（见 04） |
| MCP | stdio / Streamable HTTP、OAuth、工具发现与调用 | `lib/shared/services/mcp/` | 可用，但绕过统一审批（见 04） |

桌面端共 15 个 feature 目录：`agent_skills, asset, canvas, council, cover_studio, editing, map, monologue, narration, production, reading, roleplay, screenplay, storyboard, theater`。移动端有独立壳层，但能力明显少于桌面。

### 3.1 分层

```
lib/
├── desktop/                 # 桌面壳与页面
│   ├── pages/               # 组合页面（home、novel_editor、settings、workspace）
│   ├── features/            # 领域区域（canvas、editing、director 相关在 shared）
│   └── widgets/             # 侧栏、页头、设置、AI 面板等
├── mobile/                  # 移动端壳、页面、provider、widget
├── shared/
│   ├── agent/               # Agent 运行时（客户端、循环、消息、工具分发、hooks）
│   ├── services/            # 业务服务与 orchestrator（AI、编辑、导演、插件、MCP、备份…）
│   ├── models/              # 领域模型（DB row、JSON 文档、配置）
│   ├── database/            # Drift schema、DAO、迁移
│   ├── widgets/             # 跨页面业务组件
│   ├── components/          # 设计系统基础组件
│   ├── theme/               # 颜色、字体、间距、主题
│   ├── providers/           # Riverpod providers
│   └── utils/ hooks/ ...
└── third/                   # 内部复用的通用库（flow、form、toon）
```

`AGENTS.md` 明确要求：Page/shell 只负责组合区域和管理生命周期；region 拥有独立可见区域；本地编辑态用 Hooks/`lib/third/form`；跨页面状态用 Riverpod；多步 DB/文件/网络/AI 写入用 Orchestrator（`reference/reveric/AGENTS.md:26-27`）。代码基本遵循这一约定。

### 3.2 状态与数据

- **Riverpod 3** 是跨页面状态主通道，配合 `riverpod_annotation` 生成 provider。
- **MobX** 用于部分高频局部状态（`flutter_mobx` 在依赖中）。
- **Drift/SQLite** 是本地数据主存储：`lib/shared/database/app_database.dart` 定义 37 张表，覆盖作品、AI 供应商、Agent/会话、技能、插件、生产任务、权限规则等。
- 每部作品的正文与内容数据放在独立 SQLite：`Application Support/novel_workspaces/<novelId>.sqlite`；主库 `reveric.sqlite` 保存作品索引、配置、会话、任务与权限。备份同时包含主库与整个 `novel_workspaces` 目录（`lib/shared/services/backup_service.dart:159-167`、`lib/shared/services/novel_content.dart:1563-1573`）。
- 应用支持完整的本地数据库迁移：`schemaVersion` 在 `app_database.dart:1277`，迁移逻辑集中在同文件。

### 3.3 AI 与外部能力

- **模型客户端**：`openai_dart`、`anthropic_sdk_dart`、`googleai_dart`、`open_responses`，另有自研 Codex 客户端（`lib/shared/agent/client/codex_client.dart`）。
- **供应商抽象**：`AiProviderType` 覆盖 20+ 家（OpenAI、OpenAI-compatible、OpenRouter、Anthropic、Gemini、DeepSeek、Moonshot、智谱、豆包、火山、MiniMax、秘塔、AtlasCloud、PureFox、MOSS 等），并按 `AiModelKind`（chat/image/video/audio）声明图像、视频、音频协议（`lib/shared/models/ai_provider.dart:28-120`）。
- **媒体处理**：`fvp`/`video_player`（本地替换）、`ffmpeg_kit_flutter_new`（本地替换）、`flutter_scene 0.24.3`（3D）、`image`、`blurhash_dart`、`thumbhash`。
- **Agent 扩展**：`fjs`（QuickJS 运行时，本地替换）、`mcp_dart`（本地替换）、`a2ui_core`（插件 UI 协议）。
- **原生桥**：`flutter_rust_bridge 2.12.0`，Rust `1.99.1`，用于 FJS、深度估计等原生能力。

`app_database.dart` 中的 37 张表可以按领域分组：

| 领域 | 表 |
| --- | --- |

值得注意的是：**正文内容不放在 `reveric.sqlite`**，而是按作品写入 `novel_workspaces/<novelId>.sqlite`（每部作品一个独立内容库）；主库保存索引、配置、会话、任务与权限。这个拆分让“单部作品可单独备份/迁移”和“应用配置可整体恢复”成为两个不同粒度。

## 5. 构建与运行

- Flutter 版本由 FVM 固定为提交 `0b771a584214b44aa1f94f9707f2756207356f41`（`reference/reveric/.fvmrc:2`），不能用 stable/master 替代。
- Rust 固定 `1.99.1`；`third/` 下是本地修改过的依赖，不能替换成公开包。
- 发布架构：macOS arm64、Windows x64、Android arm64-v8a（`DEVELOPMENT.md:3`）。
- 构建入口：`make run-macos` / `make build-macos` / `make build-macos-release`；Windows 用 `build-windows.ps1`；Android 用 `build-android.sh`；安装包用 Fastforge 0.6.6。
- macOS 首次构建需准备 ONNX Runtime（深度估计）；打包 DMG 还需要 Node/npm/appdmg。
- 当前 macOS 工程使用 ad-hoc 签名（`CODE_SIGN_IDENTITY = "-"`，`macos/Runner.xcodeproj/project.pbxproj:574,651,707`），构建脚本没有 notarize 步骤。

## 6. 工程质量观察

**做得好的地方**

- **规则化**：`AGENTS.md` + `.agents/rules/*` 把目录、状态、表单、性能、i18n、错误处理、安全边界写成硬约束；Dart 文件头统一声明职责与关联文件，降低跨文件理解成本。
- **测试体量大**：878 个测试文件，覆盖服务、DAO、组件、集成与 Patrol UI 测试；对权限、备份、路径校验这类高风险逻辑有针对性测试。
- **领域拆分清楚**：编辑、导演、生产、Agent、插件各自有 models/services/widgets 三层，orchestrator 负责多步写入，页面只做组合。
- **文档密度高**：`docs/adr/` 有 20+ 篇决策记录，`designs/SYSTEM.md` 是跨端视觉契约，`CONTEXT.md` 维护 AI 领域术语。

**需要警惕的地方**

- **巨型文件**：`novel_editor.dart` 超过 4,800 行，`app_database.dart` 超过 1,300 行，局部复杂度高，修改回归面大。
- **文档漂移**：`DESIGN.md` 仍描述暖羊皮纸方向，与运行时默认的 Classic 主题不一致；“玉白·墨玉”（Reveric）是可切换主题，不是默认外观；`designs/SYSTEM.md` 内部对按钮圆角也有 999 与 8px 两种说法（见 03）。
- **“约定强于机制”**：权限、安全、备份的关键靠调用方遵守约定，部分破坏性操作没有统一门禁；这会在 04 展开。
- **单机复杂度**：37 张表、20+ 供应商协议、插件/MCP/技能三套扩展机制同时存在，新维护者的理解成本不低。

## 7. 对 huobao-drama 的架构启示

1. **“文档 + 命令 + 渲染”是跨模块可复用的骨架**：剪辑和 3D 都用版本化文档承载状态，用命令做变更，用独立渲染器出结果。这个骨架也适合短剧生产中的分镜、配音、混音工程。
2. **Agent 应该操作领域命令，而不是直接改数据库**：Reveric 的 `Run editing ...` / `Run stagings ...` 把 Agent 限制在受校验的命令面上，变更可审计、可回放，这比让模型直接写文件/表更可控。
3. **本地优先不等于本地简单**：作品文件与配置库分离、分块预览缓存、修订号冲突检测、软删除与备份，都是“本地优先”真正落地时必须补齐的工程件。
4. **扩展机制要有统一边界**：插件、MCP、技能三套机制各自很强，但权限模型没有覆盖全部入口，最终形成安全洼地；扩展点越多，越需要单一的策略执行点。
