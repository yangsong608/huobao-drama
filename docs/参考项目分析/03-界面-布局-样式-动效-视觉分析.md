## 2. 运行时第一结论：默认主题是 Classic，不是玉白·墨玉

这是本次运行验证推翻的一条旧结论，必须先说清楚。

| 证据 | 结论 |
| --- | --- |
| `lib/shared/models/app_settings_aggregate_data.dart:162` | 默认设置里 `theme: 'classic'` |
| `lib/shared/hooks/use_onboarding_setup.dart:70` | 首次引导写入 `AppTheme.classic` |
| `assets/translations/zh-CN/settings.json` | “经典：极简、永恒、高对比度”；“Reveric：象牙纸面，墨蓝落笔”；“象牙”另有一套 |
| 运行截图 `01-首页深色经典.png`、`03-小说正文编辑.png` | 首次启动就是近黑表面 + 白色主按钮 + 无绿色点缀 |
| 运行截图 `35-首页玉白墨玉深色.png`、`36-首页玉白墨玉浅色.png` | 在设置中手动切到 Reveric 后，才出现墨绿黑底 + 翡翠强调 + 玉白浅色 |

因此，**“冷调玉白 + 墨绿主操作 + 翡翠点缀”是 Reveric 主题的语言，不是开箱默认界面**。默认 Classic 的语言是：

- 浅色：纯白画布/卡片、浅灰侧栏、黑色主按钮、黑白高对比；
- 深色：近黑表面、白色主按钮、白色标题、细灰描边；
- 强调色几乎不参与装饰，只用于选中、链接与状态。

`designs/SYSTEM.md` 与 `reveric_colors.dart` 仍可作为 **Reveric 主题**的运行时真源；`DESIGN.md` 的暖羊皮纸方向依然过时。问题不在“文档全错”，而在文档没有声明“这套语言只属于哪个主题”。

### 2.1 三套主题的定位

| 主题 | 代码标识 | 运行观感 | 适用 |
| --- | --- | --- | --- |
| **经典** | `classic` | 极简黑白、高对比、接近工具软件 | 默认；长时间管理、剪辑、设置 |
| **Reveric** | `reveric` | 玉白/墨玉、翡翠点缀、文学感 | 写作、阅读、沉浸创作 |
| **象牙** | `ivory` | 暖奶油纸感、低对比、旧纸气质 | 偏好暖色的写作者；未在运行中验证 |

主题在“设置 → 外观”中切换（`31-外观设置.png`、`32-外观浅色.png`），背景可单独设置（`33-背景设置.png`）。这说明主题不是“一个布尔值切换明暗”，而是**主题 × 明暗 × 背景**三个维度。

## 3. 设计意图：三套叙事并存

| 来源 | 方向 | 状态 |
| --- | --- | --- |
| `DESIGN.md:115-130` | **The Cartographer's Desk**：暖羊皮纸、棕褐墨、黄铜、Georgia 正文 | **过时**，仍描述旧暖色方向 |
| `PRODUCT.md:29-43` | 平静、文学性、克制；手稿优先；文学温度要有纪律 | 仍然有效的产品原则 |
| `designs/SYSTEM.md:34-50` | **玉白·墨玉**：薄荷冷白、纯白卡片、近黑墨绿主操作、翡翠点缀 | **Reveric 主题**的真源，不是默认主题 |
| `lib/shared/theme/reveric_colors.dart:98-160` | 实际 light/dark token | 三套主题共用的 token 基础 |

产品原则与默认主题之间其实存在张力：产品说“手稿优先、文学温度”，默认 Classic 却是高对比黑白工具风。运行时用**正文衬线 + 72px 编辑留白 + 克制动效**保住了文学感，但 chrome 本身是冷的。Reveric 主题才把这套原则完整视觉化。

### 4.2 运行采样：Classic 与 Reveric 的实际差异

以下颜色从截图取样，受屏幕色彩管理与压缩影响，允许 ±2 的偏差：

| 场景 | 截图 | 采样/观察 |
| --- | --- | --- |
| Classic 浅色画布/卡片 | `34-首页浅色经典.png` | 纯白 `#FFFFFF` |
| Classic 浅色侧栏 | `34-首页浅色经典.png` | 浅灰约 `#E7E7E7` |
| Classic 深色首页/编辑区 | `01-首页深色经典.png`、`03-小说正文编辑.png` | 近黑表面；主按钮白底黑字；正文米白 |
| Classic 深色弹窗 | 源码对照 | 弹窗表面约 `#1E1E20`（运行截图未覆盖深色弹窗） |
| Reveric 浅色 | `36-首页玉白墨玉浅色.png` | 画布精确 `#F2F6F4`；次级面板约 `#E9F0ED`；卡片 `#FFFFFF`；主按钮约 `#15221D` |
| Reveric 深色 | `35-首页玉白墨玉深色.png` | 画布约 `#101412`；次级表面约 `#19211E`；卡片约 `#131715`；输入框约 `#242B28` |

关键差别不在“深色/浅色”，而在**中性色温**：

- Classic 是纯中性灰阶，没有色相倾向；
- Reveric 连“黑”都带绿调，并在选中态、图标、问候语旁使用翡翠绿；
- 因此同一布局在 Classic 下像专业工具，在 Reveric 下像文学作品。

### 4.3 颜色使用评价

- **优点**：语义 token 完整；主色与强调色分工明确；删除/新增/警告/成功都有底色 + 描边 + 文本色，避免只靠色相表达；深色模式不是简单反相，而是重新设计表面层级。
- **风险**：`accentAmber` 实际是翡翠绿，命名与语义脱节（历史残留）；`textMuted` 与 `textTertiary` 同为 `#646E6A`，存在冗余 token；部分低对比组合（`textSubtle` 在小字号上）需要实际对比度测试。
- **运行时观察**：Classic 深色下正文与背景对比充足；侧栏次级文字偏灰但可读；Reveric 深色的绿黑底与白玉文字对比强，翡翠强调面积控制得克制，没有变成“赛博绿”。

运行时观察与源码一致：

- 小说正文明显是**衬线中文**（Georgia 回退到宋体），字号约 16，行距松，段间距明显；章节标题比正文大两档以上。
- UI（侧栏、按钮、表单、时间码）是无衬线；时间线与检查器中的数字更接近等宽。
- 章节树、AI 面板说明、设置项说明使用 12–13px；在 1280 宽度下仍可读，但 11px 元数据偏小。
- 首页大标题是中文无衬线粗体，不是衬线；这符合“只有正在阅读/写作的正文用衬线”的约束。

### 5.1 字体决策

- **Georgia 只给“正在阅读/写作的正文”**，标题和 UI 控件用系统无衬线，避免整屏衬线的管理疲劳（`reveric_typography.dart:39-42`）。
- **中文回退**：Georgia 没有中文字形，按 `Songti SC → STSong → SimSun` 回退，覆盖 macOS 与 Windows（`:94-96`）。
- **等宽字体有明确语义**：提示词正文、批次 ID、尺寸、缩放百分比等“要原样示人的机器文本”才用 mono（`:21-24`）。
- **移动端不复用桌面 Georgia**：移动端正文用系统字体，行高更紧，适合小屏阅读（`:98-140`）。

## 6. 间距、圆角与形状

`RevericSpacing` 是 4px 基准的离散刻度（`lib/shared/theme/reveric_spacing.dart:1-14`）：

```
xxs 4 · xs 6 · sm 8 · md 10 · lg 12 · xl 14 · x2l 16 · x3l 20 · x4l 24 · x5l 28 · x6l 40
editorPaddingH 72
```

圆角（`:16-38`）：

| Token | 值 | 用途 |
| --- | --- | --- |
| `small` | 4 | 徽章、键帽 |
| `medium` | 6 | tab、输入 chip、发送按钮 |
| `large` | 8 | 卡片、下拉菜单（旧口径） |
| `xl` / `x2l` | 10 / 12 | 输入框、大表面 |
| `full` / `pill` | 14 / 16 | 聊天气泡、chip、头像 |
| `canvasNode` | 18 | 画布节点卡 |
| `capsule` | 999 | 胶囊浮层 |
| `button` | 999（= capsule） | **所有普通按钮** |
| `iconButton` | 8 | 纯图标按钮，保持圆角方形 |
| `card` | 18 | 卡片、面板、Dialog、移动端 sheet 顶部 |

设计意图：**“操作按钮是胶囊，图标按钮是圆角方形，卡片是大圆角”**。运行时完全成立：

- “保存”“继续写作”“配置 AI 提供商”“导入 TXT”“新建小说”“快速开书”“导出”等按钮都是胶囊；
- 侧栏图标按钮是 8px 圆角方形；
- 首页项目卡、设置卡片、空态容器用 12–18px 圆角；
- 分隔线极细，浅色下几乎不可见，深色下靠 1px 灰线维持结构。

固定尺寸（`:43-72`）：

- 导演台：分类栏 56、分类 tab 46、面板 256、侧栏 312、检查器 288、预览 280、dock 46、历史 300；
- 时间线：标签 300（紧凑 136）、标尺 28、行高 26、最大高度 236；
- 弹窗：默认宽 420，窄屏保留 16px 外边距；
- 编辑器侧栏：展开 340、rail 132；
- 输入框/桌面按钮高度：36；移动按钮 40；紧凑按钮 32；
- 空态最大宽度 420。

## 7. 布局

### 7.1 桌面壳

`DesktopWindowFrame` 是桌面窗口的统一框架（`lib/desktop/widgets/desktop_window_frame.dart:1-100`）：

- 内容铺到窗口顶部，自绘标题栏覆盖其上，高度 **48px**；
- macOS 左侧为红绿灯预留 **76px**；Windows/Linux 右侧为最小化/最大化/关闭预留 **138px**（3 × 46）；
- 侧栏内容需要避让标题栏；macOS 还要避让红绿灯；
- 折叠态 AI rail 宽 **44px**；
- 双击标题栏不会误触最大化：交互控件通过 `titleBarGestureExclusionKeys` 排除在 caption 拖拽层之外。

运行时：窗口顶部确实是 48px 自绘条，红绿灯嵌入其中；左侧栏从窗口左缘开始，回到首页的返回箭头、项目名、面包屑、操作按钮都在这条 48px 内。截图 `03` 中面包屑“潮汐邮局 › 章节 › 第2章”与“保存”按钮同处标题栏。

### 7.2 1280×720 实测三栏

按截图像素估算，小说编辑页在 1280 宽度下：

| 区域 | 宽度 | 说明 |
| --- | --- | --- |
| 左侧 rail | 约 132px | 系统/创作/世界观/AI/灵感分组 |
| 第二栏（章节/列表） | 约 209px | 章节树、场次列表、分集列表等随模块变化 |
| 中间主区 | 约 579px | 正文、画布、导演视口、剪辑预览与时间线 |
| 右侧 AI 面板 | 约 360px | 聊天/配置；可折叠为 44px |

左侧合计约 341px，占窗口 27%；右侧 360px，占 28%；中间只剩约 45%。这解释了运行时最明显的体感：**在 1280 笔记本宽度下，正文行长被压得偏窄，AI 面板是“常驻奢侈品”**。折叠 AI 面板后，中间区可回到约 900px，才接近舒适写作宽度。

### 7.3 正文编辑页

`NovelEditorPage` 是桌面主工作区，布局是“左侧栏 + 主编辑区 + 右侧 AI 面板”的三栏结构：

- 左侧栏：rail（132px）+ 可展开的导航/章节树/设定/关系/AI 会话列表；侧栏总宽 340px；
- 中间：小说编辑器、剧本编辑器、画布、制片、导演台、剪辑台等按内容类型切换；
- 右侧：AI 聊天面板，可折叠为 44px rail；
- 编辑区正文左右留白 72px，接近印刷页边距，控制行长与阅读节奏。

截图 `03` 的底部状态栏是编辑器的关键反馈：`已启用自动保存`、`字数 1.1千`、`替换`、`一键排版`、`历史`。这些不是藏在菜单里的功能，而是常驻状态栏——对长文写作，这比再加一个工具栏更有效。

### 7.4 制片、导演与剪辑

- **制片**（`25-视频分镜列表.png`、`26-视频画布.png`）：仍是三栏；中间顶部有“分镜/画布/列表”三视图切换，右侧是分集/场次面板；画布节点类型多，节点卡 18px 圆角 + 细描边。
- **三维导演台**（`28-三维导演台.png`）：左 rail + 分集面板之后，是“对象分类列（约 56px）+ 视口 + 右侧检查器（约 280px）”；底部是时间轴（约 190px）。工具栏含“导演视角”“16:9”“导出”“已保存”。在 1280 宽度下视口只剩约 390px 宽，属于“能操作但偏挤”；这是固定宽度面板叠加的必然结果。
- **剪辑工作台**（`29-剪辑工作台.png`）：上方是预览（约 580×260）与右侧“属性/素材”检查器；下方是六轨时间线，轨道依次为 **字幕 T1、叠加 V2、主轨 V1、对白 A1、音效 A2、音乐 A3**；工具条含撤销/重做/分割/删除/音频轨/缩放。顶部明确显示 `16:9 · 720P · 24 fps`。时间线标签列在 1280 下是紧凑档，标签只显示轨道名与类型，不再显示完整描述。

注意：截图 `29` 的预览区是黑的，因为工程没有导入素材，不是渲染失败。

### 7.5 移动端

移动端有独立的 `lib/mobile/` 壳、页面和 provider，不复用桌面三栏宽度：

- 使用 `RevericTypography.mobile`；
- 尊重安全区；
- 内容与 chrome 使用同一套颜色/间距词汇，但组合方式不同；
- 模态默认用 bottom sheet，长流程用全屏路由；破坏性确认两端都用 `AlertDialog`（`designs/SYSTEM.md:230-250`）。

### 7.6 响应式

- 没有全局断点常量，更多是局部 `LayoutBuilder`（剧本提示、时间线、卡片网格、画布等）。
- 弹窗在可用宽度小于 420 时收紧内边距、按钮平分整行（`lib/shared/components/reveric_dialog.dart:70-100`）。
- 移动端与桌面端通过 `TargetPlatform` 分支处理触控目标、字体、模态外壳；`RevericButton` 在移动端保留 Material padded 触控目标，桌面端使用 shrinkWrap（`lib/shared/components/reveric_button.dart:60-100`）。
- 运行时验证的 1280 是最低舒适宽度附近；再窄，左侧 rail + 第二栏 + 右侧 AI 会首先挤压主区，而不是自动收起某一栏。也就是说**响应式主要发生在组件内部，不在整体壳层**。

| 反馈 | `DialogFeedback`、`RevericSpinner`、`StatusAnimationClock`、`RevericPlaceholder` | toast、加载、空态/错误态 |
| 容器 | `RevericSurfaces`（Chrome/ElevatedCard/InkWell）、`RevericDialog` | 背景感知、毛玻璃、统一弹窗 |

### 8.1 按钮

`RevericButton` 的核心约束（`lib/shared/components/reveric_button.dart:1-160`）：

- 调用方只传 label、可选 Phosphor 图标、`onPressed`、`loading`、`size`；**不暴露任意 style/颜色/圆角**。
- `loading` 时禁用点击；有图标时原位替换为进度指示器，无图标时预留加载宽度，避免按钮宽度跳动。
- `danger` 变体根据背景亮度自动选择对比度更高的前景色，不盲目用 `onAccent`。
- 尺寸：桌面 standard 36、移动 standard 40、prominent 40、compact 32；水平内边距 16/12。

运行时：主页的“继续写作”是白底黑字胶囊，悬停/次级操作是描边胶囊；设置页的“检查更新”等是低强调描边按钮。同一页最多一个实心主按钮，层级清楚。

### 8.2 输入框

`revericInputDecoration`（`lib/shared/components/reveric_input_decoration.dart:9-70`）：

- 填充式（`filled: true`），填充色 `surfaceContainerHigh`；
- 默认圆角 `large` 8px；
- 默认描边 `borderInput`，focus 用 `accent`，error 用 `warningText`；
- label/hint 用 UI 字体，输入文本用主题字体；
- 显式处理 `prefixIconConstraints`，避免 Material 默认 48×48 下限把图标撑大。

运行时：首页搜索框、设置项输入、AI 提问框都是填充式，深色下填充比背景略亮一档，不靠强描边。

### 8.3 弹窗

`RevericDialog`（`lib/shared/components/reveric_dialog.dart:30-130`）：

- 默认宽 420，窄屏自动收紧并保留 16px 外边距；
- 标题用 UI semibold，正文用 UI 字体；
- 内容可滚动；操作区在窄屏平分整行；
- 圆角 `card` 18，描边在浅色下透明、深色下用 `borderSubtle`；
- 提供 `RevericDialog.panel` 给已有固定高度/列表/独立滚动区的内容，避免嵌套无界滚动；
- `showRevericDialog<T>` 会把页面主题带入弹窗路由，保留返回值和遮罩关闭策略。

截图 `41-设置弹窗浅色.png` 验证了 420 宽、18px 圆角、浅色下几乎无描边、标题+说明+操作三段的组合。

### 8.4 Toast / 反馈

`DialogFeedback`（`lib/shared/components/dialog_feedback.dart`）解决了一个常见问题：**弹窗内的 `ScaffoldMessenger` 与宿主页面不是同一个**，导致弹窗里发的 toast 被遮住或定位错误。

- 提供 `bounded / scope / surface / intrinsic` 四种模式，分别适配固定尺寸弹窗、自然尺寸弹窗、内容自提示；
- toast 按语义分 `info / success / warning / error`，各自有底色、描边、图标；
- 同一个 messenger 内**新提示替换旧提示**，避免堆叠；
- 弹窗关闭后的结果提示会转发到宿主页面；
- toast 用 pill 自绘，`SnackBar` 只作为定位容器，圆角/描边/阴影/内边距完全可控（`:159-270`）。

## 9. 动效

> 本节全部来自源码；静态截图无法验证时长与手感。

### 9.1 时长

| 场景 | 时长 | 证据 |
| --- | --- | --- |
| 小型 hover/颜色过渡 | 100ms | `reveric_select.dart:616`、`reveric_context_menu.dart:368` |
| 下拉/菜单出现 | 140–180ms | `reveric_select.dart:301`、`:452`、`reveric_context_menu.dart:132` |
| 搜索防抖 | 250ms | `reveric_search_field.dart:25,48` |
| 分段控件滑块 | 280ms | `reveric_segmented_control.dart:66` |
| 更多菜单长按 | 400ms | `reveric_more_menu_button.dart:37` |

设计文档写分段控件是 **240ms**（`designs/SYSTEM.md:227`），代码是 **280ms**（`reveric_segmented_control.dart:66`），属于文档与实现漂移。

### 9.2 共享状态时钟

`StatusAnimationClock` 是一个很值得借鉴的性能设计（`lib/shared/components/status_animation_clock.dart:12-80`）：

- 所有循环状态动画（spinner、typing dots、pulse）共享一个 **15fps** 的低频时钟；
- 不用每个动画各起一个 vsync ticker，避免每个循环都以屏幕刷新率请求整窗重绘；
- `TickerMode` 关闭（如路由离屏）时自动 detach；
- painter 用 `repaint: clock`，tick 只重绘、不重建 widget。

### 9.3 减少动态效果

代码对 `MediaQuery.disableAnimations` / `accessibleNavigation` 有广泛处理：

- 分段控件：禁用动画时直接跳到目标位置（`reveric_segmented_control.dart:82,196`）；
- 品牌加载器、地图画布、书架、生产网格、AI 浮窗等都在减少动态时降级或跳过动画；
- 设计文档也明确“减少动态效果时关闭动画”（`designs/SYSTEM.md:227`）。

### 9.4 动效风格

整体是**克制型**：没有大面积入场动画、没有弹性回弹、没有装饰性粒子；主要是 hover/选中/展开/滑块/进度/骨架屏。运行时截图能看到的状态差异（选中胶囊、绿色高亮、保存成功）都是静态可读的，不依赖动画传达信息。符合“翻一页书，而不是点一个按钮”的设计意图（`designs/SYSTEM.md:20`）。

## 10. 反馈与状态

### 10.1 加载

- 按钮内联 loading，保持宽度稳定；
- 品牌加载器用于启动/长任务；
- 骨架屏（`shimmer`）用于列表/卡片占位；
- 状态动画统一 15fps，避免长任务时整窗高频重绘。

### 10.2 空态与错误态

`RevericPlaceholder.empty` / `.error`（`lib/shared/components/reveric_placeholder.dart:12-100`）：

- 统一图标、标题、可选说明、操作按钮；
- 最大内容宽度 420；
- 普通/紧凑图标 32/24；
- 外层定位、滚动、背景由调用方决定；
- 创建/重试使用 `RevericButton.primary` / `.secondary`。

运行时最重要的空态是 **AI 未配置**（`03-小说正文编辑.png`、`17-对话空状态.png`）：

- 居中大脑图标 + “AI 未配置” + “请先在设置中配置 AI 提供商” + “配置 AI 提供商”胶囊按钮；
- 不假装可用，也不把用户丢进设置迷宫，直接给出口；
- 空态占满右侧面板，不干扰正文。

这比“一个灰色小字提示”更明确，也比“自动弹设置向导”更不打扰。

### 10.3 破坏性操作

- 统一使用 `RevericButton.danger`，删除语义色 + 对比度自适应前景；
- 确认弹窗用 `showConfirmDialog`，外观复用 `RevericDialog`；
- 确认回调执行期间禁用重复提交、取消和返回（`designs/SYSTEM.md` 的弹窗契约）；
- 移动端与桌面端破坏性确认都用 `AlertDialog`，避免平台语义不一致。

### 10.4 Agent 工具审批

审批卡是产品里最重要的“反馈”之一：

- 展示工具名、动作、目标路径/标签、冻结参数；
- 允许用户选择作用域（session/episode/work/global）并保存规则；
- 等待期间可取消；取消后 Agent 收到明确的 `cancelled`，不会继续执行；
- 拒绝后 Agent 收到“不要重试、不要绕过”的提示（`tool_permission_gate.dart:127-133`）。

运行验证中没有触发审批卡（未配置 AI、未调用生成工具），因此审批卡的视觉只能从源码确认结构，不能确认实际排版。

## 11. 可访问性

**已有做法**

- `PRODUCT.md` 明确目标 WCAG AA：文本、控件、焦点态、语义反馈；支持键盘操作、清晰禁用态、减少动态、非仅颜色反馈（`PRODUCT.md:45-52`）。
- 组件层大量使用 `Semantics` / `MergeSemantics` / `ExcludeSemantics`：分段控件、占位、开关、标签、时间线、导演台控件等都有语义标注。
- 支持文本缩放：阅读视图、备份恢复页、关系表单、插件树等读取 `MediaQuery.textScalerOf` 并做布局适配。
- 减少动态：见 9.3。
- 触控目标：移动端按钮保留 Material padded 48px 触控区；分段控件移动端点击高度至少 48px。
- 非颜色反馈：删除/新增/警告/成功都有图标或文案，不只靠颜色。

**运行时观察**

- Classic 深色下白字/近黑底对比很高；Reveric 深色下白玉字/绿黑底同样充足。
- 侧栏分组标题、时间码、状态栏说明使用 11–12px，在 1280 屏幕上偏小；如果用户放大字号，三栏宽度会更快紧张。
- 胶囊按钮的点击高度约 32–36px，桌面鼠标可用，但低于移动端 44–48px 的触控建议；桌面与移动采用不同尺寸是合理的。

**仍需验证/可能不足**

- 没有全局的键盘快捷键清单与焦点顺序文档；桌面端大量自定义控件需要逐个验证 Tab 顺序与焦点可见性。
- `textSubtle` 在 11px 小字上的对比度是否达到 AA，需要实际测量。
- 拖拽（时间线、导演台 gizmo、画布节点）是否有键盘等价操作，源码中未看到统一方案。
- 颜色主题有 3 套 × 2 明暗，设计稿与代码的对比度需要逐主题验证。

## 13. 视觉设计评价

**强项**

1. **主题分层清楚**：Classic 负责“工具”，Reveric 负责“文学”，Ivory 负责“纸感”；不是三套随机换色，而是三种使用场景。
2. **正文优先**：72px 编辑留白、1.75 行高、Georgia + 宋体回退，阅读节奏接近纸书；UI chrome 克制，不抢手稿。
3. **组件纪律**：按钮不暴露任意样式；输入框、弹窗、toast、空态都有统一封装；减少动态效果覆盖广。
4. **性能意识**：共享 15fps 状态时钟、painter 只重绘不重建、骨架屏、预览缓存，说明设计不是“只画皮”。
5. **桌面细节**：标题栏 48px、macOS 76px / Windows 138px 避让、双击标题栏不误触最大化，都是实际桌面产品才会处理的细节。
6. **空态有出口**：“AI 未配置”不是死胡同，直接给配置按钮；这对首次启动体验很关键。

**弱项**

1. **1280 宽度下主区被挤**：左侧 341px + 右侧 360px，中间只剩约 579px；正文行长偏窄，导演视口只剩约 390px。折叠 AI 面板能缓解，但默认状态不理想。
2. **固定宽度面板太多**：导演台/剪辑台/制片都叠加固定宽度的分类栏、检查器、时间线；在 1280 下“能操作但偏挤”，在 1440 才舒展。
3. **设计文档漂移与主题语境缺失**：`DESIGN.md` 与运行时方向相反；`SYSTEM.md` 内部对按钮圆角自相矛盾，也没有声明“只适用于 Reveric 主题”。
4. **token 命名历史包袱**：`accentAmber` 实际是绿色；`large` 与 `xl/x2l` 的语义重叠；圆角刻度处于迁移中间态。
5. **文本层级偏多**：`ui / uiMedium / uiSemibold / uiSmall / uiSmallSemibold / uiTiny / uiTinySemibold` 七档，实际使用时容易选错；可以收敛为 4–5 档。
6. **可访问性缺少系统化验收**：有 Semantics 和减少动态，但没有看到统一的对比度/键盘/缩放的自动化检查。

## 14. 对 huobao-drama 的 UI 启示

1. **先定一个“脊柱”**：Reveric 的脊柱是“手稿优先、克制动效”，但它的默认主题与文学主题是分开的。本项目在改混音/配音/剪辑工作台时，也应先确定一个跨模块的视觉脊柱，再谈局部美化，避免“四不像”。
2. **默认主题要匹配主任务**：Reveric 默认 Classic（工具感），把文学感留给可选的 Reveric 主题。本项目如果主任务是短剧生产，默认应偏“生产工具”，而不是把最文艺的一套设成默认。
3. **把设计 token 变成代码真源**：颜色、字体、间距、圆角、动效时长只在一处定义；文档引用 token 名而不是复制数值；CI 检查文档与代码漂移。
4. **按钮/输入/弹窗/Toast 必须组件化**：不要让每个页面自己写 `styleFrom`；Reveric 的 `RevericButton` 不暴露任意样式，是控制 UI 一致性的有效手段。
5. **动效要“少而准”**：100–280ms 的 hover/展开/滑块足够；长任务用共享低频时钟或骨架屏，不要用高频动画掩盖等待。
6. **反馈要分层**：页面级 toast、弹窗内 toast、行内错误、空态、审批卡，各有明确容器；否则弹窗里的提示会被遮住。
7. **桌面细节决定专业感**：标题栏避让、窗口按钮、分栏宽度、快捷键、焦点顺序，都是“像不像专业桌面工具”的关键。
8. **1280 是底线，不是理想值**：如果本项目要常驻“素材 + 预览 + 检查器 + 时间线”，应优先设计可折叠/可拖拽面板，而不是继续叠加固定宽度。
