# 05 · 全流程制作与功能分析

> 分析对象：`reference/reveric/`，`unstable @ 8ba248d`，v0.8.0。源码行号均指该提交；运行时证据来自官方 v0.8.0 macOS 包（`ai.reveric`，窗口标题“幻界”，1280×720）。本次未配置任何 AI 供应商，因此生成、渲染与导出链路只做了源码核验，没有真实跑通出图/出片。

## 1. 全流程总览

Reveric 把“写作”与“制作”放在同一条本地工作流里，但它是**两个出口**：生产页导出的是“片段包 + 提示词表”，真正的成片在剪辑台导出。理解这一点，才能正确评估它的流程设计。

```text
模型与供应商配置（BYOK、能力表）
        │
小说 / 剧本工作区（作品内容库）
        │  小说 ──AI 改编──► 剧本（季 → 集 → 场 → 节拍/元素）
        │                              │
        │                    每集自动建剪辑工程
        │                              │
        └──────────────► 制片画布（分镜/视频/图片/音频/3D/导入）
                                       │
                         生成任务（预览 → 提交 → 轮询 → 采用）
                                       │
                         adoptedAssetId（采用资产）──► 3D 导演台输出也有资产
                                       │
                         剪辑台（六轨、预览、修订冲突、导出 MP4/SRT）
                                       │
                                    最终成片

旁路：生产页导出 = 按集复制已采用片段 + prompts.md/csv（不拼接成片）
```

| 阶段 | 输入 | 输出/落点 | 持久化 | 运行时入口 | 成熟度 |
| --- | --- | --- | --- | --- | --- |
| 0 配置 | 供应商、密钥、模型 | 可用模型与能力校验 | 主库 `AiProviders` 等 | 设置 → AI 供应商/模型设置 | 成熟但配置项多 |
| 1 小说/剧本进入 | 新建、TXT、导入剧本、改编 | 作品 + 内容库 | `Novels`、`novel_workspaces/<id>.sqlite` | 首页/书库 | 成熟 |
| 2 剧本结构 | 季、集、场、节拍、元素 | 可拍摄的场次与台词 | 内容库 `screenplay_*` | 剧本 → 大纲/场次 | 成熟 |
| 3 制片画布 | 场次、素材、输入引用 | 分镜/视频/图片/音频节点 | `ProductionClips` + `CanvasNodes` | 视频 → 分镜/画布/列表 | 成熟 |
| 4 生成 | 预览快照、参考输入 | 生成任务与结果资产 | `GenerationTasks`、`Assets` | 节点生成/任务面板 | 成熟，依赖外部模型 |
| 5 3D 导演台 | 版本化 JSON、机位、运镜 | 静帧/预演 MP4 资产 | `VideoStagings`、`Assets` | 画布新增 → 3D 导演台 | 成熟但有硬上限 |
| 6 剪辑成片 | 已采用分镜视频、素材 | 时间线文档、预览、MP4 | `VideoEditings` | 视频 → 剪辑 | 最成熟 |
| 7 生产页导出 | 选中的已采用分镜 | 片段文件夹 + 提示词表 | 文件系统 | 分镜列表导出 | 可用，但不是成片 |

## 2. 阶段 0：模型与能力配置

Reveric 是 BYOK（Bring Your Own Key）产品：供应商和密钥由用户配置，应用只用用户选中的模型。对制作链路来说，关键不是“能填 API Key”，而是**提交前的能力校验**。

- 视频提交前会检查：供应商存在且启用、模型在该供应商的 `videoModels` 白名单内、模型在渠道能力表中登记、时长必须为整秒（`generate_orchestrator.dart:277-291`、`:384`）。
- 图像预览会校验节点类型、供应商/模型、参考图角色、提示词引用、全景比例（`image_generate_orchestrator.dart:53-108`）。
- 音频先生成参考文件再预览/提交，轮询阶段不会重复提交计费请求（`audio_generate_orchestrator.dart:100`、`:161`、`:209`、`:236`）。
- 视频支持“草稿”提交，但只有渠道声明 `supportsDraft` 才允许（`generate_orchestrator.dart:292-302`）；完成后可基于草稿补全（`:413-431`）。

运行时限制：本次没有配置 AI，右侧 AI 面板始终显示“AI 未配置 / 请先在设置中配置 AI 供应商”，因此没有产生任何生成任务或资产。截图见 `截图/40-智能助手配置.png`、`截图/30-设置通用.png`。

**判断**：能力表把“模型不支持”提前到提交前，避免用户等半天才失败，这是制作型产品的正确做法。代价是配置面很大：供应商、模型、协议、能力、审核开关分散在设置里，新用户很容易停在“AI 未配置”。

## 3. 阶段 1：小说与剧本如何进入

### 3.1 六种进入方式

| 入口 | 行为 | 证据 |
| --- | --- | --- |
| 新建小说 | 建作品 + 默认小说工作区（章节/人物/设定等） | `lib/shared/services/novel_actions.dart:136-179` |
| 快速开书 | 先建“草稿占位”作品并进编辑器，之后“加入书架”才转正 | `novel_actions.dart:234-245`、`:275-295` |
| 演示作品 | 用种子数据生成可操作示例 | `lib/shared/services/initialization/demo_screenplay.dart:104` |
| 导入 TXT | 解析章节后建小说；可勾选“导入后改编为剧本” | `lib/desktop/pages/home.dart:553-624`、`novel_import.dart:197` |
| 新建剧本 | 建剧本作品，自动生成第 1 季/第 1 集/剪辑工程 | `novel_actions.dart:149-161`、`screenplay_service.dart:93-163` |
| 导入剧本 | 原文整份存为“资料”，打开 AI 对话并按提示分段读取改编 | `novel_actions.dart:248-273`、`screenplay_import.dart:155-163` |
| 从小说改编 | 预填来源作品信息，创建空剧本；**不自动转换正文** | `lib/desktop/widgets/novel_create_submitter.dart:117-142` |

“改编”不是一条自动流水线：它只负责建立剧本作品和初始结构，真正的场次/对白仍由用户在编辑器或 AI 对话中生产。导入剧本会把原文放到 `materials/<标题>/content`，kickoff 提示明确要求 AI 用 `Read` 的 offset/limit 分段读取（`screenplay_import.dart:160-162`），这是对长文本上下文的务实处理。

### 3.2 TXT 导入的硬规则

- 只接受 TXT；字节按 UTF-8 解码，失败回退 GBK（`novel_import.dart:72` 起）。
- 卷标题匹配 `第 N 卷/部/集/篇` 或 `卷 N`；章标题匹配 `第 N 章/节/回`、`番外`、`序章`、`楔子`，并兼容英文标题（`novel_import.dart` 中的 `_isVolumeHeading` / `_isChapterHeading`）。
- 空章节会跳过；如果整本都没有识别到章节，导入直接失败并提示标题格式，而不是生成一本无章节的书。
- 同名作品会被拒绝；改编剧本创建失败时，已导入的原著会移入回收站，整次导入回滚（`novel_import.dart:197-300`）。
- 导入后统计字数，并建立可选的改编剧本（`sourceNovelId`、`plannedEpisodeCount`）。

运行时边界：本次没有实际导入 TXT 文件，以上为源码结论；截图只覆盖了小说编辑器与引导，不覆盖导入对话框。

## 4. 阶段 2：剧本结构

### 4.1 数据层级

```text
Screenplays（剧本根，比例/分辨率/风格）
  └─ ScreenplaySeasons（季，plannedEpisodeCount）
       └─ ScreenplayEpisodes（集，canvasId、editingId）
            ├─ ScreenplayBeats（幕/节拍，actNumber、chapterCount）
            └─ ScreenplayScenes（场，stage=draft/final、pageEighths、dialogueLineCount）
                 └─ ScreenplaySceneElements（场标题、动作、角色、对白、转场、字幕、备注）
```

建剧本时会在一个事务里创建根、第 1 季、第 1 集，并立刻调用 `EpisodeEditingOrchestrator.ensureEpisodeEditing` 建剪辑工程（`screenplay_service.dart:93-163`、`:157-160`）。画布则是惰性创建：第一次进入视频/分镜时 `ensureCanvas` 才建 `Canvases` 并回写 `episode.canvasId`（`storyboard/service.dart:314-342`）。这个设计让“只写剧本”的用户不必承担画布和剪辑的空对象。

### 4.2 场景与节拍

- 场次既有结构化字段（情绪、事件、梗概、草稿/终稿、⅞ 页、台词数），也有元素序列（`screenplay_element.dart` 的 8 种类型）。
- 节拍有 `actNumber`、`chapterCount`、`status`、`sortOrder`，章节范围按 `chapterCount` 累加推导；大纲视图会显示“第几章到第几章”的区间（`lib/desktop/widgets/workspace/outline_architecture_view.dart:63`、`:135`）。
- 剧本场次与小说章节是**两套内容**：改编不是把章节行映射成场次，而是重新创作。

运行时截图：`截图/19-剧本概览.png`（18 场、75% 页、65 句台词、4 角色、6 景）、`截图/20-剧本大纲.png`、`截图/22-场次列表.png`、`截图/23-场次板.png`、`截图/24-出场矩阵.png`。

**判断**：结构层是“强类型 + 可校验”的，AI 只能通过受校验的命令改结构，不会把剧本写成自由文本。代价是建场、调节拍、维护页数都要人工或 AI 逐步完成，没有“一键把小说第 1–10 章变成 10 场”的确定性流水线。

## 5. 阶段 3：制片画布

### 5.1 画布是“素材 + 分镜”的统一工作区

每集一张 production 画布；新增菜单包含：分镜、视频、图片、人物、地点、图鉴、音频、3D 导演台、导入（运行时截图 `截图/27-画布新增菜单.png`）。

关键区别在 UI 文案里写得很清楚：

- **分镜**：“排在当前场次末尾，进成片”。
- **视频**：“不进成片，可供分镜采用或参考”。

代码里对应的是 `ProductionClips.sceneId`：`episodeShots` 只返回 `sceneId IS NOT NULL` 的片段（`storyboard/service.dart:80-113`），剪辑“导入采用片段”也只读这一批；`episodeClips` 才把无场次的参考视频一并列出（`:115-124`）。这是 Reveric 流程设计里最容易被忽略、但最重要的一条边界。

### 5.2 片段的数据契约

`ProductionClips` 一行就是一个可生成的片段（`novel_content_database.dart:1464` 起）：

| 字段 | 作用 |
| --- | --- |
| `kind` | `image` / `video` / `audio` |
| `episodeId`、`sceneId`、`sortOrder` | 集、场、场内顺序；无场次即“参考视频” |
| `inputs` | 参考输入数组，顺序即提示词引用顺序 |
| `characterId`、`locationId`、`itemId` | 主体引用 |
| `styleSelection` | 风格预设/自定义 |
| `providerId`、`modelId`、`referenceMode` | 生成配置 |
| `durationMs`、`ratio`、`resolution`、`generateAudio` | 视频参数 |
| `adoptedAssetId` | 最终采用的资产；未采用为 NULL |

输入支持资产引用和画布节点引用；节点引用会建边并做环检测（`canvas_service.dart` 的 `requireAcyclic`）。角色音色会被展开成 `reference_audio` 输入，但首尾帧模式禁止挂音色（`generate_orchestrator.dart:304-312`）。提示词里的 `<ref input_id="..." />` 必须能解析到实际输入，否则预览失败。

### 5.3 采用（adopt）是唯一的结果门禁

生成完成不等于进成片。只有用户/AI 明确“采用”，片段才拥有 `adoptedAssetId`：

- `adoptGenerated` 校验任务属于当前作品、`sourceType == production_clip`、`sourceId == node.clipId`、任务类型与节点类型一致，然后调用 `adopt`（`canvas_service.dart:1550-1563`）。
- `adopt` 再把资产 id 写入片段，并同步主体照片（`:1566-1581`）。
- `unadopt` 清空采用，但保留历史结果资产（`:1584-1597`）。

运行时截图：`截图/25-视频分镜列表.png`、`截图/26-视频画布.png`，底部统计为“计划 0 秒 · 0 段 / 3 场 · 已采用 0/0”，说明当前是未生成状态。

**判断**：画布把“参考素材、生成结果、分镜、3D 输出”放在同一张图里，并用 `adoptedAssetId` 做唯一结果指针。这比“最后生成的那张就是结果”稳健得多，也解释了为什么剪辑导入可以做到确定性排序。

## 6. 阶段 4：生成任务

### 6.1 视频：预览快照 → 提交 → 采用

1. `preview` 读取节点/片段，校验供应商、模型、能力、输入角色、音色限制，编译协议特定的提示词槽位，做 `VideoCapabilities.validate`，返回一个**不可变预览**（`generate_orchestrator.dart:265-386`）。
2. `submit` 只接受预览快照，重新确认节点仍存在，创建 `GenerationTasks` 并提交；此后 UI 再改片段也不会改变已提交请求（`:388-411`）。注释写得很明确：“The preview is the explicit submission snapshot; later UI edits cannot change it.”
3. 任务结果落到 `Assets`；采用后写回 `adoptedAssetId`。
4. 草稿任务可以 `completeDraft` 补全，但要求任务属于当前作品且来源是 `production_clip`（`:413-431`）。

### 6.2 图像与音频

- 图像：`preview` 会把提示词里的 `<ref>` 解析成“图片 N”，再拼风格；`run` 记录输出路径与 SHA-256，失败写 `recordFailure`（`image_generate_orchestrator.dart:49-165`）。
- 音频：`prepareReferences` 先把参考音频解析成真实文件，`preview` → `run`/`poll`；轮询已接受的任务不会再次提交（`audio_generate_orchestrator.dart:66`、`:100`、`:161`、`:209`、`:236`）。
- 视频工具：截帧、分离音频、静音、修剪都会产出新的节点/资产（`video_tool_orchestrator.dart:22-110`）。

### 6.3 任务状态机

`GenerationTaskStatus` 覆盖 `prepared → uploading → submitting → submission_unknown → running → saving → completed`，以及 `action_required`、`reconciliation_required`、`failed`、`cancelled`、`expired`；终态为 completed/failed/cancelled/expired（`lib/shared/models/generation/task.dart:13-29`）。

**判断**：这是全流程里最像“生产系统”的部分。`submission_unknown` 和 `reconciliation_required` 专门处理“请求可能已发出但结果未知”，避免重复计费；`saving` 把“模型成功”与“文件落盘成功”分开。很多同类产品只做“请求中/成功/失败”，在断网和超时场景会出现重复生成或丢结果。

## 7. 阶段 5：3D 导演台

- 导演台文档是版本化 JSON，单文档上限 5 MiB；最多 6 个演员、20 个道具、8 个机位；时长 24–720 帧、固定 24fps（`lib/shared/models/director/document.dart:35-38`）。
- 画布上的“3D 导演台”节点通过 `addDirector` 创建 `VideoStagings` 并建节点（`canvas_service.dart:773-783`）。
- 导出静帧或整段预演：`StagingExportOrchestrator.run` 渲染后登记资产，再 `addStagingOutput` 放到导演台节点右侧并连 `staging_output` 边（`staging_export_orchestrator.dart:20-51`、`canvas_service.dart:799-808`）。
- 输出路径固定为 `director/<operationId>/still.png` 或 `preview.mp4`；`DirectorOutputOrchestrator` 会校验帧数、帧率、时长、宽高，计算 SHA-256 后登记为 `purpose=director_output`、`source=director` 的资产（`director_output_orchestrator.dart:22-29`、`:43-150`）。
- 重复导出同一操作会复用已存在资产；文件丢失则报 `invalid_media`。

运行时截图：`截图/28-三维导演台.png`，可见 16:9、5.0 秒、机位 A/35mm、灯光、时间轴、自动帧与“导出”。本次没有执行导出，因此没有导演台产出的资产。

**判断**：这是“本地可控的预演”，不是 AI 视频生成：机位、运镜、灯光、时长都可精确复现，适合在花钱生成前确认构图和节奏。限制也很硬：6/20/8 的上限、24–720 帧、单一 JSON 文档，复杂长镜头要拆段。

## 8. 阶段 6：剪辑成片

### 8.1 工程创建与“导入采用片段”

- 每集创建时自动建剪辑工程；打开剪辑页时若 `episode.editingId` 为空则补建，若引用损坏则报错而不是悄悄替换（`editing_orchestrator.dart:19-70`）。
- “导入采用片段”只在时间线为空、主轨未锁定时可用（`lib/desktop/features/editing/controller.dart:283-291`）。
- `EditingService.fromAdopted` 只取该集 `kind == video`、`sceneId` 非空、有 `adoptedAssetId` 的片段；按剧集顺序追加到主轨；未采用片段跳过；资产损坏/非视频抛 `EditingSourceProblem`（`lib/shared/services/editing/service.dart:176-217`）。
- 导入提示明确说“已按成片顺序导入 N 段 · 之后片段改动不会自动同步”（`assets/translations/zh-CN/screenplay.json:586-587`）。这是一次性快照，不是动态链接。

### 8.2 时间线模型

- 固定 24fps、48kHz、每帧 2000 采样（`lib/shared/models/editing/document.dart:7-12`）。
- 默认六轨：字幕 T1、叠加 V2、主轨 V1、对白 A1、音效 A2、音乐 A3（`:393-420`）。
- 文档只存 `assetId`，不存路径；片段有变换、淡入淡出、音量、字幕样式；轨道有 hidden/muted/locked（`document.dart` 的 `EditingTrack`/`EditingClip`）。
- 修订号用于冲突检测：保存时版本不一致会提示，而不是覆盖。

运行时截图：`截图/29-剪辑工作台.png` 可见六轨、24fps、720P、“导入采用片段”。

### 8.3 预览与导出

- 渲染按 120 帧分块，预览缓存上限 2 GiB，缓存目录 `cache/editing_preview`；预览默认 480p，正式导出默认 720p（`render_service.dart:52-53`、`:90-118`、`:279-320`）。
- 渲染前会检查磁盘空间，按“浮点立体声 + 视频 + 一层暂存”估算（`:304-312`）。
- 字幕三种：烧录、另存 SRT（标题仍烧录）、不导出（`:33-37`）。
- 导出对话框默认 720P、默认烧录；保存 MP4，若选 SRT 会写同名 `.srt` 并确认覆盖（`lib/desktop/features/editing/export_dialog.dart:62-63`、`:126-171`）。
- 导出时会提示隐藏轨道/静音轨道的处理，避免“导出的和听到的不一样”。

**判断**：剪辑是 Reveric 最成熟的模块：帧级时间单位、分块缓存、修订冲突、磁盘预检、字幕策略都考虑到了。最大的流程约束是“一次性导入”：片段之后再改、再采用，剪辑不会自动同步，必须重新导入或手动替换。这是刻意选择（保证时间线稳定），但 UI 必须把这条说清楚——当前只在导入后的 toast 里说了一次。

## 9. 阶段 7：生产页导出不是成片

`ProductionExportOrchestrator.run` 的行为需要单独强调：

- 只接受同一集的、互不重复的、`sceneId` 非空的视频片段（`export_orchestrator.dart:50-64`）。
- 每个片段必须有 `adoptedAssetId`，否则整次导出在预检阶段失败，并报告不可读段号（`:72-105`）。
- 按剧集顺序排序，文件名 `0001_标题.ext`，标题做非法字符替换并截断到 80 字（`:70-87`）。
- 逐个复制到目标目录下的临时文件夹，支持取消与部分完成报告（`:114-161`）。
- 额外写 `prompts.md` 和 `prompts.csv`，列包括场次、段号、标题、纯文本提示词、是否采用、供应商/模型/模式/时长/比例/分辨率、参考、视频文件（`lib/shared/services/storyboard/export.dart:1-80`）。
- **它不拼接视频**，也不输出时间线工程；成片只能在剪辑台导出。

| 导出 | 产物 | 用途 | 是否成片 |
| --- | --- | --- | --- |
| 生产页导出 | `0001_*.mp4`… + `prompts.md/csv` | 交审、归档、外部剪辑 | 否 |
| 剪辑台导出 | 单个 MP4（可选 SRT） | 最终交付 | 是 |

**判断**：把“片段包”和“成片”分开是对的，避免半成品被误当交付物；但产品文案必须持续强调“生产页导出不是成片”，否则用户会以为点了导出就完成了。

## 10. 跨阶段交接契约

| 交接 | 关键字段/机制 | 风险点 |
| --- | --- | --- |
| 小说 → 改编剧本 | `Novels.sourceNovelId`、`contentKind=screenplay`、`plannedEpisodeCount` | 只建空结构，正文不自动转换 |
| 剧本 → 集 | `ScreenplayEpisodes.canvasId`、`editingId` | 画布惰性创建；剪辑随集创建 |
| 集 → 片段 | `ProductionClips.episodeId/sceneId/sortOrder` | 无场次片段不进成片 |
| 片段 → 画布 | `CanvasNodes.clipId`、`stagingId` | 节点删除/重建要保住片段指针 |
| 片段 → 生成 | `GenerationTasks.sourceType/sourceId` | 预览快照提交后不可变 |
| 任务 → 资产 | `GenerationTasks.resultAssetId`、`Assets.sha256` | 采用前资产可被替换 |
| 片段 → 成片 | `ProductionClips.adoptedAssetId` | 未采用/损坏会阻断导入 |
| 导演台 → 资产 | `VideoStagings.version`、`director_output` 资产 | 输出不自动成为分镜 |
| 剪辑 → 成片 | `VideoEditings.document`、`revision`、`assetId` | 一次性导入，无回写同步 |
| 剪辑 → SRT | 字幕元素 + 导出策略 | 标题始终烧录 |

这些契约的共同点是：**下游只读稳定 id，不读 UI 状态，也不读“最新一次生成”**。这让 Agent、手动操作和批量任务可以共用同一条链路。

## 11. 横切：Agent 如何贯穿全流程

- 领域工具覆盖小说、剧本、分镜、制片、导演台、剪辑；`Run` 域命令提供 `stagings`、`editing` 等受校验操作（`lib/shared/services/ai/tools_run.dart:175`、`:334`、`:2059-2072`）。
- Agent 可以在同一事务里“建片段 + 建节点 + 校验输入”，只留一条创建记录（`canvas_service.dart:1519-1548`）。
- 导演台和剪辑都通过文档命令修改，而不是让模型直接写数据库；这是 02 中展开的“文档 + 命令 + 渲染”骨架。
- 工具审批、权限规则与密钥边界见 04；本条只强调流程含义：同一套领域命令既能被 UI 调用，也能被 Agent 调用，减少“只有 Agent 能做的操作”。

## 12. 成熟度与缺口

**做得好的地方**

1. **采用门禁清晰**：生成结果、采用资产、成片片段三层分离，避免“最后生成的就是最终结果”。
2. **任务状态机完整**：覆盖上传、提交、未知、轮询、落盘、对账，能处理真实网络的不确定性。
3. **预览即快照**：提交后不受 UI 修改影响，可复现、可审计。
4. **两条导出语义明确**：生产页是片段包，剪辑台才是成片。
5. **本地确定性组件扎实**：3D 预演、剪辑渲染、字幕策略都不依赖云端。

**仍需补的缺口**

1. **没有自动成片拼接**：生产页不拼，剪辑台要手动导入；对“批量出片”场景效率不够。
2. **剪辑导入是一次性快照**：后续采用/替换不会同步；没有“重新导入并保留手动剪辑”的合并策略。
3. **分镜与参考视频的边界靠 `sceneId`**：概念正确，但 UI 只靠菜单文案区分，用户容易把参考视频当分镜。
4. **生成前置配置过重**：AI 未配置时，制作页只有空状态；新用户需要先完成供应商、模型、能力理解。
5. **导演台输出不自动进入分镜/剪辑**：需要手动当素材使用，链路有断点。
6. **运行时未验证**：本次没有 AI 配置，没有真实生成、渲染、导出；所有“成功路径”结论来自源码与既有测试，不代表本机跑通。

## 14. 对 huobao-drama 的启示

1. **先定“成片唯一出口”**：Reveric 用剪辑台做唯一成片出口，生产页只出片段包。短剧生产也应明确“哪个页面点导出才是交付”，其余导出都标注用途。
2. **采用状态必须是一等字段**：`adoptedAssetId` 比“最新结果”可靠；它让剪辑排序、生产导出、Agent 操作都有确定输入。
3. **生成任务要做未知态**：至少区分“提交未知/对账中/保存中”，否则重试会重复计费或丢结果。
4. **预览快照 + 不可变提交**：用户改参数不应影响已提交任务；预览对象应携带完整请求与输入清单。
5. **下游只读 id**：剪辑文档存 `assetId` 而非路径；这使资产替换、备份迁移、跨设备恢复都可控。
6. **一次性导入要显式提示**：如果选择快照式导入，必须在导入时和后续编辑中持续提示“不会自动同步”，并提供“重新导入”的明确入口。
7. **能力表前置**：把模型/协议/分辨率/参考数量限制放在提交前校验，比失败后解释更省时间。
8. **Agent 与 UI 共用领域命令**：不要让 Agent 走一条“只有它能走”的捷径；否则测试、审计和回放都会分叉。
