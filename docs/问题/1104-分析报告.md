## 1. 短剧 · API 配置

### 1.1 “火宝自带适配”和新增阿里云/豆包适配是否一致？

**结论：没有独立的 `huobao` provider/adapter；“火宝”是 Firemux 代理入口，复用同一套 adapter。一致性在 adapter 层基本成立，在“预设/能力声明/测试”层不一致。**

代码证据：

- Provider 白名单里没有 `huobao`：
  - 文本：`openai / gemini / volcengine`
  - 图片：`openai / gemini / volcengine / aliyun / comfyui`
  - 视频：`volcengine / minimax / aliyun / comfyui`
  - 音频：`qwen3-tts / aliyun / volcengine / openai-compatible`  
  见 `backend/src/services/ai.ts:33-61`。
- “火宝快捷配置”把 `https://api.firemux.cn`（或 `.com`）作为 base URL，按 provider 拼接 `/qwen`、`/volcengine`、`/minimax`，见 `frontend/app/pages/settings.vue:1577`、`1744-1750`。因此火宝通道与官方通道最终走同一个 adapter，只是 base URL 和模型名不同。
- 不一致点：
  1. **快捷配置没有音频行**：只有 text/image/video，见 `settings.vue:1744-1750`。所以“火宝音频”无法一键配置。
  2. **预设模型可能超出 adapter 能力**：阿里云音频同时列了 `cosyvoice-v2` 和 `qwen-tts`，但 adapter 只有 CosyVoice 端点，见 1.2。
  3. **能力声明是 provider 级**：`supportsReferenceImages = true` 写在 adapter 类上，不区分模型，见 `backend/src/services/adapters/volcengine-image.ts:18-19`、`aliyun-image.ts:53-54`。
  4. **配置 ID 不校验 serviceType**：`getConfigById()` 只按 id 查，不校验调用方要的是 text/image/audio，见 `backend/src/services/ai.ts:131-154`。任何调用方拿错配置都可能把请求发到错误端点。

**建议：**

- 明确“火宝”只是代理通道，不新增 provider；在 UI 上把“火宝快捷配置”改名为“火宝代理配置”，避免误解为独立适配。
- 快捷配置补音频行；模型列表与 adapter 能力绑定，不再手工维护两套。
- 把 `supportsReferenceImages`、`resolutions`、`voices`、`audioModes` 等能力下沉到“模型能力表”，provider 只做端点/鉴权。
- `getConfigById(id, expectedServiceType)` 增加 serviceType 校验，错配直接报错。

参考：上游仓库 `chatfire-AI/huobao-drama`；火宝快捷配置实现位于 `settings.vue:1742-1750`。

### 1.2 音频测试是否正确？—— 不正确（P0）

**结论：当前“测试”只是端点连通性探测，不是合成测试；它既不能证明 Key 正确，也发现不了下面两个必现的合成 Bug。**

代码证据：

- 探针只发空请求体：
  - 豆包：`POST /api/v3/tts/unidirectional`，`body: {}`，见 `backend/src/routes/aiConfigs.ts:136-149`。
  - 阿里云音频：`POST /api/v1/services/audio/tts/SpeechSynthesizer`，`body: {}`，见 `aiConfigs.ts:211-218`。
  - 本地 OpenAI 兼容：`GET /v1/models`，见 `aiConfigs.ts:176-185`。
- 判定逻辑把 401/403 也算可达：
  ```ts
  const reachable = [200, 204, 400, 401, 403].includes(resp.status)
  ```
  见 `aiConfigs.ts:341`。也就是说，**Key 错误也可能显示“测试通过”**。
- 没有超时控制；`fetch` 挂起时测试会一直转圈。
- 豆包探针默认 `X-Api-Resource-Id: seed-tts-1.0`，见 `aiConfigs.ts:136-140`；实际合成默认 `seed-tts-2.0`，见 `backend/src/services/adapters/cloud-tts.ts:103`。探针和合成用的资源不一致。
- OpenAI 兼容探针打 `/v1/models`，但合成打 `/v1/audio/speech`，见 `cloud-tts.ts:133-145`。一个只提供 chat 的服务也能“测试通过”。

#### 1.2.1 豆包 TTS 必失败：成功结束码被当错误（P0）

官方豆包语音合成 v3 单向流式协议中，音频块 `code=0`，**成功结束消息 `code=20000000`**，随后 `data:[DONE]`。当前解析器把任何非 0 code 都记为错误：

```ts
if (json?.code && Number(json.code) !== 0) {
  protocolError = `[${json.code}] ${json.message || '豆包语音合成失败'}`
  continue
}
...
if (protocolError) throw new TtsError('protocol_error', protocolError, resp.status, text.slice(0, 512))
```

见 `backend/src/services/adapters/cloud-tts.ts:235-243`。

结果是：即使音频块已经收到，最后一条 `20000000` 也会让整次合成抛 `protocol_error`。这与上游 Issue #98“调用火山引擎生成音频失败”的现象一致。

**修复：**

```ts
const code = Number(json?.code ?? 0)
if (code === 0) {
  // 正常音频块
} else if (code === 20000000) {
  // 正常结束，不再追加音频，标记结束
  break
} else {
  protocolError = `[${code}] ${json?.message || '豆包语音合成失败'}`
}
```

同时补一个真实响应 fixture 的单测：`code=0` 音频块 + `code=20000000` 结束消息 + `[DONE]`，断言不抛错且音频字节完整。

参考：

- 火山引擎豆包语音合成大模型 v3 单向流式文档（成功结束码 `20000000`）。
- 上游 Issue #98：<https://github.com/chatfire-AI/huobao-drama/issues/98>

#### 1.2.2 阿里云 Qwen-TTS 走错端点（P0）

`buildAliyunRequest` 对所有阿里云音频模型都发 `SpeechSynthesizer`：

```ts
url: joinProviderUrl(opts.baseUrl, '/api/v1', '/services/audio/tts/SpeechSynthesizer'),
body: JSON.stringify({ model: opts.model || 'cosyvoice-v2', input }),
```

见 `backend/src/services/adapters/cloud-tts.ts:79-89`。

但阿里云文档中：

- **CosyVoice** 走 `/api/v1/services/audio/tts/SpeechSynthesizer`；
- **Qwen-TTS** 走 `/api/v1/services/aigc/multimodal-generation/generation`，请求体是 `input.messages` + `parameters.voice`，与 CosyVoice 不同。

因此设置里同时列出的 `qwen-tts` 实际不可用，见 `frontend/app/pages/settings.vue:1736`。

**修复（二选一）：**

1. 按模型分支：`/qwen-?tts/i.test(model)` 时走 multimodal-generation，构造 `input.messages`，并解析 `output.choices[].message.content[]` 中的音频；否则走 SpeechSynthesizer。
2. 在 adapter 未实现前，从预设中移除 `qwen-tts`，避免用户配置后必失败。

参考：阿里云百炼 Qwen-TTS 与 CosyVoice 官方文档（两个模型族的端点和请求体不同）。

#### 1.2.3 音频测试的修复建议

- 新增“真实合成测试”：提交 2–5 个字、1 秒左右的短文本，校验返回音频字节、格式、时长；UI 明确提示“会产生少量费用”。
- 或保留“连通性测试”，但改名为“端点连通性”，并且：
  - 401/403 判失败；
  - 加 8–10 秒超时；
  - 豆包 resource id 与合成一致；
  - 阿里云按模型选端点；
  - OpenAI 兼容探针改打 `/v1/audio/speech`（可用极短文本）。
- 增加 provider 级 fixtures 测试，覆盖豆包成功/失败、CosyVoice、Qwen-TTS、OpenAI 兼容四条路径。

### 1.3 连带发现：TTS 的三个隐藏缺陷

这三个问题不在原始清单里，但会直接放大“配音不好用/音色不对”的感受，建议一并修。

1. **200 字硬截断**  
   `MAX_TEXT_LENGTH = 200`，超过直接切片，见 `backend/src/services/tts.ts:95`、`143`。长旁白/长台词会被静默截断，用户听到的是半句话。建议按模型上限设置（CosyVoice/豆包通常支持更长文本），或按标点分段合成后拼接。

2. **云端 TTS 丢弃音色设计**  
   非 `qwen3-tts` 分支只传 `externalVoiceId || defaultVoiceId`，见 `tts.ts:377-380`。`designInstruct`、`refAudioUrl` 不会进入云端请求。也就是说，角色资产里设计的音色描述对阿里云/豆包不生效，只有预先配置的外部音色 ID 生效。

3. **缓存 key 不完整**  
   `buildCacheKey` 只包含 `text/voice.externalVoiceId/designInstruct/speed/emotion/seed/model`，见 `tts.ts:148-159`；不包含 `defaultVoiceId`、`format`、`sampleRate`、`resourceId`。当用户只改默认音色或采样率时，会命中旧缓存，听起来“改了没变化”。

参考：上游 Issue #85“音色任务对不上”<https://github.com/chatfire-AI/huobao-drama/issues/85>。

## 2. 短剧 · 项目

### 2.1 新建项目时，风格分析为什么只能选文本模型？

**结论：这是当前实现的限制，但不能简单“放开图片模型”；图片生成模型不适合做文本风格分析。**

代码证据：

- 新建项目只加载文本配置：
  ```js
  aiConfigAPI.list('text')
  ```
  见 `frontend/app/pages/index.vue:456`；选项只从 `textConfigs` 生成，见 `index.vue:329-331`。
- 风格分析固定调用 `/chat/completions`：
  ```ts
  const url = joinProviderUrl(base, '', '/chat/completions')
  ```
  见 `backend/src/services/style-analysis.ts:118`。
- 错误提示也假设是文本模型：
  ```ts
  return new Error('当前文本模型不支持图片理解，请在设置中启用视觉模型')
  ```
  见 `style-analysis.ts:205`。

**原因：**

- `gpt-image` 系列是图像生成/编辑模型：它接受图片输入是为了“生成/编辑图片”，输出仍是图片，不返回文本分析。用它做“风格分析”得不到文字结论。
- 真正能做“看参考图 → 输出风格描述”的，是**支持视觉输入的 chat 模型**（如 GPT 视觉系列、Gemini 多模态系列、Qwen-VL、豆包视觉模型）。它们目前归类在 `service_type=text` 下，但并不是所有文本模型都支持图片输入。
- 另外，`getConfigById()` 不校验 serviceType；如果强行把图片配置传进来，会向图片服务发 `/chat/completions`，同样失败。

**建议：**

1. 给 AI 配置/模型预设增加 `capabilities: ['vision']` 标记。
2. 风格分析下拉框改为“文本配置中支持视觉的模型”，而不是只按 `service_type=text` 过滤。
3. UI 增加说明：“风格分析需要视觉理解模型；图像生成模型只负责出图，不返回文字分析。”
4. 如果用户想要“用图片模型生成风格板”，那是另一个功能：用参考图生成一张风格基准图，再让视觉模型总结；不要混在“风格分析”里。

参考：OpenAI Images 与 Vision 文档（图像生成模型输出图片，视觉分析由 chat 模型完成）。

### 2.3 新建项目时的配音选项，对阿里云/豆包/火宝/本地/H3 是否生效？

**结论：新建项目只有一个“自动配音”开关，没有供应商/音色选择；它只控制“是否在自动流程里调用 TTS”，实际用哪个音频配置取决于设置里的激活配置。对 H3 的原生音频不生效。**

代码证据：

- 新建项目只有全局自动配音勾选：
  ```html
  <input v-model="autoDubNewProjects" type="checkbox" @change="saveAutoDubPref" />
  ```
  见 `frontend/app/pages/index.vue:244-247`；读写的是 `settingsAPI.dubbing()` 的 `autoDubForNewEpisodes`，见 `index.vue:302-318`。
- 后端默认值只有 `autoDubForNewEpisodes`，见 `backend/src/services/app-settings.ts:171-189`。
- 自动流程在 `ep.autoDub` 为真时才调用配音，见 `backend/src/services/automation.ts:627-629`。
- 实际音色由 `tts.ts` 取当前激活音频配置和角色的 `externalVoiceId/defaultVoiceId`，见 `tts.ts:377-380`。

逐项回答：

| 通道 | 是否生效 | 说明 |
|---|---|---|
| 阿里云 CosyVoice | 部分生效 | 只要它是激活音频配置，自动配音会走它；但 `designInstruct/refAudioUrl` 被丢弃，只能用外部音色 ID |
| 豆包 TTS | 目前不生效 | 受 1.2.1 的 `20000000` Bug 影响，合成必失败 |
| 火宝 | 无音频配置 | 快捷配置没有音频行；即使手工建 OpenAI 兼容音频，也要看代理是否支持 `/v1/audio/speech` |
| 本地 OpenAI 兼容 | 生效（若服务支持） | 探针打 `/v1/models`，合成打 `/v1/audio/speech`，需实测 |
| H3 | 不控制原生音频 | H3 是视频模型的原生音频能力；自动配音是后期 TTS，两者不是一条链路 |

补充：

- `audio_mode=ambient` 只有本地 MiniMax shim 会读，见 `backend/src/services/adapters/minimax-video.ts:127`；云端 H3 不会因为这个字段改变原生音频。
- 自动流程提交视频任务时会带 `generate_audio: request.audioMode !== 'ambient'` 和 `audio_mode`，见 `automation.ts:608-609`；但只有实现了该字段的 adapter 才会生效。

**建议：**

- 新建项目增加“配音方案”选择：音频配置、默认音色、是否自动配音、是否保留视频原生音频。
- 明确区分“视频原生音频”和“后期 TTS 配音”，不要用一个勾选暗示两者都控制。
- H3 增加“原生音频开关/环境音模式”，并在 adapter 层按模型能力决定是否发送。

### 2.4 顶部分辨率为什么只有 480p/720p？

**结论：分辨率档位按“厂商”而不是“模型”配置；Seedance 2.0 的 1080p 被适配器强制降成 720p，Seedance 1.x 的 1080p 在 UI 里被隐藏，MiniMax H3 的 768P/2K 被压成 720p/1080p。**

代码证据：

- 厂商级档位：
  ```ts
  export const VIDEO_RESOLUTION_TIERS = {
    volcengine: ['480p', '720p'],
    minimax: ['720p', '1080p'],
    aliyun: ['480p', '720p', '1080p'],
    comfyui: ['480p', '720p', '1080p'],
  }
  ```
  见 `frontend/app/utils/video-resolution.ts:16-22`。
- 厂商映射把 1080p 降成 720p：
  ```ts
  volcengine: { '480p': '480p', '720p': '720p', '1080p': '720p' },
  minimax: { '480p': '768P', '720p': '768P', '1080p': '2K' },
  ```
  见 `video-resolution.ts:25-29`。
- Seedance 2.0 适配器：
  ```ts
  // Seedance 2.0 仅 480p/720p 两档，1080p 收敛到 720p
  resolution: record.resolution === '480p' ? '480p' : '720p',
  ```
  见 `backend/src/services/adapters/volcengine-video.ts:110-112`。
- Seedance 1.x 适配器其实支持 1080p：
  ```ts
  resolution: /^1080p$/i.test(clean(record.resolution)) ? '1080p' : ...
  ```
  见 `volcengine-video.ts:162`，但 UI 的 volcengine 档位没有 1080p。
- MiniMax H3 适配器会把所有 H3 变体收敛到 768P/2K，见 `backend/src/services/adapters/minimax-video.ts` 的 `normalizeResolution`。

官方能力差异（要点）：

- Seedance 2.0：标准版支持 480p/720p/1080p；fast/mini 最高 720p；1.x 支持 1080p。
- MiniMax H3：H3 支持 768P/2K；H3-Highspeed 仅 768P；H3-Lite/Max 支持 480P/768P。
- Wan 3.0：480P/720P/1080P；Wan 2.x 也支持这三档。

**建议：**

1. 建“模型能力表”，键为模型族/模型 ID，值为可用分辨率、时长、参考图、音频模式等。

3. 适配器做最后一道校验：模型不支持时明确报错，不要静默降级。
4. 显示厂商原生值（如 `768P`、`2K`），同时保留内部三档映射，避免项目页/制作页显示不一致。

### 3.2 参考图在阿里云/豆包/火宝的 API 是否生效？

**结论：代码路径存在，但“是否生效”取决于模型和输入格式；当前能力声明是 provider 级，容易让 UI 放开不该放的模型。阿里云图片只有编辑类模型支持参考图。**

逐项核对：

| 服务 | 参考图支持 | 代码/限制 |

| 豆包 Seedream 图片 | 支持，`body.image = refImages` | `backend/src/services/adapters/volcengine-image.ts:35-40`；数组直接传 |
| 阿里云 Qwen-Image | 仅 `*edit*` 模型，最多 3 张 | `backend/src/services/adapters/aliyun-image.ts:57-64`；非编辑模型直接抛错 |

### 3.3 生成完成后，为什么弹出页面不刷新？

**结论：弹窗保存的是对象的“快照”，`refresh()` 只替换数组，不会更新 `assetDetail.item`；并发生成时，`pendingCharImageIds` 只有在成功回调里才清除，晚到/失败的任务会永久显示“生成中”。**

代码证据：

- 弹窗保存原始对象：
  ```js
  const assetDetail = ref({ open: false, type: '', item: null })
  function openAssetDetail(type, item) {
    assetDetail.value = { open: true, type, item }
  }
  ```
  见 `frontend/app/views/drama/episode.vue:1736`、`1765`。
- `refresh()` 重新赋值 `chars/scenes/propItems/sbs`，见 `episode.vue:2769-2801`，但没有把新的对象写回 `assetDetail.item`。
- 生成完成后如果只是轮询 `refresh()`，数组里的新对象与弹窗里的旧对象不是同一个引用，弹窗自然不更新。
- 上游 Issue #136 描述的“同时点击多个生成，最后一个一直显示生成中”与下面这段逻辑吻合：
  - `watchAsyncResult(check, attempts=24, delay=2500)` 最多等 60 秒，见 `episode.vue:3035-3045`。
  - `pendingCharImageIds` 只在 `check()` 成功时清除；超时/失败没有清理分支。
  - 失败任务不会触发 `onDone`，弹窗也不会刷新。

**建议：**

- `assetDetail` 只存 `{ type, id }`，用 `computed` 从 `chars/scenes/propItems` 里按 id 取当前对象；数组刷新后弹窗自动更新。
- 或者每次 `refresh()` 后按 id 重新赋值 `assetDetail.item`。
- `watchAsyncResult` 增加 `finally`：无论成功/超时/失败都清理 pending，并 toast 提示；失败时也刷新一次。
- 并发生成改为任务队列/任务中心，按 task id 跟踪，不要用“数组里是否还有 id”做唯一状态。
- 生成记录里保存 `status/error_msg`，弹窗直接展示失败原因，而不是一直转圈。

参考：Issue #136 <https://github.com/chatfire-AI/huobao-drama/issues/136>、Issue #88 <https://github.com/chatfire-AI/huobao-drama/issues/88>。

## 4. 短剧 · 视频制作

### 4.1 拆分分镜不即时刷新，已有分镜还停在等待页

**结论：拆分是一个同步的 Agent HTTP 调用；只有成功后才 `refresh()`，失败只 toast，不刷新。等待期间页面仍显示空态，所以看起来一直“在等待”。**

代码证据：

- 拆分入口：
  ```js
  runAgent('storyboard_breaker', renderPipelineRule(...), dramaId, epId.value, onBreakdownDone, ...)
  ```
  见 `frontend/app/views/drama/episode.vue:2987-2992`。
- `onBreakdownDone` 才刷新：
  ```js
  async function onBreakdownDone() {
    await refresh()
    ...
  }
  ```
  见 `episode.vue:2996-3001`。
- `useAgent.run` 是 `await api.post(...)`；成功才 `onDone?.()`，失败只 `toastError(err)`，见 `frontend/app/composables/useAgent.ts:10-26`。
- 空态在 `sbs.length === 0` 时一直显示，按钮只在 `rt === 'storyboard_breaker'` 时显示 spinner，见 `episode.vue:528-540`。没有骨架屏/阶段进度。
- 如果 Agent 已经写入了部分分镜但 HTTP 超时/报错，`onDone` 不会执行，页面就停在空态，直到用户手动刷新。

**建议：**

- `useAgent.run` 增加 `finally { onSettled?.() }`，或者拆分流程自己 `try/finally { await refresh() }`，保证失败也刷新。
- 拆分期间显示“正在拆分第 N 集/已生成 N 个分镜”的进度，而不是只转圈。
- 更彻底：把拆分改成后台 Job（项目已有 job-queue/任务中心），前端轮询/SSE 订阅，避免 HTTP 长连接超时。
- 拆分完成后即使 `sbs` 已有数据，也强制 `refresh()` 一次，避免“有分镜但页面不更新”。
- 加超时/取消按钮，失败时保留已生成内容并提示“可重试剩余部分”。

参考：Issue #118“断线中止与重启后继续制作”<https://github.com/chatfire-AI/huobao-drama/issues/118>。

### 4.2 每个分镜没有转场，很生硬

**结论：当前数据模型和提示词里没有“转场/连续性”概念；分镜提示词明确使用硬切，拼接也是纯 concat。要解决需要加字段、改提示词、改生成/拼接三层。**

代码证据：

- Agent 分镜规则只描述“过渡段/叙事段/爆点段”，没有镜头间的转场字段，见 `backend/src/agents/index.ts:105`。
- 视频提示词规则强调“环境音压低，无背景音乐”，没有“承接上一镜尾动作”的要求，见 `backend/src/services/pipeline-rules.ts:25-60`。
- 拼接是 concat，不做 xfade/交叉淡化，见 `backend/src/services/ffmpeg-merge.ts`。

**建议（按成本从低到高）：**

1. **提示词层**：要求每个分镜结尾保留 2–3 秒“尾部动作/空镜/情绪停顿”，并写明“下一镜从该动作继续”；对白密集的段落插入 1–2 秒空镜或文字卡。
2. **数据层**：给 `storyboards` 增加 `transition`（cut/fade/dissolve/wipe）、`continuity`（承接说明）、`bridge`（是否需要过渡镜头）字段；UI 可分镜编辑。
3. **生成层**：
   - 支持首尾帧的模型：取上一镜最后一帧作为下一镜首帧，生成“动作延续”镜头。
   - 不支持首帧的模型：生成 2–3 秒过渡空镜/文字卡，再拼接。
4. **拼接层**：用 ffmpeg `xfade` 做 0.3–0.8 秒交叉淡化，音频用 `acrossfade`；文字卡用 `drawtext`。
5. **一致性**：同一场景的分镜使用相同角色/场景参考图、相同 seed（若模型支持）、相同风格提示词。

注意：这属于新增能力，不是修 Bug；建议先做提示词层 + 拼接 xfade，再评估首尾帧。

### 4.3 每个分镜的背景声不一样，连不起来

**结论：每个镜头独立生成，原生音频各自随机；云端视频模型不会共享“环境声床”；拼接时也没有跨镜头音频淡化。`audio_mode=ambient` 只有本地 MiniMax shim 支持。**

代码证据：

- 自动流程逐镜提交视频任务，见 `backend/src/services/automation.ts:595-613`。
- `audio_mode` 只在 MiniMax 适配器里被读取：
  ```ts
  if (record.audioMode === 'ambient') body.audio_mode = 'ambient'
  ```
  见 `backend/src/services/adapters/minimax-video.ts:127`。
- 豆包/阿里云 adapter 没有对应的“统一环境声”参数；`generate_audio` 只控制是否生成原生音频，见 `volcengine-video.ts:107`、`automation.ts:608`。
- 混音图是“一条原始声床 + 对白 + 可选 BGM”，没有按镜头拼接环境声，见 `backend/src/services/audio-mix.ts:200-280`。
- 拼接是 concat，镜头边界处音频直接切换。

**建议：**

1. **统一声床**：为整集生成/选择一条连续环境音或 BGM，镜头视频统一 `generate_audio=false`（或统一保留原生音频但压低），最后由 `audio-mix` 铺一条连续底噪，对白处 ducking。
2. **跨镜头淡化**：拼接时对音频做 0.3–0.5 秒 `acrossfade`，避免突变。
3. **共享提示词**：所有镜头使用同一段“环境声描述”（如雨声/风声/室内底噪），并在视频提示词里固定；不要每个镜头自由发挥。
4. **模型能力**：H3 等支持原生音频的模型，明确“原生音频/静音/环境声”三档；云端不支持 `ambient` 时不要假装支持。
5. **试听校验**：拼接前提供“连续播放 2–3 个镜头”的预览，专门检查声音衔接。

## 8. 根因归纳

1. **能力模型粒度太粗**：参考图、分辨率、音频模式都按 provider 声明，而不是按模型；导致 UI 放开不该放的选项，或隐藏了模型实际支持的能力。
2. **音频测试是“连通性”不是“可用性”**：空请求体 + 401/403 算通过 + 无超时，测试结果没有意义。
3. **TTS 协议解析缺少真实 fixtures**：豆包 `20000000` 这种成功结束码没有被测试覆盖；Qwen-TTS/CosyVoice 端点混用。
4. **前端状态是快照而不是派生**：`assetDetail.item` 保存对象引用，`refresh()` 替换数组后弹窗不更新。
5. **长任务缺少生命周期**：分镜拆分、资产生成、视频生成都用“轮询 + 成功回调”，失败/超时没有统一收尾。
6. **数据模型缺字段**：文风、背景、转场/连续性、成片标题都没有建模，导致只能硬编码或不做。
7. **上游能力未移植/回退**：成片删除（Issue #10）在 schema 和列表过滤里还有痕迹，但路由/UI 缺失。

### 12.5 补充修复：豆包语音 `Invalid X-Api-Key`（2026-11-04 16:52–17:02）

```json
{"header":{"reqid":"28241ac0-41fc-4c18-9b11-87d107154a62","code":45000010,"message":"Invalid X-Api-Key"}}
```

**根因**

- 豆包语音 v3 新版控制台要求 `X-Api-Key`，且必须来自**语音技术控制台**并已开通豆包语音（`speech_saas_prod`）；方舟（Ark）Key 不能用于语音合成。

- `cloud-tts.ts`：双鉴权（旧版同填时优先）；缺鉴权抛可执行错误；`header.code` 解析，`45000010` 明确提示 API Key 来源。
