# 跨业务智能体落地方案

- 状态：设计稿 V2，未实施
- 日期：2026-11-07
- 定位：不设独立使用页，把统一智能体内核嵌入首页/项目列表、小说、项目、分集、导演、剪辑、混音、交付页面；配置集中到设置页“智能体”中心
- 已确认决策：
  1. 会话形态：单线程跨页。同一项目内跨页共用一个线程；跨项目不混线程。
  2. 生产 Agent：助手可建议触发。执行仍走现有页面按钮与流程，助手不直接调用生产 Agent 写库。
  3. 配置入口：扩展现有设置页，不新增独立配置页。
  4. 首版范围：所有业务页面先落地只读能力；写入只通过三类提案，按作用域开放（首页/小说不开放，项目详情仅资产提示词）。
- 上游方案：[全链路集成与优化方案](./2026-11-06-全链路集成与优化方案.md)
- 关联方案：[小说工作台落地方案](./2026-11-06-小说工作台落地方案.md) · [导演台落地方案](./2026-11-06-导演台落地方案.md) · [剪辑工作台落地方案](./2026-11-06-剪辑工作台落地方案.md) · [页面视觉优化落地方案](./2026-11-06-页面视觉优化落地方案.md)

## 1. 结论

现有系统不是“没有 Agent”，而是**Agent 只以固定按钮的形式存在**：

- 5 个固定角色：`script_rewriter`、`extractor`、`storyboard_breaker`、`prompt_generator`、`voice_designer`（`backend/src/agents/index.ts:25-176`）。
- 21 个工具（21 个 `createTool` 定义），其中 `save_*` 工具直接写业务表（`backend/src/agents/tools/*.ts`）。
- 对前端的生产 Agent 入口分两类：`POST /agent/:type/chat` 是唯一对话入口，非流式、一次性、必须带 `drama_id` + `episode_id`（`backend/src/routes/agent.ts:32-108`）；资产提取、声音设计、提示词生成还会由 `/episodes/:id/extract`、`/voices/:id/design` 等服务路由直接调用 `mastra.getAgent(...)`（`backend/src/services/extraction.ts:35`、`backend/src/services/voice-design.ts:160`、`backend/src/services/final-prompt.ts:23`）。两类入口都不经过助手链路，写库行为不变。
- 没有会话、没有历史、没有流式、没有取消、没有作用域、没有审计、没有审批。
- 前端只有 `useAgent().run()` 这种“点一下、等结果、刷新页面”的调用（`frontend/app/composables/useAgent.ts:10-34`），没有聊天界面。
- 设置页只有 4 个生产 Agent 的提示词入口；`voice_designer` 未列出，单 Agent 模型无法编辑，也没有页面绑定、会话审计或诊断（`frontend/app/pages/settings.vue:2333`）。

因此本方案不改造这 5 个生产 Agent，也不新增独立聊天页。新增一条统一助手链路，用页面适配器嵌入各业务页面：

> **固定生产 Agent 继续“按钮触发、直接写库”；助手与导演专员只读、只提案（助手另有建议卡），所有写操作由用户在现有页面点击完成。**

三句话概括：

1. **一个内核**：`assistant` 与 `director` 是同一运行时的两个预设，不是两套聊天系统。
2. **一层适配器**：每个业务页面只声明“我是谁、当前作用域、快捷问题、建议点下去走哪个现有流程”，不各自实现聊天。
3. **一条线程**：同一项目内跨页共用历史；每条消息记录当时的作用域与预设，换页不丢上下文。

## 2. 现状与边界

### 2.1 现有 5 个生产 Agent

| Agent | 工具 | 写库 | 入口 |
| --- | --- | --- | --- |
| `script_rewriter` | `read_episode_script`、`rewrite_to_screenplay`、`save_script` | 是 | 剧本页“AI 改写” |
| `extractor` | 读取剧本/已有资产，保存角色/场景/道具 | 是 | 资产页“提取角色/场景/道具” |
| `storyboard_breaker` | 读取上下文，批量保存/更新分镜 | 是 | 分镜/视频页“AI 拆镜” |
| `prompt_generator` | 读取资产/分镜，保存最终提示词/视频提示词 | 是 | 资产页、分镜/视频页；项目详情资产编辑（最终提示词） |
| `voice_designer` | 读取角色，保存声音档案 | 是 | 配音页（音色分配/设计） |

新增的 `assistant` 与 `director` 不属于这 5 个生产 Agent，见 §6。

这些 Agent 的提示词与技能已有统一文件与接口，模型解析也支持按 Agent 解析；但设置页只列出 4 个生产 Agent 的提示词入口，且尚未提交单 Agent 模型（见 §9.3）：

- 提示词文件：`backend/workspace/prompts/<agent_type>.md`（`backend/src/agents/prompts.ts`）。
- 技能目录：`backend/workspace/skills/`（`backend/src/agents/skills.ts`）。
- 设置接口：`GET/PUT /prompts/:type`、`GET/PUT /skills/*`（`backend/src/routes/prompts.ts`、`backend/src/routes/skills.ts`）。
- 模型解析：每个请求按 `textConfigId` / `modelOverride` / prompt 文件默认模型解析（`backend/src/agents/index.ts:318-360`）。

### 2.2 确定性自动化不是智能体

`backend/src/services/automation.ts` 是固定流水线：改写 → 提取 → 声音设计 → 资产图 → 分镜 → 视频提示词 → 视频 → 配音，按阶段推进，可重试、可恢复。它不参与本方案的聊天、提案与建议，也不允许助手或导演专员调用它。

### 2.3 现有缺口

1. 不能连续对话；每次调用都是无状态。
2. 不能流式输出；长任务只能等整段返回。
3. 不能取消；请求发出后只能等超时。
4. 作用域只有“项目 + 集”，不能问小说、导演台、剪辑、混音、交付。
5. 没有独立的只读工具集；生产 Agent 的工具集包含 `save_*` 写工具，不能直接复用为助手工具。
6. 没有提案、差异、审批、审计；无法安全地把“AI 建议”交给用户确认。
7. 没有全局入口；用户必须知道去哪个页面点哪个按钮。
8. 入口碎片化；生产 Agent 按钮集中在分集工作台（项目详情另有资产最终提示词单点按钮），小说、导演、剪辑、混音、交付没有助手入口。
9. 配置分散；供应商在 AI 页、流水线在规则页、提示词与技能在智能体页；页面绑定、会话、审计、诊断没有归属。
10. 页面上下文无法复用；同一问题换页后要重新解释，助手不知道用户正在看哪个镜头、哪条片段。

### 2.4 本方案的边界

| 层 | 谁负责 | 是否写业务表 |
| --- | --- | --- |
| 固定生产链路 | 现有 5 个 Agent + `automation.ts` | 是，行为不变 |
| 助手运行时 | 新增 `assistant` 预设 | 否，只读；只能写“提案”记录 |
| 导演专员 | 新增 `director` 预设 | 否，只读；只能写 `storyboard.update` 提案 |
| 建议触发 | 页面适配器 + 现有页面流程 | 由用户点击后，经现有按钮/弹窗写库 |
| 配置中心 | 设置页“智能体” | 否，只写 `app_settings` 与提示词/技能文件 |
| 用户审批 | 现有页面流程 / `AgentDock` 差异卡 | 是，经白名单与冲突检测 |

## 3. 范围与非目标

### 3.1 本期范围

- 新增 `assistant` 助手与 `director` 导演专员两个预设，共用同一运行时、同一会话表、同一个 `AgentDock`。
- 页面适配器：小说列表、小说详情、首页/项目列表、项目详情、分集工作台、导演台、剪辑工作台、混音台、交付中心。
- 单线程跨页：同一项目内跨页共用一个线程；每条消息记录作用域与预设；跨项目开新线程。
- 只读工具集：首页项目概览、小说、项目、集、资产、分镜、配音、剪辑、混音、交付；导演专员增加导演计划读取。
- 流式输出、取消、断线恢复、进程重启后的中断标记。
- 提案：`storyboard.update`、`asset.prompt.update`、`line.update` 三类。
- 提案差异、审批、拒绝、冲突检测、审计字段。
- 建议：在集相关页面（分集、导演、剪辑、混音、交付），助手可以建议用户去触发 5 个生产 Agent、打开对应页面或阶段；执行仍走现有页面流程。项目详情页只生成资产提示词提案，不生成建议；首页与小说页面不生成提案或建议。
- 集中配置：设置页“智能体”中心，覆盖开关、页面绑定、生产智能体、助手与导演专员、工具与权限、模型与预算、会话与审计、诊断。
- 配置化开关、模型选择、上下文预算、会话保留。

### 3.2 非目标

- 不让助手或导演专员直接写业务表。
- 不用助手替换现有 5 个 Agent 或自动化流水线。
- 不做多智能体编排、任务分解、自动执行整条生产链；首版不做自动路由，导演专员只在导演台显式启用。
- 不做向量库、RAG、外部网页抓取。
- 不做用户账号与权限系统；沿用本地单用户模型。
- 不做语音对话、图片理解、文件上传。
- 不做自动应用提案、批量应用提案、自动触发生产 Agent。
- 不新增独立聊天页或导航项；设置页只做配置，不显示聊天入口。
- 不做小说/剪辑/混音的完整写工具；首版只读，深度写能力后续接。

## 4. 目标形态

### 4.1 三条链路

```text
现有生产按钮
  剧本改写 / 提取资产 / AI 拆镜 / 生成提示词 / 声音设计
  → POST /agent/:type/chat 或现有服务路由（不变，具体见 §2.1）
  → 现有工具直接写库（不变）
  → 页面刷新（不变）

助手 / 导演专员线程
  问问题 / 查状态 / 要建议
  → POST /assistant/sessions/:id/messages
  → assistant 或 director 只读工具（不写业务表）
  → 需要修改时 propose_change（只写提案）
  → 用户在差异卡片点“应用”
  → 服务端校验 + 写回 + 审计

建议卡
  助手判断“需要运行生产 Agent”
  → suggest_action（只生成建议卡）
  → 用户点击“打开流程”
  → 页面适配器打开现有弹窗/按钮流程
  → 现有生产 Agent 写库（行为不变）
```

### 4.2 统一内核 + 页面适配器

```text
业务页面（小说 / 项目 / 分集 / 导演 / 剪辑 / 混音 / 交付）
        │  只声明：作用域、快捷问题、建议执行入口
        ▼
AgentPageAdapter（页面适配器，无聊天状态）
        ▼
AgentDock（唯一聊天界面：线程、流式、提案、建议）
        ▼
/assistant/*（会话、SSE、提案、诊断）
        ▼
Assistant Runtime（assistant / director 两个预设）
        ▼
只读工具 + propose_change（助手另有 suggest_action）
        ▼
SQLite 会话/消息/提案表；业务表只读
```

页面适配器接口保持极小：

```ts
type AgentScopeKind =
  | 'home' | 'novel-library' | 'novel' | 'drama'
  | 'episode' | 'director' | 'edit' | 'mix' | 'delivery'

type EpisodeStage = 'script' | 'assets' | 'videos' | 'dubbing'

/** 页面绑定阶段：分集路由的六个可视阶段；mix / delivery 仍映射为独立作用域 */
type PageBindingStage = EpisodeStage | 'mix' | 'delivery'

interface AgentScope {
  kind: AgentScopeKind
  drama_id?: number
  episode_id?: number
  novel_id?: number
  /** 仅 edit 作用域：当前剪辑工程 ID */
  edit_project_id?: number
  stage?: EpisodeStage
  focus?: Record<string, string | number>
}

interface AgentSuggestion {
  action: 'agent.run' | 'page.open'
  target: string
  label: string
  reason: string
  impact: string
  prefill?: Record<string, string | number>
}

type AgentEntry = 'floating' | 'header' | 'stage'

interface AgentPageAdapter {
  id: string
  match: (route: RouteLocationNormalized) => boolean
  /** Vue computed/ref：路由或页面阶段变化时自动更新；无法解析时为 null */
  scope: Ref<AgentScope | null>
  /** 可同时提供多个入口（如顶栏 + 悬浮）；空数组表示隐藏 */
  entries: AgentEntry[]
  /** 随作用域变化，可为 computed/ref */
  quickPrompts: Ref<string[]>
  /** 手动模式可切换的作用域；缺省只允许当前 scope.kind */
  supportedScopes?: AgentScopeKind[]
  runSuggestion?: (suggestion: AgentSuggestion) => Promise<void>
}

type AgentPresetId = 'assistant' | 'director'

/** agent.pages 的持久化项；没有配置的路由由适配器默认值兜底 */
interface AgentPageBinding {
  /** 完整路由路径模式（如 /drama/:id/episode/:episodeNumber）；整段匹配，不做前缀匹配 */
  route: string
  /** 仅分集路由允许：阶段级绑定；省略表示该路由的默认绑定 */
  stage?: PageBindingStage
  /** 入口组合；空数组表示该绑定隐藏入口 */
  entries: AgentEntry[]
  /** 新建线程时输入框的初始预设；非导演台作用域只能为 assistant */
  defaultPreset: AgentPresetId
  /** 覆盖适配器快捷问题；null = 跟随适配器 */
  quickPrompts: string[] | null
  /** 允许的作用域；省略 = 跟随适配器；只能缩小，不能为空数组 */
  allowedScopes?: AgentScopeKind[]
  /** 允许的只读工具名；省略 = 跟随预设白名单；只能缩小，不能包含 propose_change / suggest_action */
  allowedTools?: string[]
}
```

约束：

- 页面不持有消息流、不实现聊天输入、不各自保存会话。
- 页面只通过适配器注册作用域、快捷问题与建议执行入口。
- `entries` 可同时声明多个入口（如项目详情“顶栏 + 悬浮”、分集页“悬浮 + 阶段入口”）；所有入口打开的是同一个 `AgentDock` 实例与同一条线程，不复制消息流，也不为入口单独建会话。
- 适配器随页面挂载注册、卸载注销；`AgentDock` 只认当前适配器，不按路由硬编码页面逻辑。
- 同一路由只注册一个页面适配器。分集页的剧本/资产/分镜/配音/混音/导出/交付弹窗都由分集页这一只适配器根据本地状态计算，子组件不单独注册适配器，避免“最后挂载者覆盖”的不确定行为。
- `match` 按路由名或精确路径匹配，禁止用 `/drama/:id` 这类前缀吞掉分集、导演、剪辑路由；诊断页显示每个路由命中的适配器 ID。
- `agent.pages` 保存路由匹配与默认值；页面适配器可用更精确的 `match` / `scope` 覆盖默认值，但只能缩小作用域与工具范围。入口组合与默认预设以设置页页面绑定为准，适配器的 `entries` 只是未配置时的默认值；快捷问题默认由适配器按当前作用域提供，页面绑定可覆盖为自定义列表；`scope` 的运行时解析始终以适配器为准。
- 页面无法解析作用域时 `scope.value=null`：`AgentDock` 自动隐藏，不发请求；`agent.scope.autoDetect=false` 也一样，因为没有作用域就无法确定 `workspace_key`。手动模式适用于适配器能确定 `workspace_key` 的页面，典型场景是自动识别的作用域不够精确（如分集页数据未加载时回退到 `drama` 作用域，此时适配器返回的是基础作用域而不是 null）：显示作用域条，由用户在该线程允许且适配器支持的范围内选择。手动模式不自动采用适配器的当前作用域，用户必须在作用域条选择一次后才能发送；选择只影响随后发送的消息，不改写已有线程的默认预设。

### 4.3 单线程与作用域

**线程键**

| workspace_key | 覆盖页面 | 说明 |
| --- | --- | --- |
| `home` | 首页/项目列表 | 跨项目只读总览；不生成提案或建议 |
| `novel-library` | 小说列表 | 只读小说列表；不生成提案或建议 |
| `novel:<id>` | 小说详情 | 单本小说一条线程；不生成提案或建议 |
| `drama:<id>` | 项目详情、分集、导演、剪辑、混音、交付 | 同一项目内跨页共用一条线程 |

**规则**

- 进入业务页面时，若总开关开启且适配器解析到非空作用域，调用 `POST /assistant/sessions/resolve`，按 `workspace_key` 取活动线程；没有则创建。总开关关闭或作用域为空时不发请求。
- “新对话”显式创建新线程，旧线程归档；默认连续，不按页面自动新建。
- 跨项目不混线程；从项目 A 进入项目 B 时切到 B 的线程，顶部显示“当前线程：项目 B”。
- `home` / `novel-library` 是总览线程，不与具体项目/小说线程合并；从总览进入详情时切到对应线程。
- 每条用户消息写 `scope_json`；换页只更新输入框上方的作用域条，历史消息保留原作用域标签。
- 每条消息写 `preset`；导演台默认 `director`，其他页面默认 `assistant`。`director` 预设只允许在 `scope.kind=director` 时使用。
- 作用域校验在服务端完成；客户端不能把 A 项目的会话切到 B 项目。
- `resolve` 传入的 `preset` 只决定新建线程的默认值；已有线程不因换页改写 `agent_sessions.preset`。页面输入框的初始预设取页面绑定 `defaultPreset`（导演台 `director`，其他页面 `assistant`），用户显式切换只影响随后发送的消息，每条消息独立记录 `preset`。
- `drama:<id>` 线程只接受 `drama` / `episode` / `director` / `edit` / `mix` / `delivery` 作用域，且 `drama_id` 必须等于 `<id>`；`novel:<id>` 线程只接受 `novel` 且 `novel_id` 必须等于 `<id>`；`home` / `novel-library` 只接受同名作用域。

**作用域结构**

```json
{
  "kind": "episode",
  "drama_id": 12,
  "episode_id": 88,
  "stage": "videos",
  "focus": { "storyboard_id": 42 }
}
```

| kind | 必需 ID | 说明 |
| --- | --- | --- |
| `home` | 无 | 跨项目只读总览 |
| `novel-library` | 无 | 小说列表只读 |
| `novel` | `novel_id` | 小说详情、章节、人物、图谱 |
| `drama` | `drama_id` | 项目详情、集数、资产缺口、交付 |
| `episode` | `drama_id`、`episode_id` | 分集工作台；`stage` 只取 `script` / `assets` / `videos` / `dubbing`，分镜对应 `videos` |
| `director` | `drama_id`、`episode_id` | 导演台；默认 `director` 预设，可切回 `assistant` |
| `edit` | `drama_id`、`episode_id`、`edit_project_id`（读取片段或定位片段时必需） | 剪辑工作台；`edit_project_id` 是剪辑工程 ID，不是项目（drama）ID；只问工程汇总时可省略，服务端按默认工程读取 |
| `mix` | `drama_id`、`episode_id` | 混音台；由 `DubbingStage` 内的 `MixStage` 提供 |
| `delivery` | `drama_id`、`episode_id` | 交付/导出；由分集页 `panel=export`、`dubStep=4`（`ExportStage`）或 `deliveryOpen=true`（`EpisodeDeliveryDialog`）提供 |

`focus` 只允许下列 ID 键，其他键返回 `422`：

| kind | 允许的 focus 键 |
| --- | --- |
| `episode` | `storyboard_id`、`line_id` |
| `director` | `storyboard_id` |
| `edit` | `clip_id`（编辑计划内的字符串 ID，`clp_` / `img_` / `frz_` 前缀） |
| `mix` | `track_id` |
| `delivery` | `export_id` |
| `novel` | `chapter_id` |
| `home` / `novel-library` / `drama` | 无 |

`focus` 的值：`chapter_id` / `storyboard_id` / `line_id` / `track_id` / `export_id` 必须是正整数；`edit.clip_id` 是编辑计划内的字符串 ID（`clp_` / `img_` / `frz_` 前缀），不是整数，必须属于 `edit_project_id` 对应的工程。`edit_project_id` 必须是正整数，且工程属于当前 `episode_id`、未软删；`edit` 作用域带 `focus.clip_id` 时必须带 `edit_project_id`。服务端还要校验 ID 属于当前 `drama_id` / `episode_id` / `novel_id`，越界或不属于当前作用域返回 `422`。`focus` 只用于定位与上下文提示，不扩大工具注册范围。

`stage` 直接复用分集页现有状态，不新增第二套枚举：

| 当前界面 | 实际页面状态 | 作用域 |
| --- | --- | --- |
| 剧本 | `panel=script` | `episode` + `stage=script` |
| 资产 | `panel=production`、`prodTab=assets` | `episode` + `stage=assets` |
| 分镜/视频 | `panel=production`、`prodTab=videos` | `episode` + `stage=videos` |
| 配音（台词/音色/生成） | `panel=dubbing`、`dubStep=0..2` | `episode` + `stage=dubbing` |
| 混音 | `panel=dubbing`、`dubStep=3`（`MixStage`） | `mix` |
| 合成导出 | `panel=dubbing`、`dubStep=4`（`ExportStage`） | `delivery` |
| 合片/成片 | `panel=export` | `delivery` |
| 交付弹窗 | `deliveryOpen=true`（`EpisodeDeliveryDialog`） | `delivery` |

分集页只有一个页面适配器，用 computed 从 `panel`、`prodTab`、`dubStep`、`deliveryOpen` 计算作用域；`DubbingStage`、`MixStage`、`ExportStage`、`EpisodeDeliveryDialog` 只通过现有事件/状态影响分集页，不各自注册适配器。

`mix` / `delivery` 是独立作用域，不再用 `episode.stage` 表示；页面适配器在打开 `MixStage` / `ExportStage` / 交付弹窗时切换作用域，关闭后回到 `episode` 的当前阶段。

### 4.5 入口与抽屉

```text
┌ 页面 ─────────────────────────────────────────────┬ 助手 380px ─────────┐
│                                                    │ 当前线程：项目 A    │
│                                                    │ 预设：助手          │
│                                                    │ 作用域：第 3 集·分镜│
│                                                    │ 消息流              │
│                                                    │ 工具调用（折叠）    │
│                                                    │ 提案卡片 / 建议卡片 │
│                                                    │ [输入框] [发送]     │
└────────────────────────────────────────────────────┴─────────────────────┘
```

- 入口：业务页右下角悬浮按钮；工作室全屏页用顶栏“助手”图标；导演台额外“导演建议”；混音/交付在阶段头部提供入口。
- 同一时间只开一个抽屉；位置全局挂载在 `frontend/app/app.vue`，不新增页面。
- 宽度默认 380px，可拖到 360–520px；覆盖在右侧，不挤压主工作区。
- 顶部显示当前线程、预设、作用域；自动识别模式下作用域条只读并带锁图标；`agent.scope.autoDetect=false` 时，作用域条可在当前线程允许且适配器支持的范围内手动切换。
- 预设默认由页面绑定决定；导演台默认 `director`，可手动切回 `assistant`；其他页面不显示 `director` 选项。离开导演作用域时输入框自动回退到 `assistant`，不能把 `director` 预设带到普通页面继续发送。`agent.director.enabled=false` 时，导演台默认预设回退 `assistant`，不显示导演专员预设；`director.mode=off` 时导演台本身不可用（入口隐藏、直接访问返回 403），不显示导演专员预设。
- 工具调用默认折叠，只显示“读取了分镜列表（12 条）”这类摘要；展开可看参数与结果。
- 提案卡片显示目标、字段差异、理由、冲突状态，以及“应用 / 拒绝 / 查看原文”；“查看原文”展开该提案涉及的完整 `before_json` / `after_json` 字段值（纯文本），不跳转页面。
- 建议卡片显示动作、目标、理由、影响，以及“打开流程 / 打开页面”；不提供“自动执行”。
- 关闭抽屉不取消正在生成的回答；重新打开恢复同一线程。
- 消息 Markdown 只渲染安全子集：禁用原始 HTML、`<script>`、`<iframe>` 与事件属性；链接只允许 `http(s)`，`javascript:` / `data:` 不渲染为可点击链接；外链在新窗口打开时带 `rel="noopener noreferrer"`；外链图片默认不自动加载。
- 工具调用摘要与工具结果按纯文本渲染，不解析 HTML 或 Markdown，避免工具返回内容注入页面。
- 提案差异、建议卡文案按纯文本渲染，不解析 HTML 或 Markdown。
- `agent.scope.autoDetect=false` 时，作用域条列出当前线程允许且适配器 `supportedScopes` 声明的作用域；未声明时只列当前作用域。集相关作用域的 `episode_id` 由页面适配器提供（当前集），用户只能切换作用域，不能输入任意 ID，也不能跨线程选择。
- “新对话”归档当前线程；“历史”按 `workspace_key` 列出线程。
- 设置页不显示悬浮入口，避免把配置页当聊天页。

### 4.6 助手能做什么

- “这集还有哪些镜头没有视频？”
- “第 3 场为什么没有角色绑定？”
- “这集台词和分镜时长对得上吗？”
- “混音为什么显示过期？”
- “把第 5 镜的视频提示词改得更克制，给我看差异。”
- “这三条字幕太长，帮我压缩到 18 字以内，给我看差异。”
- “这个镜头的机位和景别匹配吗？给我一个更稳的构图建议。”
- “这集还差配音，帮我把声音设计流程打开。”

助手回答必须带对象 ID 或明确位置；不能只说“建议优化”。涉及写操作时，只能给提案或建议卡，不能声称已经执行。

索引：

- `agent_sessions(workspace_key, status, last_message_at)`
- `agent_sessions(workspace_key) WHERE status='active'`（部分唯一索引：同一线程键最多一个活动线程）
- `agent_messages(session_id, id)`

### 5.2 会话接口

统一挂在 `/assistant` 命名空间，避免与生产 Agent 的 `/agent/:type/chat` 混淆。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/assistant/sessions/resolve` | 按 `workspace_key` 取活动线程；没有则创建，返回会话与最近消息 |
| POST | `/assistant/sessions` | 显式新建线程；旧活动线程若有进行中的回答先取消，再归档 |
| GET | `/assistant/sessions?workspace_key=&status=active` | 线程列表；`workspace_key` 可选，省略时返回全部（仅设置页“会话与审计”使用），带值时按线程过滤；`status` 取 `active` / `archived` / `all`，缺省 `active`，“历史”用 `archived` 或 `all` |
| GET | `/assistant/sessions/:id?before_id=&limit=50` | 线程 + 消息分页 |
| POST | `/assistant/sessions/:id/messages` | 发送消息，返回 `{user_message_id, assistant_message_id, stream_url}` |
| GET | `/assistant/sessions/:id/stream?message_id=&after_seq=` | SSE 流；`after_seq` 用于断线续传，缺省 0；首次连接以 `reset` 回放已生成全文 |
| POST | `/assistant/sessions/:id/cancel` | 取消当前回答 |
| POST | `/assistant/sessions/:id/archive` | 归档线程；进行中的回答先取消 |
| DELETE | `/assistant/sessions/:id` | 软删除线程：置 `archived` 并写 `deleted_at`，进行中的回答先取消 |
| GET | `/assistant/proposals?session_id=&status=` | 提案列表；两个参数均可选，省略返回全部（设置页“会话与审计”使用） |
| GET | `/assistant/proposals/:id` | 提案详情；读取前做惰性过期检查，返回 `before_json` / `after_json` / 状态与当前目标摘要 |
| POST | `/assistant/proposals/:id/apply` | 应用提案 |
| POST | `/assistant/proposals/:id/reject` | 拒绝提案 |
| GET | `/assistant/diagnostics` | 工具清单、路由作用域解析模拟、模型可用性、最近错误 |
| POST | `/assistant/diagnostics/tool` | 诊断页试跑单个只读工具；请求体 `{ tool, args, scope }`，按作用域重新校验，不写库 |
| GET/PUT | `/settings/agent` | 智能体配置读写 |

`GET/PUT /settings/agent` 不属于 `/assistant` 命名空间，列在此处只为集中对照；实际挂在现有设置路由下。

`GET /assistant/sessions/:id` 的消息按 `id` 正序返回；`before_id` 表示“更早一页”的上界（不含该 ID），缺省返回最新 `limit` 条，响应带 `has_more`。`resolve` 返回最近 50 条消息。

`POST /assistant/sessions/resolve` 请求体：

```json
{
  "workspace_key": "drama:12",
  "preset": "assistant"
}
```

`POST /assistant/sessions` 使用与 `resolve` 相同的 `workspace_key` / `preset` 请求体与校验规则；创建前先取消并归档同 `workspace_key` 的活动线程。

`POST /assistant/sessions/:id/messages` 请求体：

```json
{
  "message": "这集还有哪些镜头没生成视频？",
  "scope": {
    "kind": "episode",
    "drama_id": 12,
    "episode_id": 88,
    "stage": "videos",
    "focus": { "storyboard_id": 42 }
  },
  "preset": "assistant",
  "model": "可选，覆盖默认模型",
  "config_id": 3
}
```

校验规则：

- `message` 去除首尾空白后不能为空，长度不超过 `agent.message.maxChars`（默认 4000）；超限返回 `422`，不创建消息。
- `scope` 必须与线程的 `workspace_key` 一致：`home` / `novel-library` 线程只接受同名作用域；`novel:<id>` 线程只接受 `novel` 且 `novel_id` 相同；`drama:<id>` 线程只接受 `drama` / `episode` / `director` / `edit` / `mix` / `delivery` 且 `drama_id` 相同。`drama:<id>` 线程不能发 `novel` 作用域消息。
- `workspace_key` 只接受 `home` / `novel-library` / `novel:<id>` / `drama:<id>`，不符合枚举或 ID 格式时返回 `422`；`novel:<id>` / `drama:<id>` 的目标必须存在且未软删，否则 `resolve` 返回 `404`；活动线程的目标之后被软删时，`resolve` 返回 `410` 并提示归档该线程，不新建同名线程。
- `episode_id` 必须存在、属于该 `drama_id`，且 `episodes.deleted_at IS NULL`，父项目 `dramas.deleted_at IS NULL`；`novel_id` 必须存在且 `novels.deleted_at IS NULL`；`scope.kind=edit` 若带 `edit_project_id`，必须存在、属于该 `episode_id` 且 `edit_projects.deleted_at IS NULL`；带 `focus.clip_id` 时必须带 `edit_project_id`。作用域目标在每次发消息时重新校验：不存在、不属于所声明的父级或越界返回 `422`；目标曾有效但已软删（仅在已有线程中可能出现）返回 `410`。
- `preset=director` 只允许 `scope.kind=director`；其他页面拒绝导演专员消息。
- `agent.dock.enabled=false` / `AGENT_DOCK=off` 时，`POST /assistant/sessions/resolve`、`POST /assistant/sessions` 与 `POST /assistant/sessions/:id/messages` 返回 `403`；已有线程仍可查看、取消、归档。`agent.director.enabled=false` / `AGENT_DIRECTOR=off` / `director.mode=off` 时，`preset=director` 返回 `403`。
- `home` / `novel-library` / `novel` 作用域不注册 `propose_change` 与 `suggest_action`；只能问答。`drama` 作用域只允许 `asset.prompt.update`。
- 会话已删除或归档时不能继续发消息；归档/删除操作会先取消进行中的回答。`GET /assistant/sessions` 不返回 `deleted_at` 非空线程（`status=all` 也不包含）；软删除线程的提案仍可按 `session_id` / 提案 ID 审计。
- 同一会话同一时间只允许一条 `running` 助手消息；已有进行中的回答时再次发消息返回 `409`，前端在生成期间禁用发送，用户需先取消或等待完成。
- `POST /cancel` 只对 `running` 消息生效；已完成、已取消、已失败或已中断的消息返回 `409`，不覆盖终态。
- `POST /assistant/diagnostics/tool` 只接受 §7.1 只读工具名；写工具、未知工具、越界参数或作用域不匹配返回 `400`，不执行。

`agent.stream.enabled=false` 时，`POST /messages` 同步等待完成，返回 `{user_message_id, assistant_message_id, text, status}`，不返回 `stream_url`；前端走非流式分支，完成后重新拉取当前线程消息与提案列表，卡片渲染规则不变。其余校验与落库规则不变。

流式模式下，`POST /messages` 只落库用户消息、创建 `running` 的助手消息并启动后台生成，立即返回；没有 SSE 订阅者时仍继续生成并缓冲，完成后落库。`POST /cancel` 中止后台任务，把已生成文本写入消息 `content`，再置 `cancelled` 并让本轮提案过期。

### 5.3 SSE 事件

沿用 `backend/src/routes/novelJobs.ts:140-218` 的 `streamSSE` 模式：

| event | data | 说明 |
| --- | --- | --- |
| `start` | `{message_id, model, preset}` | 开始 |
| `scope` | `{kind, novel_id?, drama_id?, episode_id?, edit_project_id?, stage?, focus?}` | 本次回答实际使用的作用域；按作用域省略无关字段 |
| `delta` | `{text, seq}` | 增量文本；`seq` 为消息内单调递增序号 |
| `reset` | `{text, seq}` | 首次连接或缓冲区无法续传时回放全文，前端用 `text` 替换当前消息文本 |
| `tool` | `{name, status, summary, args?, result?}`，`status` 为 `running` / `done` / `failed` | 工具调用；`running` 携带规范化参数 `args`，`done` / `failed` 携带按 `agent.tools.maxResultChars` 截断并脱敏的 `result`；前端展开时按纯文本显示 |
| `proposal` | `{proposal_id, kind, target}` | 生成提案 |
| `suggestion` | `{action, target, label, reason, impact, prefill}` | 生成建议卡；与最终 `suggestions_json` 一致 |
| `done` | `{message_id, text, status, usage?}` | 完成；`status` 为 `completed` / `cancelled` |
| `error` | `{code, message}` | 失败 |
| 心跳注释 | 无 data，仅 `: ping` | 每 15 秒保活；沿用小说任务 SSE 的注释心跳，不是业务事件 |

断线重连：客户端带 `message_id` 与已收到的最大 `seq`（`after_seq`）重连；`running` 只补发 `seq > after_seq` 的 `delta`，不重复也不丢增量；缓冲已被清理时改发 `reset`（完整已生成文本）再继续。`completed` 回放完整文本并发 `done(status=completed)`；`cancelled` 回放已生成文本并发 `done(status=cancelled)`；`failed` 发 `error`（使用落库错误）；`interrupted` 发 `error(code=interrupted)`。`scope` 事件让前端在重连后仍能还原当时的上下文标签。

`GET /stream` 先校验 `message_id` 属于 `:id` 会话；不属于返回 `404`，不建立 SSE，也不暴露其他会话是否存在。归属正确时，终态消息立即回放终态事件后关闭，不重新触发生成。对 `running` 消息，首次连接或无法对应 `after_seq` 时，服务端先发 `reset`，客户端用 `reset.text` 覆盖本地流式文本，再接收后续 `delta`，避免与已渲染文本重复。

回答进入 `failed` / `cancelled` / `interrupted` 时，本轮已创建的提案置 `expired`，本轮未完成的建议清空，避免半成品被应用。

生成由 `POST /messages` 启动，SSE 只是订阅，不负责触发；运行中的消息在内存保留增量缓冲与订阅者列表，断线重连从缓冲续传，完成后以落库文本为准。后端启动时在事务内把残留的 `running` 消息标记 `interrupted`，并按同一规则把该消息已创建的提案置 `expired`（`error=process_restart`）、清空该消息的 `suggestions_json`（该轮建议未完成，不补发）；内存缓冲不跨进程恢复。

### 5.4 现有接口保持不变

- `POST /agent/:type/chat` 不改，仍只接受 5 个生产 Agent。
- `validAgentTypes` 当前由 `Object.keys(DEFAULT_PROMPTS)` 推导（`backend/src/agents/index.ts:178`）；直接给 `DEFAULT_PROMPTS` 增加两个预设会把它们自动放行到旧 `/chat`。必须先拆成显式常量：`PRODUCTION_AGENT_TYPES` 固定 5 个生产 Agent，`validAgentTypes` 继续等于这 5 个，`allAgentTypes` 只用于提示词与注册表。
- `/prompts` 的列表查询与 `/prompts/:type`（含 `/:type/reset`）的类型校验都改用 `allAgentTypes`，让两个预设的提示词可读写、可重置；生产 Agent 行为不变。

- 设置页按“生产智能体 / 助手与导演专员”分组展示。

### 6.2 系统规则


### 6.3 请求上下文

现有 `AgentRequestContextValues` 的 `episodeId` / `dramaId` 是必填（`backend/src/agents/context.ts:8-15`）。生产链路保持不变，助手链路新增独立接口，避免把生产上下文的必填约束改松：

```ts

  episodeId: number
  dramaId: number
  modelOverride?: string
  textConfigId?: number
  language?: ContentLanguage

export interface AssistantRequestContextValues {
  sessionId: number
  messageId: number
  workspaceKey: string

  dramaId?: number

  textConfigId?: number
```

`messageId` 是本次正在生成的助手消息 ID，供 `propose_change` 写 `session_id` / `message_id`、`suggest_action` 写 `suggestions_json` 使用。`focus` 只存在于 `scope.focus`，不单独放进请求上下文。

- 生产 Agent 仍由现有 `buildAgentRequestContext()` 写入 `episodeId` / `dramaId`；值由路由校验后传入，行为不变。
- 新增 `buildAssistantRequestContext()`，只在 `scope` 带对应 ID 时写入 `episodeId` / `dramaId`；`home` / `novel-library` / `novel` 不写，也不伪造 0 或 -1。

- 语言仍走 `getContentLanguageFromRC()`。

### 6.4 上下文预算

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 作用域摘要 | ≤2000 字 | 服务端生成，不含全文 |
| 历史消息 | 最近 20 条；与工具结果共享 12000 字总预算 | 超出从最旧截断，插入“较早对话已省略” |
| 单次工具结果 | ≤6000 字（`agent.tools.maxResultChars`） | 超出截断并标记 |
| 步数 | 8 | 防止无限工具循环 |
| 超时 | 120 秒 | 超时标记失败，可重试 |

作用域摘要只放：项目名、画幅、集数、当前集标题、剧本字数、分镜数量、资产数量、配音完成度、剪辑状态、混音状态、最近成片。详细信息由工具按需读取。摘要只做只读查询；剪辑/混音状态使用 §7.1 的 `readOnly` 路径，不得触发建工程、落初始版本或补默认总线。当前用户消息也计入总预算；超预算时从最早历史截断，不截断当前消息，工具结果按单次上限截断。

### 6.5 模型选择

- 默认跟随现有文本配置与 prompt 文件的 `model`。
- 优先级：请求级 `model` > 设置页 `agent.model` / `agent.director.model` > 提示词文件 `model` > 全局文本配置的 `model`；请求级 `config_id` 选择文本配置（provider/baseUrl/apiKey，并决定兜底 `model`）。
- 落到现有 `getModel(fileModel, modelOverride, textConfigId)` 时：`modelOverride` 取 `请求级 model || (preset==='director' ? agent.director.model : agent.model)`，`fileModel` 取提示词文件 `model`，`textConfigId` 取请求级 `config_id` 或全局默认；不改 `getModel` 签名。
- 助手与导演专员的默认模型在设置页“模型与预算”区写入 `agent.model` / `agent.director.model`；提示词文件 `model` 只作后备，不提供第二个编辑入口。生产 Agent 的模型仍由提示词文件 `model` 提供。
- 会话级可传 `model` / `config_id`，只作用于本次请求，不修改全局配置。
- 模型不可用时返回明确错误，不回退到其他 provider，不打印密钥。
- 复用现有 `getModel()` 的 thinking-off、温度、max tokens 补丁逻辑，不重复实现。温度仍由 AI 服务配置统一控制，本方案不新增单 Agent 温度字段。

### 6.6 导演专员

- 作用域：`director`（导演台）为主；普通页面不显示该预设。
- 工具：`read_director_plan`、`read_storyboards`、`read_storyboard_detail`、`read_assets`、`read_asset_detail`、`read_episode_context`；全部只读，不注册 `suggest_action`。
- 提案：仅 `storyboard.update`，字段限 `shot_type`、`angle`、`movement`、`duration`；不能写 `director_plans`。
- 入口：导演台“导演建议”按钮通过全局 `AgentDock` 打开方法显式指定 `director` 预设，不新增入口类型，也不做第二个聊天框。
- 回答要求：先引用 `storyboard_id` 与当前镜头参数，再给建议；必须说明构图/机位/时长的理由，不自动应用。
- 与助手的关系：共用同一线程；普通助手在 `director` 作用域下同样可调用 `read_director_plan`，但提案类型更宽；导演专员只允许 `storyboard.update`。首版不做自动路由，用户在导演台通过“导演建议”显式启用。
- 配置：`agent.director.enabled=true`；关闭时导演台入口隐藏，助手不受影响；`director.mode=off` 时导演台页签不可用（按导演台方案返回 403），不提供导演专员入口；导演台 D0 未落地时，导演相关问答回退到 `episode` 作用域。

### 7.3 工具约束

- 所有工具只接受 ID 参数，不接受 SQL、文件路径、URL。
- 项目/集相关查询强制带 `drama_id`（以及必要时的 `episode_id`）作用域条件；小说查询只带 `novel_id`；`read_project_list` / `read_novel_list` 只返回只读汇总，不接受任意筛选条件。
- 列表工具不返回全文：`read_storyboards` 不含完整提示词与台词正文，`read_novel_chapters` 不含章节正文；需要正文时调用对应的详情/内容工具。
- 项目级工具（`read_project_overview`、`read_assets`、`read_delivery_status`）必须带 `drama_id`；集内工具（`read_episode_context`、`read_script`、`read_dubbing_status` 等）必须同时带 `drama_id` + `episode_id`；`read_edit_state` / `read_edit_clips` 必须带 `episode_id`，带 `edit_project_id` 时必须按该工程读取，`read_edit_clips` 还必须带当前 `edit_project_id`，不能按默认工程猜测片段。
- 只读工具不得调用带副作用的服务：`getEpisodeEditState()` 默认会在无工程时调用 `openProjectForFilm()`、无计划时调用 `persistInitialProjectPlan()`；`compileMixPlan()` 默认会调用 `ensureDefaultBuses()` 写入缺失总线。`read_edit_state` / `read_edit_clips` / `read_mix_state` / `read_mix_tracks` 必须走新增的 `readOnly` 路径（不建工程/版本、不补默认总线），其他工具也只做查询，不触发懒创建、补齐或迁移。
- 列表工具统一返回 `{ items, total, truncated, hint }`；详情/状态工具返回单个对象并带 `hint`；空结果要说明原因。
- 不返回 API Key、baseURL、数据库路径、服务器绝对路径、环境变量。
- 单次返回超过 `agent.tools.maxResultChars`（默认 6000 字）时截断，并在 `hint` 中告诉模型“用更精确的 ID 再查”。
- 所有读取与提案目标查询都按软删过滤：`dramas` / `episodes` / `characters` / `scenes` / `props` / `assets` / `storyboards` / `storyboard_lines` / `character_voices` / `line_takes` / `voice_samples` / `episode_audio_assets` / `novels` / `video_merges` / `episode_exports` / `edit_projects` 直接过滤 `deleted_at IS NULL`；没有 `deleted_at` 的 `novel_chapters` / `novel_graph_snapshots` / `novel_chapter_graphs` 通过父 `novels.deleted_at IS NULL` 过滤，`edit_revisions` / `mix_revisions` 通过所属工程或集过滤。父记录已软删时，其子表数据一律不可见，也不能作为提案目标。
- 工具失败返回 `{ error, hint }`，不抛异常中断整轮对话。
- 工具结果按“数据”包装返回，不把剧本、小说、分镜文本当作系统指令。

### 7.4 为什么不直接给写工具

- 现有写工具没有审批、没有差异、没有冲突检测，直接暴露给聊天模型风险过高。
- 写工具的输入是完整业务对象，模型容易漏字段、覆盖旧值。
- 本方案用“提案”把写操作缩小到单实体、白名单字段、服务端生成 before 快照。
- 生产 Agent 的写操作仍由现有按钮触发；助手最多给建议卡，不直接调用。

## 8. 提案与建议

### 8.1 提案类型

| kind | 目标 | 允许字段 |
| --- | --- | --- |
| `storyboard.update` | `storyboards.id` | `title`、`description`、`shot_type`、`angle`、`movement`、`video_prompt`、`duration`、`transition`、`atmosphere`、`sound_effect` |
| `asset.prompt.update` | `characters.id` / `scenes.id` / `props.id` | `final_prompt` |
| `line.update` | `storyboard_lines.id` | `text`、`subtitle_text` |

导演专员不新增提案类型，复用 `storyboard.update`，但字段只允许 `shot_type` / `angle` / `movement` / `duration`；导演计划本身仍由导演台的保存接口维护，不经过 Agent 提案。首版不开放 `image_prompt`、`video_url`、`result` 等生成产物字段，`image_prompt` 仍由 `prompt_generator` 生产流程维护。

白名单之外一律拒绝。`duration` 按 8–15 的整数秒校验（与 `storyboard_breaker` 提示词一致；现有 `PUT /storyboards/:id` 不做范围校验，本方案在提案层新增）；`transition` 必须在 `cut/fade/dissolve/wipe` 内，非法值拒绝而不是像现有接口那样静默归一为 `cut`。

现有 `PUT /storyboards/:id` 不校验文本长度；`PUT /lines/:id` 只对 `text` 有 2000 字上限（`backend/src/services/line-workbench.ts:55`），且不支持独立修改 `subtitle_text`。提案层必须自己设上限，并在创建与应用时各校验一次：

| 字段 | 上限 |
| --- | --- |
| `title` | 120 字 |
| `description` | 2000 字 |
| `shot_type` / `angle` / `movement` | 40 字 |
| `video_prompt` | 4000 字 |
| `atmosphere` | 200 字 |
| `sound_effect` | 500 字 |
| `final_prompt` | 4000 字 |
| `text` / `subtitle_text` | 2000 字 |

超限返回 `422`，不创建提案；白名单字段传空字符串或纯空白同样拒绝，首版不支持用空值清空字段。`rationale` 必须是非空文本且 ≤500 字。`line.update` 的 `text` 只按 `updateLine()` 的 `cleanText()` 规则去除首尾空白，不折叠内部空白，再写入 `after_json` 并参与差异/哈希；`subtitle_text` 同样只去除首尾空白。这样提案展示值与 `updateLine()` 落库值一致（`normalizeLineText()` 只用于匹配键/去重，不作为落库值）。

### 8.2 生成提案

工具：`propose_change`

```json
{
  "kind": "storyboard.update",
  "target_type": "storyboard",
  "target_id": 42,
  "after": { "video_prompt": "……" },
  "rationale": "原提示词缺少镜头运动与光线，按第 3 场氛围补充"
}
```

`asset.prompt.update` 必须带 `target_type: character | scene | prop`，避免三类实体 ID 冲突；`storyboard.update` / `line.update` 的 `target_type` 固定为 `storyboard` / `line`。服务端按 `kind + target_type` 选择表和字段白名单。

作用域归属：`storyboard` / `line` 必须属于当前 `episode_id`；`character` / `scene` / `prop` 必须属于当前 `drama_id`，不要求绑定到当前集，提案的 `episode_id` 为空。

服务端处理：

1. 校验 kind 在白名单、目标存在且未软删、目标属于当前作用域；`storyboard` / `line` 还要校验所属集与项目未软删，`character` / `scene` / `prop` 还要校验所属项目未软删；`director` 预设只接受 `storyboard.update`，且字段只允许 `shot_type` / `angle` / `movement` / `duration`。
2. 读取目标当前值，只保留本次 `after_json` 涉及的字段（不是整行，也不是该类全部白名单字段），做稳定序列化（字段名排序）后计算 SHA-256，生成 `before_json` 与 `target_hash`；无关字段变化不制造假冲突。
3. 校验 `after_json` 只含白名单字段、至少一个字段，类型与范围合法。
4. 若 `before_json` 与 `after_json` 无差异，不建提案，返回“无需修改”。
5. 写入 `agent_proposals`，带上请求上下文里的 `session_id` / `message_id`，状态 `proposed`，`proposed_by='agent'`。
6. 返回提案 ID 与摘要，由前端渲染差异卡片。

模型不能提供 `before_json`、`target_hash`、`drama_id`、`episode_id`。

### 8.3 应用提案

`POST /assistant/proposals/:id/apply`：

1. 校验提案状态与配置：`expired` 返回 `410`；`applied` / `rejected` / `conflict` 返回 `409`；`proposed` 且 `created_at` 超过 7 天则先置 `expired` 并返回 `410`；所属会话已软删除 → `410` 并置 `expired`（`error=session_deleted`）；当前 `agent.proposals.types` 未包含该类型 → 应用返回 `403`，不改状态（拒绝接口不受影响，仍可拒绝）。
2. 重新读取目标；目标不存在、已软删，或所属集/项目父记录已软删 → `410` 并置 `expired`（`error=target_missing` / `parent_deleted`）；目标已不属于提案的 `drama_id` / `episode_id`（如分镜被移动到其他集）→ `410` 并置 `expired`（`error=target_moved`）。存在且归属一致时，按 `before_json` 的同一字段集、同一稳定序列化与 SHA-256 算法计算当前哈希。重新读取、归属校验与哈希计算必须与步骤 5 的写回在同一事务内完成，或至少在事务内再次核对 `target_hash`，避免校验后被并发修改。
3. 校验 `after_json` 仍符合白名单与类型/范围；不合法返回 `422`，不改业务表。
4. 与 `target_hash` 不一致 → `409`，提案标记 `conflict`、`error=target_changed`，返回当前值供用户对比。
5. 一致 → 写回白名单字段，写 `applied_at`、`applied_by='local-user'`，状态 `applied`。写回与提案状态更新在同一事务；事务内以 `WHERE id=? AND status='proposed'` 条件更新提案，受影响行数为 0 时回滚并返回 `409`，避免双击或并发重复应用。写回必须复用现有更新语义：
   - `storyboard.update`：按 `PUT /storyboards/:id` 的字段映射写回（映射抽到 `backend/src/services/storyboard-update.ts`，路由与提案共用，避免两套映射漂移），并更新 `updated_at`。
   - `asset.prompt.update`：写 `final_prompt`，并更新 `updated_at`。
   - `line.update`：`text` 必须走 `updateLine()` 同一套逻辑，同步 `speak_text`、`subtitle_text`、`text_revision`、`audio_stale`、`origin_key` 等派生字段；只改 `subtitle_text` 时只写该列与 `updated_at`，不动 `text` / `speak_text` / 音频状态；两者同时出现时先应用 `text`，再覆盖 `subtitle_text`。为避免嵌套事务，先把 `updateLine()` 的内部写库逻辑抽成可传入事务的函数（`backend/src/services/line-workbench.ts`），再与提案状态更新放在同一事务。
6. 返回 `{ applied: true, warnings: [] }`；前端收到成功后刷新当前页面数据与提案状态。

`warnings` 规则：

- 改 `storyboard.duration` / `video_prompt` / `description` / `shot_type` / `angle` / `movement` 且该分镜已有视频 → 返回“视频可能已过期，需要重新生成；不会自动删除或重排任务”。
- 改 `storyboard.atmosphere` / `sound_effect` 且该分镜已有视频，或该集已有混音/成片 → 返回“相关视频、环境声或混音可能已过期；不会自动重新生成”。
- 改 `storyboard.transition` 且该集已有成片/剪辑版本 → 返回“成片转场可能未更新；不会自动重排或重新导出”。
- 改 `line.text` 且该台词已有配音 → 返回“配音可能已过期；不会自动重新生成”。
- 只改 `line.subtitle_text` → 返回“字幕/导出快照可能已过期；配音不受影响，不会自动重新导出”。
- 改 `final_prompt` 且已有资产图 → 返回“资产图可能已过期；不会自动重新生成”。资产提示词属于项目级，可能影响其他集，提示用户确认影响范围。

若该集已有剪辑版本、混音或成片，再提示对应产物可能需要重新生成；本方案不自动触发任何重生成。

### 8.4 拒绝与过期

- 拒绝：先做 7 天惰性过期检查，超期置 `expired` 并返回 `410`；仅 `proposed` 可拒绝，其他状态返回 `409`；成功后状态 `rejected`，不写业务表；已拒绝不可再应用。
- 过期：超过 7 天未处理、会话软删除、目标已不存在或已移出作用域，状态置 `expired`，并在 `error` 写原因（`expired_7d` / `session_deleted` / `target_missing` / `parent_deleted` / `target_moved`）；`GET /proposals`、`GET /proposals/:id`、打开卡片与 `apply` 前惰性检查，不依赖定时任务。应用过期提案返回 `410`，目标哈希不一致返回 `409`。
- 会话归档（“新对话”）不使提案过期；只有软删除会话才把该会话未处理提案置 `expired`。
- 回答 `failed` / `cancelled` / `interrupted` 时，本轮已创建提案置 `expired`，`error` 分别写 `message_failed` / `message_cancelled` / `process_restart`，不能应用。
- 打开过期卡片按原因提示“超过 7 天已过期”或“目标已删除/变化”，并建议重新提问；不允许“批量应用全部提案”，一次一个，避免误操作。

### 8.5 审计

`agent_proposals` 已包含：谁提议（`proposed_by=agent`）、谁应用（`applied_by`）、何时（`applied_at`）、前后值（`before_json` / `after_json`）、冲突原因（`error`）。不新建审计表。

### 8.6 建议触发

助手判断“需要运行生产流程”时，调用 `suggest_action`，只生成建议卡，不执行。

| 动作 | 目标 | 说明 |
| --- | --- | --- |
| `agent.run` | `script_rewriter` / `extractor` / `storyboard_breaker` / `prompt_generator` / `voice_designer` | 建议运行对应生产 Agent |
| `page.open` | `script` / `assets` / `videos` / `dubbing` / `edit` / `director` / `mix` / `delivery` | 建议打开对应页面、阶段或交付流程 |

`page.open` 的 `target` 与现有页面状态一一对应：

| target | 实际打开 |
| --- | --- |
| `script` | 分集页 `panel=script`、`scriptStep=1`（改写视图，露出“AI 改写”入口） |
| `assets` | 分集页 `panel=production`、`prodTab=assets` |
| `videos` | 分集页 `panel=production`、`prodTab=videos`（分镜/视频） |
| `dubbing` | 分集页 `panel=dubbing`、`step=0`（内部 `dubStep=0`，台词） |
| `mix` | 分集页 `panel=dubbing`、`step=3`（内部 `dubStep=3`，`MixStage`） |
| `edit` | `/drama/:id/episode/:n/edit` |
| `director` | 分集页 `panel=director`、`view=2d\|3d`（制作区导演台页签，D0 落地后） |
| `delivery` | 分集页 `panel=dubbing`、`step=4`（内部 `dubStep=4`，`ExportStage`：导出记录与失败原因）；`panel=export`（合片/成片列表）与 `EpisodeDeliveryDialog` 属同一 `delivery` 作用域，但仍由现有按钮进入，`open` 不自动展开 |

`page.open` 只负责打开页面与阶段，不自动展开二级弹窗，也不点击任何生产按钮。

`agent.run` 的“打开流程”对应现有生产入口：

| target | 实际打开 |
| --- | --- |
| `script_rewriter` | 分集页 `panel=script`、`scriptStep=1`，定位“重写剧本”入口 |
| `extractor` | 分集页 `panel=production`、`prodTab=assets`，定位“提取角色/场景/道具”入口 |
| `storyboard_breaker` | 分集页 `panel=production`、`prodTab=videos`，定位“拆分分镜”入口 |
| `prompt_generator` | 分集页 `panel=production`、`prodTab=videos`，定位对应分镜的“生成视频提示词”入口 |
| `voice_designer` | 分集页 `panel=dubbing`、`step=1`（内部 `dubStep=1`），定位“音色分配/设计”入口 |

首版 `agent.run prompt_generator` 只定位视频提示词入口；资产提示词走 `asset.prompt.update` 提案，不通过建议卡触发批量生成。

建议卡只能把用户带到上述入口，由用户自己点击；助手不得调用 `/agent/:type/chat` 或对应的生成接口。

建议卡字段（`prefill` 由服务端按当前 `scope` 填充，模型不提供）：

```json
{
  "action": "agent.run",
  "target": "storyboard_breaker",
  "label": "运行 AI 拆镜",
  "reason": "第 3 集还没有分镜",
  "impact": "会写入分镜并可能触发后续资产/提示词流程",
  "prefill": { "drama_id": 12, "episode_id": 88, "episode_number": 3 }
}
```

执行规则：

- 用户点击“打开流程/打开页面”后，先比较建议卡 `prefill` 的 `drama_id` / `episode_id` 与当前页面适配器的 `scope`：一致、目标页面/阶段属于该适配器可处理范围且适配器声明了 `runSuggestion` 时，由该适配器打开现有弹窗/按钮流程；不一致、目标不属于当前适配器或当前页面没有适配器时，用 `prefill` 定位到目标项目/集页面，再带上 `open` 参数跳转。禁止把其他项目/集或其他工作台的建议交给当前适配器执行。按钮只做导航/打开流程，不直接运行生产 Agent。`runSuggestion` 抛错或找不到目标入口时，`AgentDock` 明确提示失败并回退为“打开页面”，不静默吞错，也不改由助手执行。
- 分集内的阶段（`script` / `assets` / `videos` / `dubbing` / `mix` / `delivery`）没有独立路由：跨页跳转时带 `open=<target>` 参数，由分集页映射到 `panel` / `scriptStep` / `prodTab` / `dubStep`（`script`→`panel=script`、`scriptStep=1`；`assets`→`panel=production&prodTab=assets`；`videos`→`panel=production&prodTab=videos`；`dubbing`→`panel=dubbing&step=0`；`mix`→`panel=dubbing&step=3`；`delivery`→`panel=dubbing&step=4`（`ExportStage`）；`panel=export` 与交付弹窗不由 `open` 自动打开）。`prefill` 里的 `storyboard_id` / `line_id` / `clip_id` / `track_id` / `export_id` 作为对应的 `focus_*` 参数一并带上，目标页定位并高亮后从 URL 移除；`edit` 作用域还带 `edit_project_id`，跳转 URL 用 `?project_id=<id>` 打开对应剪辑工程，缺省或工程已不存在时只打开默认工程并提示无法定位片段，不能在错误工程里按同名字符串匹配片段。没有对应定位能力的阶段忽略这些参数。`edit` / `director` 有独立路由，直接跳到对应页面；`director` 未落地时不生成该建议。`open` 只是页面导航参数，不是消息作用域 `stage`；作用域仍由页面适配器按实际页面状态计算。分集页消费 `open` 后从 URL 移除该参数，避免刷新重复跳转。
- `prefill` 只能由服务端从当前 `scope` 生成（`drama_id`、`episode_id`、`episode_number`、`storyboard_id`、`edit_project_id` 等 ID 或阶段枚举），模型只提供 `action` / `target` / `label` / `reason` / `impact`，不能注入其他 `prefill` 字段。
- 单条消息最多 3 个建议；`reason` / `impact` 各 ≤200 字。
- 服务端按 `action` 校验 `target`：`agent.run` 只允许 5 个生产 Agent，`page.open` 只允许上表 8 个目标；未知 target 或目标功能未启用（如导演台 D0 未落地）时不生成对应建议。
- 真正的写操作仍由现有生产 Agent 按钮发起；助手进程不调用 `/agent/:type/chat`，也不调用 `/episodes/:id/extract`、`/voices/:id/design` 与资产提示词生成等生产服务路由。
- 不提供“自动执行”“批量执行”“静默执行”。
- 建议卡不写 `agent_proposals`；存放在消息的 `suggestions_json`。建议不是审计对象，保留清理时随消息正文一并清除，提案审计不受影响。同一轮多次 `suggest_action` 按 `message_id` 追加合并，不覆盖已生成的建议。
- 建议卡必须说明影响；涉及删除、重生成、覆盖时，只给建议，不提供一键执行；按钮最多打开现有流程，由用户在流程内确认。

### 8.7 边界

- 提案只覆盖三类字段；建议只覆盖白名单动作。
- 助手不能删除对象、不能触发自动流水线、不能修改导演计划、不能修改生成任务。
- 应用提案与执行建议都必须经过用户点击；服务端不接受“助手代点”。

### 9.2 设置页“智能体”中心

现有设置页有 11 个页签（`frontend/app/pages/settings.vue:1751`）。本方案不新增第 12 个页签，把 `agents` 页签升级为“智能体”中心，内部用左侧子导航分区，顶部提供子区与配置项搜索：

| 子区 | 内容 |
| --- | --- |
| 总览与开关 | 总开关、各页面入口、流式、提案、建议、导演专员 |
| 页面绑定 | 页面路由匹配 × 入口组合 × 默认预设 × 快捷问题 × 只读范围 |
| 生产智能体 | 5 个生产 Agent 的提示词、技能、模型；补齐 `voice_designer` |
| 助手与导演专员 | 两个预设的提示词、技能；默认模型在“模型与预算”区编辑 |
| 工具与权限 | 只读工具清单、提案白名单、建议动作白名单、作用域规则 |
| 模型与预算 | 默认模型、步数、超时、上下文与单条消息上限、历史条数、工具结果截断规则 |
| 会话与审计 | 线程、消息、提案、应用/拒绝记录、取消运行中的回答、保留天数、清理 |
| 诊断 | 路由作用域解析模拟（输入页面路由，返回适配器解析结果）、模型可用性、工具清单、最近错误、选择项目/集后试跑只读工具 |

边界：

- 页面绑定按 `{ route, stage? }` 存储：`stage` 是 `PageBindingStage`（`script` / `assets` / `videos` / `dubbing` / `mix` / `delivery`），只用于分集路由；它与 `AgentScope.stage`（`EpisodeStage`，前 4 个值）不是同一枚举，`mix` / `delivery` 绑定只用于选择入口、默认预设与默认作用域，不写入 `scope.stage`。未配置阶段时继承该路由的默认绑定。入口组合、默认预设、快捷问题、只读范围按最具体的 `(route, stage)` 命中，阶段绑定只能缩小作用域与工具范围，不能把 `mix` / `delivery` 绑定到非分集路由。
- `agent.pages` 持久化为 `{ version: 1, bindings: AgentPageBinding[] }`；同一 `(route, stage)` 只允许一条，`allowedScopes` / `allowedTools` 为空数组视为非法配置并在保存时拒绝。示例：

```json
{
  "version": 1,
  "bindings": [
    {
      "route": "/drama/:id/episode/:episodeNumber",
      "stage": "videos",
      "entries": ["floating", "stage"],
      "defaultPreset": "assistant",
      "quickPrompts": ["检查这一镜的提示词是否完整"],
      "allowedScopes": ["episode"],
      "allowedTools": ["read_episode_context", "read_storyboards", "read_storyboard_detail", "read_assets"]
    }
  ]
}
```

- 生效规则：有效作用域 = 预设白名单 ∩ `allowedScopes`（缺省视为全集）∩ 适配器 `supportedScopes`；有效只读工具 = 预设白名单 ∩ `allowedTools`（缺省视为全集）。两者都只做交集，交集结果为空时入口隐藏（作用域）或没有可调用工具（工具），不回退到未收窄的白名单。`propose_change` / `suggest_action` 不受 `allowedTools` 控制，仍由 `agent.proposals.enabled` / `agent.suggestions.enabled` 与预设决定。
- 供应商密钥、Base URL、文本模型配置仍留在 AI 服务页；智能体中心只链接过去，不复制一份。
- 流水线自动化仍留在规则页；智能体中心只链接，不重复实现。
- 生产智能体与助手/导演专员分组展示，避免用户把预设当成第 6 个生产 Agent。
- 设置页不显示悬浮聊天入口，避免配置与使用混在一起。

### 9.3 需要修复的现有配置缺口

- `agentDefs` 只有 4 个生产 Agent，缺少 `voice_designer`；补齐后生产智能体区应有 5 个。
- `saveAgentCfg` 只提交 `{name, system_prompt}`；补齐 `model` 字段，让单 Agent 模型可在设置页编辑。后端 `PUT /prompts/:type` 已支持 `model`，但只在 `lang=zh` 时读写，其他语言变体不保存模型；因此模型输入框只在中文提示词下显示并提交，切换其他语言时沿用中文文件的 `model`。本期不新增按语言独立模型的接口。
- 助手与导演专员的默认模型统一在“模型与预算”区编辑 `agent.model` / `agent.director.model`；提示词文件 `model` 作为后备，不在“助手与导演专员”区重复提供第二个输入框，避免两个入口互相覆盖。
- 提示词文件 frontmatter 只支持 `name` / `model`，本方案不新增温度字段；温度继续由 AI 服务统一配置。
- `/prompts` 的类型校验改为 `allAgentTypes`，让助手与导演专员出现在设置页；`/skills` 无类型校验，不改接口，只补 `AGENT_SKILL_MAP`。
- 新增页面绑定、会话审计、诊断入口；此前没有归属。

### 9.4 安全不变量

不做成配置：

- 助手与导演专员只能调用只读工具与 `propose_change`；助手额外可用 `suggest_action`。
- 页面绑定与 `agent.pages` 只能缩小可用作用域/工具范围，不能突破 §7.1 白名单。
- 页面绑定 `defaultPreset=director` 只允许用于导演台页签作用域；其他页面或页签保存时回退 `assistant`。
- `agent.proposals.types` 与 `agent.suggestions.actions` 只能取白名单子集，不能新增类型或动作。
- 导演专员不能写 `director_plans`；提案仅限 `storyboard.update` 白名单字段。
- 提案只能写白名单字段。
- 建议卡不执行写操作；执行必须用户点击现有页面流程。
- 应用提案必须经过用户点击。
- 工具与接口不得返回密钥、令牌、内部路径。
- 旧 `/agent/:type/chat` 的行为与写权限不变。

## 11. 分阶段实施

### B0 配置与注册（1–1.5 天）

- 新增 `agent.*` 配置、设置接口与设置页“智能体”中心骨架。
- 注册 `assistant` 与 `director` 两个预设，新增两份默认提示词；旧 `/chat` 仍只认 5 个生产 Agent。
- 建立页面适配器注册机制与空 `AgentDock`（无 AI 调用）。
- 入口默认可见但不自动展开；`agent.dock.enabled=false` 时完全隐藏。
- 验收：设置页能看到 5 个生产 Agent、助手、导演专员的配置项；导演台 D0 未落地时只隐藏业务入口，配置仍可编辑；关闭总开关后业务页面与现在一致；旧按钮全部正常。

### B1 会话与只读问答（3–4 天）

- 3 张表、线程 resolve/新建/归档、消息分页、作用域校验。
- SSE、取消、断线恢复、进程重启中断标记；非流式回退。
- 只读工具：首页、小说列表、小说详情、项目、分集、资产、分镜、配音、交付状态。
- 页面适配器：首页、小说列表、小说详情、项目详情、分集工作台（单适配器 + 按阶段计算作用域）。
- 单线程跨页：同一项目内切页不丢历史；每条消息记录作用域与预设。
- 验收：能在项目/分集/小说页面连续提问；换页后历史仍在；全程无业务表写入。

### B2 剪辑、混音、交付与提案（2–3 天）

- 只读工具：剪辑状态/片段、混音状态/轨道、导出历史。
- 页面适配器：剪辑工作台；分集页适配器补齐混音（`dubStep=3`）与交付（`dubStep=4` / `panel=export` / 交付弹窗）作用域。
- `propose_change`、三类提案、差异卡片、应用/拒绝、冲突检测、审计。
- 应用后返回“可能过期”提示，不自动删除/重排。
- 验收：改一个分镜的视频提示词 → 卡片显示差异 → 应用后分镜更新、审计字段完整；并发修改返回 409；剪辑/混音/交付问答可引用当前对象。

### B3 建议与导演专员（1.5–2 天）

- `suggest_action`、建议卡、5 个生产 Agent 的建议入口（只打开现有流程，不直接执行）、页面跳转/弹窗打开。
- 导演专员预设、导演台“导演建议”按钮、`read_director_plan`。
- 导演专员只生成 `storyboard.update` 提案；不能写 `director_plans`。
- 验收：建议卡不自动执行；点击后走现有页面流程；导演台问答能引用机位/景别/时长并生成提案；生产 Agent 行为不变。
- 依赖：导演台 D0 只读 API；未落地前只隐藏导演专员业务入口，配置与提示词仍可先落地。

### B4 诊断与收口（1 天）

- 诊断页：路由作用域解析模拟、模型可用性、工具清单、最近错误、选择项目/集后试跑只读工具；试跑走 `POST /assistant/diagnostics/tool`，不直接调用生产工具。
- 会话保留清理（只清消息正文、工具调用/结果与建议 JSON，保留会话壳、消息行与提案审计）、软删除、多语言文案、空态/错误态、性能。
- 验收：设置中心能看到一次完整诊断并试跑一个只读工具；30 天保留清理不影响提案审计；中英日韩切换完整。

B0–B4 合计约 8.5–11.5 天。B1 可与导演台 D0 并行；B2 依赖剪辑/混音现有只读函数；B3 依赖导演台 D0。

- [ ] 消息 Markdown 禁用原始 HTML 与 `javascript:` / `data:` 链接；外链图片不自动加载；工具摘要与结果按纯文本渲染；提案差异与建议卡文案同样不解析 HTML/Markdown。

### 12.3 会话、作用域与流式

- [ ] 同一项目内从项目详情 → 分集 → 剪辑 → 交付，历史仍在。

- [ ] 同一 `workspace_key` 并发 `resolve` 只创建一个 `active` 线程，其余请求返回同一线程，不抛唯一键错误。
- [ ] 提案与建议分别收到 `proposal` / `suggestion` 事件。
- [ ] 断线重连能拿到完整回答；重连带 `after_seq` 时不重复、不丢增量；缓冲失效时收到 `reset` 并正确替换文本。

### 12.4 提案

- [ ] 三类提案的允许字段之外一律拒绝。
- [ ] 提案字段超出 §8.1 长度上限或枚举非法时返回 422，不创建提案。
- [ ] `asset.prompt.update` 必须带 `target_type`；角色/场景/道具存在相同 ID 时不会串写。
- [ ] 导演专员只生成 `storyboard.update`，且字段仅 `shot_type` / `angle` / `movement` / `duration`；不生成 `asset.prompt.update` / `line.update`；导演计划数据不被提案修改。
- [ ] 无差异不创建提案。
- [ ] `line.update` 只改 `subtitle_text` 时不动 `text` / `speak_text` / `audio_stale`；同时改 `text` 时派生字段与 `updateLine()` 一致。
- [ ] 回答失败/取消/中断后，该轮已创建提案为 `expired`，不能应用。
- [ ] 会话软删除后，该会话未处理提案为 `expired`，应用返回 410。
- [ ] 应用前目标被修改 → 409，提案变 `conflict`，显示当前值；目标已删除、父项目/集已软删或被移动到其他集/项目 → 410，提案变 `expired`，不跨集写入。
- [ ] 对 `expired` 提案应用或拒绝返回 410；对 `applied` / `rejected` / `conflict` 提案应用或拒绝返回 409。
- [ ] 应用成功写入白名单字段，`before_json` / `after_json` / `applied_by` / `applied_at` 完整。
- [ ] 拒绝不写业务表。
- [ ] 改描述/时长/提示词/景别/机位/运动/氛围/音效/转场/台词/资产提示词后返回“可能过期”警告，不自动删除视频、配音、成片或资产图。
- [ ] `agent.proposals.enabled=false` 时 `propose_change` 不注册，应用与拒绝接口均 403；历史提案只读展示，仍可查看差异，不能应用或拒绝。
- [ ] `agent.proposals.types` 只允许三类子集；关闭某类后 `propose_change` 对该类返回错误且不创建提案；已存在的该类提案可查看、可拒绝，应用返回 403，不能绕过。
- [ ] 应用写回与提案状态更新在同一事务；写回失败不留下半写状态；并发/双击应用只成功一次，其余返回 `409`。

### 12.5 建议

- [ ] 在 `episode` / `director` / `edit` / `mix` / `delivery` 作用域，普通助手都能建议 5 个生产 Agent，但都不会被助手自动运行；导演专员不生成建议；`drama` / `home` / `novel*` 不生成建议。
- [ ] 建议卡显示动作、目标、理由、影响；涉及删除/重生成/覆盖时不提供一键执行，按钮最多打开现有流程。
- [ ] 点击“打开流程”打开现有页面弹窗/按钮流程；页面没有适配器、或当前适配器的作用域与建议卡 `prefill` 的项目/集不一致时，跳转到目标页面并打开正确阶段，不误用当前页面适配器。
- [ ] 在历史线程里点击其他页面生成的建议卡，能用 `prefill` 的 `drama_id` / `episode_id` / `episode_number` 定位到目标集并打开正确阶段。
- [ ] 用户通过建议卡打开流程并执行后，生产 Agent 的写库行为与用户直接点按钮一致。
- [ ] `agent.suggestions.enabled=false` 时 `suggest_action` 不注册；新建议不生成，历史建议卡只读展示。
- [ ] `agent.suggestions.actions` 只允许白名单子集；关闭某动作后不再生成该动作建议；未知 `target` 不生成建议。
- [ ] `prefill` 只含服务端从当前作用域生成的 ID/阶段，模型不能注入额外字段。
- [ ] 建议卡不写入 `agent_proposals`，只随消息保留；保留清理时随消息正文一并清除。

### 12.6 集中配置

- [ ] 设置页“智能体”是智能体配置的唯一入口；不新增第 12 个页签。
- [ ] 生产智能体区有 5 个 Agent，包含 `voice_designer`。
- [ ] 每个生产 Agent、助手、导演专员都能编辑默认模型；生产 Agent 的模型输入框只在中文提示词下显示并提交，切到其他语言不提交 `model`，沿用中文文件的模型。
- [ ] 页面绑定能控制入口组合、默认预设、快捷问题、只读范围；分集路由的 `script` / `assets` / `videos` / `dubbing` / `mix` / `delivery` 阶段可分别配置，未配置阶段时继承路由默认值。
- [ ] 页面绑定把 `defaultPreset` 设为 `director` 但路由不是导演台时，保存时自动回退为 `assistant`，并在设置页提示原因。
- [ ] 会话与审计能看到线程、消息、提案、应用/拒绝记录。
- [ ] 诊断能显示路由作用域解析模拟、模型可用性、工具清单、最近错误。
- [ ] 诊断试跑只接受只读工具；写工具、未知工具、越界作用域返回 400，不执行。
- [ ] `AGENT_DOCK=off` / `AGENT_DIRECTOR=off` / `AGENT_STREAM=off` / `AGENT_PROPOSALS=off` / `AGENT_SUGGESTIONS=off` 需重启后端才生效；设置页 `agent.*` 配置在下一次请求或页面刷新后生效。
- [ ] `maxSteps`、`timeoutSec`、`context.maxChars`、`message.maxChars`、`tools.maxResultChars`、`history.maxMessages` 越界被 clamp；`message.maxChars` 大于 `context.maxChars` 时保存被拒绝并提示。
- [ ] 会话级模型覆盖只影响本次请求，不改全局文本配置。
- [ ] 30 天保留清理只清理过期归档/软删除会话的消息正文、工具调用/结果与建议 JSON，保留会话壳、消息行与提案记录，不影响提案审计。

## 13. 兼容与回滚

| 场景 | 措施 |
| --- | --- |
| 助手回答异常 | 设置页总开关关闭入口并拒绝新会话/新消息（下一次请求/刷新生效）；已有回答可取消；紧急用 `AGENT_DOCK=off`，需重启后端；旧页面不受影响 |
| 导演专员异常 | 设置页关闭导演专员（下一次请求/刷新生效），`preset=director` 请求返回 403；紧急用 `AGENT_DIRECTOR=off`，需重启后端；助手与导演台不受影响 |
| 流式不稳定 | `AGENT_STREAM=off` 退回非流式 |
| 提案误用 | `AGENT_PROPOSALS=off` 禁用提案生成与应用/拒绝接口 |
| 建议误用 | `AGENT_SUGGESTIONS=off` 禁用建议卡 |
| 环境变量回滚 | 所有 `AGENT_*` 均在进程启动时读取；修改后必须重启后端，刷新页面无效；设置页 `agent.*` 不需要重启 |
| 页面适配器异常 | 该页面适配器的 `scope` 计算为 `null`，入口隐藏；不影响其他页面 |
| 模型不可用 | 返回明确错误，不自动切换 provider；用户可清空会话级 `model` / `config_id` 回到默认文本配置；不修改全局配置 |
| 数据 | 3 张新表只增不改；回滚代码后留表不影响旧功能 |
| 提示词 | 设置页可重置 `assistant` / `director` 提示词；不影响 5 个生产 Agent |
| 配置中心回归 | 设置页保留原有 AI、规则、提示词/技能页；智能体中心只新增分区，不删除旧入口 |

## 14. 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 模型直接写库 | 数据被误改 | 助手工具白名单；写工具不注册；测试断言 |
| Mastra workspace 自动注入 | 文件/命令工具绕过只读白名单 | 两个预设不挂载 `workspace`；注册表测试断言无 `read_file` / `write_file` / `edit_file` / `delete_file` / `execute_command`；技能只通过 `loadAgentSkills()` 注入 |
| 作用域越权 | 读到其他项目数据 | 项目/集查询强制 `drama_id` / `episode_id`，小说查询强制 `novel_id`；服务端解析，不信前端 |
| 跨项目串线程 | 上下文混淆 | `workspace_key` 隔离；跨项目 resolve 新线程；前端显示当前项目 |
| 页面换页丢上下文 | 用户重复解释 | 同一项目单线程；每条消息记录作用域；抽屉保留历史 |
| 页面适配器漂移 | 入口显示但作用域错误 | 适配器随页面挂载/卸载；诊断页可模拟路由解析结果 |
| 提示词注入 | 模型尝试删除/覆盖 | 只读 + 提案 + 用户审批；工具结果按数据包装；提案字段白名单 |
| 消息渲染 XSS | 模型或工具输出恶意 HTML/链接 | 安全 Markdown 子集；禁用原始 HTML、事件属性与 `javascript:` / `data:` 链接；工具结果、提案差异与建议卡文案按纯文本渲染；外链图片不自动加载 |
| 提案字段绕过 | 超长文本或非法枚举写入业务表 | 创建与应用双重校验；白名单 + §8.1 长度上限 + 枚举 |
| 环境变量误判 | 以为刷新页面就能回滚 | `AGENT_*` 为 `off` 时强制关闭并优先于设置页，其余以设置页为准；文档与诊断页明确 `AGENT_*` 需重启后端 |
| 建议被误解为已执行 | 用户以为任务已开始 | 建议卡明确“未执行”；只提供“打开流程/打开页面”；系统提示词禁止声称已执行 |
| 上下文溢出 | 回答截断、成本高 | 摘要 + 工具按需读取 + 历史/结果预算 |
| SSE 被代理缓冲 | 看不到增量 | 关闭缓存、心跳、沿用小说任务 SSE 已验证模式 |
| 进程重启 | 回答卡在 running | 启动时标记 `interrupted`；重连返回最终/中断状态 |
| 重复应用 | 同一提案写两次 | 状态机 + `target_hash` + 事务 |
| 提案过期 | 应用到旧目标 | 超过 7 天或目标被删除返回 410；目标哈希不一致返回 409，不强制覆盖 |
| 设置页类型变化 | 旧 Agent 列表异常或旧接口误放行 | `validAgentTypes` 改为显式 `PRODUCTION_AGENT_TYPES`，不再从 `DEFAULT_PROMPTS` 推导；`allAgentTypes` 只用于提示词与注册 |
| 设置中心过重 | 配置难找 | 8 个子区 + 搜索；AI 供应商与流水线规则保留原位并链接 |
| Mastra 版本差异 | `stream()` 不可用 | 流适配层 + 非流式回退开关 |

## 15. 与 V1 的差异

1. **架构**：从“全局抽屉 + 按页面切作用域”改为“统一内核 + 页面适配器 + 同一项目单线程”。
2. **会话**：从“切换页面只影响新会话”改为“每条消息记录作用域与预设；同一项目跨页共用线程；跨项目新线程”。
3. **页面**：新增页面适配器接口与完整嵌入矩阵；页面只声明作用域、快捷问题、建议执行入口，不各自实现聊天。
4. **导演专员**：从“第二个入口/另一套会话”改为同一运行时的预设，共用线程与 `AgentDock`。
5. **建议**：新增 `suggest_action` 与建议卡，承接“助手可建议触发生产 Agent”；执行仍走现有页面流程，助手不直接调用生产 Agent。
6. **配置**：`agents` 页签升级为“智能体”中心，覆盖开关、页面绑定、生产智能体、两个预设、工具与权限、模型与预算、会话与审计、诊断；补齐 `voice_designer` 与单 Agent 模型。
7. **数据**：仍为 3 张表；`agent_sessions` 增加 `workspace_key` / `preset`，`agent_messages` 增加 `scope_json` / `preset` / `suggestions_json`，不新增第四张表。
8. **接口**：统一到 `/assistant/*`，与生产 Agent 的 `/agent/:type/chat` 明确分开。
9. **阶段**：从 A0–A4 调整为 B0–B4，配置与适配器先行，只读、提案、建议、诊断依次落地。
