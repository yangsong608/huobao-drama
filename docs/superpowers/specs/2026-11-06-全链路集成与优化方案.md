# 火宝短剧全链路集成与优化方案

- 日期：2026-11-06
- 版本：v2（补充导演台一致性、剪辑能力、AI/Agent 对比、幻界 UI 借鉴）
- 状态：待评审（设计稿，未实施）
- 范围：小说、导演台、剪辑与音频工作台、Agent、UI 五个方面的集成与优化
- 前置决策：新增 2D/3D 导演台；现有生产面板与生成链路保持不动
- 实施边界：本方案批准前不写代码、不提交、不构建、不安装、不重启；端口、ComfyUI 网关、H3 工作流、模型与密钥配置均不变

> 本次修订回答四个问题：① 导演台与现有剧本/分集→分镜是否一致；② 剪辑能力如何加强到音频工作台和剪辑工作台；③ 现有 AI 调度与幻界 Agent 的差异、用途和升级路径；④ 幻界 UI 哪些该学、哪些不该学。结论见 0.4，细节见第 4、5、6、7 节。

## 0. 结论先行

### 0.1 一条主轴

```text
小说（故事源）
  → 剧本 / 分集（改编）
  → 分镜 storyboards（生产契约）
  → 导演台（2D 排演 + 3D 机位预演）
  → 生产（现有生成面板，不动）
  → 成片中心（唯一成片目录）
  → 剪辑 / 混音（以成片为源）
  → 交付
```

导演台插在“分镜”和“生产”之间，只做**排演、机位、构图、镜头节奏**，不接管生成执行。它把确认后的镜头参数写回分镜，生产面板仍然读分镜，现有链路不需要改。

### 0.2 三个“不新增”

1. **不新增第二套分镜**：`storyboards` 仍是生产侧唯一的镜头契约；导演台是叠加层，不是另一条时间线。
2. **不新增第二套成片列表**：成片只由 `video_merges` 表达；剪辑、混音、交付共用成片中心；该结论以现有《成片中心与混音 / 剪辑工作台重构设计》为准。
3. **不新增第二套 Agent 入口**：保留 5 个流水线专员，新增导演专员与一个全局创作助手；全局只保留一个助手抽屉，不在每个页面重复做聊天框。

### 0.3 五个方面的推荐结论

| 方面 | 推荐结论 | 实施定位 |
| --- | --- | --- |
| 小说 | 从“AI 生成 + 单章编辑”升级为完整写作台：章节树、引文批注、伏笔板、改编上下文包 | 基础层后并行；首版三栏 split 默认 |
| 导演台 | 新增独立工作台，2D 平面调度与 3D 机位预演共用一份镜头表；**导演镜头 = 分镜段落 1:1，子镜头内嵌**；3D 用代理资产，不做角色动画 | 基础层后并行；2D 与 3D 同期交付 |
| 剪辑 | 分两条线：**P3a 剪辑能力增强（不等成片中心）**；P3b 成片中心与剪辑源集成。音频工作台与剪辑工作台共用一套编辑内核 | 基础层后并行；P3a 先补渲染/导出闭环，P3b 另做 |
| Agent | 5 个专员保留不动；新增助手与导演专员（只读 + 提案，助手另有建议卡），补作用域/流式/审计；写入走“提案 → 确认 → 应用”；确定性流水线不改为 Agent | 基础层后并行；助手 + 导演专员，导演专员依赖导演台只读接口 |
| UI | 一级导航不变；统一 studio 工作台骨架；单集增加“导演台”入口；成片统一列表/选择器；术语中文化、可发现性优先 | U0/U1 属基础层先做；UI U2–U5 随工作包并行 |

### 0.4 四个问题的直接回答

#### 问题 1：2D/3D 导演台的输入输出，和现有剧本/分集→分镜一致吗？

**结论：生产单元一致，镜头粒度不一致，必须按“段落 + 子镜头”修正。**

| 层级 | 现有事实 | 导演台必须遵守的边界 |
| --- | --- | --- |
| 剧本/分集 | `episodes.content` 是原文，`scriptContent` 是格式化剧本 | 导演台只读，不改剧本；剧本变化通过 `sourceStale` 提示，不由导演台自动重写 |
| 分镜 | 一个 `storyboards` 行 = 一个 **8–15 秒分镜段落** = 一个视频生成任务；段落内部承载 **2–4 个子镜头**，子镜头只存在于 `description`/`videoPrompt` 文本中 | 导演镜头必须 1:1 绑定分镜段落；子镜头作为段内计划项，不能伪装成独立生产任务 |
| H3 整集 | 一个分镜段落 → 一个 `timeline_data` segment；24fps；帧数按 `17n+5` 对齐；时长会被向上取整 | 导演台不能另造时间线；改时长必须按帧网格重算并提示“生成结果将变化” |
| 参考图 | 每个 segment 的场景→角色→道具参考图按固定顺序编号，`@角色名` 映射为 `<Picture N>` | 导演台不能改变角色/道具集合与顺序；新增角色要先走现有资产关联 |
| 写回 | 生产只读 `storyboards` | 只写回分镜字段；不写 `sys_task`、`timeline_data`、`video_merges`、剪辑工程 |

原稿把“导演镜头”默认成与分镜 1:1 的单一镜头，这只在生产段落层成立，在子镜头层不成立。修正方案见 4.0 与 4.2.3：`director_shots` 与分镜段落 1:1，子镜头用 `subshots_json` 内嵌，段级机位用一条相机路径表达；首版不做“一个子镜头一个独立机位/独立生成任务”。

#### 问题 2：剪辑功能如何加强到音频工作台和剪辑工作台？

**结论：不是把两个工作台做成一样，而是抽出一套共用编辑内核，让两者各自强在正确的地方。**

- **音频工作台已经强在音频**：波形、片段增益/声像/淡入淡出/淡变曲线、循环/静音/锁定、拆分/复制、轨道 M/S/闪避/循环/锁定、总线与闪避参数、LUFS/真峰值、区间预览、实时多轨监听、版本。
- **剪辑工作台强在画面、弱在声音**：视频/字幕/音频三轨、修剪/变速/间隙/淡入淡出、转场、字幕、版本与冲突；没有音频波形与音频片段检查器、没有多选/框选、没有右键菜单、没有多片段波纹删除、没有 J/L 切、没有交叉淡化、没有音量自动化。
- **加强方向**：共用 `EditCommand`（所有变更可撤销/可审计）+ 共用选择模型（单选/多选/框选/范围）+ 共用时间线交互（吸附、波纹、右键、快捷键）+ 共用音频检查器；音频工作台补“剪辑级”操作，剪辑工作台补“音频级”操作。
- 详细能力矩阵与能力重要度见 5.4–5.8；P3a 不依赖成片中心，可先做。

#### 问题 3：现有 AI 调度和执行，和幻界 Agent 有什么区别？用在哪里？升级成 Agent 怎么做？

**结论：现有 AI 是“配置 + 适配器 + 任务队列 + 确定性流水线”，幻界是“会话型主管 Agent + 子 Agent + 工具审批”；两者不是替代关系。**

| 维度 | 本项目现状 | 幻界 Agent | 判断 |
| --- | --- | --- | --- |
| 调度单位 | `sys_task` 图片/视频任务 + `pipeline_jobs` 整集任务 | 一次会话 turn + 工具调用循环 | 我们强在媒体任务生命周期，弱在会话内连续决策 |
| 编排 | `automation.ts` 固定 8 阶段串行，失败即停 | 主控按目标动态选工具/子 Agent | 固定流水线适合量产，不适合异常处理与跨模块任务 |
| 交互 | 非流式、必须 `drama_id + episode_id`、无会话记忆 | 流式、可中断、可追问、上下文压缩 | 需要补流式、作用域与会话状态 |
| 写入 | 5 个专员直接写业务表 | 工具审批 + 参数冻结 + 作用域规则 | 需要补“提案→确认→应用”与审计 |
| 工具面 | 5 组领域工具，只覆盖剧本/提取/分镜/提示词/音色 | `Run` 命名空间覆盖小说/制作/剪辑/资产/设置等 | 需要补导演、小说、成片、剪辑只读/提案工具 |
| 失败恢复 | `sys_task` 可恢复上游任务；自动化有 3 小时超时 | 流超时/重试/截断续写/循环检测 | 可借鉴长任务收敛与会话恢复 |
| 成本控制 | 配置优先级 + 集锁定 + 重试确认 | 审批门禁 + 工具白名单 | 花钱动作不交给 Agent，仍由现有按钮发起 |

**用在哪里**：确定性整集生产继续用现有流水线；Agent 只用在“需要理解、比较、解释、补救”的地方——小说创作陪写、单集生产诊断、导演建议、剪辑粗剪/连续性检查、资产一致性质检、跨模块问答。不要让 Agent 取代批量生成流水线。

**升级怎么做**：按 6.5 的五层增量走——① 作用域与流式；② 消息状态、取消与恢复（`agent_messages`，不新增 runs/steps 表）；③ 领域只读/提案工具 + 用户确认；④ 主控 + 子 Agent 编排；⑤ 上下文、评测与观测。每一步都可独立上线，不推翻现有 5 个专员。

#### 问题 4：幻界的 UI 应该学哪些地方？

**结论：学“信息架构与工作台骨架”，不学“低对比、过小字号、过多隐藏入口”。**

该学的 8 点：① 左侧项目树 + 顶栏面包屑 + 中央舞台 + 右侧检查器 + 底部时间线的稳定骨架；② 分段控件切换视图（分镜/画布/列表、2D/3D）；③ 轨道头常驻 M/S/锁定/可见性；④ 底部状态栏显示自动保存/字数/历史；⑤ 空状态 = 图标 + 一句原因 + 一个主按钮；⑥ 关键帧菱形、滑杆、数值输入并列；⑦ 设置用左栏分类 + 右侧内容，而不是无限长页面；⑧ 媒体舞台固定深底、UI 退后，内容优先。

不该照搬的 5 点：① 12px 左右的小字对中文过长文案不友好；② 大面积纯黑低对比，长时间剪辑易疲劳；③ 左侧导航层级过深、很多图标无文字；④ 大量操作只在悬浮/右键里，新用户找不到；⑤ 右侧 AI 面板常驻会挤压舞台。

落到本项目的 6 个改动见 7.5–7.7：统一顶栏、统一状态栏、统一轨道头与传输条、统一空状态与错误横幅、建立中文排版与动效令牌、把 Agent 做成可收起的 `AgentDock` 而不是常驻侧栏。不新增 `StudioShell` 组件，页面各自保留布局，只共用组件。

### 0.5 实施顺序（2026-11-06 已决策）

本轮不按业务价值排先后，按基础依赖推进；四个工作包之间不设优先级。

| 决策项 | 结论 | 落地影响 |
| --- | --- | --- |
| 首批顺序 | 从基础做，不设优先级 | 先完成跨方案基础层，再并行四个工作包 |
| 导演台首版 | 2D + 3D 同期 | D3 不再是可选阶段，与 D0–D2 同批验收 |
| 智能体首版 | 助手 + 导演专员 | 独立方案补 `director` 专员；依赖导演台只读接口 |
| 小说首版布局 | 三栏 split 默认 | `tabs` 降为配置回退，N0 直接落三栏空壳 |

实施批次：

1. **B0 基础层（先做，不产生业务行为变化）**：U0/U1 令牌与工作台壳、`app_settings` 新命名空间、各工作包新表迁移骨架与共享类型契约、路由占位、开关默认值。
2. **B1 四个工作包并行（按各自内部依赖推进，不排先后）**：小说 N0–N3、导演台 D0–D3（2D+3D）、剪辑 E0–E4（P3a-1）→ K1–K4（P3a-2）、《智能体落地方案》B0–B2（助手、只读、提案）。
3. **B2 依赖收口（可随 B1 并行启动）**：《智能体落地方案》B3–B4（建议、导演专员、诊断；导演专员依赖导演台只读 API）、UI U2–U5（随对应工作包并行）、可选 N4；E5（=K5，成片中心）单独排期。

工作包内部的顺序仍按依赖：剪辑先补 E0–E2 渲染/导出闭环，再做 E3–E4 基础易用性，最后 K1–K4 共用内核；导演台 D0–D2 与 D3 同批交付，3D 复用 2D 的镜头表；智能体先助手再导演专员。

#### 0.5.1 核对结果（2026-11-06）

- 四项待决策已确认：实施顺序从基础层开始、导演台 2D+3D 同期、智能体助手+导演专员、小说三栏 split 默认；结论见本节上表。
- 本轮核对修正：

  2. 剪辑切片统一：P3a-1 = E0–E4，P3a-2 = K1–K4，K5 = P3b；E/K 编号不再混用。

  5. 7.10 只保留 A–D 接入点，U0–U5 以《页面视觉优化落地方案》第 9 节为准。
- 结构校验：六份方案代码围栏、相对链接、表格列数全部通过；`StudioShell` 残留均为“不新增”或反向说明。

### 1.2 关键事实

1. **分镜事实上已经是“导演计划”的载体**：`storyboards` 已有景别、角度、运动、转场、连续性、时长、提示词等字段（`backend/src/db/schema.ts:186-200`），但它们是 Agent 生成的文本字段，没有可视化排演、没有机位、没有构图预览。
2. **H3 整集链路只认分镜**：每个分镜段落映射为一个 timeline segment，帧网格 `17n+5`、24fps、参考图按场景→角色→道具编号（`backend/src/services/comfyui-timeline.ts:44-57`；`backend/src/services/comfyui-episode.ts:312-395`）。导演台若另造时间线，会直接破坏这条链路。
3. **单集页没有导演入口**：侧栏只有剧本、生产、配音、导出四段（`frontend/app/views/drama/episode.vue:3561-3596`），顶栏动作只有配音、剪辑、交付、刷新、任务（`:63-90`）。
4. **剪辑默认从分镜起步**：`bootstrapEditPlan` 在 `mode=on` 时先装配分镜视频；只有分镜没有可用视频时，才回退到最近合片或 `episode.video_url`（`backend/src/services/edit-bootstrap.ts:243-320`）。这意味着“成片”不是剪辑的默认输入。
5. **混音自动取最近一次非混音合片**：`latestMergeBed` 按 id 倒序找最近完成、未删除、非 mix 的合片（`backend/src/services/mix-plan.ts:342-360`），用户不能在界面选择源成片。
6. **成片目录尚未统一**：`video_merges` 是拼接/混音合片目录，`episode_exports` 是导出任务记录；混音和剪辑导出只进后者，不回成片列表。该问题已在《2026-11-06-film-hub-mix-edit-redesign.md》中定义，但尚未实施。
7. **Agent 是流程按钮，不是跨模块助手**：路由强制要求 `drama_id` 与 `episode_id`（`backend/src/routes/agent.ts:39-51`），上下文只注入 episode/drama（`backend/src/agents/context.ts:9-25`），没有小说、导演台、成片、剪辑的领域工具。
8. **小说模块以 AI 生成为主**：现有 6 个 Tab 是概览、架构、蓝图、写作、罗盘、导出（`frontend/app/views/novel/detail.vue:228-235`）。写作 Tab 已有章节下拉、正文编辑、自动保存与 409 冲突处理（`frontend/app/components/novel/ChapterWriterPanel.vue:91-98`、`:320-365`），但缺少章节树、引文批注、伏笔板、人物档案分区等写作台能力。
9. **没有 3D/画布依赖**：前端依赖只有 Nuxt/Vue/Pinia/Naive UI/ECharts/Driver.js 等，没有 three.js、Konva、Pixi、Babylon（`frontend/package.json`）。3D 导演台需要新增依赖，必须单独评估体积与性能。
10. **UI 是三套布局、三条路径**：`default`、`novel`、`studio` 三套布局（`frontend/app/layouts/`）；单集、剪辑、混音都是全屏 studio，但入口分散在顶栏按钮与页面内部，用户很难建立“这一集现在在哪一步”的整体感。
11. **分镜是段落，不是单镜头**：`storyboard_breaker` 的定义是“一个分镜 = 一个分镜段落 = 一个视频生成任务，8–15 秒，内部 2–4 个子镜头”（`backend/src/agents/index.ts` 的 `storyboard_breaker` 提示词）。因此导演台不能按“一个子镜头一个分镜行”设计。
12. **时长会被帧网格改写**：H3 默认 24fps、帧网格 `17n+5`；`storyboards.duration`（秒）先换算成帧，再按网格对齐，返回的 `durationSec` 可能大于原值（`backend/src/services/comfyui-timeline.ts:262-272`）。导演台改时长必须显示“对齐后时长”，不能只写秒数。
13. **AI 是四层，不是一层**：配置解析（`backend/src/services/ai.ts:9-145`）、媒体任务与轮询（`generation.ts:27-550`）、固定 8 阶段自动化（`automation.ts:246-740`）、Mastra 的 5 个专员（`agents/index.ts:403-416`）。专员只是局部文本工具循环，不是总调度器；把四层混成“一个 Agent”会误判改造范围。
14. **媒体任务没有进入持久化队列**：`pipeline_jobs` 只接管 `episode` 资源的 `automation` 与 `dub`；图片/视频任务由 `runBackground` 直接在进程内跑，`activeTasks` 只防同一任务重复，不提供全局并发上限（`backend/src/services/generation.ts:27-33`、`queue-worker.ts:42`）。
15. **两个工作台的编辑能力不对等**：混音有波形、片段级音频参数、总线/闪避、实时监听；剪辑只有三条可见轨、没有音频波形与音频检查器（`frontend/app/components/MixTimeline.vue:99-300`、`MixClipInspector.vue:220-350`；`frontend/app/components/edit/EditTimeline.vue:1-220`、`EditClipInspector.vue:1-220`）。
16. **Agent 工具直接写库**：`save_script`、`save_dedup_characters/scenes/props`、`save_storyboards`、`save_character_final_prompt` 等工具在 `execute` 内直接写业务表，没有提案/确认层（`backend/src/agents/tools/*.ts`）。

### 1.3 与参考项目的差距

参考项目 Reveric 的关键能力已在《参考项目分析》中核实：

- **3D 导演台是“可编排的镜头预演器”**：有限角色/道具/机位、固定 24fps、离屏抽帧、可烘焙运镜，不是实时游戏引擎（`docs/参考项目分析/02-智能体-剪辑-三维技术分析.md` C 节）。
- **剪辑以帧为唯一时间单位**，六轨、修订冲突、分块渲染、字幕策略；导演台输出不会自动进入分镜或剪辑，链路存在断点（`docs/参考项目分析/05-全流程制作与功能分析.md` 第 7、8、10 节）。
- **Agent 操作领域命令，不直接操作数据库**；导演台与剪辑都通过版本文档 + 命令 + 渲染驱动（同上第 11 节；02 文档 E 节）。
- **小说是完整写作台**：章节树、编辑器、自动保存、批注、伏笔、人物七区块（`docs/参考项目分析/06-小说制作分析.md` 第 6-10 节）。

本项目的优势不在“再做一个 Reveric”，而在**短剧垂直链路、H3 整集时间线、ComfyUI 命名工作流、中文生产语料**。因此本方案不照搬参考项目的全部模块，只借它的三条骨架：文档化、命令化、预演边界。

## 2. 问题定义与影响

> 这里的“高/中/低”指问题严重度，不是实施顺序；实施顺序见 0.5。

### 高影响：不解决就无法形成闭环

| # | 问题 | 根因 | 影响 |
| --- | --- | --- | --- |
| 1 | 导演意图无处承载 | 分镜只有文本字段，没有摆位、机位、构图、镜头运动可视化 | 生成前无法确认构图，返工成本高；2D/3D 导演台无入口 |

### 中影响：影响效率与产品一致性

| # | 问题 | 根因 | 影响 |
| --- | --- | --- | --- |
| 5 | 两个工作台剪辑能力不对等 | 混音与剪辑各有独立交互，没有共用命令/选择/音频检查器；剪辑没有波形与音频片段编辑 | 用户要记住两套操作；在剪辑里无法精修声音，在混音里无法精修画面 |

## 3. 目标架构

### 3.1 四层职责

| 层 | 职责 | 唯一规则 |
| --- | --- | --- |
| 故事层（小说） | 故事、章节、人物、世界观、伏笔、改编上下文 | 小说是故事源；不承担生成执行 |
| 计划层（分镜 + 导演台） | 分镜段落是生产契约；导演台是排演与镜头设计叠加层；导演镜头与分镜段落 1:1，子镜头内嵌 | `storyboards` 是唯一生产镜头表；导演台不另造生产时间线，不把子镜头变成独立生成任务 |
| 执行层（生产） | 素材生成、逐镜视频、ComfyUI 整集时间线 | 现有面板与链路不动；只读分镜与资产 |
| 成品层（成片中心 + 剪辑/混音 + 交付） | 成片目录、混音、剪辑、导出 | `video_merges` 是唯一成片目录；剪辑/混音导出只新增成片，不覆盖 |

Agent 横切四层，但权限分两种：现有 5 个专员只在用户主动点击的任务内直写当前集；新增 `director`/`assistant` 只读 + 提案，经领域 API 与用户确认后应用。UI 为每层提供唯一入口。

### 3.2 零侵入契约（针对“保留现在的不动”）

1. **生产面板内部不改**：不修改 `panel === 'production'` 的分支、`prodTab` 的 `assets | videos` 状态机、生成按钮与轮询逻辑（`frontend/app/views/drama/episode.vue:261-1006`、`:2117`、`:3548-3596`）。
2. **入口层只做加法**：在单集顶栏新增一个“导演台”按钮，跳转独立路由；若评审要求连入口都不改，第一阶段可先用 URL 直达，验证后再加入口。
3. **分镜写入必须显式确认**：导演台不自动覆盖 `video_prompt`、`image_prompt`、首尾帧；只有用户点“应用到分镜”并在差异对话框中确认的字段才写回。
4. **生成链路不变**：不改 ComfyUI 网关、命名工作流、`timeline_data` 映射、H3 帧网格、TTS 端口与模型配置。
5. **成片链路不变**：导演台不产生成片；成片只由拼接、混音、剪辑导出产生，且遵循成片中心设计。

### 3.3 为什么不把导演台塞进单集页

- 单集页已经 8555 行，包含剧本、素材、视频、配音、导出五套状态；继续加 2D/3D 视口会把耦合并发推到不可维护。
- 剪辑已经是独立 `studio` 页面（`frontend/app/views/drama/edit.vue`），导演台沿用同一模式，风险最低。
- 导演台页签内的 3D 子页签可以动态 import three.js（仅切到 3D 时加载），不影响现有生产页首屏体积。

### 3.4 导演台的技术路线选择

| 路线 | 做法 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| A. 纯 2D | SVG 平面图 + 分镜卡片 | 最快、最稳、无新依赖 | 没有空间感，无法预演机位高度/焦距 | 作为 2D 模式 |
| B. 2.5D 视差 | 用生成图做分层视差，模拟推拉摇移 | 视觉接近成片，素材现成 | 机位数学是假的，无法与 3D 机位/构图对应 | 不推荐作为主路线 |
| C. 真 3D 预演 | three.js + 代理角色/道具 + 真实相机 | 机位、焦距、构图可复现；可抽帧 | 需要新依赖与资产代理；容易滑向游戏引擎 | **推荐**，但严格限界 |

**推荐 C，并把边界写死**：3D 导演台是“可编排的镜头预演器”，不是角色动画、不是最终渲染、不是游戏引擎。角色用代理卡/简单几何体，场景用平面 + 背景图，机位用真实透视相机；只保证构图、机位、镜头运动、时长的可复现。

## 4. 导演台详细方案

### 4.0 输入输出与现有链路一致性核对

#### 4.0.1 先看现有链路到底以什么为单位

```text
小说/原文
  → episodes.content（本集原文）
  → script_rewriter → episodes.scriptContent（格式化剧本）
  → storyboard_breaker → storyboards（每行一个 8–15 秒分镜段落，内部 2–4 个子镜头）
  → 生产：逐镜原生生成 或 ComfyUI 整集时间线
      · 逐镜：storyboards.id ↔ sys_task.storyboard_id
      · 整集：storyboards.id ↔ timeline_data segment.storyboardId
  → video_merges（拼接/混音成片）→ 剪辑/混音 → 导出
```

关键事实（均可从代码核对）：

| 事实 | 证据 | 对导演台的含义 |
| --- | --- | --- |
| 分镜行 = 段落 = 生成任务 | `storyboard_breaker` 提示词：“一个分镜 = 一个分镜段落 = 一个视频生成任务，每个段落 8-15 秒，内部承载 2-4 个子镜头” | 导演台的主单位必须是段落，不是子镜头 |
| 分镜字段是段级单一值 | `shotType`、`angle`、`movement`、`duration`、`transition` 都是 `storyboards` 行字段（`backend/src/db/schema.ts:178-214`） | 一个段落只能写回一个景别/角度/运动；子镜头差异只能留在描述/提示词 |
| H3 一段对一分镜 | `storyboardRows.map(...)` 直接生成 `timeline_data` segments，`storyboardId` 原样带入（`backend/src/services/comfyui-episode.ts:312-395`） | 导演台不能新增/拆分 segment，除非用户显式“拆分分镜” |
| 时长按帧网格对齐 | `desired = duration × fps`，再 `alignTimelineFrames(desired, {step:17, offset:5})`（`backend/src/services/comfyui-timeline.ts:262-272`） | 导演台显示“计划时长”和“实际成片时长”两个值 |
| 参考图按场景→角色→道具 | 先场景，再按关联角色顺序，再按关联道具顺序；`@name` 重写为 `<Picture N>`（同上 `:318-360`） | 导演台不能改参考图顺序；换角色要回到资产关联 |
| 提示词是唯一镜头语言载体 | `videoPrompt` 按 3 秒一段书写，`description` 用【镜头N】描述子镜头 | 子镜头的景别/角度如果要影响生成，最终仍要落到 `videoPrompt` 文本 |

#### 4.0.2 导演台的输入契约

| 输入 | 来源 | 只读/可写 | 用途 | 约束 |
| --- | --- | --- | --- | --- |
| 项目画幅/风格 | `dramas.aspectRatio`、`style`、`visualBackground` | 只读 | 2D 画幅、3D 遮罩、预演色调 | 不在导演台改项目设置 |
| 集信息 | `episodes.id/dramaId/episodeNumber/title/videoMode/resolution` | 只读 | 标题、画幅、分辨率、生产方式提示 | 不改生产方式 |
| 剧本 | `episodes.scriptContent`、`content` | 只读 | 场景/台词/动作参考；子镜头拆分依据 | 导演台不改剧本 |
| 分镜段落 | `storyboards` 全部镜头字段 | 读 + 受限写回 | 导演计划的主数据源 | 只写回勾选字段，见 4.0.3 |
| 场景资产 | `scenes`（`location`、`prompt`、`lighting`、`imageUrl`） | 只读 | 2D 场景区域底图、3D 背景 | 没有图时用色块/占位 |
| 角色资产 | `characters` + `episodeCharacters` | 只读 | 代理角色、参考图、身高/朝向 | 只能使用已关联角色 |
| 道具资产 | `props` + `episodeProps` | 只读 | 代理道具、摆位 | 只能使用已关联道具 |
| 分镜关联 | `storyboardCharacters`、`storyboardProps` | 只读 | 每个段落的出场角色/道具 | 导演台不能自行增删关联 |
| 已生成结果 | `storyboards.videoUrl/firstFrameImage/lastFrameImage`、`sys_task` 状态 | 只读 | 显示“已有生成/需重生成” | 不自动删除旧结果 |
| 导演计划 | `director_plans`、`director_shots`、`director_previs_assets` | 读写 | 摆位、机位、子镜头、预演图 | 新增表，不动现有表 |

#### 4.0.3 导演台的输出契约

| 输出 | 落到哪里 | 是否影响生产 | 规则 |
| --- | --- | --- | --- |
| 导演计划/版本 | `director_plans`、`director_plan_revisions` | 否 | 只影响导演台自身；版本可恢复 |
| 导演镜头（段级） | `director_shots` | 否，直到“应用” | 与 `storyboards` 1:1；保存 `storyboard_updated_at` 做冲突检测 |
| 子镜头计划 | `director_shots.subshots_json` | 否 | 段内排序、起止、景别/角度/主体/备注；不单独生成 |
| 2D 平面布局 | `director_plans.layout_json` | 否 | 坐标、朝向、机位、场景区域 |
| 3D 世界/相机 | `director_plans.world_json`、`director_shots.camera_json` | 否 | 代理资产、灯光、关键帧；不做最终渲染 |
| 预演静帧 | `director_previs_assets` | 否 | 首/中/尾帧、联系表；默认不覆盖分镜首尾帧 |
| 应用差异 | `storyboards` 勾选字段 | 是 | 逐条结果；带 `revision`/`updated_at`；409 不静默覆盖 |
| 生产任务 | 不写 | 否 | 导演台不创建 `sys_task`、不写 `timeline_data` |

**明确不输出**：不改 `scriptContent`，不新增/删除角色场景道具，不改 `storyboardCharacters/storyboardProps`，不改参考图顺序，不生成视频，不生成成片，不写剪辑工程。

#### 4.0.4 粒度结论：段落 1:1 + 子镜头内嵌

| 方案 | 做法 | 问题 | 结论 |
| --- | --- | --- | --- |
| A. 导演镜头 = 子镜头 | 每个子镜头建一行 `director_shots`，并各自对应一个分镜 | 与现状冲突：一个分镜段落有 2–4 个子镜头，拆开后 H3 段数、时长、参考图、音画全部变化 | 不采用 |
| B. 导演镜头 = 分镜段落，子镜头不表达 | 一段一个机位一个景别 | 无法真正排演子镜头，导演台退化成字段编辑器 | 不采用 |
| C. 导演镜头 = 分镜段落，子镜头内嵌 | `director_shots` 1:1 分镜；`subshots_json` 记录段内子镜头；段级写回分镜，子镜头用于预演与提示词提案 | 子镜头不能单独生成；需要校验子镜头时长之和 | **推荐** |
| D. 两种模式并存 | 用户可把段落拆成多个生产段落 | 需要改 `storyboardNumber`、时长、参考图、H3 映射，属于“改生产契约” | 后续独立能力，不纳入首版 |

**推荐 C 的三条硬规则**：

1. **一段一镜**：`director_shots.storyboard_id` 唯一（允许为空表示计划镜头）；一个分镜段落最多一个导演镜头。
2. **子镜头只做计划**：子镜头有 `id`、`index`、`start_ms`、`end_ms`、`shot_type`、`angle`、`movement`、`subject`、`note`；不单独拥有生成任务、参考图集合或成片。
3. **写回只到段级**：`shotType/angle/movement/transition` 写分镜段级字段；子镜头差异只能通过“追加镜头语言到 `video_prompt`”提案，用户确认后才写文本。

#### 4.0.5 一致性结论

| 检查项 | 结论 | 处理 |
| --- | --- | --- |
| 生产单元 | 一致 | 导演镜头 = 分镜段落 = H3 segment = 视频任务 |
| 子镜头 | 现状用文本承载，导演台需显式表达 | 内嵌 `subshots_json`，不新增生产行 |
| 时长 | 现状秒 → 帧 → `17n+5` 对齐 | 导演台同时显示计划时长/对齐时长；应用时提示变化 |
| 景别/角度/运动 | 现状段级单值 | 段级写回；子镜头差异只进提示词提案 |
| 转场/连续性 | 现状段级字段 | 导演台按段边界显示，不跨段自动改写 |
| 参考图 | 现状按段、固定顺序 | 导演台只读展示；不改变顺序与集合 |
| 首尾帧 | 现状分镜字段 | 预演帧默认只入 `director_previs_assets`；用户勾选才写 |
| 生成状态 | 现状 `sys_task`/`storyboards.status` | 应用后标记“需重生成”，不自动触发生成、不删除旧视频 |
| 成片/剪辑 | 现状由 `video_merges` 与剪辑工程表达 | 导演台不产出成片；剪辑只读显示导演标记 |

### 4.1 产品定义

**一个工作台，两种视图，共用一份镜头表。**

- **2D 视图**：俯视平面调度 + 分镜板。解决“人站在哪、机位在哪、景别多大、镜头怎么接”。
- **3D 视图**：可旋转的预演场景 + 真实相机。解决“这个机位拍出来是什么构图、推拉摇移是否穿帮”。
- **共用数据**：场景布局、角色摆位、机位、镜头时长、景别/角度/运动、**段内子镜头序列**、备注。切换视图不丢数据。
- **输出**：预演静帧、构图参考、应用回分镜的字段差异；不直接输出视频。
- **主单位**：一个导演镜头对应一个现有分镜段落；子镜头只在段落内部排演，不拆成新的生产任务。

用户的主路径：

```text
进入导演台 → 从现有分镜导入镜头
  → 2D 摆位/定机位 → 3D 检查构图 → 抽首/中/尾帧
  → 应用到分镜（差异确认）
  → 回生产面板生成（现有链路）
```

### 4.2 数据模型：三种方案与推荐

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A. 单文档 | 一集一个 JSON 文档，镜头/场景/机位全在文档里 | 版本化简单；贴近参考项目；Agent 易读写 | 与 `storyboards` 关联弱；查询/统计/联表困难 |
| B. 全关系 | 镜头、场景、机位、关键帧都建表 | 易联表、易增量更新 | 表多、迁移多、版本快照复杂 |
| C. 混合 | `director_plans` 元数据 + `director_shots` 关系表（**1:1 分镜段落**） + 子镜头/布局/机位 JSON + 版本快照 | 既能联表又能版本化；与分镜段落 1:1；子镜头不破坏生产契约 | 需要明确 JSON 与关系字段的边界 |

**推荐 C。** 理由：本项目是 Drizzle + SQLite 的关系型应用，分镜、成片、剪辑都靠 id 关联；纯文档会把“导演镜头 ↔ 分镜”变成运行时解析，Agent 和测试都更难。混合方案把“可查询的段落镜头”放关系表，把“连续变化的布局/机位/子镜头”放 JSON，兼顾两者。**不新增 `director_subshots` 表**：子镜头是段落的内部编排，不是独立生产实体。

#### 4.2.2 与 `storyboards` 的同步规则

| 规则 | 说明 |
| --- | --- |
| 唯一生产契约 | `storyboards` 仍是生产/ComfyUI 的唯一镜头来源；导演台不产生 `timeline_data` |
| 导入粒度 | 首次进入从当前集 `storyboards` 生成 `director_shots`，**一个分镜段落对应一个导演镜头**；不复制提示词正文，只复制计划字段；同时把 `duration` 秒换算为 `duration_ms` |
| 子镜头 | 导入时把 `description` 的【镜头N】解析为初始子镜头（尽量保留原文），解析失败则生成 1 个子镜头覆盖整段；子镜头编辑不写回分镜 |
| 应用 | 用户在差异对话框中勾选字段，后端只更新勾选字段；默认勾选景别/角度/运动/转场，**时长默认不勾选**，必须显式勾选并看到“对齐后时长”警告 |
| 时长 | 勾选时长时，后端按 `fps` 和 `frameGrid(17n+5)` 计算实际帧数与 `durationSec`；若与原值不同，差异对话框显示“计划 12.0s / 实际 12.25s”；应用后标记旧视频为需重生成 |
| 冲突 | 请求带 `plan.revision` 与分镜 `updated_at`；任一不一致返回 409，让用户选择“重新载入 / 覆盖” |
| 新增镜头 | 第一阶段只允许在导演台内新增“计划镜头”（`storyboard_id` 为空）；第二阶段再支持“下发为分镜”，走现有分镜保存服务，保证 `storyboardNumber`、关联角色/道具、`sourceHash` 一致 |
| 删除 | 导演台删除计划镜头不删除分镜；只有用户明确“同时删除分镜”才调用分镜删除 |
| 分镜被删 | 导入过的分镜若被删除，导演镜头转 `detached`，保留数据并提示“重新关联或删除计划”；不自动重建分镜 |
| 提示词 | 导演台不自动改写 `video_prompt`；可选“追加镜头语言”（如“35mm，中景，缓慢推近”），由用户确认后追加到原提示词末尾；追加后同样标记需重生成 |
| 生成结果 | 应用只更新分镜字段和 `updatedAt`，不删除 `videoUrl`/首尾帧；前端显示“分镜已变，建议重新生成”，由用户在现有生产面板决定 |

#### 4.2.3 子镜头结构（`subshots_json`）

```json
[
  {
    "id": "ss_1",
    "index": 1,
    "startMs": 0,
    "endMs": 3000,
    "shotType": "medium",
    "angle": "eye_level",
    "movement": "push_in",
    "subject": "沈砚",
    "note": "从门口推近，停在她手里的铜钥匙"
  },
  {
    "id": "ss_2",
    "index": 2,
    "startMs": 3000,
    "endMs": 7200,
    "shotType": "close_up",
    "angle": "high_angle",
    "movement": "static",
    "subject": "铜钥匙",
    "note": "俯拍特写，手指轻颤"
  }
]
```

校验规则：

1. `index` 从 1 连续递增；`startMs/endMs` 不重叠、覆盖整段；`endMs - startMs` 与段落 `duration_ms` 的偏差 ≤ 1 帧。
2. 子镜头数量建议 1–6；超过 6 个给出警告，不阻断（现状分镜通常 2–4 个）。
3. 子镜头的 `shotType/angle/movement` 只用于 2D 分镜板、3D 关键帧参考和提示词提案，**不直接写 `storyboards` 段级字段**。
4. 3D 首版只支持“段级一条相机路径”；子镜头边界可作为关键帧时间点。若用户需要每个子镜头独立机位，标记为后续能力，不在首版承诺。
5. 文本与结构化字段冲突时（例如原文【镜头2】写特写、结构化写中景），以用户当前编辑的结构化字段为准，并在检查器显示“与原文不一致”提示。

### 4.3 2D 视图

**布局**：左侧镜头列表，中间平面画布 + 分镜板，右侧检查器。

1. **平面画布**
   - SVG 网格，默认 20m × 20m，可缩放/平移。
   - 场景区域：矩形/多边形；墙体、门窗、家具用简单图元；场景参考图只作为缩略图/背景，不做透视地面。
   - 角色：圆形 + 朝向箭头，显示角色名；拖动摆位，吸附网格。
   - 机位：三角形/扇形视锥，显示 FOV、焦距、高度；可拖动、旋转、复制。
   - 道具：图标/矩形，可锁定。
   - 镜头范围：多个机位可同时显示，当前镜头高亮。

2. **分镜板**
   - 横向卡片：镜号、首/尾帧缩略图（若有）、计划时长/对齐时长、段级景别/角度/运动、场景。
   - 卡片内显示**子镜头条**：按 `startMs/endMs` 比例分段，标注“中景·推”“特写·固定”；点击子镜头只切换高亮与检查器，不新建生产镜头。
   - 拖拽排序只改导演顺序，不改分镜号；需要改生产顺序时走“应用到分镜”的显式排序提案（首版不做自动重排）。
   - 拖拽卡片边缘改时长时，子镜头按比例重算；也可在子镜头条上拖动分界点。
   - “从分镜导入”“新增计划镜头”“删除计划镜头”。

3. **检查器**
   - 场景、角色、道具、机位、镜头、子镜头六组。
   - 机位：焦距 18–85mm、高度 0–300cm、景别、角度、运动、转场。
   - 摆位：角色 X/Z、朝向、动作提示；道具位置/旋转。
   - 子镜头：序号、起止、景别、角度、运动、主体、备注；显示“原文【镜头N】”对照。
   - 校验：角色出画、机位穿墙、镜头重叠、子镜头未覆盖整段、时长与分镜不一致，给出黄色提示而不是阻断。

4. **2D 预演**
   - 用 SVG/Canvas 导出“平面调度图”和“分镜板拼图”，作为沟通素材。
   - 不冒充 3D 构图；需要构图参考时切 3D 抽帧。

### 4.4 3D 视图

**技术选型**：`three` + `@types/three`，按需动态 import；不自建渲染器。

**场景构建**：

- 地面：20m × 20m 网格 + 半透明地面。
- 场景：地面色块 + 背景图（场景参考图）+ 简单墙体/门窗；不做复杂建模。
- 角色：代理卡（billboard）或胶囊体，默认身高 170cm，可在检查器调整；贴角色参考图，保证“谁是谁”可辨。
- 道具：代理卡或简单几何体（盒/柱/球），可缩放/旋转。
- 灯光：环境光 + 方向光；可调方向/强度/色温；只用于预演，不承诺与最终生成一致。
- 机位：`PerspectiveCamera`，35mm 等效焦距换算 FOV；支持目标点、机位高度、景别预设。
- 控制：`OrbitControls` 观察，`TransformControls` 移动/旋转；选中对象显示 gizmo。

**镜头与关键帧**：

- **一个分镜段落一条相机路径**；首版不承诺“每个子镜头一套独立机位”。
- 每条路径最多 6 个关键帧，必须包含 0% 与 100%：位置、目标点、FOV；中间关键帧可手动添加，也可在子镜头边界一键插入，用来近似“段内切镜/推近”。
- 插值：线性/缓入缓出；预演按 24fps 采样，最多 720 帧/镜头。
- 镜头运动预设：固定、推、拉、摇、移、跟、升降；预设只生成关键帧，用户可再调。
- 构图辅助：三分线、中心十字、安全框、画幅遮罩（16:9 / 9:16 / 4:3）。
- 角色不做骨骼动画；只用整体位移/朝向/简单上下浮动表达“走位”。这是预演，不是动画。
- 子镜头切换在 3D 里表现为“同一路径上的关键帧跳变/快速过渡”，不产生新场景、不产生新生成任务；需要真正切镜时，用户在分镜文本/提示词提案里表达。

**抽帧**：

- 当前机位渲染 PNG：首帧、中帧、尾帧；可选 3×3 联系表。
- 通过后端上传到项目存储，写 `director_previs_assets`；返回 URL。
- 抽帧尺寸由项目画幅决定，不受窗口大小影响。
- **不自动覆盖** `storyboards.firstFrameImage` / `lastFrameImage`；用户在“应用到分镜”里勾选“作为首帧/尾帧参考”才写入，且保留原图备份字段/版本。

**性能与上限**（硬约束，防止滑向游戏引擎）：

| 项 | 上限 |
| --- | --- |
| 角色 | 6 |
| 道具 | 20 |
| 机位 | 8 |
| 单镜头帧数 | 24–720（24fps） |
| 计划文档 | 5 MiB |
| 3D 资产 | 首版只支持代理卡/简单几何体；GLB 作为后续可选项 |

### 4.5 导演台 → 分镜 → 生产

**应用差异对话框**分三组：

| 组 | 字段 | 默认 |
| --- | --- | --- |
| 镜头参数 | 景别、角度、运动、转场 | 勾选 |
| 时长 | 计划时长 → 对齐后时长 | **不勾选**，勾选后显示帧数与差异 |
| 文本 | 画面描述、台词/备注 | 不勾选 |
| 子镜头 | 子镜头结构转成镜头语言文本 | 不勾选；只生成提案，不写结构化子镜头 |
| 生成参考 | 视频提示词追加镜头语言、首帧/尾帧参考 | 不勾选 |

对话框展示：字段名、旧值、新值、影响范围（哪些分镜）、冲突提示、对齐后时长、生成结果将失效的提示。确认后调用 `POST /episodes/:id/director/apply`，返回每个分镜的更新结果。

**生产衔接**：

- “去生产”只做路由跳转并高亮对应分镜，不自动触发生成。
- 生产面板仍读 `storyboards`，因此导演台的应用结果立即生效，但不需要改生产面板代码。
- H3 整集时间线不变；如果用户勾选“追加镜头语言”，只改 `video_prompt` 文本，仍由现有 `compileH3Prompt` 处理。
- 只改 `shot_type/angle/movement` 时，H3 的 `timeline_data` 文本不变；这些字段主要用于分镜卡、导演台和后续提示词提案，不会被自动拼进 H3 提示词。
- 改时长会改变该 segment 的帧数、总帧数与后续所有 segment 的起点；应用后必须提示“整集时间线将变化、已有合片/剪辑对齐可能失效”，并把相关分镜标记为需重新生成。
- 应用不触发生成；用户回生产面板后，现有逐镜或整集链路会读到新字段。

**为什么不让导演台直接生成视频**：

- 生成是花钱、耗时、可失败的操作，应该留在现有生产面板的任务体系里。
- 导演台的职责是“确认构图和节奏”，不是“执行生成”。
- 保持一个生成入口，避免任务、重试、计费、下载、审核分叉。

### 4.7 错误处理与恢复

| 场景 | 处理 |
| --- | --- |
| 保存冲突（409） | 顶部横幅：重新载入 / 覆盖 / 另存为新版本；不静默覆盖 |
| 3D WebGL 不可用 | 自动降级到 2D，提示“当前设备不支持 3D 预演” |
| 抽帧失败 | 保留计划数据，给出重试；不写半成品资产 |
| 应用分镜部分失败 | 返回逐条结果；已成功条目保留，失败条目可重试；不整体回滚已确认写入（或提供“撤销本次应用”版本） |
| 分镜已被删除 | 应用时跳过并提示；计划镜头转为 `detached`，不自动重建 |
| 子镜头时长不覆盖整段 | 阻止保存并高亮缺口/重叠；提供“按比例铺满”一键修复 |
| 时长对齐后变化 | 差异对话框显示计划/对齐值；确认后标记需重生成；取消则保留原时长 |
| 分镜关联角色/道具已变 | 导入时角色/道具集合以当前分镜为准；导演台里的旧摆位保留但标“已失效”，应用不写角色关联 |
| 只读/锁定 | 复用 `episode_locks`；只读时隐藏保存/应用按钮，保留导出平面图 |

### 4.8 3D 保真度决策

本方案明确选择**代理预演**，而不是“真三维角色 + 骨骼动画”：

- 本项目角色资产是生成图，不是带骨骼的 GLB；要真 3D 角色，需要建模、绑定、动作库，成本和周期都超出“导演台”的范围。
- 参考项目的 3D 导演台也限定 6 角色/20 道具/8 机位、固定 24fps、离屏抽帧，不是游戏引擎；这是被验证过的可控边界。
- 代理预演已经能回答用户最关键的问题：**人在画面哪里、机位多高、焦段多少、构图是否穿帮、镜头怎么运动**。
- 首版同时交付 2D 与 3D 代理预演，共用同一份镜头表；3D 不新增第二套数据。
- 如果后续确实需要真 3D 角色，作为独立阶段评估 GLB 上传/骨骼/动作，不纳入本方案首版。

## 5. 剪辑与音频工作台方案

### 5.1 与成片中心的关系

剪辑的“源选择”依赖一个尚未实施的设计：

- 《2026-11-06-film-hub-mix-edit-redesign.md》已定义：`video_merges` 是唯一成片目录，`episode_exports` 是渲染任务账本，`episodes.current_film_id` 是当前成片指针，`edit_projects.source_merge_id` 绑定源成片，混音/剪辑共用 `FilmPicker`。
- 本方案不重复设计成片中心；**以该文档为唯一实施蓝本**。本方案只定义导演台、Agent、UI 与它的接口。

**但剪辑能力增强不等成片中心。** 渲染/导出闭环与基础易用性属于 P3a-1（E0–E4）；波形、多选、交叉淡化、J/L 切、帧级操作等属于 P3a-2（K1–K4）。两者都在现有剪辑工程内完成；成片中心只影响“从哪里选源、导出回到哪里”，属于 P3b。

### 5.2 剪辑的集成点

| 集成点 | 方案 |

| 源选择 | 剪辑页左侧主列表改为成片列表（`FilmPicker`），不再默认铺分镜 |
| 工程单位 | 一个剪辑工程绑定一部源成片（`source_merge_id`）；换源 = 新建工程，不覆盖旧工程 |
| 导演标记 | 时间线只读显示导演台镜头标记（镜号、景别、时长、机位备注、子镜头边界）；不改变剪辑片段 |
| 对齐 | 若源成片由当前分镜生成，提供“按导演台镜头对齐”提示；只做标记，不自动切割 |
| 导出 | 服务端渲染；成功新增一条 `kind='edit'` 成片；不覆盖旧成片；“设为当前成片”才改变指针 |

### 5.3 不在本方案重复建设

- 不把混音/剪辑的导出逻辑复制到导演台。
- 不强行把 `episode_audio_clips` 与 `edit_plan.clips` 合并成一张表；两套文档各自演进，共用交互内核。

### 5.5 共用编辑内核：一套交互，两套文档（P3a-2）

5.5–5.7 全部属于 P3a-2（K1–K4）；P3a-1 的渲染/导出闭环见剪辑方案 E0–E2。

不做“大一统时间线表”，而是抽出一层前端交互内核，让音频工作台和剪辑工作台共享行为，不共享存储。

### 5.6 音频工作台增强（P3a-2）

“能力重要度”只表示对剪辑/混音闭环的影响，不表示实施顺序；实施顺序见 0.5。

| 能力重要度 | 能力 | 具体做法 | 验收 |
| --- | --- | --- | --- |
| 高 | 多选与范围 | Cmd/Shift 点选、空白拖框、标尺拖范围；批量移动/删除/淡变 | 选中 3 个片段，批量 -3dB 与删除可撤销 |
| 高 | 右键菜单 | 分割、复制、删除、淡入到播放头、淡出到播放头、循环、锁定、定位、复制/粘贴 | 不依赖快捷键也能完成全部常用操作 |
| 高 | 交叉淡化 | 同轨相邻片段重叠或点“交叉淡化 20/50/100ms”；曲线可选线性/S 曲线 | 两段环境声交叉后无爆音，导出可复现 |
| 高 | 波形与增益联动 | 波形按增益缩放；片段头显示 dB；静音/锁定态有明确标识 | 改增益后波形与听感一致 |
| 中 | 音量/声像包络 | 片段内关键帧；拖动加点、右键删点；播放时实时生效 | 包络写入版本，恢复后一致 |
| 中 | 批量淡变 | 选中多个片段统一设置淡入/淡出/曲线 | 一次操作、一次撤销 |
| 中 | 吸附扩展 | 吸附播放头、片段边缘、字幕 cue、标记、区间边界 | 拖动时显示吸附线 |
| 低 | 轨道编组/折叠 | 对白/音效/音乐分组折叠；组级 M/S | 大工程轨道可收起 |

**保持不动**：实时多轨监听、总线/闪避参数、LUFS/真峰值、声音生成、分离、区间预览。这些是音频工作台的优势，不在本次重做。

### 5.7 剪辑工作台增强（P3a-2）

“能力重要度”只表示对剪辑闭环的影响，不表示实施顺序；实施顺序见 0.5。

字幕检查器（文本、时间、样式、应用到全部）与基础标记随 P3a-1 E4 交付；本表只列 P3a-2 增量。

| 能力重要度 | 能力 | 具体做法 | 验收 |
| --- | --- | --- | --- |
| 高 | 音频轨可编辑 | 解析成片原声/外部音频，画波形；音频片段检查器复用 `MixClipInspector` 的字段子集 | 在剪辑里改增益/淡变，预览与导出一致 |
| 高 | 多选/框选 | 视频片段多选、音频片段多选、字幕 cue 多选；批量移动/删除/复制 | 多选后一次删除可撤销 |
| 高 | 右键菜单 | 分割、复制、删除（波纹/保留间隙）、速度、淡变、分离音频、定位、复制/粘贴 | 全部常用操作有可见按钮 + 右键 |
| 高 | 波纹语义统一 | `Delete` = 波纹删除；`Shift+Delete` = 保留间隙；菜单写明 | 删除后后续片段/字幕/音频同步移动 |
| 高 | 帧级操作 | 时间码 `HH:MM:SS:FF`；`←/→` 1 帧、`Shift+←/→` 10 帧；吸附到帧 | 分割点与导出帧一致 |
| 中 | J/L 切 | 从视频片段分离音频为独立片段；音频可前后偏移 ±帧；显示链接图标 | 分离后视频/音频可独立修剪，重新链接可恢复 |
| 中 | 交叉淡化 | 音频片段重叠自动交叉淡化；视频转场保持现有 4 种 | 声画同步、无爆音 |
| 中 | 叠加只读 | 暴露 `overlays`，只读显示与显隐；不新增叠加编辑 | 叠加不破坏导出 |
| 中 | 标记增强 | 在 E4 基础标记上补吸附、区间与锁定标记 | 标记可随片段移动，不破坏导出 |
| 低 | 音量自动化 | 与音频工作台共用包络组件 | 长对白段落可自动闪避 |
| 低 | 速度曲线 | 变速片段支持缓入缓出 | 仅视频，音频不变调 |

**暂不做**：多视频轨自由叠加、抠像、跟踪、调色台、4K/60fps、云端协作。这些会把“短剧剪辑”拖成通用 NLE。

### 5.8 统一交互规则

1. **可见按钮优先**：分割、删除、复制、淡变、缩放、吸附、撤销/重做必须在工具栏有按钮；右键只是加速，不是唯一入口（现有剪辑快捷键弹窗只是一个入口，不足以让新用户发现）。
2. **一次拖拽 = 一个历史项**：拖动中实时预览，松手才提交；连续微调在 500ms 内合并。
3. **选择有明确视觉**：选中描边 + 手柄 + 检查器标题；多选显示“已选 N 项”。
4. **危险操作可恢复**：删除走撤销，不做二次弹窗；删除工程/版本才二次确认。
5. **状态条统一**：保存中/已保存/未保存/冲突/只读 + 当前时间码 + 选中数量。
6. **时间语义统一**：音频用毫秒，视频用帧；UI 同时显示时间码与毫秒，避免“0.04 秒去哪了”。
7. **键盘统一**：Space 播放、J/K/L 倒放/暂停/播放、`←/→` 步进、`S` 分割、`Delete` 波纹删除、`Shift+Delete` 保留间隙、`Cmd/Ctrl+D` 复制、`Cmd/Ctrl+Z` 撤销。
8. **空状态统一**：说明“为什么空”+ 一个主按钮；没有源成片时引导去成片中心，不显示不可用按钮。

### 5.9 实施切片

共用编辑内核与音频增强属于 P3a 的第二波（P3a-2），在剪辑导出闭环（P3a-1，见独立剪辑方案 E0–E4）通过后实施。下表用 K 编号，避免与剪辑方案的 E 编号冲突。

| --- | --- | --- |
| K1 | 共用 selection/gestures/history/commands + Toolbar/TrackHeader/TransportBar/ContextMenu；`StudioStatusBar` 由 UI U1 可选提供 | 无；可先只接剪辑 |
| K2 | 剪辑音频轨、波形、音频片段检查器、多选、右键、波纹语义、帧级时间码 | K1 |
| K3 | 音频工作台多选、范围、右键、交叉淡化、批量淡变 | K1 |

## 6. Agent 方案

### 6.1 现状：AI 是怎么被调度和执行的

现有“AI 服务”不是一套 Agent 系统，而是四层彼此独立的机制。把它们混在一起谈，就会得出“已经有 Agent”或“全部推倒重来”两种错误结论。

#### 6.1.1 四层结构

| 层 | 职责 | 入口 | 状态与并发 | 代码证据 |
| --- | --- | --- | --- | --- |
| 配置层 | 按 `text/image/video/audio/audio-gen` 解析当前启用的官方模型配置 | `getActiveConfig(serviceType)` | 无状态；按 `priority` 降序取第一条启用配置 | `backend/src/services/ai.ts:9`、`:42-53`、`:81-101`、`:136-145` |
| 媒体任务层 | 图片/视频生成：建 `sys_task`、提交适配器、轮询、下载、回写资源 | `POST /tasks` → `createTask` → `runBackground(processTask)` | 进程内 `activeTasks` + `videoSubmissions` 去重；无全局并发上限；进程重启靠 `sys_task` 恢复 | `backend/src/services/generation.ts:27-32`、`:155-157`、`:251-281`、`:294`、`:470-550`、`:796-827` |
| 确定性管道层 | 整集自动化：重写→提取→音色→资产图→分镜→视频提示词→视频→配音 | `startAutomation` → `pipeline_jobs` → 队列 worker | 持久任务 `pipeline_jobs`；worker 每 2 秒领 1 条，只处理 `automation` 和 `dub`；8 阶段严格串行 | `backend/src/services/automation.ts:670-740`、`backend/src/services/queue-worker.ts:26-58`、`:85`、`backend/src/services/job-queue.ts:38-170` |
| Agent 层 | 5 个创作专员：剧本重写、资产提取、分镜拆分、提示词生成、音色设计 | `POST /agent/:type/chat` | 单次 HTTP 同步调用；`maxSteps: 20`；无会话、无运行记录；工具直接写库 | `backend/src/agents/index.ts:403-416`、`backend/src/routes/agent.ts:39-71`、`backend/src/agents/context.ts:9-25` |

#### 6.1.2 媒体任务层：为“单次生成”设计，不是 Agent 运行时

- 轮询参数写死：图片 120 次 × 5 秒（10 分钟上限），视频 300 次 × 10 秒（无总时长上限）（`generation.ts:38-40`）。
- 视频额外有 transferring 阶段的恢复轮询（`generation.ts:475`），失败可恢复，这是任务级韧性，不是推理级韧性。
- 自动化等待单任务的上限是图片 15 分钟、视频 90 分钟（`automation.ts:58-59`）。
- 进程内集合只防“同一个任务被重复执行”，不负责排队、配额、优先级；服务重启后由 `sys_task` 状态恢复（`generation.ts:796-827`）。
- 结论：这一层是可靠的“生成执行器”，但没有“谁在什么上下文下、为什么发起、允不允许”的概念。

#### 6.1.3 自动化管道：确定性编排，不是 Agent 规划

- 8 个阶段固定顺序执行，每阶段自己判断“已有则跳过”（`automation.ts:731-739`）。
- 资产图按角色→场景→道具串行生成（`automation.ts:425-444`）；视频按分镜编号串行生成，并复用最近一次任务避免重复计费（`automation.ts:584-622`）。
- 阶段进度、停止、中断都靠剧集上的 automation 状态与 `assertRunning`，没有“计划—观察—修正”的循环。
- 结论：这是本项目的核心资产，**不应被 Agent 替换**。Agent 应调用它、解释它、在失败处提出建议，而不是重新实现它。

#### 6.1.4 Agent 层：5 个“带工具的提示词函数”

- 5 个专员在启动时静态注册，模型、指令、工具、技能工作区在注册时确定（`agents/index.ts:403-416`）。
- 每次请求都要求 `drama_id + episode_id`，请求上下文只注入 `episodeId`、`dramaId`、模型、配置、语言（`routes/agent.ts:39-51`、`context.ts:17-25`）。
- 没有 session/memory、没有流式、没有取消、没有运行记录；前端只有“运行中”忙碌锁（`frontend/app/composables/useAgent.ts:6-16`）。
- 工具在 `execute` 内直接写表：`saveScript`（`backend/src/agents/tools/script-tools.ts:61`）、`saveStoryboards`（`storyboard-tools.ts:261`）、角色/场景/道具去重写入（`extract-tools.ts:172-420`）、最终提示词写入（`image-prompt-tools.ts:48-180`）。
- 结论：它们擅长“用户点一下，把这一集的一步做完”，不擅长“跨步骤、跨模块、可追溯地协助创作”。

#### 6.1.5 五个关键结论

1. 本项目已有**可靠的执行系统**，缺的是**会话式监督层**。
2. 现有 Agent 的写入是“任务内直写”，风险边界清楚（用户主动点击、范围限于当前集），不能简单改成“聊天里随便写”。
3. 媒体任务不在 `pipeline_jobs` 里，Agent 若要观察生成进度，必须读 `sys_task` 与剧集 automation 状态，而不是自己轮询。
4. 现有 Agent 没有作用域模型，只有“必须某一集”；小说级、成片级、跨集问题无法表达。
5. 现有系统没有“提案”概念，因此也没有“确认后应用”“差异预览”“审批审计”的位置。

### 6.2 与幻界 Agent 的差异

幻界的 Agent 是“常驻创作环境里的主控 + 子代理”，本项目是“生产流水线上的专员 + 确定性管道”。两者不是同一类产品，差异要按维度看。

| 维度 | 本项目现状 | 幻界（Reveric） | 判断 |
| --- | --- | --- | --- |
| 定位 | 单步任务执行器 | 常驻创作主控 | 学“常驻”，不学“万能” |
| 入口 | 各模块按钮触发 | 统一聊天入口 + 全局上下文 | 学统一入口 |
| 会话 | 无，单次请求即结束 | 持久会话、子会话、交接 | 学会话与交接 |
| 作用域 | 必须 `drama + episode` | 当前活动资源 + 工作区引用 | 学显式作用域 |
| 运行模型 | HTTP 同步，`maxSteps: 20` | 长运行，可取消/引导/追加 | 学分步运行与取消 |
| 流式 | 非流式，等最终文本 | 文本/思考/工具事件流 | 学流式与工具时间线 |
| 上下文 | 集 ID + 指令 + 技能 | 历史 + 规则 + 技能 + 资源引用 + 压缩 + 交接 | 学压缩与按需检索 |
| 工具面 | 5 组领域工具，直接读写 | Host 工具 + `Run` 命名空间 + Codemode + 技能 + MCP | 只学“领域工具命名空间” |
| 写入模型 | 工具内直接写表 | 权限门禁 + 审批 + 参数冻结 | 学提案/审批，不学全量文件写 |
| 权限 | 依赖接口鉴权，无 Agent 级权限 | 5 动作 × 4 作用域 × allow/ask/deny | 学“动作×作用域×决策” |
| 子代理 | 无 | 主控委派、子会话、工具白名单 | 后期学，先不做 |
| 多代理编排 | 无 | 顺序/动态选人、共享实例、统一取消 | 暂不学，短剧生产用不上 |
| 失败收敛 | 依赖 Mastra 默认与阶段重试 | 流重试、失控收敛、截断续写、半工具调用丢弃 | 学收敛与截断续写 |
| 断点恢复 | 媒体任务可恢复，Agent 不可 | 消息与工具结果持久化，可续跑 | 学消息记录 |
| 可观测 | 业务日志 + `sys_task` | 每次运行的事件、用量、上下文占用 | 学运行事件 |
| 技能 | Mastra 技能工作区（已有） | Agent Skill（name + prompt + references） | 已具备，补加载与权限 |
| 评估 | 无 | 完成前自检 Hook | 后期学 |
| 适用场景 | 确定性生产 | 开放式创作与编辑 | 各取所长 |

**差距的本质**：不是模型能力，而是**运行时**。幻界把“一次模型调用”升级成“有身份、有作用域、有工具、有审批、有记录、可取消的运行”；本项目还停留在“一次请求调用一个带工具的提示词”。

**该学的三件事**：会话与作用域、流式与消息记录、提案与审批。

**不该学的三件事**：Host 文件/SQL 工具、Codemode 任意脚本、无边界 MCP。这些能力对一个需要稳定产出短剧的系统，风险远大于收益。

### 6.3 Agent 应该用在哪里

判断标准只有一条：**需要理解上下文、跨步骤判断、用自然语言解释的事，交给 Agent；需要确定性、批量、毫秒级精确的事，留给代码。**

> 下表是产品级能力方向；“工具”列是首版实际可用的数据域，写入能力以 §6.6.2 与《智能体落地方案》§7 为准。章节改写、剪辑命令、混音增益等写提案不在 B0–B4 首批，首版做到只读诊断与三类提案。

| 场景 | 用户问题 | Agent 能做什么 | 工具 | 产出 | 适用度 |
| --- | --- | --- | --- | --- | --- |
| 小说续写 | “这一章怎么接”“帮我把这段改得更狠” | 读大纲/前文/角色，生成改写建议 | `read_novel_*` | 改写建议（首版只读，章节提案后续） | 高 |
| 小说巡检 | “伏笔埋了没回收”“人物有没有崩” | 跨章扫描，列证据与位置 | `read_novel_*`、图谱审计 | 问题清单（首版基于现有图谱/章节） | 高 |
| 剧本诊断 | “改编丢了什么”“节奏是不是太拖” | 对比小说与剧本，标信息缺失/场次冗余 | `read_novel_*`、`read_script` | 诊断报告 | 高 |
| 资产一致性 | “这个角色三张图不像一个人” | 比对描述、提示词、参考图，指出冲突字段 | `read_assets`、`read_asset_detail` | `asset.prompt.update` 提案 | 中 |
| 分镜连续性 | “轴线跳了”“景别全是中景” | 读分镜表，检查轴线、景别节奏、时长分布 | `read_storyboards`、`read_storyboard_detail` | `storyboard.update` 提案 | 中 |
| 导演台 | “这场怎么摆机位” | 读计划/分镜/资产，给摆位与机位建议 | `read_director_plan`（B3，导演台只读 API 就绪后） | 摆位/机位建议（首版不改导演计划） | 中 |
| 剪辑 | “帮我粗剪一版”“字幕错字太多” | 读剪辑状态与字幕，提出删减/顺序/文案建议 | `read_edit_state`、`read_edit_clips` | 剪辑建议（首版只读，命令提案后续） | 中 |
| 音频 | “对白被音乐盖住了” | 读轨道、增益、LUFS，定位问题片段 | `read_mix_state`、`read_mix_tracks` | 增益/闪避建议（首版只读，命令提案后续） | 低 |
| 失败诊断 | “第 7 镜为什么一直失败” | 读任务状态与错误码，解释原因与下一步 | 现有错误字段（任务/队列只读工具后续） | 诊断说明 + 重试建议 | 高 |
| 成片质检 | “这版能交吗” | 读成片元数据、字幕、时长、响度，对照清单 | `read_delivery_status`、`read_export_history` | 质检清单 | 低 |

**不交给 Agent 的事**：

- 批量生成、重试、轮询、下载、转码、拼接、渲染：确定性代码更快、更便宜、更可测。
- 模型/供应商/密钥配置：只允许管理员在设置页操作。
- 定时任务与自动巡检：用 cron/队列，不用模型“想起来”。
- 毫秒级编辑命令：时间线操作必须本地即时执行，Agent 最多生成提案。
- 删除成片、覆盖版本、改分镜生产合同：必须人工在 UI 完成。
- 任何需要“保证一定发生”的生产步骤：Agent 可以建议，不能成为唯一执行路径。

### 6.4 目标形态

**5 个流水线专员 + 1 个导演专员 + 1 个全局创作助手。**

| 类型 | 角色 | 工具范围 | 写入 |
| --- | --- | --- | --- |
| `script_rewriter` | 小说→剧本 | 读剧集原文、保存剧本 | 现有，任务内写入 |
| `extractor` | 提取角色/场景/道具 | 读剧本、读写资产 | 现有，任务内写入 |
| `storyboard_breaker` | 剧本→分镜 | 读上下文、保存分镜 | 现有，任务内写入 |
| `prompt_generator` | 图片/视频提示词 | 读资产、保存最终提示词 | 现有，任务内写入 |
| `voice_designer` | 音色设计 | 读角色、保存音色档案 | 现有，任务内写入 |
| `director`（新增） | 导演计划建议 | 读分镜/导演计划/资产；生成摆位、机位、镜头建议 | 只提案，不直接写 |
| `assistant`（新增） | 跨模块助手 | 读小说/剧本/分镜/导演/成片/剪辑；只建议触发专员，不直接调用；生成动作提案 | 只提案，确认后由 UI 应用 |

现有 5 个专员保持“任务内直写”，因为它们是用户主动点击、范围限于当前集的生产操作；新增的 `director` 与 `assistant` 走“只读 + 提案”，风险边界不同，不能混用同一套写入策略。

### 6.5 五层升级路线

> 本表是能力路线示意；具体接口、表结构与阶段以《智能体落地方案》B0–B4 为准（`/assistant/*`、`agent_sessions` / `agent_messages` / `agent_proposals` 三张表，不新增 `agent_runs` / `agent_steps`，首版不做自动路由）。

增量升级，不推倒现有管道。每层都可独立上线、独立回滚。

| 层 | 目标 | 新增 | 依赖 | 验收 |
| --- | --- | --- | --- | --- |
| L0（现状） | 任务型专员 + 确定性管道 | 无 | 无 | 现有功能不回退 |
| L1 会话与作用域 | 让 Agent 知道“在哪个作品/哪一集/哪个模块”工作 | `AgentScope`、`agent_sessions`、`/assistant/*` SSE、`AgentDock` | 无 | 小说页可连续追问 3 轮，上下文不丢 |
| L2 消息状态与取消 | 每次回答可观察、可停止、可恢复 | `agent_messages` 状态、取消、超时、断线续传、重启中断标记 | L1 | 运行中可停止；刷新后能看到历史消息与工具摘要 |
| L3 只读工具与提案 | Agent 能查全链路，但不能偷偷改 | 领域只读工具、`propose_change` / `suggest_action`、`agent_proposals`、应用接口、审计 | L2 | 提案卡片显示差异；应用带版本冲突检查；拒绝后不落库 |
| L4 编排与子代理 | 跨模块问题自动路由；复杂任务拆分 | `orchestrator`、只读子代理、交接、并发/预算上限 | L3 | “这集为什么慢”能自动查任务、分镜、资产并汇总 |
| L5 上下文与评估 | 长会话不崩；质量可度量 | 上下文压缩、截断续写、完成前自检、黄金用例与回放 | L4 | 20 轮会话不超窗；黄金用例通过率可统计 |

**上线顺序建议**：L1→L2→L3 是主线，必须先做；L4 只在 L3 稳定后做；L5 最后做。这是 Agent 能力依赖顺序，不是跨工作包的业务优先级。任何一层未通过验收，不进入下一层。

### 6.6 作用域与领域工具

#### 6.6.1 作用域模型

把“必须 episode”改为“显式作用域”，同时兼容旧请求：

```ts
type AgentScope =
  | { kind: 'home' | 'novel-library' }
  | { kind: 'novel'; novel_id: number }
  | { kind: 'drama'; drama_id: number }
  | { kind: 'episode'; drama_id: number; episode_id: number; stage: 'script' | 'assets' | 'videos' | 'dubbing'; focus?: Record<string, string | number> }
  | { kind: 'director' | 'mix' | 'delivery'; drama_id: number; episode_id: number; focus?: Record<string, string | number> }
  | { kind: 'edit'; drama_id: number; episode_id: number; edit_project_id?: number; focus?: Record<string, string | number> }
```

- 生产路由 `/agent/:type/chat` 保持不变；助手链路在 `POST /assistant/sessions/:id/messages` 中携带 `scope`，服务端按 `scope` 解析 `drama_id` / `episode_id`。
- 生产 `buildAgentRequestContext()` 保持 `dramaId` / `episodeId` 必填；新增 `buildAssistantRequestContext()`，只在 `scope` 带对应 ID 时写入，不伪造 0 或 -1。
- 工具只读/提案工具必须校验资源归属（episode 属于 drama、plan 属于 episode、novel 属于当前项目），不做“只靠前端传 id”的信任。
- 作用域同时决定可见工具：小说作用域不暴露导演/剪辑工具，剪辑作用域不暴露资产写入工具。

### 6.7 流式、会话与消息状态

#### 6.7.1 流式接口

- 新增 `GET /assistant/sessions/:id/stream`（SSE）：`start`、`scope`、`delta`、`reset`、`tool`、`proposal`、`suggestion`、`done`、`error` 九类事件，另有 15 秒 `: ping` 心跳；断线重连带 `after_seq` 续传。
- 前端 `useAgentDock` 统一处理；生产 Agent 的 `/agent/:type/chat` 非流式接口保持不变；助手在 `agent.stream.enabled=false` 时走非流式回退。
- 同一会话同一时间只允许一条 `running` 助手消息；`agent.maxSteps` 默认 8、`agent.timeoutSec` 默认 120；取消走 `POST /assistant/sessions/:id/cancel`，超限或重复发送给出明确提示，不无限重试。
- 统一 `AgentDock`：
  - 入口：业务页右下角悬浮按钮；工作室全屏页用顶栏“助手”；设置页不显示入口；不新增第二个聊天页面。
  - 上下文条：显示线程、预设与“当前：第 3 集 · 分镜”作用域。
  - 消息区：安全 Markdown + 工具摘要 + 提案卡 / 建议卡。
  - 提案卡：展示字段差异、理由、冲突状态，按钮“应用 / 拒绝 / 查看原文”。
  - 停止按钮、断线恢复、错误提示；工具调用默认折叠。

#### 6.7.2 持久化模型

```text
agent_sessions   一次连续对话：workspace_key、preset、status、标题、last_message_at
agent_messages   一条用户/助手消息：scope_json、preset、status、tool_calls_json、tool_results_json、suggestions_json
agent_proposals  提案：session_id、message_id、kind、target_type、target_id、before_json、after_json、target_hash、status
```

- `agent_messages.status`：`running / completed / failed / cancelled / interrupted`。
- 工具调用与结果存在消息的 `tool_calls_json` / `tool_results_json` 中，不单独建事件表；只存截断并脱敏后的摘要，大文本按 ID 按需读取。
- 取消：`POST /assistant/sessions/:id/cancel` 中止后台任务并写入已生成文本，提案置 `expired`。
- 恢复：服务重启后，残留 `running` 消息标记为 `interrupted`，该消息已创建的提案置 `expired`、建议清空；不自动重放。
- 保留期：会话消息默认保留 30 天后清理正文、工具结果与建议 JSON；提案与应用记录作为审计长期保留。

#### 6.7.3 长会话策略

- 上下文使用超过模型窗口 80% 时压缩：保留系统指令、最近 6 轮、未完成提案、当前作用域摘要；更早内容转为可检索摘要。
- 正文被截断时自动续写，最多 2 次；连续 3 轮只思考不产出则终止并提示。
- 交接：从“小说”切到“导演台”时，不复制整段历史，只传作用域引用与当前任务摘要。

### 6.8 写入安全、权限与审计

#### 6.8.1 提案 → 确认 → 应用

Agent 不直接写业务数据库，采用两段式：

1. **提案**：Agent 调用 `propose_change`（助手另有 `suggest_action`），只写 `agent_proposals` 或消息的 `suggestions_json`，不碰业务表。
2. **确认**：前端提案卡展示字段差异；用户点击“应用”调用 `POST /assistant/proposals/:id/apply`；建议卡只打开现有页面流程，由用户自己点击生产按钮。
3. **应用**：服务端在同一事务内重新读取目标、校验 `target_hash` 与字段白名单，再写回；`storyboard.update` / `line.update` 复用现有共享映射，不调用旧的领域写接口，避免映射漂移。
4. **审计**：记录 `proposed_by=agent`、`applied_by=local-user`、`before_json` / `after_json`、`target_hash`、`applied_at`；不记录密钥/完整提示词正文（按现有日志脱敏规则）。

提案在生成时冻结参数（深拷贝为不可变对象）；应用前在同一事务内重新读取目标并重新计算 `target_hash`，不一致则标记 `conflict` 并返回 409，要求用户重新生成或手动合并。

#### 6.8.2 权限模型

本项目是本地单用户，权限不是账号/角色系统，而是代码内的固定边界，不做用户级规则配置：

| 动作 | 说明 | 决策 |
| --- | --- | --- |
| `agent.read` | 读取当前作用域内数据 | 允许（限当前作用域） |
| `agent.propose` | 生成提案 | 允许（按作用域与提案类型白名单） |
| `agent.apply` | 应用提案 | 必须用户点击；服务端校验 `target_hash` |
| `generation.*` | 触发付费生成 | 拒绝（首版不注册生成工具） |
| `files.remove` | 删除文件/成片 | 拒绝 |

- 作用域从窄到宽：`session → 当前资源（episode/director/mix/delivery/edit/novel）→ drama/项目 → global`；工具注册与数据查询都按作用域实际解析，不信任前端传值。
- 拒绝语义固定：Agent 不得换工具绕过，必须告知“未执行”并给出下一步建议。
- 设置页只提供能力开关与白名单（总开关、提案/建议、提案类型、建议动作），不提供按用户/角色的权限配置，也不能放宽到写工具。

#### 6.8.3 审计

- 每次提案应用写提案审计：`proposed_by` / `applied_by` / `before_json` / `after_json` / `target_hash` / `applied_at`。
- 审计记录在设置页“会话与审计”可查；失败、冲突、拒绝同样记录原因，便于区分“模型没做”与“目标已变化”。
- 审计不记录密钥、完整提示词正文或服务器路径。

### 6.9 Agent 不做什么

- 不直接执行 SQL、不直接读写文件系统、不直接调用任意 HTTP。
- 不修改模型/供应商/密钥配置。
- 不删除成片、不删除工程、不覆盖旧版本。
- 不在用户未确认时写分镜、写小说正文、写剪辑时间线。
- 不自动重试付费生成；重试必须由用户确认或由确定性管道按既定策略执行。
- 不替代 `automation.ts` 的 8 阶段管道，不重新实现媒体轮询与拼接。
- 不把完整提示词、密钥、内部路径放进日志或前端错误信息。
- 不开放 Host 文件工具、Codemode、任意 MCP；领域工具之外的能力一律不进入工具面。

#### 7.3.3 视觉脊柱

**“浅色生产工具 + 深色媒体舞台 + 火焰橙单一强调色 + 克制动效。”**

- 生产区（表单、列表、检查器）浅色、紧凑、信息密度高。
- 媒体区（视频、3D、波形预览）深底，让画面与波形成为焦点。
- 强调色只用于主操作、选中、播放头、焦点环；状态色只用于状态，不做装饰。
- 动效只解释状态变化，不做入场表演。

这条脊柱与 `studio.css` 现有令牌一致，不需要换主题；需要的是**把令牌用一致**。

### 7.4 视觉系统

#### 7.4.1 颜色

复用 `frontend/app/assets/studio.css:4-140`，不新增第二套色板。补充语义映射：

| 语义 | 令牌 | 用途 |

返回逐条结果：

```json
{
  "applied": 1,
  "skipped": 0,
  "conflicts": [],
  "items": [

      "shotId": 101,
      "storyboardId": 55,
      "status": "ok",
      "changedFields": ["shotType", "movement", "duration"],
      "durationApplied": { "frames": 294, "seconds": 12.25, "staleVideo": true },
      "subshotsApplied": 2,
      "warnings": ["时长变化会使该分镜既有视频结果过期"]
    }
  ]
}
```

#### 8.2.1 应用规则

- `duration.mode` 默认 `keep`；只有显式 `apply` 才改时长。服务端按 `17n+5` 帧网格向上对齐，返回实际帧数/秒数，并把该分镜标记 `videoStale`。
- `subshots` 只以【镜头N】文本段落写入 `description` 的段内描述；`videoPrompt` 的镜头语言只通过 `appendCameraLanguage` 单独追加。写入前检查**分镜现有文本**是否已有冲突的子镜头结构（与导演计划内部“结构化字段优先”的规则不同），冲突则返回 `409` 与差异，由用户选择“覆盖 / 合并 / 取消”，不静默覆盖。
- 子镜头不创建独立分镜、不创建独立 `sys_task`、不改变 H3 的“一段一分镜”映射；相机语言只写在段级，子镜头共享一条相机路径。
- `usePrevisAsFirstFrame` 默认 `false`；为 `true` 时才把预演帧写成该分镜的首帧参考，且不覆盖已有首帧，需显式确认。
- 应用成功后才递增 `planRevision`；冲突条目不写任何字段，返回可逐条重试的结果。

### 8.3 Agent API 与数据

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/assistant/sessions/resolve` | 按 `workspace_key` 取活动线程；没有则创建 |
| `POST` | `/assistant/sessions` | 新建线程（旧活动线程先取消并归档） |
| `GET` | `/assistant/sessions/:id` | 读取线程与消息分页 |
| `POST` | `/assistant/sessions/:id/messages` | 发送消息，返回 `stream_url` |
| `GET` | `/assistant/sessions/:id/stream` | SSE 流式；`after_seq` 断线续传 |
| `POST` | `/assistant/sessions/:id/cancel` | 取消当前回答；工具调用前检查取消标记 |
| `POST` | `/assistant/proposals/:id/apply` | 应用提案；带 `target_hash` 冲突检查 |
| `POST` | `/assistant/proposals/:id/reject` | 拒绝提案；记录原因，不写业务表 |

> 本表只列主路径；会话列表、归档、软删除、提案读取与诊断试跑等完整接口以《智能体落地方案》§5.2 为准。

新增表（只新增，不改现有表）：

```text
agent_sessions    id, workspace_key, preset, status, title, last_message_at, created_at, updated_at, deleted_at
agent_messages    id, session_id, role, content, status, scope_json, preset, tool_calls_json, tool_results_json, suggestions_json, model, text_config_id, error, created_at, finished_at
agent_proposals   id, session_id, message_id, kind, target_type, target_id, drama_id, episode_id, before_json, after_json, target_hash, rationale, status, proposed_by, applied_by, applied_at, error, created_at, updated_at
```

- `agent_messages.tool_calls_json` / `tool_results_json` 只存摘要与引用（表名 + 主键 + 哈希），不存完整章节/剧本/提示词。
- `agent_proposals.status`：`proposed / applied / rejected / conflict / expired`。
- 提案应用必须走 `target_hash` + 同一事务写回，不绕过冲突检查。

### 8.4 剪辑/音频 API 边界

现有接口保持不变，能力增强只改前端交互与计划内容：

| 能力 | 现有接口 | 本方案改动 |
| --- | --- | --- |
| 剪辑读取/草稿 | `GET /episodes/:id/edit`、`PUT /episodes/:id/edit/draft` | 无 |
| 剪辑版本 | `GET/POST /episodes/:id/edit/revisions`、`POST .../restore` | 无；状态条统一展示 |
| 粗剪/字幕建议 | `POST /episodes/:id/edit/rough-cut`、`POST .../subtitles/suggest` | 无；Agent 只读/提案 |
| 混音计划/总线 | `GET/PUT /episodes/:id/mix`、`GET/PUT .../mix/buses` | 无 |
| 混音版本 | `GET/POST /episodes/:id/mix/revisions`、`POST .../restore` | 无 |
| 预览/渲染 | `POST /episodes/:id/mix/preview`、`POST .../mix/render` | 无 |
| 分离/资产 | `POST /episodes/:id/audio/separate`、`GET .../status`、`GET .../assets` | 无 |

剪辑/混音的能力增强（多选、波形、交叉淡化、J/L 切、音量包络）都在 `EditPlanV1` / `MixPlan` 的现有字段内表达；若需新增字段，按各自文档单独评审，不在本方案改 schema。

### 8.5 并发与幂等

- 所有写接口要求 `revision` 或 `updated_at`；不一致返回 `409`，body 带当前版本与差异。
- `apply` 支持 `Idempotency-Key`；同一 key 重复提交返回第一次结果，避免网络重试重复写。
- 保存计划时只递增一次 revision；预演资产上传不递增计划 revision（资产不是计划内容）。
- 版本快照保留最近 N 个（建议 50），旧快照可清理；成片/剪辑版本按各自设计保留。

### 8.6 存储与安全

- 预演资产存项目存储：`DATA_ROOT/static/projects/<projectId>/director/<planId>/<shotId>/<timestamp>.png`；数据库存相对 URL。
- 上传限制：只接受 PNG/JPEG/WebP；限制尺寸与体积（建议单张 ≤ 8 MiB）；服务端校验魔数，不信任扩展名。
- 路径校验：禁止 `..`、绝对路径、符号链接逃逸；复用现有项目存储工具。
- 权限：导演台读写复用 `episode_locks`/当前项目权限；只读模式禁止保存/应用/上传。
- 日志：记录操作者、作用域、动作、revision；不记录完整提示词/密钥。

### 8.7 迁移策略

- 只新增表，不改现有表；迁移幂等。
- `director_plans` 懒创建：首次 GET 返回空计划，首次保存才落库；避免给历史剧集批量造空行。
- 导入分镜时按 `storyboard_id` 去重；重复导入只补新增镜头，不覆盖已有导演字段。
- 不删除任何历史分镜、合片、导出、剪辑数据。

## 10. 验收标准

### 10.3b P3b 成片中心 + 源集成

1. 拼接、混音、剪辑导出的成片都在同一个成片列表可见。
2. 剪辑左侧能选择任意成片作为源；换源新建工程，不覆盖旧工程。

### 10.4 P4 Agent（L1–L3）

1. 小说页、导演台、剪辑页都能连续追问 3 轮，作用域正确；刷新后会话与消息历史还在。
2. 助手能读取当前页上下文（剧集/导演台/小说/成片），回答“这集有几个镜头、第 3 镜什么景别”。
3. 提出“把第 3 镜改成中景、镜头角度调低”，提案卡显示旧值/新值/影响范围；应用后写入，拒绝不写。
4. 提案应用带 `target_hash`；期间目标被并发修改则返回 409 / `conflict`，不覆盖新版本。
5. 写入后有审计记录；分镜/台词/资产提示词写回保存 before/after 快照与 `target_hash`；本期不提供自动撤销；导演计划与剪辑计划不由助手提案修改。
6. 越权请求（读别的项目、写只读集、改模型配置、删成片）被拒绝，不泄露内部路径/密钥。
7. SSE 流式可见文本、工具调用与进度；可停止；失败可重试；刷新后能看到消息与工具摘要。
8. 助手不触发付费生成；建议卡只打开现有流程，由用户确认后执行，不自动运行生产 Agent。
9. 现有 5 个专员的按钮任务不回归；它们的写入路径不变。
10. 工具面不包含 SQL、文件系统、任意 HTTP、Host 工具、Codemode、MCP。
11. 单用户同时运行数、单次步数、单次时长有上限；超限给出明确提示，不无限循环。
12. 导演专员只能读分镜/导演计划/资产，提案仅限 `storyboard.update` 白名单字段；不能写导演计划。
13. 助手与导演专员共用一个 `AgentDock`，不出现第二套聊天界面。
14. `agent.dock.enabled=false` 时入口完全隐藏；`agent.director.enabled=false` 时导演专员入口隐藏，助手不受影响。

### 10.5 P5 UI

1. 单集、导演台、剪辑、混音共用同一套顶栏/检查器/空态组件；面板折叠/拖宽后刷新仍保持。
2. 一个能力一个主入口：导演台、剪辑、成片、Agent 均无平行入口。
3. 单集阶段标签与实际页面对应；从任意页面能回到单集工作台。
4. 小白用户不看文档能完成“导入分镜→导演台摆位→应用→生产→剪辑”的主路径（可用性走查）。
5. 关键动作有可见按钮 + 右键菜单；不是快捷键唯一。
6. 暗色/亮色、中文/英文、窄屏折叠均可用；无文字溢出；1280 宽无横向滚动。
7. 正文对比度 ≥ 4.5:1；中文无 11px 关键文本；键盘焦点可见。
8. 空状态、错误、只读、冲突、保存状态都有统一容器与出口。
9. 提供日期化截图与“已实现/未实现”清单，不把设计稿当已完成。

### 10.6 P6 小说写作台

1. 现有章节下拉、正文编辑、自动保存、409 冲突处理与章节关系图不回归。
2. 章节树新增/重命名/排序/切换；正文编辑仍自动保存；刷新不丢。
3. 选中一段文字添加批注，批注锚点随文本编辑不漂移（或明确提示失效）。
4. 伏笔板记录“埋设章/回收章/状态”，在章节写作时可见。
5. 改编上下文包能带入剧集 `story_bible`；小说更新后剧集显示 `sourceStale` 并可重新同步。
6. 小说导出/导入不回归。
7. 默认写作 Tab 为三栏 split；`tabs` 回退可用。

### 10.7 回归与证据

- 改动前记录基线：后端测试、前端测试、现有 golden path 截图。
- 每阶段结束运行现有测试套件；新增测试单独列出；不以“测试数增加”代替功能验收。
- 所有验收以真实运行/截图/接口返回为准；无法运行的部分明确标注“未验证”，不写“已完成”。

## 11. 风险与非目标

### 11.1 风险

| 风险 | 等级 | 缓解 |
| --- | --- | --- |
| 3D 范围膨胀成游戏引擎 | 高 | 代理资产、6/20/8 上限、24–720 帧、不做骨骼/物理/最终渲染 |
| 两套镜头数据不一致 | 高 | `storyboards` 唯一生产契约；导演镜头只叠加；应用差异 + 409 |
| 子镜头文本冲突/覆盖 | 高 | 默认只追加；结构冲突返回 409；由用户显式选择“覆盖 / 合并 / 取消”，不静默覆盖 |
| 时长应用改变 H3 结果 | 高 | 默认保持；显式应用才改；按 17n+5 重算；标记 `videoStale` 并提示重新生成 |
| 成片中心迁移影响旧数据 | 高 | 按成片中心设计的幂等迁移；不删历史；先只读兼容再切换 |
| Agent 越权/误写 | 高 | 只读 + 提案；确认后应用；作用域校验；审计；before/after 快照；服务端归属检查 |
| Agent 循环/成本失控 | 中 | 步数/时长/并发上限；首版不注册付费生成工具；建议卡只打开现有流程；不自动重试生成 |
| 编辑内核抽象过度 | 中 | 先只接剪辑，音频随后接；共享命令语义，不共享序列化结构 |
| J/L 切声画不同步 | 中 | 帧为单位的链接与偏移；导出前校验；自动化测试覆盖 |
| 共用壳改造影响现有页 | 中 | U1 先只上令牌与状态栏；逐页接入；接入前后截图对比 |
| 单集页继续膨胀 | 中 | 新能力独立页面；不在本方案重构单集页 |
| 3D 性能/体积 | 中 | 动态 import；代理资产；上限；WebGL 降级 |
| 术语与 i18n 不一致 | 低 | 统一词表；中英同步；UI 走查 |
| 测试基线漂移 | 中 | P0 先记录基线；每阶段回归；不以旧数字冒充当前结果 |

### 11.2 非目标

- 不做完整 3D 角色建模、骨骼绑定、动作库、物理、实时渲染。
- 不做游戏引擎、实时多人协作、云端渲染农场。
- 不做第二套分镜/时间线/成片列表/播放器。
- 不替换现有生产面板、ComfyUI 网关、H3 工作流、TTS。
- 不自动把导演台预演帧写入分镜或生成任务；必须用户确认。
- 不做 4K/60fps、复杂调色、跟踪、抠像、多视频轨自由叠加；不把短剧剪辑拖成通用 NLE。
- 不把 Agent 做成 Host/SQL/文件系统/Codemode/MCP 通用代理；只做领域只读与提案工具。
- 不做常驻 AI 侧栏；Agent 以悬浮入口按需展开，展开不改变舞台宽度。
- 不在本方案内完成小说模块的全部 Reveric 对标；只做写作闭环与改编衔接。
