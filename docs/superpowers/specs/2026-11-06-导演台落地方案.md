# 导演台落地方案

- 状态：设计稿，未实施
- 日期：2026-11-06
- 定位：新增 2D/3D 导演台，只做排演、机位、构图与镜头节奏；不接管生成执行
- 上游方案：[全链路集成与优化方案](./2026-11-06-全链路集成与优化方案.md)
- 关联方案：[小说工作台落地方案](./2026-11-06-小说工作台落地方案.md) · [剪辑工作台落地方案](./2026-11-06-剪辑工作台落地方案.md) · [页面视觉优化落地方案](./2026-11-06-页面视觉优化落地方案.md)

## 1. 结论

导演台是分镜的**叠加层**，不是第二套分镜：

- 一个导演镜头 = 一个 `storyboards` 行 = 一个 8–15 秒视频生成任务。
- 子镜头内嵌在导演计划 JSON 中，不建独立表，不单独生成视频。
- 生产侧仍然只读 `storyboards`；导演台不新增生成入口、不改任务队列、不改 ComfyUI 时间线。
- 只有用户点击“应用到分镜”时，才把允许的字段写回 `storyboards`。

2D 与 3D 共用同一份镜头表，首版同期交付；3D 只是视图，不是第二份数据。

## 2. 现状与契约

### 2.1 现有生产契约

| 现有对象 | 代码落点 | 导演台如何使用 |
| --- | --- | --- |
| 分镜行 = 分镜段落 = 视频任务 | `backend/src/db/schema.ts:184-217` | 导演镜头 1:1 引用 `storyboard_id` |
| 分镜字段：景别、角度、运动、时长、画面描述、视频提示词 | 同上 | 读取；按允许清单回写 |
| 整集 ComfyUI 时间线：每个分镜一段 | `backend/src/services/comfyui-timeline.ts:234-290` | 不改变；时长变更后仍走原对齐逻辑 |
| 单镜生成、批量生成、视频提示词 | 现有生成面板 | 不改变；导演台不发起任务 |
| 分镜更新接口 | `backend/src/routes/storyboards.ts` | 复用其数据校验与项目归属校验 |

### 2.2 结论：输入输出与现有分镜一致

- 输入：当前集的 `storyboards`、场景图、角色图、道具图、剧集画幅。
- 输出：导演计划（机位、人物站位、子镜头、时长）与可选的分镜字段回写。
- 不输出新的分镜行，不改变镜号，不改变“一段一任务”的粒度。

### 2.3 现有缺口

- 没有导演计划、机位、站位、子镜头结构。
- 没有 2D 俯视排演，也没有 3D 机位预演。
- 分镜字段只有文本，无法直观看到“摄影机在哪、人物站哪、切点在哪”。
- 改时长/机位后，已生成视频不会自动标记过期。

## 3. 范围与非目标

### 3.1 范围

- 新增独立页面 `/drama/:id/episode/:episodeNumber/director`。
- 2D 俯视排演：场景、人物站位、摄影机、机位路径、镜头列表。
- 3D 机位预演：代理场景、人物立牌、摄影机视锥；不做角色动画。
- 导演计划保存、版本、恢复。
- 应用机位/时长到分镜，带冲突检测与写回快照。
- 配置化开关、只读模式、紧急回滚。

### 3.2 非目标

- 不做角色骨骼、动作捕捉、口型、表情动画。
- 不做第二个时间线编辑器；底部只有镜头条，用于跳转与选镜。
- 不做新的视频生成、图片生成或 ComfyUI 工作流。
- 不修改现有 `storyboards` 表结构。
- 不自动删除或重生成已有视频。
- 不把小说正文直接映射为镜头；仍以分镜为生产契约。

## 4. 目标形态

### 4.1 页面结构

```text
┌ 顶栏：返回 | 集名 | 2D/3D | 只读/可编辑 | 保存状态 | 应用到分镜 ┐
├ 左：镜头列表 260px ┬ 中：排演舞台 flex ┬ 右：检查器 320px ┤
│ 镜头 1  12.2s      │ 2D 俯视图 / 3D 视口 │ 机位 / 站位 / 子镜头 / 时长 │
│ 镜头 2   9.8s      │ 拖拽人物、摄影机      │ 写回字段勾选 / 过期提示      │
├────────────────────┴────────────────────┴──────────────────────┤
│ 底部镜头条：按镜号排列的缩略卡，点击跳转，显示已生成/未生成      │
└──────────────────────────────────────────────────────────────────┘
```

- 左栏镜头列表与 `storyboards` 一一对应，按 `storyboard_number` 排序。
- 中栏 2D/3D 共用选中镜头、检查器与镜头条；切换视图不丢状态。
- 右栏检查器只改导演计划，不直接改库；点“应用到分镜”才写回。
- 底部镜头条不是时间线，不支持拖拽改顺序、裁剪、转场；这些属于剪辑台。

### 4.2 2D 视图

- 画布为俯视网格，默认 1 米 = 40px，可缩放 50%–200%。
- 场景图可选作为底图，默认半透明；没有场景图时使用网格和场景名。
- 人物以圆形/头像牌显示，可拖拽位置、旋转朝向。
- 摄影机以图标 + 视锥显示，可拖拽位置、旋转、调整焦距。
- 机位路径以折线显示；每段路径对应一个子镜头，路径点可拖动。
- 选中人物或摄影机时，右栏显示对应字段；未选中时显示镜头概览。
- 画面外的人物可拖回；所有坐标限制在场景边界内。

### 4.3 3D 视图

- 使用代理几何：地面网格、场景图平面、人物立牌、摄影机视锥。
- 摄影机可通过鼠标拖拽环绕观察；提供“切到机位”按钮查看摄影机画面。
- 3D 只读展示站位与机位，不提供骨骼、动作、表情编辑。
- 进入 3D 才懒加载 Three.js；未启用或加载失败时回退 2D，不阻塞页面。
- 3D 不额外生成素材，全部复用场景图、角色图、道具图。

### 4.4 子镜头

- 每个导演镜头可包含 2–4 个子镜头，默认从现有 `description` 的【镜头N】解析。
- 子镜头字段：序号、画面描述、时长、对应机位路径段。
- 子镜头不是独立视频任务；应用时只影响该分镜段落的描述与时长。
- 子镜头总时长必须等于镜头时长，允许 ±0.2 秒误差；超出时禁止应用。

### 4.5 只读与可编辑

| 模式 | 页面 | 可保存 | 可应用 | 用途 |
| --- | --- | --- | --- | --- |
| `off` | 入口隐藏，接口 403 | 否 | 否 | 默认，未验收前 |
| `readonly` | 可看 2D/3D、镜头列表 | 否 | 否 | 审片、演示、外部协作 |
| `on` | 全功能 | 是 | 是 | 正式使用 |

## 5. 配置化设计

继续使用 `app_settings`，键统一 `director.*`。读取时清洗，写入时钳制；默认 `off`，首版验收切 `readonly`，稳定后再切 `on`。`director.mode!=off` 时 2D/3D 都可用，3D 默认开启。

| 配置键 | 类型 / 默认 | 范围 | 作用 | 紧急环境变量 |
| --- | --- | --- | --- | --- |
| `director.mode` | `off` | `off` / `readonly` / `on` | 导演台总开关 | `DIRECTOR_MODE` |
| `director.view.default` | `2d` | `2d` / `3d` | 默认视图 | 无 |
| `director.view3d.enabled` | `true` | 布尔 | 首版默认开启 3D；关闭时不加载 Three.js | `DIRECTOR_3D=off` |
| `director.apply.fields` | `["shot_type","angle","movement","duration"]` | JSON 数组 | 允许写回的分镜字段 | 无 |
| `director.apply.promptAppend` | `false` | 布尔 | 是否允许向 `video_prompt` 追加机位描述 | 无 |
| `director.apply.subshotSync` | `false` | 布尔 | 是否允许把子镜头描述同步到 `description` | 无 |
| `director.duration.min` | `8` | 6–12 | 镜头最短秒数 | 无 |
| `director.duration.max` | `15` | 12–20 | 镜头最长秒数 | 无 |
| `director.duration.fps` | `24` | 24 / 25 / 30 | 时长帧对齐帧率 | 无 |
| `director.stage.maxShots` | `200` | 50–500 | 单集镜头上限，超出只读 | 无 |
| `director.previs.maxAssets` | `20` | 5–50 | 3D 视图中最多加载的代理素材数 | 无 |

约定：

- `director.apply.fields` 只允许白名单值：`shot_type`、`angle`、`movement`、`duration`。
- `description` 默认不写；只有 `director.apply.subshotSync=true` 且子镜头数量与原文【镜头N】数量一致时才允许。
- `video_prompt` 只追加，不覆盖；追加带固定标记 `【机位】`，重复应用不重复追加。
- 环境变量只用于紧急回滚，不提供页面入口。
- 关闭导演台不影响任何现有分镜、生成任务、ComfyUI 时间线。

## 6. 数据设计

只新增两张表。导演计划用 JSON 文档保存，避免为每个机位/站位/子镜头建表。

### 6.1 `director_plans`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | integer PK | 计划 id |
| `episode_id` | integer unique | 一集一个当前计划 |
| `drama_id` | integer | 项目 id |
| `doc_json` | text | 导演计划文档，JSON |
| `doc_version` | integer | 文档结构版本，首批为 1 |
| `version` | integer | 保存版本号，用于乐观锁 |
| `based_on_hash` | text | 生成计划时的分镜指纹 |
| `created_at` / `updated_at` | text | 时间 |

索引：`unique(episode_id)`。

### 6.2 `director_plan_revisions`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | integer PK | 版本 id |
| `plan_id` | integer | 计划 id |
| `revision_no` | integer | 版本号，从 1 递增 |
| `doc_json` | text | 该版本的完整文档 |
| `note` | text | 版本备注，可空 |
| `is_current` | integer boolean | 当前版本 |
| `created_at` | text | 时间 |

索引：`unique(plan_id, revision_no)`、`(plan_id, is_current)`。

### 6.3 计划文档 v1

```json
{
  "version": 1,
  "episode_id": 12,
  "based_on": { "storyboard_hash": "a1b2c3", "storyboard_count": 9 },
  "view": { "mode": "2d", "zoom": 1 },
  "shots": [
    {
      "storyboard_id": 301,
      "shot_number": 1,
      "scene_id": 22,
      "duration_sec": 12.25,
      "camera": {
        "shot_type": "中景",
        "angle": "平视",
        "movement": "缓慢推进",
        "lens_mm": 35,
        "height_m": 1.6,
        "position": { "x": 4.2, "y": 0, "z": 3.1 },
        "look_at": { "x": 0, "y": 1.2, "z": 0 }
      },
      "blocking": [
        { "character_id": 8, "name": "林小雨", "x": 0.5, "y": 0, "z": 0.3, "rotation": 180 }
      ],
      "subshots": [
        { "no": 1, "description": "林小雨推门进来，停在门口。", "duration_sec": 4.5, "path_index": 0 },
        { "no": 2, "description": "她看向桌上的旧信，眼神停住。", "duration_sec": 3.75, "path_index": 1 },
        { "no": 3, "description": "特写：手指碰到信封边缘。", "duration_sec": 4.0, "path_index": 2 }
      ],
      "notes": "进门方向从画面左侧入。",
      "dirty_fields": ["movement", "duration"]
    }
  ]
}
```

约束：

- `shots.length` 必须等于当前集未删除分镜数量；缺失分镜在加载时补空镜头，多余镜头不写回。
- `storyboard_id` 必须属于该集；跨集 id 直接 400。
- `duration_sec` 在 `min`/`max` 内；应用时按 `director.duration.fps` 对齐到 `17n+5` 帧网格。
- `blocking` 只允许该集已关联角色；没有角色图时仍可排演，3D 用占位牌。
- 子镜头总时长与镜头时长误差超过 0.2 秒时，`can_apply=false`，接口返回具体原因。

## 7. 接口设计

### 7.1 读取

```http
GET /episodes/:id/director
```

返回：

```json
{
  "mode": "on",
  "view3d_enabled": true,
  "plan": { "version": 1, "doc_version": 1, "shots": [] },
  "storyboards": [
    {
      "id": 301,
      "storyboard_number": 1,
      "duration": 12,
      "shot_type": "中景",
      "angle": "平视",
      "movement": "固定",
      "has_video": true,
      "updated_at": "2026-11-06T10:00:00.000Z"
    }
  ],
  "warnings": []
}
```

- 没有计划时，服务端按当前分镜生成空计划并返回，不落库。
- `mode=off` 返回 403；`readonly` 返回数据但 `can_edit=false`。
- `warnings` 包含“分镜已变化”“镜头数超限”“场景图缺失”等。

### 7.2 保存

```http
PUT /episodes/:id/director
```

请求：

```json
{
  "base_version": 3,
  "doc": { "version": 1, "shots": [] },
  "note": "调整第 3 镜机位"
}
```

- `base_version` 与当前 `version` 不一致返回 409，并返回当前版本号。
- 保存只写导演计划与版本，不写 `storyboards`。
- 每次保存生成一条 `director_plan_revisions`；最多保留 50 个版本，超出删最旧的非当前版本。
- `doc` 通过服务端校验：镜头归属、时长范围、子镜头总时长、角色归属。

### 7.3 应用到分镜

```http
POST /episodes/:id/director/apply
```

请求：

```json
{
  "base_version": 3,
  "storyboard_ids": [301, 302],
  "fields": ["shot_type", "angle", "movement", "duration"],
  "append_prompt": false,
  "sync_subshots": false
}
```

行为：

1. 校验 `fields` 是配置白名单子集。
2. 计算当前分镜指纹；与计划 `based_on_hash` 不一致返回 409，并列出变化镜头。
3. 对每个选中镜头，只写允许字段。
4. `duration` 先对齐到 `17n+5` 帧网格，再写回。
5. `append_prompt=true` 时，向 `video_prompt` 追加一行 `【机位】景别=...；角度=...；运动=...；镜头=...mm`；已存在 `【机位】` 则不重复追加。
6. `sync_subshots=true` 时，仅当子镜头数量与 `description` 中【镜头N】数量一致，逐段替换描述文本；不一致返回 409。
7. 写回前保存 before/after 快照到响应；不新建分镜历史表。
8. 已有视频的镜头返回 `stale=true`，不删除视频、不改任务状态。

返回：

```json
{
  "applied": [301, 302],
  "skipped": [],
  "stale": [301],
  "snapshots": [
    {
      "storyboard_id": 301,
      "before": { "duration": 12, "shot_type": "中景", "angle": "平视", "movement": "固定" },
      "after": { "duration": 12.25, "shot_type": "中景", "angle": "平视", "movement": "缓慢推进" }
    }
  ],
  "warnings": ["镜头 1 已生成视频，应用后需重新生成"]
}
```

### 7.4 版本

```http
GET  /episodes/:id/director/revisions
POST /episodes/:id/director/revisions/:revisionId/restore
```

- 恢复只改导演计划，不自动写回分镜。
- 恢复后 `version` 递增，不覆盖历史版本。

### 7.5 设置

```http
GET /settings/director
PUT /settings/director
```

- 返回 `mode`、`view3d_enabled`、`apply_fields`、时长范围等前端需要的安全字段。
- 不返回任何密钥；导演台不直接调用 AI 服务。

### 7.6 错误码

| HTTP | 场景 |
| --- | --- |
| 400 | 分镜不属于本集、时长越界、子镜头总时长不符、字段不在白名单 |
| 403 | `director.mode=off`，或只读模式下写操作 |
| 404 | 分集/计划/版本不存在 |
| 409 | 保存版本冲突、分镜已被修改、子镜头数量不一致 |
| 422 | 计划文档结构非法（JSON 可解析但字段不合法） |

| `backend/src/db/schema.ts` | 改 | 两张表定义 |
| `backend/src/db/sqlite-schema.ts` | 改 | 幂等建表 + 索引 |
| `backend/src/routes/settings.ts` | 改 | 增加 `GET/PUT /director` |
| `backend/tests/director-plan.test.ts` | 新增 | 1:1、时长、子镜头、版本冲突 |
| `backend/tests/director-apply.test.ts` | 新增 | 白名单写回、指纹 409、幂等追加、过期标记 |

## 9. 分阶段实施

### D0 只读 2D 骨架（1–2 天）

任务：

1. 新增表、配置、`GET /episodes/:id/director`。
2. 注册路由与页面，顶栏入口仅 `mode!=off` 显示。
3. 2D 舞台只读渲染：场景底图、人物、摄影机、镜头列表。
4. 未选中镜头时显示空态；没有分镜时提示先生成分镜。
5. `mode=readonly` 时隐藏保存/应用按钮。

完成标准：

- 镜头数与分镜数一致，镜号一致。
- 关闭 `director.mode` 后入口消失，直接访问返回 403。
- 不写任何库；现有分镜页面与生成任务无变化。
- 100 个镜头滚动与切换不卡顿。

### D1 计划编辑与版本（2–3 天）

任务：

1. 2D 拖拽人物、旋转朝向、拖拽摄影机、调整焦距。
2. 检查器编辑景别、角度、运动、时长、子镜头描述。
3. 自动保存与手动保存；`base_version` 冲突提示。
4. 版本列表、恢复、备注。
5. 计划文档校验与错误提示。

完成标准：

- 刷新后站位、机位、子镜头、时长完整恢复。
- 两个窗口同时编辑，后保存者收到 409，不覆盖前者。
- 恢复旧版本后 `version` 递增，历史版本仍可查看。
- 子镜头总时长不等于镜头时长时，保存允许但应用按钮禁用并说明原因。

### D2 应用到分镜（1.5–2 天）

任务：

1. 应用弹窗：选择镜头、勾选字段、是否追加机位描述、是否同步子镜头。
2. 指纹校验与 409 冲突列表。
3. 写回白名单字段；时长按帧网格对齐。
4. 返回 before/after 快照，页面展示“已应用/已跳过/已过期”。
5. 已生成视频的镜头显示“需重新生成”，不自动删任务。

完成标准：

- 只写勾选字段；未勾选字段保持原值。
- `description` 默认不变；`video_prompt` 追加一次后再应用不重复。
- 分镜在导演台打开后被其他页面修改，应用返回 409，不静默覆盖。
- 应用后刷新生产面板，分镜字段与导演台一致；生成任务未被触发。
- 写回失败时事务回滚，不留下部分更新。

### D3 3D 预演（2–3 天，与 D0–D2 同批交付）

首版包含 3D，不是可选阶段；2D 与 3D 共用同一镜头表、同一保存状态，必须同批验收。

任务：

1. 懒加载 Three.js，只在 `director.view3d.enabled=true` 且用户切到 3D 时加载。
2. 地面网格、场景平面、人物立牌、摄影机视锥。
3. 鼠标环绕、缩放、切到机位；显示选中镜头路径。
4. 加载失败回退 2D，给出提示，不白屏。
5. 3D 与 2D 共用选中镜头、检查器与保存状态。

完成标准：

- 关闭 3D 时网络面板不请求 Three.js。
- 3D 切换回来，2D 选中镜头与未保存修改不丢。
- 20 个代理素材以内可交互；超过上限只加载选中镜头相关素材。
- 3D 不新增素材文件，不调用生成服务。

D0–D3 合计约 7–10 天；2D 与 3D 同批验收，不单独发布 2D MVP。

## 10. 验收清单

### 10.1 功能

- [ ] 导演镜头与分镜段落 1:1，镜号一致，数量一致。
- [ ] 2D 可拖拽人物与摄影机，刷新后位置恢复。
- [ ] 子镜头可增删改，总时长校验有效。
- [ ] 可保存、查看版本、恢复版本。
- [ ] 可选择镜头与字段应用到分镜；未勾选字段不变。
- [ ] 已生成视频的镜头应用后显示“需重新生成”，视频文件仍在。
- [ ] 3D 可切换、可回退，关闭开关时不加载。
- [ ] 2D 与 3D 同批可用；`DIRECTOR_3D=off` 时 3D 入口隐藏且不加载 Three.js。

### 10.2 兼容

- [ ] `storyboards` 表结构不变，现有分镜页面、批量生成、ComfyUI 时间线不受影响。
- [ ] 导演台不触发任何生成任务；任务队列与轮询逻辑不变。
- [ ] 应用时长后，ComfyUI 时间线仍按原 `17n+5` 对齐逻辑生成。
- [ ] 只读模式下所有写接口返回 403，读接口正常。
- [ ] `director.mode=off` 时，现有页面完全不受影响。

### 10.3 配置与回滚

- [ ] 修改 `director.mode` 后刷新生效，无需重启。
- [ ] `DIRECTOR_MODE=off` 可紧急关闭。
- [ ] `DIRECTOR_3D=off` 可紧急关闭 3D，2D 仍可用。
- [ ] 回滚到 `off` 后，新表数据保留，已写回分镜不回滚；需要恢复时用应用响应中的快照手工恢复。
- [ ] 删除导演台代码不会影响生产链路（生产只读 `storyboards`）。

## 11. 风险与边界

| 风险 | 处理 |
| --- | --- |
| 导演计划与分镜双份数据漂移 | 计划只引用 `storyboard_id`；应用前指纹校验；冲突 409 |
| 时长改动破坏帧网格 | 应用时统一对齐 `17n+5`，不直接写小数秒 |
| 追加提示词重复 | 固定 `【机位】` 标记，重复应用跳过 |
| 子镜头同步改坏台词 | 默认关闭；数量不一致直接 409；只替换对应【镜头N】文本 |
| 3D 包体过大 | 路由级懒加载；关闭开关不加载；加载失败回退 2D |
| 大场景拖拽卡顿 | 2D 用 CSS transform；3D 只加载选中镜头相关代理素材 |
| 用户误以为应用后自动重生成 | 明确“需重新生成”提示；不自动删旧视频、不自动排队 |

## 12. 不做的事

- 不做角色动画、骨骼、口型、表情。
- 不做第二个剪辑时间线。
- 不做自动分镜；分镜仍由现有拆镜 Agent 或人工维护。
- 不修改 `storyboards` 表结构，不新增镜头表。
- 不把导演计划作为生成输入；生成仍读分镜字段与 ComfyUI 时间线。
