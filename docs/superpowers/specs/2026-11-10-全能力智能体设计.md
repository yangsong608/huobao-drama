## 1. 目标与成功标准

### 1.1 目标

用户可以用自然语言发起真实的生产任务，例如：

- “帮我新建《XX》第二章”
- “帮我续接一下片尾”
- “把这一集全流程做出来”
- “把刚才生成的第三镜重新生成，其他不要动”
- “把设置里的视频并发改成 2，然后继续”

智能体需要自己读取当前页面和项目上下文，判断用户意图，列出计划，等待用户批准，然后真正调用现有能力完成工作；不是只给建议，也不是让用户手动点一串按钮。

### 1.2 成功标准

1. 任何写操作都必须先形成一个可审阅的计划，用户批准后才执行。
2. 计划中的每一步都能映射到一个明确的 MCP 工具或受控 REST 调用，不存在“模型凭空写库”。
3. 长任务不占用对话回合，以任务卡形式展示进度，完成后追加回执。
4. 失败时保留已完成步骤，暂停并给出重试、跳过、取消选项。
5. 后端重启后能识别中断的计划，并与真实作业状态对账。
6. 所有执行步骤都有审计记录；设置、提示词、技能等可回滚的操作保留旧值快照。
7. 智能体不能批准自己的计划，不能读取或回显明文密钥。
8. 真实模型、真实作业、真实数据库完成验收，不用占位测试冒充。

### 2.1 审批语义的统一解释

“计划批准 + 高风险确认”和“计划批准后自动”合并为同一套语义：

- 计划卡在批准前完整列出所有步骤、目标、参数、预计成本、不可恢复项和假设。
- 含删除、覆盖、设置变更、高成本生成等步骤时，批准按钮要求用户勾选一次“我已确认上述高风险操作”，这是计划级确认，不是逐步确认。
- 用户批准后，执行器按顺序自动执行全部启用步骤，成功路径上不再暂停。
- 任何参数修改、步骤启用状态变化都会改变计划哈希，使原批准失效，必须重新批准。

### 2.2 “全程不停”的边界

成功路径不设检查点。以下情况仍会停下：

- 某一步失败。
- 计划等待同一资源的写锁。
- 用户主动取消。
- 后端重启，计划进入中断状态等待恢复。
- 执行器发现计划参数已失效或目标已被其他操作改变。

## 3. 设计原则与不变量

1. **能力目录是唯一能力源**：MCP 工具与命名 REST 能力是仅有的两类能力；智能体不复制小说、分镜、视频、合并等业务逻辑，只编排它们和现有作业。
2. **模型提议，服务端执行**：模型只能读取上下文和提交计划，不能直接调用写能力。
3. **计划是唯一写入口**：所有业务写操作必须落在计划步骤中，由确定性执行器执行。
4. **批准只能由用户完成**：模型没有批准工具，执行面禁止调用助手计划的批准、编辑和审批状态接口；取消只允许通过 cancel_plan 操作本会话未完成计划。
5. **高风险集中确认**：批准前一次性展示，批准后不逐步打断。
6. **密钥不进模型上下文**：读取结果脱敏；需要新密钥时由计划卡的安全输入或服务端生成，模型只看到占位符。
7. **外部 MCP 不变**：外部客户端继续用 Bearer Token 直接调用；审批只作用于内嵌助手。
8. **不使用 Mastra workspace**：不挂载 shell、文件读写、命令执行工具。
9. **不写原始 SQL**：所有数据访问走现有服务与路由。
10. **资源级互斥**：同一小说、项目、分集、时间线上同时只允许一个写计划，避免互相覆盖；不同资源可并行。
11. **失败不自动烧钱重跑**：失败暂停，由用户选择重试、跳过或取消。
12. **无业务成本上限**：按用户决策不设每日预算、视频数量或并发上限；只保留计划估算、审计、取消、失败暂停和资源锁等技术保护。
13. **不依赖 rebrand 助手层**：新分支从 `main` 起步，重新实现会话、Dock、scope、计划与执行面；旧分支只作为设计参考。
14. **导演只读策略保留**：首版不做导演入口；未来接入时只读、只分析、只建议，不执行写操作。

## 4. 总体架构

| 层 | 职责 | 主要落点 |
|---|---|---|
| 页面适配层 | 声明当前页面 scope、快捷指令、刷新钩子 | 首页、小说库、小说详情、项目详情、剧集、剪辑 |
| 全局 Dock | 会话、消息流、计划卡、任务卡、审计入口 | 新增前端组件与组合式函数 |
| 助手运行时 | 意图分析、上下文读取、能力发现、计划提案 | 新增助手 Agent 与会话服务 |
| 计划层 | 计划、步骤、编辑、审批、哈希、状态机 | 新增计划服务与路由 |
| 执行器 | 依赖解析、资源锁、工具调用、作业桥、重试/取消/恢复 | 新增确定性执行器 |
| 能力网关 | 能力元数据、JSON Schema 校验、脱敏、审计、幂等 | 基于现有 MCP 工具注册表与命名 REST 注册表 |
| 作业桥 | 统一识别小说作业、视频任务、自动化、拆分、合并等作业状态 | 新增作业适配器 |
| 现有能力 | 66 个 MCP 工具、265 个 REST 处理器、现有队列与作业 | 不重写 |

数据流：

1. 页面适配器把当前 scope 写入 Dock。
2. 用户发消息，助手读取 scope 摘要和业务上下文。
3. 助手调用能力目录，选择能力，提交计划草案。
4. 服务端校验能力来源、参数、目标归属、依赖、风险和成本估算。
5. Dock 展示计划卡；用户编辑关键参数、禁用可选步骤、勾选高危确认并批准。
6. 执行器按步骤调用能力网关；异步步骤交给作业桥跟踪。
7. 每一步写入审计并推送事件；完成后追加回执。
8. 失败或重启时进入暂停/中断状态，等待用户处理。

## 5. 能力目录与 MCP 复用

### 5.1 元数据

现有 66 个 MCP 工具只有名称、描述、输入 Schema 和 handler，且没有设置、MCP 自身配置、项目/分集删除等语义工具。能力目录必须同时覆盖 MCP 工具和命名 REST 能力，不能只给 66 个工具补元数据。

每个能力补充：

| 字段 | 说明 |
|---|---|
| source | mcp 或 rest；决定执行方式 |
| category | 小说、章节、项目、分集、分镜、资产、视频、音频、合并、剪辑、混音、导出、设置、系统 |
| risk | read、write、destructive、expensive、system |
| async | 是否启动异步作业 |
| jobKind | 作业类型，供作业桥识别 |
| editableFields | 计划卡允许编辑的参数白名单 |
| secretFields | 需要脱敏或安全输入的字段 |
| fileInput | 文件输入策略：`none`、`secure_slot`、`storage_path`、`mixed`；声明安全文件槽的目标字段、类型、MIME、大小上限，以及路径字段允许的存储根 |
| resourceKeys | 从参数和结果中提取的资源键，用于资源锁 |
| estimate | 成本/规模估算方式，例如按镜头数、时长、模型 |
| agentVisible | 是否允许内嵌助手使用；默认全部可见 |
| annotations | 映射为 MCP 标准 readOnlyHint、destructiveHint、idempotentHint |
| method | 仅 source=rest：固定 HTTP 方法 |
| pathTemplate | 仅 source=rest：固定路径模板，路径参数只能按类型填充 |
| pathParamsSchema | 仅 source=rest：路径参数 Schema |

完整性测试要求：

- 每个 MCP 工具都有元数据。
- 每个命名 REST 能力都有元数据，且 method + pathTemplate 存在于后端路由。
- 元数据中不存在已删除的工具或路由。
- 每个能力的 risk 和 source 不为空。
- 异步能力必须声明 jobKind 或可被作业桥从结果中识别。
- 写能力的 editableFields 必须来自输入 Schema 的真实字段。
- 含文件参数的 MCP 工具必须声明 fileInput；`secure_slot` 的原始 base64 字段不得出现在 editableFields；`storage_path` 必须声明 allowedRoots，且助手只能引用存储根内的既有文件。
- 高风险设置、删除、MCP 自身配置不得只依赖 `api_request`，必须有命名 REST 能力。

全量业务路由口径：上述清单覆盖新增、更新、查询、删除、生成、导出、影片与首末帧等业务路由；`/api/v1/assistant`、`/api/v1/mcp`、`/api/v1/server-update`、`/api/v1/agent` 等系统/内部路由不登记为业务能力。已有 MCP 工具的操作不重复登记命名能力。未登记但只读的业务路由可由内部助手的 `api_request` GET 访问；未登记的非 GET 长尾写入默认拒绝，只有 `apiRequestWriteAllowlist` 显式登记后才可用。

命名 REST 能力的校验与执行要求：

- 只能调用清单内的 method + pathTemplate，禁止模型拼接任意路径。
- 路径参数按 pathParamsSchema 填充并做类型校验。
- 请求体按输入 Schema 校验，未知字段拒绝。
- 高风险能力（设置、删除、MCP 自身配置）不得走 `api_request`，必须走命名能力。
- `api_request` 只作为未登记只读长尾与 `apiRequestWriteAllowlist` 显式登记的低风险写入的兜底，并在计划卡标记为“原始 REST 调用”；未登记的非 GET 写入默认拒绝。
- 执行时仍复用现有路由，不复制业务逻辑；服务端记录能力键、方法、路径模板和脱敏参数。

### 5.2 风险分类规则

| 风险 | 判定规则 | 示例 |
|---|---|---|
| read | 只读查询、列表、状态、诊断 | 列项目、读章节、查任务状态 |
| write | 创建、保存、更新、导入、同步、定稿、补全 | 保存章节、更新分镜、创建分集 |
| destructive | 删除、覆盖已有内容、清空重拆、撤销修复 | 删除项目、覆盖章节、替换全部分镜 |
| expensive | 触发模型生成、图片、视频、合并、导出、自动化 | 生成章节、生成视频、整集流水线、合并 |
| system | 设置、提示词、技能、MCP 自身配置、进程级开关 | 改并发、改模型、改 MCP 端口、改提示词 |

高风险集中确认规则：

- 计划中含 destructive、expensive、system 任一步骤时，批准前必须勾选高危确认。
- 计划卡必须展示删除对象、覆盖对象、设置字段的旧值/新值、预计镜头数/时长/模型。
- 无法估算时显示“未知”，不阻止执行。

### 5.3 api_request 的特殊处理

`api_request` 是长尾能力的统一入口，但它绕过了语义工具的参数结构，需要单独治理。内部助手与外部 MCP 使用不同的治理边界。

内部助手网关采用严格白名单：

- 路径只允许 `/api/v1/` 开头，拒绝 `..`、`%2e%2e` 等编码穿越。
- GET 仅用于未命名化的只读长尾；以下前缀对所有方法一律拒绝：`/api/v1/assistant`、`/api/v1/mcp`、`/api/v1/settings`、`/api/v1/jobs`、`/api/v1/ai-configs`、`/api/v1/prompts`、`/api/v1/skills`、`/api/v1/server-update`、`/api/v1/agent`、`/api/v1/upload`。
- 非 GET 默认拒绝，只有登记在 `apiRequestWriteAllowlist` 中的低风险长尾写才允许；白名单首版为空，新增条目必须同时提供低风险理由、方法 + 路径模板测试和复核记录。
- 以下类别永远不得进入白名单：设置、队列、AI 配置、提示词、技能、MCP、助手、删除、上传，以及生成、合并、导出、渲染、分离、批量视频等昂贵作业；这些必须使用命名能力。
- DELETE 一律拒绝，只能走命名删除能力。
- `read_capability` 不得使用 `api_request` 执行非 GET。
- 方法限定 GET、POST、PUT、PATCH、DELETE；当前 handler 只实现 GET/POST/PUT/DELETE，实施时必须补齐 PATCH（已有 PATCH 路由，例如 `PATCH /api/v1/novels/:id/blueprint/chapters/:chapterNo`）。
- 计划卡展示实际方法、路径、请求体摘要，并标记“原始 REST 调用”；执行前重新计算风险，命中拒绝规则立即失败。
- 读取结果统一脱敏；`list_api_endpoints` 必须同时过滤 `/api/v1/mcp` 和 `/api/v1/assistant`。

外部 MCP 直连：

- 保持现有 Bearer Token 直接调用语义；方法集合与内部实现同步补齐 PATCH；继续拒绝 `/api/v1/mcp`，并新增拒绝 `/api/v1/assistant`。
- 外部 MCP 没有命名能力，不套用内部助手的严格写入白名单；其既有直连行为不在本次变更范围内。
- 外部 MCP 的 `api_request` 不得读取或修改助手计划、消息、批准状态。

内嵌助手修改 MCP 自身配置必须走命名能力 `mcp.update_config` / `mcp.rotate_token`，必须进入计划并展示风险，不得用 `api_request` 绕过。

### 5.4 内外部能力面的区别

| 能力面 | 调用方式 | 审批 | api_request | MCP 自身配置 |
|---|---|---|---|---|
| 内嵌助手 | 进程内调用 MCP handler + 命名 REST 能力 + 安全文件输入 | 计划批准 | 严格白名单：GET 只读长尾；非 GET 仅显式低风险白名单；高危类别拒绝 | 允许，进入计划并告警 |
| 外部 MCP 客户端 | HTTP + Bearer Token，66 个工具 + `api_request` | 无 | 保持现有方法/路径语义，新增拒绝 `/api/v1/assistant`；继续拒绝 `/api/v1/mcp` | 保持现有禁止 |
| 现有生产按钮 | 现有路由 | 现有交互 | 不涉及 | 不涉及 |

内嵌助手不走 5780 端口，不需要 Token；复用工具 handler 和现有路由，避免网络与鉴权开销。外部 MCP 的协议、端口、Token 和工具行为保持兼容，只增加注解元数据；外部客户端看不到也调不到 `/api/v1/assistant`。

## 6. 助手运行时与模型路由

### 6.1 助手 Agent

新建一个助手 Agent，不与现有五个生产 Agent 混用。它只挂载以下工具：

| 工具 | 作用 |
|---|---|
| get_scope_context | 读取当前页面、项目、分集、小说摘要 |
| read_capability | 执行 risk=read 的 MCP 工具和只读命名 REST 能力，返回脱敏结果；不得用 `api_request` 执行非 GET 方法 |
| list_capabilities | 列出能力目录的紧凑索引，包含 source=mcp/rest |
| search_capabilities | 按关键词、分类、风险、来源过滤能力 |
| describe_capability | 返回某个能力的完整 Schema、示例、副作用、可编辑字段 |
| propose_plan | 提交计划草案；步骤可引用 MCP 工具或命名 REST 能力，服务端校验并生成计划卡 |
| get_plan_status | 查询当前会话计划状态 |
| cancel_plan | 取消当前会话中未完成的计划 |
| ask_clarification | 目标无法唯一确定时向用户提问 |

关键约束：

- 没有通用的“直接执行写能力”工具。
- 没有批准、编辑计划、修改审批状态的工具。
- 没有 shell、文件、命令、原始 SQL 工具。
- `propose_plan` 本身只创建计划，不执行任何业务写操作。
- 计划步骤只能引用能力目录中的 `mcp` 或 `rest` 能力；`api_request` 只允许未登记只读长尾与白名单写入，计划卡必须标记为“原始 REST 调用”。

### 6.2 意图分析

助手按以下顺序工作：

1. 读取当前 scope 摘要。
2. 读取与请求相关的业务上下文，例如小说章节、项目分集、最后一集剧本、时间线尾部。
3. 检索能力目录，确认可用工具和参数。
4. 形成计划，写明标题、目标、假设、步骤、依赖、风险和估算。
5. 提交计划，等待用户批准。

对“续接片尾”这类开放表达：

- 不预置固定场景菜单，由模型根据当前页面和项目状态判断。
- 在剧集/项目页，默认理解为从最后一集结尾续写下一集，并按需要继续分镜、视频、合并。
- 在剪辑页，默认理解为在时间线尾部追加续接镜头并重新合并。
- 计划卡必须写明“我理解为……”，用户可以改目标、改关键参数、禁用步骤或拒绝后让助手重做。
- 只有目标无法唯一确定（例如同名小说、找不到项目、没有任何分集）时才先追问。

### 6.3 模型路由

按任务类型自动选择，不修改用户已选的生产模型：

| 任务 | 默认选择 | 回退 |
|---|---|---|
| 意图分析、能力选择、计划编排 | 助手设置中的规划模型；未配置时用当前活动文本模型 | 配置缺失、被禁用或不支持工具调用时回退到活动文本模型，并在诊断中提示 |
| 简短总结、回执、标题生成 | 助手设置中的快速模型；未配置时用活动文本模型 | 同上 |
| 计划执行 | 不调用助手模型；执行器确定性运行 | 不适用 |
| 生产 Agent 步骤 | 沿用该生产 Agent 自己的模型配置 | 沿用现有逻辑 |

设置页新增“智能体模型”区域：

- 规划模型：默认“跟随当前文本模型”。
- 快速模型：默认“跟随当前文本模型”。
- 只读取 `aiServiceConfigs`，不修改 `isActive`、优先级或用户已选 provider。
- 显示当前路由结果和不支持工具调用时的回退原因。

助手设置复用现有 `app_settings` 键值表，不新增表：

| 键 | 说明 |
|---|---|
| agent.planning_config_id | 规划模型配置 ID；空表示跟随当前文本模型 |
| agent.quick_config_id | 快速模型配置 ID；空表示跟随当前文本模型 |
| agent.planning_supports_tools | 可选，显式声明规划模型是否支持工具调用 |

设置页通过 `GET/PUT /api/v1/assistant/settings` 读写。规划模型的选择顺序：

1. 配置中存在 `agent.planning_supports_tools` 时，以显式声明为准。
2. 未声明时，按 provider/model 工具调用能力表判断。
3. 仍无法确认时，回退到当前活动文本模型，并在诊断中提示“规划模型未确认支持工具调用”。

`aiServiceConfigs` 当前没有工具调用能力字段；首版不修改生产配置结构，使用内置能力表加可选显式声明。检测失败只影响助手规划，不修改用户已选的生产模型/provider。

### 6.4 会话与工作区

| 项目 | 规则 |
|---|---|
| workspace_key | home、novel-library、novel:<id>、drama:<id>、episode:<id>、edit:<id> |
| 活动会话 | 同一 workspace 同时只有一个 active 会话；新对话归档旧会话 |
| 历史 | 保留归档会话，可查看、删除 |
| scope | 服务端校验资源存在、归属和 focus 字段 |
| 跨范围 | 默认当前 scope；用户点名其他资源时，计划卡展示目标资源并重新校验归属 |

会话不随页面切换重置；同一 workspace 的对话在页面间保持。跨页面操作不改变用户当前打开的页面，只改变计划目标。

## 7. 计划协议

### 7.1 计划结构

| 字段 | 说明 |
|---|---|
| title | 计划标题，例如“为《XX》生成第二章” |
| assumptions | 对模糊需求的解释，必须展示在计划卡顶部 |
| target | 目标资源摘要：小说、项目、分集、时间线等 |
| steps | 有序步骤列表 |
| riskSummary | 高风险步骤汇总 |
| estimate | 预计成本与规模 |
| resourceKeys | 计划涉及的写资源 |
| fileSlots | 计划需要的安全文件槽：槽位 ID、标签、类型、MIME、大小上限、是否必填；不包含字节、路径或文件名 |
| planHash | 规范化后的参数哈希，用于审批绑定 |

### 7.2 步骤结构

| 字段 | 说明 |
|---|---|
| seq | 顺序号 |
| type | tool、system、foreach；tool 调用 MCP 工具或命名 REST 能力，system 生成汇总/回执，foreach 展开集合 |
| source | mcp 或 rest；type=tool 或 foreach 子步骤时必填 |
| capability_key | 能力键；MCP 工具名为键，REST 为命名能力键（如 `edit.append_frames`） |
| method | source=rest 时的 HTTP 方法，由能力元数据固定，模型不可改写 |
| pathTemplate | source=rest 时的路径模板，由能力元数据固定，模型不可改写 |
| args | 原始参数，可包含变量引用；REST 能力按 pathParamsSchema 与请求体 Schema 拆分校验 |
| fileSlotRefs | 步骤参数引用的安全文件槽 ID；执行器在运行时把槽位内容注入目标工具字段 |
| systemAction | type=system 时的动作：summarize、receipt |
| reason | 为什么需要这一步 |
| risk | 继承能力元数据，可在计划中显式提升 |
| optional | 是否允许用户在批准前禁用 |
| editableFields | 允许在计划卡中编辑的字段 |
| dependsOn | 依赖的前序步骤 |
| foreach | type=foreach 时的集合来源、元素变量和子步骤模板 |
| concurrency | foreach 或批量步骤的并发度；不设全局上限，实际仍受现有队列控制 |
| outputs | 需要保留给后续步骤的结果字段投影 |
| jobKind | 异步作业类型 |
| idempotencyKey | 幂等键 |

### 7.3 变量与集合

支持三类引用：

- 上下文引用：当前 scope 的小说、项目、分集 ID。
- 步骤结果引用：前序步骤结果中的字段。
- 集合项引用：foreach 当前项的字段。

用途示例：

- 读取分镜列表后，对每个分镜启动一个视频生成步骤。
- 读取小说章节后，把新章节号传给生成步骤。
- 读取最后一集后，把新集号传给创建分集步骤。

执行器在计划校验阶段尽量解析引用；无法解析的引用在计划卡中标记为“运行时解析”，并在执行前再次校验。

### 7.4 校验流水线

计划提交后、展示前必须完成：

1. 能力存在且 agentVisible（MCP 工具或命名 REST 能力）；type=system 的步骤不校验能力，但 systemAction 必须在白名单内。
2. 参数符合 JSON Schema。
3. 目标资源存在且属于当前 scope 或用户明确指定的跨范围目标。
4. 依赖顺序合法，无循环。
5. 引用的前序输出字段在 steps.outputs 中声明。
6. 资源键可提取，写操作能加锁。
7. 风险等级可计算；成本估算允许为“未知”，但必须标记。
8. 不包含助手自身计划接口的调用。
9. 不包含明文密钥字段；需要密钥的步骤必须标记为安全输入。
10. 计划哈希可生成。
11. 能力来源合法：source=mcp 的工具存在且 agentVisible；source=rest 的方法 + 路径模板在命名能力清单内。
12. 按 HTTP 方法分级风险：`api_request` 的 GET 为 read，非 GET 为 write、destructive 或 system；只读上下文不得执行非 GET。
13. 服务端重查目标并动态提升风险：目标已存在、将被覆盖或替换时，风险至少提升为 destructive；设置、提示词、技能、MCP 配置提升为 system；生成类保持 expensive。
14. 二进制、路径与超大载荷：计划参数、消息、审计不得保存 base64、二进制、本地路径或文件名；含文件参数的步骤必须引用 `fileSlots`；上传类工具不接受模型提供的 base64；路径字段只允许存储根内的既有文件；单文件大小沿用现有上传限制。
15. 读取结果投影：read 能力必须声明输出字段或截断上限，避免整章、整表或全部分镜进入模型上下文。

任何一项失败，计划不展示为可批准状态；计划卡显示失败原因和修复建议。

### 7.5 计划编辑

批准前允许：

- 编辑能力元数据声明的关键参数：章节号、集数、数量、时长、分辨率、模型配置、覆盖开关、短文本提示词等。
- 通过资源选择器更换目标小说、项目、分集，服务端重新校验归属。
- 禁用 optional 步骤；禁用后重新校验依赖，依赖它的后续步骤必须自动禁用或标红。
- 查看每一步的 before/after、删除对象、设置旧值/新值、预计成本。

不允许：

- 直接编辑完整 JSON。
- 添加目录外工具。
- 编辑步骤结果引用之外的任意内容。
- 编辑后绕过重新校验。

任何编辑都会：

1. 重新校验。
2. 重新计算风险和估算。
3. 重新生成计划哈希。
4. 使已有批准失效。
5. 在审计中记录“用户编辑”。

### 7.6 审批

- 一个计划一次批准，批准覆盖全部启用步骤。
- 含高风险步骤时，必须勾选“我已确认高风险操作”。
- 审批绑定：`plan_hash + session_id + 过期时间`。
- 批准有效期从批准时刻起默认 24 小时；执行必须在有效期内开始。计划在 queued 等锁期间超过有效期时转为 expired，必须重新批准，不得静默执行；已开始的运行不受后续过期影响。
- 计划一旦批准，步骤参数不可修改；要改只能取消后重新提计划。
- 批准请求可携带 `secure_files`（槽位 ID → 文件字节），字节只在内存；缺失必填文件时拒绝批准；文件不写入计划、消息、事件或审计。
- 批准后、执行开始前，允许通过计划级安全输入替换接口更新 `secure_inputs` 与 `secure_files`（只改内存，不改变 `plan_hash`）；执行开始后锁定，审计只记录槽位、MIME、大小与内容哈希。
- 批准只能通过本机 UI 的批准接口完成。批准接口必须校验来源：桌面/本机回环请求，或服务端模式下显式配置的本地批准令牌；局域网客户端不得直接批准。
- 执行面禁止调用 `/api/v1/assistant` 下的写路径，模型无法自批。
- 外部 MCP 的 `api_request` 也禁止访问 `/api/v1/assistant`。
- `list_api_endpoints` 必须隐藏 `/api/v1/assistant` 和 `/api/v1/mcp`。

### 7.7 执行状态机

计划状态：

`draft → awaiting_approval → queued → running → completed`

异常与终态：

- `awaiting_approval → rejected`（用户拒绝）
- `awaiting_approval/queued → expired`（批准过期）
- `running → paused_error`（步骤失败）
- `paused_error → running`（重试或跳过后继续）
- `queued/running/paused_error → cancelled`（用户取消）
- `running → interrupted`（重启或进程中断）
- `interrupted → running`（恢复执行）

用户操作：

- 失败后：重试当前步骤、跳过当前步骤、取消计划。
- 中断后：恢复执行、取消计划。
- 资源等待：保持 queued，可取消；不设业务超时；批准在排队期间过期时转 expired。

步骤状态：

`pending → ready → running → succeeded`

异常分支：

`running → failed`

`pending/ready → skipped`

`running → cancelled`

`running → interrupted`

`failed → running`（重试）

`failed → skipped`（跳过）

执行器规则：

- 顺序执行；foreach 按步骤声明的并发度提交，实际并发仍受现有队列控制；不设全局并发上限。
- 每个写步骤执行前获取资源锁。
- 异步步骤启动作业后立即释放对话，不占回合；执行器在后台轮询。
- 每一步完成都写审计并推送事件。
- 成功路径不暂停。
- 失败路径暂停，不自动重试。

### 7.8 异步作业桥

作业桥统一识别以下作业：

| 作业类型 | 来源 | 状态查询 | 取消 |
|---|---|---|---|
| 小说作业 | novel_jobs | 现有小说作业查询 | 现有取消接口 |
| 视频/图片任务 | sys_task | 现有任务查询 | 能取消则取消，不能取消则停止跟踪并保留产物 |
| 整集自动化 | 分集自动化运行 | 现有自动化状态 | 现有停止接口 |
| 分镜拆分 | storyboard_split_jobs | 现有拆分作业查询 | 现有取消/停止能力 |
| 合并/导出 | 现有作业路由 | 现有状态查询 | 能取消则取消 |
| 音频/配音 | 现有音频作业 | 现有状态查询 | 能取消则取消 |

作业桥对外返回统一结构：作业类型、作业 ID、状态、进度、阶段、错误、结果摘要、可取消性。

混音试听保持同步（设置超时上限）；整集混音渲染按异步作业处理，任务卡显示作业类型、进度与可取消性。

### 7.9 幂等与重试

- 每个步骤生成幂等键。
- 异步步骤重试前先查询是否已有同一幂等键的作业：
  - 仍在运行：附着到原作业，不重复启动。
  - 已成功：直接标记成功。
  - 已失败：允许用户确认后以新尝试键重新启动。
- 同步写步骤失败后不自动重试；用户选择重试时先检查目标当前状态，避免重复写入。
- 删除、覆盖类步骤一旦成功，不允许自动重试。

### 7.10 取消与重启恢复

取消：

- 计划标记 cancel_requested。
- 当前步骤是异步作业时调用作业取消；不支持取消的作业停止跟踪，但保留产物。
- 执行器不再启动后续步骤。
- 已完成步骤保留，不自动回滚。

重启恢复：

- 启动时把 running/queued 计划标记为 interrupted。
- 对每个已启动作业查询真实状态：
  - 运行中：自动恢复轮询，计划回到 running。
  - 已成功：标记成功，继续后续步骤。
  - 已失败：计划进入 paused_error。
  - 查不到：计划进入 paused_error，等待用户处理。
- 没有关联作业的计划保持 interrupted，等待用户点击恢复。
- 流式消息标记 interrupted，前端显示可重试，不永久停在“思考中”。
- 清理过期的资源锁。

## 8. 前端体验

### 8.1 全局 Dock

- 所有业务页面右下角提供浮动入口。
- 面板宽度 360–520，可拖拽调整。
- 顶部显示当前页面和 scope，可新建对话、查看历史。
- 消息流支持文本、计划卡、任务卡、系统回执。
- Markdown 使用安全白名单渲染，不使用 v-html，只允许 HTTP(S) 链接。
- 断线重连后按事件 ID 恢复；无法恢复时标记中断，不无限转圈。

### 8.2 计划卡

计划卡是唯一批准入口，包含：

- 标题和假设。
- 目标资源。
- 步骤列表：能力（MCP 工具或命名 REST）、目的、风险、状态、是否可编辑、是否可禁用。
- 高风险汇总：删除对象、覆盖对象、设置旧值/新值、预计镜头数/时长/模型。
- 成本估算：已知则显示，未知则显示“未知”。
- 关键参数编辑区。
- 高危确认勾选框。
- 批准、拒绝、让助手调整。

批准后：

- 卡片切换为执行视图。
- 每步显示状态、耗时、结果摘要。
- 异步步骤显示任务卡入口。
- 失败步骤显示重试、跳过、取消。
- 中断计划显示恢复、取消。

### 8.3 任务卡

- 显示作业类型、目标、阶段、进度、预计剩余时间（可知时）。
- 支持取消；不可取消时说明原因。
- 支持跳转到对应页面查看产物。
- 完成后变为回执，保留在消息流中。

### 8.4 审计抽屉

- 从计划卡打开。
- 显示每一步的方法、路径/工具、脱敏参数、结果摘要、耗时、审批、作业 ID。
- 设置、提示词、技能类步骤显示旧值快照和回滚入口。
- 删除类步骤显示删除对象快照和是否可恢复。

### 8.5 页面适配器

| 页面 | workspace_key | 快捷指令示例 |
|---|---|---|
| 首页 | home | 新建小说、新建项目、查看正在执行的任务 |
| 小说库 | novel-library | 新建小说、导入小说、继续未完成章节 |
| 小说详情 | novel:<id> | 写下一章、续写结尾、检查设定一致性 |
| 项目详情 | drama:<id> | 新建分集、续写下一集、查看资产 |
| 分集 | episode:<id> | 全流程制作、续接下一集、重生成失败镜头 |
| 剪辑 | edit:<id> | 续接片尾、重新合并、检查时间线 |

快捷指令只是提示，不限制模型能力。页面适配器只提供 scope、快捷指令和刷新钩子，不持有消息流。

首版不提供导演入口；未来接入时使用同一运行时，但只挂载只读能力，不提供 propose_plan，只输出评审意见和只读检查结果。

## 11. 安全、审计与回滚

### 11.1 批准隔离

- 模型只能提交计划，不能批准、编辑计划或修改审批状态；取消只允许通过 cancel_plan 工具取消本会话未完成计划，不能操作其他会话的计划。
- 执行面禁止调用 `/api/v1/assistant` 下的写路径；cancel_plan 通过运行时内部服务执行，不走 api_request。
- 外部 MCP 的 `api_request` 同样禁止该路径。
- 批准接口只接受本机 UI 请求，不接受 MCP 调用；校验回环地址、Origin/Host，服务端模式下使用显式本地批准令牌，局域网请求拒绝。
- 高风险设置、删除、MCP 自身配置通过命名 REST 能力执行，审计记录能力键、方法、路径模板和脱敏参数；禁止用 `api_request` 绕过。
- 计划哈希绑定参数；任何编辑使旧批准失效。

### 11.2 密钥

- 读取设置、MCP 状态、AI 配置时，`api_key`、`token`、`secret`、`password`、`authorization` 等字段统一脱敏。
- 模型上下文中不出现明文密钥。
- 需要新密钥的步骤在计划卡中使用密码输入或“服务端生成”：
  - 密码输入的值直接提交给批准/执行接口，不进入模型上下文。
  - MCP Token 可服务端重新生成，模型只看到“已生成”，新 Token 在设置页查看。
  - MCP Token 也支持在计划卡安全输入新值；输入值不进入模型上下文，执行后不回显。
- 安全输入的值只保存在本次执行的内存中，不写入计划、消息或审计；目标设置本身除外。重启后需要重新输入。
- 文件输入与密钥同等对待：计划卡文件选择器只把字节保存在内存，批准/执行请求使用 `secure_files`；不写入计划、消息、事件或审计。
- 上传类工具（`upload_image`、`upload_video`、`upload_audio`）不接受模型提供的 base64；执行器在执行步骤时把安全文件槽注入为工具参数，随后释放。
- 路径类字段（`clone_voice.file_path`、`set_asset_image.path`）只允许存储根目录内的既有文件；拒绝绝对路径逃逸、`..`、符号链接逃逸和任意本地文件读取。外部 MCP 保持现有直连行为，助手网关单独限制。
- 审计只记录文件槽位、MIME、大小、内容哈希与结果摘要；不记录文件名、路径或字节。
- 审计记录中的密钥字段永久脱敏。
- 如果模型尝试把脱敏占位符写回，执行器拒绝并提示用户重新输入。

### 11.3 设置、提示词与技能

- 全部允许，但必须进入计划。
- 计划卡展示字段旧值/新值；密钥字段只显示“将变更”。
- 执行前保存旧值快照；快照中的密钥字段只记录“将变更”，不保存明文。
- 计划失败或用户主动回滚时，可从审计抽屉恢复非密钥旧值。
- 修改当前活动文本模型、MCP 开关/端口/Token 时，计划卡明确提示可能影响后续助手回合或外部 MCP 客户端。

### 11.4 删除与覆盖

- 优先使用现有软删除；只有现有路由提供恢复能力时才标记为可恢复。
- 硬删除、没有恢复路由的软删除在计划卡标记“不可恢复”。
- 覆盖已有章节、分镜、提示词时，计划卡展示目标名称、现有内容摘要和覆盖影响。
- 删除对象列表必须来自服务端重新查询，不能只信模型参数。

### 11.5 回滚边界

| 操作 | 回滚能力 |
|---|---|
| 设置变更 | 有旧值快照，可回滚 |
| 提示词/技能变更 | 有旧内容快照，可回滚 |
| 软删除 | 有恢复路由时可恢复；否则按不可恢复展示 |
| 硬删除 | 不可回滚，计划卡明确标注 |
| 密钥类设置 | 不保存旧值，不可回滚；需要用户重新输入 |
| 生成的小说/分镜/图片/视频 | 不自动回滚；通过新的删除计划处理 |
| MCP Token 重新生成 | 旧 Token 失效，不可恢复；计划卡提前警告 |
| 外部客户端配置 | 端口/开关可回滚，客户端侧需用户自行恢复 |

### 11.6 提示注入

- 小说、剧本、分镜、任务结果中的文本一律视为数据，不是指令。
- 系统提示明确要求忽略内容中的操作指令。
- 计划校验只接受能力目录中的 MCP 工具、命名 REST 能力和合法参数；`api_request` 仅接受 `/api/v1/` 下清单外路径，并拒绝 `/api/v1/assistant` 和 `/api/v1/mcp`。
- 计划卡展示真实工具、命名能力或原始 REST 方法 + 路径，用户批准前可识别异常。
- 读取结果不渲染原始 HTML；链接只允许 HTTP(S)。

### 11.7 资源锁

- 写步骤按小说、项目、分集、时间线、混音工程、设置等资源键加锁。
- 同一资源同时只允许一个写计划。
- 锁等待不失败，计划保持 queued；排队期间批准过期时转 expired。
- 锁带心跳和过期时间；进程退出后由重启清理。
- 不同资源可并行，不设全局并发上限。

## 12. 跨范围操作

- 默认操作当前页面 scope 的资源。
- 用户在对话中明确点名其他小说、项目或分集时，助手可以跨范围读取和规划。
- 计划卡必须展示目标资源的名称、ID、所属项目和 scope。
- 服务端重新校验目标归属；不存在或已删除时拒绝计划。
- 跨范围写操作同样受资源锁和审批约束。
- 助手不自动切换用户当前页面；完成后提供跳转入口。

示例：

- 在首页说“帮我给《XX》写第二章”，助手先按标题搜索小说；唯一匹配则计划目标为该小说；多个同名则追问。
- 在剧集页说“续接片尾”，默认目标是当前项目最后一集；如果用户说“续接另一个项目的片尾”，计划卡展示另一个项目名称并要求确认。

## 15. 示例计划

以下示例只说明计划形态，不是固定场景菜单；实际步骤由助手根据能力目录和上下文生成。

### 15.1 “帮我新建《XX》第二章”

可能的计划：

1. 按标题读取小说，确认唯一目标。
2. 读取现有章节、大纲和上一章结尾。
3. 生成第二章。
4. 补全章节。
5. 定稿第二章。
6. 汇总字数、状态和跳转入口。

计划卡展示：

- 假设：目标小说为《XX》，第二章不存在或将被覆盖。
- 高风险：生成模型调用、可能的覆盖。
- 可编辑：章节号、是否覆盖、是否补全、是否定稿。
- 可禁用：补全、定稿。
- 能力映射：读取用 `get_novel` / `list_novel_jobs`；生成、补全、定稿用 `generate_novel_chapter` / `enrich_novel_chapter` / `finalize_novel_chapter`；保存正文用 MCP 工具 `save_novel_chapter`。目标章节已存在时，服务端把该步风险提升为 destructive，强制高危确认。

### 15.2 “帮我续接一下片尾”

剧集/项目页的可能计划：

1. 读取项目分集和最后一集剧本/分镜。
2. 创建下一集。
3. 生成下一集剧本。
4. 拆分分镜。
5. 对每个分镜生成视频。
6. 合并本集。
7. 汇总产物。

计划卡展示：

- 假设：我理解为从第 N 集结尾续写第 N+1 集，并完成到成片。
- 高风险：生成视频、合并、成本未知或按镜头数估算。
- 可编辑：集数、分镜数量、视频模型、是否合并。
- 可禁用：视频生成、合并；只保留剧本时可直接禁用后续步骤。

剪辑页的可能计划：

1. 读取时间线尾部镜头和最后一帧。
2. 生成续接镜头。
3. 追加到时间线尾部。
4. 重新合并。
5. 汇总产物。

计划卡展示：

- 假设：我理解为在现有成片片尾追加续接镜头，而不是新建一集。
- 高风险：生成视频、覆盖现有导出。
- 可编辑：续接镜头数、时长、是否覆盖导出。
- 可禁用：重新合并。
- 能力映射：时间线读取用 `edit.timeline_read`，追加用 `edit.append_frames`，重新渲染用 `edit.render`；都走命名 REST 能力，模型不能拼接任意路径。

### 15.3 “把设置里的视频并发改成 2，然后继续”

可能的计划：

1. 读取当前设置。
2. 修改视频并发为 2。
3. 汇总变更。

计划卡展示：

- 旧值/新值：并发 1 → 2。
- 风险：system，可能影响正在排队的视频任务。
- 可回滚：是。
- 能力映射：读取用 `jobs.settings_get`，修改用 `jobs.settings_update`；走命名 REST 能力，服务端在执行前重读旧值并写入计划哈希，避免用过期值覆盖。

### 15.4 “用这张参考图给角色换图”

可能的计划：

1. 读取当前项目与角色，确认唯一目标。
2. 计划卡请求一张参考图文件槽（image，大小上限沿用现有上传限制）。
3. 上传图片到项目存储。
4. 设为角色图。
5. 可选生成角色定妆图。
6. 汇总结果与资源跳转。

计划卡展示：

- 文件槽：1 个必填图片；批准前必须选择；不显示文件名、路径或字节。
- 高风险：生成定妆图为 expensive；可禁用。
- 能力映射：上传用 `upload_image` 的安全文件槽，设定用 `set_asset_image` 的安全文件槽或存储根路径，生成用 `character.image_generate`；模型不接触文件字节、base64 或绝对路径。

## 16. 风险与取舍

| 风险 | 影响 | 应对 |
|---|---|---|
| 全开放 + 无成本上限 | 误指令可能产生高额生成费用 | 计划卡展示估算和全部步骤；批准前可禁用步骤；执行中可取消；审计可追溯；验收使用一次性数据，日常使用依靠计划卡与取消控制 |
| 全自动 + 无检查点 | 中间产物不可预审 | 计划卡是唯一把关点；关键参数可编辑；步骤可禁用；失败暂停；设置和提示词有快照回滚 |
| 模型规划不可靠 | 工具选错、参数错、步骤顺序错 | 能力目录、Schema 校验、目标重查、依赖校验、计划卡人工审阅、失败暂停 |
| 从 main 重写助手层 | 工作量大于移植 | 只复用 MCP、作业、路由和 AI 配置；不重写业务；首版不做导演页和 mix/delivery 适配 |
| SQLite 并发 | 多计划同时写可能锁库 | 单进程、WAL、资源级互斥、短事务；不设全局并发上限但避免同资源并发写 |
| 模型路由复杂 | 选错模型导致工具调用失败 | 默认跟随活动文本模型；规划模型必须支持工具调用；失败回退并提示 |
| 命名 REST 能力漂移 | 路由改名、参数变化后能力清单失效 | 能力注册表与路由契约测试同步：每个命名能力断言路由存在、方法匹配、Schema 可解析；路由变更导致测试失败 |
| api_request 绕过治理 | 非 GET 请求绕过命名能力或方法分级 | `read_capability` 只读；高危设置/删除/MCP 必须走命名能力；`api_request` 仅作长尾兜底并在计划卡标注；拒绝 `/api/v1/assistant` 与 `/api/v1/mcp` |
| 本地批准接口被远程调用 | 非本机请求伪造批准 | 批准接口校验 loopback、Origin/Host；服务器模式要求本地令牌；批准记录来源地址 |
| 模型工具能力误判 | 配置的模型不支持工具调用，规划直接失败 | 能力表 + 显式开关 + 规划前自检；失败时回退到活动文本模型并提示，不改用户配置 |
| 大对象进入计划或审计 | base64/二进制撑爆上下文与数据库 | 计划、消息、审计禁止二进制；上传走文件引用或安全输入；读取结果投影并截断 |
| 外部 MCP 被自身配置改坏 | 外部客户端断开 | 计划卡提前警告；内部助手不走 5780 端口，不受影响；端口/开关可回滚 |
| 没有 CI | 回归发现晚 | 本地测试清单、隔离数据库、前端 generate、浏览器走查、真实验收 |

## 17. 不做的事

- 不做固定场景菜单；意图由智能体分析，计划由能力目录组合。
- 不做“模型直接写库”。
- 不做模型自批。
- 不做明文密钥回显。
- 不挂载 shell、文件系统、命令执行或原始 SQL。
- 不允许模型拼接任意 REST 路径；只能使用命名能力清单，或经严格白名单校验的 `api_request` 兜底。
- 不允许模型提供 base64 或任意本地路径；文件只通过计划卡安全输入，路径字段只引用存储根内的既有文件。
- 内部助手不允许用 `api_request` 执行未登记的非 GET 写；外部 MCP 的既有直连语义不受内部白名单影响。
- 不在计划、消息或审计中存储、传输二进制与 base64 大对象；上传只接受文件引用或安全输入。
- 外部 MCP 不能访问 `/api/v1/assistant`，也不能用 `api_request` 修改 MCP 自身配置。
- 不改变外部 MCP 的直接调用语义。
- 首版不做导演入口和独立导演页。
- 首版不做 mix/delivery 页面适配；页面出现后通过适配器扩展。
- 不设业务成本/并发上限；只保留计划估算、审计、取消、失败暂停和资源锁等技术保护。
- 不把 rebrand 分支的助手代码作为实现依赖。
