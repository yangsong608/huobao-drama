# 分镜拆分方案与视频任务管理落地方案

- 日期：2026-11-09
- 范围：视频制作页的多种分镜拆分方式、设置页方案管理、左侧视频任务列表新增/删除
- 状态：设计待复核

## 1. 背景与目标

当前视频制作页只有一套固定的分镜拆分规则：系统提示词、`storyboard-breaker` Skill 与 `storyboards` 任务规则共同决定拆分结果。用户无法按项目或剧集选择不同的创作方法，也无法在设置页管理这些方法。

本方案要达成三件事：

1. 在**不改变现有输入输出契约**的前提下，增加多种分镜拆分方式；每种方式由「提示词 + Skill」两部分文本组成。
2. 在设置页提供拆分方式的增删改查，并内置从 GitHub 调研得到的优秀拆分方法。
3. 左侧视频任务列表支持新增镜头与删除镜头，并正确处理关联台词、转场与整集时长。

## 2. 现状与约束

### 2.1 现有拆分链路

- 前端 `doBreakdown` 在 `frontend/app/views/drama/episode.vue` 第 4164 行组织角色/场景/道具清单，渲染 `storyboards` 任务规则后调用 `storyboard_breaker` Agent。
- Agent 的系统提示词来自 `backend/workspace/prompts/storyboard_breaker.md`，Skill 来自 `backend/workspace/skills/storyboard-breaker/SKILL.md`。
- `backend/src/agents/index.ts` 第 376 行的 `buildInstructions` 把「系统提示词 + Agent 专属 Skill 全文 + 语言指令」拼成最终 instructions，每次生成时按 `RequestContext` 求值。
- `backend/src/agents/skills.ts` 第 122 行的 `loadAgentSkills` 会注入 `AGENT_SKILL_MAP` 前缀下的**所有** SKILL.md；第 39 行显示 `storyboard_breaker` 对应 `storyboard-breaker`，其子目录也会被全部加载。
- 全自动流程 `backend/src/services/automation.ts` 第 460 行的 `stepStoryboards` 直接调用同一个 Agent，不经过前端。

### 2.2 现有分镜数据与接口

- `backend/src/routes/storyboards.ts` 已有 `POST /storyboards`、`PUT /storyboards/:id`、`DELETE /storyboards/:id`。
- 删除逻辑当前会软删该分镜关联台词、删除角色/道具关联、硬删分镜行；但**不清理**引用该分镜的 `video_transitions`，也**不重算**整集时长。
- `backend/src/agents/tools/storyboard-tools.ts` 第 352 行按「全部存活分镜时长之和」更新剧集时长；删除接口需要复用同一口径。
- `frontend/app/composables/useApi.ts` 第 58 行已有 `episodeAPI.update`，第 169 行已有未被使用的 `storyboardAPI.create/del`。

### 2.3 现有设置页结构

- `frontend/app/pages/settings.vue` 第 1769 行定义设置 Tab：ai、dubbing、novel、general、styles、rules、agents、queue、storage、mcp、about。
- 「规则」Tab 管理 `storyboards` 等任务规则，存于 `app_settings`（`backend/src/services/pipeline-rules.ts`）。
- 「智能体」Tab 已有一套 Skill 文件编辑能力，但它是按 Agent 维度管理原始 SKILL.md，不适合承载「多个互斥拆分方案」。

### 2.4 关键约束

- 桌面版 workspace 为 copy-once，skills 只增不覆盖（`desktop/src/main.ts` 第 162 行）。因此不能把多个拆分方案放进 `storyboard-breaker/` 子目录。
- 全部既有生成链路必须继续可用：手动拆分、全自动流程、单镜视频提示词补生成、ComfyUI 时间轴。
- 现有项目数据升级不能丢；新增字段必须可空，新增表必须幂等创建。
- 界面文案需覆盖 zh、en、ja、ko 四种语言。

## 3. 方案对比与选择

| 方案 | 存储 | 优点 | 缺点 |
|---|---|---|---|
| A. 数据库方案 | `breakdown_methods` 表 | 事务化 CRUD；内置播种与恢复默认可靠；按集引用简单；自动流程与前端共用同一份选择 | 方案文本不存放在 workspace 文件系统中 |
| B. 文件方案 | `workspace/breakdown-methods/<id>/` | 是真正的 Agent Skill 文件，可在应用外编辑 | copy-once 升级、内置重置、删除保护都更复杂；设置页需另做文件扫描与校验 |
| C. 复用现有 Skill 目录 | `skills/storyboard-breaker/<方案>/` | 新概念最少 | 所有子目录会被同时注入，必须改注入器；命名约定脆弱；与原始 Skill 编辑混在一起 |

**选择 A。** 决定性理由是自动流程：`stepStoryboards` 由后端直接调用 Agent。如果方案只存在于前端请求参数里，全自动流程就无法采用同一方案。方案按集存库后，前端手动拆分与自动流程都从同一个字段读取，行为一致。

## 4. 总体设计

### 4.1 三层职责

| 层 | 位置 | 回答的问题 | 是否由本方案改动 |
|---|---|---|---|
| 系统提示词 | `workspace/prompts/storyboard_breaker.md` | Agent 是谁、有哪些硬约束 | 不改 |
| 任务规则 | 设置页「规则」→ `storyboards` | 这一次要做什么、素材如何绑定 | 不改 |
| 拆分方案 | 设置页「分镜拆分」→ 本方案新增 | 按什么创作方法拆：节拍、时长、镜头语言 | 新增 |

拆分方案是任务规则的补充层，不替代工具契约。工具调用方式、字段名、ID 来源、分批保存规则始终以系统能力为准。

### 4.2 数据模型

新增表 `breakdown_methods`：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | 自增主键 | 内部标识 |
| key | 文本，唯一 | 方案稳定标识；内置方案固定，自定义方案由后端生成，创建后不可改 |
| name | 文本 | 展示名称 |
| description | 文本 | 一句话说明与适用场景 |
| prompt | 文本 | 方案提示词 |
| skill | 文本 | 方案 Skill 正文 |
| builtin | 整数 | 1 表示内置方案 |
| sort_order | 整数 | 设置页排序 |
| created_at / updated_at | 文本 | 时间戳 |

`episodes` 增加可空文本字段 `breakdown_method`，存方案 key：

- 新建剧集默认空值，等同于 `standard`。
- 空值表示使用 `standard`。
- 保存的是 key 而非外键，允许自定义方案删除后仍能降级，不产生数据库约束错误。
- 该字段随剧集列表接口返回，前端无需额外请求。
- 设置页「使用中剧集数」只统计未删除剧集。

### 4.3 内置方案播种与恢复

- 后端维护内置方案常量，启动时幂等补齐缺失 key，**不覆盖**已有行，保留用户编辑。
- 内置方案 key 固定，按 `sort_order` 排在自定义方案之前。
- 「恢复默认」按 key 把名称、说明、提示词、Skill 写回内置常量。
- `standard` 初始两段文本为空；用户编辑后同样会注入，并可通过恢复默认回到空文本。
- 内置方案不可删除；自定义方案可删除。
- 删除自定义方案时，把所有引用该 key 的剧集置空，回退到 `standard`。
- 集上的 key 找不到时按 `standard` 处理并记录告警，不阻断拆分。

### 4.4 注入链路

1. 用户在视频制作页选择方案，前端调用 `episodeAPI.update` 写入剧集字段，并同步本地剧集对象。
2. 前端不向 Agent 路由新增方案参数；`useAgent` 与 Agent 聊天接口保持不变。
3. `buildInstructions` 在构建 `storyboard_breaker` 指令时，用 `RequestContext` 中的 `episodeId` 查询本集方案。
4. 方案块只对 `storyboard_breaker` 生效，追加顺序为：系统提示词 → 基础 Skill → 方案块 → 声音引用指令 → 语言指令。追加内容包含方案名、方案提示词、方案 Skill，以及优先级声明：
   - 与基础规范冲突时，以当前方案为准；
   - 工具名、字段名、ID 来源、首批 `replace_existing`、每批上限与分批保存规则不可违背。
5. `standard` 或方案两段文本均为空时不追加任何内容，现有行为完全不变。
6. 全自动流程不额外传参，自动读取同一剧集字段，因此与手动拆分结果一致。

优先级声明必须放在方案块内部，且方案块位于基础规范之后。这样模型同时看到「8–15 秒」与「5–8 秒」时，后出现且明确声明覆盖的方案规则才会稳定生效。

### 4.5 设置页「分镜拆分」

在设置 Tab 中新增 `breakdown`，位置放在「规则」与「智能体」之间。

页面结构：

- 左侧：方案列表，显示名称、内置/自定义徽标、正在使用的剧集数。
- 右侧：编辑器，包含名称、说明、提示词、Skill 四个字段。
- 底部操作：保存、恢复默认（仅内置）、复制为新方案、删除（仅自定义）。
- 顶部操作：新增方案。
- 切换未保存内容时弹出确认。

交互约束：

- 新方案 key 由后端生成，用户只编辑名称与文本。
- 名称必填；提示词与 Skill 允许为空，但编辑器提示「两段都为空时等同标准方案」。
- 内置方案编辑后显示「已自定义」标记，「恢复默认」可撤销。
- 删除自定义方案时展示引用剧集数，确认后相关剧集回退标准方案。

### 4.6 视频制作页方案选择

- 在视频制作页顶部模式切换旁增加「拆分方式」下拉框。
- 下拉项来自方案列表接口，`standard` 默认选中。
- 切换时立即写库；成功后再允许重新拆分，失败则回滚本地选择并提示。
- Agent 运行中或拆分工时禁用下拉框，避免拆分过程中切换方案导致结果不确定。
- 空态与拆分按钮附近显示当前方案名，让用户在点击前知道将使用哪套规则。
- 剧集上的 key 已失效时，下拉框显示并回退到 `standard`，不出现空白选项。

### 4.7 左侧视频任务列表新增/删除

#### 新增镜头

- 列表头部增加「新增镜头」按钮；无分镜空态增加「手动新增一个镜头」次级入口。
- 新增位置固定为**列表末尾**，本轮不做插入到中间。
- 前端不传分镜号；后端在未提供分镜号时取当前集最大值加一，避免与既有分镜冲突。
- 默认值：
  - 标题为「新镜头 N」；
  - 场景、角色、道具继承当前选中镜头；没有选中时继承最后一个镜头；都没有则为空；
  - 时长取 10 秒与当前视频模型时长上限的较小值，避免本地 H3 720p 直接超过 8 秒上限；
  - 描述与氛围留空。
- 创建成功后刷新列表、选中新镜头并打开右侧检查器，光标落在描述编辑区。

#### 删除镜头

- 每行悬停或键盘聚焦时显示删除按钮，点击不触发行选中。
- 使用现有确认弹窗风格，文案明确：分镜、关联台词、相邻 AI 转场会被删除；已生成视频文件与任务历史保留。
- 后端删除补全：
  - 软删该分镜关联台词；
  - 不写台词墓碑，允许后续重新拆分时按剧本重建台词；
  - 删除角色/道具关联；
  - 删除所有以该分镜为起点或终点的 `video_transitions`；
  - 硬删分镜行；
  - 按「全部存活分镜时长之和」重算剧集时长。
- 素材库与 `sys_task` 历史记录保留，不自动修改其 `storyboard_id`；任务历史用于诊断，素材文件不随镜头删除。
- 删除当前选中镜头后，自动选中相邻镜头；删到空则回到空态。
- 不重排 `storyboard_number`：界面序号按位置显示，内部编号允许空洞；下次整体重拆时由 `replace_existing` 重写。

#### 重新拆分保护

已有分镜时再次点击拆分，先确认「将清空现有 N 个分镜及关联台词」。换方案试拆时避免误删。

### 4.8 内置方案内容

| key | 名称 | 核心规则 | 调研来源 |
|---|---|---|---|
| `standard` | 标准短剧段落 | 8–15 秒/段；2–4 个子镜头；节拍边界强制切段；目标总时长按剧本字数除以 500 字/分钟；语音容量每秒 4 字 | 现有系统规范 |
| `hook-beat` | 爆款钩子节拍 | 6–12 秒/段；每段结尾必须落在钩子上（悬念、反转、信息差、危险逼近）；开场 0–2 秒直接给冲突画面；2–3 个子镜头；台词密度高 | zenstory-ai/drama-skills 等短剧分镜 Skill |
| `hook-beat-extended` | 爆款钩子节拍·扩展版 | 在 hook-beat 基础上补齐开场第一拍、全片钩子节点（按目标总时长等比缩放）、A/B/C/D 机位覆盖、景别配比、台词容量与连戏自检；短于 60 秒的剧集自动合并钩子节点 | zenstory-ai/drama-skills、JC-manju-skills、OnlyShot 的公开方法整理 |
| `director-board` | 导演分镜表 | 5–10 秒/段；按 A 主镜、B 过肩、C 特写、D 环境四类机位组织覆盖；每个子镜头写清景别、角度、运镜；强调视线与轴线连续性 | JC-manju-skills 的导演式 A/B/C/D 方法 |
| `h3-compact` | H3 紧凑段 | 5–8 秒/段；1–3 个子镜头；单段台词不超过 24 字；以固定镜头与轻推为主；优先单场景单动作，适配本机 720p 8 秒上限 | TFboy1 的 H3 导演流程与本机模型能力 |
| `trailer-cut` | 快切预告 | 3–6 秒/段；1–2 个子镜头；动作切点优先；极少台词；强调冲击画面与信息密度 | infinite-creation 与 OnlyShot 的快切分镜思路 |

内置方案写成对基础规范的增量覆盖，不复制整套规范。`standard` 的两段文本为空，直接沿用现有提示词与 Skill。扩展版作为第六个内置方案预置，可编辑、可恢复默认，不可删除；需要可删除副本时使用「复制」。

## 5. 接口设计

### 5.1 方案管理

| 方法与路径 | 用途 | 关键约束 |
|---|---|---|
| GET `/breakdown-methods` | 列表 | 返回 key、名称、说明、内置标记、使用中剧集数 |
| GET `/breakdown-methods/:key` | 详情 | 返回完整提示词与 Skill |
| POST `/breakdown-methods` | 新增自定义方案 | 名称必填（1–60 字）；key 由后端生成（`custom-` 前缀）；新方案追加到排序末尾 |
| PUT `/breakdown-methods/:key` | 编辑 | key 不可改；名称 1–60 字；提示词与 Skill 分别限制 20000 / 40000 字；内置方案允许编辑 |
| DELETE `/breakdown-methods/:key` | 删除 | 内置方案拒绝；自定义方案删除后引用剧集置空 |
| POST `/breakdown-methods/:key/reset` | 恢复默认 | 仅内置方案 |
| POST `/breakdown-methods/:key/duplicate` | 复制 | 生成自定义副本，名称加「副本」 |

### 5.2 剧集选择

复用 `PUT /episodes/:id`，增加允许字段 `breakdown_method`：

- 传合法 key 或空值。
- 空值表示回退标准方案。
- 返回失败时前端回滚选择。

### 5.3 分镜新增与删除

复用现有路由：

- `POST /storyboards`：未传分镜号时自动取最大值加一；其余字段沿用现有校验与关联同步。
- `DELETE /storyboards/:id`：补齐转场清理与时长重算。

## 6. 错误处理与边界

| 场景 | 处理 |
|---|---|
| 方案列表接口失败 | 视频页只保留「标准」选项，不阻断手动新增镜头与删除 |
| 集上的方案 key 不存在 | 按标准方案执行并记录告警 |
| 方案文本为空 | 不追加方案块 |
| 自定义方案被删除 | 引用剧集回退标准；设置页展示影响范围 |
| 删除内置方案 | 后端拒绝，前端不显示删除按钮 |
| 新增镜头时剧集不存在 | 返回明确错误，不写半条数据 |
| 删除镜头时已存在生成视频 | 确认文案提示文件保留；不删除文件与任务历史 |
| 删除镜头时存在 AI 转场 | 一并删除转场记录，避免悬空引用 |
| 拆分过程中切换方案 | 下拉框禁用 |
| 未保存的编辑被切换 | 设置页拦截确认 |
| 本地模型时长上限低于方案时长 | 新增镜头按时长上限截断；拆分方案仍由用户在方案文本中自行约束，内置 H3 方案已按 8 秒设计 |

## 7. 测试与验收

### 7.1 后端自动化测试

- 内置方案播种：首次启动补齐 6 条；再次启动不覆盖用户编辑。
- CRUD：新增、编辑、复制、删除自定义方案；内置方案删除被拒绝；恢复默认还原内置文本。
- 引用回退：删除自定义方案后，引用剧集字段置空。
- 注入：`standard` 不追加；自定义方案追加顺序为「系统提示词 → 基础 Skill → 方案块 → 声音引用指令 → 语言指令」；方案块包含优先级声明。
- 自动流程：剧集字段被 `stepStoryboards` 读取，不依赖前端传参。
- 新增分镜：未传分镜号时自动编号；继承字段与时长截断正确。
- 删除分镜：台词软删、关联删除、转场清理、剧集时长重算。

### 7.2 前端结构测试

- 设置页存在 `breakdown` Tab，且 API 接线完整。
- 视频页存在方案下拉，切换时调用剧集更新接口。
- 列表存在新增与删除入口，删除前有确认。
- zh、en、ja、ko 四份语言文件包含新增 key。

### 7.3 浏览器验收

- 设置页：查看 6 条内置方案；新增自定义方案；编辑并保存；复制；恢复默认；删除自定义方案并确认引用剧集回退。
- 视频页：切换方案并确认剧集字段持久化；使用已配置文本模型真实拆分一集，检查生成数量、段落时长与方案规则一致。
- 任务列表：新增镜头后检查选中态、继承字段、时长上限；删除镜头后检查台词、转场、整集时长与空态。
- 未配置文本模型时，拆分执行记为阻塞，不以结构测试代替真实拆分结论。

- 前端结构测试通过。

## 8. 实施顺序

1. 数据层：新增表、剧集字段、迁移、内置常量与播种。
2. 服务层：方案查询、注入块、删除回退、恢复默认。
3. 路由层：方案 CRUD 与剧集字段更新；分镜新增自动编号、删除清理。
4. 设置页：新 Tab、列表、编辑器、四语言文案。
5. 视频页：方案下拉、重新拆分确认、新增/删除镜头。
6. 测试与验收：后端测试、前端结构测试、构建、浏览器走查与证据记录。

## 9. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 方案与基础规范冲突 | 模型摇摆，拆分结果不稳定 | 方案块后置并显式声明覆盖范围；内置方案作为增量文本维护；真实模型验证 |
| 方案时长超过模型上限 | 生成视频被接口拒绝 | 新增镜头按上限截断；H3 内置方案按 8 秒设计；拆分时用户消息仍携带视频模型信息 |
| 删除镜头造成转场悬空 | AI 过渡片段打不开或合片失败 | 删除时同步清理起止引用 |
| 自定义方案删除后剧集仍引用 | 拆分降级不可预期 | 删除时置空引用并在设置页提示影响范围 |
| 方案文本过长 | instructions 膨胀、成本上升 | 编辑器展示字数；内置方案保持增量体量；接口限制单段长度 |
| 全自动流程与手动拆分不一致 | 用户困惑 | 方案按集存库，两条链路读取同一字段 |

## 10. 明确不做

- 不做镜头拖拽排序、批量删除、插入到选中镜头之后。
- 不做项目级默认拆分方案，本轮按集选择。
- 不改独立「重新生成视频提示词」链路与 `video-prompt` Skill。
- 不改 ComfyUI 帧网格、参考图数量与时间轴数据格式。
- 不自动删除已生成视频文件、`sys_task` 历史与素材库记录。
- 不把拆分方案写入 workspace 的 skills 目录。
