# 分镜动作检验设计

- 日期：2026-11-10（2026-11-10 修订：检查 2 改为逐对 AI 判定，过渡分镜标记为真实分镜行并跳过复检）
- 范围：分镜拆分完成后的五项检验（四项动作检验 + 资产完整性）、逐镜检查状态、自动插入过渡分镜、自动修复、任务中心与全自动流程接入
- 状态：已按真实第 17–21 镜漏检复盘修订

## 1. 背景与目标

分镜拆分现在能保证剧本覆盖、段落数量和视频提示词格式，但拆分结果仍然只经过「生成即保存」，没有一套独立的质量检查。实际出现的问题集中在五类：

1. 单个分镜的运镜、对话、动作、表情、旁白描述不完整或写错位置，例如把「不由失望地相视」「满脸激愤」写成台词，导致视频模型把它念出来。
2. 前后分镜动作不连贯，上一镜的尾动作、视线、站位、道具位置没有承接，或出现角色瞬移、时间倒退等不合理描述。
3. 有角色但长时间没有台词/旁白的镜头，以及没有人物也没有声音的空镜。
4. 单句台词/旁白所需时长超过镜头容量，或一句话占用了明显过长的时间，需要提示拆分。
5. 分镜绑定的角色、场景、道具不存在、已删除、未关联到本集，或资产图缺失、`@角色名` 指向错误，导致参考素材挂不上、生成结果缺人缺景。

本方案要达成五件事：

1. 在分镜拆分完成后增加一次独立的「动作检验」，同时检查五项内容，并给出可定位到分镜/台词/资产的问题清单。
2. 采用「规则引擎 + 独立检验 Agent + 受控修复器」三层结构：规则层负责确定性阈值，语义层负责镜头语言和连贯性判断，修复层只做白名单内的安全修改。
3. 逐个分镜按顺序检验，并在左侧视频任务列表的每个卡片上显示「待检查 / 检查中 / 已完成」状态；前后分镜存在明显转场时，允许在断点添加空镜、场景或文字视频形式的过渡镜头。
4. 支持手动触发与自动触发；自动触发覆盖「手动拆分完成」和「全自动流程」两处；检验发现问题后自动尝试一轮安全修复，并保留快照、撤销和回滚能力。
5. 不修改用户已生成视频、帧资产和已有配音；不阻断全自动流程；检验结果和修复记录可在视频制作页查看，任务中心展示阶段、进度与摘要。

本方案检验的是**分镜规划文本、台词时长与资产记录完整性**，不分析已经生成的视频画面、字幕文件或成片内容，也不评价资产图的视觉质量。

## 2. 现状与约束

### 2.1 现有拆分与提示词链路

- 分镜拆分由 `backend/src/services/storyboard-split-jobs.ts` 的分块任务执行，按 1200 个非空白字符切块，逐块调用 `storyboard_breaker` Agent，块内即时保存，支持断点续拆。
- 拆分任务完成后在 `backend/src/services/storyboard-split-jobs.ts` 第 703–721 行把任务置为 `done`，并计算覆盖情况；这里适合挂接自动动作检验（全自动流程内的拆分除外，见 4.9）。
- 前端 `frontend/app/views/drama/episode.vue` 第 570–595 行是分镜工具栏，包含重新拆分、断点续拆、批量视频提示词、批量视频等入口；第 5622 行的 `onBreakdownDone` 会在拆分完成后刷新分镜，并自动补齐缺失的视频提示词。
- 视频提示词批量服务在 `backend/src/services/video-prompts.ts` 第 28 行，按集维护内存任务，已有「运行中不重复启动」的并发保护；任务状态可通过 `getVideoPromptBatchStatus` 读取。
- 全自动流程在 `backend/src/services/automation.ts` 第 744–753 行按「改写 → 提取 → 声音 → 资产图 → 分镜 → 视频提示词 → 视频 → 配音」顺序执行；动作检验应插在视频提示词之后、视频生成之前。

### 2.2 现有数据

- `backend/src/db/schema.ts` 第 186 行的 `storyboards` 表保存分镜号、景别、角度、运镜、画面描述、结果、氛围、视频提示词、转场、连贯性、时长，以及 `composed_image`、`first_frame_image`、`last_frame_image`、`reference_images`、`video_url`、`composed_video_url`、`subtitle_url` 等资产字段。
- 第 553 行的 `storyboard_lines` 表保存台词/旁白、说话人、情绪、计划开始/结束时间、真实音频时长、音频地址、Take、锁定与待复核状态。已有音频的判定不能只看 `audio_url`，还要看 `active_take_id`、`audio_duration_ms` 和 Take 记录。
- 第 423 行的 `video_transitions` 表保存相邻两镜断点的 AI 过渡片段，一行一个断点，含首尾帧、提示词、来源指纹、时长、状态、视频地址与启停标记。该表服务于导出页的「AI 过渡片段」，合片时由 `backend/src/services/transition-merge.ts` 插入，缺片、过期、损坏或未完成时回退到镜头原转场。本方案的「自动插入过渡分镜」是另一条链路：在 `storyboards` 表插入真实分镜行，写入 `transition_kind`（`empty` / `scene` / `text`），插入后重排镜头号并改写 `@镜头N末帧` 引用；两条链路互不替代。
- 第 361 行的 `storyboard_split_jobs` 表是现有拆分任务持久化方式，包含状态、块 JSON、模型、配置、错误与完成时间，可作为动作检验任务表的参照。
- 第 299 行的 `sys_task` 表由 `backend/src/services/ai-task-runs.ts` 写入，任务中心按 `stage` 展示文本/音频任务；动作检验需要新增 `storyboard_audit` 阶段。
- 台词解析与视频提示词解析已有基础能力：`backend/src/services/dialogue-lines.ts` 提供按时间段拆分、台词草稿抽取、可发音文本清洗和视频提示词解析。检验层应复用这些能力，不重新实现一套解析器。

### 2.3 现有规则与检验口径

- 分镜基础提示词要求每段 8–15 秒、内部 2–4 个子镜头、视频提示词按 3 秒连续分段、每个 3 秒段最多 12 个汉字的台词/旁白，并明确「运镜、景别、表情、心理和动作不得写成台词或旁白」。
- 分镜提示词当前的台词容量口径是「4.5 字/秒 + 2 秒表演余量」；本方案的检验口径按已确认的「4 字/秒 + 每句 1 秒呼吸」执行。两者不完全相同：检验口径用于**事后判断**，不修改拆分提示词，也不要求拆分阶段改用同一公式。检验发现问题时通过延长时长、规范化提示词或人工提示解决。
- 检查 3、检查 4 的数值阈值只由规则层判定，语义层可以补充「是否真的需要拆分」「是否是合理留白」等语义意见，但不能推翻规则层的阈值结论。
- 资产准备度现有口径在 `backend/src/services/automation.ts` 第 428–430 行：角色、场景、道具的 `imageUrl` 为空即视为待生成。角色/场景/道具是项目级素材，允许跨集选用；`backend/src/routes/storyboards.ts` 第 48 行的 `ensureStoryboardBindings` 会在保存分镜时把项目内素材自动补关联到当前集。因此检查 5 必须接受「项目内、未删除、但未直接关联本集」的素材，只把不存在、已删除或跨项目的绑定判为错误。

### 2.4 关键约束

- 不修改已生成视频的分镜、已有任意帧资产的分镜、已有配音的分镜；这些分镜只读，检验可以报问题，但不自动修复。
- 不改变现有分镜字段契约、拆分工具契约、视频提示词格式和 ComfyUI 时间轴格式；动作检验是拆分后的后处理。
- 自动修复最多一轮，复查最多一次；修复后错误数增加必须整体回滚。
- 动作检验失败不得阻断全自动流程；没有文本模型时降级为规则检验。
- 界面文案覆盖 zh、en、ja、ko 四种语言；桌面模板是 copy-once，技能只增不覆盖，提示词随模板版本覆盖，因此新 Agent 的提示词/Skill 文件必须同时进入桌面模板并提升模板版本。
- 不修改用户已选择的文本/视频模型配置；检验使用触发时指定的模型，或拆分任务记录的模型/配置。
- 自动插入的过渡分镜是真实分镜行：`storyboards.transition_kind` 非空即标记为过渡分镜，分镜号按插入位置重排，`@镜头N末帧` 引用和帧资产文件名同步改写。过渡分镜不参与语义检验和规则检验，只作为前后真实分镜之间的过渡声明。
- 检查 2 一次只判定一对相邻真实分镜；没有视频提示词、没有给出明确结论或结论缺证据的对，按该对检验失败处理，不得默认通过。
- 不允许用规则阈值直接判定「文字描述是否连贯」或直接触发插卡；规则层只能报字段缺失、结构错误和不带修复动作的提示。
- 逐镜检查状态是检验任务的结果快照，不写入分镜表；分镜被修改、删除或重新拆分后，状态以最近一次任务和指纹为准，不把过期状态当成当前结论。

## 3. 方案对比与选择

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A. 规则引擎 + 独立检验 Agent + 受控修复器 | 规则层判阈值，Agent 判语义，修复层按白名单执行 | 阈值稳定；语义问题能覆盖；修复可审计、可回滚；成本可控 | 需要新增任务表、Agent、工具与前端面板 |
| B. 单一 Agent 全量重写分镜 | 把整集分镜交给一个 Agent 检查并直接改写 | 实现最短 | 不可预测、成本高、容易改动已生成资产、无法解释问题来源 |
| C. 只做规则引擎 | 只检查字段缺失、时长、空镜等确定性规则 | 无模型成本、稳定 | 无法判断前后连贯、动作合理性和描述是否写错位置 |

**选择 A。** 决定性理由是安全边界：用户已经可能生成了视频、帧资产和配音，任何语义改写都必须有白名单、快照、复查与回滚。规则层保证阈值不被模型漂移，语义层只补充规则无法判断的连贯性与镜头语言问题，修复层只执行经过校验的动作。

### 3.1 过渡分镜的落点选择

| 落点 | 做法 | 影响 |
|---|---|---|
| A. 只扩展 `video_transitions` | 断点片段不进入分镜表 | 不改变分镜号，但用户看不到独立镜头卡片，无法参与逐镜状态、视频生成和成片镜头序列；与「自动增加过渡分镜」诉求不符 |
| B. 在 `storyboards` 表插入真实过渡分镜行，用 `transition_kind` 标记 | 插入空镜/场景/文字卡，重排镜头号并改写引用 | 用户能在镜头列表看到过渡卡；可生成视频、参与合片；代价是必须可靠重排编号和引用 |
| C. 新建独立过渡分镜表 | 与 `storyboards` 平行维护顺序 | 需要第二套排序、时长、合片和前端列表逻辑，与现有分镜能力重复 |

**选择 B。** 自动修复要产生用户可见、可生成、可合片的过渡分镜，只有真实分镜行满足。编号重排是已知代价，由 `storyboard-audit-insertion` 统一处理：插入后按 `storyboard_number` 重排，并改写 `@镜头N末帧` 引用、帧资产文件名和文字卡内的镜头号；原问题在插入成功后标记为 `fixed`。自动插入的过渡分镜写入 `transition_kind`，检验时跳过，不参与语义窗口和规则检查；断点已存在过渡分镜时不再二次插卡。

导出页的 `video_transitions` AI 过渡片段仍然保留，属于另一种断点产物（不改变分镜号、不进入镜头列表），与本节的自动插入过渡分镜互不替代。

## 4. 总体设计

### 4.1 三层职责

| 层 | 位置 | 回答的问题 | 是否使用文本模型 |
|---|---|---|---|
| 规则检验层 | 后端纯函数 | 字段是否缺失、提示词结构是否合法、资产绑定与引用是否完整、空镜是否超时、台词容量是否足够 | 否 |
| 语义检验层 | `storyboard_auditor` Agent | 运镜/动作/表情/旁白是否写对位置，前后动作、视线、空间、时间是否连贯，描述中的角色/场景/道具是否与绑定一致 | 是 |
| 受控修复层 | 后端修复服务 + Agent 修复工具 | 对白名单内的问题生成安全修改，写快照、复查、必要时回滚 | 是 |

规则层与语义层的问题统一进入同一份问题清单；修复层只处理清单中标记为「可修」且通过安全校验的问题。

### 4.2 执行流程

1. 触发：手动拆分完成、全自动流程到达检验步骤，或用户手动点击「动作检验」。
2. 准备：按集加并发锁；读取剧集、未删除分镜、未删除台词、角色/场景/道具绑定、资产字段和当前拆分方式；检查是否有缺失的视频提示词；初始化每个分镜的检查状态为 `pending`。
3. 补齐提示词：如果有视频提示词批量任务正在运行，等待其结束；如果没有运行且存在缺失，先等待 15 秒观察前端是否发起批量任务；仍无运行任务时，按当前任务记录的模型/配置启动一次批量补齐并等待其结束；无文本模型时跳过。
4. 规则检验：按分镜号升序对全部分镜执行检查 1 的确定性部分、检查 3、检查 4、检查 5 的确定性部分；`transition_kind` 非空的过渡分镜整个跳过。规则检验完成后，超出语义窗口上限的真实分镜标记为「已完成（仅规则）」。
5. 语义检验：先按 16 个真实分镜为一个窗口，逐窗串行调用检验 Agent 完成检查 1 和检查 5；再逐对调用连贯性检验 Agent 完成检查 2。一次请求只提交一对相邻真实分镜，AI 必须读取两侧完整视频提示词并给出 `continuous` / `broken` 结论和原文证据；没有结论按该对失败处理并重试一次。过渡分镜不作为被检对象；两侧真实分镜之间夹着过渡分镜时，组成跨卡对。
6. 汇总：生成问题编号、严重级别、可修标记、指纹、逐镜状态和摘要；写入任务表。
7. 修复：如果存在可修问题且模型可用，调用一次修复 Agent；检查 2 只有在成对结论为 `broken` 且给出 `suggestedTransition` 时才自动插入过渡分镜。修复工具逐条校验并应用，写修复前快照和修复日志。
8. 复查：重新执行规则检验，并复查修复涉及的窗口和成对检查（包括新插入过渡分镜形成的跨卡对）；比较修复前后的错误数；复查涉及的分镜在复查期间标记为 `running`，完成后回到 `done`。
9. 回滚或完成：错误数增加或复查无法完成时按快照回滚；否则保留修复，问题标记为已修复。任务完成并写入任务中心。
10. 用户操作：查看问题、按分镜定位、查看修复记录、撤销本次修复、重新检验；检查 2 问题卡片可直接查看过渡分镜说明。

### 4.3 五项检验

#### 检查 1：单个分镜的运镜、对话、动作、表情、旁白描述

规则层：

- `description` 为空或只有占位词：错误。
- `video_prompt` 为空：错误。正常情况下第 4.2 节的准备阶段已经补齐；这里用于兜住批量失败或模型漏写。
- `shot_type`、`angle`、`movement` 任一为空：警告。
- 时长超过 3 秒但 `description` 没有【镜头N】结构：警告，提示画面描述未按子镜头拆分。
- 视频提示词第一行不是「出场人物：…｜场景：…」信息头：警告。
- 视频提示词时间段没有从 0-3 秒开始、时间段有重叠/空档、最后一段结束时间与镜头时长不一致：警告。
- 视频提示词某个 3 秒段中的台词/旁白超过 12 个可发音字符：警告。
- 台词/旁白段里出现高置信度的运镜、景别、表情、心理或动作短语（例如「不由失望地相视」「满脸激愤」「镜头推近」）：警告；语义层确认后升级为错误。
- 说话人在本集角色列表内、但没有绑定到该分镜：提示（info），可能是画外音或未出镜角色；只提示人工确认，不自动改绑定。
- 说话人不在本集角色列表：警告；只提示人工处理，不自动改绑定。
- `@角色名` 引用不在角色清单、或未绑定到该分镜：归入检查 5 的资产使用检查，不在此重复报。

语义层：

- 检查画面描述是否真的写清了谁在做什么、肢体细节、表情、视线和结果，而不是只有抽象情绪。
- 检查运镜、景别、角度是否与动作匹配，是否出现「镜头语言写成台词」「旁白写成角色开口」「动作写成旁白」。
- 检查旁白是否应该存在、是否与画面重复、是否把角色的心理活动错误地分配给旁白。
- 语义层可以判定问题为错误或警告；涉及实际生成效果严重偏差的用错误，轻微不完整用警告。

#### 检查 2：前后分镜是否连贯，是否有不合理的动作/描述

检查 2 的最终判断只由 AI 成对完成，规则层只做字段缺失提示，不用规则阈值判断文字描述是否连贯，也不直接触发插卡。

规则层（不产生自动修复）：

- 第二镜及之后的真实分镜 `continuity` 为空：警告 `continuity_missing`，提示人工补写；两侧之间存在过渡分镜时跳过该提示。
- 相邻两镜场景不同、转场为 `cut` 且 `continuity` 为空：警告 `cross_scene_cut_without_continuity`；两侧之间存在过渡分镜时跳过。
- 第一镜 `continuity` 为空或为「开场」不报问题。
- 相邻两镜 `time` 文本显示时间跨度较大且无过渡分镜：提示（info）`adjacent_time_jump`。该提示只用于提醒，不可自动修复、不指定过渡类型；是否断裂、是否需要插卡由成对 AI 判定。
- `transition_kind` 非空的过渡分镜不参与上述任何规则。

成对 AI 判定：

- 以「相邻真实分镜」为单位组成对：一个对 = 上一真实分镜 + 下一真实分镜；中间夹着的过渡分镜列入 `bridge`，不单独作为被检对象。
- 每次模型请求只提交一个对，必须携带上一镜和下一镜的完整视频提示词；提示词同时单列上一镜末段和下一镜首段，但 AI 必须读取完整时间轴，不能只看摘要。
- 该对没有过渡分镜时：同一场景同一时间段，下一镜首段必须用可见的动作、视线、站位或道具承接上一镜末段；换场景、换时间或换人物组，必须有可见的新场景建立、时间/空间过渡或明确的反应镜头。接不上即 `broken`。
- 该对存在过渡分镜时：过渡分镜是断点声明，不是证据，也不按分镜检查。文字卡只能提供时间/地点标签，不能替代动作衔接；场景/空镜卡提供视觉过渡，可以承接时间/空间跳变，但不能补足缺失的动作过程。下一镜首段与过渡声明冲突、或仍然直接进入动作中段时，判 `broken`。
- `continuity` 字段只是声明，不是证据；声明与视频提示词首段不符时同样判 `broken`。
- 每一对必须调用 `report_continuity_verdict` 提交结论：`continuous` 或 `broken`。`broken` 必须给出上一镜末段原文、下一镜首段原文和原因；没有调用工具、没有结论或证据缺失时，该对检验失败并重试一次，重试仍失败则该对标记失败，不得默认通过。
- `broken` 且该对没有过渡分镜时，可给出 `suggestedTransition`（`empty` / `scene` / `text`）表示「插一个过渡分镜可以解决」；场景/空镜用于时间、空间或情绪缓冲，文字卡只用于纯时间/地点标签跳变且下一镜新节拍本身清楚的情况。类型选择按断点性质：时间/年代/时刻明确跳变优先 `text`，地点明确变化且下一镜有场景资产优先 `scene`，同地点同时间只缺动作缓冲才用 `empty`；同一集连续断点不重复同一种类型。动作过程缺失、需要补演或需要删改剧情时，不给过渡建议，留给人工。
- 该对已有过渡分镜时，结论只能报「过渡内容是否足够」；不再给出 `suggestedTransition`，避免同一断点重复插卡。
- 连贯性问题归属到**后一个真实分镜**；跨卡问题的 `relatedStoryboardIds` 同时包含前一真实分镜和中间的过渡分镜，使它与此前触发插卡的「时间跳变」问题区分开：插卡成功后原问题固定为已修复，后续检验不会再次要求插卡。
- 修复时只允许修改后一个分镜的 `continuity`、`transition`、`description` 或 `video_prompt`；如果后一个分镜受资产/配音保护，则只能人工处理。

#### 检查 3：长时间无对话的空镜

- 「无对话」按有声内容判断：该分镜没有未删除且文本非空的台词/旁白；只有音效、环境声或空台词行不算有对话。
- 有台词/旁白但都没有可验证时长时，视为有对话，不进入本项空镜判定；其容量按检查 4 的整镜总需求校验。
- 有角色绑定的分镜（`storyboard_characters` 非空，或存在绑定角色的对白）：
  - 时长 8 秒（含）到不足 12 秒：警告。
  - 时长 12 秒（含）以上：错误。
- 没有角色绑定的分镜（无角色绑定，也没有对白/旁白说话人）：
  - 时长 6 秒（含）以上：警告；本方案不设该类的自动错误阈值。
- 如果有旁白，即使没有角色出镜，也不属于本项「无对话空镜」；旁白时长按检查 4 校验。
- 检查 3 只报问题，不自动修复：系统不能凭空补台词，缩短时长或拆镜头属于创作决策，留给人工处理。

#### 检查 4：每句话的时长是否合理，是否要拆分

计算口径：

- 可发音字符数：对 `speak_text` 优先、否则对 `text` 去掉空白和标点后的字符数；中文按字、英文按字母计。
- 每句需要时长 = 可发音字符数 ÷ 4 + 1 秒（结果保留 1 位小数）。
- 可验证的有效时长优先级：合成音频真实时长 > 台词计划时长（`planned_end_ms - planned_start_ms`）> 手动占位时长（`voice_duration_ms`）。
- 三者都没有时，用该句需要时长计入整镜总容量，不单独判定该句过短或过长。

判定：

- 单句有效时长少于需要时长：缺口不超过 1 秒为警告，超过 1 秒为错误。
- 该分镜所有台词/旁白需要时长之和超过分镜时长：错误，提示需要延长镜头、减少台词或拆分。
- 单句需要时长超过 6 秒（可发音字符超过 20 个）：警告，建议拆分为多句或拆分到相邻分镜。
- 单句有效时长超过需要时长 3 秒以上：警告，提示单句占时过长，建议拆分或压缩。
- 台词和旁白都参与计算；音效、环境声不参与。

修复边界：

- 自动修复只允许在安全条件下**延长镜头时长**并同步重写视频提示词时间轴；不自动拆句、不改台词文本、不改说话人、不缩短时长。
- 如果延长到当前拆分方式单段上限仍装不下，或分镜受资产/配音保护，问题标记为需人工处理。
- 「建议拆分」是检验结论，不保证自动执行；首版不自动改台词行结构，避免与视频提示词、后续台词抽取和配音计划产生不一致。

#### 检查 5：分镜使用的资产是否正确完整

规则层：

- `scene_id` 为空：警告，提示该镜没有场景绑定，场景参考图与一致性无法保证。
- `scene_id` 指向不存在、已删除或不属于当前项目的场景：错误。
- 场景存在但未关联到本集：提示（info）；项目级素材允许跨集使用，不判错误。
- `storyboard_characters` / `storyboard_props` 的绑定指向不存在、已删除或不属于当前项目的资产：错误。
- 绑定资产存在但未关联到本集：提示（info）；跨集选用是允许的。
- 同一分镜重复绑定同一角色或同一道具：警告，按去重后的集合展示，不自动删除绑定行。
- `@角色名` 出现在画面描述或视频提示词中时：
  - 匹配本分镜已绑定角色：通过。
  - 匹配本项目角色但未绑定到本分镜：警告 `reference_character_unbound`。
  - 匹配不到本项目任何角色：警告 `reference_character_unknown`。
  - 匹配到多个同名角色：警告，提示人工确认绑定。
- 已绑定角色、场景或道具的 `image_url` 为空：警告 `character_asset_missing` / `scene_asset_missing` / `prop_asset_missing`。
- `reference_images` 不是合法 JSON 数组、数组元素为空或不是字符串：警告 `asset_reference_malformed`；只报问题，不改字段。
- 绑定资产的图片是项目内相对路径但文件不存在：警告 `asset_file_missing`；外链不探测。
- 资产记录已删除但仍被分镜引用：错误，与绑定无效合并为对应的 `*_binding_invalid`。
- 不评价资产图的内容是否像角色、场景是否符合剧本；这属于语义层和人工判断。

语义层：

- 画面描述或视频提示词写到的角色、场景、关键道具是否与绑定一致；描述里出现但未绑定的角色或道具，报 `semantic_asset_mismatch`。
- 场景绑定与 `location`、画面描述明显冲突（例如绑定「客栈」但描述在「皇宫」），报 `semantic_asset_mismatch`。
- 语义层只报不一致，不自动改绑定；修复一律人工。

修复边界：

- 检查 5 全部只报问题，不自动修复、不改绑定、不生成资产图、不删除重复绑定。
- 资产图缺失时，面板提供「去资产页生成」的跳转提示；不在检验面板内直接触发资产生成。
- 检查 5 不阻断其他检查项的自动修复；分镜是否受只读保护只看已生成帧资产、视频、字幕和配音，与资产记录是否完整无关。

### 4.4 逐镜检查状态与顺序

任务创建时在 `shot_status_json` 中为每个未删除分镜初始化一条状态。普通分镜默认 `pending`；自动插入的过渡分镜直接写入 `done` 并带 `transition=true`，不参与检查、不显示检查图标。

| 状态 | 图标语义 | 进入条件 |
|---|---|---|
| `pending` | 灰色待检查 | 任务已创建但该镜尚未进入语义窗口；或未运行过检验 |
| `running` | 蓝色旋转检查中 | 该镜作为当前语义窗口的目标分镜，规则复查、成对连贯判定或窗口语义请求已发出；复查时涉及的分镜也回到此状态 |
| `done` | 绿色对勾已完成 | 该镜的规则检验、成对连贯判定和窗口语义检验都已完成（语义关闭时为「仅规则」），并写入该镜问题计数 |
| `failed` | 红色感叹号检查失败 | 该镜的成对连贯判定或所在语义窗口重试后仍失败；该镜的规则问题仍保留，可重新检验 |
| `transition`（标记，不是新状态） | 过渡分镜标签 | 该行是自动插入的过渡分镜；状态固定 `done`，不显示对勾图标，卡片显示「空镜 / 场景 / 文字过渡」标签 |

状态规则：

- 检查严格按分镜号升序推进；成对连贯判定和语义窗口都从前往后串行，不并行调用模型。规则检验虽是一次性扫描，但状态仍按窗口推进展示，避免所有镜头同时显示「检查中」。
- 窗口规划只使用未删除且非过渡的分镜；过渡分镜不占窗口目标，也不做前后只读上下文。
- 窗口开始前只把该窗口的目标分镜置为 `running`；因重叠而作为上下文带入的分镜不重复改状态，它属于上一窗口。
- 每个语义窗口按顺序做两件事：先对本窗口负责的成对连贯判定逐对调用模型（一次一对），再调用窗口语义检验（检查 1 和检查 5）。两步都成功，目标分镜才置为 `done`。
- 成对连贯判定的结论归属于后一个真实分镜：判定「断裂」或模型未给出结论且重试失败时，后一个真实分镜置为 `failed`，该对之前的分镜不受影响；窗口语义检验失败时，窗口内其余未失败的目标分镜置为 `failed`。
- 断点两侧存在过渡分镜时，该对称为跨卡对；跨卡对的结论同样归属后一个真实分镜，中间过渡分镜保持 `transition` 标记，不报问题。
- 超过语义窗口上限的分镜只做规则检验，规则完成后置为 `done` 并标记 `rule_only=true`，图标提示「已完成（仅规则）」；这些分镜不做成对连贯判定。
- 没有可用文本模型时，规则检验完成后全部置为 `done`，整集摘要标记「仅规则检验」，单镜提示同。
- 修复和复查只把实际被修改、被复查的分镜置回 `running`；复查结束后回到 `done`。回滚不把状态改回 `pending`，因为规则复查已经完成。
- 任务被中断时，处于 `running` 的分镜回到 `pending`，避免留下永久「检查中」；任务失败时置为 `failed`。
- 分镜在检验完成后被用户修改，图标仍显示 `done`，但叠加琥珀色过期点，提示「检验后已修改，建议重新检验」；过期由读取时比对指纹得出，不写入状态表。过渡分镜被修改后同样出现过期点，提示重新检验该断点。
- 分镜被删除后从状态映射中移除，不再显示图标；新增分镜在下次检验前显示 `pending`。
- `shot_status_json` 每个窗口落库一次（最多 20 次），终态再写一次；前端按轮询周期读取最近任务，不单独轮询每个分镜。

### 4.5 断点过渡镜头

系统里有两种过渡产物，职责不同：检验自动插入的过渡分镜是真实分镜行；导出页的 AI 过渡和自定义过渡片段是合片用的 `video_transitions` 行。

| 机制 | 存储 | 是否进入分镜号序列 | 谁创建 | 用途 |
|---|---|---|---|---|
| 过渡分镜 | `storyboards` 行，写 `transition_kind` | 是，插入后重排后续镜头号 | 检验修复阶段按 AI 判定自动插入 | 补齐断点动作/时间/空间过渡，参与整集生产流程 |
| AI/自定义过渡片段 | `video_transitions` 行，写 `kind` | 否，断点级独立产物 | 用户在导出页或检验面板手动创建 | 合片时在相邻两镜之间插入一段视频 |

#### 自动插入的过渡分镜

检查 2 的成对判定给出 `verdict=broken` 且给出 `suggestedTransition` 时，修复阶段自动插入一个真实分镜：

| 类型 | 内容 | 生成方式 | 默认时长 |
|---|---|---|---|
| `empty` | 空镜：环境全景、光影细节、道具特写或天气氛围，无人物、无台词；按断点前镜编号在四种拍法间确定性轮换（全景横移 / 光影固定 / 特写推近 / 远景拉远） | 文生视频 | 3 秒 |
| `scene` | 场景镜头：以断点场景资产图为首帧，按断点前镜编号轮换定场 / 细节 / 环视三种拍法 | 图生视频；场景图缺失时降级文生视频并警告 | 3 秒 |
| `text` | 文字视频：主标题 + 可选副标题，纯色或场景图背景 | 本地 ASS 渲染，不调用视频模型 | 3 秒 |

- 插入位置是判定断裂的两侧真实分镜之间；如果中间已有过渡分镜，则该对是跨卡对，不再插入第二个过渡分镜。
- 过渡类型按断点性质选择，不一律用空镜：时间/年代/时刻明确跳变优先 `text`，地点明确变化且下一镜有场景资产优先 `scene`，同地点同时间只缺动作缓冲才用 `empty`；同一集连续断点尽量换用不同类型，空镜拍法由服务端按断点位置轮换，成对提示词、Agent 提示词与检验技能都写入这条选择规则。
- 插入行是普通分镜：有标题、镜头字段、描述、视频提示词、连续性、时长与 `transition_kind`。文字卡默认取下一镜时间或地点作为主标题，没有时用「与此同时」；空镜和场景使用断点场景生成环境描述，标题与描述带当前拍法后缀（如「过渡空镜·光影」），便于在镜头列表区分。
- 插入后按数据库 ID 顺序重排整集镜头号，同步改写受影响的 `@镜头N末帧` 引用与末帧资产名称；重排与改写在同一事务完成。
- `transition_kind` 非空的分镜在规则检查、成对连贯判定、窗口语义检验、问题统计和自动修复中全部跳过；逐镜状态固定 `done + transition=true`，左侧卡片显示过渡类型标签而不是检查图标。
- 过渡分镜不参与检查 2 的配对：它两侧的真实分镜形成一个跨卡对，由成对判定确认。文字卡只能说明时间或地点，不能替代动作承接；空镜和场景卡只提供视觉缓冲，也不能替代缺失的动作过程。
- 自动插入受策略 `autoRepair.autoInsertTransition` 与 `maxInsertedTransitions` 限制；单任务最多插入策略配置的数量，默认 3 个。
- 插入前校验：断点两侧是相邻或仅隔过渡分镜的真实分镜；断点后方没有只读保护的分镜（已有帧资产、视频、字幕、配音或进行中任务时拒绝自动插入，避免重排镜头号改写已生成的提示词）；断点两侧至少一侧有可用场景资产。
- 插入成功即视为修复了原断点问题，问题状态置为 `fixed`；插入失败或被拒绝时问题保留为 `manual`，面板提示人工处理，不重试第二次插入。
- 回滚时按快照记录的批次删除插入行、还原镜头号、引用、末帧资产名和断点过渡启用状态；用户手工改过的分镜按指纹跳过，部分回滚在面板提示冲突。
- 除 `empty` / `scene` / `text` 外，不允许自动插入 `ai` 过渡；AI 过渡仍由用户手动创建。

#### `video_transitions` 过渡片段

- `ai`：现有 AI 过渡，连接前后两镜的连续画面，首尾帧取上一镜尾帧与下一镜首帧，环境声或静音，默认 3 秒。
- `empty` / `scene` / `text`：导出页可手动创建的自定义过渡片段，参数与自动插入的过渡分镜一致，但只写入 `video_transitions`，不进入分镜号序列。
- `fade`：本地转场片段，不调用视频模型：FFmpeg 取上一镜最后 D 秒与下一镜最前 D 秒做 `xfade` 交叉过渡，输出静音视频；样式中预设 dissolve / dip-black / dip-white / wipe-left / slide-left / circle-open 六种，创建和详情弹窗均可选择。该类型不需要提示词，也不占用模型额度，适合「不想要空镜、只要一个平滑转场」的断点。
- 断点必须仍是当前排序下的相邻两镜；一行一个断点，唯一约束不变。切换类型会清空旧输出并重新生成，不保留不匹配的旧视频。
- `empty` 和 `scene` 的提示词由用户填写或按检查 2 的问题建议预填；本地 H3 仍遵守「仅英文提示词」约束，中文提示词先走现有翻译链路，翻译失败直接报错，不回退中文。
- `scene` 的场景必须属于当前项目且未删除；场景图不存在时降级文生视频，并在过渡卡片和任务日志标记「场景图缺失，已降级」。
- `text` 复用现有 ASS 字幕生成与渲染能力：主标题最多 20 个可发音字符，副标题最多 40 个；纯色或场景图背景；淡入淡出 150ms；输出 H.264/yuv420p + 静音 AAC；24–30fps 按项目设置；`provider=local`、`model=ffmpeg-text`，不占用视频模型额度。
- 时长允许 2–5 秒，按模型能力折算后写 `duration_requested` / `duration_effective`；文字视频由本地渲染精确命中请求时长。
- 过渡片段时长不计入 `episodes.duration`；合片后的成片长度会增加，导出页按实际片段总和展示。
- `ai` 使用上一镜/下一镜视频的边界指纹；`empty` / `scene` / `text` 使用独立指纹：类型 + 提示词/文字内容 + 时长 + 音频模式 +（场景类型）场景 ID 与场景图路径。相邻镜头视频变化不会让独立过渡过期；切换类型、修改文字、替换场景图或修改提示词都会让指纹变化，旧视频标记过期并在下次合片时回退。
- `fade` 使用本地转场指纹：相邻视频路径、大小与修改时间 + 样式 + 时长。相邻镜头视频重新生成或样式切换都会让指纹变化，旧片段标记过期并在下次合片时回退。

#### 入口与合片

- 检查 2 的问题卡片在自动插入成功后显示「已插入过渡分镜」跳转；自动插入被拒绝或策略关闭时，卡片提供「添加过渡片段」作为手动兜底，写入 `video_transitions`，不改变分镜号。
- 过渡分镜作为普通分镜出现在左侧视频任务列表和检查器中，用户可以像其他分镜一样编辑、生成视频或删除；删除后再次检验时，断点会重新回到待检查状态。
- 导出页过渡卡片/详情弹窗继续管理 `video_transitions` 片段：查看、播放、新建、切换类型、重生成、停用和删除；详情弹窗可在 `ai` / `fade` / `empty` / `scene` / `text` 之间切换，切换会清空旧输出并重新生成，不保留不匹配的旧视频。自动插入过渡分镜时，同一断点原有的 `video_transitions` 行会被停用，避免重复过渡。
- 合片仍由 `backend/src/services/transition-merge.ts` 插入已完成、启用、未过期、文件可读的片段；`ai`、`empty`、`scene` 两端使用 200ms 淡入淡出，`text` 两端硬切，`fade` 片段本身已含交叉过渡、按硬切拼接；任一片段不可用仍回退到原转场，不阻断合片。过渡分镜作为真实分镜参与常规整集合片。
- `video_transitions` 片段不改分镜、不改绑定、不写分镜快照，因此对已有视频、帧资产和配音的分镜同样可用；它不是自动修复动作，不计入修复动作上限。
- 检验进行中不允许新建或重生成 `video_transitions` 片段（与视频生成同一条互斥规则）；已有过渡片段播放不受影响。过渡生成任务进行中允许启动检验，因为检验不读取过渡视频内容。

### 4.6 语义窗口与成对连贯判定

语义阶段分成两条串行链路，共用同一份上下文与顺序控制：

1. **成对连贯判定（检查 2）**：一次请求只处理一对真实分镜。
2. **窗口语义检验（检查 1 和检查 5）**：沿用 16 镜窗口批量检查。

#### 成对连贯判定

- 配对只取未删除、`transition_kind` 为空的真实分镜，按镜头号升序组成相邻对 `(前一真实分镜, 后一真实分镜)`。
- 中间隔着自动插入过渡分镜的两侧真实分镜组成跨卡对；配对时跳过过渡分镜本身，不为过渡分镜生成独立请求。
- 每个对只判定一次，归属到后一个真实分镜所在的语义窗口；窗口重叠不会造成同一对重复判定。
- 每次请求携带：一对分镜的完整上下文（含完整视频提示词）、两侧角色组、两侧场景/地点/时间、中间的过渡分镜类型与文字内容、规则层已发现的时间跳变提示；不携带其他分镜摘要替代原文。
- 模型必须调用 `report_continuity_verdict` 给出 `continuous` 或 `broken`；`broken` 必须带证据、问题描述、修改建议和可选的 `suggestedTransition`（`empty` / `scene` / `text`）。
- 没有调用结论工具、结论无法解析或请求失败，都按该对失败处理：同一对重试一次；仍失败则记录 `pairFailed`，后一个真实分镜标记 `failed`，其他对继续。
- 判定为断裂时生成一条 `semantic_continuity_break` 问题，主分镜是后一个真实分镜；普通相邻对的 `relatedStoryboardIds` 包含前一个真实分镜，跨卡对的 `relatedStoryboardIds` 包含前一个真实分镜和中间过渡分镜。
- 跨卡对判定断裂时不再建议插入过渡分镜，问题标记为不可自动修复：已有卡片只解决了一部分过渡，剩余问题需要人工改写动作或补拍。
- 窗口外分镜（规则仅检、超出窗口上限）不做成对判定。
- 成对判定的总数、失败数、断裂数写入摘要；重试用尽仍失败不阻断其他对。

#### 窗口语义检验

- 窗口目标只包含未删除且非过渡的真实分镜；过渡分镜不占窗口名额，也不作为前后只读上下文。
- 以 16 个真实分镜为一个窗口，步进 15 个分镜，相邻窗口重叠 1 个分镜，保证窗口边界的检查 1/5 能够看到前后关系。
- 如果剩余分镜不足 2 个，并入上一窗口，避免生成只有重叠镜头的空窗口。
- 每个窗口除 16 个目标分镜外，额外携带前一个和后一个真实分镜作为只读上下文；问题只针对窗口内目标分镜。
- 窗口上下文包含：分镜号、标题、场景/地点/时间、时长、景别、角度、运镜、画面描述、结果、氛围、转场、连贯性、完整视频提示词、角色/场景/道具绑定与资产可用性（名称、是否删除、是否关联本集、`image_url` 是否存在）、未删除台词（说话人、类型、文本、有效时长、计划时间）、资产保护标记。带 `transition_kind` 的分镜如果仍在上下文中，明确标注「过渡分镜，跳过检查」。
- 同时携带本集角色/场景清单和格式化剧本；剧本超过 6000 字时截取前 6000 字并注明截断，避免单次上下文失控。
- 单集最多 20 个语义窗口；超过窗口上限的分镜只做规则检验，并在摘要中标记「语义检验已截断」。成对判定只为窗口覆盖的前段真实分镜规划。
- 每个窗口失败后重试一次；仍失败则记录该窗口失败并继续后续窗口。全部窗口失败时任务仍完成规则检验，摘要标记语义失败，不阻断流程。

### 4.7 问题模型与去重

每个问题包含：

| 字段 | 说明 |
|---|---|
| id | 任务内稳定编号，如 `ISSUE-12` |
| check | 1–5，对应五项检验 |
| source | `rule` / `semantic` / `rule+semantic`（同一位置合并后） |
| severity | `error` / `warning` / `info` |
| code | 稳定问题码，如 `shot_missing_description`、`prompt_action_in_dialogue`、`line_requires_split` |
| storyboardId / storyboardNumber | 主分镜；检查 2 的语义问题固定为后一个真实分镜 |
| lineId | 台词问题可空 |
| relatedStoryboardIds | 连贯性问题涉及的前后分镜；跨卡对额外包含中间的过渡分镜 ID |
| pairKey | 检查 2 语义问题的断点标识（两侧真实分镜 ID 排序后拼接）；其他问题为空 |
| message | 面向用户的问题描述 |
| evidence | 证据片段，最多 500 字 |
| suggestion | 修改建议，最多 300 字 |
| repairable | 理论上是否可自动修复（修复前还会重新校验安全条件） |
| repairAction | 建议的修复动作，可为空 |
| suggestedTransition | 可空的过渡类型建议 `empty` / `scene` / `text`，只允许检查 2 的语义问题携带；跨卡对和已存在过渡分镜的断点不携带 |
| status | `open` / `fixed` / `manual` / `stale`（检验后分镜被修改，问题可能已失效） / `rolled_back` |
| windowIndex | 语义窗口序号，规则问题为空 |

`repairable` 为假、修复被拒绝且无替代动作、或问题受资产/配音保护时，`status` 置为 `manual`。

规则问题码固定为：
- 检查 1：`shot_missing_description`、`shot_missing_video_prompt`、`shot_missing_camera_fields`、`description_missing_subshots`、`prompt_missing_header`、`prompt_timeline_broken`、`prompt_segment_too_long`、`prompt_action_in_dialogue`、`speaker_unbound`、`speaker_unknown`。
- 检查 2：`continuity_missing`、`cross_scene_cut_without_continuity`、`adjacent_time_jump`。
- 检查 3：`silent_shot_long`、`empty_shot_long`。
- 检查 4：`line_insufficient_duration`、`line_requires_split`、`line_overlong_duration`、`shot_dialogue_over_capacity`。
- 检查 5：`scene_binding_missing`、`scene_binding_invalid`、`scene_not_linked`、`character_binding_invalid`、`character_not_linked`、`prop_binding_invalid`、`prop_not_linked`、`binding_duplicate`、`reference_character_unbound`、`reference_character_unknown`、`character_asset_missing`、`scene_asset_missing`、`prop_asset_missing`、`asset_reference_malformed`、`asset_file_missing`。

检查 2 的规则问题只做确定性提示，不直接触发修复：

- `continuity_missing`、`cross_scene_cut_without_continuity`：warning，可由修复 Agent 补 `continuity`；断点两侧存在过渡分镜时跳过。
- `adjacent_time_jump`：info，只提示「相邻两镜时间跨度大、中间没有过渡」，`repairable=false`，不再携带 `suggestedTransition`；断点两侧存在过渡分镜时跳过。是否断裂、是否需要过渡由成对 AI 判定决定。

语义问题码固定为 `semantic_shot_description`、`semantic_continuity_break` 和 `semantic_asset_mismatch`；模型不得自造问题码，前端 i18n 按 code 映射，缺少映射时回退 `message`。检查 2 的语义问题只能由 `report_continuity_verdict` 产生，不能通过 `report_storyboard_issues` 上报。

去重规则：

- 规则问题按「检查项 + 分镜 + 台词 + 问题码」去重。
- 检查 1/5 的语义问题按「检查项 + 主分镜 + 相关分镜 + 语义类别」去重；重叠窗口重复报同一问题时保留证据更完整的一条。
- 检查 2 的语义问题按 `pairKey` 去重；同一对只保留一条，跨卡对与普通相邻对不会互相合并。
- 检查 1/5 的规则与语义问题在检查项、主分镜、台词（可空）都相同时合并为一条，保留规则问题码和更严重的级别，来源标记 `rule+semantic`。
- 检查 2 的规则问题与语义问题**不合并**：规则问题是无条件提示，语义问题是 AI 对具体画面的判定；跨卡对的语义问题通过 `relatedStoryboardIds` 中的过渡分镜 ID 与原始断点问题区分，后续复查也不会把已插入过渡卡的问题重新打开。
- 单任务问题总数上限 400，单窗口语义问题上限 30；达到上限后停止新增并在摘要标记截断。检查 2 的成对判定不受单窗口 30 条限制，但受单任务总数限制。

### 4.8 受控修复

#### 安全护栏

以下分镜只读，允许报问题但不允许自动修改：

- 任意帧资产非空：`composed_image`、`first_frame_image`、`last_frame_image`、`reference_images`。
- 任意视频/字幕产物非空：`video_url`、`composed_video_url`、`subtitle_url`。
- 任一句台词已有配音：`audio_url`、`audio_duration_ms`、`active_take_id` 或有效 Take。
- 台词被锁定，或该分镜存在本检验任务之外的进行中图片/视频/配音任务时，按只读处理。

修复前还必须满足：

- 问题属于当前任务、状态为 `open`、`repairable` 为真。
- 分镜当前指纹与检验时指纹一致，说明用户没有在检验后改过该分镜。
- 修改字段在白名单内。
- 除 `insert_transition_shot` 外，修改不新增角色、场景、道具、台词或旁白，不改变分镜号、绑定关系和分镜数量。
- `insert_transition_shot` 只允许由检查 2 的成对 AI 判定触发；插入后允许新增 1 个过渡分镜并重排后续镜头号，但不得改写既有分镜的描述、台词或绑定。
- 插入点后方存在只读分镜时拒绝自动插入，避免重排镜头号改写已生成分镜的提示词和引用。
- 无法验证或依赖创作判断的问题（证据不足、语义不确定、需要决定是否删减剧情）一律标记为需人工，不提交自动修复。

#### 修复动作

| 动作 | 适用问题 | 允许改动 | 额外校验 | 自动 |
|---|---|---|---|---|
| 补全镜头字段 | 运镜/景别/角度缺失 | `shot_type`、`angle`、`movement` | 只能从已有描述和提示词归纳，不新增剧情 | 是 |
| 规范化视频提示词 | 信息头缺失、时间段断裂、动作写成台词、3 秒段超 12 字 | `video_prompt`，必要时同步 `description` | 保留全部真实台词/旁白；时间轴结束等于时长；不新增说话人 | 是 |
| 重写画面描述 | 动作、表情、旁白位置或前后动作明显写错 | `description`、`video_prompt`、`result` | 不新增角色/道具/剧情，不改变台词文本 | 是 |
| 补连贯性 | 上一镜尾动作未承接、跨场景硬切缺说明 | 后一镜的 `continuity`、`transition`，必要时 `description`、`video_prompt` | 不改变场景绑定和角色绑定 | 是 |
| 延长镜头时长 | 台词容量不足，且延长后能装下 | `duration`、`video_prompt`、`description` | 只能增加不能减少；不超过当前拆分方式单段上限；时间轴同步；重算整集时长 | 是 |
| 插入过渡分镜 | 检查 2 成对判定为断裂且给出 `suggestedTransition` | 新增 1 个 `empty` / `scene` / `text` 过渡分镜；重排后续镜头号与 `@镜头N末帧` 引用 | 只由成对 AI 结论触发；断点两侧为真实分镜且中间无过渡分镜；断点后方无只读分镜；类型合法；不超过 `maxInsertedTransitions`；不属于修复 Agent 可提交的动作 | 是（服务端） |
| 资产问题 | 绑定无效、资产图缺失、引用不一致、重复绑定 | 不改数据 | 给出人工处理建议和资产页跳转 | 否 |
| 其余问题 | 缺视频提示词、说话人未绑定、空镜、建议拆句 | 不改数据 | 给出人工处理建议 | 否 |

修复动作只能由修复 Agent 通过工具提交，每条动作必须引用问题编号；服务端逐条校验、逐条应用并记录。单任务最多 40 条动作；同一分镜同一轮最多 3 条动作，且同一字段不重复修改（例如 `duration` 只能被一条动作延长）。

`insert_transition_shot` 是唯一不经过修复 Agent 的动作：修复阶段开始时，任务层先读取检查 2 的成对结论，把可插入的 `semantic_continuity_break` 问题转成插入动作并在服务端执行，再刷新上下文交给修复 Agent 处理其余问题。该动作计入单任务动作上限，但不受同一分镜 3 条动作限制，因为它新增的是独立分镜。跨卡对问题、没有 `suggestedTransition` 的问题、策略关闭自动插入、断点后方存在只读分镜或场景不可用，都直接标记 `manual`，不尝试插入。

#### 快照、撤销与回滚

- 首次应用修复动作前写入修复前快照：所有可能被修改分镜的白名单字段、整集时长，以及修复前指纹。
- 快照写入失败或超过 1MB 时放弃本轮修复，不改任何数据，可修问题标记为 `manual`。
- 每次应用动作记录修复日志：问题编号、分镜号、字段、修改前摘要、修改后摘要、结果、拒绝原因。插入动作额外记录插入分镜 ID、类型、新镜头号、断点两侧 ID 和批次 ID。
- 复查范围：
  - 检查 1/5：被修改分镜所在的语义窗口，加上新插入分镜所在的窗口（过渡分镜本身不检查，但它改变了相邻真实分镜的上下文）。
  - 检查 2：涉及被修改分镜的所有成对判定，以及插入点两侧真实分镜形成的跨卡对；跨卡对必须重新判定，确认插入的卡片真的补上了断点。
  - 复查只跑上述窗口与成对判定，不重跑整集。
- 插入成功后原断点问题置为 `fixed`；跨卡对复查如果仍然断裂，生成一条新的 `semantic_continuity_break`，`relatedStoryboardIds` 包含过渡分镜 ID，且 `repairable=false`。
- 复查后错误数增加，或复查无法完成（包括成对判定重试后仍无结论），按快照整体回滚；如果用户在修复后手工改过某个分镜，该分镜不覆盖，回滚标记为部分完成并在面板提示冲突。
- 用户可以在任务完成后手动「撤销本次修复」；撤销同样做指纹冲突检查，只恢复未被用户再次修改的分镜，并重算整集时长。撤销插入会删除过渡分镜、还原镜头号、引用、末帧资产名和断点过渡启用状态。
- 回滚或撤销后，实际恢复的分镜对应问题恢复为 `open`；因冲突跳过、保留用户修改的分镜对应问题标记为 `stale`，面板提示重新检验；被删除的插入行对应问题恢复为 `open`。
- 修复失败、部分动作被拒绝时，已应用的动作仍需复查；复查通过保留，复查不通过回滚。

### 4.9 自动触发与并发

自动触发两处：

1. 拆分任务完成后：`storyboard-split-jobs` 在任务置为 `done` 后触发动作检验，沿用该拆分任务的 `model` 和 `config_id`。
2. 全自动流程：`stepVideoPrompts` 完成后执行 `stepStoryboardAudit`，再进入视频生成；使用自动化运行指定的模型/配置。

全自动流程调用拆分时显式关闭拆分完成钩子，统一由 `stepStoryboardAudit` 在视频提示词之后执行，避免同一集重复检验；手动拆分和断点续拆完成仍自动触发。

手动触发：

- 视频制作页「动作检验」按钮，可随时对当前分镜执行一次检验；手动请求可指定文本模型与配置，未指定时使用当前默认文本模型；没有可用文本模型时只做规则检验。
- 没有分镜时按钮禁用；有分镜但正在拆分时禁用。

并发与互斥：

- 每集同时只允许一个进行中的动作检验；重复启动返回已有任务，不新建。
- 新的拆分任务启动时，把该集进行中的动作检验标记为 `interrupted`，原因「重新拆分，检验作废」，并把对应的 `sys_task` 记录标记为失败；如果检验处于修复或复查阶段，先按快照回滚本轮修复，再标记中断，避免留下未复查的修改。
- 检验进行中，前端禁用重新拆分、断点续拆、批量视频提示词、单镜视频提示词、视频生成以及 `video_transitions` 片段的新建/重生成入口，避免检验结果与用户修改互相覆盖；已有过渡片段播放不受影响。检验自身的过渡分镜自动插入在同一事务内完成，不受该禁用影响。通过接口绕过时由指纹与资产护栏兜底。
- 停止全自动流程时：如果处于审计阶段且尚未修复，直接中断；如果处于修复或复查阶段，先按快照回滚本轮修复，再标记中断。

### 4.10 降级策略

- 没有可用的文本模型：只执行规则检验，跳过提示词补齐、语义检验和修复；任务完成，摘要标记「仅规则检验」。
- 设置中关闭语义检验但任务指定了文本模型：只跳过语义窗口，规则问题仍按自动修复策略执行受控修复与规则复查，摘要标记「语义检验已关闭」。
- 视频提示词批量运行中：等待其结束，最长等待 30 分钟；超时后带着缺失提示词继续，缺失分镜报 `shot_missing_video_prompt`。
- 视频提示词批量失败：不阻断检验；缺失提示词逐镜报错，成对判定退化为按描述与分镜字段判断，并在证据中注明「缺少视频提示词」。
- 单个成对判定失败或没有给出结论：重试一次；仍失败标记该对失败，后一个真实分镜状态置为 `failed`，继续后续对；摘要增加失败对计数。
- 单个语义窗口失败：重试一次；仍失败标记该窗口失败，其他窗口继续；该窗口内的成对判定仍可独立成功。
- 修复 Agent 失败或修复工具全部拒绝：保留检验结果，任务完成，修复状态为失败/跳过。
- 应用重启：启动时把 `pending`、`preparing`、`auditing` 的任务标记为 `interrupted`，原因「应用重启，检验中断」，并把 `shot_status_json` 中仍为 `running` 的分镜改回 `pending`；`repairing`、`rechecking` 的任务先按快照回滚本轮修复，再标记 `interrupted`，因为复查已无法完成，未验证的修改不能留在数据里。所有未完成任务都不自动续跑；已回滚或已有快照的修复仍可撤销。
- 全自动流程中的检验失败不使流程失败；记录错误和摘要后继续视频生成。

### 5.2 JSON 结构

- `issues_json`：4.7 节问题字段的数组。
- `windows_json`：每个窗口的序号、分镜范围、前后上下文分镜号、状态、失败原因、窗口指纹，以及本窗口负责的成对判定记录 `{ pairKey, leftId, rightId, bridgeIds, status, verdict, attempts, error }`。
- `shot_status_json`：分镜 ID 到 `{ status, ruleDone, semanticDone, ruleOnly, transition, errorCount, warningCount, infoCount, updatedAt }` 的映射；状态只允许 `pending` / `running` / `done` / `failed`；`transition=true` 表示自动插入的过渡分镜。
- `summary_json`：按检查项和严重级别的计数、规则/语义来源计数、逐镜完成数、`pairTotal` / `pairDone` / `pairFailed` / `pairBroken`、截断标记、等待提示词耗时、复查前后错误数。
- `snapshot_json`：修复前分镜白名单字段、整集时长、修复前指纹。
- `repair_log_json`：每条动作的问题编号、分镜号、字段、修改前/后摘要、结果、拒绝原因；以及撤销/回滚结果。
- `fingerprints_json`：分镜 ID 到「检验时字段哈希」的映射（覆盖白名单字段与资产字段），以及台词 ID 到「检验时台词哈希」的映射（覆盖文本、说话人、计划时间、音频地址、音频时长、Take 与锁定状态），用于判断结果是否过期。

### 5.3 生命周期与保留

- 任务创建时清理该集较早的记录，每集保留最近 20 次；清理不会影响当前进行中的任务。
- 应用启动时把所有未完成任务标记为 `interrupted`；其中处于修复或复查阶段的任务先按快照回滚本轮修复，再同步把对应的 `sys_task` 记录标记为失败，原因「应用重启，检验中断」。
- 任务表只存规划文本和摘要，不复制视频、图片、音频文件。

### 5.4 任务中心

- 动作检验使用 `startAiTaskRun` 写入 `sys_task`：类型 `text`，阶段 `storyboard_audit`，带 `episode_id`、`drama_id`、`model`、`config_id`。
- 进度参数包含：总镜头、已完成窗口、问题/错误/警告/提示/可修/已修数量、当前阶段。
- 任务完成调用 `finishAiTaskRun`，失败调用 `failAiTaskRun`；停止时按失败记录原因「已停止」。
- 前端任务中心把 `storyboard_audit` 显示为「整集动作检验」；首版任务中心只展示阶段、进度与摘要，不提供跳转，问题面板统一在视频制作页查看。

### 5.5 `video_transitions` 扩展

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| kind | 文本 | `ai` | `ai` / `empty` / `scene` / `text` |
| scene_id | 整数 | 空 | `scene` 类型使用的场景 ID |
| text_content | 文本 | 空 | `text` 类型的主标题，最多 20 个可发音字符 |
| text_subtitle | 文本 | 空 | `text` 类型的副标题，最多 40 个可发音字符 |

  - 修复阶段必须保留真实台词/旁白、角色/场景/道具绑定和分镜数量（`insert_transition_shot` 由服务端执行，不由模型提交）；不得新增剧情。
  - 逐镜检查状态和问题计数由服务端维护，模型不得输出或修改状态字段。
  - 文案跟随内容语言，匹配 zh/en/ja/ko 四种提示词变体。

### 6.3 Agent 工具

新增三个工具，放在独立模块 `backend/src/agents/tools/storyboard-audit-tools.ts` 中，并在 `AGENT_TOOLS` 中只挂载给 `storyboard_auditor`：

| 工具 | 阶段 | 输入 | 校验 |
|---|---|---|---|
| `report_storyboard_issues` | 窗口检验 | 当前窗口的问题数组 | 只接受检查 1/5；检查项 1–5、严重级别、问题码白名单、分镜必须在窗口内且不是过渡分镜、单窗口最多 30 条（超出丢弃并标记截断）、证据不超过 500 字；拒绝 `semantic_continuity_break` 等检查 2 语义问题 |
| `report_continuity_verdict` | 成对判定 | `pairKey`、`verdict`（`continuous` / `broken`）、断裂时的 message/evidence/suggestion、可选 `suggestedTransition` | 只接受当前任务、当前窗口正在判定的 `pairKey`；两侧分镜 ID 必须与注册的配对一致；`broken` 必须带证据；`suggestedTransition` 只允许 `empty` / `scene` / `text`；每一对只能提交一次结论 |
| `apply_storyboard_repair` | 修复 | 修复动作数组，每条引用问题编号 | 问题属于当前任务且可修；分镜安全护栏；指纹未变；字段白名单；台词/旁白不新增；时间轴结束等于时长；时长只增不减且不超过单段上限；单任务最多 40 条；同一分镜最多 3 条且同一字段不重复；拒绝 `insert_transition_shot`（该动作只由服务端按成对结论执行） |

工具通过 `RequestContext` 读取 `auditJobId`、`auditPhase`、`auditWindowIndex`、`auditPairKey`；阶段或配对不匹配直接拒绝。`backend/src/agents/context.ts` 增加这四个上下文字段。工具不直接暴露数据库句柄给模型，所有写入由服务层校验后完成。聊天页不展示该 Agent；若通过接口绕过选择直接调用，请求没有 `auditJobId`，三个工具都会拒绝执行并返回「动作检验仅可通过检验任务触发」，避免聊天入口绕过快照与护栏。

| GET `/latest/:episodeId` | 最近一次任务 | 返回任务、问题、摘要、修复日志、撤销可用性、过期标记 |
| GET `/:id` | 按 ID 查询 | 用于页面恢复和按任务 ID 查询 |
| POST `/:id/undo` | 撤销本次修复 | 仅对完成或中断且存在快照的任务有效；返回恢复/跳过/冲突数量 |

路由参数类型守卫只接受 `storyboard_auditor`；其他 Agent 返回「该 Agent 不支持动作检验」。`/latest/:episodeId` 必须注册在 `/:id` 之前，避免把 `latest` 当成任务 ID。接口沿用现有 `success` / `badRequest` / `notFound` 响应格式。

过渡镜头接口复用现有 `backend/src/routes/merge.ts` 的断点路由：列表返回增加 `kind`、`scene_id`、`text_content`、`text_subtitle`、`edge_mode`；新增「创建自定义过渡」与「按类型重新生成」两个动作。创建时校验断点仍相邻、类型合法、场景属于当前项目且未删除、文字长度与时长在 2–5 秒内；文字视频走本地渲染，不创建模型任务。检验进行中调用创建/重生成接口返回明确错误「检验进行中，暂不能生成过渡镜头」。

### 6.5 全自动流程接入

- 在 `backend/src/services/automation.ts` 的步骤链第 750 行之后增加 `stepStoryboardAudit`，位于 `stepVideoPrompts` 与 `stepVideos` 之间。

## 8. 错误处理与边界

| 场景 | 处理 |
|---|---|
| 没有分镜 | 不创建任务；手动按钮禁用；自动触发跳过 |
| 剧集不存在或已删除 | 创建任务返回明确错误，不写半条数据 |
| 没有文本模型 | 只做规则检验；语义/修复/提示词补齐跳过；任务完成并标记 |
| 提示词批量运行中 | 等待最长 30 分钟；期间显示准备阶段 |
| 提示词批量失败/超时 | 继续检验；缺失提示词逐镜报错；语义窗口仍检查描述与连贯性 |
| 语义窗口失败 | 重试一次；仍失败记录窗口失败，继续其他窗口 |
| 成对连贯判定失败或无结论 | 重试一次；仍失败记录该对失败，后一个真实分镜置 `failed`，继续后续对；不阻断其他窗口 |
| 全部语义窗口失败 | 规则结果保留；摘要标记语义失败；不阻断自动化 |
| Agent 报告问题越界 | `report_storyboard_issues` 拒绝越界分镜、过渡分镜、检查 2 语义问题或非法问题码；该窗口按失败处理 |
| Agent 对过渡分镜报问题 | 工具拒绝；过渡分镜不参与任何检查，问题丢弃并记录原因 |
| 跨卡对复查仍断裂 | 记录新的 `semantic_continuity_break`，`relatedStoryboardIds` 含过渡分镜 ID，`repairable=false`，不再次插入 |
| 自动插入遇到只读分镜或无可用场景 | 不插入，问题标记 `manual`，面板给出人工处理建议；不影响其他修复 |
| 修复动作引用非本任务问题 | 拒绝该动作并记录原因 |
| 分镜已有视频/帧资产/配音 | 只读；可报问题，不自动修改；问题标记需人工 |
| 分镜在检验后被用户修改 | 指纹不一致；修复跳过该分镜；结果显示过期提示 |
| 修复后错误数增加 | 按快照整体回滚；冲突分镜保留并标记部分回滚 |
| 复查无法完成 | 按回滚处理，避免未验证修改留在数据里 |
| 撤销时用户已再次修改 | 跳过冲突分镜，恢复其余分镜，返回冲突数量 |
| 资产绑定无效或资产图缺失 | 检查 5 报错误/警告，不自动改绑定、不生成资产图；面板提供资产页跳转 |
| 过渡断点已不相邻 | 创建/重生成返回明确错误「断点已变化，请刷新后重试」，不写半条记录 |
| 过渡类型、场景、文字或时长非法 | 创建接口拒绝并返回具体字段错误；不创建任务 |
| 过渡生成失败 | 保留之前的已完成视频和指纹；状态置失败并记录原因；合片继续回退原转场 |
| 文字视频渲染失败 | 过渡置失败并提示；不回退到视频模型、不影响分镜与合片 |
| 检验进行中请求生成过渡 | 返回「检验进行中，暂不能生成过渡镜头」，不创建任务 |
| 逐镜状态写入失败 | 检验继续；只记录日志，前端按任务整体状态显示，不据此回滚分镜 |
| 应用重启 | 未完成任务标记中断；`running` 分镜回到 `pending`；修复/复查阶段先按快照回滚；不自动续跑；可撤销已有快照 |
| 重新拆分 | 进行中的检验标记中断；修复/复查阶段先回滚；新拆分完成后重新触发检验 |
| 全自动流程停止 | 审计阶段直接中断；修复/复查阶段先回滚再中断 |
| 任务记录写入失败 | 检验仍可继续；只记录日志，不影响分镜数据 |
| 快照超过 1MB | 放弃修复，不改数据，问题保留为需人工 |

## 9. 测试与验收

### 9.1 后端规则测试

- 空镜阈值：7.9 秒有角色不报；8 秒警告；11.9 秒警告；12 秒错误；5.9 秒无人物不报；6 秒无人物警告；有旁白不算空镜。
- 台词容量：20 字需要 6 秒；有效 5 秒缺口 1 秒为警告；有效 4.9 秒为错误；整镜总需求超过时长报错；有效时长超过需要时长 3 秒以上警告；单句超过 6 秒建议拆分。
- 没有音频、计划时长和占位时长的句子只计入整镜总容量，不单独判定该句；总容量仍按每句需要时长求和校验。
- 标点、空白、英文和中英混排的字符计数；`speak_text` 优先于 `text`。
- 字段完整性：描述/提示词缺失为错误；景别/角度/运镜缺失为警告。
- 视频提示词：信息头缺失、时间段断裂、结束时间不符、3 秒段超过 12 字、动作/表情短语出现在台词中。
- 连贯性规则：第二镜起 `continuity` 为空警告；第一镜豁免；跨场景硬切且无连贯性警告；相邻两镜之间有过渡分镜时上述规则提示和时间跳变提示都跳过。
- 时间跳变规则：日/夜等时间跨度大的硬切只报 `adjacent_time_jump` info，`repairable=false`，不带 `suggestedTransition`；有过渡分镜时跳过。
- 过渡分镜跳过：`transition_kind` 非空的分镜不参与任何规则检查（字段完整性、空镜、台词容量、资产、连贯性），也不进入窗口规划。
- 资产检查：`scene_id` 为空警告；场景不存在/已删除/跨项目错误；项目内未关联本集为提示；角色/道具绑定无效错误；重复绑定警告；`@角色名` 已绑定通过、未绑定警告、未知警告、同名多角色警告；绑定资产 `image_url` 为空警告；`reference_images` 非法 JSON 或元素非法警告；相对路径文件缺失警告；外链不探测。
- 问题码白名单：检查 5 的 15 个问题码全部可报；未登记问题码被拒绝；`semantic_asset_mismatch` 只用于检查 5；`suggestedTransition` 只允许检查 2 且值限于 `empty` / `scene` / `text`；规则时间跳变不允许携带。
- 问题去重、严重级别合并、单窗口/单任务数量上限；检查 2 规则问题与语义问题不合并，跨卡语义问题凭过渡分镜 ID 与原始断点问题区分。

### 9.2 窗口、成对判定、状态与指纹测试

- 16 镜、17 镜、40 镜、301 镜、302 镜的窗口数量与范围；重叠 1 镜；剩余不足 2 镜并入上一窗；超过 20 窗截断；过渡分镜不占窗口名额。
- 窗口上下文包含前后只读分镜；问题只归属窗口内目标分镜。
- 成对规划：N 个真实分镜产生 N-1 个普通相邻对；中间隔 1 个或多个过渡分镜时产生跨卡对，过渡分镜不单独成对；每对只归属一个窗口，不重复判定。
- 成对上下文：一次请求只包含一对分镜的完整视频提示词、两侧角色组、场景/地点/时间、中间过渡卡类型与文字，不包含其他分镜的摘要替代。
- 成对结论：`continuous` 不生成问题；`broken` 生成一条 `semantic_continuity_break`，主分镜是后一个真实分镜，跨卡对 `relatedStoryboardIds` 含过渡分镜 ID；无结论按失败处理并重试一次；第二次仍失败标记 `pairFailed`。
- 逐镜状态：任务创建普通分镜 `pending`、过渡分镜 `done + transition=true`；窗口开始目标镜 `running`、结束 `done`；重叠上下文镜不被改成 `running`；成对失败只把后一个真实分镜置 `failed`；窗口失败目标镜 `failed`；超过窗口上限的分镜 `done + rule_only`；无模型时全部 `done + rule_only`；中断时 `running` 回到 `pending`；任务失败时 `running` 变 `failed`；删除分镜从状态映射移除。
- 状态写入次数：每个窗口一次、终态一次；状态写入失败不影响检验结果。
- 过期点：检验后修改分镜，读取时叠加 `stale` 标记，但 `shot_status_json` 仍为 `done`；过渡分镜修改后同样标记过期。
- 分镜/台词指纹对字段变化敏感；用户修改后修复跳过、结果标记过期。
- 摘要写入 `pairTotal` / `pairDone` / `pairFailed` / `pairBroken`，与窗口统计一致。

| 自动修复改坏分镜 | 创作内容被错误修改 | 资产/配音护栏、字段白名单、快照、复查、错误数增加回滚、手动撤销 |
| 修复与用户手工编辑冲突 | 覆盖用户新改动 | 指纹校验；修复和撤销都跳过冲突分镜；面板提示过期 |
| 检验成本高 | 相邻对逐对判定加窗口检查，整集模型调用次数上升 | 每对只判一次并归属后一镜窗口；窗口 16 镜、最多 20 窗、单窗口问题上限；只复查涉及窗口与跨卡对；异步任务与任务中心 |
| 等待提示词时间过长 | 用户以为卡住 | 准备阶段显示等待；30 分钟上限；超时继续并逐镜报缺失 |
| 语义窗口边界漏判 | 跨窗口动作不连贯 | 16 镜重叠 1 镜；额外携带前后只读分镜；问题归属后一镜 |
| 规则口径与拆分提示词不一致 | 用户困惑为什么拆分通过但检验报错 | 文档明确检验口径为 4 字/秒 + 1 秒呼吸；只影响检验，不改拆分规则；修复只做安全延长 |
| 自动触发与批量提示词/视频生成竞争 | 检验结果过期或误改 | 每集单任务；准备阶段等待；检验中前端禁用生成入口；指纹与资产护栏兜底 |
| 任务表 JSON 膨胀 | 数据库变大 | 每集保留最近 20 次；问题/窗口数量上限；不复制媒体文件 |
| 桌面模板升级遗漏 | 旧用户没有检验提示词/技能 | 新文件随模板版本 9 补齐；提示词强制覆盖；技能只增不覆盖；验收检查旧 workspace |
| 全自动流程被检验拖慢 | 整体耗时增加 | 检验异步等待但设上限；失败不阻断；只有规则结果时快速通过 |
| 自动插入过渡分镜（真实 `storyboards` 行） | 镜头号重排，破坏 `@镜头N末帧`、帧资产、视频提示词和用户认知 | 只由 AI `broken` 判定触发；单断点最多一次、整集最多 3 次；事务内插入并重排编号、改写 `@镜头N末帧`、同步末帧资产；受影响分镜含只读、资产或进行中任务时拒绝插入；快照可回滚；验收断言插入 → 回滚后编号、引用、资产与过渡行完全复原 |
| AI 误判断点导致多余过渡镜头 | 多出一镜，叙事被稀释 | 成对判定必须给出 verdict 与证据；`broken` 才允许建议过渡；同一断点最多插入一次；面板显示插入结果并可撤销本次修复；回滚删除插入行并还原编号 |
| 文字视频字体缺失或渲染失败 | 过渡片段黑屏、乱码或缺失 | 复用现有 ASS/ffmpeg 字体与样式；渲染失败保留旧产出并报错；验收检查中英文和长文本 |
| 场景图缺失后降级 | 用户以为场景过渡已生效 | 场景图缺失降级文字视频或纯文字提示；界面明确显示降级原因 |
| 资产问题误报 | 用户被已存在的项目资产打扰 | 项目内已存在但未关联本集按提示处理；只有缺失、删除、跨项目或文件不存在才报错/警告 |
| 自定义过渡被相邻视频误判过期 | 用户改镜头视频后空镜/文字片段全部失效 | `ai` 用断点指纹，`empty` / `scene` / `text` 用独立指纹；只有自身参数变化才过期 |
| 逐镜状态与真实任务脱节 | 卡片显示检查中但任务已结束 | 状态只由任务层按窗口写入；读取时按任务状态兜底；重启把 `running` 重置为 `pending` |
| 过渡生成与检验竞争 | 过渡片段使用旧首尾帧或覆盖检验结果 | 检验期间禁用过渡生成/重生成；过渡创建不写分镜快照；指纹与资产护栏兜底 |
| `video_transitions` 迁移失败 | 旧库启动报错或丢数据 | 启动 `ALTER TABLE ADD COLUMN` 幂等；默认 `ai`；迁移测试在含历史行的库上重复执行 |

## 12. 明确不做

- 不做已生成视频、字幕或成片画面的内容审查；只检验分镜规划文本、台词时长、资产绑定与资产文件有效性，不做画面质量判断。
- 除动作检验自动插入过渡分镜外，不新增、删除或重排 `storyboards` 行；自动插入只允许来自 AI `broken` 判定，单断点最多一个、整集最多 3 个，插入后重排编号并改写引用，受影响分镜含只读、资产或进行中任务时拒绝；场景/角色/道具绑定只做检验和提示，不自动改绑定。
- 手动或 AI 过渡片段仍走 `video_transitions`：只写片段、不插入分镜行、不进入分镜快照或撤销；允许的类型只有 `empty` / `scene` / `text`。自动插入的过渡分镜是真实分镜行（带 `transition_kind`），参与编号重排、跳过后续检验、进入快照与撤销。
- 不自动拆句、不改台词文本、不新增台词或旁白、不改说话人和音色。
- 不自动修改已有视频、任意帧资产或已有配音的分镜。
- 不做多轮自动修复；一轮修复、一次复查，之后交人工。
- 不做按集或按项目的检验开关；检验策略与提示词在设置页统一管理，拆分完成与全自动流程始终自动触发，手动按钮随时可用。
- 不做跨集批量检验、历史趋势对比和问题忽略标记。
- 不做检验面板内直接编辑分镜；编辑仍回到现有检查器。
- 不改变分镜拆分提示词、拆分方式、视频提示词格式、ComfyUI 时间轴和现有 AI 过渡的生成/合片契约；过渡扩展只做增量，历史 `ai` 行为不变。
- 不把动作检验作为全自动流程的强制门禁；它是质量提示与安全修复，不阻断视频生成。
