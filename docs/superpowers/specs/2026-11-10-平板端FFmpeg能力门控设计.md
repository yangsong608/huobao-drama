## 1. 背景与目标

### 1.1 问题

平板和手机以浏览器 PWA 访问服务器，FFmpeg/FFprobe 只存在于服务端，客户端本身不执行媒体转码。本期明确「平板/手机不需要 FFmpeg 相关功能」，但当前代码把 FFmpeg 能力分散在合片、导出、混音、配音、抽帧、宫格切分等多个入口：

- 有的入口已经检查 FFmpeg（导出页 `ExportStage.vue` 的检查项），有的入口只会在执行时抛错；
- 有的能力失败会中断整条自动流程（`stepDub` 调用 `startDubbing`，后者必须合片），有的能力失败可以静默降级（海报帧、波形）；
- 如果只在平板上按 UA 隐藏按钮，桌面连到没有 FFmpeg 的服务器时仍会看到可点击但必然失败的入口；平板连到有 FFmpeg 的服务器时又会被无谓禁用。

因此门控不能按设备类型，必须按**当前连接的服务端能力**。经电脑扫码接力访问时，「当前服务端」就是被连接的那台电脑：电脑有 FFmpeg 则手机/平板可触发产出动作、任务在电脑执行；电脑没有则两端一致显示「暂未开放」。设备类型不参与判定，也不会因为请求来自手机而降级。

### 1.2 本期目标

1. 服务端提供一个稳定的媒体能力查询接口，作为全部客户端判断 FFmpeg 相关功能的唯一依据。
2. 只门控「主要产物必须依赖 FFmpeg/FFprobe」的动作；编辑、预览、播放、方案与台词编辑保持可用。
3. 所有 FFmpeg 入口都有明确行为：前端显示「暂未开放」或降级提示，直接调用接口返回可识别的 503，不留死按钮和模糊报错。
4. 能力查询失败按不可用处理（fail-closed），但必须给出重试入口，不伪装成可用。
5. 桌面、平板、手机使用同一套判断；服务端缺少 FFmpeg 时，桌面同样显示标识。
6. 全自动流程遇到 FFmpeg 不可用时跳过配音与合片阶段并留下说明，不把整条流程判失败；用户恢复 FFmpeg 后可手动重试。

### 1.3 非目标

- 不在浏览器或平板本地运行 FFmpeg，不引入 ffmpeg.wasm、MediaBunny 等客户端转码链路。
- 门控本身不引入用户账号、租户或权限体系；扫码接力的设备会话是独立跨端设计的范围，不并入能力门控，也不作为门控的判定条件。
- 不改写 FFmpeg 的实际执行逻辑、转码参数、合片算法与 ComfyUI 模板。
- 不做「无 FFmpeg 时仍能合片/导出/混音」的替代实现。
- 不为旧版前端做兼容分支；前后端按同一版本部署。

### 2.6 约束

- 应用没有应用级登录；能力接口只暴露布尔值与时间，不暴露文件系统路径、版本细节或密钥。
- 默认端口 5679 不得直接暴露公网；平板必须经 HTTPS 反向代理访问。
- 不修改用户已选择的模型、服务与媒体目录来掩盖能力缺失；只报告并让用户修复。
- 不提交、不构建、不安装、不重启应用，除非用户明确要求。
- 新增文案必须同步 zh、en、ja、ko 四份 locale；技术标识保持英文。
- 文档与测试不得写入真实域名、IP、证书路径、密码、Token 或 `PUBLIC_BASE_URL` 实际值。

## 3. 已确认决策

| 编号 | 决策 | 含义 |
| --- | --- | --- |
| D1 | 按服务端能力判断，不按设备类型 | 不读取 UA、不判断平板/手机；只看当前连接的服务端是否具备 ffmpeg/ffprobe |
| D2 | 只门控产出动作 | 合片、导出、混音渲染、分离、配音/音色生成、剪辑导出、抽帧、宫格切分、图文动画等；编辑、预览、播放、方案编辑保持 |
| D3 | 覆盖全部 FFmpeg 入口 | 不只首屏五个按钮；包括宫格切分、配音/音色与声音片段、音频素材导入探测、剪辑视频素材导入探测、声音生成、抽帧、图文动画等 |
| D4 | 失败即不可用 | 能力接口请求失败、超时、返回异常或服务端版本过旧，前端一律按不可用处理并给重试 |
| D5 | 所有客户端一致 | 服务端缺少 FFmpeg 时，桌面、平板、手机看到相同的「暂未开放」标识 |
| D6 | 自动化跳过并标记，直接接口 503 | 自动流程跳过配音/合片并写入说明，不判整条失败；直接调用被门控接口返回 503 |

## 4. GitHub 替代方案评估

本期需要判断是否能用浏览器端方案替代服务端 FFmpeg。结论是**不能作为本期主链路替代**。

| 方案 | 事实 | 适合度 |
| --- | --- | --- |
| ffmpeg.wasm/ffmpeg.wasm | MIT，约 1.8 万星；浏览器 WASM；官方标注实验性；大文件受内存、线程与耗时限制 | 不适合整集转场、字幕烧录、多轨混音；平板算力与电量不可控 |
| Vanilagy/mediabunny | MPL-2.0，约 7 千星；纯 TypeScript + WebCodecs；擅长解封装、封装、剪切、拼接、转码 | 只能覆盖简单的剪切/拼接/转码；没有完整滤镜图、xfade、字幕烧录与多轨混音 |
| Yahweasel/libav.js | LGPL，约 500 星；把 libav 库编译到 WASM | 集成重、包体大，仍需为每个滤镜与容器做适配 |
| arthenica/ffmpeg-kit-next | 原 ffmpeg-kit 已退役；社区延续版为源码分发，LGPL-3.0，支持 Android/iOS/Web/WASM | 只适合未来原生壳；当前 PWA 不引入原生壳，本期不适用 |

**结论：** 本期保留服务端 FFmpeg 作为唯一产出链路；客户端只负责能力显示与禁用。未来若做原生壳，可再评估 ffmpeg-kit-next，但不属于本期。

## 5. 能力模型与接口

### 5.1 字段

服务端新增媒体能力快照，只包含布尔值、缺失项与探测时间：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `media.ffmpeg` | boolean | ffmpeg 二进制可执行 |
| `media.ffprobe` | boolean | ffprobe 二进制可执行 |
| `media.outputActions` | boolean | 当前为 `ffmpeg && ffprobe`；合片、导出、混音、抽帧等产出的总开关 |
| `media.audioSeparation` | boolean | 当前为 `ffmpeg && ffprobe`；为未来不依赖 FFmpeg 的分离引擎保留独立字段 |
| `media.voiceActions` | boolean | 当前为 `ffmpeg && ffprobe`；配音、Takes、样音、音色生成与克隆的总开关 |
| `media.missing` | string[] | `ffmpeg`、`ffprobe` 中缺失的项，供提示与排查 |
| `media.checkedAt` | string | 最近一次探测时间，ISO 8601 |

**不返回** 二进制路径、目录、版本号或环境变量值；这些只保留在设置页既有 `GET /settings/media` 中。

### 5.2 查询接口

`GET /api/v1/capabilities`

- 成功返回统一信封：`code: 200`，`data.media` 为上述字段。
- 只读，不触发任何生成、写入或配置变更。
- 首次请求惰性探测；不要求应用启动时阻塞探测。
- `?refresh=1` 强制重新探测，用于前端重试与排障。
- 单次探测最坏等待 10 秒（二进制存在但无响应）；前端必须有 loading 状态，不得空白或假可用。

### 5.3 缓存与失效

- 进程内缓存，TTL 30 秒；成功与失败都缓存，避免每次页面请求都启动子进程。
- `PUT /api/v1/settings/media` 保存成功后失效缓存；设置页随后的能力刷新会得到新结果。
- `?refresh=1` 绕过 TTL。
- 多进程部署时缓存按进程独立；保存设置只失效处理该请求的进程，其他进程最多 30 秒后更新。本期按单进程运行设计，不引入跨进程广播。
- 不使用 `checkFfmpegSuite()` 的成功缓存作为能力快照来源，因为它永远不会缓存失败且不带时间戳；新服务包装 `getFfmpegStatus()` 并按 TTL 缓存。

### 5.4 失败语义

- 探测函数抛错、超时、路径不存在、二进制不可执行，一律得到 `false`，不返回 500。
- 能力接口自身异常时返回 `code: 200` 与全 false 的完整快照，不返回 503；实现必须保证结构始终可解析，避免前端把网络错误与能力缺失混淆。
- 前端请求失败（网络、超时、404、非 2xx、结构不合法）一律进入 `failed`，按不可用处理；只有明确拿到 `outputActions: true` 才允许产出动作。

### 5.5 被门控接口的 503 契约

被门控的写接口在执行任何副作用（解析请求体、写库、启动任务）之前检查能力；不可用时返回：

- HTTP 503
- `code: 503`
- `message`: 当前服务端未检测到 FFmpeg/FFprobe，该功能暂未开放
- `error_code`: `MEDIA_UNAVAILABLE`

前端 API 封装需要保留 `error_code`，用于本地化提示与刷新能力；现有 `error.status`、`error.code` 行为不变。

服务端提供四种门控检查，按接口所需能力选择：

- `outputActions`：合片、过渡、导出、混音、剪辑导出、抽帧、宫格切分、图文动画。
- `audioSeparation`：原声分离；当前与 `outputActions` 同值，字段独立以便未来接入不依赖 FFmpeg 的分离引擎。
- `voiceActions`：配音、Takes、单句/整集合成、声音片段、样音、试听、克隆参考音频、音色同步。
- `ffprobe`：直接检查 `media.ffprobe`；用于音频素材导入、剪辑视频素材导入、声音生成落盘等只需要读时长的动作。

### 5.6 读接口与编辑接口

以下操作不因媒体能力缺失返回 503：

- 读取列表、详情、状态、进度、检查项、历史记录；
- 保存剧本、分镜、台词、混音计划、转场提示词/参考图、时间线草稿、剪辑工程与版本；
- 播放已有视频/音频、下载已有成片、切换当前成片版本；
- 上传图片、音频素材（仅存储，不探测）；
- 生成文本提示词、字幕文本、分镜拆分等不依赖 FFmpeg 的 AI 任务。

例外：波形与剪辑缩略帧的既有 503 保持不变，属于可降级的读取增强，不是新的能力门控。

## 6. 门控矩阵

原则：只有「主要产物必须依赖 FFmpeg/FFprobe」的动作才加新门控；已有明确降级路径的动作保持降级。所有门控在路由入口执行，先于请求体解析与写操作。

### 6.1 合片与过渡

合片与过渡路由挂载在 `/api/v1/merge` 下，下表按浏览器实际请求路径书写。

## 7. 全自动流程

### 7.1 跳过位置

在 `backend/src/services/automation.ts` 的 `stepDub()` 中，按以下顺序判断：

1. 未开启自动配音：保持现状，写入「未开启自动配音，已跳过」，不保留到最终说明。
2. 开启自动配音但 `media.voiceActions` 或 `media.outputActions` 为 false：写入「当前服务端未检测到 FFmpeg/FFprobe，已跳过自动配音与合片；请在设置页恢复媒体工具后手动重试」，记录 `skip-dub` 日志（原因 `media_unavailable`），返回该说明。配音既需要生成音频，也必然触发合片，因此两个开关必须同时为真。
3. 未配置语音服务：保持现状，跳过。
4. 能力可用且已配置语音服务：执行现有 `startDubbing` 流程。

能力检查必须在 `extractEpisodeLines` 与 `startDubbing` 之前，避免产生无意义的台词抽取与任务记录。

### 7.2 说明保留

- `updateProgress()` 已支持 `note`；跳过时把说明写入 `automationNote`。
- `finishRun()` 增加可选 `note` 参数；`done` 时写入该说明，没有说明时仍为 null，保持现有正常完成的界面。
- `startAutomation` 的完成序列保存 `stepDub` 返回的说明，先写入 `done` 进度，再调用 `finishRun(episodeId, 'done', undefined, note)`。
- 失败与停止路径不写入跳过说明，仍按现有错误语义处理。

### 7.3 状态语义

- 自动流程整体仍为 `done`，阶段 `done`，进度 100；不新增阶段、不新增数据库字段。
- `automationNote` 是唯一可见的「已跳过配音/合片」说明，剧集详情与流水线状态已有读取位置。
- 用户恢复 FFmpeg 后可手动启动配音或重新运行自动流程；本期不做自动续跑。

### 7.4 可测试性

- 将 `stepDub` 或其中的能力判断导出为可测试函数，测试直接构造「开启自动配音 + 已配置语音服务 + FFmpeg 不可用」的剧集，断言返回说明且没有创建配音任务、没有抽取台词。
- 测试 `finishRun(episodeId, 'done', undefined, note)` 保留说明；`finishRun(episodeId, 'done')` 仍清空说明。
- 测试失败/停止不保留成功说明。

## 8. 前端设计

### 8.1 状态机

前端只维护一份模块级能力状态：

| 状态 | 触发 | 产出动作 | 界面 |
| --- | --- | --- | --- |
| `idle` | 应用启动、尚未请求 | 禁用 | 视为加载中 |
| `loading` | 首次请求或重试中 | 禁用 | 「正在检测媒体能力…」 |
| `ready` | 请求成功且结构合法 | 按动作依赖字段决定 | 可用时不显示提示 |
| `ready` 且字段为假 | 请求成功，当前动作依赖的字段为 `false` | 该动作禁用 | 「暂未开放」+ 原因 + 设置提示 |
| `failed` | 网络、超时、404、非 2xx、结构不合法 | 禁用 | 「无法检测媒体能力，产出功能暂不可用」+ 重试 |

派生值：

- `outputReady = state === 'ready' && media.outputActions === true`
- `separationReady = state === 'ready' && media.audioSeparation === true`
- `voiceReady = state === 'ready' && media.voiceActions === true`
- `probeReady = state === 'ready' && media.ffprobe === true`
- `blockReason` 按动作依赖计算：`loading` / `failed` / `unavailable` / `null`；`unavailable` 仅当该动作依赖字段为 `false`
- 只有 `unavailable` 显示「暂未开放」；`loading` 与 `failed` 不能伪装成「暂未开放」，必须有不同文案。

### 8.2 组合式与启动加载

- 新增 `frontend/app/composables/useMediaCapabilities.ts`，模块级单例，导出只读状态、`ensureLoaded()`、`refresh(force)`、`outputReady` 与 `blockReason`。
- 新增客户端插件在应用启动时调用一次 `ensureLoaded()`；重复调用幂等，不重复请求。
- 桌面 Electron 壳同样加载能力状态，不得沿用 `pwa.client.ts` 的桌面壳跳过逻辑；D5 要求桌面与浏览器显示一致。
- 打开产出页面时再次调用 `ensureLoaded()`，保证从后台恢复或网络恢复后能补齐状态。
- 不使用轮询；只在启动、页面进入、用户重试、设置保存、收到 `MEDIA_UNAVAILABLE` 时刷新。
- 请求失败不自动无限重试；由用户点击「重试」或设置保存触发。

### 8.3 提示组件

新增 `frontend/app/components/MediaCapabilityNotice.vue`，支持两种形态：

- `banner`：页面或产出区域顶部整条提示，包含标题、说明、重试/设置入口。
- `inline`：按钮旁或卡片内的紧凑标识，显示「暂未开放」。

状态文案：

- loading：正在检测媒体能力…
- failed：无法检测媒体能力，产出功能暂不可用。请检查网络后重试。
- unavailable：当前服务端未检测到 FFmpeg/FFprobe，合片、导出、混音、配音等产出功能暂未开放；剧本、分镜、预览、播放与编辑仍可用。
- ready：不渲染。

可访问性：使用 `role="status"` 与 `aria-live="polite"`；重试按钮有明确标签；颜色不是唯一信息载体。

## 9. 验收

### 9.1 后端

- 能力接口：有效二进制返回 true；无效 `FFMPEG_BIN`/`FFPROBE_BIN` 或不存在路径返回 false；响应不含路径、版本与环境变量。
- 缓存：TTL 内重复请求不重复探测；`?refresh=1` 强制探测；保存设置后失效；失败结果也被缓存，避免每次请求都等待超时。
- 门控：按 §6 的每个门控接口在不可用时返回 503 `MEDIA_UNAVAILABLE`，且不产生写操作、不启动任务；对应读接口与编辑接口返回 200。覆盖合片与过渡、导出、混音与试听、原声分离、配音与 Takes、整集/单句合成、声音片段、样音、音频素材导入、声音生成、剪辑导出、剪辑视频素材导入、末帧抽取、宫格切分、图文动画。
- 自动化：缺少 FFmpeg 时自动流程完成，`automationNote` 保留跳过说明，未创建配音任务、未抽取台词、未合片；恢复后手动配音可执行。
- 现有测试：后端全量测试、类型检查、schema 校验通过；新增测试使用隔离数据库与临时目录，不读取开发库。

### 9.2 前端

- 结构测试覆盖：组合式状态机、插件只加载一次、提示组件四种状态、按钮绑定、四语键一致、无设备类型分支。
- 静态检查：`outputReady` 只在 `ready && outputActions` 时为 true；`failed` 与 `unavailable` 文案不混用。
- 现有前端测试全绿；新增文案不破坏既有键。

### 9.3 运行时

在隔离数据目录、独立端口启动后端，分别验证：

1. **能力可用**：使用本机有效 FFmpeg/FFprobe。能力接口为 true；平板视口与桌面视口均不显示「暂未开放」；导出、合片、混音、配音入口可点击。
2. **能力不可用**：仅对测试进程设置无效的 `FFMPEG_BIN`/`FFPROBE_BIN`，不修改用户设置。能力接口为 false；平板与桌面都显示标识；按钮禁用；直接 `curl` 门控接口得到 503 `MEDIA_UNAVAILABLE`；读接口与编辑接口正常；自动流程完成并留下跳过说明。
3. **恢复**：在设置页保存正确目录或调用 `?refresh=1`，无需重启即可恢复；按钮重新可用；恢复后手动配音成功。
4. **失败注入**：临时让能力接口不可达或返回非 2xx，前端进入 `failed`，显示重试；重试成功后恢复。
5. **回归**：播放、预览、剧本/分镜/台词编辑、混音计划编辑、剪辑工程编辑、素材上传均不因能力缺失被阻断。

### 9.4 阻塞条件

以下情况必须标「阻塞」，不得用结构测试代替：

- 没有可运行的后端或没有隔离数据库；
- 没有可用 FFmpeg 与不可用 FFmpeg 两组运行环境；
- 没有平板/手机真机或等效视口与触控环境；
- 部署环境缺少 HTTPS 反代、访问控制或真实媒体地址配置。

## 10. 风险与开放项

| 风险/开放项 | 影响 | 处理 |
| --- | --- | --- |
| 前后端版本不一致 | 旧后端没有 `/capabilities`，新前端 fail-closed 会禁用全部产出 | 部署必须同版本；`failed` 文案提示检查服务端版本 |
| 旧前端连新后端 | 旧前端不识别 `MEDIA_UNAVAILABLE`，只显示通用错误 | 本期不兼容旧前端；发布说明要求刷新/更新前端 |
| TTS 只需 ffprobe 的场景被一并门控 | WAV-only TTS 理论上可在无 ffmpeg 时工作 | 本期按 D3 统一门控；未来可用纯 JS WAV 时长解析单独放开，不纳入本期 |
| 多进程缓存不一致 | 保存设置后其他进程最多 30 秒仍旧 | 本期单进程；多进程部署需在发布说明标注 |
| 生成链路内部 FFmpeg 依赖 | 多段拼接/静音剥离可能失败 | 不全局门控；要求明确错误文案与页面提示 |
| 可选增强降级不显眼 | 海报帧、波形、缩略帧缺失可能被误认为故障 | 使用占位图与轻提示；不阻断主流程 |
| 能力探测首次耗时 | 首次请求最多等待 10 秒 | 前端 loading 状态；后续 TTL 缓存 |
