# 小说工作台落地方案

- 状态：设计稿，未实施
- 日期：2026-11-06
- 定位：在现有小说详情页与写作面板上做增量增强，不新建第二套小说页面
- 上游方案：[全链路集成与优化方案](./2026-11-06-全链路集成与优化方案.md)
- 关联方案：[导演台落地方案](./2026-11-06-导演台落地方案.md) · [智能体落地方案](./2026-11-06-智能体落地方案.md) · [页面视觉优化落地方案](./2026-11-06-页面视觉优化落地方案.md)

## 1. 结论

小说工作台不推翻现有六个 Tab。它只补四个缺口：

1. 章节树：不改变章节号语义，只做导航与状态展示。
2. 引文批注：为改编保留“为什么改、改哪里”的证据。
3. 伏笔板：把散落在章节蓝图里的伏笔变成可追踪状态。
4. 改编上下文包：把已选章节、架构、人物动态、未回收伏笔、批注压缩成一段可注入的改编提示。

四个能力都挂在现有写作 Tab 内，首版默认三栏 split；旧 Tab 布局保留为配置回退。

## 2. 现状与复用

| 现有能力 | 代码落点 | 结论 |

| 章节写作、阅读/编辑模式、自动保存 | `frontend/app/components/novel/ChapterWriterPanel.vue:91-98`、`:306-323` | 复用，不改保存协议 |

| 故事坐标（时间线、世界地图） | `ChapterAtlasCard` 与 `novel.timelineEvents` / `novel.worldMap` | 保留为资料页，不并入伏笔板 |
| 小说导入短剧、增量同步 | `frontend/app/components/novel/ImportToDramaDialog.vue`、`backend/src/services/novel-import.ts` | 只增加“附带上下文包”选项 |

现有写作 Tab 的真实缺口：

- 章节只能通过下拉框切换，长篇小说无法快速定位。
- 正文没有批注锚点，改编时无法回看“这一段为什么重要”。
- 伏笔只存在于蓝图文本和生成提示词里，没有“埋设/强化/回收”状态。
- 导入短剧只带架构五件套，未带批注和未回收伏笔。

## 3. 范围与非目标

### 3.1 范围

- 写作 Tab 的桌面端三栏布局：章节树 / 正文 / 资料检查器。
- 引文批注的创建、编辑、解决、失效提示。
- 伏笔的手工维护与可选 AI 提取。
- 改编上下文包的预览、导入时注入。
- 人物档案的只读汇总（可选阶段）。

### 3.2 非目标

- 不做多人协同、评论回复、@提醒。
- 不做富文本编辑器；正文仍是纯文本 textarea。
- 不做第二套章节表或第二套正文存储。
- 不改变章节生成、定稿、增强的现有任务链路。
- 不把小说人物直接写成短剧角色；仍走现有导入/提取流程。
- 不做移动端专属布局，窄屏回退到现有单栏。

## 4. 目标形态

### 4.1 写作 Tab 三栏

```text
┌ 章节树 240px ┬ 正文编辑区 flex ┬ 资料检查器 320px ┐
│ 第 1 章 定稿 │ 标题 / 模式 / 字数 / 保存状态      │ 批注 | 伏笔 | 人物 | 上下文包 │
│ 第 2 章 草稿 │                                  │ 选中引文与备注               │
│ 第 3 章 未写 │ 正文 textarea / 阅读视图          │ 伏笔状态与回收章             │
└──────────────┴──────────────────────────────────┴────────────────────────────┘
```

- 章节树固定在写作 Tab 内，不进入其他 Tab。
- 窄于 1180px 时，资料检查器改为抽屉；窄于 860px 时，章节树也改为抽屉。
- 现有章节下拉框保留，作为窄屏和小说的快速跳转入口。
- 阅读模式继续使用现有 `chapter-reader`，只增加阅读字号变量。

### 4.2 三种使用状态

| 状态 | 用户看到什么 | 不出现什么 |
| --- | --- | --- |
| 浏览 | 章节树、字数、状态；正文只读 | 不自动弹出批注输入框 |
| 写作 | 正文可编辑、自动保存、批注锚点高亮 | 不把批注写进正文 |
| 改编 | 勾选章节与资料，预览上下文包，再导入 | 不直接改写短剧数据 |

## 5. 配置化设计

继续使用 `app_settings` 键值表（`backend/src/db/schema.ts:435`），不新增配置表。键统一使用 `novel.*` 前缀，值用字符串或 JSON；读取时清洗，写入时钳制。

| 配置键 | 类型 / 默认 | 范围 | 作用 | 紧急环境变量 |
| --- | --- | --- | --- | --- |
| `novel.workbench.layout` | `split` | `tabs` / `split` | 写作 Tab 使用三栏布局还是旧下拉布局 | `NOVEL_WORKBENCH_LAYOUT` |
| `novel.workbench.tree` | `true` | 布尔 | 三栏模式下是否显示章节树 | 无 |
| `novel.annotations.enabled` | `true` | 布尔 | 是否显示批注能力 | `NOVEL_ANNOTATIONS` |
| `novel.annotations.anchorWindow` | `200` | 20–1000 | 引文偏移失效后，在多长范围内重新定位 | 无 |
| `novel.foreshadow.enabled` | `true` | 布尔 | 是否显示伏笔板 | `NOVEL_FORESHADOW` |
| `novel.foreshadow.autoExtract` | `false` | 布尔 | 是否允许从章节蓝图提取候选伏笔 | 无 |
| `novel.contextPack.enabled` | `true` | 布尔 | 导入短剧时是否显示上下文包选项 | `NOVEL_CONTEXT_PACK` |
| `novel.contextPack.includeAnnotations` | `true` | 布尔 | 上下文包默认是否带批注 | 无 |
| `novel.contextPack.includeUnresolved` | `true` | 布尔 | 上下文包默认是否带未回收伏笔 | 无 |
| `novel.contextPack.maxChars` | `4000` | 500–20000 | 上下文包最大字符数，超出按整句截断 | 无 |

约定：

- 默认 `layout=split`，升级后写作 Tab 直接进入三栏；`tabs` 保留为兼容回退，不删除旧布局。
- 窄屏由页面响应式规则收起章节树/检查器，不改变配置值。
- 环境变量只用于紧急回滚，优先级高于数据库；不提供页面入口修改环境变量。
- 关闭某个能力只隐藏入口，不删除已有数据。
- 现有 `novel.autosaveMs`、`novel.importTargetWords`、`novel.defaultWritingStyleKey` 不变。

## 6. 数据设计

只新增两张表，均按 `novel_id` 归属，删除小说时软删或级联清理。

### 6.1 `novel_annotations`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | integer PK | 批注 id |
| `novel_id` | integer | 小说 id |
| `chapter_no` | integer | 章节号 |
| `quote` | text | 被选中的原文，最长 500 字 |
| `start_offset` | integer | 以 JavaScript 字符串下标计的起始位置 |
| `end_offset` | integer | 结束位置，不含 |
| `prefix` | text | 前 40 字，用于重新定位 |
| `suffix` | text | 后 40 字，用于重新定位 |
| `note` | text | 批注正文，最长 2000 字 |
| `kind` | text | `note` / `adapt` / `question`，默认 `note` |
| `status` | text | `open` / `resolved` / `orphaned`，默认 `open` |
| `created_at` / `updated_at` | text | 时间 |

索引：`(novel_id, chapter_no, status)`。

锚点规则：

1. 保存时以正文纯文本为准记录 `start_offset` / `end_offset`，不用 DOM Range。
2. 加载时先校验 `content.slice(start, end) === quote`。
3. 不相等时在 `anchorWindow` 范围内搜索 `quote`；唯一命中则更新偏移，多处命中取离原偏移最近的一处。
4. 找不到时标记 `orphaned`，批注仍显示，并提供“重新选择引文”和“删除”。
5. 批注不改写正文，不参与章节保存的 409 判断。

### 6.2 `novel_foreshadows`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | integer PK | 伏笔 id |
| `novel_id` | integer | 小说 id |
| `title` | text | 一句话伏笔名，最长 120 字 |
| `setup_chapter` | integer | 埋设章 |
| `payoff_chapter` | integer nullable | 计划回收章 |
| `status` | text | `planned` / `planted` / `reinforced` / `paid` / `abandoned` |
| `evidence_quote` | text | 证据引文，最长 500 字 |
| `note` | text | 说明，最长 1000 字 |
| `source` | text | `manual` / `blueprint` / `agent` |
| `created_at` / `updated_at` | text | 时间 |

索引：`(novel_id, status, setup_chapter)`。

状态流转只允许：

```text
planned → planted → reinforced → paid
planned / planted / reinforced → abandoned
paid / abandoned 不再自动回到前面状态，除非用户显式改回
```

### 6.3 故事圣经增加 `adaptationNotes`

不新增表、不改 `dramas` 结构，只在 `STORY_BIBLE_KEYS` 末尾增加：

```ts
'adaptationNotes'
```

- 标签：`改编备注`。
- 只有导入时勾选“附带上下文包”才写入。
- 内容由已选章节的批注、未回收伏笔、章节蓝图摘要压缩而成。
- 现有 `formatStoryBible` 会自动把它注入提示词；超过长度限制时仍按整句截断。
- 未勾选时故事圣经内容与今天完全一致。

### 6.4 人物档案不建表

人物页签先做只读汇总：

- 来源：`novels.characterDynamics`、`novels.characterState`、章节正文中的人名出现次数。
- 展示：姓名、最近出现章、出现次数、关系摘要（原文摘录）。
- 不提供结构化编辑；需要改人物设定时回架构 Tab。
- 如果后续确实需要结构化人物卡，再单独评估，不在本方案首批范围。

## 7. 接口设计

所有接口挂在现有 `/api/v1/novels` 下，统一返回 `success` 包装。

### 7.1 聚合读取

```http
GET /novels/:id/workbench
```

返回：

```json
{
  "layout": "split",
  "chapters": [
    { "chapter_no": 1, "title": "雨夜", "status": "final", "word_count": 3012, "has_content": true },
    { "chapter_no": 2, "title": "旧信", "status": "draft", "word_count": 0, "has_content": false }
  ],
  "annotations": [],
  "foreshadows": [],
  "characters": [],
  "counts": { "open_annotations": 0, "unresolved_foreshadows": 3 }
}
```

- 不返回正文，避免首屏过大；正文仍走现有 `GET /novels/:id`。
- 章节树只返回元数据，按 `chapter_no` 升序。

### 7.2 批注

```http
GET    /novels/:id/annotations?chapter_no=3&status=open
POST   /novels/:id/annotations
PUT    /novels/:id/annotations/:annotationId
DELETE /novels/:id/annotations/:annotationId
```

创建请求：

```json
{
  "chapter_no": 3,
  "quote": "他把那封信放回抽屉最底层。",
  "start_offset": 1820,
  "end_offset": 1835,
  "prefix": "窗外的雨停了。",
  "suffix": "手指在抽屉边缘停了半秒。",
  "note": "这是父子线的第一次埋设，改编时要保留。",
  "kind": "adapt"
}
```

校验：

- `quote` 必须能在当前章节正文中找到；找不到返回 400。
- `start_offset < end_offset`，且不超过正文长度。
- 同一章节最多 500 条批注，超过返回 400。
- 更新只允许 `note`、`kind`、`status` 和重新选择的锚点。

### 7.3 伏笔

```http
GET    /novels/:id/foreshadows?status=planned,planted,reinforced
POST   /novels/:id/foreshadows
PUT    /novels/:id/foreshadows/:foreshadowId
DELETE /novels/:id/foreshadows/:foreshadowId
```

- `setup_chapter` 必须在 1 到 `number_of_chapters` 之间。
- `payoff_chapter` 为空表示尚未安排回收。
- `source=blueprint` 的记录必须允许用户确认后再落库；`autoExtract=false` 时只显示候选，不自动写。

### 7.4 上下文包

```http
POST /novels/:id/context-pack/preview
```

请求：

```json
{
  "chapter_nos": [1, 2, 3],
  "include_annotations": true,
  "include_unresolved_foreshadows": true,
  "max_chars": 4000
}
```

返回：

```json
{
  "text": "【小说改编上下文】\n...",
  "chars": 2860,
  "truncated": false,
  "included": { "chapters": 3, "annotations": 7, "foreshadows": 4 }
}
```

导入接口复用现有：

```http
POST /novels/:id/imports
```

新增可选字段：

```json
{
  "include_context_pack": true,
  "context_pack_max_chars": 4000
}
```

行为：

- `include_context_pack` 缺省为 `false`，保持旧行为。
- 为 `true` 时服务端重新生成上下文包，写入 `story_bible.adaptationNotes`。
- 上下文包生成失败不阻断导入，返回警告并在 `last_sync_summary` 记录 `context_pack: skipped`。

### 7.5 设置接口

扩展现有：

```http
GET /settings/novel
PUT /settings/novel
```

新增字段全部走现有 `sanitizeNovelSettings` 清洗；非法值回退默认，不抛 500。`layout` 只接受 `tabs` / `split`。

## 9. 分阶段实施

### N0 配置与壳层（0.5–1 天）

任务：

1. 在 `app-settings.ts` 增加本方案 10 个键的默认值与清洗。

完成标准：

- 默认 `split` 下章节树/正文/检查器三栏空壳可用，尺寸正确。
- 切换 `layout` 不需要重启前端，刷新后生效。
- `tabs` 回退模式下现有写作、自动保存、409 冲突全部通过回归。

### N1 章节树与批注（1.5–2 天）

任务：

1. 新增 `GET /novels/:id/workbench`，返回章节元数据与计数。
2. 章节树支持点击跳转、状态点、字数、当前章高亮。
3. 新增批注表与 CRUD 接口。
4. 正文选中文本后出现“添加批注”；批注以左侧色条标记，不插入正文。
5. 锚点失效时显示“引文已变化”，允许重新选择。

完成标准：

- 100 章小说章节树滚动不卡顿。
- 批注在无关段落编辑后仍能定位；删除引文所在段落后标记失效。
- 批注增删改不触发章节保存，不产生 409。

### N2 伏笔板（1–1.5 天）

任务：

1. 新增伏笔表与 CRUD 接口。
2. 检查器增加“伏笔”页签，按状态分组，显示埋设章/回收章。

完成标准：

- 伏笔状态只能按状态机流转。
- 回收章早于埋设章时返回 400。

任务：

1. 新增预览接口与预览弹窗。
2. 导入对话框增加“附带上下文包”，默认取配置值。
3. 导入时写入 `story_bible.adaptationNotes`，失败降级为警告。
4. 导入结果页显示上下文包字符数与包含条目数。

完成标准：

- 不勾选时，导入结果与今天一致。
- 勾选时，故事圣经多出“改编备注”，现有提示词拼装不报错。
- 超长时按整句截断，不产生半句。
- 小说更新后，现有 `novel_imports` 的同步状态仍按旧逻辑显示 `has_update`。

### N4 人物只读档案（可选，1 天）

任务：

1. 从 `characterDynamics`、`characterState` 与章节正文生成人物汇总。
2. 只展示，不写库；提供“跳到架构 Tab 编辑”。
3. 找不到人物时显示空态，不报错。

完成标准：

- 人物汇总不改变任何现有数据。
- 小说没有人物设定时页面可用。

## 10. 验收清单

### 10.1 功能

- [ ] 默认打开小说详情，六个 Tab 保留；写作 Tab 为三栏 split，自动保存与今天一致。
- [ ] 切换 `layout=tabs` 后，旧下拉布局可用；三栏组件不加载。
- [ ] 选中正文添加批注，刷新后仍在原位置高亮。
- [ ] 编辑同一章其他段落后，批注仍能定位；删除引文段落后标记失效。
- [ ] 伏笔可新建、改状态、设回收章；未回收伏笔在写作时可见。
- [ ] 上下文包可预览、复制、导入；不勾选时导入行为不变。
- [ ] 导入后 `story_bible.adaptationNotes` 存在，现有生成提示词可正常拼接。

### 10.2 兼容

- [ ] `novel.workbench.layout=tabs` 时，不加载三栏组件，不额外请求 workbench 接口。
- [ ] 关闭 `annotations` / `foreshadow` / `contextPack` 任一开关，旧功能不受影响。
- [ ] 章节保存仍使用 `base_updated_at` 冲突协议，409 分支文案不变。
- [ ] 小说导入仍支持原有 `request_id` 幂等、拆集与同步。
- [ ] 不改变 `storyboards`、`episodes`、生成任务任何字段。

### 10.3 配置与回滚

- [ ] 修改配置后刷新生效，无需重启。
- [ ] 环境变量可覆盖布局与三个开关。
- [ ] 回滚只需把 `layout` 改回 `tabs`；新表数据保留，不影响旧页面。
- [ ] 删除新表不会导致旧页面报错（旧代码不查询新表）。

## 11. 风险与边界

| 风险 | 处理 |
| --- | --- |
| 批注锚点漂移 | 偏移 + 前后文窗口重定位；失败标记 `orphaned`，不静默丢失 |
| 上下文包过长挤占提示词 | 默认 4000 字，整句截断；导入前可预览字符数 |
| 伏笔自动提取误报 | 默认关闭；候选必须人工确认 |
| 三栏挤压正文 | 1180px 以下收检查器，860px 以下收章节树 |
| 故事圣经新增键影响旧提示词 | 只有勾选导入才写入；未写入时 `formatStoryBible` 行为不变 |
| 人物档案与短剧角色不一致 | 只读汇总，明确标注“小说设定”；角色仍由现有提取流程生成 |

## 12. 不做的事

- 不做章节拖拽排序。章节号是生产契约，排序会破坏蓝图、导入映射与同步。
- 不做批注回复和多人协作。
- 不做 AI 自动改正文；AI 只能给候选伏笔或上下文摘要，落库前必须确认。
- 不把小说正文塞进剪辑/导演台；它们仍以分镜和成片为输入。
