# 全能力智能体实施计划（P0–P4）

> **给执行者：** 必须使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans`，按计划点逐项执行。每一步的实现代码由执行者在执行时编写；本文件只定义要求、约束、参考、设计、自测与验证，正文不包含实现代码。每个计划点完成后先自测，再由独立复核者按“验证”段落检查，未通过不得进入下一点。

**目标：** 在现有业务系统上交付一个能真正调度生产的全局智能体：用户说“帮我新建《XX》第二章”“帮我续接一下片尾”，助手读取当前页面与业务上下文，形成可审计划，用户批准后由确定性执行器调用现有 MCP 工具和命名 REST 能力完成工作，并把长任务、失败恢复、审计和回滚纳入同一套机制。

**架构：** 能力目录统一登记 66 个 MCP 工具与命名 REST 能力；助手只持有只读、能力发现、计划提案和取消工具，不直接写业务表；计划是唯一写入口，批准由本机用户完成；执行器进程内调用 MCP handler 或现有 REST 路由，不经过 5780 端口；异步作业由作业桥统一跟踪；全局 Dock 只做一套会话、计划卡和任务卡。

**技术栈：** Nuxt 3 + Vue 3.5（SPA）、Pinia、Naive UI、Tailwind、Hono 4.12、Drizzle 0.45 + better-sqlite3、AI SDK 6、Mastra 1.17、Node `node:test` + `tsx`、Vue I18n（zh/en/ja/ko）。

**设计稿：** [全能力智能体设计](../specs/2026-11-10-全能力智能体设计.md)

**工作区：** `/Volumes/软件目录/comfyui/工具/huobao-drama-agent`，分支 `feat/full-agent`，基线为 `main` 的 `193362b`。当前 `main` 工作树中的 7 个分镜检验改动保持不动，不合并、不复制、不清理。

## 全局约束

- 默认**不提交、不构建、不安装依赖、不推送、不重启现有服务**；只有用户明确批准才执行。每个阶段结束时保持改动未提交状态，等待用户指示。
- 不打印或泄露任何 Key、Token、DSH 密码、`ps ssh` 输出或服务器环境变量；日志、计划、消息、审计中的密钥字段一律脱敏。
- 保持端口不变：前端开发 3013、后端开发 5679、MCP 5780、本地 H3 网关 8192；不改 G5、ComfyUI 模板与既有业务语义。P0-4 的 PATCH 补全、路径过滤与安全隔离属于治理补强，不改变 MCP 工具的结果语义。
- 不修改用户已选的生产模型、provider、`isActive`、优先级或 MCP 端口/Token 来掩盖失败；助手模型只读取现有 AI 配置，失败时回退并提示。
- 数据库只做加法：新增 `agent_*` 八张表，不改旧表列、不删除旧数据、不引入迁移框架；`schema.ts` 与 `sqlite-schema.ts` 必须同步。
- 外部 MCP 保持现有 Bearer Token 直接调用语义；内部助手使用进程内 MCP handler 与现有 REST 路由，不经过 5780。外部 MCP 看不到也调不到 `/api/v1/assistant`。
- 所有业务写操作必须进入计划；模型没有写工具、没有批准工具、没有 shell/文件/命令/原始 SQL 工具；模型不能自批。
- 只允许调用能力目录中的能力；模型不能拼接任意 REST 路径。内部助手的 `api_request` 采用严格白名单：GET 只读长尾可用；非 GET 默认拒绝，仅 `apiRequestWriteAllowlist` 显式登记的低风险长尾写可用；设置、队列、AI 配置、提示词、技能、MCP、助手、删除、上传与昂贵作业必须走命名能力。外部 MCP 直连语义不受该白名单影响。
- 计划、消息、事件与审计中不保存 base64、二进制、本地路径或文件名；文件只通过计划卡的 `fileSlots` 与批准请求的 `secure_files` 输入，字节只在内存。上传类工具不接受模型提供的 base64；`clone_voice` 等路径字段只允许存储根内的既有文件。
- 后端测试必须使用隔离的 `SQLITE_PATH`、`HUOBAO_DATA_DIR`、`STORAGE_PATH` 与 `MYSQL_AUTO_IMPORT=false`；不得触碰开发库；读取现有 WAL 数据库时使用只读 URI。
- 面向用户的文案使用中文，并同步 `zh/en/ja/ko` 四份 locale；技术标识、表名、接口名、配置键保持英文。
- 每个计划点必须记录验证证据：命令、退出码、关键输出、状态码、数据库行数变化、浏览器路径、截图位置（截图保存在仓库外临时目录）。
- 没有真实模型、真实作业或真实数据库证据时，只能标记“未验收/阻塞”，不能用占位测试或替身测试冒充完成。

## 2. 范围与完成定义

### 2.1 本期范围

- 全局智能体 Dock：首页、小说库、小说详情、项目详情、剧集、剪辑页六个首批宿主。
- 能力目录：66 个 MCP 工具、命名 REST 能力（含全量业务路由）、内部助手严格 `api_request` 白名单；统一元数据、文件策略、Schema 校验、风险、脱敏、审计、资源锁。
- 助手运行时：会话、消息、SSE、事件回放、取消、模型路由、助手设置。
- 计划协议：计划提案、校验、计划卡、关键参数编辑、文件槽、高危确认、批准、拒绝、取消、过期。
- 执行器：顺序执行、资源锁、同步能力、异步作业桥、任务卡、失败暂停、重试、跳过、恢复、重启对账。
- 命名 REST 覆盖：设置、AI 配置、提示词、技能、MCP 自身、删除、项目、角色/场景/道具、台词 take、导出、影片、首末帧、剪辑、混音、分集/小说长尾。
- 安全：密钥与安全文件输入、存储根路径限制、脱敏、审计、快照、外部 MCP 隔离。

### 2.2 非目标

- 不做固定场景菜单；意图由模型分析，计划由能力目录组合。
- 不做导演入口、独立导演页、独立聊天页、第二套任务中心或第二套播放器。
- 不重写五个生产 Agent、现有 MCP 工具行为、现有作业服务或现有业务路由。
- 不移植 rebrand 分支的助手实现，不依赖其表、接口或前端组件。
- 不设业务成本/并发上限；只保留计划估算、审计、取消、失败暂停和资源锁等技术保护。
- 不做模型直接写库、模型自批、明文密钥回显、shell/文件/命令/原始 SQL。
- 不把 rebrand 分支作为实现基线，不修改 `main` 的未提交改动。

### P0-4 命名 REST 能力注册表与 api_request 治理

**要求**

- `api_request` 路径只允许 `/api/v1/` 开头，拒绝 `..` 与编码穿越；一律拒绝 `/api/v1/assistant`、`/api/v1/mcp`；支持 GET/POST/PUT/PATCH/DELETE，但业务可用性由白名单决定。

### P0-5 能力网关与统一校验

**要求**

实现能力网关：统一加载 MCP 与命名 REST 能力，执行来源校验、JSON Schema 校验、路径参数校验、方法级风险、动态风险提升、目标 scope 校验、密钥、文件与路径校验、只读结果投影、错误归一化；提供 `read` 与 `invoke` 两个入口。

**约束**

- MCP 工具用 `getMcpTool(name).handler(args)` 进程内执行；REST 能力用 `mainApp.fetch` 调现有路由；两者都不经过 5780。
- `tools/call` 不校验输入 Schema，网关必须校验；未知字段按 `additionalProperties` 处理，声明的 Schema 有该字段时拒绝。
- 只读入口只能执行 `risk=read` 的 MCP 工具与只读命名 REST；不得用 `api_request` 执行非 GET。
- 文件参数不接受模型提供的 base64 或本地路径：`secure_slot` 只接受计划文件槽引用，由执行器注入；`storage_path` 只接受存储根内的既有文件；路径解析后必须用 `realpath` 确认仍在允许根内，拒绝 `..`、绝对路径逃逸和符号链接逃逸。
- 文件字段必须在 `editableFields` 之外；计划或消息中出现 base64、本地路径或文件名时拒绝。
- 动态风险：目标已存在、将被覆盖或替换时至少提升为 `destructive`；设置/提示词/技能/MCP 配置提升为 `system`；生成类保持 `expensive`。
- 结果归一化为 `ok/data/summary/job/truncated/redacted/durationMs`；读取结果默认最多 12000 字符、50 条数组项，超出截断并标记。
- 错误码：`CAPABILITY_NOT_FOUND`、`CAPABILITY_FORBIDDEN`、`INVALID_ARGS`、`RISK_MISMATCH`、`SCOPE_DENIED`、`TARGET_NOT_FOUND`、`FILE_REQUIRED`、`FILE_INVALID`、`PATH_FORBIDDEN`、`HTTP_ERROR`、`TIMEOUT`；错误信息不得包含密钥、路径或堆栈。

## 5. P2：计划、审批与同步执行

### P2-1 计划数据服务与计划校验流水线

**要求**

实现计划数据服务与 15 项校验流水线：计划头、步骤、变量、依赖、风险、估算、资源键、哈希；任何一项失败，计划不得进入可批准状态。

**约束**

- 计划步骤只能引用能力目录中的 `mcp` 或命名 `rest` 能力；内部助手的 `api_request` 受严格白名单约束。
- 每一步必须有 `source`、`capability_key`、`args`、`risk`、`reason`；REST 步骤还必须保存 `method` 与 `path_template`。
- 计划哈希使用规范化 JSON（键排序、去除空白、解析变量后参数）计算 SHA-256；任何参数、步骤启停、风险变化都改变哈希。
- 动态风险在计划展示前与执行前各计算一次；执行前发现风险提升或目标变化，计划暂停或失效，不静默执行。
- 校验器不写业务表；只写/读计划表。
- 不估算时允许“未知”，但必须标记；不能编造成本。

**参考**

- 设计稿 §7.1、§7.2、§7.3、§7.4、§7.9。

**设计**

- 新建 `backend/src/services/assistant/plans.ts`：`createDraftPlan`、`getPlan`、`listPlanSteps`、`updatePlanAfterEdit`、`recomputePlanHash`、`setPlanStatus`、`setStepStatus`。
- 新建 `backend/src/services/assistant/plan-validator.ts`：按设计稿 §7.4 的顺序实现 15 项校验，返回 `{ok, issues, normalizedSteps, riskSummary, estimate, resourceKeys, planHash}`。
- 15 项依次为：能力存在且 agentVisible；参数 Schema；目标资源存在且属于 scope；依赖合法无循环；输出引用已声明；资源键可提取；风险可计算；不含助手自身接口；不含明文密钥；哈希可生成；来源合法；HTTP 方法风险；服务端重查动态风险；文件槽/路径/超大载荷拒绝；读取结果投影声明。

- 变量解析：`scope.*`、`steps.<seq>.outputs.*`、`foreach.item.*`；未解析变量直接失败，不做空值兜底。
- 集合展开：`foreach` 必须声明集合来源、元素变量、子步骤模板与并发度；展开后的每个子步骤有独立幂等键。
- 计划编辑：只允许能力元数据声明的 `editableFields`；禁止直接编辑完整 JSON；编辑后重新校验、重算风险与哈希。
- 步骤依赖：被禁用步骤的后续依赖必须自动禁用或标红；不允许留下悬空依赖。

- 来源校验：读取请求 socket 地址或 `x-forwarded-for` 的最后一段，只允许 `127.0.0.1`、`::1`、`::ffff:127.0.0.1`；校验 `Origin` 为本地前端来源或空；服务端模式要求 `x-huobao-local-approval` 与 `app_settings` 中的本地批准令牌哈希一致；令牌只允许设置页生成/轮换/撤销，不进入助手上下文。
- 新增 `GET/POST/DELETE /api/v1/assistant/settings/local-approval-token`：GET 返回 `configured` 与 `created_at`；POST 生成 32 字节随机令牌，返回明文一次并只保存 SHA-256 哈希；DELETE 撤销。设置页 `agents` 页签增加“本机批准令牌”区块，生成后提示只显示一次，并提供轮换/撤销。

- `POST /assistant/plans/:id/approve` 输入 `plan_hash`、`risk_ack`、可选 `secure_inputs`（P4-7 使用）；校验后状态 `awaiting_approval → queued`，写 `plan.approved` 事件与审计。

### P2-5 同步执行器与状态机

**要求**

实现确定性同步执行器：获取资源锁、顺序执行步骤、解析变量、执行前重校验、调用能力网关、写审计与事件、更新计划/步骤状态；失败暂停、用户取消、批准过期等状态按设计稿流转。

**约束**

- 执行器不调用助手模型，不做自然语言决策；只按已批准计划执行。
- 执行前重新校验计划哈希、风险、目标与锁；目标变化或风险提升时暂停/失效，不静默执行。
- 计划级资源锁在开始执行时获取全部写资源键；获取失败保持 `queued`，不失败。
- 成功路径不暂停；失败不自动重试；删除/覆盖类步骤成功后不允许自动重试。
- 异步步骤在 P2 暂不支持：计划校验标记为不可执行，P3-2 再接作业桥；不得假装完成。
- 每步执行前写“步骤开始”事件，完成后写审计与“步骤成功/失败”事件。
- 取消只停止后续步骤，已完成步骤保留，不自动回滚。

- 步骤执行：解析变量 → 重校验能力/参数/风险/scope → 获取步骤锁（计划级已持有时跳过）→ 调用网关 → 写审计 → 更新步骤 → 事件。
- 资源锁：计划开始时获取全部写资源键；若冲突，计划保持 `queued` 并定期重试；批准过期则 `expired`。

- 幂等键：每步生成；同步写步骤重试前检查目标状态；删除/覆盖成功后不再重试。

### P3-3 失败暂停、重试、跳过、取消与恢复

**要求**

实现计划与步骤的失败处理：重试失败步骤、跳过失败步骤、取消计划、恢复中断计划；状态机与 API/UI 完整；重试前检查目标与幂等键，避免重复写。

**约束**

- 重试只允许失败步骤；跳过只允许失败步骤；取消允许 queued/running/paused_error；恢复允许 interrupted。
- 重试异步步骤前先查同一幂等键作业：运行中附着、成功标记成功、失败确认后新尝试键；不重复启动。
- 同步写重试前检查目标当前状态；删除/覆盖成功后不允许自动重试。
- 跳过失败步骤后，依赖它的后续步骤必须无法继续或由用户显式处理；不能静默执行悬空依赖。
- 失败不自动烧钱重跑；所有重试/跳过/恢复由用户操作。
- 状态变化写审计与事件，UI 显示原因与后果。

**参考**

- 设计稿 §7.7、§7.9、§7.10、§8.2。
- `backend/src/services/assistant/executor.ts`、`plans.ts`、`job-bridge.ts`。
- `frontend/app/components/assistant/AssistantPlanCard.vue`、`AssistantTaskCard.vue`。

**设计**

- API：`POST /assistant/plans/:id/steps/:stepId/retry`、`/skip`、`POST /assistant/plans/:id/resume`、`/cancel`。
- 状态转换：`failed → running`（重试）、`failed → skipped`（跳过）、`paused_error → running`（重试/跳过后继续）、`interrupted → running`（恢复）、`queued/running/paused_error → cancelled`。
- 重试：读取步骤与当前目标，重新校验参数/风险/scope；异步先查幂等作业；同步检查目标；通过后重置步骤状态并继续执行。
- 跳过：标记 skipped；检查依赖，必要时把后续步骤标记 blocked 并提示用户；不自动跳过后续。
- 取消：设置 cancel_requested；当前步骤同步无法中断时完成后停止；异步调用作业取消；计划状态 cancelled。
- 恢复：只对 interrupted；重新对账关联作业，按真实状态继续/暂停；没有关联作业时等待用户选择。
- UI：失败步骤显示“重试/跳过/取消计划”；中断计划显示“恢复/取消”；跳过前二次确认并说明依赖后果。

### P4-7 安全输入（密钥与文件）与快照回滚

**要求**

实现安全输入与快照回滚：计划卡密码输入、文件选择或服务端生成；密钥与文件字节不进入模型上下文、消息、计划、事件或审计；执行时只在内存；重启/排队丢失时重新输入；设置/提示词/技能快照可通过新计划回滚；AI 配置创建/更新/删除与上传类文件输入在本点验收。

**约束**

- 密钥只允许通过批准/执行请求的 `secure_inputs` 字段传入；不写入 `agent_plans`、`agent_messages`、`agent_events`、`agent_action_audit`。
- 文件只允许通过计划 `fileSlots` 与批准/执行请求的 `secure_files` 传入；不写入计划、消息、事件或审计；字节只在内存。
- `upload_image`、`upload_video`、`upload_audio` 不接受模型提供的 base64；`set_asset_image` 与 `clone_voice` 的路径只允许存储根内的既有文件；拒绝绝对路径、`..` 与符号链接逃逸。
- 文件槽必填缺失、MIME/大小不符、文件名或路径出现在计划或消息中时拒绝。
- 文件字节在步骤执行后立即释放；异步作业只接收上传后的业务结果，不保留原始字节。
- AI 配置创建/更新/删除需要 `secure_inputs` 的 `api_key`；成功路径在此验收，P4-1 只测拒绝。
- 审计只记录文件槽位、MIME、大小、内容哈希；不记录文件名、路径、字节。
- 计划卡只显示“将变更”“已输入”或文件槽状态，不回显；日志与错误不包含密钥、路径或文件名。
- 执行器在内存保存密钥与文件；计划完成/失败/取消后清除；重启后未执行的计划需要重新输入或重新选择文件。
- 若模型把 `[REDACTED]` 占位符或文件路径写回参数，执行器拒绝并提示用户重新输入。
- 回滚不直接写库：审计抽屉生成一个预填旧值的新计划，用户批准后执行。
- MCP Token、AI Key、密码类字段都适用；Token 可服务端生成，模型只看到“已生成”。

**参考**

- 设计稿 §7.1、§7.4、§11.2、§11.3、§11.5。
- `backend/src/services/assistant/approvals.ts`、`executor.ts`、`redaction.ts`、`audit.ts`、`capability-gateway.ts`。
- `frontend/app/components/assistant/AssistantParamEditor.vue`、`AssistantPlanCard.vue`、`AssistantAuditDrawer.vue`。
- `backend/src/routes/upload.ts`、`backend/src/services/mcp.ts` 的 `upload_image`、`upload_video`、`upload_audio`、`set_asset_image`、`clone_voice`。

**设计**

- 计划结构增加 `fileSlots`：槽位 ID、标签、类型、MIME、大小上限、是否必填；不包含字节、路径或文件名。步骤通过 `fileSlotRefs` 引用槽位。
- 批准请求可带 `secure_inputs`（能力键 + 字段名 → 字符串）与 `secure_files`（槽位 ID → 文件字节）；服务端校验字段属于 `secretFields`、槽位属于该计划且必填齐全。
- 执行器将 `secure_inputs` 与 `secure_files` 放在内存 Map，执行对应步骤时注入；`upload_*` 的 `data_base64` 由文件字节在内存生成；`set_asset_image` 优先使用安全文件槽，路径模式只允许存储根；`clone_voice` 只接受存储根内的既有文件，推荐先用 `upload_audio` 生成存储文件再引用。
- 存储根解析使用现有 `STORAGE_PATH` 与项目存储目录；`realpath` 后确认仍在根内；符号链接逃逸、目录、不存在的文件都拒绝。
- 计划哈希只覆盖槽位要求，不覆盖文件字节；更换文件不使批准失效，但缺失必填文件时批准被拒绝。
- AI 配置创建/更新/删除通过 `ai_configs.*` 命名能力执行，`api_key` 走 `secure_inputs`；读取与审计只显示“将变更”。
- 回滚按钮生成新的 `awaiting_approval` 计划，步骤参数为旧值（非密钥）；密钥类不提供回滚，提示重新输入。
- 文件槽与密钥在计划完成/失败/取消后清除；重启后未执行的计划需要重新提供。

## 8. 执行顺序与交接

- 严格按 P0-1 到 P4-9 顺序执行；每个计划点完成后先自测，再由独立复核者按“验证”段落检查。

- 每个阶段结束时保持改动未提交；只有用户明确要求才提交、构建、安装或推送。
- 执行者必须在每点结束时报告：完成了什么、验证命令与结果、未完成/阻塞项、下一步建议。
