**目标：** 交付一个可侧载安装、开机即用的 Android 平板/手机独立应用；应用内嵌完整运行时与现有后端/前端，业务功能保留，FFmpeg 产出动作门控为「暂未开放」；支持扫码接力到电脑继续工作，支持与电脑进行局域网单向快照同步。

**架构：** Android 壳负责启动、解压、前台服务、进程守护、WebView、扫码与系统集成；proot + Debian arm64 + 官方 Node 22 提供 glibc 运行时；现有 Hono 后端只监听回环并增加应用令牌；Nuxt 前端增加应用模式与手机全功能布局；扫码接力复用已实现的电脑远程桥；数据同步新增主机侧接口与应用侧客户端。

**执行方式：** 直接按 A0–A11 顺序执行，不引入额外技能流程；每个任务完成后先完成自测与验证，再进入下一项。A1 是 Go/No-Go 闸门；未通过不得进入 A2 之后的实现。涉及构建、安装、提交、推送的步骤分别需要用户明确批准。

**本文不含代码。** 接口路径、表名与文件路径用于界定范围；具体实现代码在执行对应任务时编写。

## 全局约束

- 不触碰与本任务无关的既有改动：分镜审计、转场修复、desktop/package.json 等；不得用还原、清理、格式化等方式覆盖。
- 不修改用户配置来掩盖失败；不关闭系统安全机制；不要求 root；不使用 Termux 或任何用户自装环境。
- 不把本机后端暴露到局域网；应用只监听 127.0.0.1；扫码接力与数据同步都是出站连接。
- 不内置 FFmpeg/FFprobe，不引入 ffmpeg.wasm、WebCodecs 转码或 UVR；能力门控失败按不可用。
- 桌面端与服务器模式行为保持兼容：新增接口默认关闭或仅在应用/主机模式启用；不得扩大远程桥的既有权限。
- 不新增用户、账号、角色、租户或权限表；数据同步不引入双向合并。
- 不打印、不提交密钥、Cookie、令牌、真实内网 IP、域名、证书路径、PUBLIC_BASE_URL 或用户数据。
- 新增文案同步 zh/en/ja/ko 四份 locale；技术名 FFmpeg/FFprobe 不翻译。
- 测试必须使用隔离的 SQLITE_PATH 与临时目录，不读写开发库或用户数据目录；后端测试使用 Node 22。
- 构建、安装、提交、推送分别批准；不自动打包、不自动安装、不自动提交。
- 只支持 arm64-v8a；不做模拟器承诺；真机证据优先于结构测试。
- 数据库变更以加法为主；数据同步不新增业务表；如确需新增表，必须先更新设计并说明迁移与回滚。

3. 验证后端最小实例可启动：环境变量注入、监听 127.0.0.1、健康检查返回、SQLite 建表读写。
4. 验证 DNS、CA、时区：能访问 HTTPS 服务并完成证书校验；不打印真实域名与凭据。
5. 测量冷启动时间、内存峰值、运行时体积；记录失败日志。
6. 若 targetSdk 28 路线失败，验证 nativeLibraryDir 备选路线；两条都失败则 No-Go。

### 约束

- 原型代码可丢弃，不进入正式工程；不修改业务代码。
- 不安装 Termux，不使用 root，不关闭 SELinux/Play Protect，不修改系统网络或证书设置。
- 所有文件在应用私有目录；只申请原型必需的权限。
- 不写真实密钥、域名、IP 到仓库或日志；测试地址使用占位符或用户临时提供且不落盘。
- 不提交原型产物；不打包正式签名。

### 参考

- 设计文档第 6 节（运行时、执行限制、备选路线）。
- 设备事实：Android 16/SDK 36、arm64-v8a、4KB 页、15.5GB 内存、411GB 可用；JDK 21、SDK 36、NDK 27/28、adb 37.0.1。
- Node 约束：@mastra/core ≥22.13；better-sqlite3 12.x、sharp 0.34.x 的 linux-arm64 glibc 预编译。

2. 准备最小 rootfs：Debian arm64 + ca-certificates + libstdc++6 + tzdata；准备 Node 22.16+ 官方 linux-arm64。
3. 准备原生模块验证：安装 linux-arm64 生产依赖，验证 better-sqlite3 打开数据库并建表写入，sharp 读取图片并缩放输出。

6. 执行测试矩阵：

   - 杀进程后重启；

   - HTTPS 证书校验；
   - 时区与 locale；

   - 内存与耗电采样。

8. 形成 Go/No-Go 结论：通过则冻结运行时版本与 targetSdk 方案；失败则停止并输出阻塞证据与替代路线建议。

## A2 运行时打包流水线

### 要求

## A7 扫码接力应用内落地

### 要求

1. 应用内扫码：相机预览、识别二维码、手动输入短码、错误提示。
2. 地址校验：只接受私有 IPv4 的电脑桥地址；拒绝公网、域名、file、javascript 等。
3. 打开电脑桥配对页；电脑确认后获得设备 Cookie；加载电脑前端；显示连接状态。
4. 返回本机：通知动作与应用内入口；断开电脑清除 Cookie；电脑端可撤销设备。
5. 只读设备沿用既有拦截；接力期间写操作发生在电脑。
6. 电脑不可达、桥关闭、网络切换、会话过期都有明确处理。

### 约束

- 不新增第二套配对协议；复用现有 remote 路由、配对页、设备会话与状态徽标。
- 不请求麦克风、存储权限；相机仅扫码；不在后台开启相机。
- 不在 WebView 加载公网页面；不接受非私有地址；不自动打开扫码结果，必须先确认。
- 不把设备 Cookie 写入日志或应用数据库；只由 WebView 管理，同步时按第 9 节内存交接。
- 不修改远程桥的默认关闭、电脑确认、只读与撤销策略。
