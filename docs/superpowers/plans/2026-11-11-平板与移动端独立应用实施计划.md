**目标：** 交付一个可侧载安装、开机即用的 Android 平板/手机独立应用；应用内嵌完整运行时与现有后端/前端，业务功能保留，FFmpeg 产出动作门控为「暂未开放」；支持扫码接力到电脑继续工作，支持与电脑进行局域网单向快照同步。

**架构：** Android 壳负责启动、解压、前台服务、进程守护、WebView、扫码与系统集成；proot + Debian arm64 + 官方 Node 22 提供 glibc 运行时；现有 Hono 后端只监听回环并增加应用令牌；Nuxt 前端增加应用模式与手机全功能布局；扫码接力复用已实现的电脑远程桥；数据同步新增主机侧接口与应用侧客户端。

**执行方式：** 直接按 A0–A11 顺序执行，不引入额外技能流程；每个任务完成后先完成自测与验证，再进入下一项。A1 是 Go/No-Go 闸门；未通过不得进入 A2 之后的实现。涉及构建、安装、提交、推送的步骤分别需要用户明确批准。

**本文不含代码。** 接口路径、表名与文件路径用于界定范围；具体实现代码在执行对应任务时编写。

## 全局约束

- 不触碰与本任务无关的既有未提交改动：分镜审计、转场修复、desktop/package.json 等；不得用还原、清理、格式化等方式覆盖。
- 不修改用户配置来掩盖失败；不关闭系统安全机制；不要求 root；不使用 Termux 或任何用户自装环境。
- 不把本机后端暴露到局域网；应用只监听 127.0.0.1；扫码接力与数据同步都是出站连接。
- 不内置 FFmpeg/FFprobe，不引入 ffmpeg.wasm、WebCodecs 转码或 UVR；能力门控失败按不可用。
- 桌面端与服务器模式行为保持兼容：新增接口默认关闭或仅在应用/主机模式启用；不得扩大远程桥的既有权限。
- 不新增用户、账号、角色、租户或权限表；数据同步不引入双向合并。
- 不打印、不提交密钥、Cookie、令牌、真实内网 IP、域名、证书路径、PUBLIC_BASE_URL 或用户数据。
- 新增文案同步 zh/en/ja/ko 四份 locale；技术名 FFmpeg/FFprobe 不翻译。
- 测试必须使用隔离的 SQLITE_PATH 与临时目录，不读写开发库或用户数据目录；后端测试使用 Node 22。
- 构建、安装、提交、推送分别批准；不自动打包、不自动安装、不自动提交。
- 只支持 arm64-v8a；不做模拟器承诺；真机证据优先于结构测试。
- 数据库变更以加法为主；数据同步不新增业务表；如确需新增表，必须先更新设计并说明迁移与回滚。

### 要求

3. 验证后端最小实例可启动：环境变量注入、监听 127.0.0.1、健康检查返回、SQLite 建表读写。
4. 验证 DNS、CA、时区：能访问 HTTPS 服务并完成证书校验；不打印真实域名与凭据。

6. 若 targetSdk 28 路线失败，验证 nativeLibraryDir 备选路线；两条都失败则 No-Go。

### 约束

- 原型代码可丢弃，不进入正式工程；不修改业务代码。

- 不写真实密钥、域名、IP 到仓库或日志；测试地址使用占位符或用户临时提供且不落盘。
- 不提交原型产物；不打包正式签名。

## A3 Android 壳与本地服务生命周期

### 要求

1. 正式 Android 工程：Kotlin、compileSdk 36、minSdk 26、arm64 only、targetSdk 按 A1 结论。
2. 首次启动解压运行时并显示进度；校验失败可重试、可修复，不丢数据。
3. 前台服务启动 proot → Node → 后端；选择端口、生成应用令牌、等待就绪、加载 WebView。
4. 健康检查与进程守护：异常退出按退避重启；连续失败进入修复页；日志可导出。
5. 应用令牌中间件：应用模式下所有请求必须携带令牌，否则 401；桌面/服务器模式不启用。
6. WebView 导航白名单：仅本机回环与私有 IPv4 电脑桥；其他地址交系统浏览器。
7. 应用模式信号：注入 window.huobaoApp 与 client 查询参数；前端跳过 PWA/Service Worker。
8. 通知：前台服务常驻通知；提供「返回本机」「扫码连接电脑」动作。

### 约束

- 只监听 127.0.0.1；不得监听 0.0.0.0；不得开放局域网端口。
- 不申请麦克风、通讯录、短信、后台定位、全盘存储权限；相机仅用于扫码。
- 不自动开机启动；不强制电池优化白名单；提供引导而非强制。
- 不把令牌写入日志、数据库、SharedPreferences 明文或崩溃报告。
- 不改变桌面端与服务器模式的启动路径与默认行为。
- 不在 WebView 内加载公网页面；不启用 file:// 访问；不允许第三方页面调用应用接口。

### 参考

- 设计文档第 5、6、11 节。
- backend/src/index.ts:191、193（端口/主机）；backend/src/index.ts:92（健康检查）。
- frontend/app/plugins/pwa.client.ts:14-16（桌面壳跳过 PWA 的现有模式）。
- 扫码接力 P0–P15 的 remote 路由与设备会话。

### 设计

1. 工程模块：app 壳、运行时管理、进程管理、WebView、扫码、系统集成、日志。模块间接口清晰，避免单文件膨胀。
2. 启动状态机：未准备 → 解压中 → 启动中 → 健康检查 → 就绪 → 运行中 → 重启中 → 修复。每态有超时与错误码。
3. 端口：默认 5679，占用时 5679–5689 重试并持久化；启动参数注入 HOST=127.0.0.1、PORT、HUOBAO_APP=1、HUOBAO_APP_TOKEN、数据/工作区/前端路径。
4. 就绪：后端输出结构化就绪标记；壳同时轮询健康检查，二者任一成功即可加载；失败读取日志尾部并显示可操作错误。
5. 应用令牌：壳生成随机令牌，设置 HttpOnly Cookie；后端中间件校验 Cookie 或请求头；静态资源、EventSource、下载均通过 Cookie 携带。
6. 进程守护：前台服务持有进程句柄；退出后指数退避重启（1、2、5、10、30 秒），连续 5 次失败进入修复页；修复页可重新解压运行时、导出日志、保留数据。
7. 活动任务与唤醒锁：前端通过 window.huobaoApp 上报活动任务数；大于 0 时持有部分唤醒锁，归零后释放；前台服务通知常驻。
8. 网络变化：监听网络回调，重写 resolv.conf；提示「网络已切换，建议重启后端」或自动重启；不修改系统代理。
9. 日志：后端 stdout/stderr 与壳日志分文件滚动；导出时脱敏 Cookie、令牌、路径中的用户名。
10. WebView：开启安全浏览、禁用文件访问、限制导航、处理下载与外部链接；页面加载失败显示重试与返回本机。

## A8 局域网数据同步

- 不新增业务表；同步状态放内存与暂存目录，进程重启后未完成 run 作废并清理。
- 不通过请求参数读取任意文件；媒体路径必须规范化并限制在允许根目录。
- 不把同步接口加入远程桥的主机管理白名单；主机确认与拒绝接口只在电脑回环可用。

- 不传输 app_settings、AI 配置、设备会话、任务队列。

4. 数据库快照：SQLite 在线备份生成一致快照；应用下载/上传到暂存；校验 integrity_check、行数与 schema 指纹。
5. 媒体传输：按清单对比大小与哈希，只传差异；下载/上传均支持 Range 与分块；并发上限 3；失败重试 2 次；进度按文件与字节统计。
6. 应用数据：目标端暂停队列与后台任务 → 备份数据库 → 媒体原子移动 → 单事务删除并插入同步表 → 外键检查与完整性检查 → 提交 → 重启队列。
7. 运行时表清理：应用前清空 sys_task、pipeline_jobs、video_batch_jobs、video_batch_items、storyboard_split_jobs、storyboard_audit_jobs、episode_locks；不清理历史任务记录。
8. 回滚与备份：数据库事务失败回滚；媒体部分覆盖不删除；备份保留最近 3 份；提供恢复说明。
9. 应用侧客户端：壳交接设备 Cookie；后端发起出站请求，带 Origin；本机编排接口受应用令牌保护；进度通过轮询或本机 SSE。
10. 界面：方向选择、规模预览、确认、阶段进度、完成摘要、失败原因、重试、最近记录；电脑端待确认弹窗与记录列表。
11. 测试数据：构造包含多剧集、多分镜、音频/视频/图片、空表、特殊字符路径的测试库与媒体目录；不复制用户真实数据到仓库。

### 自测

- 单元测试：表清单分类、schema 指纹、媒体路径校验、清单生成、哈希对比、版本拒绝、run 状态机、限流。
- 集成测试：两个隔离测试库 + 临时媒体目录，完成拉取与推送；中断后续传；事务失败回滚；磁盘不足拒绝；过期 run 清理。
- 安全测试：只读设备拒绝；无设备 Cookie 401；错误 Origin 403；路径穿越拒绝；主机接口经桥 404。

### 验证

- 真机与电脑同一局域网：拉取一次、推送一次；校验表行数、关键字段、媒体可播放；检查备份存在；中断一次并续传。
- 3.4GB 全量或代表性数据集实测；记录总耗时、吞吐、空间占用。
- 证据：同步记录、校验报告、备份文件、日志（脱敏）。

## A9 打包、签名、升级

### 要求

1. 生成可安装的 arm64 release APK；签名密钥本地保管，不入库。
2. versionCode 单调递增；versionName 与仓库版本对齐；运行时版本可查询。
3. 覆盖安装保留数据；运行时更新替换运行时目录；降级安装拒绝或提示不兼容。
4. 记录 APK 体积、冷启动、首解压、内存与耗电；与设计目标对比。
5. 生成校验和与版本说明；不提供自动更新服务。
6. 安装与卸载说明：卸载删除应用数据，升级不删除。

### 约束

- 不在未获批准时打包或安装；构建、安装分别批准。
- 不提交 APK、签名密钥、密码、证书；发布产物放在仓库外或忽略目录。
- 不使用 Play App Signing；不做商店上架。
- 不通过删除用户数据解决升级问题；迁移失败要保留备份与可回滚路径。
- 不把调试构建当作发布构建验收。

### 参考

- 设计文档第 12 节。
- A2 运行时清单与版本；A3 启动流程；A4 备份。
- 当前仓库版本基线 4.0.31（提交 193362b），工作区另有 4.0.35 相关未提交状态；版本号以用户确认为准。

### 设计

1. 构建顺序：前端生成 → 后端 bundle → linux-arm64 依赖 → 运行时包 → APK 组装 → 签名 → 校验和。
2. 版本映射：APK versionCode、versionName、运行时版本、后端版本、schema 指纹写入设置页与日志（不含敏感信息）。
3. 升级流程：安装新 APK → 启动 → 解压新运行时到新目录 → 校验 → 停旧后端 → 切换 → 启动 → 迁移 → 健康检查 → 保留旧运行时一份。
4. 降级：versionCode 低于已安装版本时拒绝安装（系统层）或启动时提示不兼容；不得尝试用旧代码打开新 schema 并写入。
5. 回滚：运行时切换失败回退旧运行时；数据库迁移失败停止启动并提示恢复备份；不自动删库。
6. 发布材料：APK、SHA-256、版本说明、已知限制（无 FFmpeg、需模型网络、参考视频/音频限制）、卸载说明。

### 自测

- 重复构建的版本信息一致；签名校验通过。
- 覆盖安装两次，数据保留；运行时更新成功；降级被拒绝。
- 冷启动、首解压、内存、耗电记录完整。

### 验证

- 真机安装、升级、回滚各一次；数据抽样校验；证据：安装截图、版本页、日志、校验和。

### 要求

1. 在 Y700 横屏与竖屏完成全模块走查；手机设备可用时补手机视口。
