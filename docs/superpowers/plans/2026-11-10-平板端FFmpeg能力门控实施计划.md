# 平板端 FFmpeg 能力门控实施计划

> **给执行者：** 必须使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans`，按任务逐项执行。步骤使用 `- [ ]` 复选框跟踪。

**目标：** 按当前连接服务端的真实媒体能力门控全部 FFmpeg/FFprobe 产出动作；能力可用时桌面、平板、手机行为不变，能力不可用时三类客户端显示同一套「暂未开放」标识并禁用产出按钮，直接调用被门控接口返回 503 `MEDIA_UNAVAILABLE`，全自动流程跳过配音与合片但保留跳过说明。

**架构：** 后端新增只读能力快照 `GET /api/v1/capabilities`，包装现有 `getFfmpegStatus()`，进程内缓存 30 秒，保存媒体设置时失效；路由入口用 outputActions、audioSeparation、voiceActions、ffprobe 四类守卫先行返回 503，读接口与编辑接口不门控；前端用模块级单例组合式加载能力，客户端插件启动时请求一次，提示组件与按钮共用同一状态；全自动流程在 `stepDub` 读取能力，缺失时写入 `automationNote` 并跳过，不创建配音任务。

**技术栈：** Hono + TypeScript、Drizzle/SQLite 现有表、Node 22/24 `node:test`、Nuxt 3 + Vue 3、`node:test` 结构测试；不新增运行时依赖。

**设计依据：** `docs/superpowers/specs/2026-11-10-平板端FFmpeg能力门控设计.md`。本文所有门控入口、503 契约与前端状态以该设计为准；实现中发现差异，先改设计再改代码。

## 全局约束

- 门控只按服务端能力，不读取 UA、不判断平板/手机、不使用视口宽度或 `isTablet` 分支。
- 只门控产出动作；读取、播放、预览、下载、剧本/分镜/台词/混音计划/剪辑工程编辑保持开放。
- 不改变 FFmpeg 执行逻辑、转码参数、合片算法、ComfyUI 模板与现有接口字段；只增加入口检查与错误响应。
- 不新增数据库字段或迁移；`episodes.automationNote` 已存在。
- 不新增应用级登录、鉴权、租户或权限体系；能力接口只返回布尔值与时间，不返回路径、目录、版本或环境变量。
- 能力缺失一律 fail-closed：探测失败、请求失败、超时、结构不合法都按不可用处理，只有明确拿到 `outputActions: true` 才允许产出动作。
- 不修改用户设置来掩盖能力缺失；测试只对测试进程设置无效 `FFMPEG_BIN`/`FFPROBE_BIN`，不得写开发库或用户数据目录。
- 不新增运行时依赖；不引入客户端 FFmpeg/WebCodecs 转码链路。
- 新增文案同步 `zh/en/ja/ko` 四份 locale；技术名 `FFmpeg`、`FFprobe` 不翻译；不硬编码中文。
- 不提交、不构建、不安装、不重启应用，除非用户明确要求；构建、安装与提交分别批准。
- 不读取、打印或提交密钥、Token、密码、真实域名、IP、证书路径与实际 `PUBLIC_BASE_URL` 值。
- 文档、测试与提交说明不得出现真实媒体路径或用户数据。
- 没有运行时证据不得标记完成；缺少有效与无效两组 FFmpeg 环境、隔离数据库或等效视口时，相应验收标「阻塞」，不以结构测试替代。

## 1. 口径裁决

| 编号 | 歧义 | 裁决 | 理由 |
| --- | --- | --- | --- |
| M1 | 能力判断依据 | 只看服务端 `GET /api/v1/capabilities` | 平板与桌面都是浏览器客户端，设备类型不能决定服务端是否有 FFmpeg |
| M2 | 门控范围 | 只门控产出动作，读与编辑保持开放 | 用户明确要求编辑、预览、播放与方案编辑不受影响 |
| M3 | 能力查询失败 | fail-closed，进入 `failed` 并提供重试 | 不能把网络故障伪装成可用或伪装成「暂未开放」 |
| M4 | 旧后端兼容 | 不做兼容分支；前后端同版本部署 | 旧后端没有能力接口，新前端会按不可用处理；发布说明要求同版本 |
| M5 | 缓存策略 | 成功与失败都缓存 30 秒；`?refresh=1` 绕过；保存设置失效 | 避免每次页面请求启动子进程，也避免失败时不缓存造成每次等 10 秒 |
| M6 | 自动化行为 | 跳过配音与合片并写说明，整体仍为 `done` | 不把能力缺失扩大成整条流程失败；用户修复后可手动重试 |
| M7 | 音色设计是否门控 | 不门控 | `design`、`narrator`、`voice-profile` 只走文本模型或写配置，不产生媒体文件 |
| M8 | 声音生成是否门控 | 门控；按 ffprobe | 落盘后必须读时长，读不到会删文件并抛错；归一化失败才可回退 |
| M9 | 素材导入是否门控 | 音频素材导入与剪辑视频素材导入门控；图片与原始上传开放 | 导入后必须探测元数据，否则落坏素材或返回 400 |
| M10 | 按钮表现 | 不隐藏，禁用并显示「暂未开放」或 inline 标识 | 用户要能看见功能存在，也要知道为什么不能用 |
| M11 | 503 与既有错误 | 只有能力缺失返回 `MEDIA_UNAVAILABLE`；未配置服务、任务冲突等保持原错误 | 前端不能把所有 503 都当成 FFmpeg 缺失 |
| M12 | 设备分支 | 结构测试禁止新增 `isTablet`、UA、视口宽度参与能力判断 | 防止实现阶段退回按设备门控 |
| M13 | 测试替身 | 后端用隔离 SQLite 与临时目录；FFmpeg 可用组用真实二进制，不可用组用测试进程环境变量指向不存在路径 | 不修改用户设置，不用 mock 代替真实探测 |
| M14 | 部署顺序 | 后端与前端必须同批发布 | 新前端连旧后端会 fail-closed，全部产出入口不可用 |
| M15 | 多进程 | 本期按单进程设计；多进程缓存最多 30 秒不一致 | 不引入跨进程广播，发布说明标注 |
| M16 | 原声分离的守卫类别 | 使用独立的 audioSeparation 守卫，不并入 outputActions | 能力字段已存在；当前两者同值，未来接入非 FFmpeg 分离引擎时只需放开该字段 |

## 2. 批次、依赖与出口

### 2.1 批次划分

| 批次 | 任务 | 依赖 | 出口 |
| --- | --- | --- | --- |
| A 基础设施 | P0 基线、P1 能力服务、P2 门控原语 | 无 | 能力接口可查，缓存与 503 契约有测试 |
| B 后端门控 | P3 合片过渡导出、P4 混音音频、P5 配音音色、P6 剪辑与资产、P7 自动化 | A | 31 个写接口与自动化跳过行为符合设计 |

| D 验收 | P11 回归与运行时验收 | A–C | 可用、不可用、恢复、失败注入四组证据；阻塞项如实标注 |

P3–P6 可并行，但不得同时改 `backend/src/utils/response.ts` 与 `backend/src/utils/media-guard.ts`；P7 依赖 P1，可与 P3–P6 并行。P8 只依赖 P2 的接口契约，可在 B 完成前先行；P9 依赖 P8；P10 依赖 P9。

### 2.2 批次完成定义

- [ ] A：能力接口有效/无效/缓存/刷新/失效测试通过；503 响应结构与四类守卫测试通过。
- [ ] B：31 个写接口在能力缺失时返回 503 且无副作用；对应读与编辑接口 200；自动化完成并保留跳过说明。
- [ ] C：前端四态与四类能力判断有结构测试；所有页面按钮绑定；四语文案一致；无设备类型分支。
- [ ] D：后端全量测试、类型检查、前端全量测试通过；隔离环境下完成可用/不可用/恢复/失败注入四组运行验收；无法完成项标「阻塞」。

## 4. 跨任务契约

### 4.1 能力模型与缓存

| 字段 | 类型 | 语义 |
| --- | --- | --- |
| `media.ffmpeg` | boolean | ffmpeg 二进制可执行 |
| `media.ffprobe` | boolean | ffprobe 二进制可执行 |
| `media.outputActions` | boolean | 当前为 `ffmpeg && ffprobe` |
| `media.audioSeparation` | boolean | 当前为 `ffmpeg && ffprobe` |
| `media.voiceActions` | boolean | 当前为 `ffmpeg && ffprobe` |
| `media.missing` | string[] | `ffmpeg`、`ffprobe` 中缺失项，顺序固定 |
| `media.checkedAt` | string | 最近一次探测时间，ISO 8601 |

- 缓存键只有一个：单进程全局快照；不按请求、剧集或用户区分。
- TTL 固定 30 秒；成功与失败都写入缓存；`?refresh=1` 跳过读取直接探测。
- 同一时刻最多一个探测在途；并发请求复用同一 Promise。
- 探测抛错、超时、路径不存在、不可执行一律转为对应布尔值 false，不向客户端返回 500。
- `PUT /api/v1/settings/media` 保存成功后调用失效；失效失败不影响保存响应。
- 响应不包含路径、目录、来源、版本、环境变量或错误堆栈。
- 设置页既有 `GET /api/v1/settings/media` 保持原字段，不改为新快照。

### 4.2 503 契约与四类守卫

- 被门控写接口在解析请求体、写数据库、创建任务、启动子进程之前检查能力。
- 不可用时返回 HTTP 503，信封包含 `code: 503`、固定中文 `message`、`error_code: 'MEDIA_UNAVAILABLE'`。
- `message` 固定为「当前服务端未检测到 FFmpeg/FFprobe，该功能暂未开放」；前端按 `error_code` 本地化，不直接展示该中文。
- outputActions 守卫用于产出链；audioSeparation 守卫用于原声分离；voiceActions 守卫用于配音/合成/样音/克隆参考；ffprobe 守卫直接检查 `media.ffprobe`，用于导入探测与声音生成落盘。
- 能力可用时守卫不产生日志、不写库、不改变请求体与控制流。
- 既有波形与缩略帧 503 不使用 `MEDIA_UNAVAILABLE`，保持原错误码与前端占位逻辑。
- 其他 503（未配置语音服务、任务冲突等）不带 `MEDIA_UNAVAILABLE`。

### 4.3 前端状态契约

| 状态 | 条件 | 按钮 | 文案 |
| --- | --- | --- | --- |
| `idle` | 尚未请求 | 禁用 | 视为加载中 |
| `loading` | 首次请求或重试中 | 禁用 | 正在检测媒体能力… |
| `ready` | 请求成功且结构合法 | 按字段决定 | 可用时不显示提示 |
| `ready` 且不可用 | `outputActions` 或对应字段 false | 禁用 | 暂未开放 + 原因 + 设置提示 |
| `failed` | 网络、超时、非 2xx、结构不合法 | 禁用 | 无法检测媒体能力，产出功能暂不可用 + 重试 |

- 派生：`outputReady`、`separationReady`、`voiceReady`、`probeReady` 都要求 `state === 'ready'` 且对应字段为 true。
- `loading` 与 `failed` 不得显示「暂未开放」；`failed` 必须与「服务端确实缺少 FFmpeg」区分。
- `ensureLoaded()` 幂等；`ready` 后不重复请求；`failed` 不自动重试，由用户点击或设置保存触发。
- `refresh(force)` 去重并发；超时 15 秒；超时按 `failed`。
- `MEDIA_UNAVAILABLE` 兜底：显示本地化不可用提示、后台强制刷新一次、不自动重放原动作。
- 不做轮询；只在启动、产出页面进入、用户重试、设置保存、收到 `MEDIA_UNAVAILABLE` 时刷新。

### 4.4 页面绑定契约

- 所有产出按钮保持可见，禁用时用 `disabled`、`aria-disabled` 与本地化 `title` 说明原因；不以 CSS 隐藏代替禁用。
- 同一页面只放一条 banner；按钮旁只放短标签，不重复整段说明。
- 只读、播放、预览、下载、编辑与方案保存按钮不加禁用。
- 组合能力页面按最严格依赖显示：同时含 outputActions 与 ffprobe 的动作，分别判断。
- 不出现 `isTablet`、UA、`window.innerWidth`、`matchMedia` 参与能力判断。
- 视频生成区只显示「基础生成可用；海报帧、静音剥离与多段拼接可能不可用」提示，不新增按钮门控。
- 能力 `ready` 且可用时，不显示任何新增提示，桌面视觉保持现状。

### 4.5 文案契约

新增顶层命名空间 `media`，其下 `capability` 至少包含：`badge`、`loading`、`failed`、`retry`、`unavailableTitle`、`unavailableBody`、`settingsHint`、`generationHint`、`actionDisabled`、`probeDisabled`。四份 locale 键集合完全一致；`FFmpeg`、`FFprobe` 保持英文；不得在组件内硬编码中文或英文句子。

### P8 前端能力状态、API 类型与 503 兜底

**要求**
- 新增模块级能力组合式，维护 `idle/loading/ready/failed` 与能力快照。
- 新增客户端插件，应用启动时调用一次 `ensureLoaded()`，幂等。

- 请求超时 15 秒，超时按 `failed`；结构不合法按 `failed`。
- 收到 `MEDIA_UNAVAILABLE` 时显示本地化提示并后台刷新能力，不自动重放。

**约束**
- 不新增轮询；不在 `failed` 时自动无限重试。
- 不使用 UA、设备类型、视口或 `isTablet`。
- 不改变现有 API 调用的错误对象字段与重试行为。
- 不在组合式中直接拼中文；文案走 locale。
- 不把能力状态写入 Pinia 或新全局 store；保持模块级单例。
- 插件不得沿用 `pwa.client.ts` 的桌面壳跳过逻辑；Electron 桌面端同样加载能力状态。

**参考**
- `frontend/app/composables/useApi.ts` 第 4–53 行。
- `frontend/app/composables/usePwa.ts` 第 1–46 行与 `frontend/app/plugins/pwa.client.ts`。
- `frontend/app/plugins/` 现有客户端插件命名与注册方式。
- 设计文档 §8.1、§8.2、§8.5。

**设计**
- 组合式内部保存 `state`、`media`、`lastError`、`pending`；`ensureLoaded` 在 `idle` 时加载，`ready` 时直接返回，`failed` 时直接返回等待用户重试。
- `refresh(force)` 设置 `loading`，调用 `api.get('/capabilities?refresh=1', { timeoutMs: 15000 })` 或等价带超时的封装；超时置 `failed`；结构校验检查 `media` 对象与布尔字段、`missing` 数组与 `checkedAt` 字符串。
- 成功时 `ready` 并保存快照；失败时 `failed` 并保存错误消息，不保留旧快照为可用。
- `useApi` 的 `req` 在错误对象上增加 `error_code`，来源为 `json.error_code`；现有 `status`、`code`、`data` 保持。
- `useApi` 增加 `capabilities(refresh?: boolean)` 与 `MediaCapabilitySnapshot` 类型；返回 `data.media`（其中包含 `checkedAt`）。
- 组合式暴露 `handleError(error)` 或在内部提供 `isMediaUnavailable(error)`；页面捕获到该错误码时调用 `notifyUnavailable()`，设置 `ready` 且全 false 的快照并后台 `refresh(true)`。
- 插件只在客户端运行；重复调用 `ensureLoaded` 不重复请求；开发环境也加载，保证能力提示一致；桌面壳不跳过加载。
- 结构测试通过剥离类型标注执行纯派生函数，验证四态与四类 `ready`。

**自测**
- `idle` 首次 `ensureLoaded` 进入 `loading` 并只发一次请求；并发调用复用同一 Promise。
- 成功且 `outputActions: true` 时 `outputReady` 为真；false 时 `outputReady` 为假但状态仍为 `ready`。
- `audioSeparation`、`voiceActions`、`ffprobe` 分别驱动 `separationReady`、`voiceReady`、`probeReady`，任一项 false 只影响对应派生值。
- 网络失败、非 2xx、结构不合法、15 秒超时都进入 `failed`，四个 `ready` 均为假。
- `failed` 后 `ensureLoaded` 不自动请求；`refresh(true)` 才请求。
- `MEDIA_UNAVAILABLE` 触发不可用快照与一次后台刷新，不重放原动作。
- `useApi` 错误对象保留 `error_code`，既有字段不变。
- 源码中不存在设备类型或 UA 判断；能力插件不包含桌面壳跳过分支。

- `cd frontend && node --test tests/*.test.mjs` 无新增失败。

### P10 设置刷新与跨客户端一致性

**要求**
- 设置页媒体工具区显示能力摘要，不新增第二个状态源。
- 保存媒体目录成功后强制刷新能力缓存，并更新前端状态。
- 保存失败、目录无效、能力刷新失败分别给出明确提示。
- 桌面、平板、手机使用同一能力状态；服务端缺少 FFmpeg 时三类客户端显示相同标识。
- 不修改用户已选目录来掩盖失败。

**约束**
- 不新增设置页媒体状态副本；摘要读取组合式快照。
- 不改变设置页现有目录选择、保存、恢复自动与路径展示逻辑。
- 不在保存失败时假装能力已恢复。
- 不按设备类型显示不同提示。

**参考**
- `frontend/app/pages/settings.vue` 第 117、124–146、3274、3325、3375–3411 行。
- `backend/src/routes/settings.ts` 第 70–89 行。
- P1 的失效逻辑与 P8 的组合式。
- 设计文档 §8.2、§8.4、§9.3。

**设计**
- 设置页在媒体工具卡片内增加一行能力摘要：可用时显示「媒体产出可用」，不可用时显示缺失项与「暂未开放」，failed 时显示失败与重试。
- `saveMediaSettings` 成功响应后先回填现有 `mediaStatus`，再调用 `refresh(true)`；`refresh` 失败不回滚已保存目录，但显示能力检测失败。
- 目录无效时仍按现有逻辑保存并显示后端状态；能力快照为 false，摘要显示缺失项，不自动改写目录。
- 保存失败保持现有 `mediaSaveFailed` 提示，不调用能力刷新。
- 提示组件与设置摘要共用同一组合式；不新增请求去重以外的逻辑。

**自测**
- 保存有效目录后能力刷新被调用一次，摘要从不可用变为可用；按钮在页面重新进入后可用。
- 保存无效目录后目录仍落库，摘要显示不可用，错误提示明确，不自动改目录。
- 保存请求失败时不刷新能力，原状态保留。
- `refresh(true)` 失败时摘要显示失败与重试，不显示可用。
- 结构测试断言设置页只读取组合式，不维护第二份能力布尔值。

**验证**
- `cd frontend && node --test tests/media-capability-ui.test.mjs` 通过。
- 设置页在桌面、平板视口下提示不溢出，原有目录卡片功能不变。
- 后端失效测试与 P1 测试共同覆盖保存后重新探测。
