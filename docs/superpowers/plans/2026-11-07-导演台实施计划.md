# 导演台实施计划（D0–D3）

> **给执行者：** 必须使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans`，按计划点逐项执行。每一步的实施代码由执行者在执行时编写，本文件只定义要求、约束、参考、设计、自测与验证；计划正文不包含实现代码。

**目标：** 在不改变现有分镜生产链路与 ComfyUI 整集时间线的前提下，交付并列的 2D/3D 导演台：在单集制作区新增“导演台”页签（内含 2D/3D 子页签），以两表 + JSON 计划文档承载镜头、子镜头、机位与站位，支持计划编辑、版本恢复、带冲突保护地应用到分镜；导演台只是新增的第二种导演方式，不替换、不改写、不隐藏现有视频页签与整集生成流程。

**架构：** `director_plans` 保存一集一个当前计划，`director_plan_revisions` 保存版本快照；镜头、子镜头、机位、站位全部在 `doc_json` 中，不新增镜头表。后端新增导演读写服务、应用服务与路由，读取现有 `storyboards`，只在用户确认应用时按白名单写回；前端在单集制作区追加“导演台”页签（内含 2D/3D 子页签），嵌入三栏工作台、2D 舞台、3D 预演、检查器与应用弹窗，2D 与 3D 共用同一选中镜头、同一计划状态与同一保存状态；现有“素材”“视频”页签、ComfyUI 整集时间线与生成任务交互保持原样。

**技术栈：** Nuxt 3 + Vue 3.5（SPA）、Hono、Drizzle + better-sqlite3、Node `node:test` + `tsx`、Vue I18n（zh/en/ja/ko）；3D 预演使用 Three.js，仅在 D3 依赖获批后加载。

## 2. 范围与非目标

### 2.1 范围

- 单集制作区新增“导演台”页签；页签内分“2D 导演台”“3D 导演台”两个子页签；现有“素材”“视频”页签与 ComfyUI 整集时间线不变。
- 2D 俯视舞台：场景底图、网格、人物站位、人物朝向、摄影机、视锥、镜头列表、底部镜头条。
- 3D 机位预演：地面网格、场景平面、人物立牌、摄影机视锥、环绕、缩放、切到机位、选中镜头路径的受限表达。
- 镜头计划：景别、角度、运动、时长、焦距、机位高度、机位位置、目标点、站位、备注。
- 子镜头：序号、描述、时长、`path_index`；增删改与总时长校验。
- 计划保存、自动保存、手动保存、`base_version` 冲突、版本列表、备注、恢复。
- 应用到分镜：选择镜头、勾选字段、追加机位描述、同步子镜头、指纹校验、409 冲突列表、before/after 快照、已应用/已跳过/已过期。
- 开关、只读模式、镜头数上限、3D 开关、紧急环境变量回滚。
- 中文、英文、日文、韩文四语文案。

### 2.2 非目标与延期项

本批不做：

- 不替换、不改写、不隐藏现有 ComfyUI 整集时间线、视频页签、原生/ComfyUI 生成模式、合并、混音与交付流程；导演台只是并列的第二种导演方式，不成为现有流程的必经步骤。
- 不新增独立导演台页面或路由；不把导演台做成第二个生产面板、第二个播放器或第二个时间线。
- 角色动画、骨骼、动作捕捉、口型、表情动画。
- 第二个剪辑时间线、播放器、成片列表或转场编辑器。
- 新的视频生成、图片生成、ComfyUI 工作流、任务队列或生成入口。
- 修改 `storyboards` 表结构；新增第二套镜头表；按子镜头拆分为独立生产任务。
- 自动删除、自动重生成、自动标记旧视频为失败；应用后只提示“需重新生成”。
- 自动分镜；小说正文直接映射镜头；自动改写 `video_prompt` 或 `description`。
- 智能体、导演专员、建议卡与提案链路。

按总体计划 §1 D1 延期：

- `director_shots` 三表拆分与关系表方案。
- 关键帧、相机路径关键帧编辑。
- 联系表、预演图、预演静帧上传。
- 平面图导出。
- 预演素材生成与任何新素材文件。

### 2.3 2D 与 3D 共用契约

- 2D 与 3D 共用同一份 `director_plans.doc_json`、同一 `shots` 数组、同一选中镜头、同一检查器、同一保存状态与同一自动保存队列。
- 3D 只是视图：不写第二份计划、不新增镜头表、不新增素材文件、不调用生成服务。
- 视图切换不创建新的计划版本，不把 3D 轨道状态写入计划文档；3D 环绕、缩放、机位预览属于临时视图状态。
- 2D 中未保存的站位、机位、子镜头、时长修改，切到 3D 再切回必须保留；3D 中选中的镜头与人物/摄影机对象，切回 2D 后保持同一选中项。

接口响应字段：

空计划生成规则：

| 项 | 规则 |
|---|---|
| `shots` | 每个未删除分镜生成一条；`storyboard_id` 取分镜 id；`shot_number` 取 `storyboard_number`；`scene_id` 取分镜 `scene_id` |
| `duration_sec` | 取分镜 `duration`；低于 `director.duration.min` 或高于 `director.duration.max` 时钳制到范围内并给警告 |
| `camera` | 景别、角度、运动取分镜同名字段；焦距默认 35mm；高度默认 1.6m；位置默认在场景中心；`look_at` 默认指向人物站位中心或场景原点 |
| `blocking` | 取该分镜通过 `storyboard_characters` 关联、且属于当前集 `episode_characters` 的角色；无关联时为空；姓名取角色名；位置围绕场景中心分布；朝向默认 0 |
| `subshots` | 从 `description` 解析 `【镜头N】`；解析成功按数量均分镜头时长，最后一段吸收余数；解析失败生成 1 个子镜头覆盖整段 |
| `notes`、`dirty_fields` | 空字符串、空数组 |

指纹与冲突基线：

- 整体指纹覆盖当前集未删除分镜的 id、镜号、景别、角度、运动、时长、描述、视频提示词、`updated_at` 与数量，使用稳定序列化后取 SHA-256 短摘要。
- 逐镜指纹使用同一字段集合；`based_on_hash` 文本列保存“整体摘要 + 逐镜摘要清单”，不新增表字段。
- 计划文档 `based_on` 保存整体摘要与镜头数；`based_on_hash` 列是服务端权威基线，文档字段用于展示与恢复。
- 分镜被删除、新增或字段变化时，整体摘要变化；GET 通过逐镜清单给出变化镜头，供 D1/D2 提示与 409 列表使用。

模式与上限：

| 条件 | `can_edit` | 页面行为 |
|---|---|---|
| `mode=off` | 否 | 接口 403；页面显示关闭态 |
| `mode=readonly` | 否 | 可看 2D/3D 与镜头列表；无保存/应用 |
| `mode=on` 且镜头数 ≤ `maxShots` | 是 | 全功能 |
| `mode=on` 且镜头数 > `maxShots` | 否 | 只读并提示超限 |

错误状态：

| HTTP | 场景 |
|---|---|
| 400 | 集编号非法、请求参数非法 |
| 403 | `mode=off` |
| 404 | 分集不存在 |
| 422 | 已存计划文档结构非法（JSON 可解析但字段不合法） |
| 500 | 未预期错误；不得吞掉原始错误日志 |

#### D1-2 保存、冲突、版本与计划校验

**要求**
- 提供 `PUT /episodes/:id/director`：接收 `base_version`、`doc`、可选 `note`；保存计划与版本，不写 `storyboards`。
- 提供 `GET /episodes/:id/director/revisions` 与 `POST /episodes/:id/director/revisions/:revisionId/restore`。

**约束**
- 保存只写导演计划与版本，不写 `storyboards`、不写 `sys_task`、不触发生成。

- 恢复只改导演计划，不自动写回分镜；恢复后 `version` 递增，历史版本仍可查看。
- `readonly` 下所有写接口 403；版本列表可读，恢复不可用。
- 版本清理必须保留当前版本，不删除 `is_current=1` 的记录。

**设计**

保存接口：

| 项 | 设计 |
|---|---|
| 请求 | `base_version` 整数且 ≥0；`doc` 为计划文档；`note` 可选字符串 |
| 成功响应 | `version`、`doc_version`、`can_apply`、`apply_blocked_reason`、`warnings`、`revision_no`、`updated_at` |
| 版本冲突 | 409，返回 `current_version`、`updated_at`；前端停止自动保存，提示“其他窗口已保存” |
| 镜头数变化 | 409，返回当前镜头数与变化镜头清单；前端提示重新加载，不覆盖 |
| 文档结构非法 | 422，返回字段路径与中文原因 |
| 归属/范围非法 | 400，返回具体镜头与原因 |
| 只读/关闭 | 403 |

保存顺序：

1. 校验模式与集存在。
2. 解析请求体，校验 `base_version`。
3. 校验文档结构：`version=1`、`episode_id` 匹配、`view`、`shots` 数组、字段类型。
4. 校验镜头归属：`storyboard_id` 属于当前集、无重复；镜头数与当前未删除分镜数一致。
5. 校验时长范围、子镜头序号与总时长、角色归属。
6. 在事务内读取当前计划版本，再次校验 `base_version`；不一致返回冲突。
7. 写入计划文档、`version+1`、`based_on_hash`（新建时取当前指纹；已有计划保留权威基线）、`updated_at`；插入修订并切换 `is_current`；清理超过 50 的最旧非当前版本。
8. 返回新版本、`can_apply` 与警告。

版本规则：

| 项 | 设计 |
|---|---|
| `revision_no` | 从当前计划最大 `revision_no + 1` 开始 |
| `is_current` | 新版本为 1，旧当前版本置 0；同一计划最多一条当前版本 |
| 备注 | 手动保存可带备注；自动保存备注为空 |
| 恢复 | 校验版本属于当前计划与集；校验文档；插入新版本（备注可标“恢复自版本 vN”），`version` 递增；不写分镜 |
| 清理 | 保存/恢复后按 `revision_no` 从旧到新删除非当前版本，直到总数不超过 50 |
| 历史 | 恢复后旧版本仍可查询；列表按版本号倒序返回元数据 |

前端保存状态：

| 状态 | 触发 | UI |
|---|---|---|
| `idle` | 无未保存修改 | 显示“已保存”或上次保存时间 |
| `dirty` | 有未保存修改 | 显示“未保存”；启动去抖自动保存 |
| `saving` | 保存请求进行中 | 显示“保存中”；按钮禁用 |
| `saved` | 保存成功 | 显示“已保存”；清除已保存脏字段 |
| `error` | 网络/服务端错误 | 显示错误与重试；停止自动保存直到用户操作 |
| `conflict` | 409 | 显示冲突弹窗；停止自动保存；提供重新加载 |

自动保存：

- 输入/拖拽停止后去抖触发；拖拽中不保存；连续修改合并为一次。
- 同一时刻只允许一个保存请求；保存期间的新修改保留为脏状态，完成后按最新文档再保存一次。
- `readonly`、`conflict`、镜头数超限时不自动保存。
- 手动保存立即排队，优先于自动保存；保存成功后更新 `base_version`。
- 离开页面前如有未保存修改或保存中，触发浏览器离开确认；不强制拦截。

版本面板：

- 页签内工具栏“版本”按钮打开右栏抽屉或面板；显示版本号、备注、时间、当前标记。
- 手动保存前可输入备注；自动保存不输入备注。
- 恢复需二次确认；恢复后重新加载计划、选中镜头尽量保持、清空冲突状态。
- 版本面板不显示分镜快照，不提供应用入口。

**自测**
- 首次保存：编辑一个镜头，手动保存，确认 `version=1`、修订 1 条、`is_current=1`；刷新页面后站位、机位、子镜头、时长完整恢复。
- 自动保存：连续修改三个字段，确认去抖后只发一次保存；保存期间继续修改，确认最终保存包含全部修改。
- 两窗口冲突：A、B 打开同一集；A 保存；B 用旧 `base_version` 保存，确认 409；B 显示冲突提示；数据库版本仍为 A 的版本，修订数不增加。
- 镜头数变化：打开导演台后通过现有分镜接口新增一个分镜；保存计划，确认 409 与变化镜头清单；确认计划未被覆盖。

- 时长越界：把镜头时长改为低于 `director.duration.min`，保存，确认 400；数据库不变。
- 文档结构非法：构造缺少 `shots` 或字段类型错误的文档，确认 422；数据库不变。
- 版本恢复：保存 3 个版本，恢复第 1 个；确认 `version` 递增、当前版本为恢复生成的版本、旧版本仍可查看；确认分镜未被修改。
- 版本清理：连续保存 51 次，确认保留 50 条、当前版本未被删除、最旧的非当前版本被删除。
- 只读：`readonly` 下保存与恢复返回 403；版本列表可读。

### D2 应用到分镜

#### D2-1 应用服务与冲突保护

**要求**
- 提供 `POST /episodes/:id/director/apply`：接收 `base_version`、`storyboard_ids`、`fields`、`append_prompt`、`sync_subshots`。
- 应用前校验模式、版本、字段白名单、镜头归属、指纹、子镜头总时长；版本冲突 409、指纹冲突 409、字段非法 400、关闭/只读 403。
- 只写白名单字段：`shot_type`、`angle`、`movement`、`duration`；`description` 仅在 `sync_subshots=true` 且配置允许时写；`video_prompt` 仅在 `append_prompt=true` 且配置允许时追加。
- 时长先按 `director.duration.fps` 换算帧数，再按 `17n+5` 对齐；响应返回 before/after 快照。
- 已生成视频的镜头返回 `stale=true` 与“需重新生成”警告；不删除视频、不修改任务状态、不触发生成。
- 写回在单个事务内完成；任一镜头失败整体回滚，不留下部分更新。
- 应用成功后刷新计划的分镜指纹基线，清除已写回字段的脏标记，保证下一次应用能正确判断冲突。

**约束**
- `fields` 必须是 `director.apply.fields` 配置的子集，且只能包含四个白名单字段；空字段、未知字段、`description`/`video_prompt` 混入字段列表均返回 400。
- `append_prompt=true` 需要 `director.apply.promptAppend=true`；否则返回 403，不静默忽略。
- `sync_subshots=true` 需要 `director.apply.subshotSync=true`；否则返回 403。
- `sync_subshots=true` 时，子镜头数量必须与 `description` 中 `【镜头N】` 数量一致；不一致返回 409，不改写描述。
- `description` 默认不变；`video_prompt` 只追加、不覆盖；固定标记 `【机位】`；已存在标记时跳过追加，重复应用不重复追加。
- 不写 `video_url`、`composed_video_url`、`status`、首尾帧、参考图、任务表；只更新白名单字段与 `storyboards.updated_at`。
- 不新建分镜历史表；快照只出现在响应中，不落库。
- 应用不递增导演计划 `version`；只更新 `based_on_hash`、文档 `based_on` 与 `updated_at`，避免破坏保存乐观锁。

**参考**
- 规格：导演台落地方案 §5、§6.3、§7.3、§7.6、§9 D2、§10.2、§11。
- 总体计划 §1 D1、§3.4、§4、§6。
- 现有代码：`backend/src/routes/storyboards.ts` 的字段映射与归属校验；`backend/src/services/comfyui-timeline.ts` 的 `alignTimelineFrames`；`backend/src/services/edit-draft-service.ts` 的事务与冲突模式；`backend/src/services/edit-errors.ts`。

**设计**

请求字段：

| 字段 | 设计 |
|---|---|
| `base_version` | 必须等于当前计划版本；不一致 409 |
| `storyboard_ids` | 非空数组；去重；每个必须属于当前集且存在于计划 |
| `fields` | 非空数组；只能包含 `shot_type`、`angle`、`movement`、`duration`；必须是配置白名单子集 |
| `append_prompt` | 布尔；仅在配置允许时可为 true |
| `sync_subshots` | 布尔；仅在配置允许且数量一致时可为 true |

应用顺序：

1. 校验模式与集存在；`off`/`readonly` 返回 403。
2. 解析请求体；校验 `base_version`、`storyboard_ids`、`fields`。
3. 读取计划与目标镜头；校验镜头属于当前集与计划。
4. 校验配置白名单、追加/同步开关、子镜头总时长。
5. 计算当前分镜指纹，与计划基线比较；不一致返回 409 与变化镜头列表。
6. 在事务内重新读取计划版本与分镜，二次校验 `base_version` 与指纹，防止并发覆盖。
7. 逐镜计算将写字段的前后值；无变化的镜头进入 `skipped`。
8. 写回白名单字段；时长按帧对齐；按需追加提示词、同步子镜头；更新 `updated_at`。
9. 计算应用后指纹，更新计划 `based_on_hash`、文档 `based_on`、`updated_at`；清除已写回字段的脏标记。
10. 提交事务，返回 `applied`、`skipped`、`stale`、`snapshots`、`warnings`。

指纹与冲突：

- 基线使用“整体摘要 + 逐镜摘要清单”，覆盖分镜 id、镜号、景别、角度、运动、时长、描述、视频提示词、`updated_at`、删除状态与数量。
- 409 返回 `conflicts`：`storyboard_id`、`storyboard_number`、`reason`（新增/删除/字段变化）；只列实际变化镜头，不列全部。
- 外部修改分镜后应用必须 409，不静默覆盖；用户确认后可重新加载。
- 应用成功后的基线刷新在同一事务内完成；下一次应用以应用后的分镜为新基线。
- 设计稿没有定义“冲突后重新对齐基线”的独立接口；本计划提供最小恢复路径：用户确认后，前端重新读取当前分镜，更新文档 `based_on` 为当前指纹并走 `PUT` 保存；服务端校验文档 `based_on` 与当前指纹一致后才更新权威基线。该动作必须由用户显式触发，不自动执行、不新增接口。

写回矩阵：

| 字段 | 写入来源 | 条件 | 说明 |
|---|---|---|---|
| `shot_type` | 计划 `camera.shot_type` | `shot_type` 在 `fields` 且配置允许 | 未勾选保持原值 |
| `angle` | 计划 `camera.angle` | `angle` 在 `fields` 且配置允许 | 未勾选保持原值 |
| `movement` | 计划 `camera.movement` | `movement` 在 `fields` 且配置允许 | 未勾选保持原值 |
| `duration` | 计划 `duration_sec` | `duration` 在 `fields` 且配置允许 | 先按 fps 换算帧数，再按 `17n+5` 对齐；显示计划值/对齐值 |
| `description` | 子镜头描述 | `sync_subshots=true` 且配置允许且数量一致 | 默认不变；只替换对应 `【镜头N】` 段 |
| `video_prompt` | 机位描述 | `append_prompt=true` 且配置允许且无 `【机位】` 标记 | 追加一行，不覆盖；重复应用跳过 |

时长对齐：

- 帧数 = 计划秒数 × `director.duration.fps`，四舍五入后按 `17n+5` 对齐；对齐秒值 = 帧数 ÷ fps，最多保留两位小数。
- 响应快照展示 before 的当前时长、after 的对齐时长；前端在应用弹窗中显示“计划时长 / 对齐后时长”。
- 对齐后值与原值相同则 `duration` 视为无变化；所有选中字段都无变化时该镜头进入 `skipped`。
- 不写未对齐的任意小数；不改 `storyboards.duration` 列类型。

提示词追加：

- 固定格式：`【机位】景别=...；角度=...；运动=...；镜头=...mm`。
- 原提示词为空时直接写入该行；非空时另起一行追加；不删除、不改写原有内容。
- 已存在 `【机位】` 标记时跳过；重复应用不重复追加。
- 提示词追加属于“需重新生成”的变更；有视频的镜头进入 `stale`。

子镜头同步：

- 解析 `description` 中的 `【镜头N】` 标题；数量与计划子镜头数量一致才允许。
- 逐段替换标题后的描述文本，保留标题、顺序与标记外的内容；不改变 `description` 中非镜头段内容。
- 数量不一致、标题重复、标题乱序时返回 409，不写描述。
- `description` 默认不变；只有显式勾选同步且配置允许才写。

快照与结果：

- `applied`：至少一个字段或选项实际写回的镜头 id。
- `skipped`：没有实际变化的镜头 id；包括值相同、追加标记已存在、字段未勾选。
- `stale`：实际写回且原本已有视频的镜头 id；不删除视频、不改任务状态。
- `snapshots`：每个实际写回镜头一条，包含 `storyboard_id` 与本次实际写回字段的 `before`/`after`；追加/同步时包含对应字段的前后值。
- `warnings`：中文提示，如“镜头 1 已生成视频，应用后需重新生成”“部分字段未变化已跳过”。
- 快照不落库；回滚恢复依赖响应记录，设计稿 §10.3 明确保留该限制。

事务与回滚：

- 所有选中镜头的写回、计划基线刷新、脏字段清理在同一事务中完成。
- 任一镜头不存在、归属错误、字段校验失败、数据库写入失败时回滚全部变更；响应返回对应状态码。

**设计**

加载策略：

| 条件 | 行为 |
|---|---|
| `director.view3d.enabled=false` | 隐藏 3D 子页签；不挂载 3D 组件；不请求 Three.js |
| 开启但当前 2D 子页签 | 不挂载 3D 组件；不请求 Three.js |
| 当前 3D 子页签 | 动态导入 Three.js；创建渲染器、场景、相机；显示加载态 |
| 导入失败/WebGL 失败 | 回退 2D 子页签；显示原因；提供一次重试；不循环重试 |
| 默认视图 3d 且 3D 开启 | 首次激活导演台页签即切到 3D 子页签并按 3D 加载；仍只在需要时请求 Three.js |

场景元素：

| 元素 | 数据来源 | 设计 |
|---|---|---|
| 地面网格 | 固定几何 | 1 米网格；与 2D 比例一致；提供方向轴 |
| 场景平面 | 当前镜头 `scene_id` 对应场景图 | 平面贴图；无图用纯色平面 + 场景名 |
| 人物立牌 | `blocking[]` 的角色图 | 面向相机的立牌；无图用姓名占位牌；显示朝向箭头 |
| 摄影机 | 当前镜头 `camera` | 图标 + 视锥；位置、`look_at`、`lens_mm`、`height_m` |
| 路径 | 当前镜头 `camera.position` 到 `look_at` | 受限表达：视线轴 + 子镜头分段标记；不显示可拖拽折线（§1.3 S1） |
| 其他镜头 | 镜头列表 | 仅显示小型标记或不显示，避免素材膨胀 |

素材预算：

- 统计当前集所有镜头引用的唯一场景图、人物图、道具图 URL；同一 URL 只算一个。
- 唯一素材数 ≤ `director.previs.maxAssets`：加载当前镜头与可见镜头相关素材；默认只加载当前镜头，切换镜头按需加载。
- 唯一素材数 > `director.previs.maxAssets`：只加载选中镜头的场景图、站位角色图与相关道具图；其他镜头使用占位标记，不加载纹理。
- 单镜头素材仍超过上限时，按场景、主要角色、其他角色顺序截断到上限并提示；其余用占位。
- 图片加载失败不重试超过一次；失败即占位，不阻塞其他元素。

坐标与相机：

- 复用 `director-camera.ts` 的 2D/3D 换算；2D 的 x/z 对应 3D 地面 x/z，y 为高度。
- 摄影机视锥由 `lens_mm` 换算视场角；`look_at` 决定朝向；`height_m` 决定 y。
- 场景边界与 2D 一致；3D 地面范围由场景边界推导，不新增字段。

**自测**

#### D3-2 3D 交互、共享状态与降级

**要求**
- 3D 子页签支持鼠标环绕、缩放、切到机位、退出机位；显示选中镜头路径的受限表达。
- 3D 子页签与 2D 子页签共用选中镜头、选中人物/摄影机、检查器与保存状态；3D 中选中对象后检查器同步。
- 2D 未保存修改在切到 3D 再切回后不丢；3D 中不产生第二份计划、不单独保存。
- 3D 加载失败、渲染异常、上下文丢失时回退 2D 并提示，不白屏；页面其他功能继续可用。
- 关闭 3D 后网络面板不请求 Three.js；`DIRECTOR_3D=off` 紧急关闭由基础层生效。

**约束**
- 3D 不提供人物/摄影机拖拽编辑；站位与机位编辑仍在 2D 与检查器。
- 3D 子页签切换不影响导演台页签外部的视频页签、ComfyUI 整集时间线与生成任务。
- 3D 环绕、缩放、机位预览是临时视图状态，不写入计划文档，不触发脏标记。
- 切换视图不清空选中镜头、不重置未保存修改、不重复加载已加载的 Three.js 模块。
- 3D 选中对象与 2D 选中对象使用同一 id 与同一检查器状态；不得出现两套选中状态。
- 降级提示可关闭；关闭提示后仍保持 2D，不自动重试 3D。
- 3D 不触发保存、应用、生成、上传；只读展示。

|---|---|---|

共享状态：

- `useDirector` 持有唯一计划文档、选中镜头 id、选中实体、脏字段、保存状态与冲突状态。
- 2D 与 3D 只读取该状态并发出选择/编辑事件；组件内部不复制计划文档。
- 视图切换只改变 `view.mode` 的前端展示；不改变镜头数据，不标记脏，不触发自动保存。
- 3D 中选中对象后，检查器与 2D 使用同一 `selectedEntity`；切回 2D 保持选中。
- 2D 拖拽后的未保存坐标保存在 `useDirector` 的计划对象中；3D 组件重新挂载时读取同一对象。

降级与错误：

- 动态导入失败、WebGL 上下文创建失败、渲染循环异常、上下文丢失：捕获错误，切回 2D，显示中文提示；保留选中镜头与未保存修改。
- 纹理加载失败：局部占位，不整体降级；控制台记录一次警告。
- 3D 组件卸载：停止渲染循环、移除事件监听、释放几何体/材质/纹理/渲染器；取消未完成加载。
- 页面级错误边界：`DirectorWorkbench` 捕获 3D 组件错误并切回 2D；不把错误抛到页面根部。
- 重试：提示中提供一次“重试 3D”；再次失败保持 2D，不循环。

## 5. 与现有生产链路的关系

- 导演台是并列的第二种导演方式：制作区保留现有“素材”“视频”页签与 ComfyUI 整集时间线；导演台页签不替换、不改写、不隐藏该流程，也不成为生成或交付的必经步骤。
- 导演台只读 `storyboards`；镜头、子镜头、机位、站位不进入生产表，生产侧仍只认 `storyboards`。
- 只有 `POST /episodes/:id/director/apply` 会按白名单写回 `storyboards`；写回字段限于 `shot_type`、`angle`、`movement`、`duration`，以及显式勾选的 `description`/`video_prompt` 选项。
- 不新建第二套分镜数据、不新建播放器、不新建时间线、不新建任务队列；底部镜头条只用于跳转与选镜。
- 不修改 `storyboards` 表结构；不修改 `backend/src/services/comfyui-timeline.ts` 的生成算法；应用时长后 ComfyUI 时间线仍按自身 `17n+5` 逻辑生成。
- 不触发任何图片/视频生成任务；不删除、不移动、不重命名已有视频；`video_url`、`composed_video_url`、首尾帧、参考图、任务状态保持不变。
- 已生成视频的镜头只显示“需重新生成”，由用户在现有生产面板决定是否重新生成。
- `director.mode=off` 时导演台页签隐藏、接口 403；现有单集页、素材/视频页签、分镜编辑、批量生成、任务抽屉、ComfyUI 时间线与成片链路不受影响。
- 导演计划与分镜可能漂移；通过指纹、409 与快照保护，不把导演计划作为生成输入。

## 7. 风险与回滚

### 7.1 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 导演计划与分镜双份数据漂移 | 应用覆盖他人修改 | 只引用 `storyboard_id`；整体+逐镜指纹；应用前 409；不静默覆盖 |
| 时长改动破坏帧网格 | 生成结果与预期不符 | 应用时统一按 `director.duration.fps` 与 `17n+5` 对齐；弹窗显示计划/对齐值；不写未对齐小数 |
| 追加提示词重复 | 视频提示词膨胀 | 固定 `【机位】` 标记；存在即跳过；测试重复应用 |
| 子镜头同步改坏台词 | 描述被错误替换 | 默认关闭；数量/顺序不一致 409；只替换 `【镜头N】` 段；配置开关 |
| 应用部分成功 | 分镜半更新 | 单事务写回；失败全回滚；快照只在响应中 |
| 3D 包体过大/加载失败 | 页面白屏或首屏变慢 | 动态导入；关闭不加载；失败回退 2D；不阻塞页面 |
| 大场景拖拽卡顿 | 2D 不可用 | CSS transform；列表轻量；3D 只加载选中镜头相关素材 |
| 用户误以为应用后自动重生成 | 期望落空 | 明确“需重新生成”；不删旧视频、不自动排队 |
| 自动保存产生大量版本 | 版本表膨胀 | 去抖/单飞/合并；保留 50 个版本；删除最旧非当前版本 |
| 基础层产物缺失或漂移 | D0 无法开始 | D0-1 先核对；缺失按 B0 补齐；不重复定义 |
| 路径字段缺失 | 无法实现完整折线路径 | 按 §1.3 S1 限定为视线轴+分段标记；不新增字段；记录差异 |
| 逐镜冲突基线不足 | 409 无法列出变化镜头 | 复用 `based_on_hash` 文本列存整体+逐镜摘要清单；不新增字段 |
| 时长精度与整数列张力 | 回读值不一致 | 只写对齐值；快照显示实际回读；CP-D2 记录；不改列类型 |
| `director.duration.fps` 与 ComfyUI mapping fps 不同 | 对齐结果与生产时间线不一致 | 应用按设计使用 director fps；时间线仍用自身 mapping；D2 对比并记录 |
| 三语文案缺失 | 页面出现英文/空白 | 四语键集合检查；页签、子页签、空态、错误、3D 提示逐项走查 |

### 7.2 回滚顺序

1. 关闭业务开关：`director.mode=off`；紧急环境变量 `DIRECTOR_MODE=off`。
2. 关闭 3D：`director.view3d.enabled=false` 或 `DIRECTOR_3D=off`；2D 仍可用。
3. 移除页签：回退 `frontend/app/views/drama/episode.vue` 的制作区导演台页签与 `DirectorTab` 引用；不改后端数据，不新增路由需要清理。
4. 保留新表与新数据：不删 `director_plans`、`director_plan_revisions`；不自动回滚已写回分镜。
5. 需要恢复分镜时，使用应用响应中的 before/after 快照手工恢复；快照未落库，需提前保存响应记录。
6. 需要彻底下线时，先关闭开关并移除页签与组件引用，再由用户批准备份后处理新表；不自动删表、不删视频、不删任务。
7. 3D 依赖异常时优先关闭 3D 开关，不回退 2D 功能；删除 Three.js 依赖需用户批准并验证 2D 不受影响。
