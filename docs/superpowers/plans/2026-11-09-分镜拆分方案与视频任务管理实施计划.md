# 分镜拆分方案与视频任务管理实施计划

> **给执行者：** 必须使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans`，按任务逐项执行。步骤使用 `- [ ]` 复选框跟踪。

**目标：** 在不改变现有分镜输入输出契约的前提下，增加按集可选的多种拆分方案、设置页方案增删改查、左侧视频任务列表新增与删除镜头。

**架构：** 新增 `breakdown_methods` 表与 `episodes.breakdown_method` 列；拆分 Agent 在 `buildInstructions` 中按当前集读取方案，并在基础提示词与基础 Skill 之后追加方案块。设置页新增「分镜拆分」页签管理方案；视频页选择方案并写入剧集字段，手动拆分与全自动流程共用同一份选择。分镜新增由后端自动编号，删除时清理转场、软删台词并重算整集时长。

**技术栈：** Nuxt 3 + Vue 3.5、Hono、Drizzle + better-sqlite3、Node `node:test` + `tsx`、Vue I18n 四语言。

**设计依据：** [分镜拆分方案与视频任务管理落地方案](../specs/2026-11-09-分镜拆分方案与视频任务管理落地方案.md)

## 全局约束

- 数据库只做加法：新增表、新增可空列；不改旧列语义，不做破坏性迁移。
- 不提交、不构建/打包、不安装依赖、不重启应用，除非用户明确要求；所有改动默认保持未提交。
- 不打印或泄露任何 Key、Token、密码；不修改用户已选择的模型与服务配置。
- 保持端口不变：前端开发 3013，后端开发 5679；不改 G5、MCP、ComfyUI 模板与现有路由。
- 后端测试必须使用隔离的 `SQLITE_PATH`、`HUOBAO_DATA_DIR`、`STORAGE_PATH` 与 `MYSQL_AUTO_IMPORT=false`，不得触碰开发库。
- 面向用户的文案使用中文，并同步 `zh/en/ja/ko` 四份 locale；技术标识、表名、接口名保持英文。
- 不新建第二套分镜编辑器、任务列表或播放器；全部复用现有视频制作页与设置页。
- 拆分方案的「提示词 + Skill」只通过 Agent instructions 注入，不写入 `workspace/skills/`。
- 没有运行证据不得标记完成；缺少文本模型时，真实拆分验收记为阻塞，不以结构测试替代。
- **计划正文只写要求、约束、参考、设计、自测与验证，不写实现代码。** 代码由执行者在每个计划点内按设计完成。
- 每个计划点固定六段式：要求、约束、参考、设计、自测、验证。

## 1. 口径裁决

| 编号 | 歧义/冲突 | 裁决 | 理由 |
| --- | --- | --- | --- |
| C1 | 方案按项目还是按集 | 按集选择，空值回退 `standard` | 拆分对象是剧集；全自动流程也以集为单位 |
| C2 | 方案是否替代基础 Skill | 追加并声明覆盖，不删除基础 Skill | 保留工具契约与字段契约，降低回归风险 |
| C3 | `standard` 是否要写一份完整文本 | 两段文本为空，直接沿用现有规范 | 保证未选择方案时行为完全一致 |
| C4 | 内置方案能否编辑/删除 | 可编辑、可恢复默认、不可删除 | 内置需要稳定存在；用户可从副本派生 |
| C5 | 自定义方案删除后引用怎么办 | 引用剧集置空，回退 `standard` | 避免悬空 key 阻断拆分 |
| C6 | 新增镜头插入位置 | 固定追加到末尾 | 本轮不做重排与中间插入，避免编号迁移 |
| C7 | 删除镜头是否重排编号 | 不重排 | 界面按位置显示；整体重拆时由 `replace_existing` 重写 |
| C8 | 方案是否通过 Agent 请求参数传递 | 不传，后端按 `episodeId` 读库 | 保证自动流程与手动拆分一致 |
| C9 | 方案是否影响独立视频提示词补生成 | 不影响 | 本轮只改拆分 Agent；补生成链路保持现状 |
| C10 | 删除镜头是否删文件/任务历史 | 不删 | 保留素材与诊断证据；只清理分镜、关联、转场 |

## 4. 跨任务契约

### 4.1 数据库

`breakdown_methods` 表：

| 列 | 类型 | 约束 |
| --- | --- | --- |
| id | INTEGER | 主键自增 |
| key | TEXT | 非空、唯一 |
| name | TEXT | 非空 |
| description | TEXT | 默认空字符串 |
| prompt | TEXT | 非空、默认空字符串 |
| skill | TEXT | 非空、默认空字符串 |
| builtin | INTEGER | 非空、默认 0 |
| sort_order | INTEGER | 非空、默认 0 |
| created_at | TEXT | 非空 |
| updated_at | TEXT | 非空 |

`episodes.breakdown_method`：TEXT，可空，存方案 key；空值等同 `standard`。

内置 key 与排序：`standard` 10、`hook-beat` 20、`director-board` 30、`h3-compact` 40、`trailer-cut` 50。自定义方案 `sort_order` 从当前最大值加 10。

### 4.2 服务接口

`backend/src/services/breakdown-methods.ts` 对外提供：

- `DEFAULT_BREAKDOWN_METHODS`：只读数组，元素含 key、name、description、prompt、skill、sortOrder。
- `ensureBreakdownMethodsSeeded()`：幂等补齐内置方案，返回 Promise。
- `listBreakdownMethods()`：返回摘要数组，元素含 key、name、description、builtin、sortOrder、usageCount、customized。
- `getBreakdownMethod(key)`：返回完整方案或 null。
- `createBreakdownMethod(input)`：input 含 name、description、prompt、skill；返回完整方案。
- `updateBreakdownMethod(key, input)`：返回完整方案；不存在抛错。
- `deleteBreakdownMethod(key)`：内置抛错；返回 `{ releasedEpisodes }`。
- `resetBreakdownMethod(key)`：仅内置；返回完整方案。
- `duplicateBreakdownMethod(key)`：返回新自定义方案。
- `buildBreakdownMethodBlock(method)`：两段文本 trim 后均为空返回 null；否则返回方案块字符串。
- `getEpisodeBreakdownBlock(episodeId)`：episodeId 为空、读不到剧集或剧集无方案时返回 null；读剧集方案并返回方案块；任何异常记录告警并返回 null。

输入校验：名称去首尾空格后 1–60 字；prompt 最长 20000 字；skill 最长 40000 字；description 去首尾空格，不设硬上限。

### 4.3 HTTP 接口

| 方法与路径 | 请求 | 成功返回 | 失败 |
| --- | --- | --- | --- |
| GET `/breakdown-methods` | 无 | 200 + `{ list: 摘要数组 }`，字段 snake_case | 500 |
| GET `/breakdown-methods/:key` | 无 | 200 + 完整方案，字段 snake_case | 未知 key 404 |
| POST `/breakdown-methods` | name、description、prompt、skill | 201（`created`）+ 新建方案 | 校验失败 400 |
| PUT `/breakdown-methods/:key` | name、description、prompt、skill | 200 + 更新方案 | 未知 key 404；校验失败 400 |
| DELETE `/breakdown-methods/:key` | 无 | 200 + `{ released_episodes }` | 未知 key 404；内置 400 |
| POST `/breakdown-methods/:key/reset` | 无 | 200 + 恢复后的方案 | 未知 key 404；自定义 400 |
| POST `/breakdown-methods/:key/duplicate` | 无 | 201（`created`）+ 复制出的方案 | 未知 key 404 |

返回字段：`key、name、description、prompt、skill、builtin、sort_order、usage_count、customized、created_at、updated_at`。列表接口省略 prompt/skill 以减小体积。

`PUT /episodes/:id` 增加 `breakdown_method`：

- 允许 null 或空字符串，落库为 null。
- 非空时必须是已存在方案 key，否则返回 400。
- 成功后剧集列表接口通过 snake_case 自动带出该字段。

### 4.4 前端 API 客户端

`frontend/app/composables/useApi.ts` 新增 `breakdownMethodAPI`：

- `list()` 调用 GET `/breakdown-methods`。
- `get(key)` 调用 GET `/breakdown-methods/:key`。
- `create(data)` 调用 POST `/breakdown-methods`。
- `update(key, data)` 调用 PUT `/breakdown-methods/:key`。
- `del(key)` 调用 DELETE `/breakdown-methods/:key`。
- `reset(key)` 调用 POST `/breakdown-methods/:key/reset`。
- `duplicate(key)` 调用 POST `/breakdown-methods/:key/duplicate`。

### 4.5 注入块契约

方案块固定包含：

1. 标题：`## 当前分镜拆分方案：<name>`。
2. 优先级声明：与基础规范冲突时以本方案为准；工具名与调用顺序、字段名、ID 来源、首批 `replace_existing`、每批最多 8 个、`shot_number` 递增不可违背。
3. `### 方案提示词` 与方案 prompt 正文。
4. `### 方案 Skill` 与方案 skill 正文。

拼接顺序：系统提示词 → 基础 Skill → 方案块 → 声音引用指令 → 语言指令。未编辑的 `standard`（两段文本为空）、未选择方案或两段文本均为空时不产生方案块；用户把 `standard` 编辑为非空后同样注入。

### 4.6 前端命名

设置页状态：`breakdownMethods`、`breakdownLoading`、`breakdownSaving`、`breakdownDraft`、`breakdownOriginal`、`breakdownEditingKey`、`breakdownToDelete`；派生 `breakdownDirty`（草稿与原始值四字段比较）。函数：`loadBreakdownMethods`、`selectBreakdownMethod`、`newBreakdownMethod`、`saveBreakdownMethod`、`resetBreakdownMethod`、`duplicateBreakdownMethod`、`confirmDeleteBreakdownMethod`。

视频页状态：`breakdownMethods`、`breakdownMethodKey`、`methodSaving`、`shotDelete`（`{ open, loading, target }`）。函数：`loadBreakdownMethods`、`changeBreakdownMethod`、`addStoryboard`、`deleteStoryboard`、`confirmDeleteStoryboard`。模板 ref：`sbDescriptionInput`。

### 4.7 i18n 键

设置页统一挂在 `settings.tabs.breakdown` 与 `settings.breakdown.*` 下，至少包含：`title、subtitle、new、name、description、prompt、skill、promptHint、skillHint、bothEmptyHint、save、saving、saved、reset、resetConfirm、duplicate、delete、deleteTitle、deleteMessage、deleteUsage、unsaved、empty、loadFailed、builtin、custom、customized、usage`。

视频页挂在 `episode.sb.*` 与 `episode.vid.*` 下，至少包含：`methodLabel、methodStandard、methodSaved、methodSaveFailed、rebreakConfirm、newShot、newShotTitle、addShot、addShotHint、deleteShot、deleteConfirm、deleteDone、addDone`。

### P2 内置方案常量与方案服务

**要求**
- 提供五条内置方案常量与幂等播种。
- 提供方案查询、创建、更新、删除、恢复默认、复制、使用计数。
- 提供方案块构建与按集读取。
- 删除自定义方案时回退引用剧集。

**约束**
- 播种只补缺失 key，绝不覆盖用户编辑。
- `standard` 初始 prompt 与 skill 为空。
- 内置方案不可删除；`reset` 只允许内置。
- 自定义 key 由后端生成，格式为 `custom-` 前缀，不可由用户指定。
- 删除自定义方案必须在事务内完成「剧集引用置空 + 删除方案」。
- 名称、prompt、skill 的长度限制在服务层统一校验。
- 不在此任务修改 Agent、路由或前端。

**参考**
- 设计文档 §4.2–§4.5、§4.8、§5.1。
- `backend/src/services/pipeline-rules.ts` 的默认值/自定义值模式。
- `backend/src/db/schema.ts` 的 `breakdownMethods` 与 `episodes`。

**设计**

内置方案内容要求：

| key | prompt 必须包含 | skill 必须包含 |
| --- | --- | --- |
| `standard` | 空 | 空 |
| `hook-beat` | 竖屏短剧爆款导演定位；3 秒抓人；每段结尾留钩子；冲突/反转/信息差优先 | 6–12 秒/段；2–3 子镜；开场 0–2 秒给冲突画面；段尾钩子类型；台词密度；不使用纯环境铺垫开场 |
| `director-board` | 电影导演/分镜师定位；先定机位覆盖再写动作；强调轴线与视线 | 5–10 秒/段；2–4 子镜；A 主镜/B 过肩/C 特写/D 环境四类覆盖；每子镜写景别、角度、运镜；`transition` 与 `continuity` 服务于镜头连接 |
| `h3-compact` | 本地 H3 视频管线导演定位；5–8 秒成片约束；单动作单场景 | 5–8 秒/段；1–3 子镜；单段台词与旁白不超过 24 字；固定或轻推为主；避免复杂运镜与多人调度；`video_prompt` 按 3 秒段对齐 |
| `trailer-cut` | 预告片剪辑师定位；画面冲击优先；信息密度高 | 3–6 秒/段；1–2 子镜；动作切点与匹配剪辑优先；极少台词；用近景/特写制造冲击；避免长铺垫与解释性画面 |

每条内置方案的 description 写一句适用场景，并注明参考来源方向：`standard` 注明沿用现有系统规范，其余分别注明短剧 Skill、导演 A/B/C/D、H3 管线、快切分镜。不复制外部仓库原文，使用中文重写。

服务实现要点：

- 播种：读取全部已有 key；只插入缺少的内置 key；插入时 `builtin=1`、时间戳为当前时间；并发首次调用用模块级 Promise 去重。启动接入放在 `backend/src/index.ts` 的 `migrateUploadedVoices()` 附近，`await` 播种，失败只记录错误、不阻断启动；`listBreakdownMethods`、`getBreakdownMethod`、`createBreakdownMethod` 入口先等待同一个幂等播种 Promise，保证测试与热重载路径也能拿到内置方案。
- 列表：按 `sort_order`、`id` 升序；使用计数通过 episodes 聚合，只统计 `deleted_at` 为空且 `breakdown_method=key` 的剧集。
- `customized`：内置方案与默认常量按 name、description、prompt、skill 四字段逐项比较得出；自定义方案固定为 false，前端只在内置项展示「已自定义」。
- 创建：生成自定义 key；名称必填；description、prompt、skill 缺省为空字符串；默认追加到最大 `sort_order` 加 10；返回完整行。
- 更新：key 必须存在；只更新名称/说明/prompt/skill，缺省字段沿用原值；名称提供时重新校验；`updated_at` 刷新。
- 恢复：key 必须是内置；用默认常量覆盖四个文本字段；返回恢复后的行。
- 复制：源方案必须存在；名称固定由服务端生成 `${source.name} 副本`，不接受前端传入名称；新 key 为自定义；复制四段文本；排序追加。
- 删除：内置拒绝；事务内先把引用剧集置空，再删方案；返回释放剧集数。
- 方案块：两段文本 trim 后都为空返回 null（未编辑的 `standard` 即如此）；否则按 §4.5 拼接；标题与声明使用中文。
- 按集读取：episodeId 为空返回 null；查 episodes 取 key；无 key 返回 null；有 key 时查方案并交给方案块构建（未编辑的 `standard` 自然得到 null，编辑后的 `standard` 正常注入）；key 不存在记录告警并返回 null；任何数据库异常记录告警并返回 null，不抛出。
- 长度校验失败抛出带中文原因的错误，由路由转换为 400。

测试文件扩展 `backend/tests/breakdown-methods.test.ts`：

- 列表使用计数只统计未删除剧集。
- 方案块：未编辑的 `standard`（两段为空）返回 null；编辑后返回非空块；自定义块包含标题、优先级声明、两段正文；数据库异常返回 null 不抛。

**自测**

- 页面加载时调用一次 `breakdownMethodAPI.list()`，存入 `breakdownMethods`；同一页面切集不重复请求；失败时设为只含 `standard` 的本地兜底项，并提示一次。
- `breakdownMethodKey` 从 `episode.value?.breakdown_method` 读取；为空或不在列表时取 `standard`。
- `refresh()` 更新 `episode.value` 后同步 `breakdownMethodKey`，避免切集或外部修改后仍显示旧值；方案保存请求进行中时跳过同步，防止回滚覆盖。
- 顶部栏在原生/ComfyUI 模式切换后增加 `label` 与原生 `select`；选项显示方案名，选中值绑定 key；`rn`（`useAgent` 的 running）为真时禁用。
- 方案保存进行中 `methodSaving` 为真时，下拉与拆分按钮一并禁用，保证「保存成功后才允许重新拆分」。
- 切换处理：
  - 若 Agent 运行中直接返回。
  - 记录旧值，先更新 `episode.value.breakdown_method`，再调用 `episodeAPI.update(epId, { breakdown_method: key })`。
  - 成功提示 `episode.sb.methodSaved`；失败恢复旧值并提示 `episode.sb.methodSaveFailed`。
- `doBreakdown` 开头增加：`sbs.value.length` 大于 0 时，用 `window.confirm(t('episode.sb.rebreakConfirm', { n: sbs.length, method: 当前方案名 }))`，取消则返回。
- 空态描述追加当前方案名；拆分按钮 title 显示方案名。
- 页面刷新后若剧集字段被外部修改，以下拉显示为准；不做轮询。

**自测**
- 切换方案后刷新页面，选择保持。
- 后端不可用时下拉只有标准，拆分仍可点击。
- 已有分镜点击拆分弹出确认，取消后不发请求。
- Agent 运行中下拉禁用。
- ComfyUI 模式下切换方案不破坏现有预览与运行按钮。

**验证**

### P7 左侧视频任务列表新增镜头

**要求**

**约束**

- 不自动生成描述、视频提示词或视频。
- 不改变 `POST /storyboards` 的其他字段语义与绑定校验。
- 选择模式打开时仍可新增，但新增后退出选择模式，避免选中态混淆。

**参考**
- 设计文档 §4.7。
- `backend/src/routes/storyboards.ts` 的 `POST /`。
- `frontend/app/views/drama/episode.vue` 第 576 行列表头、第 562 行空态、第 756 行描述编辑框、第 3084 行 `videoDurationMax`、第 2873 行行点击。
- `frontend/app/composables/useApi.ts` 第 169 行 `storyboardAPI`。

**设计**
- 后端：
  - 先校验 `episode_id` 对应的剧集存在，不存在返回 400「剧集不存在」，不写任何关联。
  - 读取该集所有分镜的最大 `storyboardNumber`；`body.storyboard_number` 为空或 0 时使用最大值加一，否则沿用传入值。
  - 其余逻辑不变：绑定校验、角色/道具同步、返回 snake_case 与 `character_ids/prop_ids`。
  - 不修改时长默认值 10，截断由前端负责。
- 前端：
  - 列表头增加按钮，图标用已有 `Plus`，文案 `episode.vid.addShot`；空态增加次级文字按钮 `episode.vid.addShotHint`。
  - `addStoryboard()`：
    - `rn` 为真或新增请求进行中时直接返回。
    - 源镜头取 `selectedSb`，否则取 `sbs` 最后一项。
    - 场景取源镜头 `scene_id`；角色/道具取 `getStoryboardCharacters/getStoryboardProps` 的 ID；无源镜头则为空。
    - 时长取 `Math.min(10, videoDurationMax.value || 10)`，且不小于 2。
    - 标题用 `t('episode.vid.newShotTitle', { n: sbs.length + 1 })`，描述与氛围留空。
    - 调用 `storyboardAPI.create`，参数含 `episode_id`、标题、描述、时长、场景、角色、道具；不传 `storyboard_number`，由后端自动编号。
    - 成功后刷新、退出选择模式、按返回 id 选中新镜头、`nextTick` 聚焦描述编辑框。
  - 给描述 textarea 增加 `ref="sbDescriptionInput"`；聚焦前先 `nextTick`。
  - 失败用 `toastError`，不乐观插入假行，并恢复按钮可用状态。

### P8 左侧视频任务列表删除镜头

**要求**
- 每行提供删除入口，删除前确认。
- 后端删除同步软删台词、删除角色/道具关联、删除相关 AI 转场、重算整集时长。
- 删除选中镜头后自动选中相邻镜头；删到空回到空态。

**约束**
- 不重排 `storyboard_number`。
- 不删除已生成视频文件、`sys_task` 历史、素材库记录。
- 选择模式下不显示单行删除按钮，避免与勾选冲突。
- 删除必须在数据库事务内完成，任一步失败整体回滚；不能留下转场悬空。
- 确认文案必须说明台词与转场会删除、视频文件保留。

**参考**
- 设计文档 §4.7、§6。
- `backend/src/routes/storyboards.ts` 的 `DELETE /:id`。
- `backend/src/db/schema.ts` 的 `videoTransitions`。
- `backend/src/agents/tools/storyboard-tools.ts` 第 352–361 行的时长口径。
- `frontend/app/views/drama/episode.vue` 第 593–650 行任务行。

**设计**
- 后端删除顺序：
  1. 查询分镜；不存在返回「镜头不存在」。
  2. 软删该分镜关联台词（保留现有 `deletedAt/updatedAt` 逻辑），不写台词墓碑，便于后续重拆按剧本重建。
  3. 删除 `storyboardCharacters` 与 `storyboardProps`。
  4. 删除 `videoTransitions` 中 `fromStoryboardId` 或 `toStoryboardId` 等于该 ID 的行。
  5. 硬删分镜行。
  6. 查询该集剩余分镜，按存活时长求和，更新 `episodes.duration` 为向上取整分钟数，并刷新 `updatedAt`。
  - 使用数据库事务包裹 2–6；任一步失败整体回滚。
  - 返回 `{ deleted_id, episode_id, duration_minutes }`。
- 前端：
  - 行内在名称右侧或行尾增加删除图标按钮，图标用已有 `Trash2`；默认低透明度，行 hover 或按钮 `focus-visible` 时显示；仅非选择模式渲染；`@click.stop`。
  - `deleteStoryboard(sb)`：
    - 若 `videoSelectMode` 或 `rn` 为真直接返回。
    - 记录当前在 `allVideoTaskRows` 中的位置，预取后继 ID（同位置下一项，越界取前一项），作为删除后的选中目标。
    - 设置 `shotDelete.target = sb`，打开 `ConfirmDialog`，不在行内直接删除。
  - `confirmDeleteStoryboard()`：
    - 置 `shotDelete.loading`，调用 `storyboardAPI.del`。
    - 成功后关闭弹窗、刷新列表；按预取目标 ID 选中，目标不存在则选第一项，列表空则清空选中。
    - 从 `selectedVideoSbIds` 中移除该 ID；提示 `episode.vid.deleteDone`。
    - 失败提示错误并保留弹窗关闭后的原列表，不乐观删除。
  - 模板增加 `ConfirmDialog` 实例，绑定 `shotDelete`，文案包含镜头序号/标题，并明确「分镜与关联台词、相邻 AI 转场会删除；已生成视频文件与任务历史保留」。
  - 删除按钮 title 与 aria-label 使用同一文案，保证键盘可见。
- 四语言补齐新增文案。

**自测**
- 删除中间镜头后，前后镜头仍在，列表序号按位置连续显示，内部编号允许空洞。
- 删除按钮默认隐藏，行 hover 或键盘聚焦时显示；选择模式下不渲染。
- 删除选中镜头后自动选中后继；删除最后一个选中前驱；删空显示空态。
- 删除带 AI 转场的镜头后，`video_transitions` 无起止引用该 ID 的行。
- 删除后剧集时长等于剩余分镜时长之和向上取整。
- 关联台词被软删，其他镜头台词不受影响。
- 已生成视频文件与 `sys_task` 行仍存在。
- 选择模式下看不到删除按钮。

**验证**
- `cd backend && npx tsx --test tests/storyboard-management.test.ts` 全部通过。
- 浏览器走查删除流程，记录确认框、选中回退、空态与时长证据。
