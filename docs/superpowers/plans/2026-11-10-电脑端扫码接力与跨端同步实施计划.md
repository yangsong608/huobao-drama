# 电脑端扫码接力与跨端同步实施计划

- 日期：2026-11-10
- 状态：P0–P15 已执行完毕（未提交、未打包、未安装）；终审静态验证通过；真机与局域网验收待执行
- 范围：R0 安全基座、R1 同步与在线、R2 接力与前端；R3 冲突增强（v1.5）与 R4 后续可选只登记范围，本期不实施
- **执行结果（2026-11-11）**：后端 remote/sync/presence 定向测试 88 项通过；前端 remote+tablet 209 项通过；全量后端 1409 项、前端 748 项通过（Node 22）。独立应用与电脑之间的数据同步不在本文范围，见 `docs/superpowers/plans/2026-11-11-平板与移动端独立应用实施计划.md` 的 A8。
- 设计依据：`docs/superpowers/specs/2026-11-10-电脑端扫码接力与跨端同步设计.md`
- 关联文档：`docs/移动端移植方案分析-2026-11-10.md`、`docs/Y700独立运行与局域网同步方案-2026-11-10.md`、`docs/平板端部署与访问说明.md`、`docs/superpowers/plans/2026-11-10-平板端FFmpeg能力门控实施计划.md`

**目标：** 在电脑端保留回环主后端的前提下，新增一个按需开启的局域网远程桥；手机或平板扫码后经一次性配对与电脑确认获得设备会话，调用电脑端同一套前端与 `/api/v1` 接口继续当前工作；电脑与移动端通过变更事件、在线状态与接力上下文感知彼此，首版用脏表单保护避免静默覆盖。

**架构：** 同一实例、两个监听器。主后端继续监听 `127.0.0.1` 随机端口；远程桥绑定电脑选中的私有 IPv4 与固定端口 5680，先做设备 Cookie 鉴权、路径白名单与只读拦截，再把请求委托给现有 Hono `app.fetch`。数据只有一份 SQLite 与一套媒体目录；同步只广播“哪个路径变了”的序号事件，不复制数据、不做双向合并。

**技术栈：** Hono + TypeScript、Drizzle/SQLite 现有表与幂等 DDL、`@hono/node-server` 第二监听器、Node 22/24 内置 `crypto`/`net`/`os`、`node:test`；Nuxt 3 + Vue 3 SPA、现有 i18n JSON、现有确认对话框与 toast；服务端二维码生成只评估纯 JS、无原生模块、许可证兼容的二维码库，其余不新增运行时依赖。

**设计依据：** 本文所有角色、协议、路径、错误码与验收以设计文档 §7–§17、§19 为准。实现中发现设计遗漏或代码现状与设计不一致时，先改设计并记录差异，再改代码；不得用实现便利替代安全默认。

## 全局约束

- 本期只实施 R0、R1、R2；R3（v1.5 冲突增强）与 R4（HTTPS 本地证书、隧道、mDNS、服务器模式管理员配对）不写代码、不排期、不占验收。
- 主后端继续只监听回环；不得把 `5679`、桌面随机端口或远程桥端口映射到公网；远程桥不提供 TLS，只用于可信局域网。
- 远程桥默认关闭、手动开启、不随应用启动自动恢复；打开二维码对话框视为一次显式开启动作。已配对设备记录保留，重新开启后仍可使用原会话。
- 电脑确认固定开启，不实现关闭开关，不实现“扫码即接入”，不做按设备免确认；每次配对都由电脑端选择“允许（全量/只读）”或“拒绝”。
- 默认范围全量，可选只读；只读设备只允许 GET/HEAD、同步订阅、在线心跳与登出，其余非 GET 业务请求一律 403。
- 会话默认 30 天，设置只保留 7/30/90 三档；不做滑动续期；活跃设备上限 10 台；撤销立即生效。
- 不新增用户、账号、角色、租户、组织或权限表；只有设备会话与全量/只读范围。
- 管理与配对接口只在桌面进程（`HUOBAO_DESKTOP=1`）且本机回环请求下可用；服务器模式与远程桥上一律 404。`GET /api/v1/remote/session` 例外，无设备上下文时返回 `host`。
- 桥对主机专属接口返回 404：`/api/v1/storage/*`、`/api/v1/server-update/*`、`/api/v1/mcp/*`、`/api/v1/ai-configs/*`、`/api/v1/ai-providers/*`、`/api/v1/settings/media`；全量范围不等于主机管理权限。
- 远程桥必须是同源入口：不依赖跨域、不为桥扩大 CORS 白名单、不做 HTML 登录页；未认证 API 返回 401 JSON，未认证页面回退到 `/pair`。
- 配对码、短码、设备令牌、Cookie、桥密钥不得进入日志、事件、错误响应、数据库明文或前端持久化；令牌只通过 `Set-Cookie` 下发。
- 同步只广播事件元数据，不推送请求体、响应体、台词、提示词、素材地址；任务进度继续沿用现有 3–4 秒轮询，不用 SSE 重复推送。
- 事件序号与环形缓冲只在进程内，不落库；进程重启后 `instanceId` 变化，客户端通过 `reset` 刷新，不做历史事件持久化。
- 首版只做脏表单保护与远端更新提示；不实现 `base_updated_at`、409 `STALE_WRITE`、编辑租约、CRDT 或双向数据库合并，这些属于 R3 或 Y700 路线。
- 移动端产出能力只取电脑端 `/api/v1/capabilities` 与既有 FFmpeg 门控；不按手机型号、UA、视口宽度或 `isTablet` 分支。A13 在门控未落地前标“阻塞”，不得用结构测试冒充。
- 局域网 HTTP 页面可用但不可安装 PWA；需要安装能力时继续走既有 HTTPS 反向代理，本期不新增受信任证书方案。
- 唯一允许评估的新增后端依赖是服务端 SVG 二维码库；必须通过许可证、体积、维护状态与无原生模块审查。审查不通过时暂停并回到设计评审，不静默改成前端二维码包。
- 不修改用户已选模型、AI 供应商、音色、媒体目录或 FFmpeg 配置来掩盖测试失败；测试只用隔离数据库、临时目录与测试进程环境变量。
- 不触碰当前工作区已有的分镜动作检验未提交改动、`backend/src/agents/*` 相关未提交改动与 `desktop/package.json`；本计划的改动必须按文件逐项隔离。
- 本计划不包含代码，也不在本次文档编写中执行构建、安装、启动、测试、提交或推送；实施阶段另行获得明确许可。
- 没有真机、真实局域网与隔离数据目录时，相应验收标“阻塞”；结构测试、接口单测或模拟扫码不能替代真机闭环。
- 文档、测试记录与最终报告不得出现真实内网 IP、域名、证书路径、令牌、Cookie、密码、`PUBLIC_BASE_URL` 或用户数据。
- 新增文案同步 `zh/en/ja/ko` 四份 locale；设备平台名与错误码必须本地化，不直接展示技术错误码。

## 1. 口径裁决

| 编号 | 歧义 | 裁决 | 理由 |
| --- | --- | --- | --- |
| M1 | 是复制数据还是共享实例 | 共享同一实例；移动端调用电脑端接口 | 用户诉求是继续电脑端工作；数据、任务、FFmpeg 只有一份 |
| M2 | 主后端是否改为监听局域网 | 不改；新增独立桥 | 避免给全部路由补全局鉴权，失败面收敛在桥 |
| M3 | 桥是否随应用启动 | 默认关闭，每次手动开启 | 默认安全；已配对记录保留即可复用 |
| M4 | 二维码是否携带长期令牌 | 只携带一次性配对码与 `next` | 二维码可能被拍照/投屏；长期权限不能印在屏幕上 |
| M5 | 电脑确认是否可关闭 | 固定开启，无开关 | 防止“扫码即接入”变成默认路径 |
| M6 | 默认范围 | 全量，可选只读 | 覆盖继续工作；只读覆盖审片/演示 |
| M7 | 设备令牌如何保存 | 32 字节随机值，HttpOnly Cookie，数据库只存 SHA-256 哈希 | 防 XSS 读取与数据库泄露直接复用 |
| M8 | 管理接口如何隔离 | 桌面进程 + 本机回环 + 回环 Host 三重判定；桥上与服务端模式返回 404 | 防止远程设备自我扩权，也防止同机反代暴露管理面 |
| M9 | 服务器模式是否支持二维码 | 本期不支持；保持既有 HTTPS 反代 | 没有管理员身份模型，不能复用“本机即管理员”假设 |
| M10 | 同步是否复制数据 | 不复制；只发变更事件与在线状态 | 同一数据库天然一致，复制会引入冲突与版本漂移 |
| M11 | 事件序号是否持久化 | 不持久化；进程内 `instanceId` + `seq`，重启发 `reset` | 避免历史日志表与清理成本；全量刷新足够 |
| M12 | 任务进度是否走 SSE | 不走；保留现有轮询 | 任务进度高频且已有成熟轮询，重复推送无收益 |
| M13 | 首版是否做保存冲突 409 | 不做；首版只做脏表单保护与提示 | 降低所有高价值写接口的改造面；409 放 v1.5 |
| M14 | 在线状态是否可作为可用性判定 | 不作为；只用于展示与反向接力 | 电脑窗口关闭但后端/桥仍在时，远程仍应可用 |
| M15 | `next` 是否信任查询参数 | 每次生成、提交、领取都按白名单校验；非法回退 `/` | 防止开放重定向与跳到外部地址 |
| M16 | 移动端能力是否按设备判断 | 只看电脑端服务端能力接口 | 设备类型不能决定服务端有没有 FFmpeg |
| M17 | HTTP 下是否承诺 PWA | 不承诺；页面可用但不提示安装 | 安全上下文限制是浏览器行为，不能用文案绕过 |
| M18 | 二维码在哪里生成 | 服务端生成 SVG；前端只展示 | 载荷格式一处实现，避免前端新增二维码包 |
| M19 | 日志如何处理配对信息 | 配对请求体、Cookie、令牌、短码、查询码不进日志 | 一次性码进日志等于把入口写进历史 |
| M20 | `clientId` 是否可作为鉴权 | 不可；只用于事件来源与去重 | 原生 `EventSource` 不能加自定义头，查询参数必须视为不可信 |
| M21 | 只读设备的非 GET 例外 | 只允许在线心跳与登出；其余非 GET 一律 403 | 同步订阅是 GET；心跳必须能上报 |
| M22 | 运行中能否改端口 | 不能；先关闭桥再改 | 旧二维码与已打开页面会失效，运行中改端口不可预测 |
| M23 | 设备上限如何计算 | 只计未撤销且未过期的设备；达到 10 台拒绝新配对 | 防止遗忘设备无限累积 |
| M24 | 前后端版本是否兼容旧后端 | 不做兼容分支；前后端同版本部署 | 旧后端没有远程/同步接口，新前端按不可用处理并明确提示 |
| M25 | 桥密钥是否需要 | 需要；进程内随机桥密钥头，主应用只在该头匹配时信任设备上下文 | 防止主后端被误绑定到局域网后伪造设备头 |

## 4. 跨任务契约

### 4.1 角色与状态

- 电脑端 `host`：桌面窗口或本机回环浏览器；唯一可开启桥、生成配对码、批准/拒绝/撤销设备的一端。
- 移动端 `guest`：经桥访问；未配对只能加载 `/pair` 与公开信息。
- 配对会话状态：`waiting` → `pending` → `approved` / `denied` / `expired` / `cancelled`。
- 设备会话状态：`active` → `revoked` / `expired`。
- 桥状态：`disabled` → `enabling` → `running` → `disabling` → `disabled`；失败进入 `error` 并保留原因。
- 移动端页面状态：`loading` → `need-code` → `requesting` → `pending` → `claiming` → `paired`；任一阶段可进入 `error`。
- 同步状态：`idle` → `connecting` → `online` → `reconnecting` → `polling` → `offline`；401 进入 `unpaired`。

### 4.2 配对载荷与二维码

- 配对码：32 字节随机值的 base64url，约 43 字符；只在内存配对会话中保存哈希与短码。
- 短码：6 位数字，绑定同一配对会话；只用于手动输入兜底。
- 有效期：120 秒；单次使用；最多 3 个并发配对会话；过期、拒绝、取消后不可复用。
- 二维码载荷只包含桥地址、`/pair`、一次性配对码与编码后的 `next`；不包含设备令牌、管理地址或版本细节。
- `next` 必须按 §4.8 校验；生成、提交、领取三处都要校验，不信任查询参数原始值。
- 二维码由服务端生成 SVG；SVG 不得引用外部图片、字体、脚本或统计；前端只插入返回的 SVG。
- 配对页读取码后立即从地址栏移除；响应设置 `Referrer-Policy: no-referrer` 与 `Cache-Control: no-store`。

### 4.3 配对接口

- 本机管理接口（桌面本机回环可用，桥上 404）：状态、设置、开启、关闭、创建配对、查询配对、批准、拒绝、取消、设备列表、撤销单设备、全部撤销。
- 远程公开接口（未配对可访问，仅桥）：公开信息、提交配对、查询状态、领取会话、取消自己的请求。
- 远程已配对接口：会话、登出、同步事件、同步序号、在线上报与读取。
- 公开信息只返回服务名、是否需要确认、是否 HTTPS；不返回设备、路径、Key、版本细节。
- 领取会话的 `waitToken` 单次使用；批准后只能领取一次；领取响应只通过 `Set-Cookie` 下发令牌，响应体不含明文令牌。
- 批准时默认范围全量，可选只读；设备上限为 10 台活跃设备；超过返回 `REMOTE_DEVICE_LIMIT`。
- 配对状态轮询按 `waitToken` 限制为每 2 秒最多 1 次；正常等待不计入短码失败次数。

### 4.4 设备会话与 Cookie

- 设备令牌 32 字节随机值；Cookie 名 `huobao_device`；`HttpOnly`、`SameSite=Lax`、`Path=/`；有效期按设置 7/30/90 天，默认 30 天；HTTPS 下加 `Secure`。
- 数据库只存 SHA-256 哈希；比较使用定时安全比较；不存明文令牌。
- 设备记录字段：id、name、platform、token_hash、scope、created_at、last_seen_at、expires_at、revoked_at、user_agent、last_ip。
- `last_seen_at` 与 `last_ip` 最多每 5 分钟落库一次；设备列表不返回完整 UA、完整 IP 或 token_hash。
- 不做滑动续期；到期前 3 天在设备列表提示；到期、撤销、过期后请求返回 401。
- 撤销立即生效：关闭该设备所有 SSE，后续请求 401；撤销记录保留撤销时间用于排查。
- 设备上限只统计未撤销且未过期的设备；达到上限时新配对返回 409。

### 4.5 主机接口与桥 404 清单

- 主机管理接口：`/api/v1/remote/status`、`/api/v1/remote/settings`、`/api/v1/remote/enable`、`/api/v1/remote/disable`、`/api/v1/remote/pairing` 及其子路径、`/api/v1/remote/devices` 及其子路径。
- 主机专属接口：`/api/v1/storage/*`、`/api/v1/server-update/*`、`/api/v1/mcp/*`、`/api/v1/ai-configs/*`、`/api/v1/ai-providers/*`、`/api/v1/settings/media`。
- 以上两类在桥上直接返回 404 JSON，不进入主应用路由，不返回 HTML。
- 桌面本机守卫同时检查：`HUOBAO_DESKTOP=1`、连接来源为回环、`Host` 为回环主机名；任一不满足返回 404。
- 服务器模式（非桌面进程）管理接口与配对接口一律 404；`GET /api/v1/remote/session` 仍返回 `host`。

### 4.6 桥请求管线

1. 只接受当前前端需要的 HTTP 方法与 `OPTIONS`；`OPTIONS` 只返回必要响应。
2. 设置 `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`；配对相关响应加 `Referrer-Policy: no-referrer` 与 `Cache-Control: no-store`。
3. 未认证时 `/` 与业务页面回退 `/pair?next=...`；放行 `/pair` 与前端壳静态资源的 GET/HEAD；未认证不得访问 `/static/*`。
4. 放行公开配对接口；限流后委托。
5. 其他 `/api/v1/*` 与认证后的 `/static/*` 必须先校验设备 Cookie；失败返回 401 JSON，不返回 HTML 登录页。
6. 只读设备：非 GET/HEAD 业务请求返回 403；允许同步订阅、在线心跳与登出。
7. 非 GET 请求校验 `Origin` 与桥来源一致；缺失或不一致返回 403。
8. 按桥来源构造请求 URL，保留路径与查询串、Range、If-Range、If-None-Match、Accept 等头；请求体与响应体按流转发，不整段缓冲；不生成指回 `127.0.0.1` 的绝对链接。
9. 委托前剥离客户端伪造的设备头与桥密钥头，写入认证后的设备 id、范围、角色与进程内随机桥密钥；主应用只在该密钥匹配时信任设备上下文。
10. 管理接口与主机专属接口在桥上直接 404，防止远程设备自我扩权。
11. 任何错误都返回带 `error_code` 的 JSON；不把内部异常栈、路径或配置返回给远程设备。

### 4.7 错误码与响应

| 错误码 | HTTP | 含义 | 前端处理 |
| --- | --- | --- | --- |
| `REMOTE_DISABLED` | 503 | 桥未开启或已关闭 | 显示“电脑端未开启手机接力” |
| `REMOTE_UNAUTHORIZED` | 401 | 未配对、过期或已撤销 | 访客跳转配对页并保留 `next`；主机不跳转 |
| `REMOTE_READONLY` | 403 | 只读设备写操作 | 提示“该设备为只读”，不禁用查看 |
| `PAIRING_EXPIRED` | 410 | 配对码或请求过期 | 回到配对页重新扫码或输入短码 |
| `PAIRING_DENIED` | 403 | 电脑拒绝 | 显示拒绝原因与重新配对入口 |
| `PAIRING_PENDING` | 202 | 等待电脑确认 | 继续轮询，不视为失败 |
| `REMOTE_RATE_LIMITED` | 429 | 配对或短码尝试过多 | 显示等待时间，禁止自动重试轰炸 |
| `REMOTE_DEVICE_LIMIT` | 409 | 活跃设备达到上限 | 提示先在电脑撤销旧设备 |
| `STALE_WRITE` | 409 | v1.5 保存版本过期 | v1.5 才实现；首版不返回 |
| `MEDIA_UNAVAILABLE` | 503 | 电脑端 FFmpeg 能力缺失 | 复用既有门控提示，不改成只读错误 |

- 业务成功继续沿用 `{ code, data, message }`；远程错误使用 HTTP 状态码加 `{ code, message, error_code }`。
- `useApi` 新增独立 `errorCode` 字段，只在响应含 `error_code` 时赋值；不改变现有 `code` 的语义与既有错误处理。
- 设备列表、错误响应与日志都不得返回或记录 token_hash、完整 UA、完整 IP、Cookie、桥密钥。

### 4.8 `next` 白名单

- 必须以 `/` 开头，且不能以 `//` 开头；不能包含协议、主机、反斜杠或控制字符；长度不超过 512。
- 只允许精确匹配 `/`、`/settings`、`/novels`、`/huobao-novel`，或以 `/drama/`、`/novels/`、`/huobao-novel/` 开头。
- 不合法时回退 `/`，不报错、不跳转外部地址。
- 已知重工作台路径在访客端做降级映射：`/drama/:id/episode/:n/edit` 落到同集详情页并显示接力提示，不强制在手机打开桌面时间线。
- 电脑端生成二维码前提示“未保存的文本修改请先保存；接力只传递当前位置”。

### 4.9 设置键

| 键 | 默认 | 校验 | 说明 |
| --- | --- | --- | --- |
| `remote.port` | `5680` | 整数 1024–65535；运行中不可改 | 桥端口；关闭时可改 |
| `remote.bind_address` | 空 | 空或合法私有 IPv4；由开启动作写入 | 上次选择的私有地址；空表示自动选第一个 |
| `remote.session_days` | `30` | 只允许 7/30/90 | 设备会话有效天数 |
| `remote.device_name` | 操作系统主机名 | 去空格后 1–40 字符 | 电脑在配对页显示的名称 |

- 不设 `remote.require_approval`；电脑确认固定开启。
- 不设 `remote.auto_start`；桥不随应用启动自动开启。
- 设置读写使用现有 `app_settings`；非法值回退默认并记录不含敏感信息的警告。
- 服务器模式不读取、不暴露这些设置；管理接口 404。

### 4.10 同步事件模型

- 进程启动生成 `instanceId`；全局 `seq` 从 0 开始递增；环形缓冲保留最近 500 条事件。
- 中间件在主应用上挂载；非 GET/HEAD、路径以 `/api/v1/` 开头、响应状态小于 400 时发事件。
- 排除配对、同步、在线状态自身接口以及 `/api/v1/remote/*` 管理接口；撤销由会话层单独发 `revoked`。
- 事件字段：`seq`、`instanceId`、`at`、`method`、`path`、`source`；不含查询串、请求体、响应体、台词、提示词或素材地址。
- `source` 优先取认证设备 id，其次取客户端 id，内部调用标记 `server`；客户端 id 不作为鉴权依据。
- 事件广播失败不得影响业务响应；事件总线异常只记录警告，不写请求内容。
- 回放规则：序号仍在缓冲内则补发缺失事件；序号过旧或 `instanceId` 变化则发 `reset`；序号相同只发心跳。
- 直接调用 service 的写入必须显式发事件或在 P9 审计表中登记轮询兜底；不允许静默遗漏。

### 4.11 SSE 契约

| 事件 | 数据 | 说明 |
| --- | --- | --- |
| `hello` | `instanceId`、`seq`、`serverName` | 连接建立后立即发送 |
| `change` | `seq`、`method`、`path`、`source`、`at` | 业务写请求成功 |
| `presence` | 在线设备列表：设备名、范围、页面上下文、最近活跃 | 按订阅者角色生成，访客不收其他访客 |
| `ping` | 时间 | 20 秒一次，保持连接与代理存活 |
| `reset` | `instanceId`、`seq` | 事件缺口或服务重启，客户端刷新已注册视图 |
| `revoked` | 设备 id | 当前设备被撤销，客户端停止重试并跳转配对页 |

- 每条事件都写 SSE `id`；`change` 用其 `seq`，其他事件用当前 `seq`；`hello`/`reset` 的 `data` 另带 `seq`，客户端以 data 为准。
- 连接建立时校验设备 Cookie；失败返回 401，不建立流。
- `clientId` 通过查询参数传递，只用于来源标记与去重；设备身份始终来自 Cookie。
- 心跳同时检查设备有效性；撤销或过期时发送 `revoked` 并关闭流。
- 响应头明确 `text/event-stream`、`no-cache`、`keep-alive`，并设置禁用代理缓冲的头；不压缩。
- 每个订阅者维护设备、客户端、角色、最后序号与写队列；写串行化；断开、撤销、桥关闭、服务退出都要清理。
- 部署要求：`/api/v1/sync/events` 关闭代理缓冲与流式压缩，透传 `Last-Event-ID`，设置足够长读超时。

### 4.12 在线状态

- 客户端每 20 秒上报一次 `{path, dramaId?, episodeId?, stage?}`；页面切换立即上报一次，1 秒防抖。
- 桥内由桥强制标记 `guest`，忽略客户端自报角色；主应用回环/反代访问默认 `host`。
- 服务端保存在线表，60 秒无心跳视为离线；撤销/断开立即移除。
- 主机看到全部设备；访客只看到主机与自己；服务端按订阅者角色分别生成 `presence` 事件。
- 在线状态只传 ID 与阶段名，不传正文、提示词、台词内容。
- 电脑端设备列表显示“手机 · 第 3 集 · 混音”；点击可打开同一位置，实现反向接力。
- 在线状态不作为业务可用性判定；电脑窗口关闭但后端与桥仍在时，远程继续可用。

### 4.13 客户端标识与来源

- 每个标签页生成 `clientId`，优先存 sessionStorage，缺失时回退内存；不作为鉴权。
- `useApi` 统一给请求注入 `X-Client-Id`；SSE 通过查询参数传递。
- 若开发态跨端口预检未放行 `X-Client-Id`，只在 CORS 配置中显式允许该头，不扩大 origin 白名单。
- 服务端把设备 id 或 `clientId` 写入事件 `source`；客户端忽略自己发出的写事件，避免自触发刷新。
- 同一设备的不同标签页 `clientId` 不同，应互相刷新；设备撤销以设备 id 为准。

### 4.14 日志脱敏

- `/api/v1/remote/pair/*`、`/api/v1/remote/pairing/*`、`/api/v1/remote/session`、`/api/v1/remote/logout` 不记录请求体。
- 不记录 `Cookie`、`Set-Cookie`、`Authorization`、桥密钥头、配对码、短码、waitToken、设备令牌。
- 查询串中的配对码不进入日志；桥不额外打印完整 URL 查询串。
- 事件总线只记录路径与方法，不记录请求体；错误日志不打印设备令牌或 Cookie。
- 现有 `requestLogger` 的 POST/PUT/PATCH 请求体打印必须增加路径排除，不能只在桥层处理。

### 4.15 测试隔离与版本口径

- 后端测试使用隔离 `SQLITE_PATH` 与临时媒体目录；不写开发库、不读用户数据目录、不修改用户设置。
- 桥网络测试使用可注入地址分类与监听器工厂；真机/真实端口验收单独进行。
- 前端结构测试只读源码与 locale，不启动浏览器；真机验收使用真实局域网。
- 前后端同版本部署；不兼容旧后端的远程/同步接口。旧后端缺失接口时，前端按“不可用”提示，不静默降级为主机。
- 任何测试记录包含命令、退出码、通过/失败数、环境说明；没有记录的结果不算证据。

- 过期/撤销清理任务按设计执行；撤销记录先保留撤销时间用于排查。

**约束**

- 不做滑动续期；不做按设备免确认；不新增账号体系。
- 不把令牌写入 localStorage、URL、日志或响应体。
- 不以 IP、UA、设备名作为鉴权依据；它们只用于显示与排查。
- 不修改用户配置来绕过过期或撤销；测试可注入时钟与令牌生成器。

**参考**

- 设计文档 §7.5、§7.6、§12.1、§13.1。

**设计**

- 令牌生成与哈希：随机 32 字节 base64url；SHA-256 十六进制存库；Cookie 值为明文令牌，数据库无明文。
- 校验：从 Cookie 取令牌，计算哈希，按哈希查设备；校验未撤销、未过期；范围写入请求上下文。
- 签发：只在领取接口调用；同一请求只能签发一次；签发后请求标记已领取。
- 设备上限：统计未撤销且未过期设备；达到 10 台时批准接口返回 409。
- 最近活跃：`last_seen_at` 与 `last_ip` 最多每 5 分钟更新一次；不因每个请求写库。
- 撤销：设置 `revoked_at`；调用同步/在线状态服务关闭该设备 SSE；后续请求 401。
- 清理：过期设备不参与活跃计数；保留期结束后删除；撤销记录保留撤销时间。
- 会话序列化：`role`、`deviceId`、`name`、`platform`、`scope`、`readonly`、`serverName`、`expiresAt`；主机无设备时只返回 `role: host`。

### P7 同步序号、事件总线与写路径中间件

**要求**

- 事件只含序号、实例、时间、方法、路径、来源；不含查询串、请求体、响应体或业务内容。
- 来源优先取认证设备 id，其次取客户端 id，内部调用标记 `server`。
- 直接调用 service 的写入补发事件或登记轮询兜底；完成写路径覆盖审计。
- 事件广播失败不影响业务响应；异常只记录警告。
- 提供 revision 查询所需的当前实例与序号。

**约束**

- 不持久化事件、`seq` 或 `instanceId`；不新建事件日志表。
- 不为 GET 请求发事件；不为失败响应发事件；不为配对/同步/在线状态发数据变更事件。
- 不把请求体、响应体、台词、提示词、素材地址写入事件。
- 不阻塞业务响应等待广播完成；不因事件异常回滚业务。
- 不在业务路由逐个手写事件；统一中间件 + 少量直连 service 显式补发。
- 不重复发事件：同一写入经内部 REST 已发时，不再由 service 重复发。

**参考**

- 设计文档 §8.2、§11.3。
- `backend/src/index.ts:73-81`、`90-148`、`207-217`。

**设计**

- 中间件在 `await next()` 后读取响应状态；满足条件才发事件；路径规范化后判断排除。
- 事件来源：桥注入的设备 id 优先；否则读 `X-Client-Id`；都没有标记 `server`。
- 回放：请求携带 `Last-Event-ID` 时，若实例相同且序号在缓冲内，返回缺失事件；若过旧或实例不同，返回 `reset` 信号；若相同，返回空。

- 审计表列：service 入口、写入对象、触发方式、是否发事件、兜底路径、备注。

### P8 SSE 事件流与轮询降级接口

**要求**

- 新增 `GET /api/v1/sync/events`：设备 Cookie 鉴权通过后建立 SSE；主应用主机访问沿用现有访问控制。
- 连接建立后立即发送 `hello`；随后发送 `change`、`presence`、`ping`、`reset`、`revoked`。
- 每条事件写 SSE `id`；支持 `Last-Event-ID` 回放；`clientId` 只作为查询参数来源标记。
- 心跳 20 秒一次；心跳同时检查设备有效性；撤销/过期发送 `revoked` 并关闭。
- 新增 `GET /api/v1/sync/revision`：返回当前 `instanceId` 与 `seq`，供轮询降级使用。
- 订阅者写串行化；断开、撤销、桥关闭、服务退出都要清理；不允许订阅者泄漏。
- 响应头明确流式、禁用缓存与代理缓冲；不压缩。
- 在线状态事件按订阅者角色生成；访客不收其他访客。

**约束**

- 不使用 WebSocket；不引入 SSE 客户端库；不要求前端自定义请求头。
- 不以 `clientId` 鉴权；不因查询参数携带设备令牌。
- 不推送完整业务数据、任务进度百分比或台本内容。
- 不缓冲 SSE；不在代理层开启压缩。
- 不在鉴权失败时建立流；不返回 HTML 错误页。
- 不把订阅者列表暴露给客户端。

**参考**

- 设计文档 §8.3、§11.4、§16.2。
- `backend/src/routes/novelJobs.ts:135-192` 的 `streamSSE`、心跳、写串行化与清理。
- `backend/src/middleware/remote-auth.ts`（P5）与 `backend/src/services/sync-events.ts`（P7）。

**设计**

- SSE 路由先解析设备上下文；失败返回 401 JSON；成功则进入 `streamSSE`。
- 订阅者对象：设备 id、角色、客户端 id、最后发送序号、写队列、关闭标记。
- 连接时发送 `hello`；读取 `Last-Event-ID`；按回放规则补发或发 `reset`；之后订阅实时事件。
- 写函数串行化：每个订阅者一个 Promise 链；写失败只关闭该订阅者，不影响其他订阅者。
- 心跳：20 秒定时写 `ping`；同时检查设备过期/撤销；异常时发 `revoked` 并清理。
- 撤销回调：设备服务撤销时调用总线/SSE 服务，向该设备订阅者发 `revoked` 并关闭。
- 桥关闭：关闭所有 guest 订阅；host 订阅由主应用管理。
- revision：直接返回总线当前状态，不建立流。
- 响应头：`text/event-stream`、`no-cache`、`keep-alive`、禁用缓冲头；不压缩。

**自测**

- 连接后先收到 `hello`，字段完整；`change` 的 `id` 等于 `seq`。
- 带 `Last-Event-ID` 且序号在缓冲内时补发缺失事件；过旧或实例变化时收到 `reset`。
- 心跳按 20 秒发送；断开后定时器与订阅者被清理。
- 设备撤销时收到 `revoked` 并关闭；旧 Cookie 再连 401。
- revision 返回当前实例与序号；轮询变化可被前端识别。
- 只读设备可订阅；访客只看到主机与自己；主机看到全部。
- 响应头符合流式要求；没有压缩与缓冲。
- 多订阅者并发写入不串行阻塞彼此；单个写失败不影响其他。

**验证**

- 新增 SSE 测试通过；使用短心跳间隔注入时钟，不等待真实 20 秒。
- `cd backend && npm run typecheck` 通过。
- 使用路由 `request` 与模拟流；不启动真实代理。

### P13 实时同步、页面刷新与脏表单保护

**要求**

- 新增 `useRealtimeSync` 模块级单例：连接、重连、降级、事件分发、状态、统一 401。
- 启动条件：访客始终连接；主机仅在桥开启或存在已配对设备时连接；服务器模式默认不连接。
- 事件处理：`hello` 记录实例与序号；`change` 命中注册表；`presence` 更新在线状态；`reset` 刷新全部注册视图；`revoked` 停止并跳转。
- 页面通过 `useSyncedRefresh` 注册路径匹配器与刷新函数；事件命中且页面可见时 300–500 毫秒防抖后刷新。

- 表单有未保存修改或保存中时，不自动刷新；显示“另一台设备已更新此内容”，提供“刷新（放弃我的修改）”与“保留我的修改”。
- 重连退避 1/2/5/10/30 秒并加随机抖动；连续 3 次失败切 10 秒轮询 revision；轮询期间每 60 秒尝试恢复 SSE。
- 忽略自己发出的写事件；同一设备不同标签页仍应刷新。
- 401 访客停止重试并跳转配对页；403 只读只提示；主机/服务器模式不改既有 401 行为。
- 接入页面：项目列表、剧集详情、剧集页、剪辑页、小说列表、小说详情、小说工作台。
- 接入页面必须保留现有任务轮询与可见性轮询。

**约束**

- 每个客户端只允许一条 SSE；页面不得各自建连接。
- 不自动刷新脏表单；不整页 reload 普通变更；不用 WebSocket。
- 不通过 SSE 推送任务进度；不修改任务轮询周期。
- 不在服务器模式默认开启实时同步；不改变既有服务器反代行为。
- 不把事件路径当业务数据；刷新函数自行决定拉取范围。
- 不在页面卸载后保留定时器或事件监听。

**参考**

- 设计文档 §8.4、§8.5、§8.6。
- `frontend/app/views/drama/episode.vue:5548` 与 `useVisibilityPolling`。
- `frontend/app/pages/index.vue`、`frontend/app/views/drama/detail.vue`、`frontend/app/views/drama/edit.vue`。
- `frontend/app/pages/novels/index.vue`、`frontend/app/views/novel/detail.vue`、`frontend/app/pages/huobao-novel.vue`、`frontend/app/pages/huobao-novel/[...slug].vue`。
- `frontend/app/composables/useApi.ts`、`frontend/app/composables/useClientId.ts`（P10）。

**设计**

- 单例状态：idle、connecting、online、reconnecting、polling、offline、unpaired；保存实例、序号、最后事件 id、重试次数。
- 连接：EventSource 使用 `/api/v1/sync/events?clientId=...`；Cookie 同源自动携带；不自定义头。
- 事件分发：`change` 的 `source` 等于本标签页 clientId 时忽略；否则匹配注册表；`presence` 交给在线状态；`reset` 调用全部刷新；`revoked` 清理并跳转。
- 注册表：键为页面标识；每项含路径匹配器、刷新函数、脏状态读取函数；页面卸载时注销。
- 防抖与可见性：同一页面 300–500 毫秒内多次事件只刷新一次；隐藏时记录 pending；可见时执行。
- 脏表单：页面维护 dirty/saving；命中变更时不刷新，显示提示条；用户选择后执行或丢弃。
- 重连：手动管理 EventSource；打开成功重置次数；失败按退避；3 次后关闭并轮询 revision；轮询发现序号变化触发刷新；每 60 秒尝试恢复 SSE，恢复后停止轮询。
- 401/403/撤销：401 且 guest 跳转；403 提示只读；revoked 跳转；host/server 保持原行为。
- 页面接入：为每个页面提供路径匹配器与刷新函数；刷新函数只拉取当前页数据，不整页 reload；保留任务轮询。
- 编辑页：剪辑草稿与时间线状态注册脏保护；远端变更时只提示，不覆盖未保存操作。

**自测**

- 单例只创建一条 EventSource；多个页面注册不会重复连接。
- 退避序列正确；3 次失败切轮询；恢复 SSE 后停止轮询；不产生事件风暴。
- 自事件被忽略；其他标签页/设备事件触发刷新。
- 脏表单收到事件只显示提示；两种选择都可用；不自动覆盖。
- 页面隐藏不刷新；恢复可见执行待刷新；卸载后无定时器。
- `reset` 刷新全部注册视图；`revoked` 清理并跳转；401 只对 guest 跳转。
- 任务轮询代码未被修改；任务进度仍由现有轮询更新。
- 七个页面均已接入匹配器；无页面遗漏或重复连接。

**验证**

- 新增实时同步结构测试通过。
- `cd frontend && node --test tests/*.test.mjs` 通过。
- 真实双端刷新与断线恢复留到批次 B/C 运行时验收。

### 6.2 设计验收 A1–A19

> 真机项必须有设备与真实局域网；没有设备时标记“阻塞”，不得用结构测试或接口单测冒充通过。

- [ ] A1 扫码配对：手机扫码→电脑出现确认→允许→手机进入电脑当前页面；设备列表出现该设备。
- [ ] A2 短码配对：手机打开配对地址输入短码→电脑出现确认→允许→进入同一页面；限流生效。
- [ ] A3 配对码过期/拒绝/取消：分别得到明确文案；不能进入业务页面；可重新扫码。
- [ ] A4 未配对访问：手机直接访问业务 API 返回 401；配对页可加载；无数据泄露。
- [ ] A5 只读设备：GET/播放/SSE 正常；任意写请求 403；界面不出现可编辑入口。
- [ ] A6 撤销设备：撤销后旧 Cookie 401；SSE 收到 `revoked` 并关闭；设备列表移除/标记。
- [ ] A7 全量设备：手机在已支持的手机界面执行一次真实写操作并触发一次真实任务；电脑端能看到同一结果。
- [ ] A8 电脑→手机同步：电脑修改台词/分镜后，手机在 1 秒内（SSE）或 10 秒内（轮询降级）看到更新。
- [ ] A9 手机→电脑同步：手机修改后，电脑端对应视图刷新；不要求刷新整个页面。
- [ ] A10 脏表单保护：手机有未保存修改时，电脑修改不会自动覆盖；出现提示；两种选择都可用。
- [ ] A11 在线状态：两端显示彼此在线与当前页面；手机切页电脑端跟随；离线 60 秒内消失。
- [ ] A12 接力上下文：电脑在第 3 集混音生成二维码；手机进入同集；手机无该工作台时显示接力提示。
- [ ] A13 产出能力：电脑有 FFmpeg 时手机可触发合片/导出；电脑无 FFmpeg 时两端均显示“暂未开放”；直接调用返回 503。FFmpeg 门控未落地时标“阻塞”。
- [ ] A14 电脑离线：手机显示断线/电脑离线；任务状态与现有恢复逻辑一致；不出现静默写入。
- [ ] A15 安全日志：日志、事件、错误响应中无配对码、令牌、Cookie、API Key。
- [ ] A16 端口/地址变更：端口占用时启动失败有明确提示；IP 变化后旧链接失效并可重新生成。
- [ ] A17 性能：每个客户端仅一条 SSE；页面隐藏不刷新；重连不产生事件风暴；电脑无持续高 CPU。
- [ ] A18 回归：桌面本机、服务器反代、平板 PWA 三种既有入口均不受影响。
- [ ] A19 主机接口隔离：全量设备访问存储、更新、MCP、AI 供应商与媒体路径接口均返回 404；设置页对应入口不可见；本机窗口仍可正常管理。
