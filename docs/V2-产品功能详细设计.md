## 0. 摘要

V2 把产品从「能出片」推进到「能配音、能兜底、能批量」。

三条主线：

1. **声音成为一等资产**：每个角色（含旁白）拥有独立音色档案。资产制作阶段同时生成「声音提示词」，可直接试听、换音色、上传参考音频克隆；音色跨集复用，不随分镜丢失。
2. **时间轴成为一等数据**：从 `video_prompt` 的 `0-3秒：` 分段中抽取台词与旁白，逐句 TTS，按真实音频时长回写绝对时间轴，产出 SRT/ASS 字幕，并与视频原声做 ducking 混音。
3. **产能与稳定性补齐**：图文动画兜底、宫格图、整本剧本分章分集、持久化任务队列与资源锁。

V2 不改变现有「项目 → 剧集 → 资产 → 分镜 → 视频 → 合片」主链路，新增能力以**可选阶段**和**独立服务**挂接，未配置语音服务时全部降级为 V1 行为。

### 1.2 六个结构性缺口

| # | 缺口 | 现象 | 根因 |
| --- | --- | --- | --- |
| G1 | 有音色样本，没有配音 | 对白仍由视频模型一次性生成，改词/改语气/加旁白只能重生成整镜 | 没有「逐句语音」这一层数据 |
| G2 | 音色是上传物，不是设定 | 换机器、换模型、换集后音色不可复现；无法用文字描述一个声音 | 缺少声音提示词与音色档案 |
| G3 | 本地 H3 不吃参考音频 | 上传的音色在本地链路几乎不影响输出 | H3 参考音频能力限制，非本项目 bug |
| G4 | 没有字幕 | `video_prompt` 里已有 `0-3秒：` 时间码，但从未被消费 | 时间码只作为提示词，没有结构化 |
| G5 | 视频失败即断 | 任一镜失败，整集卡住，没有低成本兜底 | 只有「生成视频」一条路 |
| G6 | 产能瓶颈 | 整本剧本手工拆集；跨集同时跑自动化会抢 GPU，重启丢进度 | 无队列、无资源锁、进度只在内存 Map |

### 1.3 设计结论

- 缺的不是「再接一个 TTS」，而是**声音档案 + 逐句台词 + 绝对时间轴**这三层中间数据。有了它们，字幕、混音、图文动画、二次修改都变成纯数据操作，不再依赖重新生成视频。
- 音色必须**先于分镜**存在：角色资产阶段确定声音，分镜阶段才能按角色分配台词，配音阶段才能只做合成。
- 所有新增阶段必须**幂等、可停、可续**，与 V1 自动化保持同一套语义。

## 2. 目标与边界

### 2.1 目标（可验收）

| 编号 | 目标 | 验收口径 |
| --- | --- | --- |
| O1 | 角色音色可生成、可试听、可替换 | 新建角色后 ≤10 秒产出声音提示词，≤20 秒产出 6–12 秒试听样音 |
| O2 | 配音可独立于视频重做 | 改一句台词只重合成该句，不重新生成视频；单句重合成 ≤10 秒 |
| O3 | 字幕与语音对齐 | 抽 10 句，字幕起止与音频偏差 ≤150ms |
| O4 | 混音听感统一 | 成片整体 −16 LUFS ±0.5，真峰值 ≤−2 dBTP；旁白段原声被压低 ≥6dB |
| O5 | 全流程可无人值守 | 第 5 集成片一次跑通，8 阶段进度可见，停止后可续跑，重启不丢队列 |
| O6 | 视频失败有兜底 | 任一镜失败可一键出「图文动画」版本，时长与配音时间轴一致 |

### 2.2 本期不做

| 不做项 | 原因 | 替代 |
| --- | --- | --- |
| 实时流式配音、边说边播 | 成片是离线批处理，流式无收益 | 逐句离线合成 |
| 唇形同步 / 口型对齐 | 需要视频重生成或专门模型，成本高 | 旁白/心声走画外音；对白尽量用侧/背/远景镜头（提示词约束） |
| 音乐生成模型 | 本地无可用音乐模型 | 本地 BGM 曲库 + 自动循环淡出 + ducking |
| 音效生成 | TTS 不产生音效 | 保留 H3 环境声；P3 再做音效库关键词匹配 |
| 多用户 / 权限 / 计费 | 单机创作工具 | 无 |
| 音色市场 / 分享 | 涉及声音版权 | 仅项目内复用 |
| 自动对口型重生成 | 同上 | 人工挑镜头 |

### 2.3 V1 → V2 功能对照

| 能力 | V1 | V2 |
| --- | --- | --- |
| 音色 | 上传样本，仅作视频参考 | 声音提示词 + 设计/克隆 + 试听 + 跨集复用，并驱动 TTS |
| 对白 | 视频模型一次性生成，改词需重生成整镜 | 逐句 TTS，可改词、可重配、可单句重合成 |
| 旁白/心声 | 混在提示词里，靠模型自由发挥 | 结构化旁白行，独立音色，画外音约束 |
| 字幕 | 无 | SRT/ASS，软字幕与烧录两种模式 |
| 混音 | 逐段 loudnorm 后拼接 | 配音轨 + sidechain ducking + BGM + −16 LUFS 统一响度 |
| 视频失败 | 整集卡住 | 图文动画兜底，时长与配音对齐 |
| 角色一致性 | 逐张生成，易漂移 | 宫格图一次生成再切分 |
| 建集 | 手工逐集填内容 | 整本剧本分章、预览、批量建集 |
| 并发 | 进程内 Map，跨集抢卡 | 持久化队列 + 资源锁 + 心跳恢复 |
| 声音可控性 | 不可调 | 提示词、语速、情绪基线、seed、换一个 |

## 4. 语音服务对接（Qwen3-TTS）

### 4.1 部署形态与模型选型

语音服务部署在**另一台机器**，后端只通过 HTTP 调用，不假设 GPU 同机。

| Checkpoint | 能力 | 显存（bf16 估算） | 用途 |
| --- | --- | --- | --- |
| `Qwen3-TTS-12Hz-1.7B-VoiceDesign` | 文本描述造音色 | 5–6 GB | **主路径**：新角色无参考音频时生成音色 |
| `Qwen3-TTS-12Hz-1.7B-Base` | 3 秒起克隆（ICL/x-vector） | 5–6 GB | 用户上传参考音频时克隆 |
| `Qwen3-TTS-12Hz-1.7B-CustomVoice` | 内置预设音色 + instruct | 5–6 GB | 快速草稿、配角、群杂 |
| `Qwen3-TTS-12Hz-0.6B-Base` | 克隆（轻量） | 2–3 GB | 低配机、批量草稿 |

要点：

- 官方仓库与权重按 Apache-2.0 发布（以模型卡为准），输出 24 kHz，支持 10 种语言；**VoiceDesign 无 0.6B 版本**。
- 克隆默认走 ICL（`ref_audio` + 精确 `ref_text`）质量最好；`x_vector_only` 无需转写但相似度下降。
- 参考音频建议 3–20 秒干净人声；本项目上传入口限制 20MB（`AUDIO_MAX_BYTES`），合成前统一转 24 kHz 单声道 WAV。
- 情绪控制：VoiceDesign/CustomVoice 支持自然语言 `instruct`；**克隆模式不支持独立情绪参数**，只能靠标点、语速与参考音频本身，UI 需明示。
- 服务端可选：SGLang-Omni（OpenAI 兼容 `/v1/audio/speech`，支持流式）、vLLM-Omni（当前以离线批处理为主）、社区 `qwen3-tts-api`（提供 `/v1/audio/speech/upload` 与 `/v1/audio/speech/design`）、或自建 FastAPI 包一层 `qwen_tts`。

> 性能不在设计期拍数字。部署完成后在「设置 → 语音服务 → 压测」跑 10 句、每句 20–40 字，记录 RTF 与首字延迟，写入配置供队列并发使用。社区数据 1.7B 在消费级 GPU 上 RTF 约 0.3–0.8，CPU 上会明显更慢。

### 4.2 接口契约

适配器不绑定某一种服务实现，按「能力 + 可覆盖路径」设计。

| 能力 | 默认方法与路径 | 请求 | 响应 |
| --- | --- | --- | --- |
| 合成（预设/已注册音色） | `POST {base}/v1/audio/speech` | JSON：`model` `input` `voice` `response_format` `speed` `language` `instruct?` | 音频二进制，或 JSON `{audio, format, duration}` |
| 克隆合成（即时上传参考音频） | `POST {base}/v1/audio/speech/upload` | multipart：`input` `voice_file` `ref_text?` `language` `x_vector_only` | 音频二进制 |
| 音色设计 | `POST {base}/v1/audio/speech/design` | JSON：`input` `voice_description` `language` `model` | 音频二进制 |
| 音色列表 | `GET {base}/v1/voices` | — | `[{id,name,type}]`，克隆音色常带 `clone:` 前缀 |
| 健康检查 | `GET {base}/health` | — | `{status, models, sample_rate}` |

请求示例（设计）：

```json
{
  "model": "Qwen3-TTS-12Hz-1.7B-VoiceDesign",
  "input": "总有一天做得出来。到时候抱着它，给古人吼一首《多么痛的领悟》——",
  "voice_description": "A 15-year-old Chinese boy, bright slightly thin timbre, higher pitch, fast casual speech, faint streetwise swagger",
  "language": "Chinese",
  "response_format": "wav",
  "speed": 1.05
}
```

响应兼容三种形态，按 `Content-Type` 与魔数判定：

1. `audio/wav` / `audio/mpeg` 二进制（RIFF / ID3 开头）；
2. JSON `{ "audio": "<base64>", "format": "wav", "duration": 8.2 }`；
3. 厂商包装 JSON `{ "data": { "audio": "<hex>", ... } }`（兼容 MiniMax 式响应）。

> `voice_description` 只用于 design 端点；已注册/克隆音色走 `voice` 字段，二者不要同时依赖。

### 4.3 配置与能力探测

新增服务类型 `audio`，复用 `ai_service_configs`：

```json
{
  "service_type": "audio",
  "provider": "qwen3-tts",
  "name": "本地 Qwen3-TTS",
  "base_url": "http://192.168.1.20:8000",
  "api_key": "optional-bearer",
  "model": "[\"Qwen3-TTS-12Hz-1.7B-VoiceDesign\"]",
  "settings": {
    "speechPath": "/v1/audio/speech",
    "clonePath": "/v1/audio/speech/upload",
    "designPath": "/v1/audio/speech/design",
    "voicesPath": "/v1/voices",
    "healthPath": "/health",
    "language": "Chinese",
    "sampleRate": 24000,
    "timeoutMs": 120000,
    "concurrency": 1,
    "capabilities": { "speech": true, "clone": true, "design": true, "voices": true }
  }
}
```

> 落地注意：`services/ai.ts` 的 `ServiceType` 是联合类型、`officialProviders` 是固定 Record，`isOfficialProvider()` 对未知 `service_type` 一律返回 false。必须先把 `audio` 加进这两处，否则设置页保存语音配置会被 `400 不支持的 service_type/provider` 拒绝；路由层的新增/编辑/探测三处校验都要同步。

前端同样写死了三种类型：`pages/settings.vue` 的 `serviceTypes` 数组、`serviceMeta` 映射、`presetsByType()` 预设列表、`cfgForm.service_type` 默认值。只改后端会导致打开「新增配置」弹窗时 `serviceMeta[cfgForm.service_type]` 取不到 label 而报错。需补 `{ type: 'audio', label, desc }` 与一条 `qwen3-tts` 预设（provider=`qwen3-tts`、默认 baseUrl、预设模型数组）。

「探测能力」按钮执行：

1. `GET /health` → 服务可达、模型列表、采样率；
2. `GET /v1/voices` → 是否有 `clone:` 音色、是否有预设音色；
3. 用一小段文本合成一次（`input: "试音，一二三四五。"`，8 个字）→ 验证 `speech`；
4. `design` / `clone` 端点各发一次空请求，返回 4xx（而非 404）即视为存在。

探测结果写入 `settings.capabilities`，前端按能力隐藏不可用入口。探测失败不阻塞其他功能，只把语音相关按钮置灰并提示原因。

### 4.4 失败与降级

| 场景 | 行为 | 用户可见 |
| --- | --- | --- |
| 未配置语音服务 | `voices` 阶段仍生成文字声音提示词（不合成样音、不激活）；跳过 `dub`；连文本模型也未配置时才整段跳过 | 阶段显示「仅生成提示词」；音色卡片「服务未就绪」 |
| 服务不可达 / 超时 | 重试 2 次（1s/3s 退避）；仍失败则 `status=pending_model` | 音色卡片「服务未就绪，稍后重试」；不阻塞生图与分镜 |
| 单句合成失败 | 该句 `status=failed`，保留文本；整批继续 | 台词列表红色标记，可单句重试 |
| 克隆音色不合法 | 校验时长/格式/采样率，拒绝并给出可操作提示 | 「参考音频需 3–20 秒、MP3/WAV、无背景音乐」 |
| 响应格式异常 | 记录前 512 字节响应体到任务日志，标记 `protocol_error` | 「语音服务返回格式不兼容，请检查部署版本」 |

**任何情况下，配音失败不回滚已生成的视频与合片。** 自动化仍按 `done` 结束，只把 `dub_status='failed'` 与原因写入 `dub_note`，避免整集因配音失败被打回重跑视频。

### 4.5 部署对接清单（交付给语音服务器）

后端只依赖以下 5 个 HTTP 能力；服务端实现可自选，路径与字段名可在配置里覆盖。

| # | 能力 | 必须 | 约定 |
| --- | --- | --- | --- |
| 1 | `GET /health` | 是 | 返回 200 + JSON；建议含 `models`、`sample_rate`、`device` |
| 2 | `POST /v1/audio/speech` | 是 | JSON 入参，返回音频二进制（`audio/wav` 或 `audio/mpeg`）优先；也兼容 4.2 的 JSON/base64 |
| 3 | `POST /v1/audio/speech/design` | 是（主路径） | `voice_description` 传英文指令；中文 `input` |
| 4 | `POST /v1/audio/speech/upload` | 可选 | multipart，参考音频字段默认 `voice_file`，可配 `cloneFileField` |
| 5 | `GET /v1/voices` | 可选 | 返回数组；克隆音色建议 `clone:<name>` 命名 |

服务端约束：

- 输出 24 kHz、单声道；若为 48 kHz，后端会重采样，不报错但增加耗时；
- 单次请求文本 ≤200 字（后端按 ≤28 字切块，留足余量）；
- 克隆参考音频 3–20 秒、无背景音乐、MP3/WAV/M4A；
- 支持并发 ≥1；若显存不足请返回 `503` + `Retry-After`，后端会退避；
- 鉴权用 `Authorization: Bearer <token>`，token 可留空（内网）；
- 不要开启 Gradio 公网访问；用反向代理 + 内网 ACL。

冒烟测试（部署完成后逐条执行）：

```bash

# 2. 预设/设计音色合成
```

## 5. 音色资产

### 5.1 数据模型

```sql
CREATE TABLE IF NOT EXISTS character_voices (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  drama_id INTEGER NOT NULL,
  character_id INTEGER,                 -- 旁白为 NULL
  scope TEXT NOT NULL DEFAULT 'character', -- character | narrator
  name TEXT NOT NULL,                   -- 展示名，如「唐大郎·少年音」
  source TEXT NOT NULL DEFAULT 'design',-- design | clone | preset | upload
  provider TEXT,                        -- qwen3-tts
  model TEXT,                           -- Qwen3-TTS-12Hz-1.7B-VoiceDesign
  external_voice_id TEXT,               -- design:xxx / clone:xxx / 预设 id
  voice_prompt TEXT,                    -- 中文声音提示词（人看 + 二次生成）
  voice_prompt_source TEXT DEFAULT 'llm', -- llm | template | manual
  design_instruct TEXT,                 -- 给 VoiceDesign 的指令（英文，稳定）
  ref_audio_url TEXT,                   -- 克隆参考音频
  ref_text TEXT,                        -- 参考音频精确转写
  x_vector_only INTEGER DEFAULT 0,
  sample_url TEXT,                      -- 试听样音（也用作视频音色参考）
  sample_text TEXT,
  gender TEXT, age_range TEXT, pitch TEXT,
  speed REAL DEFAULT 1.0,
  emotion TEXT,                         -- 情绪基线
  language TEXT DEFAULT 'Chinese',
  seed INTEGER,
  consent_confirmed_at TEXT,            -- 声音克隆授权确认时间
  status TEXT DEFAULT 'draft',          -- draft | ready | pending_model | failed
  error TEXT,
  is_active INTEGER DEFAULT 0,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  deleted_at TEXT
);
CREATE INDEX IF NOT EXISTS idx_character_voices_char ON character_voices (character_id);
CREATE INDEX IF NOT EXISTS idx_character_voices_drama ON character_voices (drama_id, scope);
```

约定：

- 同一 `character_id` 同时只有一条 `is_active=1`；切换在事务内完成。
- 旁白音色 `scope='narrator'`、`character_id=NULL`，每个项目一条激活记录。
- `characters.voice_audio_url` 保留，作为**视频模型参考音频**的兼容字段，由激活音色的 `sample_url` 同步（详见 5.5）。
- `characters.voice_prompt / voice_status` 只是激活音色的**只读缓存**，仅在 `activate` 事务内写入，供角色列表直接展示；任何以 `character_voices` 为准的读取都不用这两个字段。
- 删除角色时软删其音色；音频文件不删，避免其他集引用断链。

### 5.2 四种来源与状态机

| 来源 | 输入 | 产出 | 适用 |
| --- | --- | --- | --- |
| `design` | 角色设定（外貌/性格/年龄/身份）+ 项目背景 | `voice_prompt` + `design_instruct` + 试听样音 | 默认，新角色零素材 |
| `clone` | 用户上传 3–20 秒参考音频（+ 可选转写） | 克隆音色 + 试听样音 | 有明确音色要求、真人授权 |
| `preset` | 服务端 `/v1/voices` 预设 | 绑定 `external_voice_id` | 配角、群杂、快速草稿 |
| `upload` | 已有成品音频（V1 的 `characters.voice_audio_url`） | 仅登记 `sample_url`，无提示词 | 历史数据迁移，只读兼容；不参与新生成 |

状态机：

```
draft ──生成提示词──> draft ──合成样音成功──> ready
  │                     │
  │                     └──服务不可达──> pending_model ──重试成功──> ready
  └──合成失败──────────────────────────> failed ──重试──> ready
```

- `draft`：有 `voice_prompt`，无可用样音。可用于 TTS（若服务端支持 design 即时合成），但列表标记「未试听」。
- `ready`：有 `sample_url` 且能播放，允许被台词引用。
- `pending_model` / `failed`：不可被自动配音选中，手动仍可指定并触发即时合成。

### 5.3 声音提示词生成

#### 5.3.1 触发时机

| 时机 | 行为 |
| --- | --- |
| 自动化 `voices` 阶段 | 对本集所有**无激活音色**的角色 + 旁白批量生成，一次 LLM 调用 |
| 角色详情点「生成声音设定」 | 单角色生成/重生成 |
| 手动新建角色并勾选「同时生成音色」 | 创建后异步生成 |
| 用户上传参考音频 | 不生成 design，改为生成 `voice_prompt` 描述（便于跨模型复现） |

批量优先：一集 5–10 个角色，逐角色调用既慢又容易风格漂移；一次调用返回数组，统一风格与命名。

#### 5.3.2 Agent 与工具

新增 Agent `voice_designer`：

- System prompt：`workspace/prompts/voice_designer.md`（中/英/日/韩四份）
- Skill：`workspace/skills/voice-designer/SKILL.md`
- 工具：
  - `read_characters_for_voice`：返回本集角色（`name/role/description/appearance/personality/age` 推断）、项目背景、题材、内容语言、`narrator_missing`（项目是否还没有激活旁白音色），以及**每个角色在 `script_content` 里的前 1–2 句台词**（按 `名字[:：]` / `@名字` 提取，单句截到 40 字），供 `sample_text` 使用；剧本缺失时该字段为空数组；
  - `save_voice_profiles`：批量 upsert `character_voices`，按 `(scope, character_id)` 匹配（旁白 `scope='narrator'`、`character_id=NULL`），已有激活音色默认跳过（`force` 才覆盖）；同一事务内只保留一条 `is_active=1`。

#### 5.3.3 输出结构

```json
{
  "profiles": [
    {
      "scope": "character",
      "character_name": "唐大郎",
      "gender": "male",
      "age_range": "14-16",
      "voice_prompt": "少年音，清亮偏薄，音区略高，语速偏快，句尾习惯性上扬，带一点市井痞气与不服输的劲头",
      "design_instruct": "A 15-year-old Chinese boy, bright slightly thin timbre, higher pitch, fast casual speech, faint streetwise swagger, confident and playful",
      "sample_text": "总有一天做得出来。到时候抱着它，给古人吼一首《多么痛的领悟》——",
      "emotion": "自信、调侃",
      "speed": 1.05
    },
    {
      "scope": "narrator",
      "character_name": null,
      "gender": "male",
      "age_range": "30-40",
      "voice_prompt": "叙述音，中低音区，音色干净偏暖，语速平稳，情绪克制，句尾下沉，适合第三人称旁白",
      "design_instruct": "A calm Chinese male narrator, warm clean mid-low timbre, steady pace, restrained emotion, downward sentence endings",
      "sample_text": "至于这吉他，纯粹是把我憋得没法儿的产物。",
      "emotion": "克制、平稳",
      "speed": 1.0
    }
  ]
}
```

规则（写入 SKILL，硬约束）：

- `voice_prompt` 40–80 个汉字，必须覆盖：年龄、性别、音色质感、音区、语速、气质/口音；
- 不出现真人姓名、明星、作品名，不写「像 XXX」；
- 与角色身份一致：14 岁少年不能写成低沉中年音；旁白单独一条（`scope='narrator'`、`character_name=null`），全项目仅一条，风格统一、克制、少情绪；
- `design_instruct` 用英文，顺序固定：年龄性别 → 音色 → 音区 → 语速 → 气质 → 情绪基线；
- 不输出 `name`：后端用「{角色名}·{年龄或音色关键词}」生成（如「唐大郎·少年音」），旁白固定「旁白·叙述音」，避免 LLM 起名不一致；
- `sample_text` 优先取 `read_characters_for_voice` 返回的该角色 `first_lines[0]`；没有则用 `你好，我是{name}。`；
- 同一项目内角色音色需**可区分**：若两个角色提示词高度相似，后一个必须调整音区或语速并说明差异；
- 输出必须是 JSON，不写解释。

#### 5.3.4 失败处理

- LLM 返回非 JSON：重试 1 次；仍失败则用模板兜底（从 `appearance`/`role` 拼「性别+年龄+音色+语速」），标记 `voice_prompt_source=template`；旁白兜底不走角色模板，固定用「叙述音，中低音区，语速平稳，情绪克制」。
- 角色信息不足（无外貌、无性格）：仍生成，但 `voice_prompt` 标注「待细化」，UI 提示补充设定。

### 5.4 试听、换音色、克隆

| 操作 | 接口 | 行为 |
| --- | --- | --- |
| 生成/重生成提示词 | `POST /characters/:id/voice-profile` | LLM 生成，写 `voice_prompt/design_instruct`，状态 `draft` |
| 保存编辑 | `PUT /characters/:id/voice-profile` | 用户可改提示词、语速、情绪、样音文本 |
| 生成试听 | `POST /characters/:id/voice-sample` | design 合成 → 落盘 → `sample_url`，状态 `ready` |
| 换一个 | 同上，body `{ "seed": 12345, "variant": 2 }` | 同提示词不同 seed，保留历史版本可回滚 |
| 上传克隆 | `POST /characters/:id/voice-clone`（multipart） | 校验 → 可选转写 → 克隆合成试听 → `source=clone` |
| 选预设 | `PUT /characters/:id/voice-profile` `{ source: "preset", external_voice_id }` | 合成试听 |
| 设为激活 | `POST /characters/:id/voice-profile/activate` | 事务切换 `is_active`，同步 `characters.voice_audio_url` |

台词合成时的音色解析顺序（必须固定，否则换音色后新旧混杂）：

1. `storyboard_lines.voice_id` 且 `voice_locked=1`（人工指定，优先）；
2. 角色的 `is_active=1` 且 `status=ready` 的音色；
3. 项目旁白音色（角色无可用音色时降级，UI 提示「使用旁白音色代替」）。

合成完成后把实际使用的音色回写 `voice_id`（`voice_locked` 保持 0），只作记录与排查，不参与下一次解析。激活新音色**不自动改写**已有行的 `voice_locked`；用户点「全部重合成」时按当前激活音色重算，仅跳过 `voice_locked=1` 的行。单句试听走同一解析顺序，保证试听与成片一致。

试听文本策略：

- 默认用角色第一句台词：`voices` 阶段早于 `storyboards`，此时从 `script_content` 按角色名/`@角色名` 匹配第一句；已拆分镜后重新生成时，改用 `storyboard_lines` 里该角色的第一句（最长 40 字）；
- 两处都找不到时用固定句：`我是{name}。{一句符合人设的短句}`；
- 试听时长控制在 6–12 秒，超长截断到句末标点；
- 样音统一转 24 kHz 单声道 WAV（6–12 秒约 0.3–0.6 MB，前端可直接播放；不再单独存 MP3，避免两份文件不同步）；

克隆的 `ref_text`：

- 优先让用户填（准确度最高）；
- 未填时默认 `x_vector_only=true`，并在 UI 标注「未填转写，相似度略低」；
- P1 可选接入 ASR 服务自动转写（新增 `service_type=asr`，非本期必做）。

### 5.5 与视频模型音色参考的关系

现有两条链路必须区分清楚：

| 链路 | 消费者 | 现状 | V2 处理 |
| --- | --- | --- | --- |
| A. 视频模型参考音频 | Seedance 2.0 / MiniMax H3 / Wan | `characters.voice_audio_url` + `#角色名` 语法；本地 H3 实测基本不生效 | **保留不动**。激活音色的 `sample_url` 可一键同步到 `voice_audio_url`，按 2–15 秒/段、合计 ≤15 秒裁剪（见下） |
| B. 本地 TTS 配音 | Qwen3-TTS | V2 新增 | 使用 `character_voices.external_voice_id` / `design_instruct` / `ref_audio_url`，与链路 A 解耦 |

产品文案必须说清楚：

> 视频音色参考用于「让视频模型模仿音色」，本地方案支持有限；配音音色用于「后期生成台词与旁白」，两者可分别设置。

开关：音色面板底部「同时用作视频音色参考」默认开启（`clone`/`upload` 来源），`design` 来源默认关闭（合成音与画面人物未必匹配，避免误导）。

云端模型若需要音色参考，仍要在 `video_prompt` 里写 `#角色名`（V1 语法）。V2 提供配置 `voice.referenceInVideoPrompt`（默认 0）：开启后，仅在 `video_audio_mode=native` 且视频模型支持参考音频时，自动在提示词第二行后追加一次 `#角色名`，不重复追加已存在的引用。

多角色同镜的硬限制：`prepareReferenceAudio()` 要求**每段 2–15 秒且合计 ≤15 秒**，不是每段都能给 15 秒。同步到视频参考时按镜头内引用人数 N 均分：每段裁到 `floor(15 / N)` 秒（N≥2 时 ≤7 秒），不足 2 秒则只保留主角/旁白，其余角色走配音轨。音色面板默认生成 6–12 秒样音，直接全量同步会在双人镜头触发「总时长超过 15 秒」而让视频任务失败。

## 6. 台词、字幕与混音

### 6.1 从 `video_prompt` 抽取台词

#### 6.1.1 现有结构（真实样例）

```
0-3秒：@唐记食铺柜台 近景，@唐大郎 低头刻着忽然低声自语，忍不住笑出声，眼角弯起：「总有一天做得出来。到时候抱着它，给古人吼一首《多么痛的领悟》——」
3-6秒：切特写，他手里的吉他琴头木条刀痕渐深，半成品轮廓隐约成形，木屑在暖黄晨光中飞舞。
6-9秒：切近景，@唐大郎 继续笑说：「让他们也知道知道，老子在千年之后过得好好的，却被扔到了北宋，这是多么痛的领悟啊！」
9-14秒：门外传来 @马老三 的吆喝声，@唐大郎 抬头应了一声，笑意落回眼底，镜头拉远成全景。
```

旁白写法有两种，**真实数据里绝大多数是第一种（不带引号）**：

- 裸旁白：`旁白：至于这吉他，纯粹是把我憋得没法儿的产物。`（第 5 集真实数据，`video_prompt` 里紧跟在画面描述之后，没有引号）
- 带引号：`旁白（画外音）：……` 或 `旁白说：「……」`
- 角色台词：`@唐大郎 继续笑说：「……」` / `唐大郎说：「……」`

#### 6.1.2 解析算法（确定性优先）

1. **切段**：`/^(\d+)\s*[-–]\s*(\d+)\s*秒[：:]\s*/gm`，得到 `planned_start_ms/planned_end_ms`（**镜头内相对毫秒**）与段落文本；无时间码则整段作为一段，按字数均分。
2. **抽带引号台词**：在段内匹配引号 `「...」`、`“...”`、`"..."`、`『...』`；支持引号内再套引号（`「他说：『走。』」` 取最外层）。
3. **抽裸旁白**（必须有，否则第 5 集这类素材会漏掉全部旁白）：在段内匹配 `(旁白|画外音|心声|内心独白)\s*(（[^）]*）)?\s*[：:]`，从冒号后取到段落结尾或下一个 `@角色`/时间码之前；按 `。！？` 切成多句，逐句成为 `narration`/`inner` 行。裸旁白与带引号台词重叠时，以带引号台词为准，裸旁白只取未覆盖区间。单段裸旁白超过 80 字时仍保留，但标 `needs_review=1`（可能把后面的画面描述一起吞进来），提示人工确认。
4. **定说话人**（按优先级）：
   - 引号前 12 个字符内出现 `旁白` / `画外音` / `心声` / `内心` → `narration` / `inner`；
   - 引号前出现 `@名字` 或 `名字说/道/问/喊/答/嘟囔/自语` → 该角色（需在本镜 `storyboard_characters` 内）；
   - 段内只有一个 `@角色` 且本镜只绑定一个角色 → 该角色；
   - 仍无法判断 → `speaker_type='dialogue'`、`character_id=NULL`、`speaker_name='未知'`，标记 `needs_review=1`。
5. **清洗**：去掉引号、舞台提示 `（...）`、`【镜头N】`、`@` 前缀；`——` → `，`；连续省略号归一为 `…`；保留句末标点（影响 TTS 停顿）。
6. **入参文本**：`speak_text`（给 TTS，做数字与符号规范化）、`subtitle_text`（给字幕，可更短）。

落库到 `storyboard_lines`，`source='auto'`。

#### 6.1.3 LLM 兜底

只在以下情况调用 `dialogue_extractor`（低成本、低频率）：

- 正则抽到 0 句，但段落含引号或「说/道/问」；
- 抽到的句子中 `speaker_name='未知'` 占比 >30%；
- 用户点「重新识别台词」。

LLM 输出结构与正则一致，逐条带 `reason`。兜底结果覆盖同镜的 `source='auto'` 行，但**不覆盖 `locked=1` 的行**。

#### 6.1.4 幂等与人工编辑

- `storyboard_lines.source_hash = sha256(video_prompt)`；重跑时 hash 未变则跳过。
- 重跑前在同一事务内删除该镜 `source IN ('auto','llm')` 且 `locked=0` 的行，再插入新行；否则 `UNIQUE(storyboard_id, line_no)` 会冲突。
- `locked=1` 的行在 `video_prompt` 变化时只标 `stale=1`，不删除、不自动改写；UI 提示「原文已变，建议复核」。
- 删除分镜时级联**硬删**其台词（音频文件不删，按 6.3.2 的 30 天未引用策略回收），避免软删行与 `UNIQUE(storyboard_id, line_no)` 冲突。
- 手动新增台词追加到 `max(line_no)+1`，允许 `start_ms` 为空，由时间轴阶段按顺序排。

### 6.2 语音预算与超长处理

V1 提示词已约束「时长 × 4 字/秒」「每 3 秒段 ≤12 字」，但历史数据仍有超标（第 5 集旁白 5 秒 60+ 字）。V2 不依赖提示词自觉，做四层兜底：

| 层级 | 处理 | 上限 |
| --- | --- | --- |
| L1 拆句 | 按 `。！？；，` 拆成 ≤28 字的语义块，逐块合成 | 不改变镜头 |
| L2 变速 | 合成后超长，`atempo` 加速 | ≤1.12 倍（再高会失真） |
| L3 跨镜 | 允许音频越过本镜结尾，延续到下一镜；`overflow_ms` 记录超出量 | 不设硬上限，但不得与下一句重叠（冲突时顺延下一句） |
| L4 片尾 | 整集最后一句仍超出片尾，裁到片尾并 200ms 淡出 | 仅片尾执行，不静默丢句 |

`overflow` 是标记位（`overflow_ms > 0`），不是独立状态；与「原文已变」（`stale=1`）可同时存在。UI 在台词列表用橙色标记，并显示「超出 2.3 秒」。

### 6.3 TTS 合成

#### 6.3.1 服务入口

```ts
// services/tts.ts
export interface SynthParams {
  text: string
  voice: VoiceRef            // { externalVoiceId, designInstruct, refAudioUrl, refText, xVectorOnly }
  speed?: number
  emotion?: string
  language?: string
  seed?: number
  configId?: number
}
export interface SynthResult {
  url: string                // static/tts/<hash>.wav
  durationMs: number
  format: 'wav' | 'mp3'
  hash: string               // 内容寻址
  cached: boolean
}
```

时长来源：JSON 响应带 `duration` 时直接用；二进制响应（WAV/MP3）必须用 `ffprobe` 读 `format.duration`，不能按字数估算——时间轴、字幕、ducking 都依赖真实时长，估算误差会逐句累积。

#### 6.3.2 内容寻址缓存

`hash = sha256([text, externalVoiceId, designInstruct, speed, emotion, seed, model].join('\u0001'))`

- 文件路径 `static/tts/<前2位>/<hash>.wav`；响应是 MP3/其他格式时先 `ffmpeg` 转 24 kHz 单声道 WAV 再落盘，保证缓存文件后缀与内容一致；
- 命中直接返回，不请求服务；
- 台词改一个字即新 hash，旧文件保留（可被其他集复用），由项目清理任务按 30 天未引用回收；
- 同一 hash 并发请求用 in-flight Map 去重，避免重复计费/占显存。

#### 6.3.3 文本规范化

合成前处理（只影响 `speak_text`，不改字幕原文）：

| 规则 | 示例 |
| --- | --- |
| 去 Markdown/HTML 残留 | `**重要**` → `重要` |
| 去说话人前缀 | `唐大郎说：` → 删除 |
| 数字读法 | 年份逐位（`2026` → 二零二六）；数量按量词（`3 个` → 三个） |
| 符号 | `——` → `，`；`…` 保留；`&` → 和 |
| 英文缩写 | `AI` → `A I`；`OK` → `OK`（保留字母音） |
| 长度 | 单次 ≤28 字（与 6.2 的 L1 一致），超长按标点切块；服务端上限 200 字 |

#### 6.3.4 并发、重试、超时

- 全局信号量 `tts.concurrency`，默认 1（本地单卡），可配 2–4；
- 单句超时 120 秒；连接失败重试 2 次（1s/3s）；
- 服务返回 503（队列满）时退避 5 秒重试，仍失败则该句 `failed`，批次继续；
- 批次进度按「已完成句数 / 总句数」写 `storyboard_lines` 与 `episodes.automation_*`。

### 6.4 时间轴

#### 6.4.1 为什么在成片后做

镜头视频时长由模型决定，`video_prompt` 里的 3 秒分段只是创作意图，不是最终时长。因此：

- **先合片**（现有 `mergeEpisodeVideos`），拿到每段真实时长；
- **再建绝对时间轴**，把所有台词放到整集连续轴上；
- **最后混音 + 字幕**。

好处：台词可自然跨镜、改一句只重混音、字幕时间准确、不需要逐镜二次编码。

#### 6.4.2 计算规则

```
shotStart[i]  = Σ duration(clip[j]) , j < i        // 合片后逐段 ffprobe
shotEnd[i]    = shotStart[i] + duration(clip[i])

relStart      = max(250ms, plannedStartInShot, cursor - shotStart[shot])
line.start    = shotStart[shot] + relStart
line.end      = line.start + audioDuration
cursor        = line.end + gap(0.18s)              // 初始 cursor = 0
```

> `planned_start_ms` 是**镜头内相对时间**（来自 `video_prompt` 的 `0-3秒：`），不能直接与整集绝对 `cursor` 比较，必须先加 `shotStart[shot]`。这是时间轴实现最容易写错的一处。

约束：

- 首句不早于镜头开始 +0.25 秒（留呼吸）；
- 同镜内按 `line_no` 顺序，不允许重叠；检测到重叠（抢话）时，后者顺延，并标 `overlap=1`；
- `line.end > shotEnd + 1500ms` → 先 `atempo`（≤1.12）；仍超则记 `overflow_ms = line.end - shotEnd`，不再截断；
- `overflow` 的音频**不截断**，允许延续到下一镜（混音是整集连续轨）；若与下一句重叠，则顺延下一句，不顺延者不得覆盖前一句尾音；
- 字幕结束时间夹到「下一句开始前 100ms」或「本句音频结束」，取较早者；
- 仅当整集最后一句超出片尾时，裁到片尾并 200ms 淡出（L4）。

时间轴产物：

```ts
interface TimelineCue {
  lineId: number
  shotId: number
  startMs: number
  endMs: number
  text: string
  speaker: string
  kind: 'dialogue' | 'narration' | 'inner'
}
```

### 6.5 字幕

#### 6.5.1 断句与排版

- 每条 cue 最多 2 行，每行 ≤14 个汉字（9:16）或 ≤20 个（16:9）；
- 超长按标点二次切分，切成多条连续 cue，时间按字数比例分配；
- 单条最短 0.8 秒，最长 6 秒；过短合并相邻同说话人 cue（间隔 <0.25 秒）；
- 旁白/心声加书名号式标记：`（旁白）` 前缀可配，默认关闭，靠样式区分（斜体 + 略小字号）。

#### 6.5.2 格式

| 格式 | 用途 | 产出 |
| --- | --- | --- |
| SRT | 软字幕、外挂、平台上传 | `static/subtitles/<episode>-<hash>.srt` |
| ASS | 烧录、样式控制 | `static/subtitles/<episode>-<hash>.ass` |

ASS 样式（按项目比例）：

| 参数 | 9:16 (1080×1920) | 16:9 (1920×1080) |
| --- | --- | --- |
| 字体 | 思源黑体 / 苹方 | 同 |
| 字号 | 54 | 46 |
| 描边 | 3 | 3 |
| 阴影 | 1 | 1 |
| 底边距 | 260 | 90 |
| 对齐 | 底部居中 | 底部居中 |
| 主色 | 白 | 白 |
| 描边色 | 黑 80% | 黑 80% |

#### 6.5.3 字幕模式

`subtitle_mode`：

- `soft`（默认）：混流为 `mov_text`，播放器可开关；
- `burn`：`-vf ass=...` 重编码视频（`libx264 -crf 20`），用于交付；
- `none`：不生成。

烧录必须与混音在同一次导出完成，避免二次编码叠加。

### 6.6 混音

#### 6.6.1 输入

| 轨 | 来源 | 处理 |
| --- | --- | --- |
| 原声底 | 合片视频音轨（H3 环境声/原生对白） | 按 `original_audio` 策略衰减；作为 sidechain 主轨 |
| 配音轨 | 逐句 TTS 拼装 | 主体，−16 LUFS 基准 |
| BGM | 本地曲库（可选） | 循环、`0.18`（约 −15 dBFS）起、片尾 2 秒淡出、被配音 duck |

#### 6.6.2 对话轨拼装

1. 所有 TTS（源为 24 kHz）统一重采样为 48 kHz 单声道 s16，混音前再 `aformat=channel_layouts=stereo`；
2. 生成整集静音底 `anullsrc=r=48000:cl=mono -t <totalDur>`；
3. 每句 `adelay=<start>|<start>`，`amix=inputs=N+1:normalize=0`；
4. N > 60 时分块（每 20 句一块），块间再 amix，避免滤镜图过大；
5. 输出 `dialogue.wav`（临时），混音后删除。

> 原声底来自合片视频，通常是 48 kHz 立体声 AAC；配音轨是单声道。进入 `sidechaincompress` 前，两条轨都要过 `aformat=sample_fmts=fltp:sample_rates=48000:channel_layouts=stereo`，否则会因通道布局不一致报 `Media type mismatch`。BGM 同理。

#### 6.6.3 Ducking 参数

```text
[bed] volume=0.85 [bedv]
[vo]  asplit=2 [vo_mix][vo_key]
[bedv][vo_key] sidechaincompress=
      threshold=0.05:ratio=6:attack=15:release=320:makeup=1 [ducked]
[ducked][vo_mix] amix=inputs=2:duration=first:weights=1 1.35:normalize=0 [mix]
[mix] alimiter=limit=0.95, loudnorm=I=-16:TP=-2:LRA=9 [out]
```

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `threshold` | 0.05 | 配音超过该电平即触发压缩 |
| `ratio` | 6 | 原声被压低约 6–9 dB |
| `attack` / `release` | 15 / 320 ms | 不切断环境声起音，收得自然 |
| `original_audio` | `duck` | `keep` 不压；`duck` 压 6–9 dB；`mute` 直接静音 |
| 目标响度 | −16 LUFS | 短视频平台常见 −14 ~ −16，留 0.5 余量 |
| 真峰值 | −2 dBTP | AAC 编码余量 |

若 `original_audio=mute`，仍保留一条极低电平环境声（−30 dB）避免「真空感」，可在设置关闭。

> `loudnorm` 在滤镜图里是单遍动态模式，够用且快；若交付平台对响度卡得很死，导出后再跑一次 `loudnorm` 二遍（`print_format=json` 取 measured 值）做线性归一。二遍只在「导出成片」时执行，预览不跑。

#### 6.6.4 BGM

- 目录 `data/static/bgm/`，支持 mp3/wav/m4a；
- 选择方式：项目级默认、单集覆盖、按 `bgm_prompt` 关键词匹配（P2）；
- 循环 `-stream_loop -1`，总长对齐视频，片尾 2 秒 `afade=t=out`；
- BGM 自身再被配音 duck 3 dB（`sidechaincompress` 第二级），避免压过对白。

#### 6.6.5 输出与版本

新增 `video_merges.kind`：

| kind | 含义 |
| --- | --- |
| `concat` | V1 纯拼接（现有） |
| `mix` | 拼接 + 配音 + 字幕 + BGM |
| `motion` | 图文动画 |

同一集可保留多个版本；`episodes.video_url` 指向最新完成版本，旧版本在导出页可下载/回滚。

`kind` 新增列默认 `concat`；历史行不回填也按 `concat` 解释（查询用 `COALESCE(kind,'concat')`），避免升级后旧合片在导出页消失。

### 6.7 原声策略：让视频「留白」

本地 H3 默认会生成清晰人声（shim 现在注入 `clear intelligible Mandarin dialogue`）。如果后期再叠 TTS，会出现双人声。

V2 增加项目/剧集级选项 `video_audio_mode`：

| 值 | shim 注入 | 适用 |
| --- | --- | --- |
| `native`（`auto` 且不配音时的实际值） | `clear intelligible Mandarin dialogue and voice-over, natural ambience, no background music` | 不配音，直接用 H3 原声 |
| `ambient` | `ambient sound and Foley only, no intelligible dialogue, no voice-over, no music` | 要后期配音；画面人物可张口但不发清晰语义声 |
| `silent` | `no dialogue, no voice-over, minimal ambience` | 完全后期声 |

负面词同步增加：`intelligible speech, clear dialogue, voice-over, narration`。

自动化在 `videos` 阶段读取：`auto_dub=1` 且语音服务可用 → `ambient`；否则 `native`。**同一集内不允许混用**，避免有的镜头有人声、有的没有。

`episodes.video_audio_mode` 存的是用户选择，默认 `auto`；`native/ambient/silent` 是 `auto` 解析后的实际值，写入任务 payload 与日志。手工指定非 `auto` 时不再按 `auto_dub` 推导。

> 提示词层同步约束：`ambient` 模式下，分镜提示词第二行的声音要求改为「音频：仅环境声与动作音效，无清晰人声，无旁白，无音乐」。

## 7. 自动化流水线 V2

### 7.1 阶段与权重

| # | stage | 名称 | 产出 | 权重 |
| --- | --- | --- | --- | --- |
| 1 | `rewrite` | AI 改写 | `episodes.script_content` | 8 |
| 2 | `extract` | 资产提取 | 角色/场景/道具 + 关联 | 10 |
| 3 | `voices` | 声音设定 | 声音提示词 + 试听样音 + 激活音色 | 8 |
| 4 | `asset_images` | 资产生图 | 三类资产 `image_url` | 22 |
| 5 | `storyboards` | 分镜拆分 | `storyboards` + `video_prompt` | 12 |
| 6 | `video_prompts` | 视频提示词补齐 | 只补缺 | 7 |
| 7 | `videos` | 视频生成 | 逐镜 `video_url` | 25 |
| 8 | `dub` | 配音成片 | 台词 + TTS + 字幕 + 混音 | 8 |

`done` 时 100%。

`voices` 排在生图之前：声音提示词只依赖角色设定与剧本，不依赖图片；先出音色可以让用户在等图时就能试听，且语音服务故障不会阻塞生图。样音合成失败只标记 `pending_model`，自动化继续跑生图。

`dub` 阶段开始前必须先有合片：查 `video_merges` 是否已有与当前分镜集合一致的 `kind=concat` 版本（`source_hash` 相同）；没有或不一致则先调用现有 `mergeEpisodeVideos` 自动合一次，拿到逐段真实时长后再建时间轴。否则用户必须先手动合片才能配音，自动化会卡在「无时间轴」。

若 `videos` 阶段仍有失败镜，`dub` 不拿残缺合片硬配：跳过本阶段，`dub_status='idle'`、`dub_note='等待补镜'`，自动化仍按 `done` 结束并在卡片提示「配音已跳过：N 镜缺少视频」；补镜后单独重跑配音即可。

V3 会给 `episodes` 加 `source_stale`（原著已更新）。它只是**警告标记，不自动触发重跑**：用户点「按新原文重做」时调用 `POST /episodes/:id/rework`（清 `script_content`、软删本集分镜，旧合片与视频文件保留），再启动自动化；新分镜生成成功后清 `source_stale=0`。自动跑流水线不会动已有分镜，避免「同步一次就静默毁掉已生成的画面」。该列不存在时忽略，不影响 V2 独立运行。

### 7.2 幂等规则

| 阶段 | 跳过条件 |
| --- | --- |
| rewrite | `script_content` 非空 |
| extract | 该类型资产已关联到本集 |
| voices | 角色已有非空 `voice_prompt` 且 `source != 'upload'` 的档案；若语音服务可用但尚无 `status=ready` 样音，只补样音、不重生成提示词，成功后在该角色无激活音色时自动激活；旁白同理 |
| asset_images | 资产已有 `image_url` |
| storyboards | 本集已有未删除分镜 |
| video_prompts | 无缺失（批量服务返回 `total=0`） |
| videos | 分镜已有 `video_url`；失败任务先 `recover` 再新建 |
| dub | 已有 `kind=mix` 且 `source_hash` 未变的导出；否则重算 |

`video_merges.source_hash`：`kind=concat` 为 `sha256(按顺序拼接的 [storyboard_id, video_url, duration])`；`kind=mix` 在此基础上再拼 `mix_options`（`subtitle_mode/original_audio/bgm_url/bgm_volume/speed`）与按序的 `[line_id, audio_hash, start_ms, end_ms]`。改字幕模式、换音色、改一句台词都会得到新 hash 并重混，避免「改了却被幂等跳过」。

### 7.3 停止与重启

- 每个等待循环调用 `assertRunning`；停止后当前任务不再新建，已完成内容保留。
- `stop` 只把 `running` 落 `stopped`，不覆盖 `done`（V1 已修，保持）。
- 启动时 `markInterruptedAutomations` 把遗留 `running` 标 `interrupted`，队列中的任务重新入队（见 8.4）。

## 8. 任务队列与资源锁

### 8.1 为什么需要

现状 `automation.ts` 用进程内 `Map<number, RunState>`：

- 跨集同时启动会同时抢 GPU/ComfyUI 队列，视频任务互相拖慢；
- 进程重启后 `running` 只能标中断，不能自动续跑；
- 无法限制「同时只跑 1 个 TTS 批次」。

### 8.2 数据模型

```sql
CREATE TABLE IF NOT EXISTS pipeline_jobs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  kind TEXT NOT NULL,              -- automation | dubbing | merge | motion | grid | import
  drama_id INTEGER,
  episode_id INTEGER,
  resource TEXT NOT NULL,          -- text | image | video | audio | ffmpeg
  status TEXT NOT NULL DEFAULT 'queued', -- queued | running | done | failed | stopped | interrupted
  priority INTEGER DEFAULT 0,
  payload TEXT,                    -- JSON：model/config/options
  progress INTEGER DEFAULT 0,
  note TEXT,
  error TEXT,
  attempts INTEGER DEFAULT 0,
  max_attempts INTEGER DEFAULT 2,
  locked_by TEXT,                  -- <host>:<pid>
  heartbeat_at TEXT,
  created_at TEXT NOT NULL,
  started_at TEXT,
  finished_at TEXT
);
CREATE INDEX IF NOT EXISTS idx_pipeline_jobs_status ON pipeline_jobs (status, resource, priority);
CREATE INDEX IF NOT EXISTS idx_pipeline_jobs_episode ON pipeline_jobs (episode_id);
```

### 8.3 调度

- 每种 `resource` 一个信号量，并发数来自 `app_settings`：
  - `queue.concurrency.text` 默认 2
  - `queue.concurrency.image` 默认 1
  - `queue.concurrency.video` 默认 1
  - `queue.concurrency.audio` 默认 1
  - `queue.concurrency.ffmpeg` 默认 1
- 取任务：`status=queued` 按 `priority DESC, id ASC`，事务内 `UPDATE ... SET status='running', locked_by=?, heartbeat_at=? WHERE id=? AND status='queued'`，防止双取。
- 同集互斥：同一 `episode_id` 的 `automation` 与 `dubbing` 不能同时 running（避免一边生成视频一边混音）。
- 资源互斥：`video` 任务的 payload 可声明 `exclusive: "comfyui"`，与 `image` 共享同一把锁（同一张卡）。

### 8.4 心跳与恢复

- 运行中每 15 秒写 `heartbeat_at`；
- 启动时把 `heartbeat_at` 超过 60 秒的 `running` 标 `interrupted`；
- `attempts < max_attempts` 且阶段幂等 → 重新入队 `queued`，`attempts+1`；
- 超过次数 → `failed`，错误写 `error`，前端可手动重试。

### 8.5 与现有接口兼容

- `POST /episodes/:id/automation` 改为「入队」，立即返回 `{ job_id, status: 'queued' }`；
- `GET /episodes/:id/automation` 仍返回原结构，额外带 `job_id/queue_position`；
- `POST /episodes/:id/automation/stop`：running → 置停止标记；queued → 直接 `stopped`；
- 前端轮询逻辑不变（4 秒），进度条多显示「排队中 第 N 位」。

## 9. 图文动画兜底

### 9.1 定位

不是替代视频，而是**低成本保底**：

- 视频模型排队久/失败/额度不足；
- 需要快速出「有声小说」版本验证剧情；
- 交付周期紧，先出可发布版本。

### 9.2 输入

- 分镜 `composed_image` 或 `first_frame_image`（至少一张）；
- 该镜台词/旁白的 TTS 音频（若已配音）；
- `duration`（无配音时按字数估算）。

### 9.3 算法

| 步骤 | 规则 |
| --- | --- |
| 时长 | 有配音：`audioDuration + 0.6s`；无配音：`chars / 4`（与语音预算同一基准），clamp 2.5–8.0 秒 |
| 运动 | `特写/近景` → zoom_in；`全景/远景` → zoom_out 或 pan；其余 zoom_in（按镜号交替） |
| 缩放 | 先放大到 2× 画布再 `zoompan`，避免抖动；`z` 从 1.0 到 1.12，匀速 |
| 转场 | `xfade=fade:duration=0.5`，offsets 按累计时长递减 |
| 画布 | 跟随项目 `aspect_ratio`：9:16 → 1080×1920；16:9 → 1920×1080；不写死 |
| 字幕 | 不烧 drawtext（V1 参考实现的做法会导致换行/字体问题），统一走 6.5 的 ASS 轨 |
| 音频 | 有配音轨则直接复用；无则 BGM 循环 + 淡出 |
| 输出 | `kind=motion`，写入 `video_merges` + `assets(type='motion_post')` |

### 9.4 触发

- 剧集页「导出」下拉：`图文动画`；
- 自动化 `videos` 阶段失败后：不自动降级，提示「可用图文动画先出片」；
- MCP `render_motion_post`。

### 9.5 与视频版本的差异提示

导出页明确标注：

> 图文动画：静态图 + 推拉 + 转场，无人物动作。适合审片与临时发布，不建议作为最终投放版本。

## 10. 宫格图

### 10.1 价值

同一角色/同一场景的多个镜头一次性生成，**角色一致性显著优于逐张生成**；成本约等于一张图。

### 10.2 模式

| 模式 | 格数 | 用途 |
| --- | --- | --- |
| `character_sheet` | 2×2 / 3×2 | 角色三视图/表情/年龄阶段 |
| `shot_sheet` | 2×2 ~ 3×3 | 同一场景的多个镜头首帧 |
| `first_last` | 2×2 | 每格首帧/尾帧成对 |

### 10.3 提示词模板

```text
[rows x cols grid layout], exactly [rows*cols] visible panels,
consistent art style, [style prompt], [project background],
panel 1: [镜头1 描述],
panel 2: [镜头2 描述],
...
high quality, cinematic lighting, no merged panels, no missing panels,
no text, no watermark, no borders
```

硬约束：

- 必须写 `exactly N visible panels`；
- 每格描述只写画面，不写台词；
- 角色名用 `@角色名`，与参考图机制一致；
- 负面：`merged panels, split screen artifacts, duplicated character, extra limbs`。

### 10.4 切分

1. 生成图 W×H；
2. 单元格 `cw = W/cols`, `ch = H/rows`；
3. 每格内缩 1.5% 避免接缝：`crop=cw*0.97:ch*0.97:x+cw*0.015:y+ch*0.015`；
4. 缩放到目标尺寸（角色 1920×1080，分镜按项目比例）；
5. 写入目标资产 `image_url`，`reference_images` 保留整张宫格图便于追溯；
6. 记录 `grid_sheets.cells`：`[{row,col,asset_type,asset_id,url}]`。

### 10.5 失败与人工校正

- 格数不对/人物重复：不自动重试（浪费），标 `needs_review`，UI 展示整图 + 九宫格切割预览，允许手动重新分配格子到资产；
- 切分偏位：允许调整 `inset` 与 `offset` 两个参数后重切，不重新生成。

### 10.6 数据模型

```sql
CREATE TABLE IF NOT EXISTS grid_sheets (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  drama_id INTEGER NOT NULL,
  episode_id INTEGER,
  kind TEXT NOT NULL,             -- character_sheet | shot_sheet | first_last
  rows INTEGER NOT NULL,
  cols INTEGER NOT NULL,
  prompt TEXT,
  image_url TEXT,
  cells TEXT,                     -- JSON
  inset REAL DEFAULT 0.015,
  status TEXT DEFAULT 'pending',  -- pending | completed | failed | needs_review
  error TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

## 11. 整本剧本导入与分集

### 11.1 流程

```
上传 txt/md/docx → 解析纯文本 → 分章预览 → 调整（合并/拆分/改名）
→ 选择「一章一集」或「按字数均分」→ 批量建集 → 可选立即入队自动化
```

### 11.2 分章算法

按优先级尝试 5 组正则（来自 `chapter-splitter.ts` 的成熟做法）：

1. `第X章/回/节/卷/部/篇/集`（含中文数字、阿拉伯数字）
2. 中文数字编号 `一、` `十二、`
3. 阿拉伯数字 `1.` `1、`
4. `Chapter N`
5. `【标题】`

要求：

- 至少命中 2 个章节才认为有效，否则回退「全文一章」；
- 章节标题长度 ≤60 字，正文非空；
- 保留原始顺序与标题；解析失败不丢原文。

### 11.3 分集策略

| 策略 | 规则 |
| --- | --- |
| 按字数均分 | **默认**（`split_mode='words'`）；目标 1200 字/集（范围 600–2000，与 V3 小说导入共用默认值），按章节边界切，不切断章节 |
| 一章一集 | 可选（`split_mode='chapter'`）；章节过短（<800 字）自动合并相邻章 |
| 手动 | 预览页勾选合并/拆分 |

### 11.4 幂等

- `script_imports.source_hash = sha256(rawText)`，`UNIQUE (drama_id, source_hash)` 拦重复；同项目重复上传同一文件直接返回已有 `import_id`，提示「已导入，是否覆盖」；
- 已建集不自动删除；覆盖按 `(chapter_index, part_no)` 匹配，只更新 `episodes.content`（需二次确认），多余 part 保留并提示；
- `script_chapters` 用 `(chapter_index, part_no) → episode_id` 记录映射，便于回溯「这一集来自原著哪一章的哪一部分」。

### 11.5 数据模型

```sql
CREATE TABLE IF NOT EXISTS script_imports (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  drama_id INTEGER NOT NULL,
  filename TEXT,
  source_hash TEXT NOT NULL,
  raw_text TEXT,
  chapter_count INTEGER DEFAULT 0,
  status TEXT DEFAULT 'parsed',   -- parsed | committed | failed
  created_at TEXT NOT NULL,
  UNIQUE (drama_id, source_hash)  -- 同项目同文件只解析一次，覆盖走 commit
);
CREATE TABLE IF NOT EXISTS script_chapters (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  import_id INTEGER NOT NULL,
  drama_id INTEGER NOT NULL,
  chapter_index INTEGER NOT NULL,
  part_no INTEGER DEFAULT 1,      -- 一章拆多集时的部分号
  title TEXT,
  content TEXT NOT NULL,
  char_count INTEGER DEFAULT 0,
  episode_id INTEGER,
  created_at TEXT NOT NULL,
  UNIQUE (import_id, chapter_index, part_no)
);
```

### 11.6 建集参数

- `title`：章节标题（去掉「第X章」前缀可配）；一章拆多集时加 `（1/3）`；
- `content`：章节正文；
- `auto_pipeline`：勾选则建集后入队；
- `auto_dub`：继承项目默认；
- 集号从现有最大 `episode_number` 递增，避免冲突。

- 返回体裁剪到必要字段，避免把整段音频 base64 塞进 MCP 响应。

### 16.2 新增 Agent 与技能

| 文件 | 说明 |

### 16.3 分镜提示词调整

V1 的 `storyboards` / `video_prompts` 规则（`pipeline-rules.ts`）**已经包含**「段落时长 × 4 字/秒」「每 3 秒段 ≤12 字」「旁白（画外音）不张口」和第二行声音要求。V2 不再重复追加，只做三处增量：

1. `storyboards` 规则末尾补一句：「需要对白的镜头，优先设计侧脸、背影、远景或遮挡构图，避免正脸大特写（后期配音更自然）」；
2. `video_prompts` 第二行的声音要求按 `video_audio_mode` 动态替换（见 6.7）；
3. `rewrite` 规则补一句：「保留旁白与内心独白的原文，不要改写成角色开口说」。

> 重复追加同类约束会让规则自相矛盾（例如两处字数上限不一致），维护时以 `pipeline-rules.ts` 的当前文本为准，先读再改。

第二行的替换放在生成后的 `applyAudioMode(prompt, mode)`（`services/dialogue-lines.ts` 或 `generation.ts`），按行识别「音频：」开头的第二行并整体替换；不要改规则模板，否则用户自定义规则会被覆盖。

### 16.4 资产提取提示词

`extract.characters` 增加可选字段 `personality`（现有表已有列，工具未写入）：

```
每个角色尽量补充 personality（性格关键词，2-4 个），用于后续声音设定。
```

工具 `save_dedup_characters` 的 schema 增加 `personality`，写入 `characters.personality`。

### 16.5 故事圣经注入（V3 预留）

V3 小说导入会写 `dramas.story_bible`（架构五件套 JSON）。V2 的提示词需要预留读取口，避免 V3 落地时再改一遍 Agent：

| 阶段 | 注入上限 | 理由 |
| --- | --- | --- |
| `rewrite` | 6000 字 | 需要完整人物、世界观、主线 |
| `extract` | 4000 字 | 角色/场景去重需要设定 |
| `storyboards` | 800 字 | 只取核心种子与时代地域，避免挤占镜头预算 |

实现：新增 `services/drama-story-bible.ts`，提供 `getStoryBible(dramaId)` 与 `withStoryBible(prompt, dramaId, limit)`，在 `renderPipelineRule` 之后、发给 Agent 之前前置拼接；已包含同一段不重复拼。`story_bible` 列由 V3 迁移添加，V2 实施时该列可能不存在——服务需先探测列/捕获异常，返回原文，不得因此让流水线失败。

## 18. 非功能设计

### 18.1 性能与容量

| 指标 | 目标 | 说明 |
| --- | --- | --- |
| 单句合成 | ≤3 秒（20 字，RTF 0.5） | 以部署机压测为准 |
| 一集 40 句 | ≤3 分钟 | 含重试；缓存命中可降到秒级 |
| 混音 | ≤1.5× 视频时长 | 1080p 一集 5 分钟，约 3–5 分钟 |
| 字幕 | ≤2 秒 | 纯计算 |
| 存储 | 每集音频 ≤30 MB | 24 kHz 单声道 WAV；MP3 可减半 |
| 并发 | 视频 1 / 音频 1 | 单卡机器；分离部署可提高 |

### 18.2 稳定性

- 所有外部调用有超时、重试、错误归类（`network/timeout/protocol/quota`）；
- 所有产物先写临时文件再 `rename`，避免半截文件被引用；
- 所有阶段幂等，重复执行不产生重复资产/重复计费；
- 进程重启：队列恢复、`running` 标中断、可续跑；
- FFmpeg 失败保留输入与命令日志（脱敏），便于复现。

### 18.3 可观测

沿用 `utils/task-logger.ts`，新增事件：

| 事件 | 字段 |
| --- | --- |
| `VoiceProfile` `generate` | `episodeId, count, model, ms` |
| `TTSTask` `synthesize` | `lineId, chars, voiceId, cached, ms` |
| `DubTask` `timeline` | `episodeId, lines, overflow, totalMs` |
| `DubTask` `mix` | `episodeId, duckRatio, lufs, duration` |
| `Queue` `claim/finish/recover` | `jobId, resource, waitMs, runMs` |

日志不写音频 base64、不写密钥、不写完整绝对路径。

### 18.4 隐私与合规

- 声音克隆必须确认授权：上传页勾选「我确认拥有该声音的使用授权」，写 `consent_confirmed_at`；
- 参考音频与生成音频仅存本地，不上传第三方；
- 导出成片默认不加 AI 生成标识，但设置页提供「添加 AI 生成水印/片尾声明」开关（合规选项，默认关）；
- 删除项目时级联删除 `static/tts` 下无引用文件（软删后 7 天清理）。

### 18.5 成本

- TTS 本地部署，边际成本为电费与时间；
- 视频模型仍是主要成本，V2 通过「先审片再生成视频」的图文动画路径降低试错成本；
- LLM 调用：声音设定按集一次（而非按角色），台词兜底仅在异常时触发。

## 21. 风险与开放问题

| # | 风险 | 影响 | 应对 |
| --- | --- | --- | --- |
| R1 | 本地 H3 原声与 TTS 双重人声 | 听感浑浊 | `ambient` 模式从源头解决；旧素材用更深 ducking（−12 dB）+ 中频衰减 |
| R2 | Qwen3-TTS 克隆相似度不稳定 | 角色音色漂移 | 优先 VoiceDesign 固定 seed；克隆要求 10–20 秒干净音频；P3 加一致性校验 |
| R3 | 长旁白仍超镜长 | 字幕与画面对不齐 | 四层兜底 + 跨镜延续；提示词层继续压缩字数 |
| R4 | 台词抽取误判说话人 | 配错音色 | 正则优先 + `needs_review` 人工确认；批量前先预览 |
| R5 | TTS 服务单点 | 配音全停 | 降级为「只出字幕/静音」；不阻塞视频与合片 |
| R6 | FFmpeg 混音滤镜过重 | 大集数失败 | 分块 amix；失败回退「仅拼接」并提示 |
| R7 | 声音克隆版权 | 合规风险 | 授权勾选 + 本地存储 + 可追溯 `consent_confirmed_at` |
| R8 | 队列改造影响 V1 稳定性 | 回归风险 | 队列开关 `queue.enabled`，关闭时走原内存路径 |

### 开放问题
