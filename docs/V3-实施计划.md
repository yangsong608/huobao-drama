# V3 实施计划（小说入库 + 小说→短剧改编）

## Context

V3 要把 `huobao-novel` 并入 `huobao-drama`：一个壳、三个入口（短剧/小说/设置），小说项目/章节/图谱/任务全部落 SQLite，并在小说导出页支持「导入短剧」与「同步短剧」。目标不是复制一个小说工具，而是把「写故事 → 拍故事」之间的人工复制变成可重复执行的数据管道。

本计划基于 [V3-产品功能详细设计.md](file:///Volumes/软件目录/comfyui/工具/huobao-drama/docs/V3-产品功能详细设计.md) 与当前代码核对结果。已锁定以下偏差修正：

- **不做旧数据迁移**：删除 `legacy_id`、`by-legacy`、`migrate-local`、`import-legacy`、迁移横幅及相关测试。
- **故事圣经完整落地**：`dramas.story_bible` + `services/drama-story-bible.ts` + rewrite/extract/storyboards 三处注入。
- **旧地址只做重定向**：`/huobao-novel/*` → `/novels`（90 天），不做深链映射。
- **导入默认 16:9 + 1200 字/集**，复用并扩展 V2 `planEpisodes`，不新增第二套拆集代码。
- **仅 SQLite**：`mysql-import.ts` 只保留为一次性历史迁移，不参与 V3 双库设计。
- **MCP 基线 41 个工具（V3：`import_novel_to_drama`）**；2026-11-04 新增 20 个小说查询/写入/生成/同步工具后为 **61**（见执行日志）。

范围外：双向同步、多人协作、EPUB/PDF、小说 AI 配图、雪花写作法算法改动、旧 localStorage 数据恢复、真实模型/TTS 服务验收（留到最终测试阶段）。

### 复核结论（2026-11-03）

按「检查一遍」逐项核对代码后，修正了以下问题：

1. **小说布局会丢头部**：头部与 AI 配置横幅在 `frontend/app/layouts/default.vue:4-50`，`app.vue` 只渲染 `<NuxtLayout>`；原计划 `layouts/novel.vue` 只有 `n-config-provider` + `.novel-scope`，三入口会消失。改为抽 `AppHeader.vue`，`default.vue` 与 `novel.vue` 共用；`novel.vue` 负责独立滚动容器。
2. **`shortSummary` 语义错误**：源码 `nextDraft` 把它当「当前章节摘要」（`../huobao-novel/src/prompts/chapter.js:160`），且 `src/api/generator.js:305-307` 传空串；原计划「取正文头部」错误。V3 改为取本章大纲 `chapterInfo.summary`；`previousChapterExcerpt` 取前章正文末尾 800 字。
3. **架构生成顺序**：源码实际为 `coreSeed → characterDynamics → characterState → worldBuilding → plotArchitecture`（`generator.js:39-84`，`characterState` 在 `worldBuilding` 之前），已固定。
4. **任务路由挂载不一致**：原计划同时写 `GET /novels/:id/jobs` 与「挂载 `/novel-jobs`」。改为：`GET /novels/:id/jobs` 放 novels 路由；`novelJobs.ts` 定义 `/:id`、`/:id/stream`、`/:id/cancel` 并挂 `/novel-jobs`。
5. **Phase 1 依赖倒置**：`getNovel` 的 `blueprint_chapters` 需要解析器，`listNovels.has_update` 需要导入映射 hash。大纲解析器前移 Phase 1；`has_update` 后移 P3-4；Phase 1 列表先只返回 `has_import`。
6. **设置键/路径不统一**：原计划 P1-5 写 `novel.defaults`，后文用 flat keys；设计文档写 `/novel-settings`。统一为 flat keys `novel.*` + `getNovelSettings/setNovelSettings`，接口 `/settings/novel`，P0 同步改设计 §8.6。
7. **drift-check 与 MCP 41 冲突**：`backend/scripts/drift-check.mjs:226-230` 在 M5-5 后硬编码 40。改为优先读 `docs/v3-state.json.current.mcpTools`：P0-6 记 40，P4-4 改 41；`docs/v2-state.json` 保持 40；`list_api_endpoints` 是动态路由（`backend/src/services/mcp.ts:739-755`），无需改。
8. **`source_stale` 清零时机**：设计 §6.5.4 是自动化成功后清零，原计划在 rework 清零。改为 `automation.ts` 的 `finishRun(done)` 清零；rework 不清，且 automation/配音/队列运行中返回 409。
9. **冲突原因/拆集变化不全**：补 `automation_running`、`dubbing_running`、`episode_deleted` 与 `recreate`；数量增加追加、减少 orphaned；初始导入 `episode_number=1..N`，同步 `create` 用 `max+1`。
10. **共享拆集自相矛盾**：原计划既说「默认路径字节级不变」又加场景切分。改为 `planEpisodes` 新增 `splitMode: 'legacy' | 'words' | 'chapter'`，默认 `legacy` 保 V2；小说导入显式用 `words`/`chapter`。且小说模式**不跨章合并**（映射是单章/单 part；V2 允许合并）。
11. **Tailwind 全局冲突**：改为 `important: '.novel-scope'`，不改 prefix；preflight off、content 限定小说目录；teleport 弹窗内容补 `.novel-scope` 或使用 Naive 样式，P0 spike 验证。
12. **短剧详情缺回链数据**：`GET /dramas/:id` 当前不返回来源小说（`backend/src/routes/dramas.ts:105-118`）；P3-7 增加 `source_novel: {id, title}` 联查；`source_stale` 随 episodes 返回。
13. **设置页 URL 不同步**：`frontend/app/pages/settings.vue:1208-1211` 只初始化读 query，切 tab 不回写；P2-9 增加 `router.replace` 与 `route.query.tab` watch。
14. **文档校准范围不足**：P0-1 扩到 §3.2/§4.5 头部、§4.6 路由、§5.5 迁移、§6.2/§6.4 比例、§7.1 `legacy_id`、§7.3 迁移、§8 `by-legacy`/`migrate-local`、§8.6 路径、§13.1 基线、§13.3 迁移项、§14-§16 MySQL/MCP。

## 目标架构

```
Nuxt 壳 (frontend/app)
  components/AppHeader.vue   共享头部：品牌/短剧/小说/设置/AI 横幅/GitHub/主题/语言
  layouts/default.vue        AppHeader + content
  layouts/novel.vue          AppHeader + n-config-provider + .novel-scope 独立滚动
  pages/index.vue            短剧列表
  pages/novels/index.vue     小说列表
  views/novel/detail.vue     小说详情（pages:extend）
  pages/settings.vue         + 小说分组

Hono 后端 (/api/v1)
  routes/novels.ts           /novels CRUD / 章节 / 导出 / 图谱 / jobs
  routes/novelJobs.ts        /novel-jobs/:id / stream / cancel（挂 /novel-jobs）
  routes/novelImports.ts     /novels/:id/imports...（挂 /novels）
  services/novel/            prompts / blueprint / compass / llm（编排在 novel-job-runner）
  services/novel-job-runner.ts
  services/novel-import.ts
  services/drama-story-bible.ts

SQLite: 7 张 novel_* 表 + dramas/episodes 5 个新列
```

前端依赖新增：`naive-ui`、`pinia`、`@pinia/nuxt`、`echarts`、`@vicons/ionicons5`、`@nuxtjs/tailwindcss`、`tailwindcss@3`。后端新增：`ai@^6`（流式文本；自有 `@ai-sdk/openai@3.x`、`@ai-sdk/google@3.x` 已依赖 `@ai-sdk/provider@3`，与 AI SDK 6 配套）。

**Tailwind 策略**：`preflight:false`、`content` 只扫 `app/components/novel/**`、`app/pages/novels/**`、`app/views/novel/**`、`app/layouts/novel.vue`；`darkMode: ['selector','[data-theme="dark"]']`；**不加 prefix**，改用 `important: '.novel-scope'`，让所有工具类生成 `.novel-scope .flex` 形式，避免覆盖既有 `studio.css`。teleport 到 body 的弹窗内容若用 Tailwind，需显式加 `.novel-scope` 或改用 Naive 样式；P0 spike 做视觉回归。

**Naive UI 用法**：不引入额外 Nuxt 模块，组件在 SFC 内显式 import；`n-config-provider` 放在 `layouts/novel.vue`，深色时传 `darkTheme`，`themeOverrides` 对齐圆角/主色。

**布局与滚动**：`studio.css` 已设置 `body { overflow:hidden }`。`novel.vue` 使用 `.novel-shell { height:100vh; display:flex; flex-direction:column; overflow:hidden }`，`.novel-scope { flex:1; overflow-y:auto }`；头部共享后短剧页不回归。
