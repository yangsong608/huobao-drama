## 1. 结论与建议路径

1. **先窄后宽**：先用 **6 人日** 做「第 5 集能听清」的窄切片（MVP-A），不碰 UI 面板与队列；确认音质与时间轴可信后，再投完整 P0。否则要等两周才知道方向对不对。
2. **设计稿工期偏乐观约 2 倍**：P0 的 11 项在稿中是 4–5 天，本计划按 **15.5 人日** 排。差额来自联调、e2e 调参、6475 行 `episode.vue` 改造、40 条新测——稿中未计入。
3. **三个硬前置必须先解决**：TTS 服务可达（否则全程 mock，验收不了音质）、**当前无 git 版本管理**、**2 条守卫测试会必红**（见 2.3）。
4. **字幕烧录只有一条可行路径**：随包 ffmpeg 6.0 含 libass/freetype，系统 `/opt/homebrew/bin/ffmpeg` 9.0.2 **不含** libass。必须固定使用 `utils/ffmpeg.ts` 解析的二进制，并加能力探测，否则「烧字幕」在开发机上静默失败。
5. **推荐里程碑**：M0 清障 → MVP-A 窄切片 → M1 音色 → M2 台词/字幕/混音 → M3 工作台/自动化 → M4 兜底 → M5 产能。

## 3. 实施原则

| 原则 | 落地做法 |
| --- | --- |
| 垂直切片优先 | 先跑通「1 句 → 1 段 → 1 集」，不按层横向写完所有 service 再联调 |
| 开关先行 | `dubbing.enabled` 默认 `false`、`queue.enabled` 默认 `false`；关闭时行为与 V1 完全一致，可随时回退 |
| 契约先行 | DDL、TS 类型、路由路径先定；接口先返回 501 或 mock，前端可并行 |
| 只加不改 | 迁移只加表/加列；旧字段不删不改名；`video_merges` 只加列 |
| 双实现 | TTS 真服务与 mock 同一接口（`synthesize()`），无服务也能跑完链路 |
| 一任务一提交 | 每个任务一个可独立回退的改动集；M0 先建 git 基线 |
| 先测后接 | 每个 service 先有单测再接 UI/自动化；单测失败不进下一里程碑 |
