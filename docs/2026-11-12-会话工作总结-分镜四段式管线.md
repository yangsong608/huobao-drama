## 二、会话背景与目标

本次会话围绕「分镜拆分与校验」持续展开，起点不是单一 bug，而是整条分镜生产链路的执行逻辑不正确：

- 拆分按大段批量生成，模型把多机位、多动作塞进一个分镜。
- 视频提示词结构不统一，缺少画面调度、时间帧、负面约束等硬约束。
- 模型会把「喊、叫卖、揽客」写成没有具体内容的动作，生成视频只有张嘴喊叫、没有台词。
- 场景同名多 ID、资产别名、屏幕左右翻转、地标翻面、占位台词「无」等问题反复出现。
- 校验是批量/窗口式，不能保证「这一镜通过后再进入下一镜」。
- BGM/环境声没有设计，或者逐镜重复同一风格，缺少跨镜连续性。

最终目标被明确为四段式执行模型：

1. **预拆骨架**：按场次/节拍批量产出分镜骨架。
2. **逐镜修补**：严格逐镜，加载前后镜与完整小说场景，补台词、动作、调度和固定分区。
3. **逐镜校验**：修补一镜立即校验一镜，通过才进入下一镜。
4. **声音设计**：全部镜头校验后，按场景/剧情声音单元设计 BGM、环境声、音效、静默，跨镜分配。

其中第二段「逐镜修补」要求最高，是整条链路的核心。

## 三、会话起点的主要问题

### 3.1 拆分单位错误

- 旧规则允许一个分镜包含 2–4 个子镜头，导致一个视频任务里出现多次切镜。
- 模型把整场戏塞进一个分镜，镜头数明显低于覆盖下限。
- 分块拆分虽然解决了长请求失败问题，但每块仍按旧单位生成。

### 3.2 视频提示词缺少硬约束

- 信息头、画面调度、时间帧、负面约束格式不统一。
- 屏幕左右、过肩、背景地标、轴线、动作起点/终点缺失。
- 台词与时间帧容量不匹配，长台词被压缩或改写。

### 3.3 发声动作没有台词

第 1 集第 2 镜是典型例子：

- 小说原文是「扯着嗓子高声揽客/叫卖」。
- 拆分结果写成「高声揽客」，但没有具体台词。
- 视频模型生成了张嘴喊叫动作，没有可听内容。
- 早期错误方案试图把「喊」改成拍围裙、翻炊饼等非语言动作，这被明确否定：**必须遵循小说语意补出具体台词，不能改动作**。

### 3.4 场景与资产不一致

- 54/55/56 等多个场景 ID 指向同一「唐记食铺大堂」。
- 模型只写 `location` 不写 `scene_id`，导致镜头无场景。
- `@邓州西市街` 等别名导致资产绑定警告。
- 同一场戏中人物左右、门窗侧、轴线反复翻转。
- 部分角色（如马老三）没有绑定到镜头。

### 3.5 校验规则误报与漏报

- 台词容量按派生行逐条计算，产生大量误报。
- 缺少对「发声动作必须有具体台词」的检查。
- 占位台词「旁白：无」「@角色说：无」被当成真实台词。
- 批量/窗口校验无法保证逐镜通过。

### 3.6 声音设计缺失

- 视频提示词曾尝试逐镜写完整 BGM/环境声风格，导致每镜一个风格、每镜重复。
- 正确做法是：声音属于场景/剧情单元，可能跨多个分镜甚至跨场；单镜只写增量，不重复完整风格，不逐镜重启 BGM。

## 四、关键设计决策

| 决策 | 结论 |
|---|---|
| 分镜单位 | 一个分镜 = 一个机位 + 一个主体 + 一个连续动作，6–15 秒 |
| 子镜头 | 禁止【镜头2】及以后；同一机位内可写多个时间帧 |
| 执行顺序 | 预拆骨架 → 逐镜修补 → 逐镜校验 → 声音设计 |
| 修补上下文 | 目标骨架 + 前 1–2 镜成稿 + 后 1–2 镜草稿 + 完整场次原文 + 原始小说场景 |
| 台词 | 原剧本有引号台词逐字保留；只有发声动作时补具体台词；原剧本没有发声动作时不得自行加台词 |
| 校验粒度 | 严格逐镜；失败同镜最多 3 次（初始 + 2 次重试），仍失败停在该镜等人工 |
| 失败可修 | 校验失败仍保存草稿行，页面可直接编辑，修好后继续 |
| 声音时机 | 所有普通分镜校验通过后，作为第四步执行 |
| 声音单位 | 场景/剧情单元，可跨多镜、可跨场 |
| 单镜声音 | 只写短增量：延续 / 本镜进入 / 本镜新增音效 / 淡出 / 静默 |
| BGM 交付 | `native` 或 `post`；同一集不混用 |
| 场景 | 使用 canonical scene_id；同名场景只选主场景 |
| 屏幕方向 | 同场第一镜定左右、轴线、地标侧，后续镜头沿用 |

### 5.4 四段式管线落地（核心）

#### 数据模型

新增：

- `storyboard_pipeline_jobs`：管线任务、阶段、总镜数、已修补/已校验/失败镜数、声音状态。
- `storyboard_skeletons`：分镜骨架、原文摘录、状态、重试次数、问题、关联成稿。
- `sound_plans`：一集声音计划、版本、计划 JSON、校验 JSON。
- `sound_cues`：跨镜声音线索，记录单元、类型、起止镜号、描述、强度、进入/退出、交付方式。
- `storyboards.sound_cue`、`storyboards.sound_unit_key`：单镜声音增量与声音单元键。

旧库启动迁移已验证：新表与新列可在正式库副本上自动创建。

#### 第一段：预拆骨架

- 按场次分块，模型只产出骨架：场次、人物、道具、时长、动作摘要、转场、连续性、逐字原文摘录。
- 不写最终台词，不写完整视频提示词。
- 原文摘录必须逐字来自本段（允许去空白），按剧情顺序，不得改写、概括、跨段摘取。
- 摘录覆盖率低于 25% 拒绝该段；低于 60% 记录警告。
- 镜号由系统跨块连续分配。

#### 第二段：逐镜修补

- 严格按镜头顺序，一次只修补一镜。
- 上下文包含：目标骨架、原文摘录、完整场次原文、原始小说场景、前 2 镜成稿、后 2 镜草稿、上一轮校验问题。
- 要求：
  - 原剧本有台词逐字保留。
  - 只有「喊/叫卖/揽客/吆喝/招呼/骂」等发声动作时，必须补具体台词，不能改成非语言动作。
  - 原剧本没有发声动作时不得自行加台词。
  - 固定四区：信息头 → 画面调度 → 时间帧 → 负面约束。
  - 同场沿用前镜屏幕左右、轴线、地标侧。
- 修补被拒时仍保存草稿行，用户可在页面直接编辑该镜。

#### 第三段：逐镜校验

确定性检查：

- 单机位/单主体/连续动作、6–15 秒、时间帧连续。
- 固定分区完整。
- description 与 video_prompt 台词逐字一致。
- 原剧本引号台词不丢失。
- 发声动作必须有具体台词。
- 原剧本没有台词/发声动作时禁止自行加台词。
- 相邻镜屏幕左右、地标侧、轴线、动作端点配对。
- 失败同镜最多 3 次；仍失败则标记 manual，停在该镜，不进入下一镜。

#### 第四段：声音设计

- 全部普通分镜通过后执行。
- 按场景/剧情归组声音单元；过渡分镜归入相邻单元。
- 每个单元生成 BGM 弧、环境声、画内音效、静默 cue。
- BGM/环境声用 `from_shot_number → to_shot_number` 跨镜表达，不逐镜重复。
- 单镜只派生短增量：
  - cue 从本镜开始：本镜进入 / 建立环境声。
  - cue 从更早镜头延续：延续当前 BGM/环境声，不重启。
  - 本镜有音效：本镜新增。
  - 换场/时间跳：新环境声建立，BGM 可跨场延续。
- 校验：
  - 每个普通分镜必须归入环境声或静默。
  - BGM/环境声/静默同轨不能重叠。
  - 同一单元只能一条 BGM。
  - 同一场戏不能逐镜重起 BGM（除非有静默间隔）。
  - 环境声不能跨不同场景。
  - 同一镜的 cue 必须属于同一单元。
  - 强 BGM 覆盖有台词镜头视为压过对白。
  - native/post 不能混用。
- `bgm_prompt/sound_effect` 只写在 cue 真正开始的镜头，作为后期混音聚合锚点；不再逐镜重复完整风格。

#### 自动化与接口

- 自动化流程的「分镜拆分」阶段从旧的一次性 `storyboard_breaker` 切到四段式管线。
- 新管线完成后，自动化跳过旧批量动作检验；旧数据仍保留批量补检。
- 新增管线接口：创建、最近任务、按 ID 查询、暂停、继续。
- 新增声音计划只读接口。

#### 页面

- 拆分面板显示阶段：预拆骨架 / 逐镜修补 / 声音设计。
- 预拆阶段显示块进度；修补阶段显示逐镜状态、已通过数、当前镜。
- 失败镜在列表中可见并可编辑。
- 新增声音计划抽屉，按声音单元和 BGM / 环境声 / 音效 / 静默四条轨道只读展示。

## 六、重点问题与修复记录

| 问题 | 原因 | 处理 |
|---|---|---|
| 模型把多机位塞进一个分镜 | 旧规则允许 2–4 子镜头 | 改为单机位/单主体/连续动作，6–15 秒；保存层拒绝多子镜头 |
| 「喊/叫卖」没有具体台词 | 拆分只写动作，未补台词 | 校验强制造声动作必须有具体台词；修补上下文加载小说场景补台词；禁止改成非语言动作 |
| 占位台词「无」 | 模型用「无」填充台词位 | 保存时清理占位台词；规则层禁止 |
| 场景同名多 ID | 54/55/56 等别名共存 | canonical 场景归一；保存时自动绑定主场景 |
| `@邓州西市街` 别名警告 | 别名与 canonical 名不一致 | 资产别名归一；唯一场景前缀替换 |
| 屏幕左右/地标翻转 | 模型前后镜自行换边 | 同场第一镜建立左右/轴线/地标表，后续自动纠正并成对校验 |
| 台词容量误报 | 按派生行逐条计算气口 | 改为整镜总台词字数 ÷ 4 字/秒 + 1 秒气口 |
| 批量校验不能逐镜通过 | 窗口/批量执行 | 新管线逐镜修补后立即单镜校验 |
| 逐镜声音每镜一个风格 | 单镜直接写完整 BGM | 声音改为第四步场景/剧情单元设计，单镜只写增量 |
| 跨单元 BGM 被重启 | 按“是否同一单元”判断进入/延续 | 改为按 cue 实际起始镜头判断，跨场 BGM 继续不重启 |
| 声音锚点写错镜头 | 写在单元第一镜 | 改为写在 cue 真正开始的镜头 |
| 重写提示词丢声音区 | AI 重新生成只写四区 | `update_storyboard` 与动作检验修复保留原声音区 |
| 修补失败后没有可编辑镜头 | 校验失败完全不落库 | 失败也保存草稿行，人工可修，修好续跑会先校验成稿 |
| 骨架原文约束为空 | 服务端 snake_case，工具按 camelCase 读取 | 工具统一归一化骨架字段；E2E 真实模型暴露并修复 |
| 声音 cue 单元不一致 | 模型给 BGM/环境声/音效用了不同 unit_key | 增加同镜 cue 单元一致性校验；E2E 首轮被拒、模型自动修正 |
| 分镜导演不读剧集拆分方案 | 只给 breaker 注入 breakdown 块 | 将 `storyboard_director` 加入方案块与单位规则注入 |
| 自动化仍走旧拆分 | `stepStoryboards` 直接调用旧 Agent | 改用四段式管线并轮询阶段/逐镜进度 |

## 十一、经验教训

1. **执行模型比单条提示词更重要。** 只改拆分提示词无法解决批量生成、无台词、方向翻转等问题；必须把预拆、修补、校验、声音拆成独立阶段。
2. **逐镜修补需要完整上下文。** 只给目标镜和一句摘要，模型无法判断台词归谁、动作是否接得上；必须给前后镜和完整场次原文。
3. **发声动作必须补台词，不能改动作。** 这是本次会话中被明确纠正的关键方向。
4. **声音必须按场景/剧情设计。** 逐镜写完整 BGM 一定会重复、重启、风格漂移；单镜只写增量。
5. **校验要在保存层强制执行。** 只在提示词里要求，模型会遗漏；保存时拒绝并返回具体错误，模型才能自我修正。
6. **失败也要可见可修。** 校验失败不落库会让用户没有可编辑对象；保存草稿行再停下，才是可用的工作流。
7. **服务端与工具字段边界必须测试。** snake_case/camelCase 不一致会被单元测试掩盖，真实模型 E2E 才暴露；关键上下文要加端到端测试。
8. **辅助链路不能破坏主产物。** 重新生成提示词、批量修复、动作检验都可能覆盖声音区，必须在所有写提示词的入口保留第四步结果。
