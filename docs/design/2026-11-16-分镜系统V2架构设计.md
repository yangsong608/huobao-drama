# 分镜系统 V2 架构设计

- 状态：设计稿，待评审
- 日期：2026-11-16
- 范围：分镜拆分、镜头覆盖、时间轴、TTS、提示词、校验、设置与迁移
- 目标：用一套结构化计划替代当前的阈值拆分与后处理补丁链

---

## 1. 背景与问题

当前分镜链路大致为：

剧本 → 确定性 planner 设定边界/时长/句数 → 模型补骨架 → 意图与旁白 → 模型写 description 与 video_prompt → 时间帧重排 → 画面左右对齐 → 时长裁剪 → 校验门禁 → 声音

这条链路的问题不是某一条阈值，而是多个层次同时拥有创作决定权：

- 三句上限、每句字数、固定时长、固定字数/秒等硬规则代替了叙事与覆盖判断；
- planner、模型、rebalancer、align、fit、validator 都能修改同一个结果；
- 时间帧既是生成结果，又被当作可回写的数据；
- 时长先估再分配，缺少真实音频锚点；
- 屏幕左右、时间帧精度、容量问题靠下游门禁补救；
- TTS 如果前置，会在分镜和生成方案未确认时产生不可用成本。

结果是：每出现一个内容问题，就增加一条阈值或一个后处理；规则之间互相冲突，单个镜头的问题会反复触发整段重跑。

V2 的目标是重新划分权限，而不是继续增加规则。

---

## 2. 设计结论

V2 采用六层结构：

1. Beat Plan：戏剧事实与原文覆盖
2. Coverage Plan：镜头、覆盖方式、切/合理由
3. Timing Plan：声音事件与动作事件的时间轴估算
4. Plan Review：计划确认
5. Audio Realization：确认后的正式 TTS
6. Prompt Assembly 与 Invariant Validation：提示词装配与结构校验

核心原则：

- 创作决定由节拍、覆盖、观众信息变化驱动；
- 时长由台词音频和动作事件推出；
- 平台限制只做生成适配，不做创作分配；
- 提示词由计划投影生成，不允许下游静默改写；
- 结构不变量由代码固定，创作偏好由预设和审核决定；
- 昂贵副作用（TTS、图片、视频、音乐）只在确认后执行。

---

## 3. 规则分级

V2 采用四级规则，避免把所有规则都做成硬门禁：

| 级别 | 含义 | 处理方式 |
|---|---|---|
| 结构不变量 | 违反即结构错误 | 阻断，回到 Plan 层重做 |
| 需证据判断 | 需要看原文、资产或镜头证据 | 进入审核清单，不自动改稿 |
| 常用做法 | 类型片的默认经验 | 项目预设，可覆盖 |
| 创作者选择 | 风格、镜头语言、节奏选择 | 记录，不判错 |

平台限制属于系统约束，不伪装成创作规则：

- 模型原生最短/最长时长
- 最大分辨率、参考图数量、音频能力
- 供应商接口能力

平台限制只决定“如何生成/裁剪/拆容器”，不决定内容应该几秒。

## 4. 分层架构

### 4.1 Beat Plan

输入：剧本、项目资产、场景契约、项目风格。

输出：结构化 Beat 列表。

Beat 记录：

- 原文起止位置
- 场景、说话人、台词引用
- 类型：建置、冲突、转折、揭示、反应、收尾
- 新信息、情绪变化、权力/关系变化
- 动作事件、关键道具、可见文字
- 是否明确省略及理由

Beat 不决定镜头、不决定时长。

### 4.2 Coverage Plan

输入：Beat Plan、资产、场景空间常量、项目覆盖预设。

输出：ShotPlan 列表。

每个 ShotPlan 必须声明：

- 引用哪些 Beat 或 Beat 片段
- 覆盖方式：Master、OTS、反打单人、反应特写、插入镜
- 一个机位、一个主体、一个连续动作
- 景别、角度、镜头行为
- 屏幕左右、轴线、地标
- 台词引用与动作事件引用
- 连续性入点/出点
- 视觉依据与资产引用
- 切镜理由或合镜理由

没有切镜理由就不能切；同一 Beat、同机位、只是换说话人，默认合并。

### 4.3 Timing Plan

输入：ShotPlan、Voice Timing Profile、动作事件。

输出：每镜的事件时间轴和时长估算。

- 台词是原子对象，带说话人、文本、原文引用、估算时长；
- 动作是事件，带类型、速度、起止状态；
- 镜头时长由事件自然推出；
- 估算只用于计划期，不作为最终音频；
- 平台原生时长只决定是否需要多镜容器或生成后裁剪。

### 4.4 Plan Review

确认内容：

- 原文覆盖是否完整
- 每个切点是否有理由
- 覆盖方式是否合理
- 连续性和轴线是否成立
- 时间轴是否在平台可执行范围内
- 是否有无信息镜头

确认后才允许进入 TTS 与生成准备。

### 4.5 Audio Realization

正式 TTS 只处理已确认镜头：

- 按文本、音色、语速、情绪建立缓存
- 多句并行合成
- 被合并、删除、跳过的镜头取消任务
- 用真实音频时长回写时间轴
- 只调整尚未生成视频的镜头

如果视频必须先生成，则使用计划期估算，音频后处理只做适配，并标记为降级路径。

### 4.6 Prompt Assembly 与校验

提示词由 ShotPlan 和 TimingPlan 投影生成：

- 信息头、画面调度、时间帧、负面约束来自结构字段；
- 模型只补视觉形容词、表情、环境细节；
- 不允许改变边界、台词、时长、覆盖方式、资产 ID；
- 下游不再做时间帧重排、左右对齐、时长裁剪等文本后处理。

校验只检查不变量，不修改提示词。

## 6. 计划生命周期

状态：

草稿 → 节拍完成 → 覆盖完成 → 计划确认 → 音频完成 → 提示词完成 → 生产确认 → 已生产 → 已审查

确认门：

| 门 | 检查 |
|---|---|
| G1 剧本/节拍 | 原文覆盖、场景、人物、关键动作 |
| G2 覆盖/镜头 | 每个切点有理由、一镜一机位、空间连续 |
| G3 生成计划 | 模型能力、时长容器、参考素材、成本预览 |
| G4 音频 | 真实 TTS 时长与时间轴一致 |
| G5 生产 | 只执行已确认镜头，缓存与参数可复核 |

G3 之前不生成正式 TTS；G5 之前不调用图片/视频生成。

---

## 7. 覆盖与切镜

允许的切镜理由：

1. 节拍变化
2. 听者反应成为信息
3. 机位/景别/视角必须变化
4. 插入镜
5. 场景或时间变化

规则：

- 同一节拍、同机位、只是换说话人：默认不切；
- 长台词后跟短反应：判断反应是否形成新的权力/情绪节点；
- 没有切镜理由就合并；
- 场景变化必须切或补中性镜；
- 轴线翻转必须由可见动作/中性镜解释，不能靠自动改文字掩盖；
- 每个切点必须写明理由。

Drama Skills 的 SHT-03、SHT-04、SHT-29 作为常用做法参考，不作为固定句数规则。

---

## 8. 时间与 TTS

### 8.1 计划期

不生成正式 TTS：

- 每个角色/音色有一个 Voice Timing Profile；
- 一次短校准句得到语速、标点停顿、句间停顿；
- 用发音单元、标点、语气词估算台词时长；
- 动作使用 ActionEvent 估算；
- 估算只用于容量判断与拆镜建议。

### 8.2 确认后

正式 TTS 在 G3 后、视频生成前执行：

- 只处理确认镜头；
- 文本、音色、语速、情绪作为缓存键；
- 并行合成；
- 变更镜头只重合成变化句子；
- 合并/删除/跳过时取消任务；
- 真实时长回写时间轴。

### 8.3 生成适配

- TTS 实际时长确定后生成视频；
- 模型原生片段生成后裁到实际内容长度；
- 视频生成后不再为了 TTS 重新拉长画面；
- 小于模型原生最短时长时，优先多镜容器或保持原生最短再裁剪。

---

## 9. 提示词装配

提示词是计划的投影：

- 信息头来自 ShotPlan；
- 画面调度来自空间字段与视觉依据；
- 时间帧来自 TimingPlan；
- 负面约束来自项目与镜头约束；
- 台词逐字来自 DialogueLine；
- 资产引用来自资产库。

模型只补视觉形容词、表情、环境细节，不允许改结构。

下游必须删除：

- 时间帧重排
- 画面左右自动翻转修补
- 时长再分配
- 动作延续填充
- 文本级合并/拆分

不合格时回到 Coverage Plan 或 Timing Plan 重做。

---

## 10. 校验

### 10.1 结构不变量

- 原文动作/台词/声音被镜头覆盖或明确省略
- 一镜一场景、一机位、一连续动作
- 台词逐字完整
- 资产 ID 合法
- 屏幕左右与轴线连续
- 时间轴连续、结束一致
- TTS 实际时长与时间轴一致
- 提示词与计划版本一致

### 10.2 需证据判断

- 切点是否有观看职责
- 反应镜是否承载新信息
- 视觉依据是否覆盖画面主体
- 关键帧是否只冻结一个瞬间

### 10.3 创作验收

项目可配置 checklist：

- 钩子
- 反应镜
- 镜头节奏
- 近景占比
- 无信息镜头
- 覆盖多样性

只给审核提示，不自动改分镜。

## 11. 设置与界面

### 11.1 拆分分镜方案

改为 Coverage Preset：

- 导演/覆盖风格
- Master / OTS / 反打倾向
- 对话覆盖偏好
- 动作镜处理
- 插入镜和留白
- 转场策略
- 节奏档案

删除：

- 创作性最短/最长秒数
- 句数、字数上限
- 固定字数/秒
- 固定气口
- 固定镜头数

### 11.2 检验方案

- 结构不变量：只读，由代码维护
- 创作验收：可配置 checklist
- 项目节奏档案：目标平均值，不是每镜配额
- 单集覆盖 override：一镜到底、反应强调等，存放在 EpisodePlan

### 11.3 界面

一套分镜工作台：

- 节拍视图
- 覆盖/镜头板
- 镜头详情抽屉
- 时间轴与音频
- 问题列表
- 生产确认

可选导出：

- 剧本 Markdown
- 视觉设定 Markdown
- 分镜 Markdown
- 图片提示词 Markdown
- 视频提示词 Markdown
- 证据 JSONL

数据库是唯一事实来源，导出是视图。

## 13. 迁移与逐集优化

### Phase 0：冻结 v1

- v1 只读保留
- 不再新增阈值补丁
- 建立兼容读取

### Phase 1：V2 计划模型

- Beat、ShotPlan、TimingPlan、PromptVersion、Manifest
- 版本与修订血缘
- 结构不变量校验器

### Phase 2：Coverage Plan

- 节拍分析
- 覆盖设计
- 切镜理由
- 第 53 集影子运行

### Phase 3：Timing 与 TTS

- Voice Timing Profile
- 计划期估算
- 确认后 TTS
- 缓存、并行、取消
- 真实时长回写

### Phase 4：设置与界面

- Coverage Preset
- Rhythm/Production Profile
- Review Checklist
- Markdown 导出

### Phase 5：切换

- 连续 3 到 5 集影子对比
- 生产切换
- 删除旧 planner、merge 补丁、rebalance、align、fit、自动左右翻转等

### 逐集优化

- 每集只改 EpisodePlan override，不改代码
- 同一问题连续出现，才升级为项目预设或架构规则
- 单集问题保留在单集版本
- 建立 golden episodes 回归集
- 每集记录切镜理由、覆盖类型、时长来源、人工 override、TTS 估算误差、验收结果

---

## 14. 验收指标

- 原文覆盖 100%
- 每个切点有理由
- 不存在固定句数/字数切分
- 时长由音频/事件决定
- TTS 不在计划确认前生成
- 合并/删除镜头取消 TTS
- 提示词无下游改写
- 屏幕左右与轴线由计划决定
- 视频生成后不再重新分配时长
- 第 7/8、24-26 类问题由节拍、覆盖、音频自然决定
- 影子运行中 v2 的镜头数、平均时长、无信息镜头、覆盖多样性可解释

---

## 15. 风险与取舍

- Coverage Plan 依赖模型判断，需要结构化输出和人工审核门；
- 估算时长与真实 TTS 有误差，必须只调整未生成镜头；
- 旧数据迁移成本高，v1 需保留读兼容；
- 模型原生时长和能力差异，需要 Production Profile；
- 创作验收不能全部自动化，必须允许人工接受/覆盖；
- 去掉后处理后，上游计划质量要求更高，不能再靠门禁补救。

---

## 16. 结论

V2 的核心不是再定义一套更复杂的阈值，而是确定权限边界：

- Beat 决定发生了什么；
- Coverage 决定怎么拍、为什么切；
- Timing 决定多长；
- Audio 决定真实音频；
- Prompt 只负责投影；
- Validator 只负责不变量。

只有这套边界稳定后，逐集优化才有意义；否则每集都会变成新的规则补丁。
