# 火宝与 DSH 集成设计方案（dsh-moss-huobao）

- 日期：2026-11-13
- 状态：P0 本地实现完成；P1 文本桥启用设置与开关已实现；DSH 真机与 A/B 验收待批准
- 范围：设计决策、运行架构、接口契约、任务状态机、数据变更、安全边界、验收与分期
- 结论：采用「dsh-moss-huobao 双桥接插件 + DSH 主入口 + 火宝独立窗口」方案，私有自用，不对外分发

---

## 1. 背景与目标

火宝短剧（MossHuobao）是一个 AI 短剧/漫剧一站式制作平台，覆盖「小说/剧本 → 改写 → 资产提取 → 生图 → 分镜 → 视频 → 配音 → 混音/剪辑 → 拼接导出」。当前由三端组成，本次新增独立 DSH 插件目录：

- `backend/`：Hono + Drizzle + better-sqlite3 + Mastra，262 个 TS 文件、约 85,063 行；46 个路由文件、336 个路由声明；153 个服务文件、17 个适配器；73 张表；7 个 Mastra Agent；66 个 MCP 工具。
- `frontend/`：Nuxt 3 + Vue 3，约 68,820 行；98 个 Vue 组件；核心工作台 `views/drama/episode.vue` 约 13,082 行。
- `desktop/`：Electron 壳，负责端口编排、后端 fork、userData、模板迁移和应用内更新。
- `app/dsh/`：DSH 插件 `dsh-moss-huobao` 的独立包目录（宿主、客户端、共享契约、Preset、测试）；不属于火宝三端运行时，也不复制火宝业务代码。

DSH（DeepSeek Harness）是 Cordis 驱动的「一切皆插件」Agent Harness，本机已安装 0.2.2-rc.1，运行时 Node v24.21.0。它提供内置 LLM、Agent 循环、会话日志、子 Agent、工具注册表、技能、审批、MCP 客户端和 Web 客户端。宿主插件是 `apply(ctx)`，客户端是 React bundle；核心服务包括 `ctx.llm`、`ctx.agents`、`ctx.subagents`、`ctx.tools`、`ctx.skills`、`ctx.jobs`、`ctx.webServer`。`ctx.webServer` 是浏览器/桌面 UI 的 HTTP 载体，不能假定它对其他本地进程一定可达；桥接传输单独设计。

本次集成的目标是：

1. 把 DSH 作为统一主入口，负责对话、Agent 编排、任务和插件能力。
2. 保留火宝现有独立界面，用于精细编辑、媒体预览和可视化操作。
3. 火宝的全部**文本 AI**改用 DSH 内置 LLM；图片、视频、TTS、ComfyUI 生成仍由火宝适配器执行。
4. 火宝原有的 Mastra Agent 默认由 DSH Agent 替代；DSH 不可用时回退 Mastra。
5. 私有自用，不对外发布插件，不改变火宝的许可证与分发边界。

## 2. 范围与非目标

### 2.1 本期范围

- 在 `app/dsh/` 新建 DSH 宿主插件 `dsh-moss-huobao`：LLM 桥、Agent 桥、业务工具、健康检查、火宝状态面板。
- 火宝后端：`dsh-bridge` 文本 provider、异步任务桥、运行时描述文件、Mastra 回退、任务中心展示。
- 火宝界面：AI 按钮改为异步任务；显示 DSH/回退标识；保留现有编辑能力。
- 7 个角色的 DSH Agent Preset、技能迁移、模型映射、工具白名单。
- 本地回环安全、令牌、健康检查、重连、幂等、失败回退和验收用例。

### 2.1.1 文本 AI 范围

「全部文本 AI 走 DSH」包含两类路径：由 DSH Agent 承担的多步任务，以及火宝后端直接发起的一次性文本调用。两者都必须使用 DSH 模型，但入口不同。

| 路径 | 调用方 | 走法 | 角色 |
|---|---|---|---|
| Agent 类文本任务 | 剧本改写、资产提取、分镜拆分、导演、提示词生成、分镜校验、音色设计 | Agent 桥 | 7 个角色 |
| 一次性文本调用 | `h3-prompt.ts`、`line-performance.ts`、`novel-import.ts`、`sound-plan-audio.ts`、`soundscape-compiler.ts`、`voice-design.ts` | LLM 桥 | `prompt_generator`、`storyboard_auditor`、`extractor`、`sound_designer`、`voice_designer`、`generic` |
| 其他文本调用 | 后续新增的 `callText`/`callTextJson` 调用方 | LLM 桥 | 按语义选角色，默认 `generic` |

明确排除，仍走火宝原 provider：

| 路径 | 原因 |
|---|---|
| `style-analysis.ts` | 需要图片输入，属于视觉理解 |
| `storyboard-acceptance.ts`、`storyboard-visual-preflight.ts`、`vision-call.ts` | 视觉预检/验收 |
| `routes/aiConfigs.ts` 的连通性测试 | 测试用户外部配置，不应经 DSH 桥 |
| 图片、视频、TTS、ComfyUI 生成 | DSH 不提供这些生成能力 |

由 DSH Agent 承担的任务，LLM 调用发生在 DSH 内部；由火宝后端直接发起的文本调用，走 LLM 桥。两者都受角色模型映射约束。

### 2.2 非目标

- 不把火宝的 Nuxt 界面重写为 React，也不在 DSH 内用 iframe 嵌入火宝界面。
- 不把火宝后端整体移植进 DSH 插件进程。
- 不把图片、视频、TTS、ComfyUI 生成替换为 DSH 能力；DSH 不提供这些生成模型。
- 不引入多租户、账号体系、公网访问或远程协作。
- 不对外发布插件，不把火宝代码复制进 MIT 插件分发。
- 不改变火宝现有的 73 张表、媒体目录和队列语义；只做必要的桥接字段与运行时文件。

## 3. 现状与约束

### 3.1 关键事实

| 项 | 现状 | 证据 |
|---|---|---|
| 后端框架 | Hono 4 + `@hono/node-server`，入口 `backend/src/index.ts` | 代码 |
| 数据库 | SQLite + better-sqlite3 + WAL；72 条静态 DDL + `storyboard_lines` 动态 DDL，共 73 张表 | `backend/src/db/sqlite-schema.ts`、`backend/src/db/schema.ts` |
| 数据访问 | 21 个路由文件直接 import `db`；服务层大量使用 Drizzle | `backend/src/routes/*`、`backend/src/services/*` |
| Agent | Mastra 1.17，7 个注册 Agent | `backend/src/agents/index.ts` |
| MCP | 手写 JSON-RPC，Streamable HTTP 的 POST 形态；66 个工具；默认 127.0.0.1:5780 + Bearer | `backend/src/services/mcp.ts`、`backend/src/routes/mcp.ts` |
| 前端 | Nuxt 3 SPA，98 个 Vue 组件；核心工作台 13,082 行 | `frontend/app/views/drama/episode.vue` |
| 桌面 | Electron 37；随机端口；userData；模板版本 19 | `desktop/src/main.ts` |
| 任务表 | `sys_task` 已有动态列迁移模式（`config_id`、`config_base_url`、`stage`、`error_code`、`transition_id`、`episode_id`） | `backend/src/db/sqlite-schema.ts` |
| 运行时 | 火宝测试与桌面按 Node 22；better-sqlite3 ABI 127 | 本机验证 |
| DSH 运行时 | DSH Desktop 0.2.2-rc.1，自带 Node v24.21.0；Node 24 的 better-sqlite3 需要 ABI 137 | 本机安装与 `/Applications/DeepSeek Harness.app/Contents/Resources/runtime/bin/node` |
| 许可证 | CC BY-NC-SA 4.0 | `LICENSE`、`backend/package.json` |
| DSH 状态 | Developer Preview，官方明确会有破坏性变更 | DSH 官方文档 |

### 3.2 约束

1. **单一写入者**：火宝后端是 SQLite 与媒体目录的唯一写入者；DSH 插件不直接打开火宝数据库。
2. **进程隔离**：DSH 运行在 Node 24；火宝后端继续运行在 Node 22 sidecar，避免原生模块 ABI 冲突。
3. **界面隔离**：火宝 UI 保持 Nuxt/Vue；DSH 客户端只增加轻量状态面板和入口，不重写 UI。
4. **文本 AI 统一**：火宝直接发起的文本模型调用必须经过 DSH LLM 桥；由 DSH Agent 承担的任务在 DSH 内部调用模型。两种路径都不得回落到火宝自己的文本模型，除非显式回退 Mastra。
5. **私有自用**：不对外分发；所有桥接只监听回环地址。
6. **DSH 预览版**：插件必须锁定 DSH 版本范围，并把 DSH 适配层与业务逻辑隔离，便于升级。

## 4. 决策记录

| 编号 | 决策 | 选择 | 理由 | 影响 |
|---|---|---|---|---|
| D1 | 集成形态 | DSH 主入口 + 火宝独立窗口 | 保留火宝成熟编辑体验，避免 UI 重写 | 不做 iframe；共享数据而非共享窗口 |
| D2 | 文本 AI | 全部走 DSH（Agent 内部或 LLM 桥） | 满足「LLM 用 DSH 内置」 | 火宝直接文本调用增加 `dsh-bridge`；文本模型配置降级为回退 |
| D3 | Agent | DSH Agent 桥 + 7 个角色 Preset | 满足「Agent 用 DSH 内置」 | Mastra 仅保留回退 |
| D4 | 任务触发 | 异步任务 | 改写/拆分/视频等耗时不一，同步会卡 UI | 火宝任务中心统一展示；插件提供状态查询与回调 |
| D5 | 模型分配 | 按角色 Preset 映射 | 不同角色对质量/速度要求不同 | 需要角色到 provider/model 的映射表 |
| D6 | Mastra | 默认 DSH + 回退 | 保证桥故障时火宝仍可用 | 任务记录必须标记 `engine` 与 `fallback_reason` |
| D7 | 分发 | 私有自用 | CC BY-NC-SA 不适合直接作为 MIT 插件分发 | 不发布、不复制火宝代码到公开插件 |
| D8 | 数据所有权 | 火宝后端唯一写库 | 避免双写与状态分裂 | DSH 只保存会话与任务映射 |
| D9 | 工具暴露 | 精选白名单 | 66 个工具 + 其他插件工具会造成噪声和误操作 | Preset 限制工具；昂贵操作仅 UI 触发 |
| D10 | 网络边界 | 仅回环 + 令牌 | 私有自用，降低暴露面 | 不监听 0.0.0.0，不开放公网 |

**「统一工作台」的定义**：DSH 是唯一主入口，负责对话、Agent、任务和插件；火宝是独立窗口，负责精细编辑和媒体预览。两者共享同一份 SQLite、媒体目录和任务状态；不是单窗口 iframe，也不是两套数据。

## 5. 总体架构

### 5.1 容器与职责

| 容器 | 职责 | 关键约束 |
|---|---|---|
| DSH Desktop | 主入口；内置 Chat/Session/LLM/Agent/Subagent/审批；加载 `dsh-moss-huobao` 与其他插件 | Node v24.21.0；不直接写火宝数据库 |
| `dsh-moss-huobao` 插件宿主 | LLM 桥、Agent 桥、工具/MCP、健康检查、任务映射、火宝面板 | 只监听回环；通过 HTTP 调火宝；通过 DSH 服务调 LLM/Agent |
| 火宝后端 | 唯一数据库写入者；业务服务；媒体适配器；任务队列；Mastra 回退 | Node 22 sidecar；文本 provider 指向 DSH 桥 |
| 火宝界面 | 精细编辑、媒体预览、任务中心、AI 按钮 | 独立窗口；不嵌入 DSH |
| 媒体执行层 | 图片/视频/TTS/ComfyUI/FFmpeg | 不变；由火宝队列调度 |
| 外部 DSH 插件 | browser/search/ssh/office 等 | 工具进入同一注册表；按 Preset 限制 |

### 5.2 逻辑分层

| 层 | 组件 | 说明 |
|---|---|---|
| 入口层 | DSH 内置 Chat + 火宝面板 | 用户从 DSH 发起对话、查看任务、打开火宝 |
| 编排层 | DSH Agent + Subagent + Agent Preset | 7 个角色；工具调用；会话与审批 |
| 桥接层 | LLM 桥 + Agent 桥 + 工具/MCP | 在 DSH 与火宝之间做协议转换、鉴权、幂等、状态映射 |
| 业务层 | 火宝 routes/services | 保持现有业务逻辑与校验 |
| 数据层 | SQLite + 媒体目录 + 任务队列 | 火宝唯一写入 |
| 生成层 | 图片/视频/TTS/ComfyUI/FFmpeg | 由火宝适配器与队列执行 |

### 5.3 数据流

1. 用户在 DSH 对话中提出任务，或点击火宝 UI 的 AI 按钮。
2. 火宝后端创建异步任务，写入 `sys_task`，标记 `engine=dsh`。
3. 火宝调用 DSH 插件的 Agent 桥，传入角色、任务类型、项目/剧集上下文和幂等键。
4. 插件按角色选择 Preset 与模型，创建 DSH Agent 会话，投递任务。
5. Agent 通过白名单工具读取火宝数据；写操作调用火宝 API 或 MCP 工具。
6. Agent 完成时调用统一的完成工具，插件记录结构化结果并回调火宝。
7. 火宝更新任务状态，任务中心展示结果；DSH 会话保留完整轨迹。
8. 桥不可用或失败时，火宝按策略回退 Mastra，并标记 `engine=mastra`。

## 6. 运行与部署

### 6.1 进程拓扑

| 进程 | 运行时 | 端口/地址 | 说明 |
|---|---|---|---|
| DSH Desktop | Node v24.21.0 | DSH 自身 UI/Agent 传输 | 主入口 |
| `dsh-moss-huobao` 宿主 | DSH 进程内 | **专用回环 HTTP 桥** `127.0.0.1:<OS 分配端口>` | 与 DSH UI 传输解耦；插件启动时监听，关闭时释放 |
| 火宝后端 | Node 22 sidecar | 复用桌面版并写 `runtime.json`；或固定 5679 | 唯一写库 |
| 火宝界面 | 浏览器/Electron 窗口 | 由火宝后端同源托管 | 独立窗口 |
| 火宝 MCP | 火宝后端进程内 | 127.0.0.1:5780 | 66 个工具 |
| 媒体服务 | 火宝适配器/ComfyUI | 由现有配置决定 | 不变 |

桥接传输说明：DSH 的 `ctx.webServer` 主要服务浏览器/桌面 UI，官方文档明确 Electron 渲染层可能通过 `file://` 与 IPC 访问，不能假定它对其他本地进程一定可达。因此 LLM 桥与 Agent 桥默认由插件启动**专用回环 HTTP 服务**，端口由 OS 分配并写入描述文件；`ctx.webServer` 只用于可选的 DSH 面板只读路由，不承担跨进程桥接。P0 仍需验证 DSH Desktop 下专用 HTTP 服务与 `ctx.llm`/`ctx.agents` 的可用性。

### 6.2 发现文件

| 文件 | 写入方 | 内容 | 用途 |
|---|---|---|---|
| `~/.dsh/moss-huobao-bridge.json` | DSH 插件 | 专用桥接地址（含端口）、令牌、插件版本、启动时间 | 火宝后端发现 DSH 桥 |
| 火宝 userData 下的 `runtime.json` | 火宝后端 | API 地址、MCP 地址、进程号、版本、数据目录、启动时间 | DSH 插件发现火宝 |
| `~/.dsh/moss-huobao-bridge/config.json` | DSH 插件/用户 | 角色到 provider/model 的映射、超时、并发、回退开关 | 运行期配置 |

文件权限要求：仅当前用户可读；令牌不得写入日志、不得出现在 argv 或前端可见位置。若 DSH 的 `ctx.webServer` 在目标运行形态下确认可被本地进程访问，可作为可选传输复用，但默认仍使用专用桥接服务。

### 6.3 启动顺序

1. 启动 DSH。插件加载，启动专用回环 HTTP 桥，生成/读取桥接令牌，写入 `moss-huobao-bridge.json`。
2. 启动火宝后端。读取 `moss-huobao-bridge.json`，写入 `runtime.json`，初始化 `dsh-bridge` 文本 provider。
3. DSH 面板健康检查通过，显示「火宝已连接」。
4. 用户从 DSH 面板打开火宝窗口，或手动打开火宝界面。

### 6.4 启动顺序异常

| 场景 | 行为 |
|---|---|
| 火宝先启动、DSH 后启动 | 火宝文本 AI 暂用 Mastra 回退；后台每 30 秒探测桥接文件与健康状态，恢复后切换 |
| DSH 重启 | 火宝将进行中的 DSH 任务标记为 `interrupted`；按策略重试一次，失败后回退 Mastra |
| 火宝重启 | DSH 插件保留任务映射；对已不存在的火宝任务标记 `orphaned`，不再回调 |
| 桥接文件缺失 | 火宝不启用 `dsh-bridge`；DSH 面板提示「未发现火宝」，不阻塞 DSH 其他功能 |

## 7. 模块设计

### 7.1 DSH 插件宿主

职责：

- 启动并维护专用回环 HTTP 桥：`/moss-huobao/health`、`/moss-huobao/llm/chat/completions`、`/moss-huobao/agent/tasks` 等；插件卸载时释放端口。
- 可选：通过 `ctx.webServer` 注册只读的面板状态路由，不承担跨进程桥接。
- 读取火宝 `runtime.json`，维持连接状态与版本兼容检查。
- 生成/轮换桥接令牌，写入 `moss-huobao-bridge.json`。
- 维护任务映射：DSH 任务 ID、DSH 会话 ID、火宝任务 ID、角色、状态、创建/完成时间。
- 注册 7 个 Agent Preset 与工具白名单。
- 注册火宝状态面板：连接状态、MCP 状态、最近任务、回退率、打开火宝按钮。
- 记录审计日志：任务派发、工具调用、模型、回退原因；不记录密钥。

插件不负责：

- 不直接打开火宝 SQLite。
- 不执行 FFmpeg、ComfyUI、TTS。
- 不替代火宝的业务校验与事务。
- 不暴露通用 API 代理；只暴露白名单工具和桥接端点。

### 7.2 LLM 桥

用途：承接火宝后端**直接发起**的文本模型调用，满足「全部文本 AI 走 DSH」。由 DSH Agent 承担的多步任务不经过这里，而是在 Agent 会话内直接调用 DSH 模型；两者共用同一套角色模型映射。

| 项 | 设计 |
|---|---|
| 端点 | `POST /moss-huobao/llm/chat/completions` |
| 协议 | OpenAI 兼容的 chat completions 形态；v1 非流式聚合，v2 可选 SSE |
| 鉴权 | `Authorization: Bearer <桥接令牌>`；仅回环 |
| 角色 | 请求携带 `role`：7 个 Agent 角色，以及 `sound_designer`、`translator`、`generic` 三个仅走 LLM 桥的角色 |
| 模型选择 | 按角色映射到 DSH provider/model；火宝不能任意指定模型，避免绕过成本与权限 |
| 请求字段 | `role`、`messages`、`temperature`、`maxTokens`、`responseFormat`、`timeoutMs`、`requestId`、`traceId` |
| 响应字段 | `id`、`model`、`choices[0].message.content`、`usage`、`engine=dsh`、`traceId` |
| 流式 | v1 聚合后返回；v2 支持 SSE，供长文本改写 |
| 失败 | 返回稳定错误码；火宝记录并决定重试/回退 |
| 审计 | 记录角色、模型、耗时、token 用量、请求 ID；不记录完整提示词正文，除非调试开关显式打开 |

角色与模型映射：

| 角色 | 质量档位 | 说明 |
|---|---|---|
| `script_rewriter` | 高质量 | 长文本改写，优先上下文与文风 |
| `extractor` | 快速/结构化 | JSON 输出，重试与校验优先 |
| `storyboard_director` | 高质量 | 导演口径、镜头语言 |
| `storyboard_breaker` | 高质量 | 拆分质量优先 |
| `prompt_generator` | 高质量 | 图片/视频提示词 |
| `storyboard_auditor` | 快速/校验 | 规则校验与修复建议 |
| `voice_designer` | 中等 | 音色与配音指令 |
| `sound_designer` | 中等 | 声音计划、环境音/配乐提示词；仅 LLM 桥 |
| `translator` | 快速 | 提示词翻译、语言转换；仅 LLM 桥 |
| `generic` | 中等 | 其他文本调用 |

实际 provider/model 由 DSH 设置页和插件配置决定；映射表只保存角色到模型引用的关系，不硬编码模型名。`sound_designer` 与 `translator` 不对应 Agent Preset，只用于火宝后端直接发起的文本调用。

### 7.3 Agent 桥

用途：让火宝 UI 的 AI 按钮和 DSH 对话都能触发 DSH Agent。

| 项 | 设计 |
|---|---|
| 创建任务 | `POST /moss-huobao/agent/tasks` |
| 查询任务 | `GET /moss-huobao/agent/tasks/{id}` |
| 取消任务 | `POST /moss-huobao/agent/tasks/{id}/cancel` |
| 完成回调 | 火宝 `POST /api/v1/dsh-bridge/tasks/{id}/complete`；失败回调 `/fail` |
| 鉴权 | 桥接令牌；回调带签名或同一令牌 |
| 幂等 | 请求必须携带 `idempotencyKey`；重复请求返回同一任务 |
| 角色 | 7 个 Agent 角色之一；`sound_designer`/`translator` 只走 LLM 桥，不走 Agent 桥 |
| 上下文 | `dramaId`、`episodeId`、`taskType`、`input`（原文、约束、已有 ID）、`contentLanguage` |
| 超时 | 按角色配置；文本任务默认 10 分钟，长任务由火宝队列承接，不占用 Agent turn |
| 完成信号 | Agent 必须调用 `huobao_task_complete` 工具提交结构化结果；插件据此完成回调。若 Agent 空闲仍未调用，插件提示一次；仍未调用则标记 `INCOMPLETE_OUTPUT` 并按失败处理 |
| 失败 | 插件返回稳定错误码；火宝按策略重试或回退 Mastra |
| 中断 | 用户取消或 DSH 重启时，插件标记任务；火宝更新为 `cancelled`/`interrupted` |

Agent 创建方式：

- 优先使用 DSH Agent Preset 选择角色（persona、技能、工具限制）。
- 若当前 DSH 版本的编程式创建不能直接选择 Preset，则在 `ctx.agents.create` 的 setup 阶段挂载同一套 persona、工具限制和技能，保持行为一致。
- 每个任务使用独立会话，会话 ID 写入任务映射；任务完成后会话保留，供 DSH 轨迹查看。
- P0 必须验证插件宿主可以调用 `ctx.agents.create`，并确认 DSH Desktop 已挂载会话持久化；若会话只在内存，任务轨迹无法跨重启查询，需要调整验收或改用持久化配置。
- 若任务量大导致 DSH 会话列表膨胀，v2 再评估“长驻调度 Agent + Subagent”的模型；v1 采用每任务独立会话。
- 后台任务默认不使用需要人工审批的工具；昂贵操作（视频批量、合片、导出）不暴露给 Agent，只允许火宝 UI 触发。

### 7.4 工具与 MCP

| 阶段 | 方案 | 说明 |
|---|---|---|
| P0 | 用户在 DSH 设置中手动配置 `mcp-client` 接火宝 MCP | 最快验证；66 个工具；Streamable HTTP + Bearer；插件只做健康检查，不修改用户配置 |
| P1 | Preset 工具白名单 | 只暴露 15–20 个核心工具；按角色限制；验证 DSH 是否支持按 Agent 限制 MCP 工具 |
| P2 | 原生工具补充 | 对高频工具用 `defineTool` 重写 schema、输出渲染与错误语义；必要时用独立 mcp-client 实例隔离工具集 |
| 后续 | 其他 DSH 插件工具 | browser/search/ssh/office 等按角色启用 |

MCP 令牌引导：P0 由用户从火宝设置页复制 MCP 地址与 Bearer token 到 DSH；P1 可由插件读取火宝 `/api/v1/mcp` 状态并提示配置，但不自动改写用户的 DSH profile。若 DSH 当前版本无法按 Agent 限制 MCP 工具，则改用独立 `mcp-client` 实例或原生工具，确保工具白名单有效。

工具白名单建议：

| 类别 | 允许 | 禁止 |
|---|---|---|
| 读 | 项目、剧集、分镜、角色、场景、道具、台词、任务状态、知识库检索 | 无 |
| 写 | 保存剧本、保存资产、保存/更新分镜、保存台词、绑定关系 | 删除项目/剧集、清空数据 |
| 媒体 | 入队图片/视频/配音任务、查询任务状态 | 批量删除、合片、导出、修改全局配置 |
| 系统 | 健康检查、版本查询 | `api_request`、`list_api_endpoints`、MCP 配置、远程访问、设置写入 |

知识库：新增只读工具 `huobao_knowledge_search`，按 Agent 分配的知识库范围检索；不把 8 个知识库全文注入系统提示，避免上下文膨胀。

工具设计原则：

- 写工具必须幂等，接受 `taskId`/`idempotencyKey`，重复调用不产生重复数据。
- 工具返回结构化结果与稳定错误码，不返回大段自由文本。
- 昂贵工具必须显式确认；后台 Agent 默认不可调用。
- 工具描述要说明前置条件、影响范围和副作用。
- 其他 DSH 插件工具按角色启用，不在所有角色中默认开放。

### 7.5 角色与 Preset

| Preset | 迁移来源 | 核心技能 | 工具范围 | 默认模型档 |
|---|---|---|---|---|
| `script_rewriter` | `workspace/prompts/script_rewriter*`、`skills/script-rewriter` | 小说改写、剧本格式、场景头、对白 | 读原文、读项目、保存剧本 | 高质量 |
| `extractor` | `workspace/prompts/extractor*`、`skills/extractor` | 角色/场景/道具提取、去重、关联 | 读剧本、读已有资产、保存资产 | 快速/结构化 |
| `storyboard_director` | 导演提示词与知识库 | 导演口径、镜头语言、场景契约 | 读剧本/资产、读分镜、保存分镜 | 高质量 |
| `storyboard_breaker` | `workspace/prompts/storyboard_breaker*`、`skills/storyboard-breaker` | 四段式拆分、节拍、边界契约 | 读剧本、读拆分方案、保存分镜 | 高质量 |
| `prompt_generator` | `workspace/prompts/prompt_generator*`、`skills/prompt-generator` | 图片/视频提示词、角色设定图、版式约束 | 读资产/分镜、保存提示词 | 高质量 |
| `storyboard_auditor` | `workspace/prompts/storyboard_auditor*`、`skills/storyboard-auditor` | 规则校验、连贯性、修复建议 | 读分镜/资产、写校验结果 | 快速/校验 |
| `voice_designer` | `workspace/prompts/voice_designer*`、`skills/voice-designer` | 音色、情绪、配音指令 | 读台词/角色、保存配音指令 | 中等 |

Preset 只负责 persona、技能与工具组合；模型由 Agent 桥在创建 Agent 时通过 `agentOptions` 传入，二者通过 `role` 关联。这样换模型不需要改 Preset，换技能/工具不需要改模型映射。

技能迁移：

- 现有 `workspace/skills` 为 Markdown，保留四语言版本。
- DSH 使用 `ctx.skills` 与 `skill-filesystem` 发现技能；插件优先把火宝技能目录映射为 DSH 技能源。若当前 DSH 版本不支持外部目录，再复制到 DSH 用户技能目录，并记录来源哈希避免静默漂移。
- 技能正文保持中文/英文/日文/韩文变体；按内容语言选择。
- 知识库（`backend/workspace/knowledge`）通过 `huobao_knowledge_search` 只读工具按需检索；不直接写入 DSH 会话，也不复制全文。

## 8. 接口契约

### 8.1 通用约定

| 项 | 约定 |
|---|---|
| 地址 | 仅 `127.0.0.1`；使用插件启动的专用回环 HTTP 桥，地址由 `moss-huobao-bridge.json` 下发；不依赖 DSH Web 服务。下文的 `/moss-huobao/*` 路径均相对于 `bridgeBaseUrl` |
| 鉴权 | `Authorization: Bearer <桥接令牌>`；火宝 MCP 使用现有 Bearer |
| 内容类型 | `application/json; charset=utf-8` |
| 请求 ID | 每个请求携带 `requestId`；跨进程传递 `traceId` |
| 超时 | LLM 默认 120 秒；Agent 任务按角色配置；HTTP 客户端必须有超时 |
| 幂等 | 写任务必须携带 `idempotencyKey`；重复请求返回既有结果 |
| 错误 | 统一错误码 + 可读消息；不返回堆栈或密钥 |

### 8.2 LLM 桥

`POST /moss-huobao/llm/chat/completions`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `role` | string | 是 | 角色枚举；决定模型映射 |
| `model` | string | 否 | 兼容字段；桥不采用，仅记录审计；模型由角色映射决定 |
| `messages` | array | 是 | system/user/assistant 消息；内容为文本 |
| `temperature` | number | 否 | 采样温度 |
| `maxTokens` | number | 否 | 输出上限 |
| `responseFormat` | string | 否 | `text` 或 `json` |
| `timeoutMs` | number | 否 | 覆盖默认超时 |
| `requestId` | string | 是 | 火宝请求 ID |
| `traceId` | string | 否 | 跨进程追踪 ID |

响应：

| 字段 | 说明 |
|---|---|
| `id` | 桥接响应 ID |
| `model` | 实际使用的 DSH 模型标识 |
| `choices` | 兼容 chat completions 的候选结果 |
| `usage` | token 用量（若 DSH 提供） |
| `engine` | 固定 `dsh` |
| `traceId` | 原样返回 |

错误码：

| 错误码 | 含义 | 火宝动作 |
|---|---|---|
| `BRIDGE_UNAVAILABLE` | DSH 桥未加载/无健康连接 | 回退 Mastra |
| `MODEL_NOT_CONFIGURED` | 角色未映射模型 | 回退或提示配置 |
| `AUTH` | 令牌无效 | 不重试，提示检查桥接 |
| `RATE_LIMIT` | 上游限流 | 退避重试，必要时回退 |
| `TIMEOUT` | 请求超时 | 重试一次，再回退 |
| `INVALID_REQUEST` | 参数不合法 | 不重试，记录错误 |
| `UPSTREAM_ERROR` | 模型/适配器错误 | 重试，再回退 |
| `INVALID_OUTPUT` | JSON/结构校验失败 | 重试一次，再回退 |
| `INCOMPLETE_OUTPUT` | Agent 未提交完成结果 | 重试一次，再回退 |
| `BUSY` | 桥接队列已满 | 退避，必要时回退 |

### 8.3 Agent 桥

`POST /moss-huobao/agent/tasks`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `idempotencyKey` | string | 是 | 火宝任务幂等键 |
| `huobaoTaskId` | number | 是 | 火宝 `sys_task` ID |
| `role` | string | 是 | 7 个角色之一 |
| `taskType` | string | 是 | `rewrite`/`extract`/`split`/`prompt`/`audit`/`voice`/`sound` 等 |
| `dramaId` | number | 是 | 项目 ID |
| `episodeId` | number | 否 | 剧集 ID |
| `input` | object | 是 | 任务输入：原文、约束、已有 ID、语言等 |
| `contentLanguage` | string | 否 | `zh`/`en`/`ja`/`ko` |
| `callbackUrl` | string | 是 | 火宝回调地址 |
| `deadlineMs` | number | 否 | 任务截止时间 |
| `traceId` | string | 否 | 追踪 ID |

响应：

| 字段 | 说明 |
|---|---|
| `dshTaskId` | 插件侧任务 ID |
| `dshSessionId` | DSH 会话 ID |
| `status` | `accepted` |
| `acceptedAt` | 接受时间 |

`GET /moss-huobao/agent/tasks/{id}` 返回：

| 字段 | 说明 |
|---|---|
| `dshTaskId` | 插件侧任务 ID |
| `huobaoTaskId` | 火宝任务 ID |
| `status` | `queued`/`running`/`succeeded`/`failed`/`cancelled`/`interrupted` |
| `result` | 结构化结果（成功时） |
| `error` | 错误码与消息（失败时） |
| `fallbackSuggested` | 是否建议火宝回退 |

## 9. 任务状态机与幂等

### 9.1 状态

下表是 `bridge_status` 的细分状态，不直接写入 `sys_task.status`。`sys_task.status` 继续使用现有任务中心的粗粒度值（`processing`/`completed`/`failed`），避免破坏既有筛选、删除、重试和 UI 判断。

| 状态 | 含义 | 终态 |
|---|---|---|
| `queued` | 已创建，等待派发 | 否 |
| `dispatched` | 已提交给 DSH 桥 | 否 |
| `running` | DSH Agent 执行中 | 否 |
| `needs_attention` | 等待用户审批/补充信息 | 否 |
| `succeeded` | DSH 成功 | 是 |
| `failed` | DSH 失败 | 是 |
| `cancelled` | 用户取消 | 是 |
| `interrupted` | DSH 重启导致中断 | 是 |
| `orphaned` | 火宝任务已不存在，插件停止回调 | 是（插件侧） |
| `fallback_running` | 正在用 Mastra 回退 | 否 |
| `fallback_succeeded` | 回退成功 | 是 |
| `fallback_failed` | 回退失败 | 是 |

`sys_task.status` 映射：

| `bridge_status` | `sys_task.status` | 任务中心展示 |
|---|---|---|
| `queued`/`dispatched`/`running` | `processing` | 运行中 |
| `needs_attention` | `processing` | 待处理（附提示） |
| `succeeded`/`fallback_succeeded` | `completed` | 成功 |
| `failed`/`fallback_failed`/`interrupted`/`cancelled`/`orphaned` | `failed` | 失败/中断（附错误码） |

### 9.2 允许的迁移

| 从 | 到 | 条件 |
|---|---|---|
| `queued` | `dispatched` | 桥健康检查通过 |
| `queued` | `fallback_running` | 桥不可用且回退开启 |
| `dispatched` | `running` | 插件接受任务 |
| `dispatched` | `failed` | 插件拒绝/参数错误 |
| `running` | `needs_attention` | Agent 需要审批或补充信息 |
| `needs_attention` | `running`/`cancelled`/`failed` | 用户处理后继续/取消/拒绝 |
| `running` | `succeeded` | 收到完成工具结果 |
| `running` | `failed` | 收到失败结果/超时 |
| `running` | `cancelled` | 用户取消 |
| `running` | `interrupted` | DSH 重启 |
| `running` | `fallback_running` | 可重试失败且回退开启 |
| `running`/`fallback_running` | `orphaned` | 火宝任务被删除或不存在 |
| `fallback_running` | `fallback_succeeded`/`fallback_failed` | Mastra 结果 |

### 9.3 幂等

- `idempotencyKey` 由火宝生成：项目 + 剧集 + 任务类型 + 输入哈希 + 手动运行标识。
- 同一 key 在 `queued`/`dispatched`/`running`/`succeeded` 时返回既有任务，不重复派发。
- 失败任务允许用户显式重试；重试生成新 key，旧任务保留。
- Agent 写工具接受 `taskId`；重复调用不重复写。
- 回调按 `dshTaskId` 幂等：重复回调只更新一次终态。

## 11. 安全与权限

| 项 | 设计 |
|---|---|
| 网络 | 专用桥接服务与火宝 API 仅监听回环；不监听 0.0.0.0；不开放公网 |
| 令牌 | 插件生成桥接令牌，文件权限 0600；定期轮换；旧令牌立即失效 |
| MCP | 沿用火宝 Bearer token；P0 由用户手动配置到 DSH，P1 使用凭据引用与 `expandTemplates`，不写入明文配置 |
| 工具权限 | Preset 白名单；禁止通用 API 代理；昂贵操作仅 UI 触发 |
| 审批 | 后台任务默认不触发需要人工审批的工具；需要审批时任务进入 `needs_attention` 并通知 |
| 数据 | DSH 不直接打开火宝 SQLite；火宝不把数据库路径暴露给插件 |
| 日志 | 不记录令牌、API Key、完整提示词正文；错误信息脱敏 |
| 审计 | 记录任务、角色、模型、工具、耗时、回退原因；保留时间可配置 |
| 分发 | 私有自用；不发布；不把火宝代码复制到公开 MIT 插件 |

## 12. 失败与回退

| 场景 | 处理 |
|---|---|
| DSH 未启动/桥文件缺失 | 火宝使用 Mastra 回退；标记 `engine=mastra`、`fallback_reason=bridge_unavailable` |
| LLM 桥 401/403 | 不重试；提示检查令牌；任务失败或回退 |
| LLM 桥限流 | 指数退避重试；超过阈值回退 |
| LLM 超时 | 重试一次；仍失败回退 |
| JSON/结构校验失败 | 让 Agent 修复一次；仍失败回退 |
| Agent 未调用完成工具 | 提示一次；仍无完成结果则标记 `INCOMPLETE_OUTPUT`，重试一次后失败/回退 |
| Agent 工具失败 | Agent 可在会话内重试；超过重试次数标记失败 |
| Agent 等待审批 | 任务标记 `needs_attention`；通知火宝；不自动回退 |
| DSH 重启 | 进行中任务标记 `interrupted`；火宝可选择重试或回退 |
| 火宝重启 | 插件标记 `orphaned`；停止回调；火宝任务中心显示中断 |
| 回退配置缺失 | 没有可用的旧文本配置时，回退直接标记 `fallback_failed`，提示先在火宝设置中配置回退模型 |
| 回退也失败 | 任务 `fallback_failed`；保留错误与 traceId，供人工排查 |
| 严格模式 | `DSH_REQUIRED=true` 时禁止回退；桥不可用直接失败 |

回退只针对文本任务；媒体任务不受影响。

## 13. 性能与并发

| 项 | 设计 |
|---|---|
| 文本并发 | 默认每个角色 2 个并发；总并发可配置；避免上游限流 |
| Agent 并发 | 默认最多 2–4 个后台 Agent；与火宝任务队列解耦 |
| 长任务 | 视频/合片/导出由火宝队列执行；Agent 只入队和查询，不阻塞 |
| 超时 | LLM 120 秒；文本 Agent 10 分钟；长任务按角色配置 |
| 上下文 | 使用 DSH 会话与压缩；火宝长剧本按段落/场景切分，避免超上下文 |
| 输出 | 设置 `maxTokens`；JSON 输出做大小限制与截断保护 |
| 背压 | 桥接队列满时返回 `BUSY`；火宝退避或回退 |
| 资源 | DSH 进程不做媒体转码；火宝 sidecar 负责 CPU/GPU 密集任务 |

## 16. 验收标准

### 16.1 P0 验收

- 使用隔离 SQLite 副本或专用测试项目，不写生产数据；记录测试项目/剧集 ID。
- LLM 桥：一次剧本改写成功；响应 `engine=dsh`，`model` 来自 DSH；日志确认未调用外部文本 API。
- Agent 桥：一次测试任务读取项目、写入测试字段、回读成功；DSH 会话 ID 可查，工具调用轨迹完整。
- MCP：DSH `tools/list` 能看到火宝工具；至少一个工具调用成功；记录工具数量。
- 传输：专用回环 HTTP 桥可被火宝后端访问；若 DSH Desktop 下不可达，P0 失败并切换传输方案。
- 数据：火宝 SQLite 未出现重复写入；任务记录包含 `engine=dsh`、`bridge_status`、`dsh_task_id`。

### 16.2 P1 验收

- 7 个 Agent 角色 + 6 个直接文本调用方（`h3-prompt`、`line-performance`、`novel-import`、`sound-plan-audio`、`soundscape-compiler`、`voice-design`）全部走 DSH 或 LLM 桥。
- 固定剧集对比 DSH 与 Mastra 输出，按下表判定；不满足任一项即不通过。

| 任务 | 通过标准 |
|---|---|
| 剧本改写 | 场景/角色/关键对白无丢失；场景头格式正确；字数在旧版 ±20% 内；语言正确 |
| 资产提取 | JSON 可解析；角色/场景/道具覆盖剧本；同名去重；必填字段齐全 |
| 分镜拆分 | 覆盖全部剧情；镜号连续；台词不丢；镜数在方案允许范围；动作/时长字段完整 |
| 提示词生成 | 必填字段齐全；无禁用内容；语言/风格符合约束；角色/场景绑定正确 |
| 分镜校验 | 输出可解析；问题定位到具体镜号；不产生规则外的新分镜；修复建议可执行 |
| 声音计划/音色 | JSON 可解析；cue/音色字段齐全；时间窗口合法；语言正确 |
| 直接文本调用 | 返回非空文本；JSON 可解析；错误码符合契约；不调用外部文本 API |

- 关闭 DSH 桥后，Mastra 回退成功；任务标记 `engine=mastra`、`fallback_reason` 正确；回退配置缺失时给出明确错误。
- JSON 输出校验失败时能自动修复或回退。
- 验收证据：任务 ID、DSH 会话 ID、模型标识、耗时、token 用量、输出 diff、日志片段。

### 16.3 P2 验收

- 7 个角色都能通过 DSH Agent 执行；任务中心显示异步进度；`bridge_status` 与 `sys_task.status` 映射正确。
- 昂贵操作（视频/合片/导出）未被 Agent 自动触发；审批场景进入 `needs_attention` 并能恢复。
- DSH 重启、火宝重启、桥断开三种故障均有明确状态与恢复路径。
- 工具白名单生效：禁止工具不可见/不可调用；MCP 工具限制方案已验证。
- 完成工具缺失时能触发 `INCOMPLETE_OUTPUT` 并按策略重试/回退。

### 16.4 P3 验收

- 从 DSH 面板一键打开火宝窗口；状态卡显示已连接。
- DSH 对话与火宝 UI 共享同一项目和任务；数据一致。
- 同一会话可调用其他 DSH 插件工具（至少一个）且不破坏火宝工具。

### 16.5 P4 验收

- 令牌轮换、健康检查、重连、幂等、并发限制均有测试。
- 升级 DSH 小版本后，P0–P3 回归通过。
- 操作文档、故障排查、回滚步骤齐全。

## 17. 分期计划

### P0 桥接验证

- 目标：验证 LLM 桥、Agent 桥、MCP 三条链路可行，并确认桥接传输。

- 风险：审批阻塞、Agent 超时、完成工具未调用、工具副作用；需要严格白名单与幂等。

### P3 统一入口

- 目标：DSH 成为主入口，火宝作为独立编辑窗口。
- 范围：火宝面板、状态卡、一键打开、其他 DSH 插件工具、MCP/原生工具精选。
- 产出：一个入口的日常工作流；共享数据验证；窗口打开方式确定。
- 依赖：P2 通过；火宝窗口启动方式确定。
- 验收：见 16.4。
- 风险：窗口打开方式（浏览器/Electron）、端口发现、DSH 宿主是否提供打开外部窗口的能力；P3 前先验证。

### P4 加固

- 目标：达到私有自用的稳定状态。
- 范围：安全、重连、令牌轮换、幂等、并发、回归、文档。
- 产出：验收报告、故障排查手册、回滚手册。
- 依赖：P3 通过。
- 验收：见 16.5。
- 风险：DSH 预览版升级破坏兼容；需要适配层和回归用例。

## 20. 术语

| 术语 | 含义 |
|---|---|
| DSH | DeepSeek Harness，Cordis 驱动的插件化 Agent Harness |
| `dsh-moss-huobao` | 本项目 DSH 插件包名；源码目录为 `app/dsh` |
| 桥接令牌 | DSH 插件生成、火宝后端使用的本地回环鉴权令牌 |
| LLM 桥 | 火宝文本调用到 DSH `ctx.llm` 的本地 HTTP 适配层 |
| Agent 桥 | 火宝异步任务到 DSH Agent 会话的本地 HTTP 适配层 |
| Preset | DSH 的角色化 Agent 组合：persona、技能、工具；模型由 Agent 桥按角色映射 |
| 回退 | DSH 不可用时火宝使用 Mastra 原路径执行 |
| 唯一写入者 | 火宝后端是 SQLite/媒体目录的唯一写入进程 |
| 幂等键 | 防止重复派发/重复写入的任务唯一标识 |

### 21.4 真机验证前置条件

1. 用户批准在 DSH profile 中以 `link:` 方式安装 `app/dsh` 并重启 DSH；安装前先在 `app/dsh` 执行 `npm install && npm run build`，确保 `lib/` 存在。

3. 可选：在 DSH 配置 `mcp-client` 连接火宝 MCP（127.0.0.1:5780 + Bearer）。
4. 启动火宝后端；在设置页「DSH 桥接」打开开关，或设置 `DSH_BRIDGE_ENABLE=1`；确认 `data/runtime.json` 存在。
5. 用隔离测试项目执行改写、Agent 任务、工具读写与回退验证，记录任务 ID、DSH 会话 ID、模型标识和日志。
