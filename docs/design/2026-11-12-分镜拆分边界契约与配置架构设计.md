## 0. 一页结论

当前链式插件只完成了“编排层”：运行有链 key、模板、参数、快照和步骤 trace，但拆分业务规则仍散在提示词、保存工具和校验器里，步骤开关与规则包大多只是展示。第 9 集第 3/4 镜的失败不是单镜修补问题，而是**预拆阶段没有镜头边界契约**。

本设计把分镜拆成三层：

1. **ShotPlan（镜头计划）**：结构化镜头与台词原子单元，不写最终画面文案。
2. **BoundaryContract（边界契约）**：相邻镜的续接、过渡词、人物左右、轴线、动作端点。
3. **ShotRender（镜头渲染）**：只把 ShotPlan 渲染成 description 和 video_prompt，不重新决定边界。

再配一套**可执行规则包**和**配置注册表**：每个配置必须声明消费步骤和规则包，没有消费者的配置不进入生效区。

### 已确认口径

| 决策 | 选择 |
|---|---|
| 台词与边界 | **台词原子化 + 过渡词单次承接** |
| 配置化范围 | **只重构分镜链路配置**；其他工作流保持不变，全页审计并标注用途 |
| 六套方案 | **保留三套主力，其余归档** |
| 未消费配置 | **删除或隐藏**，不把预留项伪装成生效项 |
| 失败镜 | **显式跳过 + 可选自动阈值**；跳过镜头标记但允许生成 |

## 1. 现状流程与故障复盘

### 1.1 当前流程

| 阶段 | 现在做什么 | 实际约束 |
|---|---|---|
| 分块 | 按字数/场次切块 | 只保证长度，不保证说话行为完整 |
| 预拆骨架 | 导演模型按自由节拍切镜，保存 `source_excerpt` | 只校验摘录逐字、6–15 秒、场景/资产绑定 |
| 骨架门禁 | 校验单块摘录覆盖率与整集下限 | 不校验台词原子性、边界连续性、重复内容 |
| 逐镜修补 | 模型根据骨架、前镜、后镜、完整场次写 description/video_prompt | 同时承担“决定边界”和“渲染画面”两个职责 |
| 逐镜校验 | 单位合同、台词完整、相邻镜合同 | 到这一步才发现越界、重复、左右翻转 |
| 声音设计 | 全部普通分镜通过后按声音单元设计 | 跳过/人工通过策略尚未落地 |

### 1.2 第 9 集实际失败数据

| 镜头 | 骨架摘录 | 成稿结果 |
|---|---|---|
| 第 3 镜 | 结束于“贾婆子眼睛一亮，急忙高声唱喝。” | 成稿自行补了“@贾婆子扯着嗓子唱喝：「呦！」” |
| 第 4 镜 | 开始于“贾婆子：（热情地）呦！六婶起得可是够早……” | 成稿完整重复“呦！六婶起得可是够早……” |
| 第 3/4 镜画面 | 第 3 镜：左六婶、右贾婆子 | 第 4 镜：左贾婆子、右六婶 |

这次失败包含三类问题：

1. **校验器误报一**：剧本格式 `角色：（情绪）台词` 没有引号，校验器不把它当台词，于是把第 4 镜的真实台词判成“自行加台词”。
2. **校验器误报二**：第 4 镜提示词把一句台词拆到 `0-4 秒` 与 `4-9 秒`，第二段前的“催促：”不满足说话人判定，校验器只看到前半句，误报“提示词缺台词”。
3. **真实问题**：第 3/4 镜同场人物左右翻转；同时预拆把“说话提示”和台词切到了两镜，第 3 镜补开头、第 4 镜重复开头。

### 1.3 为什么链式插件没有拦住

- `skeleton-split` 插件只负责注入方案/知识/工具，不拥有边界规则。
- `skeleton-gate` 只查摘录覆盖率，不查说话行为是否完整。
- `save_storyboard_skeletons` 没有相邻骨架的边界校验。
- 步骤开关、规则包、部分参数没有真正的执行消费者。
- 结果：错误骨架进入修补阶段，模型在“删台词/保留台词”的矛盾要求中耗尽 3 次重试。

## 2. 根因架构诊断

| 根因 | 表现 | 后果 |
|---|---|---|
| 缺少 ShotPlan 中间表示 | 骨架只是摘要，边界不是结构字段 | 模型每次修补重新猜边界 |
| 计划与渲染职责混合 | 修补模型同时决定边界和画面文案 | 边界错误无法在计划层被拦住 |
| 源文本双源 | 骨架摘录与完整小说/场次同时喂给模型，但校验只用摘录 | 模型补出摘录外台词，校验判自创 |
| 台词解析不统一 | 引号台词、剧本格式台词、短台词分散判定 | 同一句台词时而过、时而不认 |
| 规则散落 | 单位、台词、边界、左右、覆盖率各写一处 | 规则互相矛盾，难以配置 |
| 链式插件只是外壳 | 步骤开关/规则包只展示不执行 | 设置页看起来可配，实际不生效 |
| 预拆门禁只查覆盖 | 说话提示、过渡词、重复开头不在门禁内 | 3/4 镜类错误直接进入修补 |
| 失败太晚 | 到逐镜校验才报错，重试只修渲染 | 无法修复计划层错误 |

## 3. 目标架构

### 3.1 三层对象

| 对象 | 职责 | 不负责 |
|---|---|---|
| ShotPlan | 决定镜头边界、场景、人物、动作端点、时长、台词原子单元、过渡词 | 写最终 description/video_prompt |
| BoundaryContract | 表达相邻镜的续接关系、过渡词归属、左右/轴线/地标侧、动作端点 | 决定台词内容 |
| ShotRender | 把 ShotPlan 渲染成 description 与 video_prompt | 重新拆镜、重新分配台词、改变边界 |

### 3.2 新流程

| 步骤 | 输入 | 输出 | 门禁 |
|---|---|---|---|
| source-segment | 剧本/小说、分块 | 场次、节拍、说话行为、动作行为 | 场景/说话行为识别完整 |
| shot-plan | 场次与节拍 | ShotPlan[] + BoundaryContract[] | 台词原子、边界连续、左右轴线常量、时长/容量 |
| plan-gate | ShotPlan + 边界契约 | 通过或结构化问题 | 覆盖、台词原子、无重复、无断层、场景常量 |
| shot-render | 单个 ShotPlan + 边界契约 | ShotRender（description/video_prompt） | 单位合同、台词完整、渲染与计划一致 |
| render-gate | ShotRender + 计划 | 通过或结构化问题 | 渲染不得改变计划边界/台词/左右/轴线 |
| sound-plan / sound-gate | 通过或跳过的镜头 | 声音计划 | 覆盖、同轨、单元 BGM、native/post |

关键原则：

- **计划层决定边界，渲染层只负责表达。**
- **台词是原子单元**：说话提示与整句台词同镜；过长只在标点处拆，下一镜从续接文字开始，不重复开头。
- **过渡词单次承接**：允许过渡词，但只能出现在上一镜末尾或下一镜开头之一；下一镜必须从上一镜尾状态继续。
- **场景常量先定后传**：同一场第一镜确定画面左右、地标侧、轴线，后续镜沿用；换场才允许重置。
- **规则先于重试**：计划门禁不通过，不允许进入渲染；渲染门禁不通过，只修渲染，不重新拆镜。

## 4. 数据契约

### 4.1 ShotPlan

| 字段 | 说明 |
|---|---|
| shot_number | 全集群内稳定编号 |
| scene_id / location | canonical 场景 |
| source_range | 本镜覆盖的原文起止位置 |
| source_excerpt | 逐字摘录，必须完整包含台词原子单元 |
| cast_on_screen | 画内人物 |
| action_start / action_end | 动作起点/终点 |
| duration_seconds | 6–15 秒 |
| coverage_type | 建立/主镜/双人/过肩/反应/插入/过渡等 |
| speech_segments | 说话人、台词原文、原文位置、顺序 |
| transition_in / transition_out | 本镜进入/退出方式 |
| boundary_out | 本镜尾状态，供下一镜承接 |
| sides_axis_snapshot | 本镜画面左右、地标侧、轴线；同场沿用 |
| status | planned / validated / skipped / manual |

### 4.2 BoundaryContract

| 字段 | 说明 |
|---|---|
| from_shot / to_shot | 相邻镜编号 |
| type | 台词续接 / 动作承接 / 反应 / 场景切换 / 时间跳 |
| from_end_state | 上一镜尾动作、视线、台词尾字 |
| to_start_state | 下一镜起动作、视线、续接字 |
| transition_word | 可选；只能单侧出现 |
| duplicate_guard | 禁止下一镜重复上一镜开头 |
| sides_axis_carry | 同场左右/地标侧/轴线继承 |
| validation | 通过/问题/证据 |

### 4.3 ShotRender

| 字段 | 说明 |
|---|---|
| plan_id / plan_version | 绑定 ShotPlan，禁止脱离计划另起边界 |
| description | 单镜连续画面 |
| video_prompt | 固定四区 |
| contract_snapshot | 信息头/调度/时间帧/负面约束 |
| status | rendered / validated / skipped / manual |
| issues | 结构化问题与证据 |

### 4.4 结构化问题

问题必须带 `layer`（plan/render）、`code`、`shot_number`、`boundary`（如涉及）、`severity`、`evidence`、`fixability`。计划层问题不得用渲染重试来掩盖。

## 5. 配置注册表

### 5.1 原则

- 每个配置必须声明：`key`、类型、默认值、范围、适用步骤、消费规则包、状态。
- 状态分为：**生效**、**预留**、**仅其他工作流**、**已归档**。
- 没有消费者的配置不进入生效区；预留项默认折叠，不参与运行。
- 规则包必须是可执行校验；只展示不执行的规则包从设置页移除。
- 每次运行快照记录实际读取的配置、规则包版本和方案版本。

### 5.2 分镜链路配置

| 配置 | 消费步骤 | 状态 |
|---|---|---|
| 镜头时长范围 6–15 秒 | shot-plan / plan-gate / render-gate | 生效，范围受锁定上下限约束 |
| 台词原子化 | shot-plan / plan-gate | 生效，锁定 |
| 过渡词策略（单侧、允许类型） | shot-plan / plan-gate | 生效，可配置 |
| 前后镜上下文数量 | shot-render | 生效，可配置 |
| 摘录拒收/警告阈值 | plan-gate | 生效，可配置 |
| 整集覆盖下限与门禁 | plan-gate | 生效，可配置 |
| 逐镜/块级重试次数 | shot-render / plan-gate | 生效，可配置 |
| 自动跳过阈值 | shot-render | 生效，0 表示关闭 |
| 拆分预设 | shot-plan | 生效，三套主力 |
| 步骤知识绑定 | shot-plan / shot-render / sound-plan | 生效 |
| 规则包启停 | plan-gate / render-gate / sound-gate | 仅非锁定规则可配 |
| 语义复检 | 未实现 | 隐藏 |
| 自动修复 | 未实现 | 隐藏 |
| 单集调用上限 | 未实现 | 隐藏 |
| 人工通过（旧） | 未实现 | 删除，改为显式跳过 |
| 旧检验策略 | 旧批量检验 | 已下线，不再显示 |

### 5.3 设置页重组

| 区域 | 内容 |
|---|---|
| 分镜流水线 | 模板、拆分预设、计划策略、边界策略、规则包、知识绑定、测试运行、运行记录 |
| 分镜方案 | 三套主力的结构化字段；归档方案只读 |
| Agent 配置 | 导演/检验/提示词/声音等提示词与 Skill；知识库按步骤绑定 |
| 其他工作流 | AI 服务、配音、小说、风格、存储、MCP、手机接力、任务队列、关于更新；标注“仅其他工作流” |

设置页增加“配置影响预览”：选择模板/方案后，显示本次运行实际读取的配置、锁定项、规则包和知识列表。预留项折叠到“未生效/预留”，不伪装成可用。

### 5.4 配置校验

- 启动或 CI 校验：每个生效配置必须有消费者；没有消费者的配置不允许出现在生效区。
- 每个规则包必须有执行器；没有执行器的规则包只能显示为“预留”。
- 方案字段必须通过 schema 校验；旧字段缺失时给出迁移提示，不静默回退。

## 6. 三套主力方案

### 6.1 保留

| 方案 | 定位 | 结构化重点 |
|---|---|---|
| 标准短剧 | 默认生产 | 6–15 秒单镜、台词原子、边界承接、场景常量 |
| 爆款钩子 | 竖屏强钩子 | 6–12 秒、开场冲突、段尾钩子；仍受台词原子与边界契约约束 |
| H3 紧凑 | 本地 H3/短段 | 6–8 秒、单动作、少调度；仍受台词原子与边界契约约束 |

### 6.2 归档

- 原「爆款钩子节拍」基础版：合并到「爆款钩子」。
- 原「导演分镜表」：归档，已有剧集映射到标准，并提示重选。
- 原「快切预告」：归档，已有剧集映射到 H3 紧凑，并提示重选。

归档方案保留历史行，不出现在新选择列表；已有剧集下次拆分前提示重新选择。归档不做删除，避免历史数据失去解释。

### 6.3 方案与硬约束的关系

- 方案只控制风格、节奏、覆盖偏好和镜头取舍。
- 台词原子化、边界承接、左右/轴线、固定四区、6–15 秒等硬约束由平台锁定，方案不可覆盖。
- 方案文本不再包含“段内 2–4 个子镜头”等旧表述；全部改为结构化字段和短风格指令。

## 7. 规则包

| 规则包 | 层 | 锁定 | 可配置 |
|---|---|---|---|
| source-coverage | plan | 摘录逐字/覆盖 | 拒收/警告阈值、覆盖下限 |
| speech-atomicity | plan | 说话提示与台词同镜 | 无 |
| boundary-continuity | plan | 无断层、无重复开头、过渡词单侧 | 过渡词类型/位置 |
| scene-geometry | plan/render | 同场左右、地标侧、轴线 | 换场重置策略 |
| unit-contract | render | 单机位/单主体/连续动作/6–15 秒/四区 | 时长范围受锁定 |
| dialogue-integrity | render | 台词逐字、发声动作有台词、无自创 | 无 |
| render-plan-consistency | render | 渲染不得改变计划边界/台词 | 无 |
| sound | sound | 覆盖、同轨、单元 BGM、native/post | 重试次数、交付策略 |

规则包由步骤插件显式引用；引擎执行对应规则；启停非锁定规则必须真实改变行为。锁定规则不允许关闭。

## 8. 失败、跳过与完成标记

- 状态：planned / rendered / validated / manual / skipped / failed。
- 失败达到重试上限：
  - 默认停在该镜，进入人工处理；
  - 可选手动“跳过并标记问题”，填写原因后继续；
  - 可选自动跳过阈值：连续失败达到 N 次后自动跳过并记录，0 表示关闭。
- 跳过的镜头保留草稿，允许生成视频，但必须在分镜列表、完成报告和生成界面显示问题标记。
- 运行完成后输出问题清单：跳过镜头、人工处理镜头、规则问题、声音问题；不把跳过当作通过。
- 声音设计可以在“全部普通分镜为 validated 或 skipped”后执行；跳过镜头仍进入声音单元，但带问题标记。

## 9. 迁移与实施

本设计一次定清契约，实施分阶段，但每个阶段都以完整契约为目标，不做临时补丁。

| 阶段 | 目标 | 出口 |
|---|---|---|
| P0 配置审计 | 设置页所有分镜配置标记消费者/状态；隐藏死配置；归档三套方案 | 设置页不再出现无效开关 |
| P1 计划层 | 引入 ShotPlan / BoundaryContract / 结构化问题；迁移骨架字段 | 计划层可独立校验，3/4 镜类边界错误在计划阶段被拦住 |
| P2 计划门禁 | 台词原子、边界连续、场景常量、覆盖/时长/容量规则 | plan-gate 拒绝说话提示跨镜、重复开头、左右翻转 |
| P3 渲染层 | shot-render 只渲染计划；render-gate 校验渲染忠实度 | 渲染不再重新决定边界；误报消除 |
| P4 链与配置 | 插件 manifest 声明输入/输出/规则/配置；设置页配置注册表 | 步骤开关、规则包、参数都有真实消费者 |
| P5 失败策略 | 显式跳过、自动阈值、完成问题清单 | 跳过可继续，完成后可定位所有问题 |
| P6 数据验证 | 在正式库副本重拆第 9 集 3/4/5 镜 | 结构、边界、左右、台词全部通过；再决定是否覆盖正式集 |

## 10. 验收

- 第 9 集第 3/4/5 镜：同一句台词只出现一次；说话提示与台词同镜；下一镜从上一镜尾状态继续；同场左右/轴线一致。
- 剧本格式台词 `角色：（情绪）台词` 可被识别；短台词“呦！”在说话人冒号后可识别。
- video_prompt 把台词拆到多个时间帧时，完整性校验通过；不因“催促：”等续接词误报。
- plan-gate 能拒绝说话提示跨镜、重复开头、左右翻转，并给出结构化证据。
- 跳过/自动跳过/完成问题清单可用；跳过镜头标记但允许生成。
- 设置页每个生效配置都有消费者；没有死开关；三套主力方案可选，归档方案不可选但有迁移提示。

## 11. 风险与开放问题

| 风险 | 应对 |
|---|---|
| 计划层模型仍可能切错 | 结构化边界校验 + 计划层重试，不让错误进入渲染 |
| 台词过长 | 只允许在标点处拆，下一镜严格续接；不重复开头 |
| 过渡词位置争议 | 规则锁定为单侧出现；方案只能选择“上一镜末尾/下一镜开头”之一 |
| 现有数据迁移 | 旧骨架字段映射；归档方案保留；正式库先副本验证 |
| 规则包执行成本 | 锁定规则轻量确定性；语义规则后续按预算接入 |
| 设置页复杂度 | 配置注册表 + 影响预览；未生效项折叠 |
| 三套方案差异不足 | 先保证硬契约一致，再在风格/节奏/覆盖偏好上拉开差异 |

开放问题：

1. 过渡词默认放上一镜末尾还是下一镜开头；本设计建议默认下一镜开头承接，上一镜不重复。
2. 台词是否允许跨镜；本设计锁定为“原子化”，只有超容量时才在标点处拆。
3. 归档方案的已有剧集映射：导演分镜表 → 标准；快切预告 → H3 紧凑；是否接受由用户确认。
4. 第 9 集正式库是否在 P6 后直接重拆，还是先保留副本报告。
