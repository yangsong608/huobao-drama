# 旁白形态双轨制设计方案

日期：2026-11-13
状态：决策已冻结，待「开始执行」
范围：分镜拆分链（planner / shot-intent-plan / repair / validate）、负面约束、手改重算、项目设置 UI

## 一、背景与问题

第 8 次拆分（ep9，调教大宋第一集，35 镜）完成后，用户手改了 10 条旁白（镜 6/10/11/16/23/24/25/26/28/29）。量化结果：

| 指标 | 数值 | 含义 |
| --- | --- | --- |
| 全集旁白总字数 | 450 字 | 对白 320 字，旁白占口播 58% |
| 手改镜超语速预算 | 8/10 | 按 4 字/秒 + 1 秒气口，旁白读不完 |
| 最严重超预算 | 镜23：67 字需 17.8s，镜头 6s | 镜24：76 字需 20s，镜头 12s |
| 负面约束自相矛盾 | 7 镜 | 正文有旁白，负面约束仍写「不生成任何对话，对白以及旁白」 |
| description/旁白计划 | 未同步 | 重校验必失败 |

用户改法特征：第三人称完整句、可写情绪与前因、可放在对白镜与动作镜、按时间帧分段、称呼统一（唐大郎→唐奕、马伯→马老三）。这是**旁白驱动的小说改编形态**，而当前流水线执行的是**对白驱动短剧形态**的规则（24 字上限、仅开场/压缩过渡镜可旁白、动作/对白镜禁旁白、原文逐字门禁、时长固定）。

结论：不是参数问题，是生产形态错配。需要形态级开关，两套规则共存。

## 三、冻结决策

| 编号 | 决策 | 依据 |
| --- | --- | --- |
| D1 | 项目级「旁白形态」开关，双轨规则：dialogue（对白驱动，现行规则不变）/ narration（旁白驱动小说改编，新规则） | 用户选定；对齐 LocalMiniDrama wantNarration 与 zenstory form profile |
| D2 | 已手改的 10 条旁白按新规则重算：超预算自动延长时间或按标点拆到相邻镜，同步 description/旁白计划，清除矛盾负面约束 | 用户选定 |
| D3 | 保留 6 秒下限与方案单段上限（standard 15 / hook 12 / h3-compact 8） | 前次决策延续 |
| D4 | 旁白音频走现有配音通路（台词抽取→TTS→混音），不新建第二条音频管线；本地 H3 无 `<d>` 强制静音策略不变 | 架构复用；现有通路已识别旁白（dialogue-lines.ts）并绑定项目旁白音色（dramas.narratorVoiceId） |
| D5 | 默认形态 dialogue，存量项目行为不变；调教大宋由用户手动切到 narration | 向后兼容 |
| D6 | 旁白风格规则成文化进规则包：第三人称完整句、可写情绪/心理/前因、称呼用项目规范名、任意镜可旁白但与对白分时不重叠、按标点分段不断词、旁白与画面同步、不逐字复述对白、第 1 镜必须有开场旁白 | 用户 10 条手改语料 + LocalMiniDrama/AI_novel 规则综合 |

### P1 旁白计划扩展（shot-intent-plan）

**要求**

- narration 形态的旁白来源：原文叙述 prose 经改写（允许情绪、心理、前因、跨时间浓缩），称呼用项目规范名；budgetChars 公式不变（(时长-1)×4）。
- dialogue 形态：24 字上下文上限、仅开场/压缩过渡镜、原文逐字门禁全部保留。

**约束**
- 意图分类器（storyboard-content.ts 共享正则）不改；形态只影响旁白策略，不影响意图判定。
- overflow 语义不变：超预算时不截断，交由 P2 时长/拆分与 P3 修补指令解决。
- 旁白与对白不得在同一时间帧重叠（分时共存）。

**参考**

### P2 时长与拆分：旁白决定时长（planner）

**要求**
- narration 形态：镜头时长 = clamp(ceil((对白字数+旁白字数)/4)+1, 6, 方案单段上限)；旁白字数按原文叙述 prose 估算。
- 长叙述段落按标点（。！？；）拆到相邻镜，禁止词中断开；每镜旁白 ≤ 本镜预算。
- 压缩过渡镜（narrativeRun）在 narration 形态下携带旁白，时长同样按字数折算。
- dialogue 形态：现有时长逻辑（silentDuration、语速权重）不变。

**约束**
- D3：6 秒下限与方案上限（15/12/8）不变；h3-compact 上限 8 秒意味着单镜旁白 ≤28 字，长文必须多镜。
- 拆分边界契约（骨架锁定、覆盖率门禁）不变；旁白拆分只影响时长与镜数，不破坏原文覆盖。
- 战斗/比拼豁免压缩的规则不变。

**参考**
- backend/src/services/storyboard-planner.ts（duration 计算、compressSilentRuns、mergeSilentGroup、buildPlannedShotsBlock）
- backend/src/services/storyboard-plan-contract.ts（PlanShot.narrativeRun）
- backend/src/services/breakdown-methods.ts（getMaxSegmentSeconds）

**设计**
- planner 输入增加 narrationForm；narration 形态下每个骨架的旁白候选字数参与时长权重；超上限时段落按标点贪心装箱到相邻骨架，必要时增加骨架（覆盖率门禁仍按原文字数核算）。
- 预拆分锁定清单（buildPlannedShotsBlock）为每个骨架标注旁白预算字数，修补模型不得超。
- validateSilentRuns 的「有声」判定已含旁白，narration 形态下连续无声门禁自然放宽，无需改阈值。

**自测**

- dialogue 形态：现有 planner 测试（压缩、战斗豁免、时长）全部不变通过。
- 三种方案（standard/hook/h3-compact）各跑一遍 ep9 原文，覆盖率门禁通过。

**验证**
- 新增 planner 形态测试；ep9 干跑输出镜数/时长分布表，与方案上限核对。

### P4 负面约束双向一致

**要求**

**约束**
- 只改负面约束分区，不改画面、台词、声音设计（现有注释契约不变）。
- promptHasSpokenContent 已能识别旁白（画外音）：「…」，复用不新写正则。
- 幂等：重复评估不重复追加/移除。

### P5 手改重算通路（D2）

**要求**
- 提供「按旁白重算」能力：读取镜头提示词，用现有抽取器解析对白+旁白，重算语速预算；超预算时优先延长时长至方案上限，仍超则按标点给出拆镜建议。
- 重算同步：duration、description 旁白行、narration_json、负面约束（P4）。
- 对 ep9 的 10 条手改镜执行重算：镜23（67 字）与镜24（76 字）等超上限镜拆成相邻两镜，编号顺延；其余镜延长时长。
- 前端在最终提示词下方问题面板显示超预算警告，提供「按旁白重算时长」按钮（单镜）；拆镜建议以预览清单呈现，用户确认后应用。

**约束**
- 重算不改变用户写的旁白文字（D2：以用户改法为准）；只动时长/拆分/同步字段。
- 拆镜复用现有分镜插入/编号顺延逻辑，不新写编号器；删除残留清理规则不变。
- 重算后镜头状态回到待校验，不自动标 validated。
- 预览未确认前不落库。
