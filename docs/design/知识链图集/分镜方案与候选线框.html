设计说明

  1. 不新增「分镜校验」顶级页签：旧批量动作检验已下线（创建/撤销返回 410），前端有测试断言其入口不存在。校验方案作为「分镜拆分」的第二个子页签，避免复活旧入口，也保证规则一套、口径一套。分镜流水线 页签的规则包区只加一条只读跳转「校验方案见分镜拆分」。
  2. 沿用 breakdown-layout：左列表 minmax(240px,320px) + 右详情；右侧由编辑卡改为只读详情卡，字段全部 input.ro，无保存按钮。
  3. 列表新增信息：来源（内置导出 / Obsidian / 自定义）、当前版本、引用知识数、候选徽标、正文与数值矛盾徽标、使用集数；归档方案标 compat: legacy 并禁用「重新启用」直到通过检查。
  4. 写操作迁移：删除保存/复制/恢复默认/删除四个按钮，替换为「在 Obsidian 中编辑」「回滚到指定版本」「同步方案」。回滚走方案版本接口，不删中间版本。
  5. diff 需新建组件：仓库当前没有 diff 查看组件。新增轻量结构化 diff（字段级三列表 + 正文行级 ±），复用 .card/.tag/.overlay > .dialog；不引入第三方 diff 库。真实实现中「看 diff」打开右侧抽屉或弹窗，线框里内联展开便于评审。
  6. 批准前门禁：候选检查未通过（缺列、未知 scope、非法 severity、削弱锁定检查、正文与时长数值矛盾）时批准按钮置灰，并给出具体原因与修改位置。
  7. 校验方案表格：八列必填字段全部可见（检查项 / 范围 / 严重度 / 门禁 / 证据要求 / 启用 / 修复提示，外加层与 applies_to），锁定行灰底且开关不可点；底部汇总门禁影响（阻断 / 人工确认 / 提示 各几项）。
  8. 投影只读：breakdown_methods 与 validation_schemes 是运行时投影，页面不直接写；版本事实源是方案版本表，避免设置页与运行时各存一份。
