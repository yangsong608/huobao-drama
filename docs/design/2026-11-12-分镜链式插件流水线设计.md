## 0. 一页结论

### 0.1 现在的链路是什么

当前是**一条硬编码的四段式流水线 + 四套互不完全对齐的配置面 + 两条旧路径**：

- 主链路：预拆骨架 → 逐镜修补 → 逐镜校验 → 声音设计，全部由 `storyboard_director` 执行。
- 配置面：拆分方案、流程规则、分镜检验策略、知识库分别存在四个地方；导演甚至不在设置页的 Agent 列表里。
- 两条旧路径：旧 `storyboard_breaker` 分块拆分、旧 `storyboard_auditor` 批量动作检验仍然存在，且可以对新管线产物运行。
- 结果是：加一个检查、换一个模型、调整一次重试，都要改核心服务；同一条链两次运行结果不同时无法复现；新旧两套校验口径互相冲突。

### 0.2 新设计是什么

把“流程”从代码里抽出来，拆成五个对象：

1. **Chain（链）**：有序步骤、版本、适用项目/剧集。
2. **Step Plugin（步骤插件）**：每个步骤自己的提示词、技能、知识、工具、模型、校验、重试策略。
3. **Rule Pack（规则包）**：确定性校验规则的版本化集合，管线与旧检验共用。
4. **Run Snapshot（运行快照）**：每次任务开始时固化链、插件、提示词、知识、规则、模型的版本。
5. **Engine（执行引擎）**：负责 episode / chunk / shot 三种作用域、逐镜循环、重试、人工暂停、断点恢复、预算和事件。

### 0.3 四项已确认口径

| 决策 | 选择 | 对设计的约束 |
|---|---|---|
| 插件粒度 | **粗粒度阶段插件** | 预拆、修补、校验、声音、收尾各为一个插件；chunk / shot 循环由引擎处理，不让插件作者写循环 |
| 首版编排能力 | **固定模板 + 开关/参数** | 内置 3 条链；只允许启停可选步骤、调参数；不做拖拽排序，不允许自由增删必选步骤 |
| 旧链路 | **直接下线** | 不做长期双轨；新任务只走链；旧接口/旧 UI 在迁移期后移除；旧数据先归档，物理删表另走审批 |
| 校验体系 | **统一规则包** | 管线校验与旧检验共用规则与策略；旧检验不再作为独立系统存在，能力收敛为可选插件 |

### 0.4 首个可用版本的目标

- 3 条内置链：标准四段式、严格四段式、轻量四段式。
- 10 个内置步骤插件，其中 7 个必选、3 个可选。
- 设置页出现「分镜流水线」：模板、步骤开关、参数、规则包、知识/提示词/Skill、测试运行。
- 视频制作页显示步骤级/镜头级进度；失败镜进入人工队列；可查看本次运行快照与 trace。
- 旧 breaker 拆分、旧批量动作检验的入口下线；旧任务先归档，不静默删除。
- 运行结果可复现：同链、同快照、同输入重跑，结构结果与规则判定一致。

## 1. 现状诊断

### 1.1 今天的实际链路

| 环节 | 现在做什么 | 关键位置 |
|---|---|---|
| 选择方案 | 设置页 6 套方案；集上记录 `episodes.breakdown_method` | 设置页「分镜拆分方案」 |
| 触发 | 视频页点击「拆分分镜」，调用 director 管线任务 | 前端 `doBreakdown` |
| 任务初始化 | 中断旧检验、分块、清旧分镜与帧资产 | `createStoryboardPipelineJob` |
| 第一段 | 按块生成骨架，校验摘录覆盖率 | `defaultSkeletonRunner` |
| 第二段 | 逐镜修补，保存成稿 | `defaultRepairRunner` |
| 第三段 | 逐镜确定性校验，失败同镜重试 | `validateRepairedShot` |
| 第四段 | 场景/剧情级声音设计 | `defaultSoundRunner` |
| 自动化 | 管线完成后跳过旧批量检验 | `automation.ts` |
| 旧路径 | 旧分块拆分、手动动作检验仍可运行 | 旧路由与视频页按钮 |

### 1.2 七个结构性缺口

| 缺口 | 证据 | 后果 |
|---|---|---|
| 阶段硬编码 | 四段逻辑、阶段消息、工具集合分散在管线与 Agent 注册表 | 新增步骤必须改核心服务 |
| 配置面割裂 | 拆分方案、流程规则、检验策略、知识库各自存储 | 用户无法判断某项配置影响哪一步 |
| 两套校验 | 管线逐镜检查不读策略；旧批量检验读 `storyboard_audit.policy` | 同一集两套口径；自动插过渡与管线决策冲突 |
| 覆盖不门禁 | 方案声明段落数下限；管线只校验单块摘录覆盖率 | 覆盖下限只是提示，不阻止少拆 |
| 知识未绑定步骤 | 知识按 Agent 分配；导演默认 0 分配且无 UI 入口 | 四段式核心链路没有使用知识库 |
| 无运行快照 | 只记录 job 状态和计数 | 无法复现、无法定位“为什么这次结果不同” |
| 旧路径并存 | 旧 breaker / auditor 路由与 UI 仍在 | 新旧同时改数据，长期维护成本高 |

### 1.3 为什么不能只改设置页

只改设置页只能让配置“看起来统一”，但四段逻辑仍写死在管线里：

- 步骤顺序、作用域、重试、失败停点都是代码。
- 每个步骤的提示词、知识、工具、校验没有统一 manifest。
- 运行结果没有版本快照。
- 旧路径仍然可以绕过新链直接改数据。

因此本次必须同时改**配置模型、执行模型、数据模型和旧路径**，只改 UI 不够。

### 1.4 本次边界

包含：

- 分镜拆分、逐镜修补、逐镜校验、声音设计及其规则包。
- 设置页、视频制作页、运行 trace、人工队列。
- 旧 breaker 拆分、旧批量动作检验的下线与数据归档。

不包含：

- 视频生成模型、首尾帧策略、合并导出、配音与混音的算法改造。
- 任意代码插件、插件市场、拖拽式自由编排。
- L2 视觉预检、L3 生成后验收的规则扩展（后续单独设计）。
- 多用户权限体系。

## 2. 目标与原则

### 2.1 目标

1. **一条链就是一个可版本化对象**：链定义、步骤插件、规则包、运行快照都可查询、可回滚。
2. **每个步骤自包含**：步骤的输入、输出、提示词、技能、知识、工具、模型、校验、重试全部在 manifest 中声明。
3. **一套规则**：硬约束与可选规则统一到规则包；旧检验不再维护第二套策略。
4. **可复现**：每次运行固化所有影响结果的版本；支持同快照重跑。
5. **可下线**：旧 breaker / auditor 路径在迁移期后移除，不保留长期双轨。
6. **可解释**：页面能看到每一步、每一镜、每次尝试的问题、证据和版本。

### 2.2 非目标

- 不做通用工作流引擎，不追求任意 DAG。
- 不做插件市场，不加载外部代码。
- 不在首版做拖拽排序和自由增删必选步骤。
- 不用链式插件取代视频生成、配音、混音、导出链路。
- 不为了“插件化”牺牲当前四段式的确定性校验与人工停点。

### 2.3 原则

1. **声明式优先**：插件只声明能力，不执行任意代码。
2. **必选步骤不可削弱**：核心校验规则锁定，参数只能在安全范围内调整。
3. **快照先于执行**：没有快照就不允许开始运行。
4. **失败可见可修**：失败镜保存草稿、进入人工队列，不跳过、不丢失。
5. **先归档再下线**：旧数据先导出归档，物理删除另走审批。
6. **行为先等价再扩展**：默认链必须与当前四段式结构等价，再开放可选步骤。

## 3. 链式插件模型

### 3.1 五个核心对象

| 对象 | 职责 | 不负责 |
|---|---|---|
| Chain | 步骤顺序、模板、参数、版本 | 具体提示词与工具实现 |
| Step Plugin | 单个步骤的 manifest 与执行器 | 跨步骤循环、断点恢复 |
| Rule Pack | 确定性规则与阈值 | 调用模型、修改分镜 |
| Run Snapshot | 固化本次运行的全部版本 | 业务判断 |
| Engine | 作用域循环、重试、暂停、恢复、预算、事件 | 业务规则本身 |

### 3.2 步骤插件 manifest

每个插件至少声明：

| 字段 | 说明 |
|---|---|
| `key` / `name` / `version` | 稳定标识与版本；版本参与运行快照 |
| `kind` | `deterministic` / `llm` / `validate` / `human` / `finalize` |
| `scope` | `episode` / `chunk` / `shot` |
| `order` | 在模板中的固定槽位；不允许用户任意改序 |
| `required` | 必选步骤不可关闭；可选步骤可开关 |
| `inputContract` | 需要读取的上下文与数据字段 |
| `outputContract` | 写入的上下文与数据表字段 |
| `agent` | 使用的 Agent 类型；确定性步骤为空 |
| `promptRef` / `skillRefs` | 提示词与技能引用 |
| `knowledgeRefs` | 步骤级知识绑定；优先于 Agent 默认知识 |
| `toolRefs` | 工具白名单；只能从工具注册表选择 |
| `modelPolicy` | 模型/配置来源与覆盖规则 |
| `execution` | 最大尝试次数、超时、并发、预算、失败策略 |
| `validation` | 规则包引用、阈值覆盖、门禁级别 |
| `ui` | 标签、进度文案、可编辑字段、人工队列展示 |
| `compatibility` | 最低应用版本、所需能力、废弃标记 |
| `legacyMapping` | 旧路径/旧数据的迁移说明 |

### 3.3 插件类型

| 类型 | 示例 | 是否调用模型 | 是否可人工暂停 |
|---|---|---|---|
| deterministic | prepare、finalize、transition-insert | 否 | 否 |
| llm | skeleton-split、shot-repair、sound-design | 是 | 是 |
| validate | skeleton-gate、shot-validate、sound-validate | 否 | 失败可进入人工 |
| human | manual-shot-edit | 否 | 是 |
| finalize | finalize | 否 | 否 |

### 3.4 作用域语义

- `episode`：整个剧集执行一次，例如 prepare、sound-design、finalize。
- `chunk`：按剧本分块迭代，例如 skeleton-split、skeleton-gate。
- `shot`：按分镜顺序迭代，例如 shot-repair、shot-validate、semantic-review。
- 引擎负责循环；插件只处理“一个 item”，不写 for 循环。
- shot 作用域默认顺序执行，保证“这一镜通过后再进入下一镜”；首版不开放并发。

### 3.5 工具注册表与安全边界

- 工具仍然由应用内置，分三类：读取上下文、保存结果、查询资产。
- 插件只能从注册表选择工具，不能声明任意模块路径。
- 保存类工具必须幂等：同一镜重复保存不产生重复行；保存前做事务与规则校验。
- 工具声明包含：读写权限、作用域、是否允许批量、是否允许覆盖已有成稿。
- 不加载外部脚本、不执行 shell、不访问任意文件路径。

### 3.6 步骤级知识绑定

- 每个插件声明 `knowledgeRefs`，例如：
  - `skeleton-split`：短剧叙事与节奏、分镜与导演语法。
  - `shot-repair`：分镜与导演语法、前后镜连贯与过渡。
  - `semantic-review`：分镜校验清单、连贯规则。
  - `sound-design`：声音与旁白设计、连贯规则。
- 知识加载顺序：步骤级绑定优先；未声明时回退到 Agent 默认分配。
- 知识 id、内容 hash、版本写入运行快照与 step run。
- 必读知识缺失时，步骤启动前直接阻断；不再允许“导演无知识静默运行”。

### 3.7 版本与兼容

- Chain、Plugin、Rule Pack 都有独立版本；运行快照记录组合版本。
- 插件 manifest 声明最低应用版本；升级后不兼容的链不允许启动，提示迁移。
- 内置插件只随应用发布；用户不能上传代码插件。
- 模板可克隆为“项目级覆盖”，但步骤顺序和必选步骤不变。

## 4. 默认链与模板

### 4.1 默认链（10 个步骤）

| # | 步骤 | 类型 | 作用域 | 必选 | 关键绑定 | 失败策略 |
|---|---|---|---|---|---|---|
| 1 | `prepare` | deterministic | episode | 是 | 校验输入、canonical 场景、分块、清理旧分镜 | 停止 |
| 2 | `skeleton-split` | llm | chunk | 是 | 导演 + 骨架保存工具 + 拆分预设 + 节奏/导演知识 | 块级重试 |
| 3 | `skeleton-gate` | validate | chunk + episode | 是 | 摘录覆盖率 + 总覆盖下限 + 场景覆盖 | 重拆/警告 |
| 4 | `shot-repair` | llm | shot | 是 | 导演 + 单镜保存工具 + 连贯/方向知识 | 同镜最多 3 次 |
| 5 | `shot-validate` | validate | shot | 是 | 单位合同 + 台词完整 + 相邻镜配对 | 3 次后人工 |
| 6 | `semantic-review` | llm | shot 或窗口 | 否 | 检验 Agent + 校验清单知识 | 只报问题 |
| 7 | `auto-repair` | llm | shot | 否 | 导演 + 白名单修复 + 快照回滚 | 回滚 |
| 8 | `sound-design` | llm | episode | 是 | 导演 + 声音计划工具 + 声音/连贯知识 | 重试 |
| 9 | `sound-validate` | validate | episode | 是 | 声音规则包 | 停止/人工 |
| 10 | `finalize` | deterministic | episode | 是 | 快照、事件、任务完成、清理临时状态 | 停止 |

可选但不在首版模板中：

- `transition-insert`：过渡分镜插入；默认关闭，后续单独设计。
- `legacy-batch-audit`：不再作为插件存在；旧能力由规则包与语义复检覆盖。

### 4.2 三个内置模板

| 模板 | 包含步骤 | 适用场景 | 默认参数 |
|---|---|---|---|
| 标准四段式 | 1–5、8–10 | 默认生产 | 逐镜重试 3 次；语义复检关闭；自动修复关闭 |
| 严格四段式 | 1–10 | 关键集、回归、问题集中集 | 语义复检开启；自动修复开启但限次数；窗口 16/15/20 |
| 轻量四段式 | 1–5、8–10 | 试拍、草稿、快速验证 | 语义复检关闭；重试 2 次；覆盖下限仍为硬门禁 |

三条模板都保留：

- 6–15 秒、单机位、固定四区、台词逐字、发声动作必须有台词等硬规则。
- 失败同镜停点与人工队列。
- 声音设计必须在所有普通分镜通过后执行。
- native / post 不混用、BGM 不逐镜重启等声音规则。

### 4.3 首版可开关与可调参数

| 参数 | 范围 | 默认 | 说明 |
|---|---|---|---|
| 拆分预设 | 6 个内置预设 | 标准 | 只影响风格与节奏，不覆盖硬约束 |
| 逐镜最大尝试 | 2–5 | 3 | 初始 + 重试；用完进入人工 |
| 块级最大尝试 | 1–3 | 2 | 骨架覆盖率不足时重拆 |
| 摘录拒收阈值 | 0.2–0.35 | 0.25 | 低于此值判本块失败 |
| 摘录警告阈值 | 0.5–0.8 | 0.6 | 低于此值记录警告 |
| 覆盖下限比例 | 0.85–1.0 | 0.9 | 低于下限阻断完成 |
| 语义复检 | 开/关 | 关 | 严格模板默认开 |
| 语义窗口 | 4–40 | 16 | 窗口步长不超过窗口 |
| 最多窗口 | 1–60 | 20 | 成本保护 |
| 自动修复 | 开/关 | 关 | 严格模板默认开 |
| 单任务最多动作 | 1–100 | 40 | 成本与风险保护 |
| 单镜最多动作 | 1–10 | 3 | 防止越修越乱 |
| 过渡分镜插入 | 开/关 | 关 | 首版不开放 |
| 单集 LLM 调用上限 | 10–500 | 120 | 超限暂停，不静默降级 |
| 单集墙钟上限 | 10–240 分钟 | 60 | 超限暂停 |

参数只能影响“可调规则”；硬规则与必选步骤不可关闭。

### 4.4 必选步骤与不可变契约

不可关闭、不可改序、不可用参数削弱的步骤与规则：

- `prepare`、`skeleton-split`、`skeleton-gate`、`shot-repair`、`shot-validate`、`sound-design`、`sound-validate`、`finalize`。
- 单机位 / 单主体 / 连续动作。
- 6–15 秒镜头时长。
- 固定四区：信息头 → 画面调度 → 时间帧 → 负面约束。
- 台词逐字复制；原文无台词不得自行加；发声动作必须有具体台词。
- 相邻镜屏幕左右、地标侧、轴线、动作端点。
- 声音覆盖、同轨不重叠、单元单 BGM、native/post 不混用。
- 失败镜不跳镜、不丢失、必须进入人工队列。

### 4.5 与现有六套拆分方案的关系

六套方案不删除，但降级为 `skeleton-split` 步骤的“拆分预设”：

| 预设 | 原时长 | 原问题 | 新定位 |
|---|---|---|---|
| 标准短剧段落 | 8–15 秒 | 描述仍写 2–4 子镜 | 默认预设；重写描述，保持空 prompt/skill |
| 爆款钩子节拍 | 6–12 秒 | 多处“最后的子镜头” | 保留钩子思路，改写为单镜/时间帧语言 |
| 爆款钩子节拍·扩展版 | 6–12 秒 | 十节按【镜头N】写 | 保留覆盖/钩子/机位方法，全部改写为单镜 |
| 导演分镜表 | 5–10 秒 | 5 秒低于下限 + 2–4 子镜 | 改为 6–15 秒；A/B/C/D 变成跨镜覆盖 |
| H3 紧凑段 | 5–8 秒 | 5 秒低于下限 + 1–3 子镜 | 改为 6–8 秒；单镜单动作 |
| 快切预告 | 3–6 秒 | 3–5 秒低于下限 + 子镜 | 改为 6–10 秒，或降级为“节奏参数”而非独立预设 |

新增结构化字段（只存数据，不在本文写实现）：

- `min_duration_seconds`、`max_duration_seconds`。
- `allow_multi_shot` 固定为否，不允许用户修改。
- `coverage_floor_mode`：按最大时长计算。
- `style_prompt`、`style_skill`：只放风格增量，不放单位规则。
- `compatibility_status`：保存时校验是否包含禁用表述（子镜头、镜头2、低于 6 秒等）。

`getMaxSegmentSeconds` 改为读取预设行，不再只查静态 seed；自定义/复制预设继承最大时长，不再回落 15 秒。

### 4.6 与现有四段式的行为映射

| 现四段式 | 新链 | 保持不变的语义 |
|---|---|---|
| 第一段预拆 | `skeleton-split` + `skeleton-gate` | 按场次分块、逐字摘录、覆盖率 25%/60%、镜号跨块连续 |
| 第二段修补 | `shot-repair` | 目标骨架 + 完整场次 + 前后镜上下文 + 同场方向常量 |
| 第三段校验 | `shot-validate` | 补一镜校验一镜、失败同镜重试、3 次停 manual、草稿落库 |
| 第四段声音 | `sound-design` + `sound-validate` | 全部通过后执行、按场景/剧情单元、单镜只写增量 |
| 自动化跳过旧检验 | 链完成即完成 | 旧 `storyboard_audit` 阶段删除 |

## 5. 统一规则包

### 5.1 规则分类

| 规则包 | 规则内容 | 级别 |
|---|---|---|
| `unit-contract` | 单机位、单主体、连续动作、6–15 秒、时间帧 1–6 秒连续、固定四区、动作端点 | 锁定 |
| `dialogue-integrity` | 台词逐字、原文引号台词不丢、发声动作必须有台词、原文无台词不得加、占位台词清理 | 锁定 |
| `dialogue-capacity` | 4 字/秒 + 1 秒气口；超容量阻断 | 锁定，阈值可调 |
| `pair-continuity` | 屏幕左右、地标侧、轴线、动作端点配对 | 锁定 |
| `coverage` | 单块摘录 25%/60%、整集段落数下限、场景覆盖、资产绑定 | 摘录/下限锁定；资产绑定警告 |
| `sound` | 普通镜被环境声/静默覆盖、同轨不重叠、单元单 BGM、不逐镜重启、环境声不跨场景、同镜 cue 同单元、native/post 不混用 | 锁定 |
| `semantic-review` | 动作是否接得上、台词是否符合人物、反应镜头是否缺失、时间跳跃/回忆是否合理 | 可选 |

### 5.2 规则模型

每条规则至少包含：

- `key`、`version`、`name`、`description`。
- `scope`：shot / pair / chunk / episode。
- `severity`：error / warning / info。
- `locked`：锁定规则不可关闭，只能在安全范围内调阈值。
- `configSchema`：可调参数、范围、默认值。
- `evaluatorKey`：确定性规则实现；语义规则为空。
- `message`：四语言文案键。
- `fixability`：是否可自动修复、修复动作白名单。
- `evidence`：需要展示的证据字段。

### 5.3 旧检验五项检查的映射

| 旧检查 | 新规则包 | 处理 |
|---|---|---|
| 运镜 / 对话 / 动作 / 表情 / 旁白 | `unit-contract` + `dialogue-integrity` | 确定性规则吸收；语义部分进 `semantic-review` |
| 前后镜连贯与不合理动作 | `pair-continuity` + `semantic-review` | 轴线/左右/端点锁定；语义连贯可选 |
| 长时间无对白空镜 | `coverage` 的空镜警告 | 降为 warning，不再独立开关 |
| 台词时长与拆句 | `dialogue-capacity` | 统一为 4 字/秒 + 1 秒气口；阈值可调 |
| 资产正确与完整 | `coverage` 的资产绑定 | 降为 warning；缺资产提示人工 |

旧 `storyboard_audit.policy` 不再作为独立配置存在；其有效能力迁移到规则包与严格模板参数。

### 5.4 规则包版本与快照

- 规则包版本随应用发布；每次运行把规则包版本与阈值写入快照。
- 规则文案、严重级别、阈值都参与快照 hash。
- 同一条规则升级后，旧运行仍可按旧快照解释结果。
- 规则包变更需要跑回归样例，特别是黄金镜头集。

### 5.5 语义复检插件

- 输入：目标镜、前后镜、场景地理、合同、确定性校验已发现的问题。
- 输出：语义问题清单，包含严重级别、证据、建议修复；默认不直接修改。
- 使用 `storyboard_auditor` Agent 与校验知识。
- 默认按镜执行；严格模板可按窗口执行，窗口大小/步长/数量受参数限制。
- 只作为严格模板的可选步骤；标准模板不开启。
- 语义问题不阻断保存，但进入人工队列；若开启自动修复，只允许修复白名单问题。

### 5.6 自动修复插件

- 只处理 `fixability` 为可修复的问题；锁定规则不通过“改规则”修复，只能改内容。
- 修复前保存快照；修复后立即重跑同一规则包。
- 复查错误数增加时整轮回滚。
- 受 `maxActions` 与 `maxActionsPerShot` 限制。
- 默认关闭；严格模板开启。
- 不允许自动插入过渡分镜（首版）。

### 5.7 门禁与人工队列

- `shot-validate` 失败达到上限：标记 manual，保存草稿，暂停在该镜。
- 人工编辑后点击继续：先重跑 `shot-validate`，通过后进入下一镜。
- 是否允许“人工通过”需单独参数控制；默认不允许；若开启，必须记录原因与操作者。
- 声音校验失败：暂停在声音设计，不进入自动化后续。
- 覆盖下限不达标：`skeleton-gate` 阻断，不允许进入逐镜修补。

## 6. 执行引擎

### 6.1 运行状态

| 层级 | 状态 |
|---|---|
| Run | pending / running / paused / manual / interrupted / done / failed |
| Step | pending / running / passed / failed / skipped / manual |
| Item（chunk / shot） | pending / running / passed / failed / manual |

### 6.2 循环与顺序

- episode 步骤执行一次。
- chunk 步骤按分块顺序执行；一块失败重试，超过上限停止。
- shot 步骤按镜号顺序执行；`shot-repair` 与 `shot-validate` 组成一个 pair 循环。
- 只有所有普通分镜 passed，才进入 `sound-design`。
- 可选语义复检/自动修复在 pair 循环内按配置执行；不改变必选步骤顺序。
- 首版 shot 循环串行；未来并行必须保证提交顺序与幂等。

### 6.3 重试与失败策略

| 场景 | 策略 |
|---|---|
| 块级摘录覆盖率低于拒收阈值 | 重跑本块骨架，最多 `blockMaxAttempts` |
| 单镜校验失败 | 带错误清单重跑同一镜，最多 `shotMaxAttempts` |
| 单镜达到上限 | 保存草稿，标记 manual，暂停 |
| 声音计划校验失败 | 重跑声音设计，最多 `soundMaxAttempts`；仍失败暂停 |
| 覆盖下限不达标 | 阻断完成，回到骨架阶段补拆 |
| 预算超限 | 暂停，提示提高预算或停止；不静默降级 |
| 应用重启 | running → interrupted，可从最后未完成步骤/镜头恢复 |

### 6.4 人工暂停与恢复

- 人工队列展示：剧集、镜号、问题、证据、尝试次数、上次修改时间。
- 页面直接编辑该镜；保存走现有保存层与规则校验。
- 继续时先校验成稿；通过则推进，失败则保留人工状态。
- 支持按步骤暂停：`pause_requested` 在当前 item 完成后生效。
- 恢复时重新加载快照，不允许用新版本悄悄替换旧运行。

### 6.5 运行快照

快照至少包含：

- 链 key、链版本、模板名称。
- 每个步骤插件 key/version/order/required。
- 生效参数（含项目/剧集覆盖）。
- 提示词文件 hash、技能文件 hash。
- 知识 id、内容 hash、绑定来源（步骤级/Agent 默认）。
- 规则包版本、阈值、锁定状态。
- 模型配置 id/名称、供应商、模型名。
- 应用版本、数据库 schema 版本。

快照写入运行记录；step run 另存本步骤的提示词/知识/规则 hash，便于定位差异。

### 6.6 预算与并发

- 每次运行设置 LLM 调用数、token、墙钟、语义窗口上限。
- 超限暂停，不自动降级模型或跳过规则。
- 首版并发为 1；后续如需并发，必须按镜头顺序提交，且保存工具幂等。
- 语义复检与自动修复单独计预算。

### 6.7 事件与可观测性

- 事件：运行开始、步骤状态、item 状态、人工待处理、预算告警、完成、失败。
- 复用现有同步事件/SSE，保证跨端页面实时刷新。
- Trace 页面展示：步骤、item、attempt、问题、证据、耗时、调用数、快照摘要。
- 指标：每步通过率、重试率、人工率、平均尝试数、语义问题数、单集耗时/调用数。

### 6.8 幂等与恢复

- 保存骨架/成稿/声音计划的工具必须幂等；重复执行不产生重复行。
- 运行恢复从最后一个未 passed 的 item 开始；已 passed 的 item 不重复调用模型。
- 中断恢复时，如果数据库已有部分成稿，先校验再决定是否重跑。
- 任何自动修复都先保存快照；恢复时可按快照回滚本轮修复。

### 7.4 接口

| 接口 | 用途 |
|---|---|
| 链模板列表/详情 | 读取内置链、参数 schema、步骤顺序 |

| 运行查询 | 状态、步骤、item、问题、快照摘要 |
| 运行暂停/恢复/取消 | 人工控制 |
| 单镜重试/人工继续 | 人工队列操作 |

旧接口：

- `/agent/storyboard_breaker/split-jobs`：迁移期返回 410 与迁移说明，随后删除。
- `/agent/storyboard_auditor/audit-jobs`：同上。
- `/agent/storyboard_director/pipeline-jobs`：由新的运行接口替代；迁移期可返回 410 指向新接口。

### 7.5 迁移映射

- 旧管线任务 → `pipeline_runs`：保留剧集、状态、阶段、计数、开始/结束时间；缺失快照标记为“迁移前运行”。
- 旧拆分任务/旧检验任务 → 归档 JSON 或归档表；不映射为可恢复运行。
- 旧分镜/骨架/声音数据保持原表，新链可直接读取。
- 旧检验结果不迁移为链结果；需要时用新规则包重新校验。

### 7.6 保留与归档

- 运行快照默认保留最近 N 次/集；更早的归档。
- 旧任务归档保留至少一个发布周期；物理删除需单独确认。
- 归档文件写入数据目录的迁移目录，不写入仓库。

## 8. 设置页与页面

### 8.1 设置页「分镜流水线」

首版采用“固定模板 + 开关/参数”，不采用拖拽编排。

页面结构：

1. **模板**：标准 / 严格 / 轻量；显示步骤数、可选步骤、适用场景；可设为默认。
2. **步骤**：按固定顺序展示；必选步骤显示锁定标记；可选步骤显示开关；点击步骤查看详情。
3. **参数**：按步骤分组；显示默认值、范围、生效层级（全局/项目/剧集）；禁止输入越界值。
4. **规则包**：只读列表 + 可调阈值；锁定规则显示“不可关闭”；展示规则版本。
5. **知识与提示词**：步骤级知识绑定、提示词/Skill 引用；显示文件 hash 与最后修改时间。
6. **测试运行**：选择样例剧集/单镜，预估调用次数与耗时；只读试跑或真实试跑需明确选择。
7. **运行记录**：最近运行、状态、问题、快照摘要、trace 入口。

旧的「分镜拆分方案」和「分镜检验」不再作为顶级页签：

- 拆分方案 → `skeleton-split` 步骤内的“拆分预设”。
- 分镜检验 → 规则包与语义复检步骤。
- 导演 Agent → 加入 Agent 配置列表；可查看/编辑提示词、技能、知识。

### 8.2 Agent 配置

| Agent | 处理 |
|---|---|

## 9. 旧链路下线与迁移

### 9.1 下线范围

运行时下线：

- 旧 `storyboard_breaker` 分块拆分服务与路由。
- 旧 `storyboard_auditor` 批量动作检验服务与路由。
- 旧 `storyboard_director/pipeline-jobs` 路由。
- 旧 UI 按钮、抽屉、旧策略页签。
- 自动化中的旧 `storyboard_audit` 步骤。

代码下线：

- `storyboard-split-jobs` 的旧任务编排（保留分块工具）。
- `storyboard-audit-jobs`、`storyboard-audit-context`、`storyboard-audit-rules`、`storyboard-audit-repair`、`storyboard-audit-insertion` 的旧任务外壳。
- 旧任务相关测试与结构测试。

能力保留：

- 规则逻辑迁入规则包。
- 语义复检/自动修复能力迁入可选插件。
- 分块工具迁入 `skeleton-split` 共享模块。

### 9.2 下线顺序

1. **冻结新写入**：旧接口停止创建新任务；UI 隐藏旧入口；自动化不再创建旧检验。
2. **处理在途任务**：启动时把旧 running 标为 interrupted，并写明“旧链路已下线”；不再恢复。
3. **导出归档**：把旧拆分/旧检验任务导出为归档文件；保留剧集、状态、问题、时间。
4. **切换新链**：视频页与自动化改为新运行接口；默认链上线。
5. **返回 410**：旧接口在迁移期返回 410 与迁移说明；随后移除。
6. **删除代码**：移除旧服务、路由、测试、Agent 注册。
7. **物理删表**：单独审批后执行；先备份。

### 9.3 数据迁移

- 旧管线的 `storyboard_pipeline_jobs` 映射为历史运行；缺失快照标明。
- 旧 `storyboard_split_jobs` / `storyboard_audit_jobs` 归档，不映射为可恢复运行。
- 现有分镜、骨架、声音计划保持；新链可从 `shot-repair` 或 `sound-design` 起步（带前置检查）。
- 旧检验结果不作为新链输入；需要时用规则包重跑。
- 旧 `breakdown_methods` 增加结构化字段，并做兼容性迁移。

### 9.4 现有剧集

- 已有成稿的剧集：允许选择“从逐镜修补开始”或“从声音设计开始”，前提是前置数据完整。
- 从逐镜修补开始时，先对现有分镜做一次规则校验；通过的可跳过重写，失败进入人工队列。
- 从声音设计开始时，要求全部分镜通过 `shot-validate`。
- 已存在的旧检验报告只读展示或归档，不再驱动门禁。

### 9.5 回滚

- 直接下线不等于无回滚：在切换版本保留一个发布周期的功能开关，用于临时回到旧四段式管线。
- 开关只用于故障回滚，不用于长期双轨；验收通过后删除。
- 回滚不得覆盖新链已产生的数据；只停止新链写入并恢复旧入口。
- 回滚需记录原因、影响范围与后续修复计划。

### 9.6 用户沟通

- 发布说明写清：旧「动作检验」入口移除；能力进入严格模板；旧任务已归档。
- 首次打开旧集时提示迁移状态与可选起点。
- 迁移报告包含：归档数量、映射运行数量、失败/跳过数量、需要人工处理的集。

## 10. 实施批次与验收

### 10.1 批次

| 批次 | 目标 | 主要交付 | 出口 |
|---|---|---|---|
| P0 止血 | 让当前配置面先自洽 | 导演加入设置页/知识；检验策略标注边界；`maxSegmentSeconds` 读 DB；覆盖下限门禁；旧入口冻结 | 现有四段式行为不变，配置不再误导 |
| P1 引擎 | 把四段式抽成链 | 新表、快照、引擎、10 个插件、3 模板；旧路径暂不接入 UI | 黄金样例结构等价；引擎测试全绿 |
| P2 切换 | 新链成为唯一入口 | 设置页「分镜流水线」、视频页、trace、人工队列；旧接口 410 | 真实模型小样 + 整集跑通；旧入口不可用 |
| P3 下线 | 移除旧代码与数据 | 归档旧任务；删除旧服务/路由/测试；物理删表另审批 | 代码零引用；归档可查；回归全绿 |
| P4 增强 | 可选能力与度量 | 语义复检、自动修复、过渡插件实验、指标看板 | 严格模板可用；成本/质量有数据 |

### 10.2 验收矩阵

| 维度 | 验收 |
|---|---|
| 结构等价 | 黄金剧集重跑，骨架/分镜/声音结构、规则问题类型与当前四段式一致 |
| 引擎 | 逐镜重试、3 次停 manual、人工编辑继续、块级重试、预算暂停、重启恢复 |
| 规则包 | 锁定规则不可关闭；阈值越界被拒；旧五项检查映射有对照测试 |
| 数据 | 旧任务归档；旧表无新写入；新运行有快照；同快照可解释 |
| 真实模型 | 2 镜小样 + 1 集完整跑通；无旧路径调用 |
| 页面 | 设置页模板/参数/规则/知识可操作；视频页步骤/镜头进度；人工队列；trace |
| 兼容 | 老 workspace 知识索引合并；旧剧集可从修补/声音起步 |
| 性能 | 单集 LLM 调用/耗时不超过基线 +20%（以实测为准） |
| 安全 | 插件不能执行外部代码；工具白名单生效；路径与文件访问受限 |

### 10.3 测试策略

- 规则包单测：每条规则的通过/失败/边界/证据。
- 插件 manifest 契约测试：字段完整、工具在白名单、知识存在、版本兼容。
- 引擎模拟测试：用假 runner 覆盖循环、重试、暂停、恢复、预算、失败策略。
- 集成测试：临时 SQLite 真库，覆盖保存幂等、快照、迁移。
- 黄金样例：16–19 镜、整集 51+3 结构、声音单元。
- 真实模型小样：2 镜；再跑整集；记录调用数与耗时。
- 前端：结构测试 + 浏览器人工走查；重点看参数保存、人工继续、trace、窄屏。

### 10.4 回滚标准

出现以下情况暂停切换并回滚：

- 黄金样例结构不一致，或锁定规则被绕过。
- 人工队列无法继续，或失败镜丢失。
- 旧数据迁移后无法读取成稿/声音。
- 单集调用/耗时明显失控且无法通过预算解释。

### 10.5 交付物

- 本文设计稿。
- 实施计划（按批次拆分，每个任务写明要求/约束/参考/设计/自测/验证）。
- 数据迁移说明与归档清单。
- 验收记录：黄金样例、真实模型小样、整集回归、页面走查。
- 发布说明与用户迁移提示。

## 11. 风险与开放问题

### 11.1 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 过度设计 | 插件系统复杂、开发周期长 | 粗粒度插件、固定模板、首版不做拖拽与代码插件 |
| 迁移丢数据 | 旧任务/旧分镜不可用 | 先归档、备份、只读校验；物理删表另审批 |
| 提示词冲突 | 旧方案文本与硬约束冲突 | 拆分预设重写 + 兼容性校验 + 黄金样例 |
| 规则被削弱 | 用户关闭核心检查导致质量下降 | 锁定规则；参数范围受限 |
| 成本/延迟 | 语义复检与自动修复增加调用 | 预算、窗口上限、严格模板才开启 |
| 用户困惑 | 模板/参数/知识概念多 | 一套设置页、清晰标签、生效预览、恢复默认 |
| 旧路径删除破坏习惯 | 用户找不到「动作检验」 | 发布说明 + 迁移提示 + 严格模板承接能力 |
| 模型波动 | 同链结果不同 | 结构化验收，不做逐字对比；快照记录版本 |

### 11.2 开放问题

1. 旧任务归档保留多久；物理删表的具体时间与审批人。
2. 是否允许“人工通过”某镜并记录原因；默认建议不允许。
3. 首版是否允许新增自定义拆分预设；建议只允许编辑现有预设并做兼容校验。
4. 语义复检按镜还是按窗口；建议严格模板默认按镜，窗口作为成本优化选项。
5. `storyboard_breaker` Agent 是否立即删除；建议先移出活跃列表，P3 再删代码。
6. 过渡分镜插件是否进入首个版本；建议不进入，保持“新管线不自动插过渡”的现有决策。
7. 运行 trace 的保留周期与存储体积；建议按集保留最近 N 次，超限归档。
8. 旧 `storyboard_audit.policy` 的阈值是否全部迁移；建议只迁移仍在使用的阈值，其余随旧系统归档。
