## 1. 背景与结论

第 1、2、3、9 镜暴露出的问题不是四个独立缺陷，而是拆分单位、边界契约和渲染输入没有分层：

- 第 1 镜建立了街景，但没有形成可继承的场景契约；
- 第 2 镜把“吆喝、失望、看唐记”多个节拍塞进一个镜头，台词又超过单时间帧容量；
- 第 3 镜双人同框、台词拆成多段，H3 把第一句口型分给六婶；
- 第 9 镜从街道回店内属于跨地点，却绑定街道场景，同时被“骂完”误判、被第 8 镜的左右翻转连坐；
- 第 3 镜使用第 2 镜尾帧作为首帧后，参考图 Picture 编号整体错位，六婶参考图越界被忽略，人物发生变化。

本方案的核心结论是：

1. 一个分镜必须是一个场景、一个节拍、一个连续动作、一个机位、一个说话人或无台词。
2. 时间帧只用于同一动作的表演节奏，不是微型分镜。
3. 连续边界必须有尾帧到首帧的视觉锚点，没有锚点只能标切镜。
4. 首帧、尾帧和普通参考图必须使用三个独立角色，只有普通参考图参与 Picture 编号。
5. H3 是单镜头渲染器，不是时间轴执行器，也不是可靠的多说话人绑定器。
6. 失败必须回到拆分，不允许继续用改提示词的方式打补丁。

## 2. 统一根因

| 根因 | 表现 | 影响镜头 |
|---|---|---|
| 分镜单位过粗 | 一个分镜容纳多个动作节拍 | 第 2、3、9 镜 |
| 时间帧被当作微型分镜 | 同一镜头内切换主体、焦点、地点 | 第 2、3、9 镜 |
| 边界只有文字没有视觉锚点 | 下一镜重新摆姿势、换道具 | 第 2 到第 3 镜 |
| 场景地理不是单一事实来源 | 左右翻转、责任镜头判断错误 | 第 8、9 镜 |
| 完成态被当成发声动作 | “骂完”被要求补台词 | 第 9 镜 |
| 说话人绑定只靠文本 | 六婶抢走贾婆子的口型 | 第 3 镜 |
| 首帧、尾帧、参考图混用索引 | Picture 编号整体偏移，六婶参考图失效 | 第 3 镜 |
| 画面调度混入动作和情绪 | 模型优先执行调度行，时间帧失效 | 第 2、3、9 镜 |
| 生成后没有验证 | 字幕、错误说话人、动作缺失无人拦截 | 第 2、3、9 镜 |

## 3. 目标架构

### 3.1 场景契约 SceneContract

每个场景只定义一次，所有镜头继承：

| 字段 | 内容 |
|---|---|
| 场景身份 | 场景 ID、地点、时间、光线、天气 |
| 空间常量 | 画面左、画面右、门窗/柜台/灶台等地标侧 |
| 轴线 | 仅双人及以上定义；单人或空镜为无 |
| 道具锚点 | 主要道具位置、初始状态、可变化条件 |
| 入口出口 | 人物从哪侧进出、镜头朝向 |
| 环境声 | 场景底噪与延续策略 |

第 1 镜这类建立镜头负责建立契约，不负责定义人物轴线。第 2、3、9 镜必须继承，不能各自重写。

### 3.2 台词与节拍计划 SpeechPlan 与 BeatPlan

先抽台词单元：说话人、听众、台词原文、情绪、是否发声。

再切节拍。一个节拍等于一个动作或情绪变化。以下任一变化必须新节拍：

- 说话人变化；
- 动作目标变化；
- 情绪转折；
- 地点变化；
- 道具状态变化；
- 机位或景别需要变化。

### 3.3 分镜契约 ShotPlan

一个分镜必须同时满足：

- 一个场景或地点，不跨室内外；
- 一个连续动作弧；
- 一个可见动作起点和一个可见动作终点；
- 一个机位，不切镜；
- 一个说话人，或完全无台词；
- 六到十五秒；
- 时间帧只推进同一动作，不新增人物、焦点、地点或说话人。

“心酸、渐弱、愈发、失落”等心理或声音描述不能作为动作端点，必须落成可见动作。

### 3.4 边界与帧锚点 BoundaryContract 与 FrameAnchor

连续动作必须同时具备：

- 上一镜存在可提取的尾帧；
- 尾帧只有在用户显式设为首帧时才作为首帧；本地 H3 有画内人物参考时不自动使用首帧；
- 下一镜零秒描述从该帧的手、视线、身体朝向、道具位置继续；
- 没有尾帧就标切镜，不能声称连续。

边界文字必须包含可见状态，而不是只写“失落”或“眼睛一亮”。

### 3.5 渲染输入契约 RenderInputPlan

图片分为三类，编号空间完全隔离：

| 图片角色 | 用途 | 是否参与 Picture 编号 |
|---|---|---|
| 本地 H3 fl2v 首帧 | 固定开场画面 | 是（Picture 1） |
| timeline guide 首帧/尾帧 | 固定开场/结束画面 | 否 |
| 普通参考图 references | 场景、角色、道具参考 | 是（fl2v 从 Picture 2 起） |

规则：

- 本地 H3 fl2v：首帧=Picture 1；场景复用首帧，人物参考从 Picture 2 起，默认省略冗余场景参考；
- timeline guide：首帧/尾帧不占 Picture，只有普通参考图参与编号；
- 生成前校验所有 Picture 编号不超过实际图片位（fl2v 首帧占 1 位）；
- 最终提示词预览和实际请求必须使用同一套编号；
- 首帧图和普通参考图不能重复占位；
- 任何参考图索引必须在请求构造完成后统一生成，不能在过滤前预分配。

### 3.6 H3 能力档位

H3 需要单独的能力档位：

- 单说话人优先；
- 多角色同框时，其他角色必须明确嘴唇闭合、不说话；
- 一个说话人尽量只用一个台词标签，不按时间帧拆成多段；
- 台词超容量时拆分镜，不拆同一镜的时间帧；
- 不依赖时间文本执行新节拍；
- 字幕被台词标签烧入属于后处理问题，不能靠负面约束解决；
- 双人对话优先正反打或单人近景，而不是一个双人镜头内轮流说话。

## 4. 图片角色与 Picture 编号问题

### 4.1 实测证据

第 3 镜使用第 2 镜尾帧作为首帧后，请求实际包含：

- 首帧一张；
- 普通参考图三张：街道、贾婆子、六婶。

提示词却写成：

- 上一镜末帧是 Picture 1；
- 街道是 Picture 2；
- 贾婆子是 Picture 3；
- 六婶是 Picture 4。

本地 H3 的两条链路不同：timeline guide 不占 Picture；标准 fl2v（首帧生视频）里首帧实际占 Picture 1。本次修正后，本地 H3 首帧=Picture 1，场景复用首帧，人物参考从 Picture 2 起，并优先保留人物参考、去掉冗余场景参考。

于是实际编号变成：

- Picture 1 是首帧（街道）；
- Picture 2 是贾婆子；
- Picture 3 是六婶；
- Picture 4 不存在。

结果是街道、贾婆子、六婶全部错位，六婶的参考图越界被忽略，模型按文字重新生成了一个年轻女性。

### 4.2 设计结论

- 参考图索引必须在确定首帧、尾帧和普通参考图之后生成；
- 首帧和尾帧不能进入普通参考图索引；
- 提示词里不应出现指代引导图的 Picture 编号；
- 生成请求门禁必须校验 Picture 编号范围；
- 最终提示词预览、实际请求、生成日志必须使用同一编号空间。

## 5. 四层门禁

### 5.1 计划门禁

| 检查 | 处理 |
|---|---|
| 是否跨场景或跨室内外 | 拒绝，要求拆分 |
| 是否包含多个动作节拍 | 拒绝，要求拆分 |
| 是否多个说话人 | 拒绝；H3 下必须拆成正反打或单人镜头 |
| 台词是否超过单时间帧容量 | 拒绝，要求在标点处拆到相邻分镜 |
| 单角色是否错误写轴线 | 拒绝 |
| 描述左右与画面调度左右是否一致 | 拒绝，并标明偏离场景契约的镜头 |
| 动作端点是否可见 | 拒绝心理或声音端点 |
| 场景左右、地标、道具是否继承契约 | 拒绝偏离项 |
| 连续边界是否有尾帧锚点 | 没有则标切镜或拒绝连续声明 |

### 5.2 渲染门禁

| 检查 | 处理 |
|---|---|
| 画面调度是否混入心理或声音 | 拒绝 |
| 时间帧是否新增主体、地点或焦点 | 拒绝 |
| 多角色同框是否写明听众闭嘴 | 拒绝 |
| 首帧存在时零秒描述是否承接首帧 | 拒绝 |
| 台词是否绑定唯一说话人 | 拒绝 |

### 5.3 生成请求门禁

| 检查 | 处理 |
|---|---|
| 首帧或尾帧是否出现在参考图索引 | 拒绝 |
| Picture 编号是否超过普通参考图数量 | 拒绝 |
| 参考图顺序与提示词编号是否一致 | 拒绝 |
| 首帧图和普通参考图是否重复占位 | 拒绝 |
| 模型能力是否支持当前说话人数量 | 不满足则拆镜或拒绝 |

### 5.4 生成后门禁

| 检查 | 处理 |
|---|---|
| 零秒帧是否匹配首帧锚点 | 不匹配判失败 |
| 中间帧是否按时间帧推进 | 缺失判失败 |
| 说话段是否只有指定说话人张嘴 | 错位判失败 |
| 是否烧入字幕 | 记录并进入后处理策略 |
| 是否新增未绑定人物或道具 | 判失败 |
| 动作端点是否出现 | 缺失判失败 |

失败处理统一为回到拆分，不允许只重试提示词。

## 6. 实施计划

### 计划点 1：场景契约与共享地理

#### 要求

建立场景级左右、轴线、地标、道具锚点和入口出口的单一事实来源，所有分镜继承。

#### 约束

不改变现有场景资产结构；不覆盖用户编辑；单人或空镜不得定义人物轴线；场景变化必须显式声明。

#### 参考

现有场景表、场景地理卡、分镜左右字段、第 8 镜描述与画面调度矛盾、第 9 镜跨地点问题。

#### 设计

新增场景契约数据结构，包含场景身份、空间常量、轴线适用条件、道具锚点、入口出口和环境声。拆分时先读取场景契约，再生成分镜左右和轴线。成对校验时以场景契约为基准，标记偏离的镜头，而不是默认标记后一镜。

#### 自测

单角色镜头不得出现轴线 A；同场左右翻转必须定位到偏离镜头；空镜只建立地标，不建立人物轴线；场景契约变更必须触发受影响分镜重新校验。

#### 验证

第 8 镜左右矛盾被定位到第 8 镜；第 9 镜恢复场景常量后不再被误判为翻转；第 1 镜只建立街景契约。

### 计划点 2：台词、节拍与分镜拆分器重写

#### 要求

把拆分顺序改为台词单元、场景、说话人、节拍、分镜，保证一个分镜只承载一个连续动作和一个说话人。

#### 约束

台词保持原子性；不得在标点之外拆台词；不得跨室内外；多说话人必须拆成正反打或单人镜头；时长保持六到十五秒。

#### 参考

第 2 镜多节拍与台词超容量；第 3 镜双人同框与三段台词；第 9 镜回店跨地点；“骂完”被误判为发声动作。

#### 设计

先抽台词和听众，再按场景切分，再按说话人切分，再按动作或情绪节点切分，最后分配机位。台词总容量按四字每秒加一秒气口计算；单时间帧装不下时，在原文标点处拆到相邻分镜。完成态、结果态不当作新的发声动作。一个分镜若需要两个说话人，默认拆成正反打。

#### 自测

第 2 镜不再同时包含吆喝、失望、看唐记三个节拍；第 3 镜不再在同一镜头内出现两个说话人；第 9 镜不会把街道和店内放进同一分镜；“骂完”不再要求新增台词；单时间帧台词超容量被拒绝。

#### 验证

在正式库副本上重拆第 1、2、3、9 镜，计划门禁通过且镜头数量、时长、覆盖下限不下降。

### 计划点 3：边界与帧锚点

#### 要求

把连续边界从文字描述升级为可见状态加尾帧到首帧的视觉锚点。

#### 约束

没有尾帧不得声称连续；切镜必须显式声明；首帧状态必须与上一镜尾帧一致；优化单镜时必须读取尾帧信息。

#### 参考

第 2 镜结尾与第 3 镜开头的姿势、手势、道具断点；第 3 镜使用尾帧后上下文改善；第 9 镜回店动作未执行。

#### 设计

边界契约保存上一镜尾帧地址或指纹、下一镜首帧地址或指纹、手部姿势、视线、身体朝向、道具位置、过渡类型和连续模式。连续模式要求尾帧作为首帧；无尾帧时自动改为切镜。单镜优化在存在尾帧时必须加入“零秒从首帧姿势继续”的约束，禁止重新摆姿势。

#### 自测

连续边界缺尾帧被拒绝；首帧与零秒描述不一致被拒绝；切镜不要求尾帧；优化后的提示词保留首帧承接说明。

#### 验证

第 3 镜从第 2 镜末帧开始，手部姿势和道具位置连续；六婶入画前不重新摆摊；第 9 镜不再出现“说回店但画面在门口”的断点。

### 计划点 4：渲染输入与 Picture 编号隔离

#### 要求

首帧、尾帧和普通参考图使用独立角色；本地 H3 fl2v 首帧占 Picture 1，timeline guide 首尾帧不占编号。

#### 约束

fl2v 首帧进入 Picture 1 且不得再作为普通参考图重复占位；timeline guide 不进入索引；提示词预览与实际请求同一编号；任何越界编号在请求前拒绝。

#### 参考

标准 fl2v 首帧实际占 Picture 1；4.0.44 曾按“引导图不占编号”排成场景 1/贾 2/六 3，task 693 仍出现人物错位，证明该约定不适用于本地 fl2v。

#### 设计

渲染输入计划先确定首帧、尾帧和普通参考图三个列表，再按运行时语义生成 Picture 编号。本地 H3 fl2v 首帧占 Picture 1，场景引用复用首帧，人物参考从 2 起并优先保留；timeline guide 只用文字承接。生成请求构造完成后，用实际图片位校验提示词中的所有 Picture 编号。最终提示词预览复用同一映射。

#### 自测

本地 H3 fl2v：首帧为 Picture 1（街道复用首帧场景），贾婆子为 Picture 2、六婶为 Picture 3，不出现 Picture 4；场景参考不再单独占位；越界编号被拒绝。timeline guide 仍不占编号。

#### 验证

第 3 镜重新生成时六婶使用正确参考图，人物身份与角色资产一致；最终提示词预览编号与实际请求一致。

### 计划点 5：H3 说话人与能力适配

#### 要求

把 H3 的多说话人限制、台词标签和字幕行为纳入能力档位，拆分时主动规避。

#### 约束

一个分镜一个说话人；多角色同框必须写明听众闭嘴；一个说话人尽量只用一个台词标签；台词超容量拆分镜；字幕烧入进入后处理策略，不能依赖负面提示词。

#### 参考

第 3 镜第一句口型落在六婶身上；三段台词标签导致说话人漂移；第 2 镜原生音频拖长叫卖；第 3 镜字幕烧入。

#### 设计

H3 档位默认单人说话镜头；双人同框只允许一个说话人，并明确其他角色嘴唇闭合。同一说话人的整句台词优先合并为一个标签；装不下时拆分镜。正反打优先于双人轮流说话。字幕检测放到生成后门禁，发现烧字幕后进入裁切或后期配音策略。

#### 自测

第 3 镜只有贾婆子张嘴；六婶保持听姿和闭嘴；台词不再拆成三个标签；字幕烧入被记录并可选后处理。

#### 验证

重生成第 3 镜抽帧检查：第一句、第二句、第三句均由贾婆子发声，六婶嘴唇闭合；字幕策略明确。

### 计划点 6：四层门禁与失败策略

#### 要求

建立计划、渲染、生成请求、生成后四层门禁，所有失败回到拆分。

#### 约束

不允许通过只改提示词绕过门禁；不允许静默修改模型配置；跳过镜头仍保留问题标记；生成后验证必须使用实际帧和音轨。

#### 参考

现有计划门禁、逐镜校验、H3 任务日志、实际视频抽帧结果。

#### 设计

计划门禁检查场景、节拍、说话人、容量、端点、场景常量和帧锚点；渲染门禁检查调度 purity、时间帧焦点、听众闭嘴、首帧承接；请求门禁检查图片角色和 Picture 范围；生成后门禁抽零秒帧、中间帧、说话段和字幕，检查动作、人物身份、口型和道具。失败统一回到拆分，不允许继续消耗生成次数。

#### 自测

多节拍、多说话人、跨地点、无尾帧连续、Picture 越界、错误说话人均被拦截；跳过镜头允许生成但必须带标记和生成后检查。

#### 验证

在正式库副本上运行第 1、2、3、9 镜，四层门禁均能给出结构化问题并阻止错误生成。

### 计划点 7：迁移与四镜验收

#### 要求

在正式库副本上完成旧数据迁移和四镜重拆验证，再决定是否覆盖正式集。

#### 约束

不直接修改正式库；不覆盖已完成且用户确认的镜头；构建、安装、提交单独授权；验证使用实际生成视频和抽帧，不只用单元测试。

#### 参考

正式库第 9 集第 1、2、3、9 镜；现有任务 684、686、687；场景 38 与角色 25、26 的绑定关系。

#### 设计

先复制正式库，执行数据迁移和契约补齐，再重拆第 1、2、3、9 镜。第 1 镜作为场景建立，第 2 镜拆为吆喝和失望两个节拍或压缩为一个动作，第 3 镜拆为六婶入画与贾婆子说话两个镜头并使用尾帧，第 9 镜拆为外景和内景或保留门槛外。每一镜生成后抽帧核对动作、说话人、参考图和字幕。

#### 自测

第 2 镜台词容量不过载；第 3 镜六婶身份正确且只有贾婆子说话；第 9 镜不跨地点；所有 Picture 编号不越界；生成后抽帧无动作断点和错误口型。

#### 验证

副本验证报告通过后，再决定是否覆盖正式集；正式库操作、构建、安装、提交均需单独确认。

## 7. 四镜处理建议

| 镜头 | 处理 |
|---|---|
| 第 1 镜 | 保留为空镜，建立街景、左右地标、光线、环境声；不定义人物轴线 |
| 第 2 镜 | 拆为吆喝和失望两个节拍，或压缩为一个动作；台词放零到五秒，五到八秒只做可见收势 |
| 第 3 镜 | 拆为六婶入画与贾婆子单人说话；使用第 2 镜尾帧；只有贾婆子说话，六婶闭嘴听 |
| 第 8 镜 | 修正描述与画面调度的左右矛盾，以场景契约为基准重校验 |
| 第 9 镜 | 拆为外景转身和内景看长队，或保留门槛外；修正“骂完”误判和轴线 A |

## 8. 验收标准

- 第 2 镜不再出现多节拍和台词超单帧容量。
- 第 3 镜从第 2 镜尾帧开始，六婶使用正确参考图，只有贾婆子说话。
- 第 8 镜左右矛盾被正确定位，第 9 镜不再被误判为翻转。
- 第 9 镜不跨地点，回店动作和场景一致。
- 所有 Picture 编号都在实际普通参考图范围内。
- 时间帧只推进同一动作，不引入新主体、地点或说话人。
- 生成后抽帧能发现动作断点、错误说话人、烧字幕和道具变化，并阻止错误镜头通过。

## 9. 风险与开放问题

| 风险 | 应对 |
|---|---|
| H3 仍不按时间帧执行 | 拆分成独立镜头，不依赖文本时间标记 |
| H3 多说话人绑定仍不稳定 | 优先单人镜头或正反打；双人同框明确听众闭嘴 |
| 字幕烧入无法由提示词消除 | 生成后检测，进入裁切或后期配音策略 |
| 旧数据缺少场景契约 | 迁移时从首个建立镜头和场景地理卡补齐，无法补齐的标为待人工 |
| 参考图索引修复影响旧任务 | 新请求使用新编号；历史任务只读不回写 |
| 用户已确认镜头被误覆盖 | 迁移和重拆只操作副本，正式集覆盖单独确认 |

## 10. 变更边界

- 本方案只定义拆分架构、渲染输入契约和门禁；不在设计文档中写实现代码。
- 不修改用户已确认的模型配置和生成参数。
- 不删除旧数据；迁移和重拆先在正式库副本执行。
- 构建、安装、提交、推送不属于本方案执行范围，需要单独授权。
