## 0. 一页结论

### 0.1 现在的问题

1. **拆分单位错了。** 当前一个分镜行是 8–15 秒「段落」，内部允许 2–4 个子镜头切镜（见 `backend/workspace/prompts/storyboard_breaker.md` 的核心定义）。但内部切镜只是提示词里的一段文字，不是独立生成、独立剪辑的镜头。模型在一次生成里要完成「单人 + 群像」「对话 + 反应」两个调度，第二个经常被丢掉。
2. **没有场景地理。** 分镜行只绑 `scene_id` 和一张场景参考图，没有桌面/窗/门/人物站位的唯一布局。每个镜头独立生成，模型每次重新想象房间。
3. **没有覆盖计划。** 只有段落下限，没有上限、没有总时长预算、没有建立镜头/正反打/反应镜头/插入镜头的覆盖要求，也没有轴线定义。
4. **没有镜头合同。** 视频提示词由 Agent 自由写，系统只补信息头。人物左右、过肩、轴线、谁在画、谁在画外、动作起止、视线目标都不是结构字段。
5. **校验只看文本。** 现行动作检验 5 类检查、语义窗口和成对判定都基于文本上下文；不看成片，也没有生成后验收。
6. **页面以「分镜行 + 提示词文本框」为中心。** 看不到场景地理、覆盖缺口、轴线、人物在场，也看不到生成后的对照。

### 0.2 新设计

| 维度 | 现在 | 新设计 |
|---|---|---|
| 拆分单位 | 8–15 秒段落，内含 2–4 子镜 | **一个分镜行 = 一个机位 / 一个主体 / 一个连续动作**；跨主体、跨机位必须新行；长镜头只允许同机位连续运动 |
| 拆分依据 | 剧本 + 资产 + 方案文本；只有段落下限 | **场景地理 + 覆盖计划 + 时长预算 + 覆盖模板 + 镜头合同** |
| 提示词 | Agent 自由写，系统补信息头 | **合同渲染**：信息头、画面调度、时间轴、台词、负面约束由系统生成；高级可覆盖，但覆盖要重新校验 |
| 校验 | 5 类文本规则 + 语义窗口，不看生成 | **三层**：合同校验、视觉预检、生成后验收；成对检查轴线、场景、人物在场 |
| 页面 | 平铺分镜列表 + 提示词文本框 | **场景导航 + 覆盖板 + 场景地理卡 + 镜头合同 + 成对检查 + 生成队列** |
| 16–19 问题 | 只能在成片后发现 | 在覆盖计划/合同阶段拦住，生成后再验收 |

### 0.3 四个必须记住的决定

1. **默认「逐镜精确」**：对话、连续性关键场景，一行只做一个 setup；「长镜头省算力」只允许同一机位连续运动，不允许跨主体/跨机位切。
2. **合同是唯一源**：`video_prompt` 是镜头合同的投影，不是源文件；系统渲染骨架，Agent 只写画面文采。
3. **先计划后生成**：没有覆盖计划、没有轴线、没有人物在场表、没有参考图的镜头，不允许进入生成队列。
4. **知识按 Agent 分配**：不做全员共读；分镜拆分、分镜校验、视频提示词等关键 Agent 开工前必须读取自己的知识库，必读缺失直接阻断。

### 1.2 现行字段够不够

`storyboards` 现在有：`title`、`shot_type`、`angle`、`movement`、`description`、`result`、`atmosphere`、`image_prompt`、`video_prompt`、`bgm_prompt`、`sound_effect`、`transition`、`continuity`、`duration`、`scene_id`、`character_ids`、`prop_ids`、`first/last_frame_image`、`reference_images`。

缺的是：覆盖类型、轴线、屏幕左右、过肩、画内/画外人物、动作起止、视线目标、场景地理、机位侧、声音计划、BGM 点、负面约束、合同版本。

### 1.3 16–19 的证据

| 镜 | 成片事实 | 结构缺口 |
|---|---|---|
| 16 | 范左/唐右；9–12 秒提示词写「唐聆听、范公子冷笑」，成片只有唐 | 没有画内/画外人物表；反应被塞进别人主导的 3 秒段 |
| 17 | 唐左/范右；「逼近」只靠推镜，人物没离桌 | 没有动作起止；没有尾帧/首帧衔接 |
| 18 | 开头右前景空，范 5 秒才从右入画；窗从唐后左跑到范后右 | 没有场景地理；没有反打前景肩；没有首帧约束 |
| 19 | 唐单人朝左；尾段二老也朝左；孙郎中回归；范公子没出现 | 没有屏幕方向；没有单人/群像的成对关系；没有反应覆盖 |

这四镜不是「提示词写得不好」，是**没有结构字段可写**。现行提示词里能写的只有台词和动作结果，写不了「谁在画面左、谁在画面右、过谁的肩、背景窗在哪、上一镜尾帧是什么」。

### 1.4 根因

1. **生成单位是 8–15 秒多子镜段落**，内部切镜不可控；模型一次生成里只能保住一个主调度。
2. **没有场景地理**，每个镜头独立生成，空间靠模型即兴。
3. **没有覆盖计划**，建立/正反打/反应/插入没有强制项，轴线没有分配。
4. **没有镜头合同**，prompt 是自由文本，人物左右、过肩、画内画外、动作匹配都不是字段。
5. **审核是文本审核**，不看成片；没有视觉预检，也没有生成后验收。
6. **页面以单镜和 prompt 为中心**，用户看不到覆盖、轴线、人物在场，只能等成片出来再发现问题。

## 2. 设计目标与原则

### 2.1 目标

| 目标 | 可验证的结果 |
|---|---|
| G1 连贯性由结构保证 | 轴线、屏幕方向、画内人物、动作起止是字段，不靠模型自觉 |
| G2 先覆盖后文采 | 覆盖计划先过，才允许写镜头合同和提示词 |
| G3 场景地理唯一 | 每个场景一张 canonical 地理卡，所有镜头共用 |
| G4 人物在场明确 | 每镜都有画内/画外人物表，参考图只送画内人物 |
| G5 时长预算可控 | 集/场/镜三级上下限，超预算直接阻断 |
| G6 合同是唯一源 | 提示词可重渲染，合同不变则提示词不漂 |
| G7 生成前拦住、生成后验收 | L1/L2 门禁 + L3 验收报告 |
| G8 UI 让问题可见 | 覆盖缺口、轴线、人物在场、场景地理在页面上一眼可见 |

### 2.2 原则

1. **一个分镜行 = 一个机位 / 一个主体 / 一个连续动作。** 换主体、换机位、换场景，必须新行。
2. **先计划后生成。** 没有覆盖计划和镜头合同，不允许生成。
3. **结构化字段优先于自然语言。** 能用字段表达的，不写进 prompt。
4. **规则可解释、可修复、可门禁。** 每条问题都要有证据、建议动作和门禁级别。
5. **默认精确，经济可选。** 对话/连续性场景用逐镜；空镜/蒙太奇可用长镜头。
6. **旧数据兼容。** 老分镜不强制重拆，按场景逐个升级；新集默认新链路。
7. **不用开放枚举。** 覆盖类型、过渡类型、声音类型、门禁状态都闭集。
8. **所有关键判断留证据。** 文本证据 + 帧证据 + 版本指纹，能回放。

| S1 | 场景剧本 | 集剧本 + 资产清单 | `scene_script[]` | — | 拆分向导第 1 步 |
| S2 | 场景地理与调度 | 场景剧本 + 场景图 + 角色图 | `scene_geography` + `blocking[]` | G1a | 场景地理卡 |
| S3 | 覆盖计划 | 场景剧本 + 地理 + 方案 profile | `coverage_plan` | G1 | 覆盖板/计划预览 |
| S4 | 镜头合同 | 覆盖单元 + 地理 + 资产 + 台词 | `shot_contract[]` | G2 | 镜头检查器 |
| S5 | 合同校验 | 合同 + 计划 + 资产 + 台词 | `validation_report` | G3a | 校验面板 |
| S6 | 视觉预检 | 合同 + 参考图 + 关键帧 | `visual_preflight_report` | G3b | 成对检查 |
| S7 | 生成 | 合同 + 参考图 + 首尾帧/上一镜尾帧 | `generation_request/result` | G3 | 生成队列 |
| S8 | 生成后验收 | 成片 + 合同 + 邻镜尾帧 + 参考图 | `acceptance_report` | G4 | 验收面板 |
| S9 | 集装配/终检 | 验收通过的片段 + 转场 + 声音/字幕 | `assembly_report` | G5 | 成片页 |

每个阶段的 Agent 在开工前加载自己的知识库（见第 8 节）：拆分读短剧语法/分镜导演/连贯过渡，校验读校验清单/连贯过渡，提示词读视频提示词/连贯过渡；小说改编、资产提取、声音设计各读自己的。知识库按 Agent 分配，不做全员共读。

### 3.2 门禁

| 门禁 | 名称 | 通过条件 | 不通过时 |
|---|---|---|---|
| G0 | 规格完整 | 画幅、模型、声音模式、时长预算、镜头数范围、覆盖模板齐全 | 不允许拆分 |
| G1a | 地理完整 | 每个新场景有地理卡，地标/机位/轴线齐全 | 不允许写覆盖计划 |
| G1 | 计划完整 | 每场有建立镜头；每个节拍有覆盖单元；每个说话人有镜头；每个听者有反应；时长在预算内；轴线已分配 | 不允许写合同 |
| G2 | 合同完整 | 画内/画外人物、屏幕左右、机位侧、动作起止、参考图、台词/声音类型齐全 | 不允许生成 |
| G3a | 合同校验 | L1 合同校验无 blocker | 不允许视觉预检 |
| G3b | 视觉预检 | L2 视觉预检无 blocker | 不允许生成 |
| G3 | 生成前 | G3a + G3b 均通过 | 生成按钮禁用，显示原因和修复入口 |
| G4 | 生成后 | 身份/场景/轴线/动作/在场/声音验收通过 | 不允许进入装配 |
| G5 | 导出 | 片段齐全、转场合法、声音/字幕/时长通过 | 不允许导出 |

知识库门禁（K0–K3）独立于 G0–G5 执行，见第 8 节：K0 索引有效；K1 关键 Agent 的必读知识存在；K2 任务开始前已加载并记录版本；K3 任务结果记录知识版本（知识变更只做软提醒，不自动作废项目数据）。

## 4. 输入输出契约

### 4.1 S0 集制作规格

**输入**：项目（题材、视觉风格、画幅、图片/视频模型）、集（剧本、时长目标、声音模式、分辨率）。

**输出**：`episode_production_spec`

| 字段 | 含义 | 必填 |
|---|---|---|
| drama_id / episode_id | 项目/集 | 是 |
| aspect_ratio | 16:9 / 9:16 / 1:1 等 | 是 |
| visual_style | 视觉风格 key | 是 |
| video_model / resolution | 本集锁定的视频模型与分辨率 | 是 |
| audio_mode | native / ambient / silent / dub | 是 |
| target_duration_sec | 目标总时长 | 是 |
| shot_count_min / max | 镜头数范围 | 是 |
| avg_shot_sec_target | 平均镜头时长目标 | 是 |
| coverage_template | 对话/动作/悬疑/蒙太奇/过渡 | 是 |

**拒绝条件**：画幅与方案画幅语法不一致；目标时长与镜头数范围矛盾；声音模式与台词/旁白策略冲突。

### 4.2 S1 场景剧本

**输入**：集剧本、项目/集资产（角色、场景、道具）、场次标记。

**输出**：`scene_script[]`

| 字段 | 含义 | 必填 |
|---|---|---|
| scene_script_id | 场景剧本 ID | 是 |
| scene_id | canonical 场景 ID | 是 |
| scene_no / location / time | 场次、地点、时间 | 是 |
| characters[] | 本场出现角色（canonical ID） | 是 |
| props[] | 本场关键道具 | 否 |
| beats[] | 叙事节拍：进入/发展/转折/揭示/反应/退出 | 是 |
| dialogue_lines[] | 台词行（说话人、类型、文本、情绪、目标时长） | 是 |
| actions[] | 关键动作（谁、做什么、对谁、结果） | 是 |
| estimated_duration | 本场预估时长 | 是 |
| continuity_notes | 与上一场/下一场的连接点 | 否 |

**拒绝条件**：场景无法匹配 canonical 场景；角色别名无法解析；台词没有说话人或类型。

### 4.3 S2 场景地理与调度

**输入**：场景剧本、canonical 场景参考图、角色参考图、上一场尾镜（如有）。

**输出**：`scene_geography` + `blocking[]`

| 字段 | 含义 | 必填 |
|---|---|---|
| geography_id / scene_id / version | 地理卡 ID、场景、版本 | 是 |
| layout | 俯视布局：桌、窗、门、柜台、入口、关键家具 | 是 |
| landmarks | 可被镜头拍到的地标及屏幕侧（窗左/门右/匾后等） | 是 |
| camera_sides | A/B 两个机位侧，及各自能看到的地标 | 是 |
| axis_line | 主要人物关系轴线 | 是 |
| cast_positions[] | 每个节拍的角色位置、朝向、距离 | 是 |
| entries_exits[] | 谁从哪进/出、在哪个节拍 | 是 |
| lighting_time | 光线、时间、季节、天气 | 是 |
| reference_image_ids | 场景图、角色图、道具图 | 是 |
| canonical_scene_id | 唯一场景资产 ID | 是 |

`blocking[]` 字段：`beat_id`、`character_id`、`position`、`facing`、`distance_to`、`action_start`、`action_end`、`entry/exit`。

**拒绝条件**：同一场景有多张同名不同布局的参考图；关键地标没有屏幕侧；轴线没有定义；角色站位与上一场尾镜冲突。

### 4.4 S3 覆盖计划

**输入**：场景剧本、场景地理、BreakdownProfile、时长预算。

**输出**：`coverage_plan`

| 字段 | 含义 | 必填 |
|---|---|---|
| plan_id / episode_id / scene_id | 计划 ID、集、场景 | 是 |
| profile_key / version | 拆分方案 key 与版本 | 是 |
| target_duration_sec / shot_count_range | 本场时长预算与镜头数范围 | 是 |
| units[] | 覆盖单元列表 | 是 |
| coverage_summary | 各覆盖类型的数量与缺口 | 是 |

`units[]` 每个覆盖单元：

| 字段 | 含义 | 必填 |
|---|---|---|
| unit_id | 单元 ID | 是 |
| beat_id | 所属节拍 | 是 |
| narrative_function | 建立/发展/转折/揭示/反应/退出 | 是 |
| coverage_type | establishing / master / two_shot / ots / single / reaction / insert / pov / action / transition / long_take | 是 |
| subject | 主主体（角色/道具/环境） | 是 |
| cast_on_screen[] | 画内人物 | 是 |
| cast_off_screen[] | 画外人物 | 是 |
| screen_left[] / screen_right[] | 屏幕左右人物 | 是 |
| foreground_shoulder | 过肩：无/左/右 + 谁的肩 | 否 |
| camera_side | A / B / neutral | 是 |
| axis_side | A / B | 是 |
| shot_size / angle / movement | 景别/角度/运镜 | 是 |
| duration_min / max | 本单元时长范围 | 是 |
| dialogue_line_ids[] | 本单元承载的台词 | 否 |
| dialogue_capacity_sec | 台词容量估算 | 否 |
| relation_prev / relation_next | 正反打/动作匹配/视线匹配/时间跳/新场景 | 是 |
| transition_in / out | 剪辑转场 cut/fade/dissolve/wipe；如需要过渡分镜，填 transition_shot_id | 是 |
| geography_ref | 场景地理版本 | 是 |
| risk_flags[] | 轴线交叉/人物丢失/场景翻面/道具特写等 | 否 |
| required | must / should / optional | 是 |

**覆盖模板的最低要求**：

| 模板 | 最低覆盖 |
|---|---|
| 对话 | 每场 1 个 establishing；每 2–4 人 1 个 master/two-shot；每个说话人至少 1 个 OTS/single；每个听者至少 1 个 reaction；关键道具/信息 1 个 insert |
| 动作 | 1 个 establishing；1 个 wide/action；1 个 impact/close；1 个 reaction；1 个 insert（可选） |
| 悬疑 | 1 个 establishing；1 个 detail insert；1 个 POV；1 个 reaction；1 个 reveal |
| 蒙太奇 | wide/medium/close 混合；无对白；每 2–4 秒一个信息增量 |
| 过渡 | 时间空镜/场景空镜/人物空镜/插入/文字；闭集；1–4 秒；必须写清 from→to 和时间/地点/人物线索 |

**拒绝条件**：缺 establishing；缺说话人镜头；缺听者反应；时长超上限；轴线未分配；覆盖类型与画幅语法冲突（例如 9:16 方案套 16:9）。

### 4.5 S4 镜头合同

**输入**：覆盖单元、场景地理、资产、台词行、上一镜尾帧。

**输出**：`shot_contract`

| 组 | 字段 | 含义 | 必填 |
|---|---|---|---|
| 身份 | contract_id / storyboard_id / plan_unit_id / version | 合同 ID、分镜行、覆盖单元、版本 | 是 |
| 身份 | scene_id / geography_id / beat_id | 场景、地理、节拍 | 是 |
| 身份 | coverage_type | 覆盖类型（闭集） | 是 |
| 叙事 | narrative_function / result / emotion / information_delta | 叙事功能、结尾结果、情绪、信息增量 | 是 |
| 空间 | camera_side / axis_side | 机位侧、轴线侧 | 是 |
| 空间 | screen_left / screen_right | 屏幕左右人物/主体 | 是 |
| 空间 | foreground_shoulder | 过肩：无/左/右 + 谁 | 否 |
| 空间 | background_landmarks | 背景地标及屏幕侧 | 是 |
| 空间 | blocking_start / blocking_end | 动作起止站位 | 是 |
| 人物 | cast_on_screen / cast_off_screen | 画内/画外人物 | 是 |
| 人物 | gaze_target / entries_exits | 视线目标、进出 | 否 |
| 人物 | lip_sync | 是否需要对口型 | 是 |
| 镜头 | shot_size / angle / movement / lens / composition | 景别/角度/运镜/镜头/构图 | 是 |
| 动作 | action_start / action_end / match_point | 动作起止、匹配点 | 是 |
| 台词 | line_ids / voice_type | 台词行、对白/画外音/内心/旁白 | 否 |
| 声音 | ambient / bgm_cue / silence | 环境声、BGM 点、静默 | 否 |
| 连续 | prev_shot_id / next_shot_id / relation | 前后镜、关系 | 是 |
| 连续 | start_frame_ref / tail_frame_ref | 首帧/尾帧参考 | 否 |
| 生成 | refs / negative / duration / aspect_ratio / seed | 参考图、负面、时长、画幅、种子 | 是 |
| 校验 | required_checks / gate | 必过检查、门禁 | 是 |

**合同渲染成视频提示词的规则**：

1. 信息头只写 `cast_on_screen` + canonical 场景名；`cast_off_screen` 不进信息头。
2. 第二行写「画面调度」：屏幕左是谁、屏幕右是谁、过谁的肩、背景窗/门/桌在哪、轴线侧。
3. 时间轴按覆盖单元的节拍切成 3 秒段；最后一段结束时间等于 `duration`。
4. 台词从 `storyboard_lines` 取，对白/画外音/内心/旁白分别渲染；需要发声的包 `<d>`；画外音标记 `lip_sync=false`，画面中角色不张口。
5. 负面约束由合同生成：只出现画内人物；不换脸/换装/加人；不生成字幕；不出现现代物品；不出现错误招牌/匾额。
6. Agent 只写画面文采（动作、表情、光线），不写信息头、时间轴、画内人物表、负面约束。
7. 高级用户覆盖提示词后，渲染器保留原稿，但校验会比较合同与提示词，不一致则阻断。

**拒绝条件**：画内人物未绑定/无参考图；场景地理缺失；轴线/屏幕方向缺失；动作起止缺失；时长超出范围；台词行与合同不匹配；首帧/尾帧参考与上一镜冲突。

### 4.6 S5 合同校验报告

**输出**：`validation_report`

| 字段 | 含义 |
|---|---|
| report_id / plan_version / contract_version | 报告 ID、计划/合同版本 |
| gate_status | pass / warn / block |
| issues[] | 问题列表 |
| summary | 按检查、严重度、可修复数统计 |

每个 issue：`issue_id`、`code`、`check`、`severity`、`gate`、`shot_id`、`related_shot_ids`、`evidence_text`、`evidence_frame_ids`、`suggestion`、`fix_action`、`auto_fixable`、`owner`、`status`、`fingerprint`。

### 4.7 S6 视觉预检报告

**输入**：合同、场景地理卡、参考图、关键帧/构图草稿。

**输出**：`visual_preflight_report`

| 检查 | 输出 |
|---|---|
| 身份 | 画内人物与参考图的相似度/差异点 |
| 场景 | 背景地标、窗/门/桌位置是否与地理卡一致 |
| 轴线 | 人物左右、视线方向、过肩侧是否与合同一致 |
| 调度 | 站位、距离、动作起止是否可执行 |
| 构图 | 景别、主体位置、前/中/后景是否成立 |
| 结论 | pass / warn / block + 证据图 + 修复建议 |

**说明**：视觉预检不要求每个镜头都生成完整关键帧；默认对对话/连续性关键镜头生成构图草稿或使用场景图 + 人物图 + 俯视图做 AI 预检；蒙太奇/空镜可跳过。

### 4.8 S7 生成请求/结果

**输入**：合同、参考图、首帧/尾帧、上一镜尾帧、模型配置。

**输出**：`generation_request` + `generation_result`

`generation_request` 字段：`request_id`、`contract_id`、`prompt`（渲染版本）、`prompt_version`、`scene_ref`、`cast_refs[]`、`prop_refs[]`、`first_frame`、`last_frame`、`prev_tail_frame`、`seed`、`duration`、`aspect_ratio`、`resolution`、`audio_mode`、`generate_audio`、`model`、`config_id`、`negative_prompt`。

`generation_result` 字段：`task_id`、`video_url`、`duration`、`frames`、`audio`、`status`、`error`。

**关键变化**：

1. 只送画内人物参考图，不送画外人物。
2. 默认把上一镜尾帧作为本镜首帧参考；没有尾帧的镜头必须标记 `start_frame_ref=null` 并说明原因。
3. 逐镜串行生成，保证下一镜能拿到上一镜尾帧；批量并发生成只用于无连续性要求的空镜/蒙太奇。
4. 请求快照入库，生成后可按合同/版本复现。

### 4.9 S8 生成后验收报告

**输入**：成片、合同、参考图、邻镜尾帧、台词/字幕。

**输出**：`acceptance_report`

| 检查 | 内容 |
|---|---|
| 身份 | 画内人物是否与参考图一致；有没有换脸/换装/加人 |
| 场景 | 背景地标、窗/门/桌、季节/光线是否与地理卡一致 |
| 轴线 | 人物左右、视线、过肩侧是否与合同/上一镜一致 |
| 动作 | 动作起止是否与合同匹配；与上一镜尾帧是否动作匹配 |
| 在场 | 画内人物是否齐全；画外人物是否误入 |
| 道具 | 关键道具外观/位置是否正确 |
| 声音 | 对白/旁白是否发声；口型是否匹配；环境声/BGM 是否合理 |
| 文本 | 字幕/画面文字是否正确；有没有乱码/错字 |

输出：`verdict`（pass/warn/fail）、每项分数、证据帧、修复动作（接受/重生成/裁切/换参考图/改合同）。

### 4.10 S9 集装配/终检

**输入**：验收通过的片段、转场计划、声音/BGM、字幕、片头片尾。

**输出**：`assembly_report`：成片地址、时长、转场清单、声音清单、字幕清单、QA 结论。

| `breakdown_profiles` | `key`、`version`、`profile_json`、`prompt/skill` | 把拆分方案从纯文本升级为 profile |
| `asset_aliases` | `asset_type`、`alias`、`canonical_id` | 角色/场景/道具别名归一 |
| `knowledge_index`（文件） | `items[]`：`id`、`name`、`description`、`agents`、`required`、`enabled` | Agent 专用知识库的分配表；文件在 `workspace/knowledge/index.json` |

### 5.2 兼容与迁移

1. 新字段全部可空，默认 `contract_version=0`，旧分镜标记「legacy」，不阻断现有链路。
2. 旧分镜的 `cast_on_screen` 从 `video_prompt` 信息头解析；`coverage_type` 从 `shot_type` 映射；`axis_side=unknown`；在 UI 上显示「待补合同」。
3. 场景 canonical 化：同一 `location` 只保留一张 canonical 场景图；旧图作为别名/历史版本保留，不直接删除；54/55/56 这类同名不同图的场景必须合并到一个 canonical ID，旧 ID 做映射。
4. 角色别名：`唐大郎`、`唐大郎（唐奕）`、`唐奕` 统一到一个 canonical 角色；`@` 解析和合同都走别名表。
5. 道具参考图 QA：关键道具必须有白底图；图像语义与道具名不符的标记为「参考图待替换」，不允许绑定到生成。
6. 迁移按场景进行，不做整集强制重拆；新集默认新链路。

### 5.3 版本与失效

- `plan_version`、`contract_version`、`prompt_version`、`audit_version` 四级指纹。
- 任一上游变化（计划/合同/参考图/台词）使下游审核与验收失效；UI 显示「已失效」，门禁不能使用旧结果。
- 生成请求保存合同版本；重生成时若合同已变，必须重新校验。

## 6. 拆分设计

### 6.1 拆分单位：从「段落」改为「镜头单元」

| 模式 | 单位 | 时长 | 允许内部切镜 | 适用 |
|---|---|---|---|---|
| 逐镜精确（默认） | 一个机位/一个主体/一个连续动作 | 3–8 秒，最大 10 秒 | 不允许跨主体/跨机位切 | 对话、连续性关键、正反打、反应 |
| 长镜头省算力（可选） | 一个连续长镜头 | 8–15 秒 | 只允许同机位推拉摇移，不允许切 | 空镜、环境建立、蒙太奇、过渡 |
| 过渡/空镜 | 一个环境/物件/文字 | 1–3 秒 | 不允许 | 场间转场 |

**为什么改**：16/19 的「单人 + 反应/群像」被塞进一条 12 秒视频，模型只保住主调度；17/18 的「推镜 + 反打」在同一条里无法保证首尾帧。一个 setup 一行，才能独立生成、独立剪辑、独立验收。

**代价**：镜头行数增加，生成任务数增加；用队列、批量、经济模式控制成本。默认对话场景用逐镜，空镜/蒙太奇用长镜头。

### 6.2 BreakdownProfile

| 字段 | 含义 |
|---|---|
| `format` | 画幅与画幅语法：16:9 横屏 / 9:16 竖屏 / 1:1 |
| `genre` | 题材：都市/古装/悬疑/喜剧/动作等 |
| `target_duration_sec` | 集目标时长 |
| `shot_count_min/max` | 镜头数范围 |
| `avg_shot_sec_min/max` | 平均镜头时长范围 |
| `shot_size_distribution` | 远景/全景/中景/近景/特写的比例 |
| `movement_ratio` | 固定/推拉/摇移/跟拍的比例 |
| `dialogue_density` | 对白密度：高/中/低 |
| `coverage_template` | 对话/动作/悬疑/蒙太奇/过渡 |
| `axis_rules` | 轴线策略：严格/允许中性镜头越轴/手持自由 |
| `transition_policy` | 转场策略：cut 为主/允许 fade/dissolve/wipe |
| `audio_policy` | native/ambient/silent/dub；旁白/BGM 策略 |
| `validation_profile` | 哪些检查是 blocker，哪些是 warning |

内置六套方案（含 `hook-beat-extended`）升级为 profile + prompt/skill；prompt/skill 只保留风格文本，时长、镜头数、覆盖模板、校验 profile 由 profile 控制。自定义方案同样走 profile；版本化的 profile 随拆分任务记录，旧集不受新版本影响。

### 6.3 覆盖计划算法

1. **场次节拍化**：把场景剧本切成进入/发展/转折/揭示/反应/退出六类节拍。
2. **时长分配**：按节拍信息量分配本场预算；每场有 `target_duration` 和 `shot_count_range`。
3. **模板选择**：按场景类型选对话/动作/悬疑/蒙太奇/过渡模板。
4. **覆盖单元放置**：
   - 每场先放 establishing（建立空间/人物关系）。
   - 对话场放 master/two-shot，再放说话人 OTS/single，再放听者 reaction。
   - 关键信息/道具放 insert。
   - 场尾需要过渡时放 transition（闭集）。
5. **轴线与屏幕方向分配**：
   - 选一条主轴线（通常是两个主要人物的连线）。
   - 分配 A/B 机位侧；同一侧镜头人物左右不镜像。
   - 正反打只换前景肩，不换人物左右；需要越轴时用中性镜头（establishing/insert）过渡。
6. **关系生成**：为每对相邻单元生成 `relation`（正反打/动作匹配/视线匹配/时间跳/新场景）和期望屏幕方向。
7. **覆盖检查**：缺 establishing、缺说话人、缺听者反应、缺 insert、超预算、镜头数越界，直接拒绝。
8. **输出计划**：UI 预览；用户可拖动/增删单元，但每次改动重新跑覆盖检查。

### 6.4 镜头合同与提示词渲染

**合同是源，提示词是投影。** 渲染器固定生成：

- 信息头：`出场人物：@画内人物｜场景：@canonical场景`
- 画面调度：`画面左：A；画面右：B；过B右肩；窗在左后；门在右后；轴线A侧`
- 时间轴：按节拍切 3 秒段，最后一段结束于 `duration`
- 台词/旁白：从 `storyboard_lines` 取，按 `voice_type` 包 `<d>`；画外音不张口
- 负面约束：只出现画内人物；不换脸/换装/加人；不生成字幕；不出现现代物品/错误招牌

Agent 只写：画面动作、表情、光线、氛围、构图文采。这样 16–19 的「人物左右、过肩、窗侧、画内人物、时间轴、旁白」不再靠模型自由发挥。

**高级覆盖**：用户可以直接改 `video_prompt`，但系统保存「合同渲染版」和「用户覆盖版」两份；校验比较两者，差异涉及画内人物/轴线/时间轴/台词时阻断生成。

### 6.5 拆分 Agent 的输入输出

**工具顺序**：

1. `read_storyboard_context`：读本场剧本、canonical 场景、角色/道具、别名、上一场尾镜合同摘要。
2. `save_scene_geography`：保存/复用场景地理卡；新场景必须先建卡。
3. `save_coverage_plan`：保存覆盖计划；计划不过不允许下一步。
4. `save_storyboards`：按覆盖单元逐条保存镜头合同；每条合同对应一个分镜行。
5. `validate_storyboards`：保存后自动校验；blocker 返回给 Agent 修复。

**分块方式**：从「1200 字硬切」改为「按场次切」；单场过长按节拍切，但必须带上一场的尾镜合同摘要（画内人物、屏幕左右、轴线、尾帧）。跨块的 `continuity` 从自由文本改为合同字段。

**拒绝保存**：无覆盖计划；合同与计划单元不一致；画内人物未绑定/无参考图；场景地理缺失；轴线/屏幕方向缺失；时长超范围；台词与合同不匹配。

### 6.6 拆分方案的管理

- 设置页从「方案名称 + prompt + skill」升级为「profile 摘要 + prompt + skill」。
- 方案卡片显示：画幅、目标时长、镜头数范围、覆盖模板、平均镜头时长、轴线策略、适用题材。
- 新建/编辑方案时，profile 用表单，prompt/skill 用文本；校验 profile 可选「严格/标准/宽松」。
- 旧方案自动生成默认 profile；不改变已有集的 `breakdown_method` 行为，直到用户升级。

### 6.7 前后分镜一致性协议

**一句话：相邻两镜不是靠“写得像”，而是靠一份成对合同 + 一张尾帧/首帧 + 三道校验。**

#### 6.7.1 每个切点一份成对合同

| 字段 | 说明 | 16–19 例子 |
|---|---|---|
| `relation` | 正反打/动作匹配/视线匹配/时间跳/新场景 | 17→18 正反打；18→19 正反打 |
| `axis_side` | 轴线 A/B | 17/18 都在 A 侧 |
| `screen_left / right` | 屏幕左右人物 | 唐左/范右 |
| `foreground_shoulder` | 过肩侧和谁的肩 | 17 过唐肩；18 过范肩 |
| `cast_end / cast_start` | 上一镜尾帧人物 vs 下一镜首帧人物 | 17 尾唐+范；18 首唐+范 |
| `blocking_end / start` | 尾站位/动作 vs 首站位/动作 | 17 尾范在右前一臂；18 首范肩在右前景 |
| `gaze_end / start` | 尾视线 vs 首视线 | 17 尾范看唐；18 首唐看范 |
| `prop_state` | 道具在谁手里/在桌上/被使用 | 碗在桌右；书在范手边 |
| `light_time` | 光线方向、时间、季节、天气 | 午后暖光、窗左 |
| `audio_bridge` | 环境声、BGM、台词是否连续 | 环境声延续；BGM 不换 |
| `tail_frame_ref` | 上一镜尾帧 | 作为下一镜首帧参考 |

#### 6.7.2 六条硬规则

1. **同场景同对话，只换机位/景别，不换屏幕左右。** 正反打只换前景肩，人物左右不动。
2. **越轴必须有中性镜头。** 需要翻面时，先插 establishing/insert 过渡，不允许硬切翻面。
3. **人物在场连续。** 上一镜尾帧有谁，下一镜首帧必须能接上；谁出画/入画必须有动作，不能瞬移。
4. **动作匹配。** 上一镜尾动作 = 下一镜首动作；不能靠观众猜。
5. **场景地理一致。** 同一面墙的地标不换边；窗/门/桌的位置来自地理卡，不靠模型即兴。
6. **声音桥不断。** 切点环境声/BGM/台词连续；需要静默时明确写 `silence`，不能默认断掉。

#### 6.7.3 三条生成链

- **首帧链**：上一镜尾帧作为本镜首帧参考；没有尾帧的镜头必须说明原因。
- **参考链**：只送画内人物 + 场景 + 关键道具；画外人物不送图。
- **验收链**：生成后把尾帧/首帧、人物、场景、轴线、动作、在场逐项对照。

#### 6.7.4 什么时候必须用过渡分镜

| 情况 | 必须的过渡 | 说明 |
|---|---|---|
| 同一场景，时间跳跃/光线变化 | 时间过渡空镜 | 用本场景已有地标和光线线索，不换房间 |
| 换地点/换场 | 场景过渡空镜 | 先建立新场景地理，再进人物 |
| 人物退出/进入/换人，轴线改变 | 人物过渡空镜 | 用脚步/背影/手/门帘/空椅接方向 |
| 信息/情绪/章节切换 | 插入或文字 | 道具特写、信件、地图、时间/地点卡 |
| 同场景连续对话 | 不需要过渡 | 直接正反打；插空镜反而打断反应 |

### 6.8 过渡分镜

**定义：过渡分镜是真实的分镜行，`coverage_type=transition`，有自己的 duration、合同、参考图和生成任务；不是只把下一镜的剪辑参数改成 `fade`。**

#### 6.8.1 五种过渡

| 类型 | 什么时候用 | 镜头内容 | 必须匹配 | 时长 | 禁止 |
|---|---|---|---|---|---|
| 时间过渡空镜 | 同场景时间跳跃、光线变化、等待 | 光影移动、蜡烛、蒸汽、钟表、窗外天色、落叶、茶凉 | 同场景地标、光线方向、季节、环境声 | 1–3 秒 | 换房间/换季节无提示 |
| 场景过渡空镜 | 换地点/换场 | 新场景建立：门、街、院落、招牌、桌面、交通工具 | 新场景地理卡、人物去向、声音桥 | 2–4 秒 | 用旧场景背景；不建立新空间就切人物 |
| 人物过渡空镜 | 人物进出/换人/视线转移 | 脚步、背影、手、门帘、放下/拿起物件、空椅 | 服装、道具、方向、轴线、尾帧 | 1–3 秒 | 用空镜掩盖人物瞬移；方向反了 |
| 插入镜头 | 信息/情绪/关键道具 | 信件、地图、手部、刀刃、碗筷、书页 | 道具状态、位置、光线 | 1–2 秒 | 无信息量的装饰空镜 |
| 文字卡 | 章节/时间/地点 | 时间、地点、章节、字幕卡 | 字体/风格/安全区 | 1–2 秒 | 开放枚举、无计划 |

#### 6.8.2 过渡分镜自己的合同

| 字段 | 说明 |
|---|---|
| `from_shot_id / to_shot_id` | 从哪镜来、到哪镜去 |
| `kind` | time_empty / scene_empty / character_empty / insert / text |
| `reason` | 时间跳/换场/人物进出/信息/情绪 |
| `time_cue` | 光影、天色、蜡烛、钟表、蒸汽等时间线索 |
| `location_cue` | 新场景的门/窗/桌/招牌/街道等地标 |
| `character_cue` | 脚步/背影/手/服装/道具/方向 |
| `cast_on_screen` | 过渡分镜里实际出现的人；通常为空，人物空镜可只拍局部 |
| `direction` | 出画/入画方向、轴线侧 |
| `light_time` | 与前后镜一致的光线/时间/季节 |
| `audio_bridge` | 环境声/BGM/台词是否延续 |
| `duration` | 1–4 秒，计入总时长和镜头数 |
| `geo_ref` | 时间空镜用本场景地理；场景空镜用新场景地理 |
| `tail_frame_ref / start_frame_ref` | 与前后镜的帧衔接 |

#### 6.8.3 插入位置与预算

- 过渡分镜写在覆盖计划里，位于两个覆盖单元之间；占时长、占镜头数。
- 同场景连续对话不插过渡；插了会打断反应和节奏。
- 一个场景边界最多一个过渡；不允许连续两个无信息空镜。
- 过渡不能用来掩盖动作不匹配或人物瞬移；能直接匹配的，用直接切。
- 时间空镜只在时间跳跃或光线变化明显时用；否则用 cut。
- 场景空镜必须建立新场景地理；人物空镜必须接住进出方向。

#### 6.8.4 过渡分镜的校验

| 规则码 | 检查 |
|---|---|
| `transition_kind_missing` | 该用过渡（换场/时间跳/人物进出）却没有，或类型用错 |
| `transition_geometry_mismatch` | 时间空镜换了房间；场景空镜没建立新地理 |
| `transition_cast_mismatch` | 人物空镜的服装/道具/人物与前后镜不一致 |
| `transition_light_mismatch` | 时间/光线/季节与前后镜不一致 |
| `transition_direction_mismatch` | 出画/入画方向或轴线与前后镜不一致 |
| `transition_overuse` | 过渡过多、无信息、连续空镜 |
| `transition_not_planned` | 过渡分镜不在覆盖计划里，临时插入 |

门禁：`transition_kind_missing`、`transition_geometry_mismatch`、`transition_cast_mismatch` 为 blocker；其余按 warning 处理。

#### 6.8.5 16–19 怎么用

- **17→18**：同场景、同对话，不需要过渡；要的是尾帧接首帧、过肩前景和同一面墙。插时间/场景空镜会打断“逼视→噎住”的反应。
- **18→19**：同场景、同对话，不需要过渡；需要的是正反打和群像反应。如果孙郎中/范公子需要先建立，用**人物插入镜头**（他们的反应），不要用时间/场景空镜。
- **19→20**：范仲淹/孙郎中退、范公子接话，是人物换位；适合插一个 1–2 秒**人物过渡空镜**（范/孙转身、范公子起身或手按桌面、空椅/桌沿），再接 20 的唐/范公子过肩。这样不会出现“人物洗牌”。
- **20→下一场**：换地点用**场景过渡空镜**；同地点时间跳跃用**时间过渡空镜**；同一场连续动作用直接切。

## 7. 校验设计

### 7.1 三层校验

| 层 | 时机 | 输入 | 输出 | 成本 |
|---|---|---|---|---|
| L1 合同校验 | 保存合同后、生成前 | 合同 + 计划 + 资产 + 台词 | 规则问题 + 门禁 | 低，纯规则 |
| L2 视觉预检 | 生成前 | 合同 + 地理 + 参考图 + 构图草稿/关键帧 | 身份/场景/轴线/构图问题 | 中，AI + 图 |
| L3 生成后验收 | 生成后 | 成片帧 + 合同 + 邻镜尾帧 + 参考图 | 验收报告 + 修复动作 | 中高，AI + 帧 |

### 7.2 检查矩阵

| 检查 | 层 | 内容 | 主要规则码 | 门禁 |
|---|---|---|---|---|
| C1 合同完整性 | L1 | 字段、时间轴、信息头、时长、画内人物 | 现有 `shot_missing_*`、`prompt_timeline_broken`、`prompt_missing_header` + 新增 `contract_field_missing`、`cast_table_missing` | G2/G3 |
| C2 连贯/轴线 | L1+L2 | 屏幕方向、正反打、过肩、30°、场景翻面、动作匹配、在场连续 | 现有 `continuity_missing`、`cross_scene_cut_without_continuity` + 新增 `axis_cross`、`screen_direction_flip`、`set_mirror`、`cast_presence_break`、`action_match_missing` | G3/G4 |
| C3 空镜/静默 | L1 | 长空镜、长静默 | 现有 `silent_shot_long`、`empty_shot_long` | G3 |
| C4 台词/声音 | L1 | 容量、逐字、旁白 `<d>`、声音类型、口型 | 现有 `line_*`、`shot_dialogue_over_capacity` + 新增 `voice_type_mismatch`、`narration_not_spoken`、`lip_sync_conflict` | G2/G3 |
| C5 资产/绑定 | L1 | 场景 canonical、角色/道具绑定、别名、参考图存在 | 现有 `scene_binding_*`、`character_*`、`prop_*`、`asset_file_missing` + 新增 `alias_unresolved`、`reference_image_missing`、`prop_image_semantic_mismatch` | G2/G3 |
| C6 覆盖完整性 | L1 | establishing/master/OTS/reaction/insert、说话人/听者、镜头多样性、重复/过拆 | 新增 `coverage_gap`、`speaker_uncovered`、`listener_reaction_missing`、`shot_duplicate`、`shot_over_split`、`shot_size_monotony` | G1/G2 |
| C7 场景地理 | L1+L2 | 窗/门/桌/地标、背景侧、季节/光线、轴线侧 | 新增 `landmark_missing`、`background_side_mismatch`、`season_light_break` | G3 |
| C8 视觉预检 | L2 | 身份、场景、轴线、构图、调度 | 新增 `preflight_identity`、`preflight_set`、`preflight_axis`、`preflight_blocking` | G3 |
| C9 生成后验收 | L3 | 身份、场景、轴线、动作、在场、道具、声音、文本 | 新增 `accept_identity`、`accept_set`、`accept_axis`、`accept_action`、`accept_presence`、`accept_prop`、`accept_audio`、`accept_text` | G4 |

### 7.3 问题模型与门禁

每个问题必须包含：

- `code`：闭集规则码。
- `check`：C1–C9。
- `severity`：error/warning/info。
- `gate`：G1–G4；error 默认阻断，warning 需确认，info 不阻断。
- `evidence`：文本证据 + 可选帧证据（shot_id、frame_time、region）。
- `related_shot_ids`：成对/跨镜问题必须列出。
- `suggestion`：可执行修复建议。
- `fix_action`：`normalize_header`、`normalize_timeline`、`bind_cast`、`fix_axis`、`add_reaction_shot`、`split_shot`、`merge_shot`、`rewrite_contract`、`regenerate`、`manual`。
- `auto_fixable`：是否可自动修。
- `owner`：system/agent/human。
- `status`：open/fixed/manual/stale/rolled_back。
- `fingerprint`：合同/计划/资产版本；任一变化即失效。

### 7.4 修复动作

| 类型 | 动作 | 适用 |
|---|---|---|
| 确定性修复 | 信息头、时间轴、时长、转场、参考图绑定、别名归一 | C1/C4/C5 |
| AI 修复 | 重排覆盖、补反应镜头、改轴线/站位、重写合同、拆/并镜头 | C2/C6/C7 |
| 重生成 | 用上一镜尾帧 + 合同重生成；最多 2 次；超过转人工 | C8/C9 |
| 人工 | 剧本歧义、资产缺失、创作选择 | 所有 |

自动修复必须保留原值和修复值，支持回滚；修复后重新跑对应层校验，不能直接跳过门禁。

### 7.5 生成后验收

1. 抽帧：首帧、1/4、1/2、3/4、尾帧；与上一镜尾帧并排。
2. 身份：画内人物 vs 角色参考图；检查换脸/换装/加人。
3. 场景：背景地标 vs 场景地理卡；检查窗/门/桌/季节/光线。
4. 轴线：人物左右/视线/过肩 vs 合同和上一镜；检查翻面。
5. 动作：尾帧动作 vs 合同 `action_end`；检查动作匹配。
6. 在场：画内人物是否齐全；画外人物是否误入。
7. 道具：关键道具外观/位置。
8. 声音：对白/旁白是否发声；口型；环境声/BGM。
9. 文本：字幕/画面文字。

验收结论：`pass` 进入装配；`warn` 可接受但记录；`fail` 重生成/改合同/换参考图/人工。

### 7.6 失效与版本

- 任何合同/计划/参考图/台词变更，都会让下游校验与验收失效；UI 显示「已失效」，门禁不能使用旧结果。
- 审核任务记录 `plan_version`、`contract_version`、`prompt_version`；报告里展示版本。
- 旧审核结果不删，只标记 stale；用户可查看历史，但不能作为门禁依据。
- 生成门禁对 stale 的处理：最新审计早于分镜 `updatedAt`，或 `shot_status.stale=true` 时，旧 error 不再作为 blocker；返回 `audit_stale` 警告，要求重跑审计。

### 7.7 度量

| 指标 | 目标 |
|---|---|
| 覆盖完整率 | 100% 场景/节拍/说话人/听者 |
| 轴线/场景/在场首过率 | ≥ 90% |
| 生成首过验收率 | ≥ 70% |
| 重生成率 | < 20% |
| 人工修复率 | < 10% |
| 时长预算偏差 | ±10% |
| 单集制作时间 | 不超过现在的 120% |

## 8. Agent 专用知识库

### 8.1 原则

- **知识库是通用方法论，不是项目数据。** 项目事实（剧本、角色、场景、道具、台词）仍由工具读取；知识库只提供判断标准和工作方法。
- **按 Agent 分配，不做全员共读。** 一个知识库可以分配给多个指定 Agent；没有被分配的 Agent 不读。
- **关键 Agent 必读缺失就阻断。** 分镜拆分、分镜校验、视频提示词三个关键 Agent，开工前必须加载至少一个必读知识库；必读缺失不允许“裸跑”。
- **每次任务重新读取。** 不是启动时读一次；设置页保存后，下一次 Agent 调用立即生效。
- **知识库不覆盖用户和项目事实。** 与用户明确要求冲突时，以用户要求为准；与剧本/资产事实冲突时，以项目数据为准。

### 8.2 默认知识库目录

| ID | 名称 | 内容 | 默认 Agent | 必读 |
|---|---|---|---|---|
| `novel-to-short-drama` | 小说改编短剧 | 钩子、节拍、对白化、心理外化、集尾钩子、格式 | `script_rewriter` | 是 |
| `asset-extraction` | 角色场景道具提取 | 提取边界、去重、别名归一、参考图要求 | `extractor` | 是 |
| `short-drama-grammar` | 短剧叙事与节奏 | 结构、节拍、时长预算、对白容量、竖屏/横屏、失败模式 | `storyboard_breaker` | 是 |
| `storyboard-direction` | 分镜与导演语法 | 景别、角度、运镜、构图、轴线、正反打、过肩、反应、动作匹配、覆盖模板 | `storyboard_breaker` | 是 |
| `continuity-and-transitions` | 前后镜连贯与过渡分镜 | 成对合同、尾帧/首帧、六条连贯规则、时间/场景/人物过渡空镜 | `storyboard_breaker`、`storyboard_auditor`、`prompt_generator` | 是 |
| `storyboard-validation` | 分镜校验清单 | 三层校验、检查矩阵、门禁、证据要求、修复动作、误报/漏报 | `storyboard_auditor` | 是 |
| `video-prompt-consistency` | 视频提示词一致性 | 提示词结构、画内人物、参考图、首尾帧、台词/旁白、声音/BGM | `prompt_generator` | 是 |
| `voice-and-narration` | 声音与旁白设计 | 音色档案、对白/画外音/内心/旁白分型、跨集一致性、环境声/BGM | `voice_designer` | 是 |

项目专属的分析文档（如《调教大宋》分析、16–19 修复示例）**不进入知识库**；它们是参考资料，不是通用规则，避免把单个项目的结论强加给所有项目。

### 8.3 分配关系

| Agent | 默认读取 | 为什么 |
|---|---|---|
| `script_rewriter` | `novel-to-short-drama` | 小说改编需要钩子、节拍、对白化和心理外化 |
| `extractor` | `asset-extraction` | 资产提取需要边界、去重、别名和参考图标准 |
| `storyboard_breaker` | `short-drama-grammar`、`storyboard-direction`、`continuity-and-transitions` | 拆分需要节奏、镜头语法和前后镜连贯 |
| `storyboard_auditor` | `storyboard-validation`、`continuity-and-transitions` | 校验需要检查矩阵、证据标准和连贯规则 |
| `prompt_generator` | `video-prompt-consistency`、`continuity-and-transitions` | 提示词需要画内人物、首尾帧、台词/旁白和连贯规则 |
| `voice_designer` | `voice-and-narration` | 声音设计需要音色档案、四型声音和跨集一致性 |

分配规则：

- `continuity-and-transitions` 是共享知识库，但**只分配给上述三个 Agent**，不是全员共读。
- 拆分 Agent 不读校验清单；校验 Agent 不读分镜语法；避免提示词膨胀和规则冲突。
- 自定义知识库可以分配给任意 Agent 子集；也可以只给一个 Agent。
- 关键 Agent 至少保留一个必读知识库；取消最后一个必读分配要二次确认，并标记“无知识运行”风险。

### 8.4 输入输出

**输入**：

| 输入 | 说明 |
|---|---|
| Agent 类型 | `storyboard_breaker`、`storyboard_auditor` 等 |
| 内容语言 | zh/en/ja/ko；非中文优先读语言变体，缺失回退中文 |
| `knowledge/index.json` | 知识库清单与 `agents` 分配、`required`、`enabled` |
| `knowledge/<id>.md` | 知识库正文；可选 `<id>.<lang>.md` |
| 调用时机 | 每次 Agent 任务/每个拆分块/每轮校验/每次提示词生成 |

**输出**：

| 输出 | 说明 |
|---|---|
| `knowledge_block` | 注入系统提示词的“专用知识库”段 |
| `knowledge_ids` | 本次实际加载的知识库 ID |
| `knowledge_version` | 内容哈希版本，用于日志和任务记录 |
| `missing` | 缺失的必读/选读知识库 |
| `gate_status` | K0–K3 的通过/阻断状态 |

注入顺序：**系统提示词 → 专用知识库 → 技能 → 拆分方案 → 声音引用 → 语言指令**。知识库在角色定义之后、技能之前，先建立共同判断标准，再进入角色专属规范。

### 8.5 读取时机

| Agent | 读取时机 | 失败行为 |
|---|---|---|
| `script_rewriter` | 每次改写任务开始前 | 必读缺失阻断 |
| `extractor` | 每次提取任务开始前 | 必读缺失阻断 |
| `storyboard_breaker` | 每个拆分块开始前；整集拆分也按块读 | 必读缺失阻断，不允许保存空分镜 |
| `storyboard_auditor` | 每次校验任务、每个窗口、每对判定、每次修复前 | 必读缺失阻断，不允许“无标准审核” |
| `prompt_generator` | 每次视频提示词生成/重写前 | 必读缺失阻断 |
| `voice_designer` | 每次声音设计前 | 必读缺失阻断 |

- 读写文件每次重新读取，不用进程级缓存；保证设置页保存后下一次任务生效。
- 同一 Agent 同一版本只记一次加载日志，避免多步工具调用刷屏。
- 拆分/校验任务记录 `knowledge_ids` 和 `knowledge_version`；知识更新后 UI 显示“知识已更新，建议重跑”，但不自动作废已产出的项目数据。

### 8.6 知识门禁

| 门禁 | 名称 | 通过条件 | 不通过时 |
|---|---|---|---|
| K0 | 索引有效 | `index.json` 可解析；ID 唯一；`agents` 是已知类型 | 关键 Agent 阻断；UI 显示索引错误 |
| K1 | 必读存在 | 关键 Agent 至少有一个已分配的必读知识且文件非空 | 拆分/校验/提示词阻断，列出缺失名称和修复入口 |
| K2 | 已加载并记录 | 任务开始前 `knowledge_block` 已注入，`knowledge_version` 已记录 | 任务失败，不允许空知识运行 |
| K3 | 结果记录版本 | 拆分/校验结果带知识版本 | 软提醒，不阻断；UI 可提示重跑 |

行为边界：

- 必读缺失：**阻断**，错误信息写清“缺哪个知识库、去设置 → Agent 配置 → 知识库补”。
- 选读缺失：警告，继续。
- 语言变体缺失：回退中文，标记“跟随中文”，不阻断。
- 关键 Agent 没有任何必读分配：阻断，要求至少保留一个。
- 非关键 Agent 没有分配：允许运行，UI 提示“该 Agent 无专用知识”。

### 8.7 管理页面

入口：**设置 → Agent 配置 → 知识库**（与 System Prompt、Skills 并列的第三个子页）。

| 区域 | 内容 | 交互 |
|---|---|---|
| 左侧 Agent 列表 | 与现有 Agent 列表一致 | 切换 Agent，右侧只看该 Agent 的知识 |
| 顶部 | “这个 Agent 开工前先读哪些知识” | 说明按 Agent 分配，不共读 |
| 已分配 | 知识库卡片：名称、ID、描述、必读标签、文件状态、分配 Agent | 展开编辑正文；取消分配 |
| 未分配 | 同一知识库在其他 Agent 下的卡片 | “分配给本 Agent”；未分配的可删除 |
| 编辑 | 名称、描述、正文、必读开关 | 保存后下一次任务生效 |
| 新建 | ID、名称、描述、正文；默认分配给当前 Agent | 创建后出现在已分配 |
| 版本 | 内容哈希/更新时间 | 只读展示；用于判断任务用的是哪版 |

交互约束：

- 关键 Agent 取消最后一个必读分配时，二次确认并提示“拆分/校验/提示词将无法启动”。
- 删除知识库前必须先取消所有分配；仍被分配时禁止删除。
- 普通用户不暴露 `index.json`；高级查看放在“高级”抽屉。
- 语言切换时，知识库正文跟随内容语言：有变体读变体，没有变体读中文并提示“跟随中文”。
- 保存后不需要重启后端；下一次 Agent 调用重新读取文件。

### 8.8 生命周期与模板

- 文件位置：`workspace/knowledge/index.json` + `workspace/knowledge/<id>.md`。
- 新安装：模板自带 8 个默认知识库和分配关系。
- 版本升级：知识库文件**只增不覆盖**（copy-once），保留用户编辑；新增默认知识库会补进来。`prompts/` 仍按现有策略随版本覆盖。
- 语言变体：`<id>.en.md`、`<id>.ja.md`、`<id>.ko.md`；缺失回退中文。
- 自定义知识库：可新建、编辑、分配、取消分配、删除；删除前必须无分配。
- 项目分析文档不进入知识库；知识库只放可复用的方法论和检查清单。
- 版本：索引版本 + 每个知识库内容哈希；任务记录实际加载的版本。

### 8.9 与 16–19 的关系

- 拆分 Agent 先读 `storyboard-direction` 和 `continuity-and-transitions`：不会在同一场对话里把 16/17 拆成镜像，也不会把反应塞进别人主导的段。
- 校验 Agent 先读 `storyboard-validation` 和 `continuity-and-transitions`：会检查轴线、场景翻面、人物在场，而不是只看文本和 continuity 声明。
- 提示词 Agent 先读 `video-prompt-consistency` 和 `continuity-and-transitions`：会只写画内人物、带首尾帧、旁白进 `<d>`、不把 BGM 写进提示词。
- 三个 Agent 各读各的，不互相污染：拆分不读校验清单，校验不读分镜语法，提示词不读资产提取规则。

### 8.10 验收标准

- [ ] 拆分 Agent 只收到短剧语法、分镜语法、连贯过渡三个知识库，不收到校验清单/视频提示词。
- [ ] 校验 Agent 只收到校验清单、连贯过渡，不收到分镜语法/短剧语法。
- [ ] 提示词 Agent 只收到视频提示词、连贯过渡。
- [ ] 小说、资产、声音 Agent 各收到自己的知识库。
- [ ] 必读知识库缺失时，拆分/校验/提示词直接失败，并给出修复入口。
- [ ] 关键 Agent 不能取消最后一个必读分配。
- [ ] 设置页保存后，下一次任务立即读到新内容。
- [ ] 非中文语言变体缺失时回退中文并显示“跟随中文”。
- [ ] 任务日志能看到本次加载的知识库 ID 和版本。
- [ ] 模板升级只补新知识库，不覆盖用户编辑。

## 9. 视频制作页 UI 重设计

### 9.1 现在页面在优化什么

当前视频制作页（`frontend/app/views/drama/episode.vue:555` 起）是一个三栏工作台：

| 区域 | 现在 | 优化了什么 | 缺什么 |
|---|---|---|---|
| 顶栏 | 模式（native/comfyui）、拆分方案、段数/时长、开始拆分、批量提示词、动作检验、批量生成 | 单集操作入口 | 时长预算、覆盖门禁、计划状态 |
| 左栏 | 平铺分镜列表、缩略图、状态、审计标记 | 单镜选择/生成 | 场景分组、覆盖类型、轴线、人物在场 |
| 中栏 | description、atmosphere、transition、continuity、参考素材、视频提示词 | 单镜编辑 | 合同字段、画面调度、画内/画外、动作起止 |
| 右栏 | 播放器、历史、绑定参考、帧资产、时长、生成 | 单镜预览/生成 | 成对检查、场景地理、生成后验收 |
| 抽屉 | 任务中心、动作检验面板 | 任务/问题列表 | 成对帧、轴线/场景证据、门禁解释 |

结果：用户看到的是「一条一条分镜 + 一段提示词」，看不到 16–19 的轴线、翻面、人物在场；只能在成片后发现。

当前页面最具体的六个问题是：

1. 拆分时三处进度重复（顶栏按钮文字、列表上方 banner、空状态文案），列表位置会跳；
2. 校验图标用绿勾表示“流程完成”，不是“镜头通过”，绿勾和红数字并存；
3. 检查器把 `description`、`atmosphere`、`transition`、`continuity` 四个自由文本框并列，用户不知道它们影响哪一步；
4. 视频提示词是整段自由文本，没有分行结构，换行和保存都不确定；
5. 提示词没有固定分区，人物/场景/画面调度/时间帧/负面约束混在一起；
6. 右下角时长是手填独立字段，和分段不联动。

这六点在 9.8 逐项重设计。

### 9.2 新信息架构

| 区域 | 内容 | 主要交互 |
|---|---|---|
| 顶部「集制作条」 | 集标题、当前阶段、时长预算条、门禁徽标、主按钮 | 切换规划/生成；查看门禁；开始拆分 |
| 左栏「场景导航」 | 场景卡片：场次、地点、镜头数、时长、覆盖健康度、问题数 | 选场景；展开覆盖单元；跳问题 |
| 中栏「拆分进行中」 | 拆分时占据工作台主体：场景/块进度、当前块、已生成镜头数、暂停/继续/停止、查看已生成 | 拆分中锁定编辑/生成/校验；完成后进入结果摘要 |
| 中栏「覆盖板」 | 按节拍分组的镜头卡；每卡：缩略图/关键帧、覆盖类型、画内人物头像、屏幕左右、时长、轴线箭头、问题徽标；上方场景地理卡 | 点卡选中；拖拽增删；点边界看成对；点缺口补镜头 |
| 中栏「场景地理卡」 | 俯视布局：桌/窗/门/柜台/入口；A/B 机位；轴线；人物站位；地标屏幕侧 | 编辑布局；切换机位侧；保存版本 |
| 右栏「镜头检查器」 | 标签：合同 / 提示词 / 参考 / 校验 / 生成；提示词不再是一整段自由文本，而是固定分区编辑器 | 编辑合同；按分区编辑提示词；绑定参考；看问题；生成 |
| 底部「分段时长条」 | 时间帧列表、每段时长、总时长、台词容量、模型上限 | 加减段时长；自动重算总时长；均分/按台词分配 |
| 底部「生成队列」 | 当前批次、逐镜状态、暂停/继续、预计耗时/费用 | 批量生成；失败重试；单镜重生成 |
| 抽屉「拆分向导」 | 范围/方案 → 预算/模板 → 计划预览 → 保存校验 | 四步完成拆分；预览计划和覆盖缺口 |
| 抽屉「成对检查」 | 上一镜尾帧、本镜首帧/尾帧、下一镜首帧；轴线/地标/人物在场叠加 | 修复轴线/场景/在场；用上一镜尾帧重生成 |
| 抽屉「验收」 | 成片 vs 合同、抽帧 vs 参考图、验收项 | 接受/重生成/改合同 |

### 9.3 关键流程

**流程 1：拆分规划**

1. 顶部点「拆分」→ 打开向导。
2. 第 1 步：选范围（整集/单场）、拆分方案（显示 profile 摘要：画幅、时长、镜头数、覆盖模板）。
3. 第 2 步：确认时长预算、镜头数范围、覆盖模板、精确/经济模式。
4. 第 3 步：预览计划——按场显示覆盖单元、覆盖类型、时长、轴线、缺口；可拖动/增删；缺口用红色标出。
5. 第 4 步：保存并校验——生成合同、跑 L1；blocker 停在当前步，显示「哪一场缺建立镜头/缺反应/超预算」。
6. 通过后进入覆盖板。

**流程 2：覆盖板 review**

- 左栏选场景；中栏按节拍显示镜头卡；卡片上直接看到画内人物头像、屏幕左/右、覆盖类型、时长、轴线箭头。
- 顶部「覆盖缺口」条：缺 establishing、缺 reaction、缺 insert、说话人未覆盖、听者未反应。
- 点缺口 → 建议补一个什么镜头 → 一键插入到当前节拍。
- 点两张卡之间的边界 → 打开成对检查，显示两镜尾/首帧、轴线、场景地标、人物在场。

**流程 3：镜头合同**

- 右栏「合同」标签用表单，不用 JSON：
  - 这镜谁在画面里（多选头像）
  - 谁在画外（多选头像）
  - 画面左边是谁 / 右边是谁
  - 镜头在谁身后（无/左/右）
  - 背景里必须看到什么（窗/门/桌/柜台，及屏幕侧）
  - 从哪一秒到哪一秒做什么（动作起止）
  - 看哪里（视线目标）
  - 这镜的声音（对白/画外音/内心/旁白/环境/BGM/静默）
  - 这镜多长、什么画幅、什么模型
- 「提示词」标签是只读渲染预览；高级用户可切换「覆盖编辑」，覆盖后显示差异。
- 「参考」标签只显示画内人物 + 场景 + 关键道具；画外人物灰显，不送参考图。

**流程 4：成对检查**

- 三帧并排：上一镜尾帧、本镜首帧、本镜尾帧；下一镜首帧可选。
- 叠加层：屏幕左/右人物标签、轴线箭头、背景地标标签、画内/画外人物徽标。
- 问题区：轴线翻转、场景翻面、人物丢失、动作不匹配、过肩缺失。
- 修复按钮：改合同、补反应镜头、用上一镜尾帧重生成、换参考图、插入过渡。

**流程 5：生成队列**

- 生成前门禁：显示「可生成 / 缺 3 项」；点缺项跳到对应镜头/字段。
- 逐镜串行：上一镜尾帧自动带到下一镜；无连续性要求的镜头可并行。
- 队列卡：缩略图、状态、耗时、费用、失败原因、重试次数。
- 批量：按场景/按覆盖类型/按问题筛选后批量。

**流程 6：生成后验收**

- 成片播放器 + 合同摘要 + 抽帧条 + 参考图并排。
- 验收项：身份/场景/轴线/动作/在场/道具/声音/文本，每项 pass/warn/fail + 证据帧。
- 操作：接受、重生成（带上一镜尾帧）、改合同、换参考图、人工标记。

### 9.6 文案与新手友好

- 用「这镜谁在画面里」而不是 `cast_on_screen`。
- 用「画面左边 / 右边」而不是 `screen_left/right`。
- 用「镜头在谁身后」而不是 `foreground_shoulder`。
- 用「从第几秒到第几秒做什么」而不是 `blocking_start/end`。
- 用「为什么不能生成」列出具体原因：范公子没有参考图 / 孙郎中未绑定 / 时间轴只到 11 秒 / 缺一个反应镜头。
- 所有修复动作可见、可撤销；不把 JSON 暴露给普通用户；高级 JSON 放「高级」抽屉。
- 颜色只表达状态：红=阻断、黄=警告、绿=通过；不用颜色表达覆盖类型（用图标/文字）。

### 9.7 UI 验收标准

1. 打开一集，能在 10 秒内看出：哪些场缺建立镜头、哪些镜缺反应、哪些轴线会翻、哪些人物没参考图。
2. 点任意两个相邻镜头，能看到上一镜尾帧和本镜首帧的并排对照，以及轴线/地标/人物在场叠加。
3. 任意 blocker 都能一键跳到对应镜头/字段；修复后门禁实时更新。
4. 生成前能看到「这一镜会送哪几张参考图、首帧是什么、上一镜尾帧是什么」。
5. 生成后能看到「成片 vs 合同」的验收报告，失败能一键带尾帧重生成。
6. 平板/手机：场景导航抽屉、覆盖板、检查器底部抽屉、生成队列标签；不依赖 hover。
7. 不出现「只有提示词文本框、没有合同」的页面。

### 9.8 六项具体优化（本轮）

这六项直接对应现在视频制作页的体验问题。只改页面/交互设计，不改模型与生成协议。

#### 9.8.1 拆分分镜时页面不再“乱”

**现状问题**

- 拆分时同时出现三处进度：顶栏按钮文字变成进度、列表上方 `video-split-banner`、空状态里的 `splitRunning` 文案；页面高度和列表位置会跳。
- 拆分中列表/检查器仍可能被点选、编辑、生成；用户不知道哪些操作被锁定。
- 首次拆分（空列表）和重拆（已有列表）走两套展示，失败/续拆状态又混在空状态里。

**新设计**

- 引入唯一的 `SplitProgressPanel`，拆分时占据中栏工作台主体，不再用 banner/空状态文案重复进度。
- 状态机：`idle → confirm → running → paused → failed → review`。
- running 时：顶栏只保留“暂停/停止拆分”；编辑、生成、校验、拖拽、绑定全部禁用并显示原因；左栏场景列表只读可见；右侧检查器显示只读摘要。
- 暂停 = 当前块完成后不再启动下一块，不中断正在进行的模型调用；恢复从下一块继续。不要承诺“随时暂停当前请求”。已拍板（D10）：采用块间暂停，不新增后端 `paused` 状态。
- 面板内容：总场景/块数、当前块、进度条、已生成镜头数、耗时、每块状态（待拆/进行中/已完成/失败）、当前块剧本范围。
- 首次拆分：直接显示进度面板，不显示空状态。
- 重拆：先确认“将清空旧分镜”；旧列表只读可见，第一块保存成功后切换到新结果；失败时提供“继续剩余”和“回滚本次”。
- 完成：显示“拆分结果摘要”（镜头数、总时长、覆盖缺口、问题数）+“进入覆盖板”，不要自动跳走。
- 失败：进度面板显示失败块、错误、已生成数量；“继续剩余”从断点续拆，“回滚”清理半截数据。

**验收**

- 拆分中只有一套进度界面，页面不出现 banner + 空状态 + 按钮文字三处重复。
- 拆分中不能编辑/生成/校验；按钮禁用有原因。
- 首次拆分、重拆、失败续拆、完成进入覆盖板四种状态都有明确界面。
- 拆分过程中列表位置不跳；完成后列表一次性切换。

#### 9.8.2 列表卡片的校验图标状态

**现状问题**

- `done` 和 `ruleOnly` 都显示绿色对勾，即使同时有错误/警告数字；绿勾和红数字互相矛盾。
- `stale` 只换卡片 class，图标仍是旧状态；用户看不出“需要重检”。
- 错误、警告、信息没有分层；badge 只显示 error+warning 总数，点开才知道是什么。
- 图标点击会打开审计面板，但和整行点击选中的交互没有明显区分。

**新设计：状态矩阵**

| 状态 | 图标 | 徽标 | 文案 | 说明 |
|---|---|---|---|---|
| 未检验 `not_checked` | 灰色圆点 | 无 | 未检验 | 还没有审计结果 |
| 排队 `queued` | 灰色时钟 | 无 | 排队中 | 已进入队列 |
| 检验中 `running` | 蓝色 spinner | 无 | 检验中 | 不允许重复触发 |
| 通过 `pass` | 不显示（干净就隐藏） | 无 | 通过（仅筛选/摘要） | error=0、warning=0、非 stale；列表卡片不显示图标 |
| 警告 `warning` | 黄色三角 | 警告数 | N 个警告 | 可生成但需确认 |
| 错误 `error` | 红色叉 | 错误数/总数 | N 个错误 | 阻断生成 |
| 过期 `stale` | 保留最高严重度图标 + 灰色虚线环 | 原数量 | 需重检 | 不替换严重度 |
| 失败 `failed` | 红色感叹号 | 重试 | 检验失败 | 可重试 |
| 仅规则 `rule_only` | 蓝色盾牌 | 无 | 仅规则校验 | 不显示绿勾 |

说明：这些是 **UI 派生状态**，不要求后端新增同名状态。后端仍保留 `pending/running/done/failed/ruleOnly`；UI 用 job status + error/warning 计数 + stale 标记推导 `pass/warning/error/queued/not_checked`。

已拍板（D12）：**通过的镜头列表卡片不显示图标（干净就隐藏）**；列表筛选提供“已检验 / 未检验 / 有问题”，通过的镜头在筛选结果和详情里可见；异常/进行中/失败/过期仍然显示。

**交互**

- 图标是独立按钮，`@click.stop` 打开 popover：前 3 条问题 + “查看全部”；整行点击仍然是选中镜头。
- badge 只计 error+warning；info 放 tooltip。
- 场景导航聚合：场景卡显示错误/警告数；镜头卡显示最高严重度。
- 通过的镜头不显示图标；显示中的图标只表示未检验/排队/检验中/警告/错误/过期/失败/仅规则，避免绿勾和红数字并存。

**验收**

- 通过的镜头卡片不显示图标；筛选“已检验”能看到它们。
- 通过不会和红数字同时出现（因为通过不显示图标）。
- `ruleOnly` 不冒充通过。
- stale 不掩盖严重度。
- 每个显示中的状态不看 tooltip 也能区分；点图标和点行不冲突。
- 数字与审计面板问题数一致。

#### 9.8.3 分镜描述/转场/场景描述：不是没用，是层级放错了

**现状问题**

- 检查器把 `description`、`atmosphere`、`transition`、`continuity` 都做成自由文本框；用户不知道这些字段和视频提示词/合同是什么关系，感觉“填了也没用”。
- `transition` 是镜头之间的边界属性，不是单镜属性；放在单镜检查器里容易和剪辑转场混淆。
- “场景描述”是场景资产级信息，不是单镜级信息；放在单镜里会重复且容易漂。
- `continuity` 是成对属性，单镜文本框写“接上一镜”没有约束力。
- `description` 本身有用：它是台词和视频提示词的来源；但它应该是结构化的“画面/动作”字段，而不是一段自由文本。

**新设计**

- 检查器只保留四类：
  1. **合同**：画内/画外人物、屏幕左右、过肩、背景地标、动作起止、视线、声音。
  2. **提示词**：固定分区编辑器（见 9.8.5）。
  3. **参考**：画内人物、场景、关键道具、首尾帧。
  4. **校验/生成**：问题、门禁、模型、时长、生成。
- `description` → 合同里的“画面/动作”分区，按子镜/节拍分行；保留“原始描述”折叠入口给旧数据。
- `transition` → 移到覆盖板的镜头边界控件；检查器只读显示“入点/出点”，点击跳到边界。
- “场景描述” → 移到场景资产/场景地理卡；检查器只显示只读场景摘要 + “编辑场景”链接。
- `continuity` → 移到成对检查；检查器显示“上一镜/下一镜”摘要 + “查看成对”。
- `atmosphere`/`sound_effect` → 合同里的“声音/氛围”分区；`bgm_prompt` 不在单镜检查器显示（BGM 后期混音）。
- 旧分镜：这些字段仍可查看/编辑，但收进“旧版字段”折叠区；新分镜默认不出现自由文本框。

**验收**

- 单镜检查器不再同时出现四个无语境的自由文本框。
- 转场只在镜头边界编辑；场景描述只在场景资产编辑；continuity 只在成对检查编辑。
- 用户能说清每个字段“影响哪一步”：description→合同/提示词；transition→剪辑边界；scene→场景地理；continuity→成对校验。

#### 9.8.4 视频提示词/分镜描述换行

**现状问题**

- 视频提示词是整段 `MentionTextarea`，没有固定分行结构；`@` 下拉打开时 Enter 用于选中，用户容易误以为不能换行。
- 描述是 `textarea`，但失焦才提交；换行后没有明确保存反馈，刷新后不确定是否保留。
- 固定格式要求“信息头一行、时间帧每段一行、负面约束一行”，但自由文本无法保证。

**新设计**

- 提示词按分区编辑：每个分区独立多行编辑器；Enter 换行，Ctrl/Cmd+Enter 保存；`@` 下拉打开时 Enter 选中资产，Escape 关闭；下拉关闭时 Enter 正常换行。
- 描述编辑器：多行；Enter 换行；失焦或 Ctrl/Cmd+Enter 保存；保存后显示“已保存”；内部换行不 trim、不折叠。
- 后端保存原样 `\n`；刷新、切换镜头、重新打开后保持分行；复制/粘贴保留换行。
- “格式预览”按最终渲染显示：信息头一行、画面调度一行、每个时间帧一行、负面约束一行；缺行/空行时报格式问题。
- 不在输入框里用 `white-space: normal` 或 `trim()` 折叠内部换行；只 trim 首尾空白。

**验收**

- 输入三行，失焦/保存/刷新后仍是三行。
- 时间帧每段独立一行；复制到外部编辑器保留换行。
- `@` 下拉打开时 Enter 选中，不换行；下拉关闭时 Enter 换行。
- Ctrl/Cmd+Enter 保存；保存状态可见。
- 格式预览与分区内容一致。

#### 9.8.5 视频提示词固定格式编辑

**现状问题**

- 现在是一整段自由提示词，只有约定“第一行信息头、后面 3 秒分段”，没有强制分区；人物/场景/画面调度/时间帧/负面约束混在一起。
- @ 资产可以插入，但没有分区校验：画外人物可能被写进信息头，场景可能不 canonical，负面约束可能缺失。
- 负面约束没有固定入口，靠模型自由发挥。

**新设计：`PromptSectionEditor` 五个固定分区**

| 分区 | 内容 | 编辑 | 校验 |
|---|---|---|---|
| 1 出场人物 | 只列画内人物，@ 角色 chips | 添加/删除/搜索 @；画外人物灰显不可选 | 未绑定/无参考图/画外人物 → 阻断 |
| 2 场景 | 一个 canonical 场景 @ | 场景选择器；显示场景图 | 未绑定/非 canonical → 阻断 |
| 3 画面调度 | 屏幕左/右、过肩、背景地标、轴线 | 多行文本 + 快捷插入（左/右/过肩/窗/门/桌/轴线）+ @ | 缺左右/过肩/地标 → 警告；与合同冲突 → 阻断 |
| 4 时间帧分段 | 每段起止、画面、台词/旁白、@/# | 分段列表；每段独立文本；添加/删除/排序 | 时间不连续/重叠/最后不到 duration/台词容量超限 → 阻断 |
| 5 负面约束 | 只出现画内人物、不换脸/换装/加人、不生成字幕、不出现现代物品/错误招牌 | 默认 chips + 自定义文本 | 缺默认项 → 警告；与画内人物冲突 → 阻断 |

- 固定渲染顺序：信息头 → 画面调度 → 时间帧 → 负面约束；每个时间帧独占一行；分区之间空行。
- 负面约束与模型级 `negative_prompt` 叠加：模型级继续管风格/质量，镜头级管画内人物/加人/字幕/现代物品；不要重复同一句。
- H3 编译器仍是最终渲染器：UI 分区只负责结构化，`<d>`、`<Picture N>`、时间标记仍由 H3 编译层生成；UI 不直接产出最终 H3 文本。
- @ 资产：角色/场景/道具；# 资产：音色；选择器只显示可用资产；未解析 token 红色高亮，点击修复。
- 原始 `video_prompt` 只读预览；“高级原文”可切换编辑，保存时重新解析分区并校验；不合法不允许保存。
- 与合同联动：人物/场景/画面调度/时间帧的字段来自合同；改分区会回写合同对应字段，避免两套真相。
- 冲突规则：同一字段在合同和提示词两边都被修改时，以最后一次保存为准；保存前比较版本，提示“合同已变更，覆盖/合并/取消”，不允许静默覆盖。
- 旧分镜：自由文本按现有格式解析成五个分区；解析失败的段落进“未识别内容”，不丢字。

**验收**

- 五个分区都存在；缺信息头/场景/时间帧 → 不能保存；缺默认负面约束 → 警告；负面约束与画内人物冲突 → 不能保存。
- 画外人物不能被加入出场人物；未绑定/无图角色被阻断。
- @/# 选择器只显示可用资产；未解析 token 可见且可修。
- 分区改动回写合同；原始预览与分区一致。
- 旧分镜解析不丢字，未识别内容有提示。

#### 9.8.6 时间帧分段时长与总时长

**现状问题**

- 右下角 `duration` 是手动数字输入，和提示词里的时间帧没有绑定；改分段不会自动改总时长，改总时长也不会重排分段。
- 每个时间帧只有文本里的起止数字，没有加减按钮/拖动；调一段要手改所有后续段。
- 台词容量（4 字/秒）没有和分段时长联动；段太短不会提示。

**新设计：`SegmentTimelineEditor`**

- 每段一行：起止时间、时长、`−0.5s`/`+0.5s`、拖动把手、精确输入；最小 1 秒，最大 6 秒，建议 2–4 秒。
- 总时长的上下限由当前拆分模式决定：现有 8–15 秒段落模式为 8–15 秒；一镜一 setup 模式为 3–8 秒（最大 10 秒）；两者都不得超过当前模型上限（本地 H3 720p 8s、480p 15s；云端按模型）。
- H3 原生按 3 秒节奏生成；分段偏离 3 秒时提示“模型可能按 3 秒窗口重采样”，不阻止保存，但验收以实际成片为准。
- 已拍板（D11）：允许 1–6 秒自由分段；上线前用 1–2 个镜头做真实生成验证，确认时间标记与画面窗口一致；若偏差明显，再限制为 3 秒倍数。
- 调整一段后：
  - **锁定总时长（默认）**：把变化量按比例分摊到其他段；碰到最小/最大则固定，剩余再分摊；无法分摊时提示“总时长不变，建议压缩某段/拆段”。
  - **顺延**：保持当前段起点，后续段整体后移；总时长变化；显示新总时长。
  - **均分**：所有段等长。
  - **按台词分配**：按每段台词字数 ÷ 4 字/秒 + 气口分配，再夹到最小/最大。
- 总时长 = 所有分段时长之和；右下角改为只读 `DurationSummary`：“总时长 12.0s（4 段）/ 本模式 8–15s / 模型上限 {videoDurationMax}”；不再手动输入。
- 保存的 `duration` 是分镜总时长；厂商返回的 `resultDuration` 可能取整（如 12.25s），以请求 `duration` 为准，验收看实际时长偏差。
- 每段显示“台词需要 X 秒 / 实际 Y 秒”；不足时红色“至少 X 秒”，提供“自动补足”。
- 时间轴连续：无重叠、无空洞，最后一段结束 = 总时长；拖动/加减按 0.1 秒吸附。
- 超过本模式上限或模型上限：阻断生成，提示“压缩/拆段/换模型”；低于本模式下限：提示或阻断（按方案 profile）。
- 高级：允许“手动锁定总时长”覆盖自动分配，但保存时仍校验分段总和 = 总时长。

**验收**

- 调整任意一段，其他段自动调整，右下角总时长同步变化。
- 右下角不再能手动输入一个和分段不一致的总时长。
- 台词容量不足的段有红色提示和自动补足。
- 总时长超过模型上限时不能生成。
- 时间轴始终连续，最后结束 = 总时长。

#### 9.8.7 六项之间的联动

- 拆分进度面板完成后，覆盖板的镜头卡显示新的校验状态。
- 点镜头卡进入检查器；检查器只显示合同/提示词/参考/校验/生成，不再有四个自由文本框。
- 提示词五个分区与合同同源；时间帧分段和底部时长条是同一个数据；改任一处，另一处实时更新。
- 列表校验图标点开的问题，跳到检查器的“校验”标签；修完后图标实时更新。
- 这六项共同把页面从“分镜行 + 提示词文本框”变成“场景/镜头工作台”。

#### 9.8.8 与现有实现的边界

这六项是 UI/交互重设计，不要求先改后端协议。和现有实现的边界如下：

| 主题 | 现有实现 | 本设计的处理 |
|---|---|---|
| 拆分任务状态 | `pending/running/done/failed/interrupted`，没有 `paused` | UI 的“暂停”= 当前块完成后不再启动下一块；如后端新增 `paused`，直接映射；不承诺中断当前模型调用 |
| 校验状态 | 后端 `pending/running/done/failed/ruleOnly` + error/warning/info 计数 | UI 的 `pass/warning/error/queued/not_checked` 是派生状态，不新增后端同名状态 |
| 转场字段 | 存在 `storyboards.transition`，语义是“从上一镜进入本镜” | 数据不迁移；UI 只在镜头边界展示/编辑，检查器只读 |
| description | 存在 `storyboards.description`，是台词和提示词的来源 | 数据保留；UI 改为合同里的“画面/动作”分区，旧数据进“原始描述”折叠 |
| continuity | 存在 `storyboards.continuity` | 数据保留；UI 移到成对检查，单镜检查器只显示摘要 |
| 场景描述 | 属于场景资产，不是分镜字段 | UI 只在场景资产/地理卡编辑，单镜检查器只读 |
| 时长上限 | 由模型/分辨率决定：本地 H3 720p 8s、480p 15s，云端按模型 | 总时长上限动态读取 `videoDurationMax`，不写死 12s |
| H3 分段 | H3 原生按 3 秒节奏；编译器接受任意时间标记，但可能按窗口重采样 | UI 允许 1–6 秒分段，偏离 3 秒时提示；最终以成片验收 |
| 负面约束 | 模型级 `negative_prompt` 已有 | 镜头级负面约束是提示词文本，与模型级叠加，不重复同一句 |
| 最终提示词 | H3 编译器负责 `<d>`、`<Picture N>`、时间标记 | UI 五个分区只负责结构化，最终文本仍由 H3 编译层生成 |
| 拆分单位 | 当前一行 8–15 秒、2–4 子镜 | 本轮 UI 不强制先改拆分单位；§6.1 的一镜一 setup 是独立改造，改完后这些组件不变 |

这条边界的目的：六项 UI 改造可以先落地，不被 §6.1 的拆分单位改造、H3 协议或后端状态机绑住；但也不会假装已经改了底层。

**风险与对策**：

| 风险 | 对策 |

| 视觉预检成本 | 只对关键镜头；用构图草稿/参考图预检；可关闭 |

| 编号 | 决策 | 默认 | 可改选项 | 影响 |
|---|---|---|---|---|
| D1 | 拆分单位 | 一个分镜行 = 一个机位/一个主体/一个连续动作；3–8 秒，最大 10 秒 | 经济模式：8–15 秒长镜头，只允许同机位运动 | 镜头行数、生成成本、连续性可控度 |

## 14. 四段式执行与场景/剧情级声音设计（2026-11-12 追加）

### 14.1 执行顺序

| 步骤 | 做什么 | 执行粒度 | 产物 |
|---|---|---|---|
| 1 预拆 | 把小说/剧本预拆成分镜骨架：场次、人物、机位骨架、时长、动作、转场、连续性 | 按场/节拍批量 | 分镜草稿 |
| 2 逐镜修补 | 目标镜 + 前 1–2 镜已修补内容 + 后 1–2 镜草稿 + 小说完整场景，语义理解后补台词、动作、调度、固定四区 | 严格逐镜顺序 | 分镜成稿 |
| 3 逐镜校验 | 合同、固定分区、台词、发声动作、场景、方向、地标、动作衔接；该镜通过才进入下一镜 | 严格逐镜 | 逐镜通过状态 |
| 4 声音设计 | 以场景/剧情声音单元为单位，设计 BGM、环境声、画内音效、静默，并跨分镜分配 | 场景/剧情单元，可跨多个分镜甚至跨场 | 声音计划 + 每镜声音增量 |

### 14.2 声音单元原则

- **声音单元是场景/剧情单位，不是分镜单位。** 同一地点、同一时间、连续动作或同一情绪/剧情段落组成一个声音单元。
- 一个声音单元可以覆盖多个分镜；BGM 和底噪只在单元起点建立一次，后续分镜延续。
- 一个 BGM 弧可以跨场景；换场时用淡出/淡入，不重新起一段同风格音乐。
- 环境声按地点/时间建立底噪；画内音效（门、脚步、锅灶、碗筷）只出现在对应动作分镜。
- 静默是合法声音设计；无 BGM/无环境声时明确写静默，不重复默认风格。

### 14.3 第四步流程

1. **归组**：把已校验分镜按场景/时间/动作/剧情节拍归为声音单元；过渡分镜归入相邻单元。
2. **剧情分析**：读取小说/剧本的场次、情绪弧、人物关系、关键动作，确定 BGM 主题、进入点、退出点、强度变化、环境声底噪、画内音效和静默。
3. **生成声音计划**：每个声音单元产生 BGM 弧、环境声底噪、音效事件、静默区间；BGM/环境声用 `from_shot_id → to_shot_id` 范围表达，不逐镜重复。
4. **派生逐镜声音增量**：每镜只写相对上一个声音状态的增量：
   - 单元第一镜：建立环境声/BGM；
   - 后续镜：`延续本单元环境声；BGM 继续，不重启；本镜新增：…`；
   - 无变化：只写短承接，不复制完整 BGM 风格；
   - 换场/时间跳：写淡出、淡入、静默或新单元起点。
5. **声音校验**：检查跨镜连续性、重复、重启、音效归属、对白优先级、转场淡入淡出；失败只回到声音单元修正，不重拆分镜。

### 14.4 数据模型

| 实体 | 关键字段 | 用途 |
|---|---|---|
| `sound_plans` | episode_id、version、status、plan_json、validation_json、fingerprint | 一集的声音设计源 |
| `sound_cues` | plan_id、unit_key、kind（bgm/ambience/sfx/silence）、from_shot_id、to_shot_id、start/end、description、intensity、entry/exit、delivery | 跨分镜的声音线索 |
| `storyboards.sound_cue` | plan_id、cue_ids、delta_text、unit_key | 单镜只存声音增量，不存完整 BGM 风格 |

兼容：`bgm_prompt`/`sound_effect` 保留为单元级来源或旧数据字段；新链路不再把它们当作逐镜风格。

### 14.5 视频提示词中的声音区

声音区只写当前分镜需要知道的**短增量**，不写完整风格：

| 场景 | 声音区内容 |
|---|---|
| 声音单元第一镜 | 环境声底噪；BGM 名称/情绪/进入点；本镜音效 |
| 同单元后续镜 | 延续本单元环境声；BGM 继续，不重启；本镜新增音效 |
| 无变化镜头 | 延续上一镜声音；不重复 BGM 风格 |
| 换场/时间跳 | 上一单元淡出；新单元环境声/BGM 起点 |
| 静默镜头 | 明确写静默，不补默认 BGM/环境声 |

BGM 的完整主题、乐器、强度曲线只存在于声音计划；逐镜提示词只引用短 cue。禁止每镜重复“轻快市井基调”这类完整风格描述。

### 14.6 UI

- 在逐镜校验完成后出现“声音设计”视图，按声音单元展示时间线。
- 时间线分 BGM、环境声、画内音效、静默四条轨道，cue 块可跨分镜拖拽。
- 点击某镜显示该镜的声音增量，不显示整段 BGM 风格。
- 修改 cue 边界时自动更新覆盖到的分镜增量；跨场 BGM 用淡出/淡入表示。
- 不提供“每镜一个 BGM 文本框”的主编辑方式。

### 14.7 校验

| 规则码 | 检查 |
|---|---|
| `sound_unit_missing` | 已校验镜头没有归入声音单元 |
| `sound_cue_overlap` | 同轨 cue 时间/镜头重叠冲突 |
| `bgm_restart_every_shot` | 同一单元每镜都重新起 BGM |
| `sound_style_repeated` | 逐镜重复完整 BGM/环境声风格 |
| `ambience_mismatch` | 环境声与场景地点/时间不符 |
| `sfx_shot_mismatch` | 音效事件与画内动作不对应 |
| `dialogue_sound_conflict` | BGM/环境声压过对白或旁白 |
| `sound_transition_missing` | 换场/时间跳没有淡出淡入或静默 |
| `silence_unplanned` | 长静默未在声音计划中说明 |

门禁：结构性声音冲突为 error；风格重复、BGM 重启为 error；可选环境细节为 warning。

### 14.8 BGM 交付

- 声音计划是 BGM 唯一源；逐镜 prompt 只带短 cue。
- 支持两种交付：
  - `native`：视频模型生成 BGM/环境声；逐镜 prompt 写短 cue，并明确“继续，不重启”。
  - `post`：BGM 不进视频模型，由后期混音按声音计划处理；视频 prompt 仅保留环境声/画内音效。
- 默认按视频模型能力选择；同一集内不混用两种 BGM 交付，避免双重 BGM。

### 14.9 新增决策

| 编号 | 决策 | 默认 | 可改选项 | 影响 |
|---|---|---|---|---|
| D14 | 声音设计时机 | 逐镜校验后第 4 步 | 拆分时顺带 / 生成前临时 | 连贯性、返工成本 |
| D15 | 声音单位 | 场景/剧情声音单元，可跨多镜、可跨场 | 每场固定 / 每镜 | BGM 连续、编辑复杂度 |
| D16 | 逐镜声音写法 | 只写增量，禁止重复完整风格 | 每镜完整描述 | token、风格漂移、重启风险 |
| D17 | BGM 交付 | 按模型 native 或 post；同集不混用 | 全部 native / 全部 post | 声画一致、后期可控性 |

### 14.10 实现状态（2026-11-12）

已落地：

- 数据模型：`storyboard_pipeline_jobs`、`storyboard_skeletons`、`sound_plans`、`sound_cues`，`storyboards.sound_cue/sound_unit_key`；旧库启动迁移已验证。
- 第一段：按场次分块预拆，只保存骨架；原文摘录必须逐字来自本段并保持顺序，覆盖不足会拒绝本段。
- 第二段：严格逐镜修补；目标骨架 + 前 2 镜成稿 + 后 2 镜草稿 + 完整场次原文；拒绝保存时仍落草稿行，方便人工修改。
- 第三段：修补后立即单镜确定性校验（合同/分区/台词逐字/发声动作/方向/动作端点）；失败同镜最多 3 次（初始 + 2 次重试），仍失败则停在该镜，不进入下一镜。
- 第四段：全部普通分镜通过后，按声音单元保存跨镜 cue；单镜提示词只写短增量；校验 BGM 重启、cue 重叠、镜头未归组、BGM 强度压对白、native/post 混用。
- 接口与页面：创建/查询/暂停/继续/最近任务；制作页展示阶段与逐镜进度；声音计划只读抽屉按四条轨道展示。
- 测试：后端管线 7 项、全量 1468 项；前端 768 项；桌面模板 7 项；前端生产构建通过。
- 真实模型小样：用正式库副本建 2 镜临时测试集，跑通预拆→逐镜修补→逐镜校验→声音设计；两镜均 validated，声音计划 1 个单元 4 条 cue，第二镜 BGM/环境声为「延续不重启」。首轮声音计划因 cue 的 unit_key 不一致被校验拒绝，模型自动修正后通过。

待验收：

- 在临时库只跑了 2 镜小样；正式集完整跑通仍待单独执行。
- 声音时间线拖拽编辑、cue 边界调整后自动回写逐镜增量。
