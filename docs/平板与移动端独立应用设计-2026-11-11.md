## 0. 结论摘要

1. **产品形态是 Android 独立应用，不是 PWA、不是 Termux 脚本、不是远程客户端。** 应用内嵌完整运行时（proot + Debian arm64 + 官方 Node 22 + 现有 Hono 后端 + Nuxt 前端 + SQLite + 媒体目录），开机即用，不要求用户安装外部环境，不依赖火宝服务端或桌面端进程。
2. **全功能保留，FFmpeg 产出动作除外。** 项目、剧本、分镜、生成、审片、剪辑、混音、配音编辑、小说、任务中心、设置全部可用；合片、导出、混音渲染、剪辑渲染、宫格切分、抽帧/海报、音源分离、需要 FFprobe 的音色校验等入口统一显示「暂未开放」。
3. **扫码接力复用已实现的电脑端远程接入桥。** 应用扫码后打开电脑端的同一套前端，作为电脑同一实例的远程客户端继续工作；数据、任务与 FFmpeg 能力都留在电脑，工作仍在电脑执行。
4. **局域网数据同步是两台独立实例之间的一次性单向快照。** 应用发起、电脑逐次确认、方向显式选择、不做双向合并；数据库事务替换、媒体按清单增量传输、目标端自动备份。
5. **可复用资产已经存在：** 平板端全站适配已提交（4.0.25，e84d84b）；扫码接力 P0–P15 已提交（4.0.35，c5c7192）；后端路径/端口/工作区均已支持环境变量注入；桌面端已有 esbuild 后端打包与资源准备流水线。
6. **最大技术风险在运行时，不在业务代码。** A1 真机原型已于 2026-11-11 通过（proot + Node 22 + better-sqlite3/sharp + 后端健康检查）；运行时、壳与存储集成（A2–A4）已完成，A5 应用模式与全功能 UI 进行中（UI 审计 P0/P1/P2 已修复并在 4.0.35-runtime5 真机复测通过）。

## 1. 决策基线

以下四条为 2026-11-11 用户确认的现行基线，逐字保留：

1. 独立的平板/移动端应用，不依赖任何服务端/桌面端；
2. 平板/移动端暂不实现ffmpeg等功能；
3. 支持局域网扫码桌面端进行桌面的接续工作，工作还是在桌面端；
4. 支持局域网数据同步。

解释口径：

| 决策 | 本设计的解释 | 不表示 |
| --- | --- | --- |
| 独立应用 | 业务进程、数据库、媒体、界面都在设备内；应用内嵌的本机后端属于应用自身，不算外部服务端 | 不表示离线可用；AI 文本/图像/视频生成与 ComfyUI 仍需要网络或局域网服务 |
| 不依赖服务端/桌面端 | 不要求常驻服务器、不要求桌面端开机、不要求 Termux 或用户自装 Linux | 不表示所有生成能力都能脱离外部模型服务 |
| 暂不实现 FFmpeg 等功能 | 不内置 FFmpeg/FFprobe，不引入 ffmpeg.wasm/WebCodecs 替代链路；产出动作门控为「暂未开放」 | 不表示剪辑、混音、配音编辑、播放、审片不可用 |
| 扫码接力 | 应用作为电脑同一实例的远程客户端；数据与算力在电脑 | 不表示应用本地数据会随接力变化 |
| 局域网数据同步 | 两台独立实例之间显式、单向、可重复的全量快照同步；目标端以来源为准 | 不表示双向实时合并、CRDT、字段级冲突解决 |

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 独立应用 / 本机实例 | 设备内的 APK，内含本机后端、SQLite、媒体目录与前端；离开电脑可独立工作 |
| 电脑实例 | Electron 桌面端或本机浏览器访问的现有后端实例 |
| 扫码接力 | 应用打开电脑端远程桥的前端，作为电脑实例的远程客户端；写操作发生在电脑 |
| 数据同步 | 应用与电脑两个独立实例之间复制业务数据与媒体；单向快照，不合并 |
| 服务端能力 | 当前连接实例的媒体能力；独立应用的本机能力恒为不可用（无 FFmpeg） |
| 暂未开放 | 功能入口可见但禁用，统一说明「暂未开放」；直连接口返回 503 |
| 应用模式 | 前端运行在 Android 壳内、通过本机回环地址访问本机后端的模式 |

### 4.2 不做什么

- 不做 iOS 版本；不做 App Store / Google Play 上架；不做应用内账号体系。
- 不在应用内运行 FFmpeg、ffmpeg.wasm、WebCodecs 转码或 UVR。
- 不把本机后端暴露到局域网；应用不监听局域网端口。
- 不做双向实时数据库合并、CRDT、字段级冲突解决。
- 不替代现有桌面端与服务器 PWA；三者共用同一后端代码与前端代码。
- 不把「独立应用」宣传为「离线可用」：生成类功能依赖外部模型服务。

### 4.3 参考素材的真实边界

- 本地参考图：视频生成会把 `/static` 图片压缩后内联为 data URL（backend/src/services/generation.ts:945-970），应用可用。
- 本地参考视频/音频：部分厂商要求公网 URL（backend/src/services/generation.ts:997-1013、backend/src/services/reference-audio.ts:17-22）；应用没有公网地址，这类模型在本机按不可用处理并提示「需电脑接力」，或改用支持内联的厂商。
- 本地音色校验：需要 FFprobe（backend/src/services/reference-audio.ts:40-41），本机门控为不可用；接力到电脑后可用。
- 以上不改变「全功能」承诺：入口存在、状态明确、可一键转接力，而不是静默失败。

## 5. 总体架构

### 5.1 分层

| 层 | 组件 | 职责 |
| --- | --- | --- |
| 壳层 | Kotlin Android 应用 | 启动页、权限、WebView、扫码、文件选择、分享、通知、前台服务、进程守护 |
| 运行时层 | proot + Debian arm64 + Node 22 | 提供 glibc 环境与 Node 运行时；不依赖 Termux |
| 应用层 | 现有 Hono 后端 + Nuxt 前端 + SQLite + workspace | 业务逻辑零改写；仅增加应用模式与同步接口 |
| 数据层 | 应用私有目录 | SQLite、媒体、工作区、备份、同步暂存、日志；与运行时目录分离 |
| 连接层 | 电脑远程桥 / 数据同步 | 扫码接力与快照同步；应用只发起出站连接 |

### 5.2 进程与端口

- 主 Activity 启动前台服务；前台服务负责解压运行时、启动 Node、健康检查与重启。
- Node 只监听 `127.0.0.1`；端口默认 5679，占用时在 5679–5689 内重试，并持久化本次端口。端口变化会改变 WebView 来源，只影响本机界面偏好，不影响 SQLite 中的业务数据；切换端口时界面需提示。
- WebView 加载 `http://127.0.0.1:<port>`；所有请求带本机应用令牌 Cookie。
- 应用不监听 0.0.0.0，不开放局域网端口；扫码接力与数据同步都是出站 HTTP。
- 电脑端仍按既有设计：主后端回环，远程桥默认关闭、手动开启、绑定私有 IPv4。

### 5.3 应用私有目录布局

| 路径（应用私有根下） | 内容 | 升级策略 |
| --- | --- | --- |
| runtime/&lt;runtimeVersion&gt;/rootfs | Debian rootfs，含 Node、后端 bundle、前端、工作区模板、生产原生模块 | 随运行时包整体替换 |
| runtime/&lt;runtimeVersion&gt;/proot | proot 二进制、loader/loader32、运行库 | 随运行时包整体替换 |
| runtime/&lt;runtimeVersion&gt;/licenses | 第三方许可证与版权文本 | 随运行时包整体替换 |
| runtime/&lt;runtimeVersion&gt;/runtime-meta.json | 运行时版本、Node/proot 版本、schema 指纹 | 随运行时包整体替换 |
| runtime/&lt;runtimeVersion&gt;/manifest.json | 逐文件哈希、分卷哈希与体积 | 随运行时包整体替换 |
| data | SQLITE_PATH、STORAGE_PATH、媒体、workspace | 保留、迁移 |
| data/workspace | 可写工作区（提示词/技能） | 保留；按现有模板规则覆盖提示词、技能仅首次复制 |
| data/backups | 数据库备份（同步前、升级前、恢复前、手动） | 保留最近若干份 |
| data/sync | 同步暂存与清单 | 任务结束后清理 |
| data/.app-storage.json | 壳上报的运行时/日志/缓存占用快照（5 分钟一次），后端并入应用总占用 | 覆盖写 |
| logs | 后端与壳日志 | 滚动保留 |

运行时目录与数据目录必须分离，保证升级只替换运行时、不动数据；数据迁移由后端启动时的现有建表/迁移逻辑完成。数据目录在启动时以 `-b <data>:/mnt` 绑定进 guest，后端使用 `/mnt/huobao.sqlite3`、`/mnt/static`、`/mnt/workspace`（A2 真机验证）。

### 5.4 首次启动与重启

1. 壳检查运行时清单与哈希；缺失或不匹配则从 APK 资源解压（显示进度与剩余空间检查）。
2. 壳写入 DNS、时区、CA 证书等运行环境；复制工作区模板（仅首次）。
3. 壳生成一次性应用令牌，选择端口，启动 proot → Node → 后端。
4. 后端打印就绪标记；壳轮询 `/api/v1/health`（带令牌），超时则读取日志并提示重试。
5. 壳设置令牌 Cookie，加载 WebView；前端识别应用模式。
6. 进程退出或健康检查连续失败：前台服务按退避重启；连续失败进入「运行时修复」页，可重新解压运行时，数据保留。
7. 恢复备份：后端写入恢复请求并生成「恢复前」安全备份；前端经壳桥重启服务，后端在打开数据库前完成整文件替换；失败保留原库并在设置页显示结果。

### 5.5 本机访问控制（新增）

- 应用模式注入 `HUOBAO_APP=1` 与一次性 `HUOBAO_APP_TOKEN`；后端中间件要求所有请求携带该令牌（Cookie 或请求头），否则返回 401。
- 令牌每次启动随机生成，只存在于壳内存与 WebView Cookie，不写日志、不入库。
- 同进程内部调用（自动化、MCP、批量视频）经 `app.fetch` 不经过网络，但同样经过中间件；由统一的内部请求包装补上 `x-huobao-app-token`，不额外复制令牌。
- 端口随机化不能替代令牌：同机其他应用可以扫描回环端口；令牌是必要边界。
- 桌面端与服务器模式不启用该中间件，行为不变。

### 5.6 应用模式信号

- 壳注入 `window.huobaoApp` 对象（与桌面壳 `window.huobaoDesktop` 同思路），并提供受限方法：打开扫码、返回本机、设置活动任务数、导出日志。
- 壳加载首页时附加 `client=android-app` 查询参数；前端写入本机存储，后续路由沿用。
- 前端据此跳过 Service Worker/PWA 安装逻辑、显示「本机与连接」设置分区、隐藏主机专属入口。
- WebView 导航白名单：仅允许 `http://127.0.0.1:<port>` 与私有 IPv4 的电脑桥地址；其他地址交给系统浏览器，禁止在 WebView 内加载。

## 6. 内嵌运行时方案

### 6.1 路线选择

| 路线 | 结论 | 理由 |
| --- | --- | --- |
| 应用内嵌 proot + Debian arm64 + 官方 Node 22 | 采用（2026-11-11 A1 真机通过） | 与现有后端零改写；glibc 预编译原生模块可用；不要求用户装 Termux |
| 用户自装 Termux + proot-distro | 不采用 | 依赖用户操作与外部应用，违背独立应用 |
| nodejs-mobile | 不采用 | 运行时版本过低，无法满足 Node ≥22.13 |
| 重写后端为纯 Web/WASM | 不采用 | 工作量为数量级，且 SQLite/sharp/任务队列无法等价 |
| 远程连接电脑/服务器 | 仅作为接力形态 | 不满足独立运行 |

### 6.2 运行时组成

| 组件 | 版本/来源 | 说明 |
| --- | --- | --- |
| proot | Termux proot 5.1.107.102 aarch64（含 `libtalloc`、`libandroid-shmem`） | 只作为运行时组件，不安装 Termux 应用 |
| proot loader | 与 proot 包同源的 `loader`/`loader32` | 必需组件；缺失时所有 exec 返回 EACCES；经 `PROOT_LOADER`/`PROOT_LOADER_32` 指向应用私有目录 |
| Debian rootfs | Debian bookworm/trixie arm64 最小根文件系统 | 含 ca-certificates、libstdc++6、tzdata；不含 FFmpeg |
| Node | 官方 linux-arm64 22.16.x 或更高（≥22.13） | 与原生模块 ABI 对齐（Node 22 ABI 127） |
| better-sqlite3 | 12.x linux-arm64 glibc 预编译 | 在 Linux arm64 环境安装，不能在 macOS 交叉安装后直接复用 |
| sharp | 0.34.x linux-arm64 预编译 | 含 @img/sharp-linux-arm64 |
| 后端 | esbuild 单文件 ESM | 外置 sharp/better-sqlite3；不包含 ffmpeg-static/ffprobe-static |
| 前端 | Nuxt generate 静态产物 | 约 5MB |
| 工作区 | backend/workspace 模板 | 首次复制到数据目录 |

### 6.3 构建环境

- 在 linux/arm64 容器或真机环境中执行运行时打包：安装生产依赖、验证原生模块、生成后端 bundle、复制前端产物。
- 不得在 macOS 上直接安装 linux-arm64 原生模块后假定可用；必须以 Linux arm64 环境产物为准。
- 运行时包清单记录：运行时版本、Node 版本、后端版本、schema 指纹、每个文件的 SHA-256。
- 打包脚本纳入仓库（A2），签名密钥不入库。

### 6.4 解压与校验

- 运行时以 zstd 压缩 tar 分卷放入 APK assets；壳用 Apache Commons Compress + zstd-jni 解压，保留符号链接与可执行位。归档不含硬链接条目（Android 16 应用私有目录禁止 `link()`，A2 已用 `--hard-dereference` 生成并按文件清单校验）。
- 解压前检查可用空间（运行时大小 × 1.5 + 数据增量）；解压到临时目录，校验清单后原子重命名。
- 解压失败或校验失败：清除临时目录，保留旧运行时；提示重试或重新安装。
- 升级 APK 时：新运行时解压到新版本目录，校验通过后切换；旧版本保留一份以便回滚。

### 6.5 Android 执行限制与备选

- Android 10 起，targetSdk ≥29 的应用不能执行应用数据目录内的文件；Termux 通过 targetSdk 28 规避，本设计优先采用同一路线。
- 2026-11-11 A1 已在 Y700（Android 16）验证通过：targetSdk 28 的 APK 可安装，并能从应用私有目录执行 proot、rootfs 内 Node 22 与 glibc 原生模块；SELinux 保持 Enforcing。
- 备选路线（A1 结论后保留为应急）：保持现代 targetSdk，把 proot/Node 等可执行 ELF 以 `lib*.so` 形式放入 jniLibs（nativeLibraryDir），从该目录执行；rootfs 与业务文件仍在数据目录，原生模块通过 dlopen 加载。
- 两条路线都失败时停止实施，按第 15 节重新决策；不得通过关闭系统安全机制或要求 root 绕过。

### 6.6 运行环境细节

- DNS：壳从 Android 网络信息读取 DNS 并写入 rootfs 的 resolv.conf；网络切换后重写并提示重启后端。
- CA：rootfs 安装 ca-certificates；如企业代理使用自签证书，由用户在应用设置中导入，不默认信任用户证书。
- 时区：壳注入 TZ；rootfs 含 tzdata。
- 语言：Node/后端按现有 locale 逻辑；前端语言由用户设置。
- FFmpeg：不放入 rootfs，不设置 FFMPEG_BIN/FFPROBE_BIN；能力探测为不可用。
- 内存：Node 默认堆上限按设备内存调整；A1 记录启动与生成任务的内存峰值。
- proot 运行参数（A1/A2 实测）：设置 `PROOT_TMP_DIR`（应用私有、可写）、`PROOT_NO_SECCOMP=1`、`PROOT_LOADER`/`PROOT_LOADER_32` 指向随包分发的 loader，并设置 `LD_LIBRARY_PATH` 指向 `<runtime>/proot/lib`（Termux proot 的 RUNPATH 固定为 Termux 安装路径，不设置会找不到 `libtalloc.so.2`/`libandroid-shmem.so`）；rootfs 与可执行文件使用物理路径 `/data/data/...`；绑定 `/dev`、`/proc`、`/sys`；数据目录以 `-b <data>:/mnt` 绑定进 guest，后端使用 `/mnt/huobao.sqlite3`、`/mnt/static`、`/mnt/workspace`（数据路径必须映射，否则会被写进 rootfs，A2 真机实测）。

## 8. 局域网扫码接力（复用已实现设计）

### 8.1 流程

1. 电脑端设置 → 手机接力 → 开启远程桥（默认关闭、每次手动）→ 展示二维码（120 秒一次性码）。
2. 应用 → 连接电脑 → 扫码（或手动输入短码）→ 校验地址必须是私有 IPv4 的电脑桥地址。
3. 应用在 WebView 打开电脑桥的配对页 → 电脑端弹窗确认设备与范围（全量/只读）→ 应用获得 30 天设备 Cookie。
4. 应用加载电脑端前端，作为同一实例的远程客户端继续工作；页面显示远程状态徽标。
5. 返回本机：通知栏动作或应用内「客户端」入口；断开电脑可清除设备 Cookie，电脑端也可撤销设备。

### 8.2 应用侧要求

- 相机权限仅用于扫码；不申请麦克风与存储权限。
- 扫码结果只接受 `http://<私有 IPv4>:<桥端口>/pair...`；拒绝公网、域名、file、javascript 等地址。
- WebView 内允许加载电脑桥页面；外部链接交给系统浏览器。
- 接力期间本机后端继续运行但前台页面连接电脑；本机数据不被读写。
- 电脑桥停止、电脑休眠或网络切换：显示不可达，提供返回本机与重试。
- 只读设备：前端沿用既有只读拦截；应用不提供绕过入口。

### 8.3 能力与数据

- 接力期间所有接口与能力取电脑实例；电脑有 FFmpeg 时导出/合片可用，任务在电脑执行。
- 接力不改变本机数据库；返回本机后看到的是本机数据。
- 接力与数据同步是两件事：接力共享电脑实例，数据同步复制数据；界面文案必须区分。

### 8.4 复用与改动

- 复用：remote 路由与服务、配对页、远程状态徽标、只读与在线状态、脏表单保护。
- 新增：壳侧扫码、地址校验、WebView 打开/返回、通知栏动作、应用内连接入口。
- 不新增第二套配对协议，不修改设备会话模型。

## 9. 局域网数据同步

### 9.1 语义

- 同步单位：整库（业务表 + 媒体）；v1 不做按剧集选择。
- 方向：显式二选一，应用发起。
  - 拉取：电脑 → 应用（应用以电脑数据为准）。
  - 推送：应用 → 电脑（电脑以应用数据为准）。
- 不做双向合并；目标端现有同表数据被来源替换；媒体只增/覆盖，不删除目标端多余文件。
- 每次同步必须由电脑端逐次确认；设备配对只提供身份，不提供静默同步权限。
- 同步是可选功能；不连接电脑时应用完全独立。

### 9.2 角色与鉴权

| 角色 | 监听 | 职责 |
| --- | --- | --- |
| 电脑（主机） | 远程桥，私有 IPv4，端口 5680 | 提供清单、数据库快照、媒体下载；接收上传、校验、应用、备份 |
| 应用（客户端） | 不监听局域网 | 发起同步、预览、传输、应用、备份、报告结果 |

- 鉴权沿用设备 Cookie（`huobao_device`）与桥的设备上下文；只读设备不能同步。
- 数据同步接口在桥管线的白名单内，但仅对全量设备开放；主机管理接口仍 404。
- 每次同步创建一次性 run，电脑端确认后有效；run 有过期时间（建议 24 小时）与取消能力。
- 应用侧的同步客户端在本机回环内运行，使用应用令牌调用本机后端编排接口；对电脑的请求带设备 Cookie 与正确 Origin。
- 设备 Cookie 的交接：壳从 WebView CookieManager 读取电脑桥来源的 `huobao_device`，仅在发起同步时通过应用令牌保护的回环接口交给本机后端；后端只保存在本次 run 的内存中，不写库、不落盘、不写日志。读取不到 Cookie 时提示先完成扫码接力或重新配对。

### 9.5 拉取流程（电脑 → 应用）

1. 应用检查空间（预计媒体总大小 + 数据库大小 + 20%），读取本机版本与 schema 指纹。
2. 应用发起 run；电脑端弹窗显示设备、方向、版本、表数量、媒体数量与总大小；用户确认。
3. 电脑端用 SQLite 在线备份生成一致快照（业务可继续读写），计算媒体清单与哈希；清单是 run 起点的点时间视图，期间新增文件由下次同步补齐。
4. 应用下载数据库快照到 data/sync/staging，校验完整性、schema 指纹与行数。
5. 应用按清单下载缺失或哈希不同的媒体到暂存；支持断点续传与并发上限（建议 3）。
6. 应用停止本机队列与后台任务，备份本机数据库（保留最近 3 份）。
7. 应用把暂存媒体原子移动到目标路径；再在单个事务内替换业务表；外键检查与完整性检查通过后提交。
8. 应用重启队列与后台任务，报告完成；电脑端记录结果并清理快照与暂存。
9. 失败：事务回滚，数据库保持同步前状态；媒体可能已部分覆盖，但不影响旧数据库引用；暂存下次启动清理。

### 9.6 推送流程（应用 → 电脑）

1. 应用检查空间与版本；电脑端确认 run。
2. 应用生成数据库快照与媒体清单（哈希可后台计算并显示进度）。
3. 应用向电脑上传数据库快照（分块、可续传）；电脑校验完整性与 schema 指纹。
4. 应用按清单上传缺失或不同的媒体到电脑暂存；电脑逐文件校验大小与哈希。
5. 电脑端停止队列，备份数据库，应用暂存媒体，事务替换业务表，完整性检查通过后重启队列。
6. 电脑端报告完成；应用清理暂存。
7. 失败：电脑数据库事务回滚，旧数据可用；暂存清理；已上传媒体不影响旧数据。

### 9.7 数据应用细节

- 事务内先删除同步表数据，再按外键顺序插入来源快照；SQLite 外键在事务外关闭、事务内使用延迟检查，提交前执行 foreign_key_check，失败回滚。
- 保留来源主键与时间戳；不重新生成 ID。
- 若存在 AUTOINCREMENT 表，同步更新 sqlite_sequence，避免后续插入冲突。
- 媒体移动使用同盘原子重命名；跨盘时先复制到目标同盘临时文件再重命名。
- 目标端多余媒体不删除；提供「清理未被引用媒体」的后续功能，不在 v1 自动执行。
- 同步前备份只覆盖数据库；媒体按文件覆盖，无法整体回滚，故必须先完成全部媒体暂存再应用数据库，避免数据库指向未就绪文件。

### 9.8 版本与完整性

- 版本校验：应用版本、后端版本、schema 指纹三者一致才允许同步；不一致直接拒绝并提示升级到同一版本。
- schema 指纹由同步表的列定义排序计算，不依赖数据库文件版本；不同步表的变化不影响指纹。
- 数据库快照校验：integrity_check、表行数、schema 指纹、文件大小。
- 媒体校验：大小 + SHA-256；哈希不一致的文件重传，最多重试 2 次。
- 清单与 run 绑定；run 过期后必须重新生成，避免使用过期清单。

### 9.9 界面

- 应用：设置 → 数据同步 → 选择方向 → 预览（来源、表数量、媒体数量与大小、上次同步）→ 确认 → 进度（准备、传输、应用、完成）→ 结果。
- 电脑：待确认弹窗（设备、方向、规模、预计时间）；同步记录列表；暂存占用与清理。
- 文案必须写清「将覆盖本机/电脑的业务数据与媒体」「不会删除多余媒体」「不会同步 AI 密钥与设备会话」。
- 同步中禁止关闭应用或电脑；离开页面不中断，前台服务保持运行。

### 9.10 失败与恢复

| 场景 | 处理 |
| --- | --- |
| 网络中断 | 下载/上传断点续传；run 保留 24 小时；超时后重新发起 |
| 电脑休眠/桥关闭 | 应用提示不可达；恢复后重试；不自动重连写入 |
| 应用被杀 | 前台服务重启；数据库事务回滚；暂存清理；提示重新同步 |
| 磁盘不足 | 预检拒绝；已暂存内容保留待清理；不开始应用 |
| 版本不一致 | 传输前拒绝；提示两端升级 |
| 哈希不一致 | 重传该文件；仍失败则中止并保留旧数据 |
| 应用数据库事务失败 | 回滚；备份保留；报告错误码与日志位置 |
| 电脑数据库应用失败 | 回滚；旧数据可用；通知应用失败 |

### 9.11 安全与限流

- 每次同步电脑端确认；设备只读范围不能同步；设备撤销后立即失效。
- 桥只绑定私有 IPv4；不映射公网；传输为局域网 HTTP，限可信网络。
- 同步接口限流：每设备每分钟创建 run 上限、并发 run 上限 1、单文件大小上限、总大小上限（可配置）。
- 日志不记录 Cookie、令牌、文件内容；记录 run、方向、大小、结果、错误码。
- 同步暂存目录权限仅应用/电脑用户可读写；结束后清理。
- 应用侧电脑 Cookie 由 WebView 管理；同步客户端只在内存中使用，不写入日志。

### 9.12 后续版本

- v1.1：按剧集/项目选择同步、增量媒体清单缓存、同步记录与差异预览。
- v2：双向同步与冲突解决（需要版本字段、基础快照与合并策略），另立设计；不在本期承诺。

## 10. FFmpeg 能力门控

- 判定：按当前连接实例的服务端能力，不按设备类型；探测失败按不可用；所有客户端一致。
- 接口：`GET /api/v1/capabilities` 返回 `outputActions`、`audioSeparation`、`voiceActions`、`ffprobe` 等布尔值与版本信息；进程内缓存 30 秒，媒体设置变更时失效。
- 入口：所有 FFmpeg/FFprobe 产出动作统一门控；读取、播放、预览、编辑保持开放。
- 直连：被门控接口返回 503 与 `MEDIA_UNAVAILABLE`，不执行半途失败。
- 自动流程：缺少能力时跳过配音/合片等后期阶段并写入说明，不使整条流程失败。
- 独立应用：本机能力恒为不可用；应用不设置 FFmpeg/FFprobe 路径，不内置二进制。
- 接力：能力取电脑实例；电脑有 FFmpeg 时应用页面恢复产出入口，任务在电脑执行。
- 文案：四语言同步；技术名 FFmpeg/FFprobe 不翻译；入口显示「暂未开放」并说明原因与替代路径（接力到电脑）。

## 11. 安全与隐私

- 本机后端只监听回环，且要求一次性应用令牌；同机其他应用无法直接调用。
- 应用令牌随机、短生命周期、不入库、不写日志；WebView 通过 HttpOnly Cookie 携带。
- WebView 导航白名单；禁止 file://、content://、第三方公网页面在壳内加载；外部链接交系统浏览器。
- 文件选择使用系统选择器；下载只接受本机回环地址，先用系统选择器确定保存位置，再由前台服务带应用令牌流式写入并显示进度，完成后可打开或分享。
- 数据库备份不含 Cookie、令牌与设备会话；导出由用户在系统选择器中显式选择目标。
- 数据存储于应用私有目录，受 Android 文件级加密保护；`allowBackup=false` 或备份规则排除运行时、数据库与媒体，避免云备份泄露与体积膨胀。
- 扫码只接受私有 IPv4 的配对地址；配对必须电脑确认；设备可撤销；只读设备不能写。
- 同步不传输 AI 密钥、MCP 令牌、设备会话与主机设置；日志不记录 Cookie 与内容。
- 不修改用户网络/证书/代理配置来掩盖失败；需要自签证书时由用户显式导入。
- 安全边界诚实声明：局域网 HTTP 存在窃听风险，仅限可信网络；需要公网时继续使用既有 HTTPS 反代形态，应用不提供公网入口。

## 12. 构建、签名、升级与分发

- 工程：Kotlin + Android Gradle Plugin；compileSdk 36；minSdk 26；仅 arm64-v8a；targetSdk 由 A1 结论决定（优先 28，备选现代 targetSdk + nativeLibraryDir 方案）。
- 签名：本地 keystore，密码与文件不入库；构建产物不入库。
- 版本：应用 versionName 与仓库版本对齐（4.0.x）；versionCode 单调递增；运行时包独立版本，记录在应用设置中。
- 构建顺序：前端生成 → 后端 bundle → Linux arm64 生产依赖 → 运行时打包 → APK 组装 → 真机安装。
- 升级：覆盖安装保留数据；启动时后端执行现有迁移；运行时版本变化时替换运行时目录；降级安装拒绝或提示不兼容。
- 回滚：保留上一份运行时与数据库备份；回滚只回滚运行时，不回滚数据（除非用户显式恢复备份）。
- 分发：侧载 APK；不接商店；提供校验和与版本说明；不提供自动更新服务（应用内可检查用户手动下载的新 APK，属后续可选）。
