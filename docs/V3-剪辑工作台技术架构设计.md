## 0. 一页结论

### 0.1 技术结论

剪辑工作台不引入新的运行时、不嵌入开源编辑器内核、不新建第二套导出系统。它以现有 **Nuxt 3 SPA + Hono + Drizzle/SQLite + FFmpeg** 为底座，新增三层能力：

1. **一份计划**：`EditPlan v1` 是画面顺序、时长、字幕、画中画、转场的唯一真相源；
2. **一条时间桥**：`EditPlan → buildEditTimeline → MixPlan`，用 `editSyncHash` 判断混音是否过期；
3. **一条渲染链**：`静音剪辑轨 cut.mp4 + 原声参考 audio-ref.m4a + 混音 mix.wav/subtitles → 最终封装`，交互预览与最终渲染分离。

```text
┌──────────────────────────── 浏览器（Nuxt 3 SPA） ────────────────────────────┐
│                                                                              │
│  /edit  剪辑工作台                         /mix  混音工作台                    │
│  ├─ useEditPlan（唯一编辑状态）             ├─ useMixStage（现有）              │
│  ├─ EditTimeline（Canvas 主轨/字幕/参考）   ├─ MixTimeline（Canvas 多音轨）     │
│  ├─ EditPreview（视频池 2–3 个）            ├─ useMixPlayback（WebAudio）       │
│  └─ EditExportDrawer                        └─ 只读画面/字幕 + 跳转剪辑          │
│                                                                              │
└───────────────┬──────────────────────────────────────────┬───────────────────┘
                │ REST（camelCase 内部 / snake_case HTTP）    │
┌───────────────▼──────────────────────────────────────────▼───────────────────┐
│ Hono 路由                                                                    │
│  /episodes/:id/edit/**      /episodes/:id/mix/**      /episodes/:id/exports/**│
├──────────────────────────────────────────────────────────────────────────────┤
│ 服务层                                                                        │
│  edit-service ── edit-plan（纯函数：校验/布局/哈希/差异）                       │
│       │         edit-media（探测/代理/导入/重链）                              │
│       │         edit-timeline（EditPlan → 台词放置 → Mix 时间轴）              │
│       │         edit-render（剪辑轨/原声参考/精确预览）                         │
│       │                                                                      │
│  mix-plan（改造：优先 EditPlan，保留 legacy 回退）                              │
│  mix-render（复用：音频滤镜图）                                                │
│  export-service（扩展：快照 edit/mix revision，render_mode）                   │
├──────────────────────────────────────────────────────────────────────────────┤
│ SQLite（Drizzle）                          FFmpeg（ffmpeg-static / ffprobe）  │
│  episode_edit_drafts / edit_revisions      cut / audio-ref / preview / final  │
│  edit_renders / episode_media_proxies      concat / xfade / subtitles / mux   │
│  episodes.* 指针 / mix_revisions.* 指针                                        │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 0.2 十二个关键决策

| # | 决策 | 理由 | 代价 |
| --- | --- | --- | --- |
| D1 | 视频 `/edit` 与音频 `/mix` 两个独立路由、两个页面 | 一个页面两个时钟/两条时间线必然“四不像”；已由用户明确要求 | 需要跨页交接与状态同步 |
| D2 | `EditPlan` 是唯一画面时间轴真相源 | 混音、字幕、导出、预览都必须读同一份时间 | 需要一个可靠的迁移与 bootstrap |
| D3 | `MixPlan` 绑定 `editSyncHash`，不静默错位 | 画面时长/素材变化必须显式提示 | 需要 realign 差异算法 |
| D4 | 交互预览 = 视频池 + WebAudio；最终校验 = 服务端渲染 | 浏览器端无法实时做 xfade/滤镜/烧字幕；FFmpeg 结果才是权威 | 简化预览与成片存在轻微差异，需标注 |
| D5 | 最终成片导出归剪辑页，混音页只导出音频 | 避免两个页面都能写 `episodes.video_url` | 旧导出入口需要迁移 |
| D6 | 主轨磁吸 + 显式间隙（`gapBeforeMs`/`tailGapMs`） | 短剧剪辑以顺序拼接为主，间隙是少数情况；模型简单可验证 | 不支持多轨自由重叠（P2 才扩展） |
| D7 | 草稿与版本双层：300ms 自动存草稿，`Cmd+S` 存版本 | 自动保存不制造版本噪音，版本可回滚 | 需要 `baseVersion` 乐观锁 |
| D8 | 乐观并发：整份计划 + `baseVersion`，冲突显式选择 | 本地应用双窗口场景真实存在；JSON Patch 复杂且难审计 | 冲突时用户需做一次选择 |
| D9 | 静音剪辑轨与 `audio-ref` 原声轨分离 | 画面渲染可缓存、混音可独立重渲、原声可 ducking | 多一次音频渲染，需缓存 |
| D10 | 不嵌入开源编辑器内核，原生 Vue 时间轴 | OpenCut 重写中、Shotcut/Kdenlive 为 GPL/AGPL、React/Qt UI 不匹配 | 时间线交互需自研，工作量集中在 UI |
| D11 | 代理按需生成：>1080p 或非 H.264 | 控制磁盘与首次打开耗时 | 首次预览可能需要等待代理 |
| D12 | 复用 `episode_exports`，以 `render_mode` 区分最终/临时，不新建导出表 | 现有状态机、校验、历史、canonical 指针已可用 | 需要扩展字段与 `reuseKey` |

### 0.3 与产品设计的范围对齐

- P0/P1 的产品能力全部有对应的数据字段、API 与渲染路径；P2 只预留字段，不实现。
- “完整核心 = P0 + P1”在技术上落地为产品第 6 章矩阵中的全部 P1 能力，包括主轨编辑、字幕（全局偏移/分割合并/同步回台词本）、转场、变速、适配、叠加轨、滤镜、标题、Take、精确预览、版本对比、批量/多预设导出、标记、SRT 导入/导出、帧率设置、复制/粘贴、图片片段、旋转/翻转、全屏与 I/O。
- “操作简单”在技术上落地为：磁吸主轨、智能默认值、自动保存、无阻断撤销、预检提示、单主按钮导出。

## 1. 目标、约束与非目标

### 1.1 目标

| 目标 | 可验证结果 |
| --- | --- |
| 可用 | 一集 15–40 个镜头能在 `/edit` 完成初剪、字幕、试听、导出，不依赖外部剪辑软件 |
| 实用 | 画面变动后混音状态明确；导出结果可回溯到 `edit_revision` 与 `mix_revision` |
| 简单 | 默认一条主轨、磁吸、硬切、填充、硬字幕；首次打开自动初剪与字幕建议 |
| 不破坏 | 旧页面、旧导出、旧 `episodes.video_url` 在迁移期仍可用；源文件只读 |
| 可维护 | 计划校验/布局/哈希为纯函数；渲染与路由分层；前端状态单一来源 |

### 1.2 硬约束

- **技术栈不变**：Nuxt 3（`ssr:false`）、Vue 3.5、Pinia、Tailwind、naive-ui、lucide、vue-i18n；后端 Hono + Drizzle + better-sqlite3 + FFmpeg。
- **路由参数**：`/drama/:id/episode/:episodeNumber/edit` 与 `/mix`，与现有 `pages:extend` 的 `episodeNumber` 对齐（`frontend/nuxt.config.ts:19`）。
- **端口**：5679（后端）/3013（前端 dev）不变。
- **项目存储**：`PROJECT_SUBDIRS`（`backend/src/services/project-storage.ts:20`）只增不改；新增 `edit` 子目录。
- **模板**：`TEMPLATE_VERSION=6` 与 ComfyUI 工作流不变。
- **数据安全**：不删除旧表、不重写旧字段值；迁移先加列/加表，回滚只隐藏入口。
- **单机单进程**：桌面应用为单后端进程；锁与任务队列可以进程内为主、数据库为审计。

### 1.3 非目标

- 本设计（P0/P1）不做多机位、跟踪、三维、粒子、关键帧曲线、蒙版、调色轮、LUT 导入；多机位/跟踪/关键帧/蒙版/调色属于产品 P2 远期候选，不在本次实现；AI 自动字幕、AI 粗剪（含静音/口癖清理）同为 P2 评估项，需单独技术选型。
- 不做多人实时协作、云端渲染农场、社交平台直发。
- 不在本轮引入 WebCodecs 生产渲染、ffmpeg.wasm、GPU 端剪辑内核。
- 不重构视频生成、剧本、资产、ComfyUI 适配层。
- 不改变现有混音总线/ducking/loudnorm 的算法与参数语义。

## 2. 现状审计

### 2.1 技术栈与运行形态

| 层 | 现状 | 对本设计的影响 |
| --- | --- | --- |
| 前端 | Nuxt 3 SPA，`ssr:false`，页面集中在 `app/views/`，由 `pages:extend` 手动注册 | 新页面继续用 `views/drama/*.vue` + 手动注册，避免 `[id]` 目录 |

### 2.2 现有数据流（与剪辑相关）

```text
storyboards (每个镜头 video_url)
   │
   ├─ ensureMergedVideo() ──► video_merges + merged/*.mp4
   │        │                         │
   │        └──────────────► episodes.video_url（当前实现会写回）
   │                                  │
   ├─ previewTimeline() ──► buildTimeline() ──► 台词时间轴（配音/字幕/混音共用）
   │                                  │
   │                                  ├─ buildEpisodeSubtitles() ──► SRT/ASS
   │                                  └─ compileMixPlan() ──► MixPlan ──► mix-render
   │
   └─ episode_exports(kind=video) ──► renderExportVideo() ──► 成片
```

关键事实：

- `previewTimeline`（`backend/src/services/dubbing.ts:531`）按**分镜顺序**构建，不支持重排/裁剪后的时间轴；
- `compileMixPlan`（`backend/src/services/mix-plan.ts:433`）以 `previewTimeline` 为台词来源；
- `ensureMergedVideo`（`backend/src/services/dubbing.ts:134`）会在合片过期时自动重合并等待；
- `mergeEpisodeVideos` 完成后直接写 `episodes.video_url`（`backend/src/services/ffmpeg-merge.ts:252`）；
- `renderExportVideo`（`backend/src/services/export-render.ts`）只做画面缩放/字幕/封装，不设置输出帧率；
- `export-presets.ts` 现有视频预设为 `vertical-hd`（1080×1920，10 Mbps）、`horizontal-hd`（1920×1080，10 Mbps）、`vertical-high`（1080×1920，14 Mbps）；无 720p，无 `fps` 字段。

### 2.3 现有混音工作台能力与边界

| 能力 | 现状 | 剪辑页可复用 |
| --- | --- | --- |
| 多轨（对白/原声/音效/BGM/总线） | `MixStage.vue` + `useMixStage` | 只读参考与状态 |

### 2.4 现有导出流水线

`runVideoPipeline`（`backend/src/services/export-service.ts:615`）当前顺序：

1. `ensureMergedVideo`（合并分镜）；
2. `buildEpisodeSubtitles`（legacy 时间轴生成 SRT/ASS）；
3. `compileMixPlan`；
4. `renderMixAudio`（WAV）；
5. `measureAndCorrect`（响度）；
6. `renderExportVideo`（画面 + 混音 + 字幕）；
7. `validateExport`。

新导出必须替换 1–3 为“快照 EditPlan + 快照 MixRevision”，4–7 可复用。

`reuseKeyOf`（`export-service.ts:218`）当前由 `kind/preset/planHash/sourceVideoHash/subtitleHash/reuseParams` 组成；新导出必须显式加入 `editPlanHash/editSyncHash/dialogueSyncHash/subtitleHash/mixRevisionId/subtitleMode/renderMode`，防止“画面相同但字幕/剪辑/混音版本不同”误复用。最终导出复用键的完整输入见 9.11。

## 3. 架构决策记录（ADR）

### ADR-01 两个独立页面，共享项目层数据

**背景**：用户明确要求音频与视频分开；现有配音第 4/5 步同时承载预览、混音与导出，已经出现“四不像”。

**决策**：

- `/edit` 与 `/mix` 是两个路由、两个页面实例、两个播放器；
- 共享 `episodeId`、`episode_exports`、素材库、版本指针；
- 每次跳转通过 `WorkbenchHandoff` 传递播放头/区间/选中对象，不共享播放器实例；
- 两个页面各自只有一个可见预览与一个播放时钟。

**后果**：

- 正面：键盘、撤销、自动保存、版本语义可以独立定义；页面职责清晰；
- 负面：跨页状态需要显式同步；导出与混音状态的读取需要统一的 `GET /edit` 聚合响应。

### ADR-02 `EditPlan` 是唯一画面时间轴真相源

**背景**：现有分镜顺序、合片、台词时间轴、字幕、导出的时间信息分散在 `storyboards`、`video_merges`、`previewTimeline`、`episode_exports` 中，任何一处变化都可能让另一处过期。

**决策**：

- 所有画面顺序、入出点、变速、间隙、转场、字幕、叠加轨、工程设置写入 `EditPlan`；
- 混音页、字幕生成、导出、精确预览都从 `EditPlan` 读取；
- `episodes.video_url` 只是“当前成片”指针，不参与时间轴推导；
- 源素材（分镜/Take/合片/导入）只读，不被剪辑计划修改。

**后果**：

- 正面：单一真相源、可哈希、可版本化、可缓存；
- 负面：首次打开需要 bootstrap；旧数据需要兼容回退。

### ADR-03 `MixPlan` 绑定 `editSyncHash`，过期必须显式

**背景**：画面裁剪/重排/变速会改变时间，混音若继续播放会静默错位；画面滤镜/字幕变化则不应打扰声音。

**决策**：

- `EditPlan` 计算两个哈希：`planHash`（完整渲染）与 `editSyncHash`（影响时间/源素材的子集）；
- `mix_revisions` 保存创建时的 `edit_sync_hash` 与 `dialogue_sync_hash`；
- 混音状态 = 当前 `editSyncHash`/`dialogueSyncHash` 与当前混音版本比较；
- 过期时导出最终成片被阻断，只允许临时导出（原声，不含混音）。

**后果**：

- 正面：绝不静默错位；画面-only 修改不触发混音重做；
- 负面：需要 realign 差异算法与待确认列表。

### ADR-04 交互预览用视频池 + WebAudio，最终校验用服务端渲染

**背景**：浏览器无法实时做 FFmpeg 的 xfade、滤镜、烧字幕与多轨混音；但每次编辑都调用服务端渲染又太慢。

**决策**：

- 交互预览：2–3 个 `<video>` 组成的视频池（同一时刻只有一个可见），全部静音；音频由 WebAudio 播放混音或 `audio-ref`；
- 简化转场：CSS 透明度/黑场覆盖，明确标注“简化预览”；
- 精确预览：服务端按最终滤镜链渲染 0.5–30 秒区间（默认 5 秒），P1 提供；
- 导出前可用“精确预览”检查转场与字幕；
- WebCodecs 仅作为后续技术评估项，不在 P0/P1 范围。

**后果**：

- 正面：编辑流畅、结果可预期；
- 负面：简化预览与成片存在像素级差异，需要 UI 标注。

### ADR-05 最终成片导出唯一归属剪辑页

**背景**：`episodes.video_url` 当前有 5 个写入点，两个页面都能导出会造成指针竞态。

**决策**：

- 最终成片（`kind='video'`, `render_mode='final'`）只能从 `/edit` 导出；
- 混音页只导出 `audio-wav` / `audio-m4a` / `stems`；
- 合片、配音、动效产物一律降级为素材；
- `setCurrentExport` 是唯一更新 `episodes.video_url` 的业务入口（删除回退除外，见 6.10）。

**后果**：

- 正面：指针单一、导出可追溯；
- 负面：旧入口必须逐步收敛（M4）。

### ADR-06 磁吸主轨 + 显式间隙

**背景**：短剧以顺序叙事为主，自由多轨重叠不是核心；用户要“简单”。

**决策**：

- 主轨是一条有序数组，每个片段有 `gapBeforeMs`（相对前一片段结束的额外空档）；
- 默认波纹删除/插入时 `gapBeforeMs=0`；
- **裁剪默认两端波纹**：改源入/出点后片段起点不变，后续片段随内容时长整体移动；
- **`Alt/Option` 非波纹裁剪**：改变片段起点/终点本身，差额写入 `gapBeforeMs`（尾部写入 `tailGapMs`），后续片段不动；
- “仅删除留空”把删除片段的时长并入后一片段的 `gapBeforeMs`；
- 叠化转场允许重叠，重叠时长从总时长中扣除；
- 首段可有 `gapBeforeMs`，尾段由 `tailGapMs` 控制；
- 空档导出为黑场。

**后果**：

- 正面：模型简单、布局可解析、波纹/留空都可表达；
- 负面：不支持多视频轨自由重叠（P2 用独立 `overlays` 表达画中画）。

### ADR-07 草稿与版本双层

**背景**：自动保存若每次都产生版本，版本列表会被噪音淹没；若不保存，崩溃会丢工作。

**决策**：

- `episode_edit_drafts`：每集一行，300ms 防抖覆盖写，带 `version` 自增；
- `edit_revisions`：用户 `Cmd+S` 或系统里程碑创建，不可变；
- 导出必须引用一个 revision（导出前若草稿未存版本，自动创建里程碑）；
- 恢复版本 = 以旧版本内容创建新版本，不删除历史。

**后果**：

- 正面：自动保存与版本历史解耦；
- 负面：草稿与当前版本可能不同，UI 必须显示“未保存版本”状态。

### ADR-08 乐观并发：整份计划 + `baseVersion`

**背景**：同一集可能在两个窗口打开；本地应用也可能有多个标签页。

**决策**：

- `PUT /edit/draft` 携带 `base_version`；
- 服务端在事务内比较 `episode_edit_drafts.version`，不匹配返回 `409 EDIT_VERSION_CONFLICT` 与当前草稿；
- 客户端选项：重新加载 / 另存为副本 / 覆盖（二次确认）；
- 不做自动合并、不做字段级冲突解决；
- 导出与版本创建同样带 `base_version`，避免导出快照与用户认知不一致。

**后果**：

- 正面：实现简单、行为可解释；
- 负面：冲突时用户需要做一次选择。

### ADR-09 静音剪辑轨 + `audio-ref` 原声轨分离

**背景**：最终混音由混音页负责；但如果把原声直接混进剪辑视频，混音页无法单独 ducking/替换；如果剪辑轨完全没有音频，混音页又缺少原声床。

**决策**：

- `cut.mp4` 只渲染画面（无音轨或静音音轨）；
- `audio-ref.m4a` 按剪辑时间轴渲染源素材原声（含入出点/变速/间隙）；
- 混音页把 `audio-ref` 作为原声总线的一个片段源，可调音量/声像/ducking；
- 导出最终封装 = `cut.mp4` + `mix.wav` + 字幕。

**后果**：

- 正面：画面与声音可独立缓存、独立重渲；原声仍可被混音处理；
- 负面：多一个渲染产物；`audio-ref` 过期需要重建。

### ADR-10 不嵌入开源编辑器内核，原生 Vue 时间轴

**背景**：可行性分析已核查 OpenCut/Concat/Shotcut/Kdenlive/OpenShot/etro/Remotion 等，未找到可直接嵌入、许可证与栈匹配的内核。

**决策**：

- 时间线自研，复用 `MixTimeline` 的 Canvas 经验；
- 只借鉴交互模式与渲染思路，不引入 GPL/AGPL 代码；
- 渲染继续用 FFmpeg CLI，不引入 Remotion/WebCodecs 生产依赖。

**后果**：

- 正面：完全可控、与项目数据模型贴合；
- 负面：时间线交互（吸附、拖拽、缩放手感）需要打磨与测试。

### ADR-11 代理按需生成

**背景**：素材可能是 1080p/4K、H.265、可变帧率；直接放进 `<video>` 预览会卡顿，且浏览器解码能力不一。

**决策**：

- 阈值：`height > 1080` 或编码非 H.264 或帧率 > 30 时生成 720p H.264 代理；
- 代理只用于预览，不用于导出；
- 代理文件存 `edit/proxy/`，按 `source_fingerprint` 缓存；
- 生成失败不阻断编辑，回退原文件并提示。

**后果**：

- 正面：预览稳定；
- 负面：首次打开可能等待；磁盘占用增加。

### ADR-12 复用 `episode_exports`，不新建导出系统

**背景**：现有导出已有状态机、进度、校验、历史、当前指针、取消/重试。

**决策**：

- 新导出沿用 `episode_exports`，`kind='video'`；
- 新增 `render_mode`（`final`/`temp`/`edit-only`）、`edit_revision_id`、`mix_revision_id`、`edit_plan_hash`、`edit_sync_hash`、`dialogue_sync_hash`、`subtitle_mode`；
- `reuseKeyOf` 纳入新哈希；
- 旧导出记录保持原样，不批量重写。

**后果**：

- 正面：一套状态机、一套 UI 轮询；
- 负面：`episode_exports` 字段增多，需要迁移与索引。

## 4. 领域模型：EditPlan v1

### 4.1 实体关系

```text
episodes 1 ─── 1 episode_edit_drafts
    │ 1
    ├── n edit_revisions ─── n edit_renders（缓存/预览）
    │        │
    │        └── n episode_exports（快照引用）
    │
    ├── n mix_revisions ─── n episode_exports
    │        │
    │        └── 绑定 edit_revision_id + edit_sync_hash + dialogue_sync_hash
    │
    ├── n video_merges（素材来源，不再写最终指针）
    ├── n storyboards / storyboard_lines / line_takes（素材与台词来源）
    └── 1 episodes.video_url（仅由最终导出更新）
```

### 4.3 时间模型

**源片段时长**

```text
contentDurationMs = round((sourceOutMs - sourceInMs) / speed)
```

约束：

- `MIN_CLIP_FRAMES = 3`，`minimumClipMs = ceil(MIN_CLIP_FRAMES * 1000 / project.fps)`（30fps 约 100ms，24fps 125ms；60fps 工程为 P2）；
- `sourceOutMs - sourceInMs >= minimumClipMs`；
- `contentDurationMs >= minimumClipMs`；
- 变速不改变源素材，只改变时间映射；音频用 `atempo` 链保持一致；
- 图片片段：`durationMs` 为显示时长，`sourceInMs=0`，`sourceOutMs=durationMs`，`speed=1`。

**布局**

```text
start[0] = gapBeforeMs[0]
end[i]   = start[i] + contentDurationMs[i]
start[i] = end[i-1] - overlap(i-1, i) + gapBeforeMs[i]
overlap(i-1, i) = transition(i-1, i)?.durationMs ?? 0
contentEndMs = end[n-1]
durationMs = max(contentEndMs, max(overlay.endMs)) + tailGapMs
```

**转场规则**

| 规则 | 值 |
| --- | --- |
| 允许位置 | 仅主轨相邻片段交界 |
| 一个交界 | 最多一个转场 |
| 转场与空档 | `gapBeforeMs > 0` 时不允许转场（归一化时移除并告警） |
| 时长范围 | `100–1500ms`，P0 叠化默认 400ms；可用余量 `<100ms` 时移除转场并告警 |
| 可用余量 | `overlap <= min(contentDuration[i-1], contentDuration[i]) - 1/fps` |
| 总时长 | 叠化减少总时长；片段边缘淡入/淡出不改变总时长 |
| 转场类型 | P0 仅 `dissolve`；P1 增加 `white`/`push-left`/`blur` |

**片段边缘淡入/淡出黑**

产品与技术在 2026-11-05 统一：淡入/淡出黑是**片段边缘效果**，不是转场类型，不在交界转场槽位中。

| 用户选择 | 数据表示 | 渲染 |
| --- | --- | --- |
| 片段头部淡入黑 | 该片段 `videoFadeInMs=d` | `fade=t=in:st=0:d=d/1000` |
| 片段尾部淡出黑 | 该片段 `videoFadeOutMs=d` | `fade=t=out:st=contentD/1000-d/1000:d=d/1000` |
| 片头淡入 | 第一段 `videoFadeInMs` | 同上 |
| 片尾淡出 | 最后段 `videoFadeOutMs` | 同上 |

片段边缘淡入/淡出可与叠化同时存在：叠化作用在片段之间，淡入淡出作用在片段首尾。淡入淡出不进入 `editSyncHash`，只进入 `renderHash`。

归一化约束：`videoFadeInMs + videoFadeOutMs <= contentDurationMs`；超出时按比例缩短并告警。

**间隙**

- 间隙在导出中生成黑场（可带静音）；
- 间隙不产生字幕，不产生声音；
- `tailGapMs` 默认 0，最大 60s；
- `gapBeforeMs` 单段最大 5 分钟，超过视为错误（防止误输入撑爆渲染）。

### 4.4 校验与归一化

**执行顺序**

```text
parse → schema 校验 → 数值归一化 → 片段归一化 → 转场归一化
     → 字幕归属与跟随归一化 → 叠加轨归一化 → 重新布局
     → 源文件存在性/指纹校验（I/O，可异步）→ 返回 issues
```

**规则表**

| 字段 | 规则 | 级别 | 归一化 |
| --- | --- | --- | --- |
| `version` | 必须为 1 | error | 拒绝 |
| `project.width/height` | 16–7680，偶数 | error | 拒绝 |
| `project.fps` | 1–120 | error | 拒绝 |
| `clips[].id` | 唯一、非空 | error | 拒绝 |
| `clips[].source.url` | 非空 | error | 拒绝 |
| `sourceInMs` | `>=0` 且 `< sourceOutMs` | error | 截断到源时长 |
| 片段时长 | `>= minimumClipMs`（3 帧） | error | 拒绝 |
| `speed` | 0.25–4.0 | error | 截断 |
| `gapBeforeMs` | 0–300000 | error | 截断 |
| `videoFadeIn/Out` | `0–1500ms`，和 ≤ 片段时长 | warning | 先截断到 1500ms，再等比缩放 |
| `transition.durationMs` | 100–1500 且 ≤ 可用余量 | warning | 余量 ≥100ms 时截断到余量；余量 <100ms 时移除转场 |
| 非相邻转场 | — | error | 移除 |
| 有间隙的转场 | — | warning | 移除转场 |
| 字幕 `start < end` | — | error | 修正为 100ms |
| 字幕重叠 | 同轨重叠 | warning | 保留，导出时提示 |
| `follow` 但无 anchor | — | warning | 转为固定 |
| anchor 指向不存在片段 | — | warning | 转为固定 |
| cue 超出总时长 | — | warning | 截断到总时长 |
| 叠加轨 `end <= start` | — | error | 移除或修正 |
| 叠加轨重叠 | 同轨重叠 | warning | 保留（后添加者覆盖） |
| 文案长度 | 单条 ≤ 500 字符 | warning | 截断 |
| 片段数 | ≤ 200 | error | 拒绝 |
| 字幕数 | ≤ 2000 | error | 拒绝 |
| 计划 JSON | ≤ 8 MB | error | 拒绝 |

**字幕跟随的归一化**

```text
若 follow && anchor:
  clipStart = layout.clip(anchor.clipId).timelineStartMs
  duration = endMs - startMs
  startMs = clipStart + anchor.offsetMs
  endMs = startMs + duration
  若 startMs < clipStart: startMs = clipStart, endMs = startMs + duration
  若 endMs > clip 末尾: endMs = clipEnd，并告警“字幕超出片段”
```

当用户拖动片段时，服务端只改 `anchor.offsetMs` 不变；布局后 cue 自动跟随。用户拖动 cue 时，客户端将 `follow=false`、`anchor=null`。

### 4.5 哈希

所有哈希使用 SHA-256，输出 16 进制前 32 位（足够区分且便于日志），对规范化 JSON 计算。

| 哈希 | 覆盖范围 | 用途 |
| --- | --- | --- |
| `planHash` | 完整计划：项目设置、片段、转场、字幕、叠加轨、滤镜、变换、淡入淡出；导出复用键中记作 `editPlanHash`，二者同值 | 导出复用、审计 |
| `renderHash` | 画面子集：片段源/入出点/变速/间隙/转场/变换/滤镜/淡入淡出/叠加轨/项目尺寸帧率背景/`tailGapMs`；不含字幕文本与时间 | 剪辑轨缓存 |
| `editSyncHash` | 时间与源素材子集：`fps`、同步段（相邻同源连续片段合并后的顺序/源指纹/入出点/变速/间隙）、转场类型/时长、`tailGapMs`、叠加轨对总时长的影响 | 混音过期判断 |
| `dialogueSyncHash` | 当前台词/生效配音 Take：`lineId`、`voiceTakeId`（`line_takes.id`）、`takeUrl`、`takeFingerprint`、`durationMs`、顺序 | 混音过期判断（配音变化） |
| `subtitleHash` | 字幕子集：cue 文本、起止、样式、跟随/固定、锚点、排序 | 字幕文件、精确预览、导出复用 |
| `sourceFingerprint` | 源文件 `size:mtimeMs` | 源文件替换检测、代理缓存 |

**规范化规则**

- 对象键按字典序；数值统一为整数毫秒/整数百分比；
- 片段按时间线顺序输出，不按 ID 排序；
- `editSyncHash` 使用合并后的同步段序列；只保留同步段之间的转场类型与时长，段内拆分产生的硬切不进入哈希；
- 转场映射为“交界索引 + 类型 + 时长”，不直接哈希 `fromClipId/toClipId`；
- 字幕按 `startMs`、`endMs`、`text` 排序；不包含 `id`、`lineId`；
- 叠加轨按 `startMs`、`id` 排序；包含文本样式与位置；
- 不包含 `markers`、`layout`、`label`、`thumbnailUrl`；
- `renderHash` 不包含任何字幕字段。

**拆分不变性（split invariance）**

拆分片段不应让混音过期。计算 `editSyncHash` 前，先把主轨归一化为“同步段”：

- 相邻片段满足以下全部条件时合并为一个同步段：`source.kind/id/fingerprint` 相同、源入点连续（前段 `sourceOutMs === 后段.sourceInMs`）、`speed` 相同、`gapBeforeMs === 0`、两者之间无转场；
- 合并后只记录：源指纹、合并后的源入点/出点、变速；
- 因此 `B` 拆成 `B1+B2` 后哈希不变；插入/删除/移动、改变转场、变速、换源仍会改变哈希；
- 片段级淡入淡出只影响画面，不进入 `editSyncHash`。

**叠加轨在 `editSyncHash` 中的口径**

叠加轨的起止变化不一定影响混音；只有叠加轨延长总时长才影响。`editSyncHash` 只包含 `max(0, overlayEndMs - mainTrackEndMs)`，不包含每条叠加轨的起止。因此叠加轨内部移动、缩短或样式变化不触发混音过期；延长总时长会触发 `timing_changed`。

**为什么 `editSyncHash` 不包含画幅/分辨率**

画幅与分辨率只影响画面适配，不影响声音时间；包含它们会导致“改画幅也提示混音过期”，违背产品原则“只影响画面的操作不打扰声音”。但 `fps` 必须包含，因为时间码与逐帧语义变化。

**为什么 `dialogueSyncHash` 独立**

台词/音色/Take 的变化发生在配音页，不会改变 `EditPlan`；如果只比较 `editSyncHash`，混音会看起来“已对齐”但实际对白已经变了。独立哈希让混音状态覆盖“画面变化”和“台词变化”两类原因。

### 4.6 布局算法（伪代码）

```ts
export function computeLayout(plan: EditPlanV1): EditLayout {
  const clips: EditLayoutClip[] = []
  const transitions: EditLayout['transitions'] = []
  let cursor = 0

  plan.clips.forEach((clip, i) => {
    const content = Math.round((clip.sourceOutMs - clip.sourceInMs) / clip.speed)
    const overlap = i === 0 ? 0 : findTransition(plan, plan.clips[i - 1].id, clip.id)?.durationMs ?? 0
    const start = i === 0
      ? clip.gapBeforeMs
      : cursor - overlap + clip.gapBeforeMs
    const end = start + content
    clips.push({ clipId: clip.id, timelineStartMs: start, timelineEndMs: end, contentDurationMs: content })
    if (overlap > 0) {
      transitions.push({
        id: findTransition(plan, plan.clips[i - 1].id, clip.id)!.id,
        fromClipId: plan.clips[i - 1].id,
        toClipId: clip.id,
        overlapMs: overlap,
      })
    }
    cursor = end
  })

  const contentEndMs = clips.length ? clips[clips.length - 1].timelineEndMs : 0
  const overlayEnd = plan.overlays.reduce((m, o) => Math.max(m, o.endMs), 0)
  return {
    contentEndMs,
    durationMs: Math.max(contentEndMs, overlayEnd) + plan.project.tailGapMs,
    clips,
    transitions,
  }
}
```

> 说明：为了与产品“画中画可延长总时长”一致，`durationMs` 取主轨与叠加轨结束的较大值；`tailGapMs` 放在 `project` 下，属于工程设置，字幕不延长总时长。

### 4.7 首次打开：bootstrap

```text
GET /episodes/:id/edit
  ├─ 有 episode_edit_drafts        → 返回草稿（标记 draft）
  ├─ 有 edit_revisions(is_current) → 返回当前版本（标记 revision）
  ├─ 有分镜视频                     → 构建初始计划 v1：
  │     1. 按 storyboard_number 排序，仅含有可读视频的分镜；
  │     2. 每段 sourceIn=0, sourceOut=durationMs, speed=1, gap=0；
  │     3. storyboard.transition 映射为 dissolve（时长裁剪到 100–1500ms）；
  │     4. 生成字幕建议 cue（见 8.2）；
  │     5. 创建 edit_revisions(v1, note='自动初始化') 与草稿；
  ├─ 有 video_merges 且无可用分镜      → 单片段 kind='merge'
  ├─ 有 episodes.video_url             → 单片段 kind='episode-video'
  └─ 都没有                            → 返回空计划，roughCutAvailable=false（无素材不提供一键初剪）
```

**工程默认值**

- `project.aspect` 取 `dramas.aspect_ratio`（现有默认 `16:9`）；
- `project.width/height` 由画幅与默认清晰度推导：9:16 → 1080×1920，16:9 → 1920×1080，1:1 → 1080×1080；
- `project.fps` 取主素材帧率（P0/P1 上限 30，超过归一到 30），兜底 30；60fps 工程为 P2；
- `project.defaultExportPreset`：9:16 → `edit-vertical-hd`，16:9 → `edit-horizontal-hd`，1:1 → `edit-source`（P1）；
- 修改工程画幅只创建新版本，不回写 `dramas.aspect_ratio`。

**M1 只读模式**

- `edit_workspace=readonly` 时不创建版本/草稿，也不写入任何计划；
- 若已有 `edit_revisions`，返回当前版本只读；
- 否则只用 `episodes.video_url` 构建单片段临时计划（`revision=null`），与产品 M1“当前成片为单片段”一致；
- 分镜/合片 bootstrap 只在 `edit_workspace=on` 时执行。

**为什么优先分镜而不是合片**

分镜是剪辑的最小可编辑单元；合片已经丢失入出点/顺序信息。只有在分镜缺失或不可读时才回退到合片/成片，保证首次打开尽可能可编辑。

**源素材可读性**

- 分镜 `video_url` 必须能解析到存在的文件；缺失的镜头跳过并在 `issues` 中列出；
- 视频无音轨时 `hasAudio=false`，`audio-ref` 生成时跳过；
- 时长通过 `ffprobe` 获取并缓存到 `edit-media` 的探测缓存（按 URL + fingerprint）。

### 4.8 版本、草稿与导出快照

```text
草稿（可变）                          版本（不可变）
episode_edit_drafts.plan_json   ──保存──► edit_revisions.plan_json
version 自增                           revision_no 自增
300ms 防抖                              Cmd+S / 导出前 / 首次编辑
```

**草稿保存事务**

1. `BEGIN IMMEDIATE`；
2. 读取当前行 `version`；
3. `base_version` 不匹配 → 409；
4. 校验/归一化计划；
5. 写入 `plan_json/plan_hash/edit_sync_hash/version+1/updated_at`；
6. 若 `base_revision_id` 为空，补当前 revision id；
7. `COMMIT`。

**版本创建事务**

1. 校验 `base_version`；
2. 计算 `plan_hash/edit_sync_hash/render_hash/duration_ms/clip_count`；
3. `revision_no = max(revision_no)+1`；
4. 插入 `is_current=1`，同时把同集其他版本置 0；
5. 更新 `episodes.edit_revision_id/edit_plan_hash/edit_sync_hash`；
6. 草稿的 `base_revision_id` 指向新版本；
7. 返回版本摘要。

**导出快照**

- 导出任务创建时，若草稿有未保存修改，先创建里程碑版本；
- 导出记录写入 `edit_revision_id`、`mix_revision_id`、`edit_plan_hash`、`edit_sync_hash`、`dialogue_sync_hash`；
- 渲染只读快照，不读草稿；
- 导出期间 P0 锁定编辑（`episode_locks`），P1 允许继续编辑并提示快照版本。

## 5. 数据库设计

### 5.1 设计原则

- 只加表/加列，不改旧列类型，不删旧数据；
- 所有时间字段为整数毫秒；所有布尔为 `INTEGER`；
- 计划 JSON 为唯一内容，哈希与摘要列用于索引/查询；
- 新表全部带 `created_at`；可变表带 `updated_at`；
- 迁移可重复执行（`CREATE TABLE IF NOT EXISTS` + `PRAGMA table_info` 检查）。

### 5.5 迁移实现（与现有模式一致）

`schema.ts` 与 `sqlite-schema.ts` 双写：

1. **Drizzle 定义**：在 `backend/src/db/schema.ts` 增加 `episodeEditDrafts`、`editRevisions`、`editRenders`、`episodeMediaProxies`、`episodeLocks`；在 `episodes`、`mixRevisions`、`episodeExports` 增加列。
2. **DDL**：在 `backend/src/db/sqlite-schema.ts` 的建表数组中增加新表；索引同数组。
3. **列迁移**：沿用 `PRAGMA table_info(table)` + `ALTER TABLE ... ADD COLUMN`：

```ts
function ensureColumn(db, table: string, column: string, ddl: string) {
  const cols = db.prepare(`PRAGMA table_info(${table})`).all() as { name: string }[]
  if (!cols.some(c => c.name === column)) {
    db.exec(`ALTER TABLE ${table} ADD COLUMN ${column} ${ddl}`)
  }
}
```

4. **回填**：对已有 `edit_revisions` 的集，回填 `episodes.edit_enabled=1`、`edit_revision_id`；无版本的集保持 0。
5. **幂等**：所有 DDL 使用 `IF NOT EXISTS`；列迁移只检查不删除；重复启动安全。
6. **测试**：使用隔离 `SQLITE_PATH` 启动空库 + 旧库快照各跑一次迁移，断言列存在、旧数据不变。

### 6.3 `edit-media.ts`：源解析与代理

**源解析**

| `source.kind` | 解析方式 | 备注 |
| --- | --- | --- |
| `storyboard` | `storyboards.video_url` | 校验文件存在；`hasAudio` 由 ffprobe 判断 |
| `take` | `assets` 中 `type='video'` 且 `storyboard_id=source.id` 的素材 | 视频 Take 不新建表，复用素材库 |
| `asset` | `assets` 行 | 视频/图片 |
| `merge` | `video_merges` 最新完成记录 | 只读素材 |
| `episode-video` | `episodes.video_url` | 只读素材 |
| `import` | `assets` 行（`category='edit-import'`） | 导入时已落库 |

**探测**

```ts
interface ProbeResult {
  durationMs: number
  width: number
  height: number
  fps: number | null
  hasAudio: boolean
  videoCodec: string | null
  audioCodec: string | null
  sizeBytes: number
  mtimeMs: number
}
```

- `ffprobe -v error -show_streams -show_format -of json <path>`；
- 结果按 `url + fingerprint` 缓存 10 分钟（内存 LRU），避免拖拽时反复探测；
- 源文件缺失返回 `SOURCE_OFFLINE`，计划仍可保存，导出检查阻断；
- `fingerprint = sha1(size + ':' + mtimeMs).slice(0, 16)`。

**代理策略**

```text
需要代理 = height > 1080 || videoCodec !== 'h264' || (fps ?? 30) > 30
代理规格 = 720p（保持画幅），H.264 High，CRF 26，AAC 128k（可选无音轨）
```

- 代理生成是后台任务，状态写 `episode_media_proxies`；
- 同一源同一指纹只生成一次；
- 代理文件命名：`<fingerprint>_720p.mp4`；
- 剪辑页请求 `GET /edit/media/proxy?source_url=...`，未完成时返回原文件并标记 `proxy_pending`；
- 代理只用于 `<video>` 预览；`cut/audio-ref/export` 永远使用原文件。

**导入**

- `POST /edit/media/import`：multipart 文件（视频/图片），保存到项目 `uploads/` 或 `assets/`，创建 `assets` 行，探测元数据；
- 限制：视频 ≤ 2GB、图片 ≤ 50MB；MIME/扩展名白名单；文件名去除路径分隔符；
- 导入素材默认 `category='edit-import'`，可在素材库筛选；
- 不复制到临时目录后忘记清理；失败时删除半成品。

**重链**

- 当 `SOURCE_CHANGED`（指纹变化）或 `SOURCE_OFFLINE` 时，用户可以：
  - 重新选择同一 storyboard 的当前视频；
  - 从素材库选择替代视频；
  - 重新生成（跳转生成流程，不在剪辑页内实现）。
- 重链只更新计划中的 `source`，保留入出点/变换/滤镜；若新源短于当前 `sourceOut`，将 `sourceOut` 截到新源时长，并把差额并入下一片段 `gapBeforeMs`（末段并入 `tailGapMs`），保持总时长与后续片段位置；该交界移除转场并告警。

### 6.4 `edit-service.ts`：状态、草稿、版本

**聚合读取 `getEditState(episodeId, dramaId)`**

```ts
interface EditState {
  episodeId: number
  episodeNumber: number
  enabled: boolean
  draft: { plan: EditPlanV1; version: number; updatedAt: string } | null
  currentRevision: EditRevisionSummary | null
  plan: EditPlanV1              // 优先草稿；无草稿用当前版本；都没有用 bootstrap
  layout: EditLayout
  hashes: { planHash: string; renderHash: string; editSyncHash: string }
  draftDirty: boolean           // 草稿哈希 ≠ 当前版本哈希
  mixStatus: MixStatus
  renders: { cut: RenderSummary | null; audioRef: RenderSummary | null }
  mediaWarnings: EditIssue[]
  linePlacements: LinePlacement[]
  capabilities: { canEdit: boolean; canExport: boolean; lock: LockInfo | null }
}
```

**Bootstrap 事务**

- 同一集的并发首次打开可能同时 bootstrap；用 `BEGIN IMMEDIATE` + 唯一索引 `episode_edit_drafts(episode_id)` 保证只创建一次；
- 若插入冲突，回滚并读取已存在草稿；
- 初始版本 `revision_no=1`，`note='自动初始化'`；
- bootstrap 失败（如源探测异常）不阻塞：创建空计划草稿，返回 `issues`。

**保存草稿**

- 输入：完整 `plan` + `baseVersion`；
- 服务端重新归一化，不信任客户端 `layout/hashes`；
- 写入后返回 `{ plan, layout, hashes, version, updatedAt }`；
- 若 `plan.clips.length === 0` 允许保存（空时间线草稿），但导出检查阻断；
- 若 `baseVersion` 缺失：视为强制覆盖（仅内部任务使用），HTTP 路由必须要求。

**版本**

- `createRevision` 可从草稿或指定 `plan` 创建；
- 版本号在事务内分配，避免并发跳号；
- `is_current` 切换与 `episodes.edit_revision_id` 更新在同一事务；
- 版本计划 JSON 不可变，不提供 UPDATE；
- 恢复 = 读取旧版本 → 创建新版本（`note='恢复自 vN'`）。

**草稿与版本的关系**

- `draftDirty = draft.plan_hash !== currentRevision.plan_hash`（若存在草稿且存在版本）；
- 混音页只读当前版本；草稿有修改时混音状态置为 `draft_dirty`；
- 导出前若有草稿修改，自动创建里程碑版本（note='导出前自动保存'），保证导出的快照可见、可回溯。

### 6.5 `edit-timeline.ts`：从画面计划到台词时间

**输入输出**

```ts
interface BuildEditTimelineInput {
  plan: EditPlanV1
  episodeId: number
  dramaId: number
  /** 是否包含绝对锚点台词；默认 true */
  includeAbsolute?: boolean
}

interface LinePlacement {
  lineId: number
  clipId: string
  storyboardId: number | null
  startMs: number
  endMs: number
  durationMs: number
  text: string
  speakerName: string | null
  voiceId: number | null
  /** 配音 Take：line_takes.id */
  voiceTakeId: number | null
  audioUrl: string | null
  audioFingerprint: string | null
  overflowsClip: boolean
  overflowMs: number
  anchorType: 'shot' | 'absolute'
  warnings: string[]
}

interface EditAudioSegment {
  clipId: string
  sourceUrl: string
  sourceInMs: number
  sourceOutMs: number
  speed: number
  timelineStartMs: number
  timelineEndMs: number
  hasAudio: boolean
}

interface EditTimelineResult {
  durationMs: number
  linePlacements: LinePlacement[]
  audioSegments: EditAudioSegment[]
  clipMap: { clipId: string; storyboardId: number | null; startMs: number; endMs: number; contentDurationMs: number }[]
}
```

**台词放置算法**

```text
for each clip in timeline order:
  lines = linesOf(clip.storyboardId)  // anchorType='shot'，按 lineNo/sortOrder
  cursor = 0
  lead = clamp(MIN_LEAD_MS, 0, max(0, clipDuration - 500))
  cursor = lead
  for each line:
    duration = voiceDurationMs ?? audioDurationMs ?? estimateFromText(line.text)
    start = clipStart + cursor
    end = start + duration
    if end > clipEnd:
      overflowsClip = true
      overflowMs = end - clipEnd
    cursor += duration + LINE_GAP_MS
```

- 复用 `timeline.ts` 的 `MIN_LEAD_MS=250`、`LINE_GAP_MS=180`、`MIN_LINE_MS=300`；
- 台词总时长超过片段时**不压缩、不静默截断**：允许溢出到下一片段/间隙，标记 `overflowsClip`；字幕在片段边界截断并告警；
- 可选加速：仅当 `line.speed` 或 `voiceDurationMs` 已经由配音页设定时使用；剪辑页不改台词语速（避免与配音页冲突）；
- `anchorType='absolute'` 或 `voiceStartMs != null`：
  - 计算旧时间轴中该台词所属分镜的起点 `legacyStart`；
  - `offset = voiceStartMs - legacyStart`；
  - 映射到当前片段：`start = currentClipStart + clamp(offset, 0, clipDuration - MIN_LINE_MS)`；
  - 若所属分镜不在时间线，挂到最近的同分镜片段；仍找不到则进入 `unmappedLines`，在混音页待确认；
- 没有 `storyboardId` 的台词（整集绝对锚点）：
  - 若 `voiceStartMs` 在总时长内，按时间找覆盖片段并加偏移；
  - 否则挂到第一段，标记 `absolute_unmapped`。

**字幕建议**

- 首次 bootstrap 或用户点击“重新生成字幕建议”时：
  - 对每个 placement 生成 cue：`start = placement.startMs`，`end = min(placement.endMs + SUBTITLE_TAIL_GAP_MS, clipEnd)`；
  - `follow=true`, `anchor = { clipId, offsetMs: start - clipStart }`；
  - `source='line'`, `lineId`；
  - 若已存在手动 cue 或用户编辑过的 cue，不覆盖；
  - 若没有台词，不生成。
- 字幕文本优先 `subtitleText ?? text`；
- 单条超过 2 行/20 字显示 warning，不自动换行到多 cue（P1 可选智能拆分）；
- 台词本重新抽取后，加载时比对 `lineId/text`：`source='line'` 且文本变化的 cue 产生 `SUBTITLE_SOURCE_CHANGED` warning，提供「同步字幕」显式操作；`source='manual'` 与用户改过的 cue 不自动覆盖。
- 「同步回台词本」（P1）：显式二次确认；仅处理 `source='line'` 且 cue 文本被手动修改的条目，更新对应 `storyboard_lines.text`；不删除配音 Take，但返回 `voice_outdated_line_ids` 提示需重新生成；失败整体回滚。

### 6.6 `edit-render.ts`：画面与原声参考

| 函数 | 产物 | 缓存键 | 说明 |
| --- | --- | --- | --- |
| `ensureCutRender(plan, revisionId)` | `edit/cut/<renderHash>.mp4` | `render_hash` | 静音主轨（含转场/黑场/变换/滤镜/叠加轨 P1） |
| `ensureAudioRef(plan, revisionId)` | `edit/audio-ref/<editSyncHash>.m4a` | `edit_sync_hash` | 源素材原声（含入出点/变速/间隙） |
| `buildEditSubtitleFiles(plan, width, height, dir)` | `.srt` + `.ass` | `subtitleHash` | 硬字幕/软字幕共用 |
| `renderEditVideoTrack(plan, outPath, opts)` | 中间/最终画面 | — | 供 cut/精确预览复用 |
| `renderEditFinal({cutPath, mixPath, subtitles, preset, outPath})` | 最终 mp4 | — | 复用 `renderExportVideo` |

**渲染队列**

- `edit-jobs.ts` 维护进程内队列：全局并发 2，单集并发 1；
- 同一缓存键的重复请求合并为一个任务（in-flight map）；
- 任务状态写 `edit_renders`，前端轮询 `GET /edit/render/:id`；
- 服务启动时把 `running` 置 `failed`（error='服务重启，任务中断'），清理 `edit/tmp`；
- 取消：`AbortController` → 杀 FFmpeg 子进程 → 删除半成品 → 状态 `cancelled`。

**原声参考的音频段落**

- 按 `EditAudioSegment` 逐段 `atrim/asetpts/atempo`；
- 段间按时间线插入静音（`adelay` 或 `anullsrc` 拼接）；
- 输出 M4A（AAC 192k，48kHz）或 WAV（PCM 24bit）；混音输入优先 M4A，减少磁盘；
- 源无音轨的片段输出静音，不报错；
- 不对整条 `audio-ref` 做 loudnorm：原声响度由混音页处理，避免双重归一化。

### 6.7 `edit-preview.ts`：精确预览

- 请求：`{ startMs, endMs, quality: 'draft'|'final' }`；
- 区间限制：500ms ≤ 长度 ≤ 30s（与现有 mix preview 限制一致）；
- 渲染：按最终滤镜链 + 当前混音（若有） + 字幕；
- 输出：`edit/preview/<hash>.mp4`，H.264 720p/1080p，AAC；
- 缓存键：`renderHash + editSyncHash + dialogueSyncHash + mixRevisionId + subtitleHash + start + end + quality`；
- 前端在同一可见预览窗口播放精确预览（临时替换视频池显示），结束后自动回到交互模式，不新增第二个播放器；
- 失败回退：提示“精确预览不可用”，不影响编辑与最终导出。

### 6.8 `mix-plan.ts` 改造：edit-aware

**`compileMixPlan` 新流程**

```text
compileMixPlan(episodeId, dramaId, options)
  ├─ 读取 episode + 当前 edit_revision_id
  ├─ 若存在 edit revision 且 edit_workspace 开启：
  │    ├─ 读取 revision.plan_json（不读草稿）
  │    ├─ buildEditTimeline(plan)
  │    ├─ 读取混音 buses/tracks/clips + 虚拟轨覆盖
  │    ├─ 构建 dialogue 虚拟轨（按 linePlacements）
  │    ├─ 查找 audio-ref（按 edit_sync_hash，completed）
  │    ├─ 构建 original 虚拟轨（audio-ref 单片段；缺失则空 + warning）
  │    ├─ 构建 BGM/音效真实轨
  │    ├─ 应用虚拟轨覆盖（含 per-line overrides）
  │    ├─ targetDuration = plan.layout.durationMs（外扩以容纳真实音频片段）
  │    └─ 返回 MixPlan + editBinding + originalBed
  └─ 否则：
       └─ 走现有 previewTimeline + latestMergeBed 逻辑（legacy）
```

### 6.9 `export-service.ts` 改造

**分支判断**

```text
POST /episodes/:id/exports
  ├─ body.edit_revision_id 存在，或 episode.edit_enabled=1 且 kind='video'
  │    └─ runEditExportPipeline()
  └─ 否则
       └─ runVideoPipeline()（legacy，保留至 M4）
```

**`runEditExportPipeline`**

1. 获取 `episode_locks` 导出锁（P0）；锁冲突 → 409 `EXPORT_LOCKED`；
2. 加载 `edit_revisions` 快照（`edit_revision_id`）；
3. 加载 `mix_revisions` 快照（`mix_revision_id`，默认当前）；
4. 校验（以哈希为准，版本 ID 仅用于审计与回溯）：
   - `mixRevision.editSyncHash === editRevision.editSyncHash`；
   - `mixRevision.dialogueSyncHash === currentDialogueSyncHash`；
   - `mixRevision.editRevisionId` 可与 `editRevision.id` 不同（例如恢复到内容相同的另一版本），哈希一致即视为对齐；
   - 不匹配 → 422 `MIX_STALE`（`render_mode='temp'` 可跳过混音校验）；
5. 校验源文件存在、时长、字幕、存储空间；
6. `ensureCutRender`（`renderHash` 命中则跳过）；
7. 若最终导出：
   - `ensureAudioRef`（混音计划引用它时必须）；
   - 若 `mixRevision.planJson` 不含已渲染 audio-ref，先补渲染；
   - `renderMixAudio(mixPlan, { format:'wav', codec:'pcm_s24le' })`；
   - `measureAndCorrect`；
8. `buildEditSubtitleFiles(editSnapshot.plan)`；
9. `renderExportVideo({ videoPath: cutPath, mixPath, subtitleMode, srtPath, assPath, preset, fps, durationMs })`；
10. `validateExport`；
11. 写回 `episode_exports`（输出 URL/时长/大小/响度/哈希）；若请求 `set_current=true`，调用 `setCurrentExport`；否则保持当前成片不变；释放锁。

**临时/仅画面导出**

- `render_mode='temp'`：使用 `cut + audio-ref`（源原声，无混音）；`audio-ref` 缺失时静音；
- 文件名后缀 `_temp`；
- 不更新 `episodes.video_url`；
- 导出历史标记“临时”；
- 前置检查允许混音过期，但必须提示“不包含最终混音”。

**`reuseKeyOf` 扩展**

```ts
const key = hash([
  kind,
  preset,
  editPlanHash,
  editSyncHash,
  dialogueSyncHash,

```

- legacy 导出继续使用旧 key（保留 `planHash/sourceVideoHash/subtitleHash`），避免旧缓存失效；
- 新导出不再使用 `sourceVideoHash`（由 `editPlanHash` 覆盖）；
- `reuseParamsJson` 包含 fps/分辨率/背景/字幕样式等。

**导出预设扩展**

在 `export-presets.ts` 增加剪辑预设，不修改旧预设：

| --- | --- | --- | --- | --- | --- |

**`edit_enabled` 的维护**

- `createRevision` 首次成功时设 1；
- `restore` 不改变；
- 回滚开关不清零（避免旧合片再次抢指针）；
- 若用户明确要回到旧流程，提供设置项重置为 0，并提示风险（不会自动删除剪辑版本）。

### 6.11 锁、清理与崩溃恢复

**锁**

- `episode_locks` 主键 `episode_id`；
- `acquire(episodeId, kind, ttlMs)`：`INSERT ... ON CONFLICT DO NOTHING`，成功后返回 owner；冲突时检查 `expires_at`，过期则抢占；
- 导出锁 TTL 2 小时，进度更新时续期；任务结束/取消/失败释放；
- 服务启动清理过期锁；
- P1 快照导出可只锁导出记录，不锁编辑。

**清理**

| 目标 | 策略 |
| --- | --- |
| `edit/tmp` | 启动清理 >24h；任务结束立即删 |
| `edit/cut` | 保留被当前版本、最近 10 个导出引用的文件；其余 >7 天删除 |
| `edit/audio-ref` | 保留当前版本与最近 10 个混音版本引用；其余 >7 天删除 |
| `edit/preview` | 保留 24 小时 |
| `edit/proxy` | 保留被当前计划引用的源；其余 >30 天删除 |
| `episode_exports` 文件 | 沿用现有删除策略，不主动清理 |

**崩溃恢复**

- 启动时：`edit_renders.status='running'` → `failed`；`episode_locks` 过期清理；
- 若导出任务在 `running` 时进程退出，`episode_exports` 同样标记 failed，提示重试；
- 草稿是最后一道防线：即使渲染失败，编辑内容不丢。

## 7. API 设计

### 7.1 约定

- 路由前缀：`/api/episodes/:id/...`（与现有后端一致）；
- HTTP 响应沿用 `success(c, data)` / `badRequest(c, message)` 等工具；
- 外部 JSON 使用 **snake_case**（与项目现有 API 一致），服务内部使用 camelCase，由路由层转换；
- 所有写接口要求 `base_version`（草稿）或 `edit_revision_id`（导出）；
- 错误响应：

```json
{
  "success": false,
  "error": {
    "code": "EDIT_VERSION_CONFLICT",
    "message": "此集已在另一个窗口修改",
    "details": { "current_version": 12, "current_plan": { "...": "..." } }
  }
}
```

- 时间单位统一毫秒；文件 URL 使用项目逻辑 URL（以 `/` 开头的站内路径）或绝对路径；
- 所有接口在 `edit_workspace=readonly` 时拒绝写操作，返回 `403 EDIT_READONLY`。

### 7.6 `POST /episodes/:id/edit/rough-cut`

**请求**

```json
{
  "mode": "replace",
  "order": "storyboard",
  "include_missing": false,
  "transition": "cut",
  "create_revision": false
}
```

**行为**

- `mode='replace'`（默认）替换主轨；`mode='append'` 追加到主轨末尾，保留现有片段与字幕；
- 读取所有有视频的分镜，按 `storyboard_number` 排序；
- 生成计划草稿（不自动保存版本，除非 `create_revision=true`）；
- 替换非空时间线时，前端先保存当前草稿为版本（note=`一键初剪前`），再应用初剪结果；旧时间线始终可从版本历史恢复；
- 替换模式默认**替换主轨**并重新建议字幕；追加模式保留现有字幕，并为新片段追加建议；
- 返回归一化计划与 issues；
- 前端需二次确认“将替换当前时间线”。

### 7.8 `GET /episodes/:id/mix/status`

```json
{
  "success": true,
  "data": {
    "status": "stale",
    "reasons": ["timing_changed", "dialogue_changed"],
    "edit_revision_id": 88,
    "mix_revision_id": 31,
    "edit_sync_hash": "a31d...",
    "mix_edit_sync_hash": "9c02...",
    "dialogue_sync_hash": "77aa...",
    "mix_dialogue_sync_hash": "66bb...",
    "draft_dirty": true,
    "pending_count": 0,
    "updated_at": "2026-11-05T11:32:00.000Z"

```

**状态优先级**

```text
failed > running > draft_dirty > stale > missing > aligned
```

- `aligned`：存在当前混音版本且两个哈希都匹配；
- `stale`：存在混音版本但哈希不匹配；
- `missing`：没有当前混音版本；
- `running`：有混音渲染/生成任务进行中；
- `failed`：最近一次混音失败；
- `draft_dirty`：剪辑草稿未存版本（即使混音哈希匹配，也提示先保存版本）。

### 7.10 `POST /episodes/:id/exports` 扩展

**请求**

```json
{
  "kind": "video",
  "preset": "edit-vertical-hd",
  "edit_revision_id": 88,
  "mix_revision_id": 31,
  "subtitle_mode": "burn",
  "render_mode": "final",
  "set_current": false,
  "file_name": "EP03_成片_v7_20261105_1430.mp4"
}
```

- `render_mode='final'`：要求混音对齐；产出正式成片候选，不自动更新 `episodes.video_url`；
- `set_current=true`：导出成功后更新当前成片（等价于导出完成后再点「设为当前成片」）；默认 `false`；
- `render_mode='temp'`：允许混音缺失/过期；文件名加 `_temp`；不更新当前成片；`set_current` 强制为 `false`；
- `render_mode='edit-only'`：只渲染静音画面（无字幕/无原声/无混音），用于内部画面检查；`set_current` 强制为 `false`；
- 未传 `edit_revision_id` 且该集无剪辑：走 legacy（兼容旧前端）；
- 响应沿用现有导出记录结构，新增 `edit_revision_id/mix_revision_id/render_mode/subtitle_mode`。

**前置检查扩展项**

| 检查 | 阻断 final | 阻断 temp | 说明 |
| --- | --- | --- | --- |
| 剪辑草稿未存版本 | 是 | 否 | 自动保存为里程碑后可继续 |
| 混音缺失 | 是 | 否 | temp 使用原声 |
| 混音过期 | 是 | 否 | temp 明确提示 |
| 台词哈希过期 | 是 | 否 | 配音 Take 变化 |
| 源文件离线 | 是 | 是 | 列出片段 |
| 渲染锁被占用 | 是 | 是 | 等待/取消 |
| 字幕警告 | 否 | 否 | 汇总提示 |
| 存储不足 | 是 | 是 | 预计大小 |

### 7.11 并发与幂等

| 场景 | 行为 |
| --- | --- |
| 两个窗口同时保存草稿 | 后保存者 409 + 当前草稿；不自动合并 |
| 两个窗口同时创建版本 | 事务内 `revision_no` 唯一索引；失败者重试或 409 |
| 两个导出同时启动 | `episode_locks` 抢锁；失败者 409 `EXPORT_LOCKED` |
| 同一渲染键重复请求 | 合并 in-flight，返回同一 `render_id` |
| 重复点击“设为当前” | 幂等：同一导出重复设置不报错 |
| 删除正在导出的记录 | 409 `EXPORT_RUNNING`；先取消 |
| 恢复旧版本 | 创建新版本，不修改旧版本；幂等由前端按钮防抖保证 |

## 8. 混音联动：时间桥

### 8.1 时间桥的职责

把“画面时间轴”翻译成“声音时间轴”，并保证：

1. 台词/配音片段的位置、时长、Take 与画面一致；
2. 原声参考与剪辑后的画面一致（入出点/变速/间隙）；
3. 画中画/字幕/滤镜等纯画面变化不导致混音过期；
4. 画面或台词变化必须让混音显式过期；
5. 重新对齐时尽量保留人工调整，无法保留的进入待确认，不静默丢弃。

### 8.2 时间桥数据流

```text
edit_revisions.plan_json
        │
        ├─ computeLayout ──► clip timeline starts/ends
        │
        ├─ storyboard_lines + line_takes
        │        │
        │        └─ placeLinesInClip ──► linePlacements
        │
        ├─ audioSegments（源原声） ──► ensureAudioRef ──► audio-ref.m4a
        │
        └─ linePlacements ──► buildEditDialogueTrack ──► MixPlan voice track
                                              │
audio-ref + BGM/SFX tracks ───────────────────┴──► MixPlan original/bgm/sfx
                                              │
                                              └──► mix-render ──► mix.wav
```

### 8.3 台词放置规则（逐条）

| 情况 | 规则 | 结果 |
| --- | --- | --- |
| 台词属于某分镜，顺序正常 | 从片段起点 + 250ms 开始，逐句 180ms 间隔 | 正常 |
| 台词总时长超出片段 | 允许溢出到下一片段/间隙，标记 `overflowsClip` | 混音可连续；字幕截断警告 |
| 台词 `voiceStartMs` 有值 | 相对旧分镜起点映射到新片段 | `anchorType='absolute'` |
| 台词属于已删除镜头 | 尝试挂到同分镜剩余片段；没有则 unmapped | 混音页待确认 |
| 镜头被分割 | 台词按原偏移落入对应的分割片段；跨分割的台词允许溢出 | 不丢台词 |
| 镜头被重排 | 台词随片段移动 | 位置正确 |
| 镜头切换视频 Take | 台词不变；`dialogueSyncHash` 不变（视频 Take 只影响原声） | 混音只标记 `source_changed`（原声变化） |
| 配音 Take 变化 | `dialogueSyncHash` 变化 | 混音标记 `dialogue_changed` |
| 台词文本修改 | 已有音频不自动重生成；`audioStale=1` 时提示 | 混音页显示待处理 |
| 无音轨镜头 | 原声段静音；台词仍可放 | 正常 |

**“分割不重排台词”的实现**

- 分割产生两个片段，源入出点连续；
- 原台词锚定在分割前的片段偏移上；分割时客户端/服务端把 `lineId` 归属到包含其起点的片段；
- `buildEditTimeline` 在计算时，若检测到同分镜的多个连续片段，按顺序在整个分镜范围内放置台词，再映射到片段；
- 这样即使一句台词跨两个分割片段，也不会被截断。

### 8.4 `buildEditTimeline` 与 legacy 的差异

| 维度 | legacy `previewTimeline` | `buildEditTimeline` |
| --- | --- | --- |
| 顺序 | 分镜编号 | EditPlan 顺序 |
| 时长 | 合并后视频时长缩放 | 入出点/变速后的真实时长 |
| 台词锚点 | 整集绝对/分镜 | 片段 + 偏移 |
| 间隙 | 无 | 支持，静音 |
| 转场 | 不参与台词计算 | 叠化重叠影响起点 |
| 多 Take | 取 active take | 同左，但按 lineId 映射 |
| 输出 | `TimelineResult` | `EditTimelineResult`（含 audioSegments） |

### 8.5 `compileMixPlan` 的 edit 分支（详细）

```ts
async function compileMixPlanEdit(episode, dramaId): Promise<MixPlan> {
  const revision = await loadCurrentEditRevision(episode.id)
  if (!revision) return compileMixPlanLegacy(episode.id, dramaId)

  const plan = JSON.parse(revision.planJson) as EditPlanV1
  const timeline = await buildEditTimeline({ plan, episodeId: episode.id, dramaId })
  const dialogueHash = dialogueSyncHashOf(timeline.linePlacements)

  const buses = await loadBuses(episode.id)
  const realTracks = await loadRealTracks(episode.id)       // BGM/SFX/ambience
  const overrides = parseVirtualOverrides(episode.mixVirtualTracks)

  const voiceTrack = buildEditDialogueTrack(timeline.linePlacements, overrides.voice)
  const audioRef = await findCompletedAudioRef(episode.id, revision.editSyncHash)
  const originalTrack = buildOriginalTrack(audioRef, overrides.original)

  const targetDurationMs = Math.max(
    plan.layout?.durationMs ?? computeLayout(plan).durationMs,
    maxClipEnd(realTracks),
  )

  return {
    version: 1,
    episodeId: episode.id,
    durationMs: targetDurationMs,
    buses,
    tracks: [voiceTrack, originalTrack, ...realTracks],
    editBinding: {
      editRevisionId: revision.id,
      editSyncHash: revision.editSyncHash,
      dialogueSyncHash: dialogueHash,
      draftNewer: await isDraftNewer(episode.id, revision.id),
      sourceKind: 'edit',
    },
    originalBed: audioRef
      ? { status: 'ready', url: audioRef.outputUrl, durationMs: audioRef.durationMs, editSyncHash: revision.editSyncHash }
      : { status: 'missing', url: null, durationMs: null, editSyncHash: revision.editSyncHash },
  }
}
```

**原声缺失时**

- MixPlan 仍返回，`originalBed.status='missing'`；
- 混音页显示“原声参考生成中”，并触发 `POST /edit/render {kind:'audio-ref'}`；
- 用户可先调对白/BGM；原声轨在生成完成后自动刷新（轮询 `GET /mix` 或 `GET /edit/render/:id`）；
- 导出最终成片前必须 `ready`（否则 `AUDIO_REF_MISSING`）。

### 8.6 过期判定表

| 变化 | `editSyncHash` | `dialogueSyncHash` | 混音状态 | 说明 |
| --- | --- | --- | --- | --- |
| 插入/删除/移动片段 | 变 | 不变 | stale(`timing_changed`) | 时间轴变化 |
| 裁剪/变速 | 变 | 不变 | stale(`timing_changed`) | 时长变化 |
| 叠化转场 | 变 | 不变 | stale(`timing_changed`) | 重叠改变总时长 |
| 黑场淡入/淡出 | 不变 | 不变 | aligned | 纯画面 |
| 分割 | 不变 | 不变 | aligned | 总时长不变；台词放置不变 |
| 仅删除留空 | 变 | 不变 | stale(`gap_changed`) | 出现间隙 |
| 视频 Take 切换 | 变 | 不变 | stale(`source_changed`) | 原声参考变化 |
| 配音 Take 切换 | 不变 | 变 | stale(`dialogue_changed`) | 对白变化 |
| 台词文本修改（未重生成） | 不变 | 不变 | aligned + 提示 | 不改变音频；显示“文本与配音不一致”提示，不阻断导出 |
| 台词文本修改并重新生成（新 Take） | 不变 | 变 | stale(`dialogue_changed`) | 新 Take 生效 |
| 画面适配/缩放/旋转 | 不变 | 不变 | aligned | 纯画面 |
| 滤镜/标题/画中画（不延长总时长） | 不变 | 不变 | aligned | 纯画面 |
| 画中画延长总时长 | 变 | 不变 | stale(`timing_changed`) | 总时长变化 |
| 字幕文本/时间 | 不变 | 不变 | aligned | 字幕不进混音 |
| 工程画幅 | 不变 | 不变 | aligned | 纯画面 |
| 工程帧率 | 变 | 不变 | stale(`timing_changed`) | 时间基准变化 |
| 草稿未存版本 | — | — | `draft_dirty` | 先保存版本 |

### 8.7 重新对齐（realign）算法

**模式 A：保留人工调整（默认）**

```text
输入：旧混音（tracks/clips/overrides）+ 新 EditPlan + 新 linePlacements
1. 备份旧混音为内存快照（不写库）
2. 对白：
   - 新 placements 按 lineId 建索引
   - 旧 voice clips（真实轨或 lineOverrides）按 lineId 匹配：
       ├─ 匹配到 → 保留 gain/pan/fade/muted，更新 start/end，take 仍取当前 active take
       ├─ 未匹配（台词删除） → pending: line_removed
       └─ 新台词无旧片段 → 创建默认片段，pending: line_added（用户选择原声/生成/静音）
3. 原声：替换为新的 audio-ref；保留轨道 volume/pan/muted/ducking
4. BGM/SFX：
   - 有 lineId 的片段按 lineId 重新映射
   - 无 lineId 的片段保持绝对时间；若超出新总时长 → pending: clip_out_of_range
   - 保留 gain/pan/fade/loop
5. 虚拟轨：
   - lineOverrides 按 lineId 保留
   - 新增台词无覆盖 → 默认
6. 总线/ducking/响度：完全保留
7. 输出混音草稿 + pending 列表
```

**模式 B：按当前画面重排**

```text
1. 清空对白逐句调整（lineOverrides）与对白片段
2. 按新 placements 重建默认对白
3. 原声替换为新 audio-ref
4. BGM/SFX 保留素材与轨道设置，按绝对时间截断；超出部分 pending
5. 总线/ducking 保留
6. 输出混音草稿 + pending
```

**待确认项必须处理**

- `pending` 列表在混音页顶部常驻，保存前必须逐项选择处理方式（删除/保留/静音/移位）；
- 不允许“忽略全部”一键跳过；
- 处理结果写回混音计划后才允许 `createMixRevision`。

**差异摘要**

- 总时长变化；
- 移动/删除/新增片段数；
- 受影响台词数；
- 未匹配音效片段数；
- 原声参考是否需要重建。

### 8.8 配音 Take 变化的传播

```text
line_takes.is_active 切换
  → storyboard_lines.active_take_id 更新
  → dialogueSyncHash 变化
  → 混音状态 stale(dialogue_changed)
  → realign 时按 lineId 保留音量/声像，只替换音频源
```

- 如果旧 Take 被删除但仍在混音修订中引用，`mix_revisions.plan_json` 仍保留 URL；播放时若文件丢失，显示缺失并提示 realign；
- 导出快照使用快照中的 URL，不跟随最新 Take；保证“导出可回溯”；
- 若用户希望导出最新 Take，需重新对齐并创建新的混音版本。

### 8.9 原声参考（audio-ref）与混音

- `audio-ref` 是“剪辑后源视频自带声音”的混合，不含 TTS 对白；
- 混音页将 `audio-ref` 放在 `original` 虚拟轨，默认音量 0.35（可调）；
- 对白轨由 linePlacements 生成，ducking 侧链以对白轨为触发源，压低原声；
- BGM 默认走独立总线，ducking 可配置；
- 如果源视频本身含有人声（AI 生成的口型音），它属于原声，用户可在混音页降低/静音；这与现有 `video_audio_mode` 语义一致；
- `audio-ref` 不应用 loudnorm，最终响度由 master 总线处理。

### 8.10 Legacy 回退

- 没有 `edit_revision_id` 的集：`compileMixPlan` 走旧逻辑；
- `mix_revisions.source_kind='legacy'`：`GET /mix/status` 返回 `source_kind='legacy'`，混音页显示“旧混音流程”；
- 旧混音在剪辑页首次 bootstrap 时：
  - 若存在当前混音版本，尝试用其 `plan_json` 的时间与当前 EditPlan 比对；
  - 无法匹配 → `stale`，提示重新对齐；
  - 不自动改写旧混音。

## 9. 渲染流水线

### 9.1 总览

```text
EditPlan（快照）
   │
   ├─ 逐片段规范化（trim / speed / fit / transform / filter / fade / fps）
   │       └─ 中间文件：edit/tmp/clip_<n>.mp4（无音轨，统一 WxH/fps/pix_fmt）
   │
   ├─ 主轨合成（cut / xfade / 黑场间隙），按块渲染
   │       └─ edit/cut/<renderHash>.mp4（静音）
   │
   ├─ 原声参考（逐段 atrim/atempo + 静音填充）
   │       └─ edit/audio-ref/<editSyncHash>.m4a
   │
   ├─ 混音（mix-render，输入 audio-ref + 配音 + BGM/SFX）
   │       └─ mix.wav
   │
   ├─ 字幕（ASS/SRT）
   │
   └─ 最终封装（cut + mix + subtitles + fps/preset）
           └─ episodes/<episodeId>/exports/<recordId>/EP03_成片_v7_....mp4
```

**为什么先规范化再拼接**

- `xfade` 要求输入同分辨率、同帧率、同像素格式、同时间基；
- 逐片段规范化把变速、裁剪、适配、滤镜都收敛到统一格式，拼接图更简单；
- 规范化结果可按片段缓存（后续优化），失败时容易定位是哪一个片段。

**分辨率与帧率**

- 输出分辨率由工程设置/预设决定，必须为偶数；
- 帧率来自 `project.fps`，默认取主素材帧率（P0/P1 上限 30），兜底 30；60fps 工程为 P2；
- 所有片段 `fps` 与 `setsar=1` 统一；
- 像素格式 `yuv420p`（兼容性优先）。

### 9.2 逐片段规范化

**视频片段**

```bash
ffmpeg -y -ss <sourceInSec> -i <src> \
  -vf "<fit>,<transform>,<filter>,fps=<fps>,format=yuv420p,setsar=1,<fade>" \
  -an -c:v libx264 -preset veryfast -crf 18 -pix_fmt yuv420p \
  -t <contentDurationSec> <tmp>/clip_<n>.mp4
```

要点：

- 先 `-ss` 快速定位，再用输出 `-t`（或滤镜内 `trim`）精确截断；
- 变速：`setpts=PTS/<speed>`；音频侧 `atempo=<speed>`（链式）；
- 片段时长以 `contentDurationMs` 为准，使用 `-t` 截断，避免容器时间基误差；
- `-an`：剪辑轨静音；原声在 `audio-ref` 单独生成；
- CRF 18 是中间文件，最终导出再按预设码率编码；避免二次压缩明显损失；
- 中间文件放 `edit/tmp`，任务结束后删除。

**图片片段**

- 插入时默认 `durationMs=3000`，之后按片段时长编辑；
- `sourceInMs=0`、`sourceOutMs=durationMs`、`speed=1`；

```bash
ffmpeg -y -loop 1 -framerate <fps> -t <durationSec> -i <image> \
  -vf "<fit>,<transform>,<filter>,fps=<fps>,format=yuv420p,setsar=1,<fade>" \
  -an -c:v libx264 -preset veryfast -crf 18 -pix_fmt yuv420p <tmp>/clip_<n>.mp4
```

**适配（fit/fill）**

```text
fill: scale=W:H:force_original_aspect_ratio=increase,crop=W:H
fit : scale=W:H:force_original_aspect_ratio=decrease,pad=W:H:(ow-iw)/2:(oh-ih)/2:color=black
```

- `background='blur'` 时，fit 模式可叠加背景层：原图放大模糊 + 前景适配；P1；
- 奇数尺寸先 `scale=trunc(iw/2)*2:trunc(ih/2)*2`；
- 缩放/位置：`scale=iw*<scale>:ih*<scale>` 后 `pad`/`crop` 实现偏移；
- 旋转：`transpose=1`（90°）、`transpose=2`（270°）、`hflip`+`vflip`（180°）；
- 翻转：`hflip` / `vflip`。

**滤镜预设参数**

| 预设 | 滤镜（强度 i=0–1） | 说明 |
| --- | --- | --- |
| none | — | 原片 |
| clear | `eq=contrast=1+0.08*i:saturation=1+0.1*i:brightness=0.01*i,unsharp=3:3:0.4*i` | 轻锐化 |
| warm | `colorbalance=rs=0.08*i:gs=0.03*i:bs=-0.06*i` | 暖色 |
| cool | `colorbalance=rs=-0.06*i:gs=0.0:bs=0.08*i` | 冷色 |
| cinematic | `eq=saturation=1-0.25*i:contrast=1+0.12*i,colorbalance=rs=0.04*i:bs=0.05*i` | 青橙 |
| mono | `hue=s=1-i` | 黑白 |
| vintage | `eq=saturation=1-0.3*i:contrast=1-0.05*i,colorbalance=rs=0.06*i:gs=0.02*i:bs=-0.04*i` | 复古 |

- 预览端用 CSS filter 近似（`saturate/contrast/sepia`），导出用上表；
- 强度插值只做线性近似，不承诺与专业调色一致。

**淡入/淡出黑**

```text
fade=t=in:st=0:d=<fadeInSec>
fade=t=out:st=<contentDurationSec - fadeOutSec>:d=<fadeOutSec>
```

- 仅视频；音频淡入淡出由混音页处理（原声轨/对白轨）；
- 淡入淡出作用在规范化后的片段上，转场再作用在片段之间。

### 9.3 主轨合成

**输入**

- 规范化片段 `clip_0.mp4 ... clip_n.mp4`；
- 间隙黑场（按需生成）：`color=black:s=WxH:r=fps:d=<gapSec>`；
- 转场表：`{ fromIndex, toIndex, type, durationMs }`。

**单块滤镜图（≤20 个片段）**

```text
[0:v]settb=AVTB,setpts=PTS-STARTPTS[v0]
[1:v]settb=AVTB,setpts=PTS-STARTPTS[v1]
[v0][v1]xfade=transition=dissolve:duration=0.4:offset=4.4[x1]
[x1][v2]concat=n=2:v=1:a=0[x2]
...
```

- 硬切：`concat`；
- 叠化：`xfade`，`offset = 前一累积时长 - 转场时长`；
- 白场：`xfade=transition=fadewhite`（P1）；
- 推拉：`xfade=transition=slideleft`（P1，方向可映射）；
- 模糊：`xfade=transition=fade` + 两端 `boxblur` 近似（P1，文档标注近似）；
- 间隙：在片段之间插入黑场输入，按硬切拼接；
- 片头/片尾间隙同理。

**分块策略**

- 每 20 个片段或每 120 秒切一块；
- **只在硬切交界分块**，避免把 xfade 拆到两块；
- 块内编码参数完全一致（同 WxH/fps/pix_fmt/CRF）；
- 块间用 concat demuxer 无损拼接：

```bash
ffmpeg -y -f concat -safe 0 -i chunks.txt -c copy cut.mp4
```

- 若块间无法流拷贝（参数不一致），回退为 concat filter 重新编码；
- 拼接后校验总时长与 `layout.durationMs` 的误差 ≤ 1 帧 + 50ms。

**为什么不在一个图里拼完**

- 40 个片段 × 每段滤镜会让 filter graph 巨大、内存占用高、失败难定位；
- 分块后单块失败可重试，不影响已完成的块；
- 块边界选择硬切，保证流拷贝可行。

### 9.4 黑场与间隙

- `gapBeforeMs > 0`：在片段前插入黑场；
- 片头 `gapBeforeMs`：时间线从黑场开始；
- `tailGapMs > 0`：结尾黑场；
- 黑场无音轨；`audio-ref` 用静音填充；
- 黑场不产生字幕；
- 播放器在间隙显示黑场 + 时间码。

### 9.5 叠加轨（P1）

**视频/图片叠加**

```text
[base][overlay]overlay=x=<X>:y=<Y>:enable='between(t,<start>,<end>)'[out]
```

- 叠加素材先规范化到目标尺寸（按 `transform.scale`），保留 alpha（图片 PNG/WebP）；
- 不透明度：`format=rgba,colorchannelmixer=aa=<opacity>`；
- 淡入淡出：`fade=t=in:st=0:d=...,fade=t=out:...:alpha=1`；
- 位置：中心偏移 + 画幅比例计算像素坐标；
- 叠加素材音频不使用（产品规定默认静音）；
- 同一轨多个叠加片段按时间顺序串联 overlay 滤镜。

**文字/标题**

- 生成独立 ASS 文件，按 `EditTextStyle` 设置字体、字号、描边、背景条、位置；
- 通过 `subtitles=` 烧录到 base 上；
- 文字与字幕可以合并为一个 ASS（同一时间轴，不同 Layer），减少一次滤镜；
- 字体：使用系统可用中文字体；导出与预览字体一致性由工程设置锁定（P1 可选择字体）。

### 9.6 字幕

**硬字幕**

- 从 `EditPlan.subtitles` 生成 ASS：
  - `PlayResX/PlayResY` = 工程分辨率；
  - 每条 cue 一个 Dialogue；
  - `Layer`：字幕 0，标题/叠加文字 1；
  - 样式：默认/描边/背景条；
  - 角色名条可用 `\pos` 与独立样式；
- 转义：`{`→`\{`、`}`→`\}`、换行→`\N`、反斜杠→`\\`；禁止用户文本注入 ASS 覆盖标签；
- 烧录：`subtitles=<assPath>`；
- 字幕时间基于 EditPlan 绝对时间，与画面一致。

**软字幕**

- 生成 SRT 或 ASS，封装为 `mov_text`；
- `-map 2:s:0 -c:s mov_text -metadata:s:s:0 language=zho`；
- 播放器兼容性提示：部分平台不识别 mov_text；
- 默认硬字幕，符合产品决策。

**无字幕**

- 不生成字幕流，不烧录。

**字幕校验**

- 单条 > 2 行 / > 20 汉字：warning；
- 时长 < 0.8s：warning；
- 间隔 < 0.1s：warning；
- cue 超出总时长：warning（归一化时截断到总时长，不阻断导出）；
- 字幕与画面安全区：warning；
- 警告不阻断导出，但在导出检查与报告中汇总。

### 9.7 原声参考（audio-ref）渲染

**输入**

- `EditAudioSegment[]`：每段的源 URL、入出点、变速、时间线起止；
- 片段间隙/无音轨段：静音。

**滤镜图**

```text
[0:a]atrim=start=<inSec>:end=<outSec>,asetpts=PTS-STARTPTS,atempo=<speed>,adelay=<startMs>|<startMs>[a0]
[1:a]atrim=...,adelay=...[a1]
[a0][a1]amix=inputs=2:duration=longest:normalize=0[aout]
```

- 段数多时使用 `concat` + 静音段，或分批 `amix`；
- 速度 >2 或 <0.5 时链式 `atempo`；
- 源无音轨：跳过该段，用静音填充；
- 输出：AAC 192k / 48kHz / 立体声；或 WAV 24bit 供混音（体积大，默认 M4A）；
- 不做 loudnorm；
- 时长必须等于 `layout.durationMs`（尾部补静音）。

**缓存键**

- `episodeId + editSyncHash + audioVersion`；
- `audioVersion` 在渲染器参数变化时递增（如 atempo 算法变更）；
- 命中 `completed` 且文件存在 → 直接返回 URL。

### 9.8 最终封装

复用 `renderExportVideo`，扩展参数：

```ts
interface RenderExportVideoInput {
  videoPath: string        // cut.mp4（无音轨）
  mixPath: string | null   // mix.wav；temp 模式可为 audio-ref
  durationMs: number
  preset: ExportPreset
  fps: number
  subtitleMode: 'burn' | 'soft' | 'none'
  srtPath?: string
  assPath?: string
  outputPath: string
  onProgress?: (percent: number) => void
}
```

命令要点：

```bash
ffmpeg -y -i cut.mp4 -i mix.wav -i subtitles.ass \
  -map 0:v:0 -map 1:a:0 -map 2:s:0? \
  -c:v libx264 -preset medium -b:v <preset> -maxrate <maxrate> -bufsize <bufsize> \
  -r <fps> -pix_fmt yuv420p -c:a aac -b:a <audioBitrate> -ar 48000 -ac 2 \
  -t <durationSec> -movflags +faststart <output>
```

- 硬字幕：`-vf "subtitles=<assPath>"`（在编码前烧录）；不使用 `-map 2`；
- 软字幕：`-map 2:s:0 -c:s mov_text`；
- 无字幕：不传字幕输入；
- `-shortest` 不用于最终封装（以 `-t` 为准，避免音频略短被截）；
- 音频采样率固定 48kHz；`measureAndCorrect` 后的响度参数写入导出记录。

### 9.9 校验

```text
validateEditExport(outputPath, expected):
  1. 文件存在且 size > 0
  2. ffprobe：至少一个视频流；final 模式至少一个音频流
  3. 分辨率 == 预设；fps 与工程误差 ≤ 0.01
  4. duration 与 expected 误差 ≤ max(2 帧, 100ms)
  5. 音频响度：LUFS/TruePeak/LRA 在预设范围（沿用现有校验）
  6. 首帧/尾帧可解码：ffmpeg -v error -ss 0/-sseof -1 -frames:v 1 -f null -
  7. 字幕：软字幕流存在（若 subtitle_mode=soft）；硬字幕抽帧抽检（可选）
  8. 写入导出记录；失败抛出可读错误
```

- 校验失败不删除输出文件，保留供排查；
- 导出记录 `status='failed'`，`error` 含阶段与 stderr 摘要；
- 前端展示“失败阶段 + 重试”。

### 9.10 进度与取消

- 每个 FFmpeg 子进程加 `-progress pipe:1 -nostats`；
- 解析 `out_time_ms`，映射到阶段进度；
- 阶段权重：

| 阶段 | 权重 |
| --- | --- |
| 规范化片段 | 15% |
| 主轨合成 | 35% |
| 原声参考 | 10% |
| 混音 | 15% |
| 字幕/封装 | 20% |
| 校验 | 5% |

- 取消：`AbortController` → `SIGTERM` → 2s 后 `SIGKILL`；
- 取消后删除输出与临时文件；记录保留 `cancelled`；
- 服务重启：`running` 任务标记 failed，临时文件清理。

### 9.11 渲染缓存键汇总

| 产物 | 键 | 失效条件 |
| --- | --- | --- |
| 规范化片段（未来优化） | `sourceFingerprint + in/out + speed + size/fps + transform/filter/fade` | 任一变化 |
| `cut.mp4` | `renderHash` | 画面相关字段变化 |
| `audio-ref.m4a` | `editSyncHash + audioVersion` | 时间/源/变速变化 |
| 精确预览 | `renderHash + editSyncHash + dialogueSyncHash + mixRevisionId + subtitleHash + range + quality` | 任一变化 |
| 最终导出 | `reuseKeyOf(kind, preset, editPlanHash, editSyncHash, dialogueSyncHash, subtitleHash, mixRevisionId, subtitleMode, renderMode, reuseParams)` | 任一输入变化 |
| 代理 | `sourceFingerprint` | 源替换 |

### 9.12 失败与降级

| 失败 | 降级 |
| --- | --- |
| 代理生成失败 | 使用原文件预览，提示可能卡顿 |
| 精确预览失败 | 回退简化预览，不影响导出 |
| `audio-ref` 失败 | 混音页原声轨空；用户可重试；最终导出阻断 |
| 单片段规范化失败 | 标记该片段，停止导出，列出源与错误 |
| 转场渲染失败 | 回退硬切并警告（仅临时导出）；最终导出失败 |
| 磁盘不足 | 预检阻断，列出所需空间；不启动渲染 |
| FFmpeg 超时 | 单片段 10 分钟 / 整片 2 小时超时，杀进程并失败 |


**单一来源**

- `plan` 是唯一可变状态；`layout` 由纯函数 computed；
- 视图状态（播放头、缩放、选中）不进入历史、不触发自动保存；
- 简单/专业模式仅控制控件可见性（数值输入、逐帧、吸附开关、I/O 循环），存 `localStorage`，不进入计划/API；默认 `simple`；
- 所有命令在提交时生成新计划对象（不可变更新），便于快照历史；
- 拖拽过程只更新临时视图/草稿副本，`pointerup` 时提交一次命令。

### 10.4 命令、历史与撤销

**历史模型**

- 快照式：每次提交命令前 `structuredClone(plan)` 入 `history`，上限 50；
- 连续微调合并：同一命令在 500ms 内重复（如连续 nudges）合并为一步；
- 拖拽不产生中间历史，仅在结束时提交；
- 撤销/重做恢复计划并尽量恢复播放头到变更位置；
- 命令标签用于菜单“撤销 分割片段”。

**命令纯函数**

```ts
// edit-commands.ts
export function insertClips(plan: EditPlanV1, sources: EditClipSource[], atIndex: number): EditPlanV1
export function moveClip(plan: EditPlanV1, clipId: string, toIndex: number, gapBeforeMs?: number): EditPlanV1
export function trimClip(plan: EditPlanV1, clipId: string, edge: 'in'|'out', deltaMs: number, ripple = true): EditPlanV1
export function splitClip(plan: EditPlanV1, clipId: string, atMs: number): EditPlanV1
export function deleteClips(plan: EditPlanV1, clipIds: string[], mode: 'ripple'|'lift'): EditPlanV1
// ...
```

- 纯函数不调用 API，不做 I/O，可直接在 Node 测试；
- 命令内部处理：磁吸闭合、间隙、字幕跟随、转场清理、分割后 lineId 归属；
- 服务端归一化是最后防线，但客户端命令应尽量产出合法计划。

**关键命令语义**

| 命令 | 语义 |
| --- | --- |
| `insertClips` | 在 `atIndex` 插入；若时间线为空且 atIndex=0，保留片头间隙；后续片段 `gapBeforeMs` 不变 |
| `copySelection` / `pasteAt` | 复制选中片段到前端剪贴板（不入计划）；粘贴生成新 ID 的克隆，保留源/入出点/变速/变换/滤镜，不跨集复用源 |
| `moveClip` | 调整顺序；若移动到新位置，原位置后续片段闭合；字幕跟随由 anchor 自动处理 |
| `trimClip(edge, deltaMs, ripple)` | `ripple=true`（默认）：只改 `sourceIn/Out`，片段起点不变，内容时长变化，后续片段整体移动；`ripple=false`（`Alt/Option`）：`trim-in` 同时改起点与 `gapBeforeMs`，`trim-out` 改下一片段 `gapBeforeMs`（末段改 `tailGapMs`），后续片段不动；两端都不短于 `minimumClipMs`，且不得越过源边界或下一片段起点 |
| `splitClip` | 在播放头/指定时间分割；两段源入出点连续；`gapBeforeMs` 第二段为 0；转场归属到包含交界的一侧；字幕/台词归属到包含起点的片段 |
| `deleteClips(ripple)` | 删除并闭合；后续片段 gap 不变 |
| `deleteClips(lift)` | 删除但保留时长：把删除片段时长加到后一片段的 `gapBeforeMs`；若无后一片段，加到 `tailGapMs` |
| `setSpeed` | 改速度；片段内容时长变化；片段起点不变，后续片段前移/后移（磁吸） |
| `setVideoTake(clipId, assetId)` | 切换视频 Take，更新 `videoTakeAssetId` 与 `source`；保留入出点/变换/滤镜；若新源短于当前 `sourceOut`，截到新源时长并把差额并入下一片段 `gapBeforeMs`（末段并入 `tailGapMs`），保持总时长；该交界移除转场并告警 |
| `setTransition` | `cut` 删除转场并恢复 `gapBeforeMs`；`dissolve` 要求相邻且 gap=0；时长按余量裁剪 |
| `arrangeSubtitles` | 按时间线起点排序，仅调整非固定 cue：重叠时整体后移（保持时长；跟随 cue 改 `anchor.offsetMs`，固定 cue 不动）；后移将超出总时长时停止并提示，不裁剪内容；整次操作可撤销 |
| `addMarker` / `updateMarker` / `removeMarker` | 只存时间点、名称、颜色；不进入任何哈希、不影响渲染与总时长 |
| `setProject` | 画幅/分辨率/帧率变化；画幅变化不改时间；帧率变化可能 ±1 帧 |

### 10.5 自动保存与冲突

```text
plan 变化（命令提交）
  → dirty=true
  → 300ms 防抖
  → PUT /edit/draft { plan, base_version }
      ├─ 200 → draftVersion=resp.version; saveState='saved'; dirty=false
      ├─ 409 → saveState='conflict'; 打开 EditConflictDialog
      └─ 5xx/网络 → saveState='error'; 重试按钮 + 指数退避（3 次）
```

- 自动保存失败不阻塞编辑，但导出按钮禁用；
- 关闭页面：`beforeunload` 提示；桌面版直接保存后退出；
- 再次打开：若服务端草稿比当前版本新，提示“恢复上次编辑 / 丢弃草稿”；
- 导出前：若 `draftDirty`，自动 `createRevision('导出前自动保存')`；
- 冲突选项：
  - `reload`：丢弃本地，加载服务端草稿；
  - `copy`：本地计划另存为新版本/副本（不覆盖服务端草稿）；
  - `overwrite`：二次确认后带 `force=true` 覆盖；
- 不做自动合并。

### 10.6 时间线渲染（Canvas）

**分层**

```text
Layer 0: 背景/网格
Layer 1: 标尺（时间刻度）
Layer 2: 轨道背景/间隙
Layer 3: 视频片段（缩略图条/标题/转场图标）
Layer 4: 字幕 cue
Layer 5: 声音参考波形
Layer 6: 选择框/拖拽预览/吸附线/播放头
Layer 7: 标记/区间
```

- 一个 `<canvas>` 绘制所有层（减少合成开销），按需分层级重绘；
- `devicePixelRatio` 缩放；
- 只绘制可视区间（`visibleStartMs–visibleEndMs`）；
- 波形数据缓存：按片段/缩放级别分桶；
- 分轨参考展开（P1）：Layer 5 可展开为只读子行（对白/原声/BGM/SFX），数据取自 `audio.tracks/clips`；不新增播放器，不提供音量/声像/拖拽编辑；无混音时仅显示原声参考；
- 播放头用 `requestAnimationFrame` 更新，避免重绘整条时间线（仅清空/重画 Layer 6 的播放头区域或全量轻量重绘）。

**坐标与交互**

```text
x = (timeMs - scrollMs) * pxPerMs
pxPerMs = zoom（5–500 px/s → 0.005–0.5 px/ms）
```

- 命中测试顺序：转场图标 → 裁剪把手（左右 6px）→ 片段主体 → 字幕 cue → 标尺 → 空白；
- 拖拽阈值 3px；
- 吸附目标：播放头、片段边界、字幕边界、标记、0 点；阈值 8px；
- `S` 临时关闭吸附；
- 拖动片段到另一位置时显示插入线；
- 时间线支持横向滚动/触控板平移；`Shift+滚轮` 横向；
- 缩放以鼠标位置为锚点。

**视频片段显示**

- 缩略图条：取源视频首帧/中间帧（服务端生成或浏览器截帧缓存）；
- 片段标题：分镜号 + 场景/角色（来自 storyboard）；
- 变速标记、滤镜标记、转场图标、离线标记；
- 选中高亮 + 边框；
- 拖拽裁剪时显示源入出点与时长气泡。

**字幕轨**

- cue 矩形显示文本前 N 字；
- 跟随 cue 显示图钉图标；固定 cue 显示锁形；
- 重叠 cue 上下错位显示（若有）；
- 双击进入内联编辑（DOM 输入框覆盖在 canvas 上）。

### 10.7 预览与同步（`useEditPlayback`）

**视频池**

```ts
interface VideoPool {
  elements: HTMLVideoElement[]   // 2–3 个
  activeIndex: number
  load(clip: EditClip, sourceUrl: string): Promise<void>
  preload(clip: EditClip, sourceUrl: string): void
  show(index: number): void
  seek(msInClip: number): void
  setRate(rate: number): void
  dispose(): void
}
```

- 所有 `video` 元素 `muted=true`、`playsInline=true`、`preload='auto'`；
- 同一时刻只有一个预览窗口；非转场时仅一个 `video` 元素可见，转场时两个元素在窗口内叠化；其余 `display:none` 但保留解码状态；
- 在片段结束前 500ms 预加载下一片段；
- 转场时两个视频同时可见，CSS 透明度过渡；
- 间隙显示黑色背景层。

**时钟**

| 页面 / 场景 | 主时钟 | 同步策略 | 漂移阈值 | 回退 |
| --- | --- | --- | --- | --- |
| 剪辑页，有混音/原声参考 | WebAudio `AudioContext.currentTime` | 视频定期 `sync` 到音频位置 | 120ms | 混音 → audio-ref → 静音 |
| 剪辑页，无音频 | 当前视频 `currentTime` | 播放头跟随视频；片段切换时更新 | 原生 | 静音 + 横幅 |
| 剪辑页，WebAudio 不可用 | 当前视频 `currentTime` | 视频原生播放，仅输出片段原声 | 原生 | 提示「实时混音不可用，播放片段原声」 |
| 剪辑页，精确预览 | 精确预览视频（替换视频池显示） | 单视频原生播放，结束后恢复 | 原生 | 恢复实时预览 |
| 剪辑页，暂停拖动 | 播放头 | 视频 seek 到对应帧 | — | — |
| 混音页，现有实现 | 现有视频（只读画面） | WebAudio 多轨跟随视频时钟 | 320ms | 视频 → 静音预览（波形仍可编辑） |

- 剪辑页视频漂移阈值 **120ms**，比混音页现有 320ms 更严格：剪辑页看口型与切点，错位更敏感；混音页以实时多轨听感优先，沿用 320ms 避免监听回归。这是场景差异，不是两套时钟模型。
- 剪辑页音频回退顺序固定为 `混音 → audio-ref → 静音`；回退时必须显示横幅，不得静默播放错误声源。
- WebAudio 不可用是降级路径而非第二套时钟模型：按“剪辑页，无音频”处理并提示，波形编辑与导出不受影响。
- 超过阈值：暂停 → seek → 恢复；
- 片段切换：`activeVideo.currentTime = sourceInSec + (playhead - clipStart) * speed / 1000`；
- `playbackRate = speed`（0.25–4）；
- 变速时音频由 `audio-ref`/混音处理，视频只做画面；
- 暂停时显示当前帧：seek 后等待 `seeked` 事件；
- 播放质量：`auto`（代理就绪且非精确预览时用 720p 代理，否则原画）/ `720p`（强制代理，未就绪显示生成中）/ `source`（直接源文件，高分辨率可能掉帧）；切换只换 `sourceUrl`，保持播放位置。

**简化转场**

- 叠化：两个视频透明度 0→1/1→0，时长与计划一致；
- 淡入/淡出黑：黑色遮罩透明度；
- 白场：白色遮罩；
- 推拉：CSS `translateX`；
- 模糊：CSS `filter: blur()`；
- 顶部/角落显示“简化预览”标签，精确预览/导出为准。

**字幕叠加**

- DOM 层按当前 cue 渲染文本，样式与 ASS 近似；
- 安全区参考线可开关；
- 精确预览时隐藏 DOM 字幕（画面已烧录）。

**播放控制（P1）**

- 全屏预览（P1）：只对预览容器调用 `requestFullscreen`，不新增播放器；进入后控件 2s 自动隐藏，`Esc` 退出；
- I/O 区间循环：设置入/出点后，播放到出点自动 seek 回入点；关闭循环、切换片段或修改计划时清除区间；
- 对比原片：滤镜检查器按住「对比」时临时移除 CSS filter，松开恢复；只影响预览，不写入计划。

| `/` | 聚焦素材搜索 | 素材库 |
| `?` | 快捷键帮助 | 全局 |
| `Cmd/Ctrl+= / -` | 预览缩放（适应/100%） | 预览 |
| `F` | 全屏预览（P1） | 预览 |

- `J/K/L` 暂不提供：`J` 的倒放在 P2，技术层只保证 `playbackRate > 0`；倒放上线前不绑定该键，避免“按了没反应”。
- P1 能力（标记、全屏、I/O 循环）未启用时对应快捷键不生效，并在快捷键帮助中标注所属阶段。
- 所有按钮有 `aria-label`、可见焦点环；
- 时间线提供键盘替代：方向键移动播放头，`Alt+方向` 移动选中片段（P1）；
- 片段列表替代视图（P1）：表格展示顺序、时长、源状态；支持键盘排序与定位，与时间线共享同一 `EditPlan` 和命令，不产生第二套状态；
- 颜色对比度 ≥ 4.5:1；状态不能只靠颜色；
- i18n 新增 `edit.*` 命名空间，四语言（zh/en/ja/ko）同步；
- 文案避免专业术语堆砌，错误信息说明“发生了什么 + 怎么处理”。

### 10.14 性能预算

| 指标 | 目标 |
| --- | --- |
| 首次打开（40 片段） | < 2.5s（不含代理生成） |
| 时间线交互帧率 | ≥ 60fps（100 片段）；200 片段降级 ≥ 30fps |
| 拖动播放头响应 | < 50ms |
| Seek（代理就绪） | < 200ms |
| 自动保存往返 | < 300ms（本地），主线程阻塞 < 50ms |
| 内存（2 分钟 1080p） | < 600MB |
| 简化转场预览 | ≥ 24fps |
| 精确预览启动 | < 5s（5 秒区间）；30 秒区间完整渲染 < 30s（1080p 代理） |

降级策略：

- 代理未就绪：使用原文件，标注“可能卡顿”；
- 波形未就绪：显示占位条；
- 长剧集（>60 片段）：关闭缩略图条，仅显示色块；
- 低内存：减少视频池到 2 个，降低预加载。

### 13.6 黄金路径验收

**路径 A：首次初剪**

1. 打开 `/edit` → 自动 bootstrap → 主轨出现所有分镜；
2. 播放 → 视频/字幕/声音参考同步；
3. 删除一个镜头 → 后续闭合；总时长变化；混音徽标变“需更新”；
4. 调整顺序 → 字幕跟随；
5. 分割 + 裁剪 → 时长正确；
6. 保存版本 → 版本号 +1；
7. 打开导出 → 预检提示混音过期 → 去混音页重新对齐 → 回来导出成功；
8. 导出完成后**记录生成**，但当前成片默认不更新；只有用户点击「设为当前成片」或显式 `set_current=true` 才更新 `episodes.video_url`；验收断言默认不更新。

**路径 B：横屏与导入素材（P0）**

1. 新建/切换横屏工程；
2. 导入本地 mp4（`POST /edit/media/import`）；
3. 插入时间线，裁剪、变速 1.5x；
4. 适配填充；
5. 导出横屏，校验通过。

**路径 C：跨页一致性（P0）**

1. 完成一版画面与混音，混音已对齐；
2. 回剪辑页删除一个 2 秒片段 → 混音徽标变「需更新」；
3. 打开混音页看到差异摘要；
4. 选择「保留人工调整」重新对齐并保存新版本；
5. 回剪辑页状态恢复「已对齐」；
6. 导出成功，音画同步。

**路径 D：精修（P1）**

1. 加叠化 → 总时长减少；预览简化转场；
2. 改滤镜/适配 → 预览生效；混音状态不变；
3. 编辑字幕文本/时间 → 混音状态不变；导出硬字幕正确；
4. Take 切换 → 画面/原声变化；混音需更新；
5. 精确预览 5 秒 → 转场/字幕与最终一致；
6. 导出 720p/1080p → 参数正确。

**路径 E：并发/恢复（P0 可靠性）**

1. 两个窗口打开同一集；
2. 窗口 A 保存；窗口 B 保存 → 冲突对话框；
3. 选择重新加载/另存副本/覆盖；
4. 刷新页面 → 草稿恢复提示；
5. 导出中关闭应用 → 重启后任务标记失败，可重试；
6. 导出中尝试编辑 → P0 锁定提示。

## 14. 性能与容量

### 14.1 容量假设

| 项目 | 假设 |
| --- | --- |
| 单集时长 | 典型 1–3 分钟；硬上限 60 分钟 |
| 单集片段数 | 典型 15–40；MVP 性能目标 100；硬上限 200 |
| 计划 JSON | 典型 50–200KB；硬上限 8MB |
| 素材分辨率 | 720p–4K |
| 帧率 | 24–60，常见 30 |
| 并发编辑 | 1 集/用户；桌面单实例 |
| 并发渲染 | 全局 2，单集 1 |
| 项目集数 | 10–100 |

**容量口径：**

- 硬上限（200 片段 / 60 分钟 / 8MB）是校验错误，超过时拒绝保存与导出；
- MVP 性能承诺只覆盖 **10 分钟 / 100 片段**；100–200 片段允许降级（缩略图降采样、代理预览、后台渲染），不承诺交互帧率；
- 典型短剧 1–3 分钟 / 15–40 片段必须保持流畅。

### 14.2 渲染耗时估算

以 M 系列 Mac、1080p、30fps、2 分钟为例：

| 阶段 | 估算 | 说明 |
| --- | --- | --- |
| 逐片段规范化 | 1–3 分钟 | 40 段，veryfast CRF18 |
| 主轨合成 | 1–3 分钟 | xfade 需重编码 |
| audio-ref | 10–30 秒 | 仅音频 |
| 混音 | 20–60 秒 | 取决于轨道数 |
| 最终封装 | 2–5 分钟 | medium/8Mbps |
| 合计 | 4–10 分钟 | 首次；缓存命中后大幅降低 |

- 缓存命中：cut/audio-ref 直接复用，最终封装仍是主要耗时；
- 720p 导出约为 1080p 的 40–60%；
- 4K 素材代理后预览流畅，但导出仍按 1080p/预设编码；
- **100 片段 / 10 分钟**：首次导出约 15–30 分钟；交互仍按代理预览，不承诺原画实时；
- **200 片段 / 60 分钟**：分块渲染、后台任务、进度可恢复；进入前提示预计耗时，不承诺交互帧率。

### 14.3 磁盘估算

| 产物 | 2 分钟 1080p |
| --- | --- |
| cut（CRF18） | 60–120MB |
| audio-ref（AAC192） | ~3MB |
| mix.wav（48k/24bit/stereo） | ~35MB |
| 精确预览（5s） | 3–8MB |
| 代理（720p） | 20–50MB/分钟源 |
| 最终导出（8Mbps） | ~120MB |

- 单集缓存预算 500MB；超出时按 6.11 清理；
- 代理按源指纹缓存，跨版本复用；
- 导出文件不由剪辑页主动删除，沿用现有导出管理。

### 14.4 数据库

- 计划 JSON 典型 50–200KB；200 片段上限 8MB；
- `edit_revisions` 每次版本都存完整 JSON；100 个版本约 20MB/集，可接受；
- 若项目长期积累，可提供“压缩旧版本”策略（保留最近 20 个 + 里程碑），P2；
- `edit_renders` 行数少，索引足够。

### 14.5 前端性能

- 时间线 Canvas 分层/可视区绘制；
- 计划不可变更新；避免深度 watch 整个计划；
- 自动保存只序列化一次；
- 缩略图/波形按需加载并缓存；
- 视频池 2–3 个，避免同时解码过多；
- 长剧集降级（见 10.14）。

### 14.6 瓶颈与优化顺序

1. **主轨合成 xfade 重编码**：分块、硬切 concat、缓存；
2. **逐片段规范化**：未来按片段缓存（source+参数）；
3. **最终封装**：预设码率/编码速度权衡；可选硬件编码（P2）；
4. **浏览器解码**：代理 + 视频池；
5. **波形/缩略图**：预生成与缓存。

## 15. 安全

### 15.1 威胁模型

本地桌面应用，主要风险来自：

- 用户导入的恶意文件（超大、损坏、伪造扩展名）；
- 用户输入的字幕/标题文本注入 ASS/HTML；
- 项目路径/文件名的路径穿越；
- FFmpeg 参数注入；
- 日志泄露密钥/IP/密码；
- 本机其他进程访问本地端口（现有部署边界）。

### 15.2 控制措施

| 风险 | 措施 |
| --- | --- |
| 命令注入 | 所有 FFmpeg 调用使用 `spawn(bin, args[])`，不经过 shell；参数来自白名单/数值校验 |
| 路径穿越 | `resolveProjectPath` 校验最终路径在项目根内；拒绝 `..`、绝对路径、NUL |
| 任意文件读取 | 源 URL 只允许项目存储/已登记资产；导入只接受上传文件 |
| ASS 注入 | 转义 `{`、`}`、`\`、换行；字体/颜色白名单；不拼接原始样式 |
| XSS | Vue 默认转义；禁止 `v-html` 渲染字幕/标题；文件名转义 |
| 超大文件 | 导入上限（视频 2GB/图片 50MB）；计划 8MB；片段 200；字幕 2000 |
| 渲染 DoS | 预览区间 ≤30s；并发 2；超时杀进程；锁 TTL |
| 磁盘耗尽 | 导出/渲染前检查可用空间（预计大小 ×1.5）；清理临时文件 |
| 日志泄露 | 不打印 API Key/密码/完整请求头；错误信息脱敏；沿用项目安全边界 |
| 端口暴露 | 保持现有绑定策略，不新增公网监听；不修改端口 |
| 锁竞争 | `episode_locks` + TTL；崩溃后清理 |
| 文件替换 | `sourceFingerprint` 检测；导出前校验；不静默使用新文件 |

### 15.3 媒体文件校验

- 导入时用 ffprobe 校验容器/流；扩展名与 MIME 双重检查；
- 解码失败的文件不允许加入计划；
- 图片只允许 PNG/JPEG/WebP；
- 视频编码不在白名单时允许导入但生成代理；
- 不执行媒体文件中的任何脚本/元数据指令。

### 15.4 数据保留

- 草稿/版本/渲染记录属于项目数据，随项目删除；
- 导出文件由用户管理；
- 日志不包含计划全文（只记录哈希/ID/阶段）；
- 备份/迁移沿用现有项目存储迁移逻辑，新增 `edit` 子目录。

## 附录 B：渲染命令参考

### B.1 单片段规范化（含变速/适配/滤镜/淡入）

```bash
ffmpeg -y -ss 0.2 -i input.mp4 \
  -vf "scale=1080:1920:force_original_aspect_ratio=increase,crop=1080:1920,\
setpts=PTS/1.0,eq=contrast=1.08:saturation=1.1,unsharp=3:3:0.4,\
fps=30,format=yuv420p,setsar=1,fade=t=in:st=0:d=0.3" \
  -an -c:v libx264 -preset veryfast -crf 18 -pix_fmt yuv420p -t 4.8 clip_0.mp4
```

### B.2 两片段叠化

```bash
ffmpeg -y -i clip_0.mp4 -i clip_1.mp4 \
  -filter_complex "\
[0:v]settb=AVTB,setpts=PTS-STARTPTS[v0];\
[1:v]settb=AVTB,setpts=PTS-STARTPTS[v1];\
[v0][v1]xfade=transition=dissolve:duration=0.4:offset=4.4[v]" \
  -map "[v]" -an -c:v libx264 -preset veryfast -crf 18 -pix_fmt yuv420p out.mp4
```

### B.3 块间无损拼接

```bash
printf "file '%s'\nfile '%s'\n" "$PWD/chunk_0.mp4" "$PWD/chunk_1.mp4" > chunks.txt
ffmpeg -y -f concat -safe 0 -i chunks.txt -c copy cut.mp4
```

### B.4 原声参考（两段 + 延迟 + 静音）

```bash
ffmpeg -y -i src0.mp4 -i src1.mp4 \
  -filter_complex "\
[0:a]atrim=start=0.2:end=5.0,asetpts=PTS-STARTPTS,atempo=1.0,adelay=0|0[a0];\
[1:a]atrim=start=1.0:end=4.0,asetpts=PTS-STARTPTS,atempo=2.0,adelay=5200|5200[a1];\
[a0][a1]amix=inputs=2:duration=longest:normalize=0[a]" \
  -map "[a]" -c:a aac -b:a 192k -ar 48000 -ac 2 audio-ref.m4a
```

> 实际实现按时间线插入静音段，保证总时长严格等于 `layout.durationMs`。

### B.5 最终封装（硬字幕）

```bash
ffmpeg -y -i cut.mp4 -i mix.wav -i subtitles.ass \
  -map 0:v:0 -map 1:a:0 \
  -vf "subtitles=subtitles.ass" \
  -c:v libx264 -preset medium -b:v 8000k -maxrate 9600k -bufsize 16000k \
  -r 30 -pix_fmt yuv420p -c:a aac -b:a 192k -ar 48000 -ac 2 \
  -t 92.0 -movflags +faststart EP03_成片_v7.mp4
```
