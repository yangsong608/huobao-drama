# 运行时打包说明（A2）

面向独立平板/移动应用的运行时包：Debian bookworm arm64 rootfs + Node 22.16.0 + 后端单文件 bundle + 前端静态产物 + 工作区模板 + Termux proot。运行时包与 APK、用户数据分离，升级运行时不触碰数据。

## 1. 边界

- 只在 linux/arm64 环境构建；macOS 上通过 Docker Desktop 的原生 arm64 虚拟化执行。
- 不携带开发依赖、测试、源码映射、缓存、日志、FFmpeg/FFprobe。
- 不设置 `FFMPEG_BIN`/`FFPROBE_BIN`；后端缺失静态包时按能力不可用处理。
- 签名、真实配置、用户数据不进入运行时包。
- 构建产物在 `app/runtime/.build/` 与 `app/runtime/out/`，均不入库。

## 2. 前置条件

- Docker Desktop 可运行 `linux/arm64` 容器，`docker info` 架构为 `aarch64`。
- 宿主机 Node 可读取版本号（仅用于注入清单）。
- 前端产物 `frontend/.output/public/index.html`；可用 `WEB_SOURCE` 指向已有产物，或用 `SKIP_WEB=1` 只验证运行时流水线。
- 首次构建需网络：Debian 软件源、nodejs.org、Termux 软件源。

## 3. 命令

```bash
app/runtime/build.sh                          # 完整构建 + 冒烟 + 校验
WEB_SOURCE=/path/to/frontend/.output/public app/runtime/build.sh
SKIP_WEB=1 app/runtime/build.sh               # 不含前端，仅流水线自测
FORCE_REBUILD=1 app/runtime/build.sh          # 重建构建容器（no-cache）
SKIP_SMOKE=1 app/runtime/build.sh             # 跳过容器冒烟（不推荐）
ARTIFACT_DIR=app/runtime/out/build-1 app/runtime/build.sh
```

常用环境变量：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `APP_VERSION` | `desktop/package.json` 版本 | 应用版本，写入清单 |
| `BACKEND_VERSION` | `backend/package.json` 版本 | 后端版本，写入清单 |
| `RUNTIME_VERSION` | `<APP_VERSION>-runtime1` | 运行时版本，独立于 versionName |
| `SOURCE_DATE_EPOCH` | `946684800` | tar 内所有 mtime，保证可复现 |
| `VOLUME_SIZE` | `200M` | 分卷大小 |
| `ZSTD_LEVEL` | `19` | 压缩级别 |
| `WEB_SOURCE` | `<repo>/frontend/.output/public` | 前端产物来源 |
| `SKIP_WEB` | `0` | 1 时前端目录留空 |
| `ARTIFACT_DIR` | `app/runtime/out/<RUNTIME_VERSION>` | 产物归档目录 |
| `BASE_IMAGE` / `BUILDER_IMAGE` / `ROOTFS_IMAGE` | 见脚本 | 镜像标签 |

连续构建两次并用 `app/runtime/scripts/compare-manifests.mjs` 比对两个 `manifest.json`，可验证可复现性。

## 4. 阶段

1. `scripts/import-base.sh`：下载固定 LXC Debian bookworm arm64 rootfs（SHA-256 校验）并 `docker import` 为 `huobao-debian-base:arm64`。
2. `container/Dockerfile.builder`：基础镜像 + curl/xz/zstd/dpkg + Node 22.16.0（SHA-256 校验）+ 全局 esbuild。
3. `scripts/inner-bundle.sh`：
   - `scripts/fetch-proot.sh` 取 Termux `proot 5.1.107.102`、`libtalloc 2.5.0`、`libandroid-shmem 0.7`，逐个校验 SHA-256；必须包含 `libexec/proot/loader` 与 `loader32`。
   - `scripts/build-backend.cjs` 以 esbuild 打包 `backend/src/index.ts` 为 ESM 单文件；external 限定 `sharp`、`better-sqlite3`、`ffmpeg-static`、`ffprobe-static`。
   - 复制前端产物与 `backend/workspace`，计算 schema 指纹，写构建元数据。
4. `rootfs/Dockerfile`：基础镜像 + `ca-certificates`/`libstdc++6`/`tzdata`/`xz-utils` + Node；`npm ci --omit=dev` 只安装生产原生依赖（`better-sqlite3 12.11.1`、`sharp 0.34.5`，锁文件提交在 `package/`）；复制后端 bundle、前端、工作区模板；记录系统包版本。
5. `docker export` 根文件系统。
6. `scripts/inner-package.sh`：裁剪 apt/dpkg 数据库、文档、man、服务脚本、日志与缓存；合入 proot 与许可证；生成文件清单；确定性 tar（`--sort=name --mtime --owner=0 --group=0 --numeric-owner --format=gnu --hard-dereference`）；`zstd -19 -T1`；按 `VOLUME_SIZE` 分卷；生成最终清单。
7. 冒烟：容器内启动后端，`/api/v1/health` 通过；`scripts/smoke.mjs` 验证 better-sqlite3 读写、sharp 生成 PNG、FFmpeg/FFprobe 缺席、SQLite 建表。
8. 校验：分卷逐个比对 SHA-256；合并解压记录首解压耗时；检查归档无硬链接条目；逐文件哈希与清单一致；禁用项扫描；必需文件与执行位检查。

## 5. 产物

`ARTIFACT_DIR/`：

| 文件 | 说明 |
| --- | --- |
| `manifest.json` | 随包清单：版本、schema 指纹、逐文件哈希、分卷顺序与哈希、压缩包整体哈希 |
| `runtime.tar.zst.part-NNN` | 分卷，按名称顺序拼接即为完整压缩包 |
| `smoke.json` | 容器冒烟结果 |
| `verify.log` | 解压校验日志 |

运行时包内部布局（tar 根）：

```
runtime-meta.json
rootfs/                  Debian rootfs，含 /opt/huobao/{backend.mjs,web,workspace,node_modules}
proot/bin/proot
proot/lib/{libtalloc.so,libtalloc.so.2,libtalloc.so.2.5.0,libandroid-shmem.so}
proot/libexec/proot/{loader,loader32}
proot/VERSION
licenses/                THIRD-PARTY.md 与各组件许可证/版权文本
```

## 6. 壳侧解压契约（A3 实现）

- 解压前逐个校验分卷 SHA-256，再按名称顺序拼接，zstd 解压后以 tar 解包；保留符号链接与执行位。
- 归档不含硬链接条目（`--hard-dereference`）：Android 16 的应用私有目录与 `/data/local/tmp` 均禁止 `link()`，壳侧解压不得依赖硬链接；同类文件按独立文件解出。校验阶段会检查归档中不存在硬链接条目。
- 解压到版本化目录（如 `files/runtime/<runtimeVersion>`），校验 `manifest.json` 的文件哈希后再切换使用；失败保留旧版本并重试。
- 清单路径相对解压根；`totals` 用于空间预估；`archive.volumes` 用于分卷校验。
- 运行时与用户数据分离：数据目录包含 `huobao.sqlite3`、`static/`、`workspace/`、`logs/`、`tmp/`；升级只替换运行时目录。

## 7. 启动参数（与 A1 真机结论一致）

- `PROOT_LOADER` → `<runtime>/proot/libexec/proot/loader`，`PROOT_LOADER_32` → `loader32`；缺失会导致全部 exec 返回 EACCES。
- `LD_LIBRARY_PATH` → `<runtime>/proot/lib`：Termux proot 的 ELF RUNPATH 固定为 Termux 安装路径，不设置找不到 `libtalloc.so.2`/`libandroid-shmem.so`。
- `PROOT_TMP_DIR` 指向应用私有可写目录；`PROOT_NO_SECCOMP=1`。
- proot 参数：`-r <runtime>/rootfs -0 -b /dev -b /proc -b /sys -b <data>:/mnt -w /opt/huobao`。数据目录必须绑定进 guest；使用宿主路径会把数据库写进 rootfs（A2 真机实测）。
- 后端环境：`HOST=127.0.0.1`、`PORT=5679`、`SQLITE_PATH=/mnt/huobao.sqlite3`、`HUOBAO_DATA_DIR=/mnt`、`STORAGE_PATH=/mnt/static`、`WORKSPACE_PATH=/mnt/workspace`、`FRONTEND_DIST=/opt/huobao/web`、`HUOBAO_VERSION=<appVersion>`。
- 首次启动把 `/opt/huobao/workspace` 复制到数据目录：提示词按现有规则覆盖，技能仅首次复制。

## 8. FFmpeg 缺席

- 运行时镜像不安装 FFmpeg/FFprobe，也不安装 `ffmpeg-static`/`ffprobe-static`。
- 后端 `backend/src/utils/ffmpeg.ts` 通过 try/catch 探测，缺失时能力不可用，不阻塞启动。
- 构建期 `scripts/scan-forbidden.mjs` 检查禁用文件名、静态包目录与 FFmpeg 动态库依赖；冒烟期验证模块不可解析且 PATH 中无二进制。

## 9. 许可证

`licenses/THIRD-PARTY.md` 列出运行时与 APK 侧组件。可获得的许可证原文随包提供：Node、Debian 各包 copyright、npm 依赖、Termux 包、proot/talloc 的 GPL-2.0 文本。APK 侧（zstd-jni、Commons Compress、ZXing、Kotlin/AndroidX）的许可证文本由 APK 构建提供。

## 10. 可复现性说明

- tar 顺序、属主、mtime、格式固定；压缩与分卷参数固定，清单不含构建时间。
- 两次构建的清单与全部分卷哈希应完全一致。
- Debian 软件源为在线仓库；跨日期重建可能因包版本更新产生差异。清单内的 `system-packages.txt` 记录实际包版本，用于定位差异。需要长期逐字节复现时应改用 snapshot 源并固定快照时间。

## 11. 已知限制

- 本流水线不负责 APK 组装与签名；APK 体积、资源分包、首解压时间在 A3/A8 记录。
- 运行时包不含前端开发服务器与源码映射。
- 应用令牌、端口选择、进程守护、网络切换属于 A3。
