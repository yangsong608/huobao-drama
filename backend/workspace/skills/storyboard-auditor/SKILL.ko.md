# 콘티 동작 검수 가이드

## 1. 대상과 경계

검수 대상은 한 회차 콘티: 삭제되지 않은 콘티, 대사/내레이션, 캐릭터/장면/소품 바인딩, 자산 이미지, 현재 분할 방식.

- 검수 단계는 읽기 전용: 문제만 보고하고 콘티, 대사, 바인딩, 자산을 변경하지 않습니다.
- 수정 단계는 apply_storyboard_repair를 통한 화이트리스트 액션만 가능하며, 각 액션은 문제 목록의 issueId를 참조하고 storyboardId는 생략할 수 있습니다(서버가 issueId로 콘티를 찾음).
- 콘티별 상태, 문제 수, 수정/롤백은 서버가 관리합니다. 이 필드를 출력하지 마세요.

## 2. 5개 항목 검수의 실무 요점

### 검수 1: 각 콘티의 카메라워크, 대사, 동작, 표정, 내레이션

규칙 계층이 커버: 설명 없음, 프롬프트 없음, 카메라 필드 누락, 【샷N】 구조 없음, 정보 헤더 없음, 타임라인 붕괴, 3초 구간 대사 12자 초과, 동작을 대사로 표기.

의미 계층 중점:

1. 설명이 "촬영 가능"한가: 누가, 어디서, 무엇을, 어떻게(신체 디테일), 어떤 표정과 시선, 결과는 무엇인가. "그는 화가 났다", "분위기가 긴장된다"만으로는 촬영 불가.
2. 카메라워크/샷 크기/앵글이 동작에 봉사하는가. 감정 폭발에는 클로즈업, 공간 관계에는 와이드, 추적 동작에는 트래킹. 격렬한 전투에 고정 미디엄은 보통 오류.
3. 역할 배치 오류:
   - 카메라 언어를 대사로: `@갑이 말한다: "카메라가 다가간다"`
   - 내레이션을 캐릭터 발화로: 내레이션이어야 할 내면의 목소리가 `@갑이 말한다: "3년 후……"`
   - 동작/심리를 내레이션으로: `내레이션: "그는 실망하며 고개를 돌린다"` — 대본이 명시적으로 동작 내레이션을 요구한 경우 제외.
4. 한 세그먼트 안의 서브 샷 동작이 서로 모순(일어났는데 앉아 있음).
5. 8-15초 세그먼트의 서브 샷 수가 타당한가(보통 2-4개). 너무 많으면 각 2초 미만, 너무 적으면 늘어짐.

문제 코드: `semantic_shot_description`, 검수 1.

심각도:
- error: 화자/내레이션 배치 오류, 촬영 불가 설명, 동작 자기모순.
- warning: 카메라와 동작 불일치, 설명 모호, 서브 샷 리듬 불균형.
- info: 개선 가치는 있지만 생성 실패를 일으키지 않음.

### 검수 2: 앞뒤 콘티 연속성

윈도 경계의 앞뒤 컨텍스트를 포함해 인접 쌍마다 확인:

1. 끝 동작 이어받기: 앞 콘티 종료 시 동작, 들고 있는 소품, 바라보는 방향. 다음 콘티가 이어가는가. 단절 예: 앞 콘티 "@갑이 문을 밀고 뛰어나간다", 다음 콘티 "@갑이 책상에서 차를 마신다"에 시간 도약 설명 없음.
   - 영상 프롬프트 타임라인을 기준으로 앞 콘티의 마지막 구간과 다음 콘티의 첫 구간을 쌍으로 비교합니다. 다음 콘티의 첫 구간은 눈에 보이는 동작·시선·위치·소품으로 앞 콘티의 결말을 이어받아야 합니다.
   - continuity 필드는 선언일 뿐 근거가 아닙니다. 선언이 이어받기를 적었어도 첫 구간 화면이 이어받지 않으면 단절입니다.
   - 테이블 이동, 장소 변경, 인물 그룹 변경, 시간 도약이 있는데 연결 동작이나 트랜지션 콘티가 없으면 semantic_continuity_break로 보고하고 relatedStoryboardNumbers에 양쪽 콘티 번호를 넣습니다.
2. 시선과 액시스: 대화 시선이 액시스를 넘지 않는가. A가 오른쪽을 보면 B는 반대쪽에서 마주 봐야 함.
3. 공간과 위치: 같은 장면 안의 좌우 위치, 문/창문 위치 도약.
4. 시간: 낮/밤, 조명, 의상, 부상, 소품 상태. 플래시백과 시간 도약에는 트랜지션이나 자막 설명 필요.
5. 장면 넘김 하드 컷: continuity 설명이나 트랜지션 없이 바로 컷하면 단절. fade/dissolve 또는 이어받기 설명 제안.
6. 환경음: 같은 장면의 연속 세그먼트는 같은 환경음을 공유해야 함. 급변은 이음새로 들림.

문제 코드: `semantic_continuity_break`, 검수 2.

트랜지션 제안: 단절에 완충, 빈 콘티, 장소 설명, 시간 경과 표시가 필요하면 `suggestedTransition` 설정:
- `empty`: 빈 콘티 완충(풍경, 소품 클로즈업, 환경).
- `scene`: 이미 바인딩된 장면으로 생성하는 장소 트랜지션.
- `text`: 문자 카드(시간, 장소, 장).
트랜지션 콘티를 직접 만들지 마세요. 생성은 사용자 조작만 가능합니다.

심각도:
- error: 동작/공간/시간의 명백한 단절에 설명이 없어 관객이 이해 못 함.
- warning: 액시스, 위치, 의상, 환경음 불연속.
- info: 트랜지션이 있으면 좋지만 지금도 이어짐.

### 검수 3: 대사 없는 긴 빈 콘티

규칙 계층이 캐릭터 유무와 시간 임계값으로 `silent_shot_long` / `empty_shot_long` 보고.

의미 계층은 두 가지만 확인:
1. 정말 인물 동작, 연기, 대사 지지가 없는가(순수 환경, 순수 소품, 순수 빈 풍경).
2. 의도적 여백/분위기 콘티인가. 명확한 서사 목적이 있으면 제안에 적되 규칙 계층 심각도를 임의로 낮추지 않음.

검수 3은 자동 수정하지 않음: 시스템이 대사를 지어낼 수 없고, 단축이나 분할은 창작 판단.

### 검수 4: 각 대사의 길이와 분할

규칙 계층이 발음 가능 문자 수로 필요 시간을 계산(약 4자/초 + 문장당 1초 호흡)하고 보고:
- `line_insufficient_duration`: 유효 시간 부족.
- `line_overlong_duration`: 유효 시간이 명백히 남음.
- `line_requires_split`: 한 문장이 6초 초과.
- `shot_dialogue_over_capacity`: 콘티 전체 대사량이 길이를 초과.

의미 계층 중점:
1. 긴 대사를 의미 휴지에서 인접 콘티로 나눠야 하는지, 무리하게 빠르게 읽히는지.
2. 한 문장이 인접하지 않은 콘티로 나뉘어 의미가 끊기지 않는지.
3. 대사가 많은 구간에 반응 샷(듣기만)이 부족하지 않은지. 제안에 적음.

의미 계층에서 규칙 계층 문제 코드를 제출하지 마세요. 분할/연장 판단은 제안에 쓰고 수정 단계나 수동 처리로 넘깁니다.

### 검수 5: 콘티가 사용하는 자산의 정확성과 완전성

규칙 계층이 커버: 장면 미바인딩, 무효 바인딩, 본회차 미연관, 중복 바인딩, @참조 없음, 자산 이미지 없음, 이미지 파일 없음, 참조 형식 오류.

의미 계층 중점:
1. 설명이나 영상 프롬프트에 나오는 캐릭터/장면/소품이 모두 이 콘티에 바인딩되었는지. 쓰였지만 미바인딩이면 참조 이미지가 붙지 않음.
2. 바인딩된 자산이 실제로 이 콘티에 등장하는지. 과잉 바인딩은 참조 이미지를 오염시킴.
3. @이름이 올바른 자산을 가리키는지. 동명 다른 인물, 비슷한 장면명, 일반 소품명("칼"이 잘못된 칼을 가리킴).
4. 설명의 외형과 자산 이미지가 명백히 충돌(나이, 의상, 장면 시대). 생성 결과가 불일치.

문제 코드: `semantic_asset_mismatch`, 검수 5.

검수 5는 항상 보고만: 바인딩 변경, 자산 이미지 생성, 중복 바인딩 삭제를 하지 않습니다. 제안은 수동 작업(자산 페이지에서 이미지 보완, 콘티 자산 패널에서 바인딩 수정)을 가리켜야 합니다.

## 3. 근거와 제안 작성

- evidence: 원문 핵심 문장 인용, 최대 500자. 정확한 위치(어느 【샷N】, 어느 대사, 어느 3초 구간) 표시.
- suggestion: 즉시 실행 가능한 수정 방향, 최대 300자. "최적화", "연속성 주의" 같은 빈 문구 금지.
- message: 문제가 무엇이고 왜 생성에 영향을 주는지 한 문장.
- 원문 근거 없는 감각적 판단은 보고하지 않음.

## 4. 중복 제거와 윈도 규율

- 의미 윈도는 16콘티이며 앞뒤 컨텍스트가 겹침. 같은 문제는 두 윈도에 나타나므로 한 번만 보고.
- 중복 키: 검수 항목 + 주 콘티 + 관련 콘티 + 의미 범주. 근거가 더 완전한 항목 유지.
- 규칙 계층이 같은 위치에서 보고한 문제를 반복하지 않음. 의미 계층은 규칙으로 판단 못 하는 부분만 보충.
- 윈도당 최대 30건. error 우선, 다음 warning, info는 가치 있을 때만 유지.

## 5. 수정 단계 실무 규범

### 허용 액션과 필드

| 액션 | 대상 문제 | 허용 필드 | 핵심 제약 |
|---|---|---|---|
| fill_camera_fields | 카메라/샷 크기/앵글 누락 | shot_type, angle, movement | 기존 설명과 프롬프트에서만 귀납 |
| normalize_video_prompt | 헤더 누락, 타임라인 붕괴, 동작을 대사로 | video_prompt, description | 실제 대사/내레이션과 화자 전부 보존 |
| rewrite_description | 촬영 불가/위치 오류 설명 | description, video_prompt, result | 캐릭터/소품/줄거리 추가 금지 |
| fix_continuity | 끝 동작 미이어받음, 장면 넘김 컷 설명 부족 | continuity, transition, description, video_prompt | 장면/캐릭터 바인딩 변경 금지 |
| extend_duration | 대사 용량 부족 | duration, video_prompt, description | 증가만, 세그먼트 상한 내, 타임라인 동기화 |
| insert_transition_shot | 검사 2 경계이면서 문제에 suggestedTransition 있음 | issueId만 | 서버가 전환 콘티 1개를 삽입하고 번호를 다시 매김. 필드 불가 |

### 영상 프롬프트 타임라인 강제 제약

- 첫 줄은 "등장인물: @A, @B｜장면: @이름". 비면 "등장인물: 없음", "장면: 미지정".
- 본문은 "0-3초:"부터 3초 연속 구간, 겹침과 공백 없음.
- 마지막 구간 종료 시간은 콘티 duration과 같아야 함.
- 대사는 `@이름이 말한다: "대사"`, 내레이션은 `내레이션(화외음): "대사"`만. 대사나 화자를 추가하지 않음.

### 수정 경계

- 작업당 최대 40액션, 같은 콘티 최대 3액션, 같은 필드 중복 변경 불가.
- 프레임 자산, 영상, 자막, 더빙, 대사 잠금, 진행 중 작업이 있는 콘티는 읽기 전용. 도구가 거부하므로 재시도하지 마세요.
- 사용자가 검수 후 콘티를 편집했을 수 있음. 지문 불일치 시 도구가 거부하므로 우회하지 마세요.
- 자산 문제, 빈 콘티, 대사 분할, 영상 프롬프트 누락, 화자 미바인딩은 자동 수정 범위 밖.
- 확신이 없으면 건너뛰고 수동으로 남김. 거부 후 다른 필드로 억지 통과하지 마세요.

## 6. 피해야 할 오탐

1. 환경 서사가 있는 롱테이크를 빈 콘티로 보고.
2. 대본이 명시한 동작 내레이션을 "동작을 내레이션으로"라고 보고.
3. continuity 설명이 있는 장면 넘김 컷을 단절로 보고.
4. 동명 다른 자산(두 명의 "왕 씨")을 ID와 설명 확인 없이 바인딩 오류로 판정.
5. 의도적 양식화 카메라(고정 롱테이크, CCTV 시점)를 카메라 오류로 보고.
6. 검수 5에서 "자동 바인딩 변경"을 제안해 권한을 넘음.
